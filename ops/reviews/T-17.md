## Findings
- [P1] R1: Queued and Starting reviewers are released while their tasks are still under review — `crates/gear-engine/src/release.rs:60`. The liveness guard only runs for Active seats. Every Queued/Starting temp therefore reaches `release_one`, which removes any bound worktree and marks it Released even when its task is Verifying and its latest attempt is Submitted. This happens in normal operation: `start_reviews` leaves a reviewer Queued when quota is full or Starting after `agent_pane_busy`, then this tick's release step immediately releases it. Subsequent `tasks_to_review` excludes Released seats, so that task never receives its review. Reproduced separately for both states, and through full `tick` with two occupied temp slots and a third submitted task waiting: the waiting reviewer changes Queued → Released. Apply the task/attempt liveness check to Queued and Starting seats too; only continue an already committed release independently of task liveness. Add full-tick regressions for quota waiting and shell-not-ready startup, then verify the reviewer starts on a later eligible tick.
- [P1] R2: Cancellation does not free the slot on the next tick — `crates/gear-engine/src/release.rs:134`. After successful exit keys and saving Releasing, the unconditional return defers removal and Released until another tick. Releasing still occupies quota. Reproduced with a Working FakeHerdr reviewer and a Cancelled task: one full `tick` sends one exit but makes zero WorktreeRemove calls, reports no released seat, and leaves the seat Releasing. This directly fails the explicit next-tick exit + removal + slot-free acceptance; the existing test encodes the relaxed two-tick behavior. After saving successful exit progress, continue to removal and quota release in that same tick; retain saved progress for restart/retry. Change the cancellation regression to assert all three outcomes after one full tick.
- [P1] R3: One restart can send exit keys twice — `crates/gear-engine/src/release.rs:122`. Exit keys reach Herdr before Releasing is persisted at line 132. If the engine dies after Herdr accepts the exit but before that write, the saved seat remains Active. The next tick blindly sends the exit again into the shell instead of finishing removal. Reproduced with a FakeHerdr wrapper that records successful SendKeys, makes the agent exit, then simulates a crash before returning; resuming the release on the saved store produces two SendKeys calls and no removal that tick. This requires one restart, explicitly in scope. Persist release/exit intent before external IO and reconcile an interrupted or uncertain exit using current Herdr evidence before deciding to resend or remove; simply moving Releasing before the call and skipping exit thereafter would instead lose exits. Add a fault-injection regression at the actual accepted-exit/before-store-write boundary, rather than only pre-seeding Releasing.
- [P1] R4: An already removed workspace can hold quota forever after restart — `crates/gear-engine/src/release.rs:143`. The idempotent removal success list accepts `not_found` and `worktree_not_found` but omits `workspace_not_found`. The adapter explicitly classifies that code as removal of an unknown workspace (`crates/gear-herdr/src/lib.rs:298`). A restart after successful worktree removal but before saving Released leaves Releasing; the next removal returns workspace_not_found, and every retry remains Releasing, retaining the slot indefinitely. A manually removed review workspace reaches the same case. Reproduced by seeding Releasing and injecting Refuse(workspace_not_found): the seat stays Releasing and is reported failed. Treat this documented missing-workspace refusal as successful idempotent removal and add a restart-after-remove/before-state-write regression using that response.
