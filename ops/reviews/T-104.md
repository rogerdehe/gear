## Findings

F1 [P0, blocking] Caller-controlled PATH can fabricate process ancestry — `crates/gear-app/src/identity.rs:234`. `process_ancestors` executes `Command::new("ps")`, which resolves through the caller's PATH. A shell can prepend a directory containing an executable `ps` that prints the captain pane's shell PID. Reproduction against the candidate: a fake Herdr bound the captain to PID 424242 in w1:p1 and the actual probe process to lane pane w1:p2; a PATH-selected script containing `#!/bin/sh` and `printf '424242\n'` produced ancestry `[<probe pid>, 424242]`, after which `observe` and `require_seat` accepted the caller as `p:captain`. This also compromises handover's real-pane search. It breaks the v2 identity safety contract: environment changes must not establish another pane's identity. Smallest fix: in `process_ancestors`, use a trusted absolute system executable (`/bin/ps` on the supported platform), or a native OS parent-PID query, instead of PATH lookup (about 1–10 production lines). Add a subprocess regression with an injected PATH that proves the fake captain PID is excluded and the forged claim remains refused.

F2 [P1, blocking] Seat-binding refusals after observation do not raise the captain item — `crates/gear-cli/src/main.rs:455`. `observe_identity` reports only an error returned by `observe`; it returns an observed fingerprint without checking its seat binding. With `GEAR_CTX=p:captain:1` and the genuine lane `HERDR_PANE_ID=w1:p2`, observation succeeds because the process really runs in w1:p2. `require_seat` then returns NotRegistered because the captain is bound to w1:p1, but callers such as `run_send` propagate that error without `report_claim`. The independent fake-Herdr probe confirmed NotRegistered and zero `identity:w1:p2` items. This breaks the contract's “otherwise NotRegistered and one urgent captain item naming the real pane” requirement and the DELIVERABLE bar for a single normal setup error (a wrong GEAR_CTX while the pane id remains correct). Smallest fix: in `observe_identity`, when a context is present, validate the observed fingerprint against `require_seat` in a read transaction, route its NotRegistered error through the existing reporting branch, and preserve existing handling of other errors (about 15–25 lines). Add a CLI-level regression for this partial claim and a repeat, asserting exactly one urgent item naming w1:p2.

F3 [P0, blocking] Registered-project admin init still accepts a forged captain seat without real-pane proof — `crates/gear-cli/src/main.rs:414` (the unguarded `cmd_admin_init` call to `init_with_home`). This command never calls `observe_identity`. `crates/gear-app/src/admin.rs:102` authorizes an existing captain using only the supplied context's project/name/generation; GEAR_ADMIN is also caller-controlled. A lane can therefore run `GEAR_ADMIN=1 GEAR_CTX=<project>:captain:<generation> gear admin init <config>` and change the registered project's configuration. The independent probe initialized the existing admin contract fixture, then supplied captain context with lane pane w2:p2 and changed quota lanes from 2 to 3: config version advanced to 2 without any Herdr/process observation. This path predates the diff, but leaving it unprotected defeats this task's explicit guarantee that a claimed seat holds only in its bound real pane; fixing F1 alone does not close it. Smallest fix: in `cmd_admin_init`, before calling `init_with_home` for a registered project with a supplied context, open Herdr and apply the same real-pane plus binding proof used by other seat commands, including the deduplicated refusal report (about 10–20 lines). Preserve the existing first-registration/user-shell flow. Add an integration regression showing a forged lane claim cannot advance config_version, emits one urgent real-pane item, and the captain's real pane can still reapply configuration.
