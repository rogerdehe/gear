The new error arm immediately calls mark_checkout_stuck, and start_reviews then skips that task forever, even after release_dead_temps frees the seat and Git recovers. A temporary origin/fetch failure in normal use now requires a hand fix; previously the checkout had a bounded retry budget. Probe: hand in T-1, inject one Git failure, restore success, release the dead temp, call start_reviews again; started remains empty. This breaks done (1)'s no-hand-fix review loop and the STABLE bar. Smallest fix: in the direct-checkout failure handling, retain an attempt-scoped bounded retry counter (approximately 20–30 lines), retry on subsequent ticks while preserving the reservation, and set checkout_stuck/tell the captain only after exhaustion. Apply consistent handling to the early Standby/Released checkout calls too; add a one-failure-then-success regression.

F2 [P1, blocking] A cancelled reviewer startup leaks its Starting seat and quota slot — `crates/gear-engine/src/review.rs:552`, with `crates/gear-engine/src/release.rs:90`. New seats now carry only engine.review_pending and have task_id = NULL until delivery. release_finished_reviews still skips every Starting seat with a NULL task_id, so it cannot cancel these starts. Probe: refuse one agent_start with agent_pane_busy, cancel T-1, run release_finished_reviews; the seat remains Starting instead of Released. No future tasks_to_review iteration will drive the cancelled job, and with temps = 1 later reviews cannot obtain a seat. This breaks done (1)'s automatic reviewer release/progress and the STABLE bar. Smallest fix: have release_finished_reviews/cancel_start resolve the pending task when task_id is NULL, check that job's current review state, cancel/close its start, and clear its pending reservation (approximately 25–40 lines). Also reclaim pending reservations for jobs cancelled before onboarding, without setting task_id early. Add the busy-start → cancel → next-review regression.

F3 [P1, blocking] Standby reuse applies another repository's candidate to the previous repository's checkout — `crates/gear-engine/src/review.rs:746`. A non-void binding bypasses the repo-aware worktree reopening above; this arm then reads the old current worktree_path and passes it to prepare_seat_tree alongside the new repo. In a two-repo project, after a root-repo review becomes Standby, assigning a child-repo review runs status/stash/fetch/checkout in the root checkout. Normally its candidate is absent there, so the review errors every tick; if the object exists there, the reviewer instead works in the wrong repository. Probe: start a root review, put the seat in Standby, bind the lane's next task to web, start that review; no web worktree is opened or created and the old pane/path is retained. This breaks done (4)'s two-repo behavior and the STABLE bar for supported multi-repo use. Smallest fix: before retaining a Standby binding, compare its recorded repo with the task repo; on mismatch release that idle occupant through the existing Releasing path and reopen/create the correct repo checkout after Released (approximately 15–25 lines). Keep the pending reservation and the existing per-repo path archive. Cover Standby root → child reuse, not only Released reuse.

F4 [P1, blocking] A warm re-review can run on the writer's current model despite selection of a different review model — `crates/gear-engine/src/review.rs:754`. free_seat checks CLI compatibility only, and the Standby arm returns after delivery without applying entry/model arguments or the later model gate. Smallest fix: persist the reviewer's actual selected model/entry at startup, compare it with the newly selected entry before Standby delivery, and route a mismatch through the existing restart/start path with the new model arguments and this task's session; gate delivery until the change is confirmed (approximately 25–40 lines plus regression).
