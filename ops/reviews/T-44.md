## Set aside
- Strict reading ("not the open attempt ⇒ Void") would also void a Deliver op whose attempt row **does not exist at all**; the implementation deliberately still delivers it, so `deliver_contract::delivery_is_intended_then_executed` (un-ignored, intends a delivery with no attempt row and expects `submitted`) stays green. The packet's parenthetical enumerates only settled/abandoned/newer, none of which apply to a missing row, so this is a faithful reading rather than a covered-case defect — carried to Questions below.
- `settled` is detected via `get_attempt(project, task, n)` without a seat filter, while `superseded` is seat-scoped. Attempt `(project, task, n)` is unique and always intended with the matching seat, so this asymmetry is harmless in the covered flows; not a bug worth flagging.
- The Void reason ("task {task} attempt {attempt} is no longer the seat's open attempt") names the stale attempt but not whether it was superseded vs settled; the packet only requires "naming the mismatch", so this is acceptable wording, not even a P3.
- The happy path where the op's attempt *is* the open attempt (the `any(…)` guard passes) is exercised indirectly only; the packet specifies one test and the deliver_contract path covers delivery success, so no extra test is required by this task.

## Questions for the captain
- The writer already flags it: should a Deliver op whose attempt row does not exist at all be voided too? The strict rule needs `deliver_contract::delivery_is_intended_then_executed` to record an attempt row first (or be re-scoped). As written, the missing-row case still delivers.
