## Findings
- [P1] F1 — A normal OpenCode lane restarts into a new conversation when its binding has no session reference — `crates/gear-engine/src/quota.rs:267`. Resume args are added only for `binding.session_ref`; otherwise the restart is treated as successful with just `--auto --standalone`. The built-in OpenCode profile has `session_ref=false`, and the repository's verified SOP (`skills/gear/references/agents/opencode.md`, “Find the session id”) explicitly says Herdr does not report this ID: it must be discovered, including from `Continue opencode -s <id>` on exit. Onboarding only persists the session returned by `agent_start`; this branch adds no discovery. Reproduction: active OpenCode lane, NULL binding session, two Token Plan screens; after exit supply `Session task\nContinue opencode -s ses_live\n$ ` as the pane tail. The next full tick starts with `["--auto", "--standalone"]`, without `-s ses_live`, and sends Continue into that new conversation. `resumes_live_session_when_binding_has_no_session_yet` fails. Discover and durably retain the lane's actual session before declaring the switch complete; use the profile resume args and that ID. The writer's manually seeded `ses_lane` test does not cover the normal OpenCode case.
- [P1] F2 — The confirmed quota tick can still flag the lane — `crates/gear-engine/src/quota.rs:210` (consumer: `crates/gear-engine/src/ops.rs:278`). `begin_restart` resets `engine.quota.<seat>` to 0 before the same tick calls `confirm_pending`; `seats_on_quota` derives its protection solely from that counter. Reproduction with the default check budget of 3: seed a Submitted Deliver for T-1 with check_budget=2, then run two quota ticks with an engine/store restart between them. The first preserves the budget, but the second sends the exit key, increments the delivery to 3, and returns `flagged: ["p:heat"]` while the screen still shows Token Plan. `a_confirmed_quota_tick_never_flags_the_lane` fails. Keep the current quota observation and restart/park suppression independent of resetting the confirmation counter; quota-related recovery must not consume the no-progress budget. The writer's test only applies one quota observation and then repeatedly calls confirmation, so it misses this boundary.
- [P1] F3 — Restart lacks occupancy checks and recovery after a successful external start — `crates/gear-engine/src/quota.rs:272` and `crates/gear-engine/src/quota.rs:280`. A persisted restart unconditionally sends the shell export line before checking whether the pane has become a shell. With the old agent still present one tick after its accepted exit key, `does_not_run_shell_exports_while_agent_is_still_present` records `PaneRun(export ...)` followed by an occupied-pane start refusal. The real adapter implements PaneRun with `pane.send_input`, so that shell command is submitted to the live agent. A second reproduction interrupts the engine immediately after FakeHerdr successfully starts the replacement, before the restart marker is cleared, then reopens the store and runs startup recovery and four full ticks. `restart_after_agent_start_recovers_and_delivers_continue` fails: `engine.restart.p:heat` remains `provider/fallback`, every tick exports into the running replacement and retries an occupied-pane start, and the current-model/captain completion records are never written. Ordinary dispatch can send a Continue, but the quota supervisor is permanently stuck in its restart branch and cannot handle the next quota event. Persist and reconcile explicit restart phases with the observed pane/agent; wait for verified exit before shell input, recognize an already completed start after engine recovery, and finish the model/Continue/notification records without repeating external effects.
