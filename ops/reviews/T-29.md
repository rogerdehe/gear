## Findings
- [P2] `--need` is silently ignored — `crates/gear-cli/src/main.rs:303-319` — `SendCmd` carries a `need` field (design/13 lists `--need`, design/07 uses it with `blocked`), but `mail::SendArgs` has no `need` field, and `run_send` neither maps nor rejects it. A lane's `--need` value is silently lost with no error, contradicting the packet's own rule to reject unsupported flags "naming the flag instead of ignoring it" (the writer even restates this in the `reject_unsupported` docstring and progress notes). Fix: add `("--need", c.need.is_some())` to the send `reject_unsupported` list, consistent with `--candidate`/`--preempted`/`--saved`.

## Set aside
- `parse_until` computes `n * seconds` unchecked: an absurd `+<n>m`/`+<n>h` (`n` near `i64::MAX`) overflows (panic in debug, wrap in release) — no realistic input, and the packet does not require bounds; set aside.
- `--wait` combined with `--note`/`--downgrade` is not mutually exclusive in the pre-existing `ReplyCmd` clap struct, so `reply_mode` silently prioritizes `--wait` — pre-existing clap definition, out of T-29's allowed scope; set aside.
- `--about` is mapped into `SendArgs.about` and rejected by `mail::send` with a clear `BadFormat` rather than at the CLI — consistent with "map the clap struct to SendArgs"; set aside.
- `parse_until` accepts a negative absolute unix-seconds value (e.g. `-5`); the packet says "unix seconds" without a positivity rule; non-blocking, set aside.
- `cmd_send` prints the request id (via `announce_request_id`) before `open_herdr()`, so an unreachable socket yields a printed id with no store write — harmless (the id is never persisted) and matches "announce before write"; set aside.
