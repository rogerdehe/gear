F1 [P1, blocking] A pending same-CLI restart still waits forever after its agent exits without a session — `crates/gear-engine/src/restart.rs:259`. Reproduce by starting a lane attempt with an open round and no session reference, then applying a same-CLI model/args config change while the pane still hosts the agent but Herdr has no session id. `restart::reconcile_config` persists a plan with `resume_required=true`; after the agent exits and the pane shows a shell, the missing-agent tick resumes that existing plan. The new shell fallback only runs while constructing a plan (`restart.rs:232`), and the existing-plan path reaches this guard, cannot recover a session from the shell, and returns `Ok(None)` forever. `restart_missing_jobs` sees the plan is still pending and suppresses the stall, so no AgentStart or stall item ever appears. This leaves attempt 1 F1 unresolved for an existing durable plan and breaks the task's startup-recovery goal under the STABLE bar. Smallest fix: in `restart::advance`, apply the shell/no-session fallback to an already loaded plan before this guard, persist the relaxed `resume_required` flag, and add a regression that creates the pending plan while the agent is present, then exits it and ticks; about 6–10 lines plus the test.
