## Findings
F2 [P1, blocking] `plan check` bypasses caller resolution and identity/generation validation — `crates/gear-cli/src/main.rs:1068`, `crates/gear-cli/src/main.rs:1100`. Reproduce with project p, captain generation 1, and heat Parked until an expired timestamp with its binding Void. Invoke check carrying `GEAR_CTX=p:captain:999` with no reachable Herdr session. It succeeds, reports `heat: the park ended`, and writes heat to Queued instead of rejecting the stale caller. A nonexistent caller works too. The handler checks only that ctx exists and then uses its project; it never calls `resolve_caller`, `observe_identity`, or `identity::require_seat`. Conversely, a legitimate caller discovered from its pane without GEAR_CTX is rejected before resolution. This leaves the identity part of previous F2 unresolved and breaks the STABLE bar: an old session can still mutate lane states after replacement. Smallest fix: follow cmd_plan's caller resolution/identity flow, pass the observed fingerprint into the check body, and call `identity::require_seat` with the Captain role inside the same write transaction before expiry; use the validated context's project. Read the agents through that same injected Herdr handle. Roughly 20–35 lines plus stale-generation/anonymous and successful authenticated-check regressions. No broader check implementation is needed.
F4 [P1, blocking] Ordinary `gear plan apply` leaves expired parks with active bindings unchanged — `crates/gear-app/src/plan.rs:826`, `crates/gear-cli/src/main.rs:1289`. Reproduce with heat Parked until an elapsed timestamp, an active binding and its agent present; apply an ordinary plan update with no lane-release staff line (for example, hold another lane). `run_plan` reads agents only when `releasing` is true, passes None otherwise, and the new expiry call skips heat because its binding is active but the snapshot is absent. The independent CLI-body probe returns `Ok("plan version 1")` while heat remains Parked with its original until reason. This directly breaks contract part (2), which requires apply to end eligible parks, and the STABLE bar's normal-use recovery requirement. The engine eventually doing it does not satisfy apply's promised behavior. Smallest fix: in `run_plan`, read/pass a session agent snapshot for ordinary apply too; preserve the existing hard error when an explicit release cannot observe agents, and allow automatic expiry to stay fail-closed on actual observation failure. About 8–15 lines replacing the release-only snapshot gate. Add a CLI-body regression with an expired active-binding park and an unrelated staff update, asserting Active and `park ended`.
