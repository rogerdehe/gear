## Findings

1. **[P1] A restart after saving checkout intent but before submission strands the next review forever.** — `crates/gear-engine/src/review.rs:743`, `crates/gear-engine/src/review.rs:725`. `submit_checkout` commits the token before calling `pane_run`. A restart between those steps leaves a token for a command that was never submitted. On every subsequent tick, `checkout_ready` treats the missing report as Pending and neither submits the command nor times out/reconciles it. The strengthened `restart_after_checkout_intent_before_submission_recovers` probe starts T-1, uses production release, observes its agent exit, assigns T-2, interrupts at the checkout call after generation 2's token is committed, and reopens the SQLite store. Nineteen subsequent start attempts leave the start history at `["p-review-t1"]`; T-2 never starts. This is one restart in the explicitly required old-exit/new-start interval. **Fix:** make recovery reconcile an intent that may never have reached the shell, and safely retry the idempotent checkout once execution can be ruled out; do not equate a saved intent with submission. Preserve the existing rule that a genuinely running checkout cannot start a reviewer. Add a persistent-store regression for this exact boundary and prove exactly one T-2 start at its candidate, with the same worktree/cache.

2. **[P1] A session reported after `agent_start` is lost, so re-review still starts a new conversation.** — `crates/gear-engine/src/review.rs:518`, `crates/gear-engine/src/review.rs:524`, `crates/gear-engine/src/review.rs:821`. The task's session key is written only from the immediate start/adoption reply. `AgentInfo.agent_session` is optional; `SocketHerdr::agent_start` does not poll for a missing session when the agent kind is already present. Once the seat becomes Active, neither later observation nor release updates the task's session key. In `late_reported_session_is_used_for_rereview`, start succeeds without a session in its reply, the next `agent_get` reports `p-review-t1:session`, and a complete engine tick observes the live agent. After rejection, production release and attempt 2, start arguments still contain only unattended/model arguments, with no `resume` or session id. The candidate fake now always reports a session immediately, hiding this normal asynchronous case. **Fix:** capture and durably associate later session observations with the correct task/job before release or seat reassignment, and resume that saved identity for subsequent attempts. Keep a missing expected session explicit rather than silently treating a re-review as a first review. Add a delayed-session test; retain the passing case where another task occupies the seat between attempts.

3. **[P1] A start intent authorizes adoption of any occupant, including the wrong agent kind.** — `crates/gear-engine/src/review.rs:432`, `crates/gear-engine/src/review.rs:784`. `recorded_start` compares the stored requested pane/kind with the requested pane/kind; it never checks `info.agent`, the observed session, or even its stored `label`. Probe `start_intent_does_not_authorize_a_different_occupant` completes checkout, gets that retryable refusal, then models one captain action opening a Claude agent in the pending review pane. The next attempt reports the Codex review started and activates/queues its packet for that unrelated Claude agent. No restart is needed. **Fix:** validate the actual observed kind and intended job identity before adoption; a persisted request alone is not evidence that the occupant is its result. Refused starts must not authorize unrelated occupants. Add this regression and retain the accepted-start/no-shell-input restart test.
