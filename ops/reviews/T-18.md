1. **[P1] Release still removes the warm worktree after integration.** — `ops/reports/T-18.md:18`, `crates/gear-engine/src/review.rs:340`; retained dev implementation `crates/gear-engine/src/release.rs:137` in the clean merge tree. The candidate has no release module, and its automatic merge with current dev retains T-17's `worktree_remove` call unchanged (blob `034024c26710752b12ebef9db5461bcb8c86556f`). Probe `merged_release_keeps_the_warm_seats_worktree` starts T-1, marks its task Done, runs the release tick, exits the fake agent, and runs the next release tick: Herdr receives `WorktreeRemove { workspace: "wt1" }`. The cache is deleted; the stored binding/path subsequently refer to a removed seat. The report's promise to drop this call during a later merge is not implemented by Git's clean merge. **Fix:** integrate current dev into the task branch and change release to exit via profile keys, confirm the agent is gone, and retain the workspace, checkout and cache. Exercise the real release-to-next-start path, including a restart after exit; do not simulate release by directly changing seat state.

2. **[P1] A job queued while the seat is busy later creates a cold second seat.** — `crates/gear-engine/src/review.rs:82`. With `temps = 1`, start T-1, submit T-2 before T-1 ends, and tick: T-2 gets a new Queued `review-2` row before the quota check. Release `review-1` and settle T-1, then tick again: `temp_seat_of(T-2)` returns its queued row, bypassing `free_seat`; the engine creates the `home/review-2` worktree. Probe `queued_second_job_reuses_the_released_first_seat` expects `p:review-1` but gets `p:review-2`. This is ordinary overlapping work and defeats both N long-lived seats and warm-cache reuse. **Fix:** separate waiting jobs from seat allocation, or transfer queued jobs to a free existing seat before provisioning. Bound physical seats to the configured pool and test a second job submitted while the first is active, asserting the same workspace/path and no additional open/create calls.

3. **[P1] Input acceptance is treated as successful checkout.** — `crates/gear-engine/src/review.rs:465`. `SocketHerdr::pane_run` (`crates/gear-herdr/src/lib.rs:147`) calls `pane.send_input` and returns when text plus Enter is accepted; it does not wait for Git or return its exit status. `start_reviewer` immediately starts the agent and marks it Active. One ordinary `git fetch origin` failure therefore leaves the checkout at the previous branch/commit while the new review starts. Probe `failed_checkout_does_not_start_reviewer` executes the emitted command with an unavailable origin, returns the same input-accepted outcome as the socket adapter, and observes the agent start at a different HEAD from the candidate. Slow commands also have no completion barrier. **Fix:** confirm successful completion of cleanup and candidate checkout before starting the agent (with a durable phase/confirmation across ticks), and verify branch/HEAD. A failed or unfinished checkout must not start the review or block other seats. Add delayed-completion and failed-fetch tests using the adapter's asynchronous semantics.

4. **[P1] Restart adoption submits shell text to the already running reviewer.** — `crates/gear-engine/src/review.rs:402`. Environment export now runs on every attempt before `agent_get` at line 430. After a restart between accepted `agent_start` and activation, the binding is Pending and the pane already contains the live reviewer. Probe `restart_after_accepted_start_does_not_type_into_the_live_agent` observes `PaneRun { command: "export GEAR_CTX=p:review-1:1; export GEAR_DB=/state/gear.db", ... }` sent into that agent before adoption. The real adapter submits this as agent input; it does not set a shell environment there. If a backend refuses such input, the early return instead prevents adoption indefinitely. **Fix:** inspect and validate the occupant before every shell write, adopt the matching job without environment/checkout input, and only export in a confirmed shell before a new session. Extend the accepted-start test to assert zero `PaneRun` calls to the live agent, not merely zero second starts.

5. **[P1] Re-review discards the previous reviewer's session.** — `crates/gear-engine/src/review.rs:471`. Every start clears the binding's session reference and passes fresh-start arguments, with no path distinguishing a new task from a re-review. Probe `rereview_resumes_the_same_job_session` records `job1-session` for T-1, rejects attempt 1, releases the reviewer, submits attempt 2, and starts its review: the arguments contain only unattended/model flags, with no `resume job1-session`. The same job loses its findings/context, contrary to the explicit re-review rule. Leaving the old seat Active is not a solution either: task selection skips it and no new packet is dispatched. **Fix:** preserve a task's review-session identity independently of whichever job currently occupies a seat; resume that saved session using the profile's resume arguments for subsequent attempts, while keeping different tasks on new sessions. Test fail → rework → second attempt, including an intervening different task on the seat.
