## Findings

F1 [P0, blocking] IPv6 host truncation permits an unregistered destination — `crates/gear-app/src/push.rs:227` (`split`). Splitting an authority at its first colon turns both `ssh://git@[2001:db8::1]/team/repo.git` and `ssh://git@[2001:db8::2]/team/repo.git` into `[2001/team/repo`. Independent reproduction: create a real Git repo with the first URL as origin; call `admin::init` with an in-memory store; the frozen list is `["[2001/team/repo"]`; `push::check` for the second host returns `Ok(())`. This breaks the push safety rule and M3 done clause (2), which requires refusing every destination the project did not register; it is a P0 allow-list bypass, not merely an unsupported URL being refused. Smallest fix: in `push.rs::split`, preserve the complete bracketed IPv6 host through `]` and strip only a port after that closing bracket (roughly 10–15 lines); add a regression using init and check that allows the registered IPv6 host and refuses a different IPv6 host with the same path. Keep the existing hostname/port behavior.

F2 [P2, logged] Some valid Unicode paths panic during normalization — `crates/gear-app/src/push.rs:244` (`clean_path`). `normalise("https://example.com/中文")` panics because `path[path.len() - 4..]` starts inside a UTF-8 character. This can terminate init/check instead of returning a destination/refusal. Independently reproduced with `catch_unwind` against the candidate library. Logged as an edge case under the DELIVERABLE bar, with no rework required for this round. A future small fix can test the last four bytes for the ASCII suffix before slicing, with a Unicode path regression.
