This breaks the contract's “an HTTP error ... give Err with the reason” acceptance and the STABLE bar requiring normal-use usability errors to be fixed: expired credentials, throttling, and provider outages are normal operational errors. Smallest fix: add `--fail` to `http_get`'s arguments (one line), retaining the timeout and stdin header; make the fake HTTP-error test check that failure detection is enabled before emitting code 22, and verify the returned error includes the status (about 10–15 test lines). Apply through the shared helper so both HTTP readers are covered.
