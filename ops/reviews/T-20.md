## Findings
- [P3] The budget flag fires only on exact equality, `used == budget` — `crates/gear-engine/src/ops.rs:79` — so if `EngineCfg::doorbell_check_budget` is ever lowered across a restart below an op's accumulated `check_budget`, `used` steps past `budget` and the seat is never flagged while the op keeps holding the seat's delivery slot (`updated` is still rewritten by the bump). The same holds for `budget <= 0`, which never flags. Not blocking: the packet's rule is literally "when it reaches `budget`", the default is 3, and `>=` alone would re-flag on every later call; the robust form needs a persisted "already flagged" marker (e.g. the op's `result`).
- [P3] The `Unknown` half of the loop (`OpState::Submitted` and `OpState::Unknown` at `crates/gear-engine/src/ops.rs:57`) has no test: all six use Submitted. The doc comment promises Submitted/Unknown and `Unknown → Confirmed` is a legal transition, so one test that moves an op to Unknown and asserts confirmation (or the budget bump) would cover it. The code path is identical, coverage gap only.
- [P3] `older_view_does_not_confirm` (`crates/gear-engine/tests/eng_confirm.rs:101`) calls `confirm_pending` with `now = T0 + 6` while the op is created at `T0 + 10` — a tick that runs before the op exists. It fails for the right reason (`views_since(created)`) but reads as an impossible tick; creating the op at `T0 + 1` and the view at `T0 + 2` with `now = T0 + 20` would test the real case. Also no test pins the boundary `view.ts == op.created`, which the packet's "at/after" admits.
- [P3] The Result's `Branch:` line still says `@ e6da8e9` (`ops/tasks/T-20.md:64`), while the hand-in tip is `2f448da` (the merge and packet commits come after the feature commit) — stale sha in the brief.
- [P3] Confirmation writes `result: None` (`crates/gear-engine/src/ops.rs:71`), so the op keeps no pointer to the evidence that settled it, although design/08's `confirm(conn, op_id, evidence)` records evidence. Traceability is not lost (the view is still in `views` at its (seat, generation, ts)), only unlinked; storing the view's `ts` in the op's `result` would close it.

## Set aside
- Non-doorbell Submitted/Unknown ops are skipped rather than bumped: the doc comment scopes this function to doorbell ops, T-19 does the same for Intended, and the other kinds get their own evidence rules (T-4 and later). Not changed.
- `views_since` has no project filter, so confirmation relies on seat ids being project-qualified. They are: `insert_op`/`intend_doorbells` carry ids built as `{project}:{name}` (see `gear_store::testing::seed_active_seat`), so no view of another project's seat can match; no finding.
- An op with an empty `covers` can never be confirmed and keeps its slot until a caller settles it. `doorbell::decide` only rings with non-empty `covers` (all six `doorbell_contract` tests), and refusing to link evidence to nothing is the safe direction — documented in the progress note.
- The flagged seat is returned, not persisted as "needs check": the packet says "returned as flagged once", and design/07's mark-and-notify belongs to the caller (tick, T-4). Out of this task.
- `require_transition` runs on a constant predicate inside the loop: it cannot fail here but guards the raw `set_op_state`, and the whole walk is one transaction that rolls back on error — kept, as in T-18.
- `bump_op_check_budget` also rewrites the unconfirmed op's `updated` time on every check; that is the store helper's contract and the evidence query uses `created`, so behaviour is unaffected.
- "Tests written first and seen red" cannot be verified: the feature commit `e6da8e9` adds tests and implementation together. The delivered tests match the contract, so nothing to act on.
- No test for two unconfirmed doorbell ops on one seat and the `flagged.contains` dedupe; `slot_ops` keeps at most one outstanding deliver/doorbell per seat, so that branch is defence in depth, not a reachable packet case.
