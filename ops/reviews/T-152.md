About 25–40 production lines across doorbell.rs/lib.rs/ops.rs plus regressions for both statuses and both sender/tick paths.

F2 [P1, blocking] An existing Intended task delivery bypasses readiness on the next tick — `crates/gear-engine/src/ops.rs:322`. Dispatch's new check governs creation only; execute_intended drains old Deliver ops, and aim accepts Working and Unknown agents. Reproduction: reuse ready_state_contract::world(Idle), name the lane p-heat, call dispatch::intend_dispatch with the heat seat and Action::Assign { task: "T-1" } at T0+1, change the fake status to Working, then tick at T0+10. Smallest fix: recheck the live Herdr status for Deliver ops immediately before prompt, allowing only Idle/Done; return the existing retry/wait outcome for other states, keeping the same Intended op rather than failing or duplicating it. Propagate the op kind/readiness requirement through execute_intended to aim (about 15–25 production lines, sharing F1's live-status read). Add a regression that intends while Idle, retries while Working/Unknown/Blocked with no prompt, then switches to Done and verifies exactly one task delivery.
