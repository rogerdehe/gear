## Findings

F1 [P1, blocking] The required timing result has not been delivered — `ops/reports/T-127.md:70` — the report explicitly says under 30 s on an idle machine is not met, and independent warm whole-crate runs were 56.54 s and 99.61 s under contention. This blocks the DELIVERABLE bar's requested test-time fix through missing mechanical acceptance; it is not a claim that these busy-host runs prove an idle failure. Smallest fix: first obtain a quiet measurement window, build separately, run `/usr/bin/time -p cargo test -q -p gear-engine` twice without thread tuning, and replace the report's caveat with both actual under-30-second results and direct binary measurements (roughly 15–25 report lines). If those runs still exceed 30 s, finish the packet's fixture optimization rather than treating it as out of scope; begin with `review.rs::scratch_review_repo`'s repeatedly built repository. Do not waive the limit or add slow-test exceptions.

F2 [P1, blocking] Engine tests still sleep on the wall clock — `crates/gear-engine/src/switch.rs:410` — `text()` unconditionally sleeps 300 ms after each successful `pane_type`, including with `FakeHerdr`. `switch::tests::the_switch_uses_the_production_sequence_one_submission_per_tick` exercises this twice; the independent workspace run measured 0.656 s for that test. This is a failed fact against the packet's explicit “No test may sleep on the wall clock” requirement and leaves the DELIVERABLE test-time fix incomplete; the report's claim that every remaining fixture test is sleep-free is incorrect. Smallest fix: inject the typed-input settle wait at the Herdr boundary, retain the 300 ms production default, and make `FakeHerdr`'s wait a no-op (approximately 15–25 lines across `gear-herdr/src/lib.rs`, `gear-herdr/src/fake.rs`, and `switch.rs::text`). Keep the existing input-order assertions and ensure integration tests use the same no-op boundary; a unit-test-only cfg guard would leave integration callers sleeping. Correct the report's blanket claim. A separate filtered run of this test also passed in 0.64 s of test execution, consistent with the two unconditional waits (Cargo/build overhead is excluded from that figure).

F3 [P2, blocking] The completion-time regression assertion is weakened — `crates/gear-engine/src/merge.rs:3605` — the old test required `op.updated > launched_at`; the replacement permits `op.updated == launched_at` whenever launch and release fall in the same second (`wall_time()` has whole-second precision). A regression recording the launching tick's timestamp can therefore pass, whereas the old sleeping test distinguished it. This fails the mechanical acceptance “No assertion is weakened or deleted,” a DELIVERABLE requirement rather than a request for extra edge coverage. Smallest fix: in `a_gate_that_is_still_running_does_not_block_the_merge_step`, use a deterministic launching tick timestamp earlier than the sampled completion/release time (for example `wall_time() - 1`), restore the strict `op.updated > launched_at` assertion, and retain the release lower bound and attempt-time equality (roughly 3–5 lines). This preserves the original check without any sleep.

F4 [P2, logged] FIFO test waits have no failure bound — `crates/gear-engine/src/merge.rs:2928` — both opening/reading `running` and writing `release` can block forever if a worker fails before reaching its gate or exits between handshakes. The previous file polling failed on a deadline; the new `WAIT` timeout does not cover these helpers. This can hang a future failing test, but it is an error-path edge and does not block under the DELIVERABLE bar. A later fix can bound the handshake through a channel result with a timeout, without adding polling or sleeps.
