Reproduction: in a temporary HOME with skills installed, unset `GEAR_DB` and `HERDR_SOCKET_PATH`; register project a on R, which uses `$HOME/.local/state/gear/gear.db`; then run `gear admin init b.toml --check` for b on R with default templates. It reports `cross-project check skipped: no store` and accepts b, while real registration refuses b. I independently compiled the candidate's verbatim `other_projects` helper in a temporary Rust harness with stub store types; with `GEAR_DB` absent and an existing temporary `$HOME/.local/state/gear/gear.db`, it printed `candidate other_projects result: Ok(None)` without reaching the opener. This is a normal user-shell invocation and breaks the STABLE bar's requirement to fix normal-use errors, plus contract v2's requirement to inspect the store file the command would use. Smallest fix: in `other_projects`, resolve the path from `GEAR_DB`, else from HOME via the existing pure `default_store_in(home, HERDR_SOCKET_PATH)` helper (roughly 6–10 lines), then retain the existence guard and read-only open; do not call the directory-creating `default_store_path`. Add a CLI regression that registers a into the default store, removes `GEAR_DB`, and checks b on the same repo; require BAD_FORMAT naming a and R and no store changes. The same resolver also covers named-session and registered-target defaults.
