## Findings
- [P1] Read the config and queued-seat roster from one database snapshot — `crates/gear-engine/src/onboard.rs:167`, `crates/gear-engine/src/onboard.rs:182`. `config::latest` reads the project in a transaction that ends before parsing (`crates/gear-app/src/config.rs:190`); the roster is read in a separate transaction. If re-init commits a new lane between those reads, onboarding receives the old config together with the new lane seat. `onboard_seat` reports “lane pricing is not in the project config”, and line 192 parks that valid queued lane in NeedsCheck. Subsequent ticks skip it permanently, so a successful mid-run config update breaks the required new-lane onboarding without any Herdr failure. Reproduced on a scratch on-disk store: re-init committed v2 at 246.750291 ms; the overlapping onboarding call finished at 5.0977745 s with only heat active, pricing in needs_check with that exact reason, and the next call onboarded nothing. A valid 32 MiB TOML comment in v1 widens the scheduling window; the defect is the transaction split and also exists with ordinary configs. Fix by obtaining the config row and seat roster in one read transaction, then parsing and doing Herdr work outside it; alternatively detect a changed config version and defer/retry without parking a newly added seat. Add a regression covering an update between config and roster acquisition, rather than only re-init completed before onboarding.

## Reproduction evidence

The following standalone harness was compiled against this checkout's built rlibs and run with a fresh temporary database. It calls the actual admin and engine functions; it does not modify project code. Its assertions confirm the observed failure, rather than the desired behavior. Compile with `rustc --edition=2021`, `-L dependency=target/debug/deps`, and `--extern <crate>=<matching target/debug/deps/lib<crate>-*.rlib>` for gear_app, gear_engine, gear_herdr and gear_store; run the resulting executable with a scratch database path as its sole argument.

```rust
use gear_app::{admin, Env};
use gear_engine::{EngineCfg, onboard::onboard_queued};
use gear_herdr::fake::FakeHerdr;
use gear_store::Store;
use std::{path::Path, thread, time::{Duration, Instant}};
const BASE: &str = r#"
[project]
id = "toy"
herdr_session = "scratch"
repo = "/scratch"
[quota]
lanes = 2
temps = 1
[captain]
pane = "w1:p1"
kind = "claude"
profile = "claude"
[[lanes]]
name = "heat"
duty = "heat"
owns = ["src/heat/"]
kind = "opencode"
profile = "opencode"
"#;
fn main() {
    let path = std::env::args().nth(1).unwrap();
    let env = Env { ctx: None, pane_id: None, admin: true };
    let mut store = Store::open(Path::new(&path)).unwrap();
    // A valid TOML comment makes the interval after reading the old row and
    // before reading the seat roster long enough to exercise deterministically.
    let old = format!("{}\n#{}\n", BASE, "x".repeat(32 * 1024 * 1024));
    admin::init(&mut store, &env, &old, 1800000000).unwrap();
    let changed = format!("{}\n[[lanes]]\nname = \"pricing\"\nduty = \"prices\"\nowns = [\"src/pricing/\"]\nkind = \"opencode\"\nprofile = \"opencode\"\n", BASE);
    let mut writer = Store::open(Path::new(&path)).unwrap();
    let begin = Instant::now();
    let update = thread::spawn(move || {
        thread::sleep(Duration::from_millis(50));
        let result = admin::init(&mut writer, &env, &changed, 1800000001).unwrap();
        println!("re-init at {:?}: version {}", begin.elapsed(), result.config_version);
    });
    let mut cfg = EngineCfg::default();
    cfg.db_path = path.clone();
    cfg.profiles.insert("opencode".into(), gear_herdr::builtin("opencode").unwrap());
    let mut herdr = FakeHerdr::new();
    let active = onboard_queued(&mut store, &mut herdr, &cfg, 1800000002).unwrap();
    update.join().unwrap();
    println!("onboard at {:?}: {:?}", begin.elapsed(), active);
    let pricing = store.read(|tx| tx.get_seat("toy:pricing")).unwrap().unwrap();
    println!("pricing state={}, reason={:?}", pricing.state, pricing.state_reason);
    let next = onboard_queued(&mut store, &mut herdr, &cfg, 1800000003).unwrap();
    println!("next tick onboarded={:?}", next);
    assert_eq!(pricing.state.as_str(), "needs_check", "race not hit");
    assert!(pricing.state_reason.unwrap().contains("not in the project config"));
    assert!(next.is_empty());
}
```
