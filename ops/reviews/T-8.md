## Findings
- [P1] R1: Recording a page silently adopts a newer contract that page never showed — `crates/gear-app/src/home.rs:153` and `crates/gear-app/src/tasks.rs:146`. `record_view` ignores `view.shown_contract`; `adopt_contract` rereads and consumes whatever pending marker exists at recording time. Reproduce with the existing engine-test helpers: start a v1 attempt; `bump(..., 0, "g2", "r1")`; build the lane home page (it records `shown_contract = Some(2)`); apply `bump(..., 1, "g3", "r2")`; record that saved page. Actual `(adopted_version, pending_update)` is `(3, None)` although the lane only saw v2. The v3 update is now considered adopted and will receive no update notice. One concurrent captain apply during the CLI's build/print/record sequence is sufficient. Fix adoption to use the version evidenced by this view, preserve any newer pending update, and never acknowledge an unseen version. Add the build-v2/apply-v3/record-v2 regression; `(2, Some(3))` is a valid outcome (deferring adoption while retaining the newer marker is also safe). This contradicts the report's claim that a bump between viewing and adoption is left pending for another delivery.
- [P1] R2: A routine home view after hand-in changes the submitted attempt's contract and breaks its verdict — `crates/gear-app/src/tasks.rs:139` and `crates/gear-app/src/home.rs:153`. Adoption has no attempt-state guard, and `open_attempts_of_seat` intentionally includes Submitted attempts. Reproduce sequentially: start v1; bump to v2 while working; submit the result with `--contract 1` before reading the update (submission succeeds); then build/record the lane's home page while its result is in review. Actual state remains Submitted but `adopted_version` changes from 1 to 2. An otherwise valid v1 fail verdict now returns `BadFormat: attempt 1 of task T-1 works to contract 2, not 1`; a reviewer started after the view also gets v2 criteria for the v1 submission. This loses the submitted candidate's version binding and interferes with rework. Guard adoption transactionally so a Submitted/terminal attempt retains the version it had at hand-in, including when submission occurs after page construction but before recording. Preserve the existing old-version result/verdict rule. Add regressions for bump → submit-v1 → home → fail-v1 and build → submit → record.
