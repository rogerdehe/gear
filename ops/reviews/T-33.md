The reviewer has not modified the candidate.

- **F2 [P1, blocking] The production key sequence presses Enter twice after every text** — `crates/gear-engine/src/switch.rs:109`. `SocketHerdr::pane_run` already submits text plus Enter (`crates/gear-herdr/src/lib.rs:147–157`). Consequently this helper actually sends `Esc, /model+Enter, Enter, filter+Enter, Enter`, and similarly two Enters for a variant. The second Enter can select the current picker row before the filter is typed; later text can become a prompt. FakeHerdr records PaneRun without modeling its Enter, so its current expected sequence hides the bug. **Smallest fix:** treat pane_run as text-plus-Enter and remove the three redundant explicit Enter sends in this function (roughly 5–10 changed lines); wait/check the picker and resulting dialog/bar between submissions rather than issuing the entire sequence without a readiness check. Keep pane_run's shell semantics unchanged. Update the switch test to assert the effective production sequence, including PaneRun's implicit Enter, with one submission per step.

- **F3 [P1, blocking] A conversation quote is accepted as the model, and mid-screen variant dialogs are missed** — `crates/gear-engine/src/switch.rs:67`, `:98`, `:119`. `shows_model` accepts the configured text anywhere in any returned line. It returns Already for `Please switch to DeepSeek V4.1 Flash OpenCode Go` followed by a MiniMax status bar, sending nothing. All reads use read_tail; the real adapter requests RecentUnwrapped with only 16 lines. A Select variant title more than 16 lines above the bottom is never seen, although the SOP explicitly says variants appear in the middle of the visible screen. Immediate one-shot reads also consume a failed attempt before a delayed render can confirm. **Smallest fix:** expose a full visible-pane read through HerdrRead/SocketHerdr/FakeHerdr (about 20–30 lines), use it for picker/variant/status inspection, and match the model only on the OpenCode status-bar line beginning `Build auto` (about 5–10 lines). Do not accept success while Select variant is still open; poll across a bounded wait before counting a failure. Add the two failing cases `quoted_model_label_is_not_a_status_bar` and `variant_above_tail_window_is_answered`, plus a delayed-dialog/confirmation case. This fixes the actual verification path, not general screen classification.

- **F4 [P1, blocking] Missing labels and quota reset still close the agent to change models** — `crates/gear-engine/src/quota.rs:139`, `:87`. With no labels for the next model, the code explicitly calls begin_restart, sends exit keys, then agent_start. The shipped ops/gear.toml has no models.switch entries, so the normal project still takes this path. Separately, a parked lane waking at provider reset always calls begin_restart even if labels exist. This preserves the exact OpenCode failure T-33 is meant to remove: the shared service ignores the restarted client's model environment. **Smallest fix:** replace both policy-triggered begin_restart calls with the same in-place switch path; when labels are absent, flag NeedsCheck with the missing model/config key instead of exiting (roughly 15–25 lines plus reuse of the pending-switch logic in F6). Add the real chain's picker/bar labels to the example config/report, using the exact full provider-specific filter. Tests must cover both missing labels and reset wake-up and assert zero exit keys and zero AgentStart calls.

- **F5 [P1, blocking] OpenCode starts are dispatched without enforcing the chain's model** — `crates/gear-engine/src/switch.rs:76`; missing calls at `crates/gear-engine/src/onboard.rs:260` and `crates/gear-engine/src/review.rs:435`. Neither start path calls this helper or checks a status bar; onboarding marks the lane Active immediately and reviewer start queues its packet immediately. model_start still relies on the environment that the shared OpenCode service ignores. A fresh lane can start on an exhausted default model, and an OpenCode reviewer can run on the writer's model despite the configured chain. **Smallest fix:** after an OpenCode start/adoption, while idle, resolve the already-selected chain model's labels and call the switch helper before marking startup complete/queuing work. Leave startup pending on Waiting and flag on Failed; send no task packet until Done/Already. Apply this to lane and reviewer startup only (about 40–70 lines across the two call sites and a small shared helper, excluding tests). Add start-path FakeHerdr tests for wrong bar, correct bar/no input, and Waiting/no delivery.

- **F6 [P1, blocking] An unfinished switch is forgotten as soon as the quota marker disappears** — `crates/gear-engine/src/quota.rs:110–113`, `:128–138`. The switch runs only while the current observation still has a quota flag. Reproduction: two quota ticks start a switch, the UI changes to the target's status bar without the old error, then five non-quota ticks. No Continue is queued and the stored current model is not advanced. The existing quota test passes `quota=true` manually after replacing its fake screen with a bar containing no quota marker (`:1325–1326`), concealing this case. A cleared toast, open dialog, or engine restart mid-switch makes this a normal path. Ordinary dispatch is also free to prompt while the switch is unfinished. **Smallest fix:** persist the selected target before the first UI action; resume that target before quota detection on subsequent ticks, regardless of current error text (roughly 25–40 lines using meta, like the existing restart marker). While pending, suppress ordinary deliveries for that seat. Clear the marker only after the status check and successful completion transaction, or terminal flagging. Add a recovery test that removes the quota marker, restarts the engine, confirms the target bar, and verifies no retyping and one Continue; also test that a cleared error during a failed switch still reaches the second try/NeedsCheck.

- **F7 [P1, blocking] One engine restart can record the new model but lose Continue** — `crates/gear-engine/src/quota.rs:287–305`. finish_switch commits the current model and quota reset separately before inserting the Deliver op in a third transaction. A restart after the first write leaves the new model durable with no Continue. With the old quota line still visible, recovery treats the new last model as exhausted and parks the lane instead of completing the switch. The focused test seeds exactly that reachable boundary and gets zero deliveries. **Smallest fix:** in finish_switch, commit the new model, quota reset, pending-switch clear from F6, and the one Deliver intent in a single store.write transaction (roughly 15–25 changed lines); notify the captain afterward. Recovery then sees either a pending target or a completed switch with its existing op. Verify both sides of that transaction boundary produce exactly one Continue and no restart/input replay.

- **F8 [P1, blocking] Stale idle observations allow input into a currently working agent** — `crates/gear-engine/src/switch.rs:85–110`. The helper trusts obs.idle from earlier in the tick and never re-reads the pane's occupant/status before its first key. Reproduction: create an idle observation, set the fake's agent to Working with `esc interrupt`, then call switch_in_place with that observation. It still sends Esc, /model, the filter and Enters. One captain prompt between observation and switching is sufficient; no stacked faults are needed. **Smallest fix:** immediately before switch input, agent_get the bound pane and verify the expected kind is still Idle/Done, and recheck the visible busy marker. Return Waiting with no input when working or observation fails; flag an unexpected occupant (roughly 10–20 lines). Recheck readiness before later text steps if a prior step can start a turn. Keep the existing early obs gate as an optimization. Add the failing stale-idle case and a changed-occupant case.
