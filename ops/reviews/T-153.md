## Findings

F1 [P1, blocking] Session preparation leaves the pane available to doorbells — `crates/gear-engine/src/lib.rs:330` and `crates/gear-engine/src/lib.rs:587`. Reproduce with `session_dispatch_contract::world(false)`, an unshown Open Question from p:captain to p:heat created at T, and the first tick at T. The calls include `PaneType("/new")` followed by a lane `Prompt("GEAR: 1 item(s) waiting for you ...")` in that same tick, while the assignment is still waiting and sent_at is unset. prepare_dispatch creates no Deliver op during Wait, and doorbell_inputs only checks slot_ops, so the session command and a prompt can occupy the same input; a doorbell can also provoke a check-in/work before the intended session is ready. This breaks the STABLE bar's normal-use stability requirement and the v0.4.0 promise that an unrelated task starts in its new session without a hand fix. Smallest fix: in lib.rs::doorbell_inputs, treat a pending session preparation for the seat's current open round as slot_busy (including urgent doorbells), through all nonterminal session steps, and release that reservation at completion; about 10–20 lines plus a fake-Herdr regression verifying no doorbell during Wait and eventual delivery after Ready.
F2 [P1, blocking] An onboarding fresh marker survives S1 and suppresses the next unrelated task's reset — `crates/gear-engine/src/session.rs:276` and `crates/gear-engine/src/session.rs:306`. Reproduce with a Started T-1 and an open dev round owning session old; re-onboard the seat as generation 2 with session restart and marker engine.session_fresh.p:heat=2 (the value onboard now writes). Tick S1, remove the exiting agent, tick until AgentStart uses `--session old`, set the fake session to old, and complete recovery. Accept T-1 and queue an unrelated T-2. T-2 records session_action=fresh and its assignment goes directly into old, with no /new. The marker is only consumed when round.is_none(), so preparing the recovered existing round leaves it behind after that generation has already resumed prior work. This directly breaks done sentence (1), “an unrelated task starts a new one,” and the STABLE bar. Smallest fix: consume the matching generation marker when prepare_lane prepares/resumes an existing round too, without using it to override the resume action; about 5–10 lines in prepare_lane plus a recovery-then-unrelated-task test. Retain fresh behavior for a genuinely unused first session and the existing related-session resume test.
F3 [P1, blocking] S1 never restarts a Retiring lane's unfinished round — `crates/gear-engine/src/dispatch.rs:432`. Reproduce with a Started attempt and open round owning old, set the lane to Retiring (finish current work, accept no new work), remove its agent, and tick three times. There are no recovery calls or AgentStart, whereas the same fixture in Active starts with resume arguments. decide cannot Continue a missing agent, and recover_open_rounds explicitly skips every state except Active, leaving this normal lifecycle state permanently stuck after a single crash. This violates the task's S1 requirement and the STABLE bar's requirement to fix normal-operation stability failures. Smallest fix: allow Retiring alongside Active in recover_open_rounds (one predicate change), retain the existing open-attempt/pending-op guards, and add a test proving that a Retiring lane resumes its current round without receiving another task.
F4 [P2, logged] The changed gate/dispatch fixture exceeds the individual-test timing target — `crates/gear-engine/src/merge.rs:3545`. `merge::tests::dispatch_and_doorbells_continue_while_the_gate_runs` took 19.817 s in the full suite and 13.772 s in an isolated nextest run. Logged as required by ops/REVIEW.md for a changed test above 10 s. The candidate only clears its synthetic new-session command; its Git/gate fixture and synchronization predate this change, no new sleep or polling was added, and the acceptance suite remains below the 300 s hard limit. No session-behavior regression is established by this timing observation; profile and shorten the existing fixture in the test-performance work.
