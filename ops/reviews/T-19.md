## Findings
- [P1] **F5 — Truncate the fetch diagnostic at a UTF-8 character boundary (blocking fetch-failure acceptance failure).** `crates/gear-app/src/base.rs:143` — `&joined[..400]` panics whenever byte 400 falls inside a multibyte character. Reproduce with the bare-origin fixture: create a current candidate, then set the lane's origin URL to `format!("/missing/{}/{}/{}.git", "a".repeat(151), "b".repeat(150), "界".repeat(60))` and call `require_current_base`. This is a valid pathname shape with every component below NAME_MAX; the unavailable remote is the single failure. Instead of BAD_FORMAT, the independent test panics at `base.rs:143:31`: `end byte index 400 is not a char boundary; it is inside '界' (bytes 398..401 of string)`. A failed fetch from a long non-ASCII workspace/remote path therefore crashes the CLI and drops the promised failure reason. Bound the excerpt using characters or a byte limit rounded down to a character boundary. Add a regression using a real failed git fetch with multibyte stderr that exceeds the limit, asserting an ordinary BAD_FORMAT result, a useful failure excerpt, and no stored message or attempt change.
- [P1] **F6 — Validate live identity before returning an early receipt replay (nonblocking under the milestone closing rule).** `crates/gear-app/src/mail.rs:82` — the new return at line 93 precedes `require_seat` at line 115 and applies to every message kind. The stored argument hash proves only that the input context matches the old request; it does not establish that the generation is still current, its binding is active, or the current occupant matches. Independent reproductions: send a current candidate successfully as `p:heat:1`, then separately (a) retry with `fp=None`, (b) set the seat generation to 2 and retry with the original context, or (c) void binding 1 and retry. All three return `Ok(SendResult { msg_id: "M-1", thread: "T-1:1", recipient: "p:captain", replayed: true })`; they must return NotRegistered, StaleGeneration, and StaleGeneration respectively. This regresses `docs/design/03-identity-seats.md`'s rejection of late old-session calls and the existing authentication-before-replay behavior. Validate the seat, role/state, generation, binding, and fingerprint in the same short transaction that reads the stored receipt before returning it; keep git outside transactions and retain the existing write-transaction revalidation for a new submission. Add these three replay regressions alongside the valid-caller offline replay test. No extra message or task mutation was observed, so this is not reported as a P0 data-integrity issue.
