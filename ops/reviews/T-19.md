## Findings
- [P1] **F1 — Fetch the integration ref explicitly before trusting it (blocking acceptance failure).** `crates/gear-app/src/base.rs:59` — `git fetch origin` follows `remote.origin.fetch`; success can leave `origin/dev` untouched. Reproduction using the existing bare-origin fixture: create candidate C from cached dev A; push another branch `other`; set the lane's `remote.origin.fetch` to `+refs/heads/other:refs/remotes/origin/other`; advance and push dev to B; send C with the gate enabled. The fetch succeeds, cached `origin/dev` stays A, and `mail::send` returns `Ok` and stores one message although C does not contain B. Independently observed A=`85cbe9cd8a12298de438efee5bd23a0fb4b863ed`, B=`c34157ebdcdb5aab0094b98164e3abec2476e5ac`, `stored_messages=1`. With the default fetch refspec, deleting remote dev also leaves the cached ref and the gate returns `Ok(())`. Fetch the configured source explicitly into a fully qualified tracking ref, e.g. `git fetch --quiet origin +refs/heads/dev:refs/remotes/origin/dev`, substituting the configured integration, then compare that fully qualified refreshed ref. A missing remote integration branch must refuse. Add regressions for a restricted fetch refspec and a deleted remote branch, asserting BAD_FORMAT, zero stored messages, and an unchanged attempt.
- [P1] **F2 — An already committed request can no longer replay its receipt after a fetch failure (nonblocking under the current closing rule).** `crates/gear-app/src/mail.rs:81` — the network gate executes before `run_request` checks the stored request. Reproduction: send a current candidate successfully with request id `r-1`; make origin unavailable; resend exactly the same arguments and request id. The first call creates `M-1`, but the retry returns BAD_FORMAT instead of its stored `SendResult { replayed: true }`. A lost receipt followed by an outage now tells the lane its hand-in failed even though the attempt is Submitted. This regresses the documented receipt-replay contract (`docs/design/13-cli.md:15`, `docs/design/07-mail.md:83`). Preserve authenticated replay of an identical committed request before the fetch; keep git outside transactions and keep the fetch mandatory for every new submission. Test the replay outcome, the original message id, and that no second message is stored.
- [P2] **F3 — The recovery instruction names local dev instead of origin/dev.** `crates/gear-app/src/base.rs:94` — the required phrase is `merge origin/dev into your branch, build, then hand in again`, but the implementation prints `merge dev ...`. A lane's local dev may lag after fetching; following this instruction can leave it stale and produce another refusal. Format the instruction with `origin/<integration>` and update `crates/gear-app/tests/base_gate.rs:131` to assert that phrase. The real proof above reproduces the mismatch.
- [P2] **F4 — The fetch error discards the reason the user needs.** `crates/gear-app/src/base.rs:68` — keeping only the last stderr line commonly yields `and the repository exists.`, omitting the fatal error that identified an unavailable repository or failed transport. The offline probe produced `cannot fetch origin in <lane>, so the hand-in cannot be checked: and the repository exists.` Retain a bounded stderr excerpt containing the fatal/transport line, rather than only the final boilerplate sentence. Add a failure-message assertion that the actual unavailable-remote reason survives. Refusal itself correctly remains BAD_FORMAT.
