## Findings

F1: [P0, blocking] Recheck the schema version under the migration write lock before any DDL or version stamp — `crates/gear-store/src/lib.rs:457` (also `Store::open` at line 344 and `Store::create` at line 443). `open` reads the version outside a transaction, and `migrate_up` later trusts that value after waiting for `BEGIN IMMEDIATE`. Reproduced with the real candidate CLI: start with a WAL-mode store stamped 1; another connection begins an immediate transaction and updates the stamp to 3 without committing; launch the candidate against that temporary store; let it wait, then commit the other connection. Actual: the candidate runs its v1→v2 migration, stamps 2, and proceeds until the unrelated missing-Herdr error. Expected: `SCHEMA_TOO_NEW`, version 3 retained, no migration writes. This is a schema downgrade and wrong authoritative metadata, breaking the explicit "never migrated down" safety contract and M2's bar "an error in normal use is fixed at its root." Smallest fix: in `lib.rs`, make the version reader usable with a transaction and reread inside each acquired immediate transaction in `migrate_up` and `create`; reject versions above SCHEMA_VERSION before schema/stamp writes, skip steps already committed by another opener, and select any remaining work from the locked version rather than the earlier snapshot. Keep the early pre-pragmas refusal too. This is approximately 30–50 local lines, with no redesign. Add a two-connection regression that holds an uncommitted newer stamp while an older opener waits, commits it, then asserts SchemaTooNew and preservation of version, rows, and schema; also cover two same-version openers so a committed step is not run twice.
