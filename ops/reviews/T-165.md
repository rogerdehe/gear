## Findings
F1 [P1, blocking] Adding `integrated-by` to an already accepted attempt silently does nothing — `crates/gear-app/src/tasks.rs:662` (unreachable through the existing early return at line 509). Reproduction: in the new integrated-by fixture, settle T-1 with an ordinary pass; apply a second plan at the next base with the identical pass plus `integrated-by=T-2`, where T-2 has merged and the candidate tree is on origin/dev. Both applies succeed, but T-1's merged time remains `None` and no integration attribution is written. This is the normal recovery path after auto-settlement or a failed merge; it breaks B03-01 and the STABLE bar by acknowledging an action it does not perform. Smallest fix: in `settle`, let a matching existing pass with `integrated_by` validate and write the merge time/attribution before returning, without inserting another verdict or repeating state transitions (about 15–25 lines, preferably sharing the final marking helper). Add a regression that first passes, then supplies the attribution, and verifies replay remains idempotent.
F2 [P1, blocking] A task marked merged by another task still gets its own merge launched — `crates/gear-app/src/tasks.rs:663`, consumed by `crates/gear-engine/src/merge.rs:853`. Reproduction: apply the new accepted integrated-by fixture, then call `merge::merge_passed` once with FakeHerdr. It creates `O-1`, task T-1/attempt 1, kind Merge, state Executing, despite that attempt already carrying T-2's merged timestamp. `passed_tasks` and the queued-op launch path never inspect that timestamp or attribution. Tree-equivalent/re-written candidates can therefore run another gate/merge, fail, or overwrite the attribution's merge time. This breaks B03-01's already-merged behavior and the STABLE bar. Smallest fix: make the engine skip attempts with a recorded merged time when collecting passed tasks and void pending Intended/Unknown merge ops for those attempts before launch (about 10–20 lines in `merge.rs`; retain real in-flight completion handling). Add a regression from accepted integrated-by through an engine merge tick, including a previously queued op, proving no new worker launches. Coordinate the small engine-file edit with its owner/captain.
F3 [P1, blocking] `whoami` diagnoses a different identity rule from the commands it is meant to explain — `crates/gear-app/src/identity.rs:589`. Two independent reproductions using the new bound-pane fixture: (a) carry generation 0 for a seat currently at generation 1: `require_seat` returns STALE_GENERATION, but `whoami.reason` is `None`; (b) omit GEAR_CTX in the bound pane: `resolve_env` successfully recovers the seat, but `whoami.reason` says `no GEAR_CTX in the environment`. Seat restarts and context-free pane resolution are normal supported use. Missing the actual refusal reason and inventing one for a valid caller breaks B9 and the STABLE usability bar. Smallest fix: resolve the effective environment using `resolve_env`, then use the existing read-only observation and `require_seat` checks to obtain the actual claim error, converting errors into `reason` while retaining the observed pane/seat. Do not use `prove_seat`, which can write a claim report. Preserve meaningful unbound-pane reporting (about 25–40 lines replacing the hand-written match), and add stale-generation and context-free-bound-pane regressions.
