## Findings

F1 [P1, blocking] Running-task elapsed time freezes at the last recorded step — `crates/gear-app/src/queue.rs:205`. `AttemptTimes::last()` returns Started even when the attempt is still running, so the fallback to `now` never runs. With only normal Delivered/Started timestamps at t, a queue built at t+38 minutes prints `hull  working T-1 0/60m · left 0`; its JSON also says actual_min=0. Rework similarly stops its clock at the latest recorded event. This breaks §8.3's actual/estimate facts and the STABLE bar's normal-use correctness. Smallest fix: in `actual_min_of`, use now for an in-flight task (or use the board's existing merged-or-now calculation), removing the last-event fallback, about 3–8 lines. Change the queue fixture to advance injected now with only Started recorded, without fabricating a HandedIn timestamp on a running attempt; assert 38/60m and JSON actual_min=38.

F2 [P1, blocking] A held, quota-parked or declared-waiting lane is printed as working — `crates/gear-app/src/queue.rs:234`. Queue correctly calls `idle_reason`, but `lane_line` matches Some(working) first, discarding that reason whenever the retained attempt is Started/Stopped/etc. The normal held fixture produces human `hull  working T-1 0/60m · left 0` while JSON idle is `held: captain paused`; a declared wait deliberately keeps its attempt Started, so it has the same failure. This breaks M4 done (2), “every idle lane says why,” §8.2/8.3 and the STABLE usability bar. Smallest fix: in `queue`, compute idle first and populate working only when idle is None, about 5–10 lines, so human and JSON consistently identify the lane as idle; leave its unfinished task in left. Add held/open-attempt and declared-wait/open-attempt fixtures asserting the exact shared describe text and matching JSON facts (also cover quota if convenient).

F3 [P1, blocking] Released reviewers are advertised as standby — `crates/gear-app/src/queue.rs:143`. `seats_of_project` returns durable seat history, but every Temp row is appended regardless of state and `reviewer_line` calls any row with no task or standby duration `standby`. A normal released reviewer with cleared task_id prints `review-1 standby`, although its agent/pane has been released; retired reviewers can also remain. This makes the captain's live availability view wrong during the ordinary review/release loop, breaking §8.3 and the STABLE usability bar. Smallest fix: filter Released/Retired Temp seats before appending reviewers, and reserve standby wording for actual Standby seats (render other live lifecycle states truthfully if included), about 8–15 lines. Add Active, Standby (three minutes), Released and Retired fixture rows; assert active/standby are correct and released/retired are absent in both text and JSON.
