## Findings
- [P2] A plain-form Codex entry no longer gets reasoning effort — `crates/gear-engine/src/model.rs:~118` — the old code always added `-c model_reasoning_effort=high` for Codex. A project whose `review = ["gpt-6.1-sol"]` runs on a Codex `[temps]` kind now starts Codex on its own default effort without saying so. The shipped config uses the entry form and the design doc says the effort is the entry's, so this is intended. It is logged because the change is silent for old configs. Smallest fix if wanted: a line in `docs/design/01-config.md` saying the plain form carries no effort.
- [P3] Chain position is matched by model id only — `crates/gear-engine/src/quota.rs` `next_entry`/`current_model` (~lines 195-215) — `chain_problem` treats the same model on two CLIs as two entries, but `next_entry` finds the first entry with that id. A chain listing one model twice (once per CLI) would not advance past it. Not reachable with the shipped config.
- [P3] A corrupt or unknown-phase plan is dropped silently — `crates/gear-engine/src/restart.rs:92-111` (`pending`) — it returns `None` on bad JSON, so a half-done restart would leave the seat in Missing/Starting with nothing flagging it. Needs a corrupt meta value, which only an engine bug or a hand edit produces.
- [P3] `leave_reachable` and `reserve` ignore a seat in `Held` (`restart.rs:633`, `678`) — the generation is bumped while the seat stays Held. Quota policy only acts on Active/Standby/Retiring/Parked seats, so it is not reachable today.
- [P3] `[models].on_quota.review = "fallback"` in `gear/gear.toml` does nothing — nothing reads `on_quota.review` (only `on_quota.lanes`, `quota.rs:147`). Reviewer quota fallback is out of scope, as the report says; the config line only reads as if it were live.
- [P3] After the restart the pane's scrollback may still hold the old quota text — the new agent's profile markers decide, and the quota counter is reset to 0 in `finish`, so a false park is unlikely. Noted only.
