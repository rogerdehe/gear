## Findings
- [P1] **Reconcile an interrupted start before calling agent_start again** — `crates/gear-engine/src/review.rs:373`. A restart after Herdr accepts the start but before finish_onboard commits leaves Starting/Pending with a live agent. start_reviewer reuses the binding but unconditionally calls agent_start again; neither the existing observation nor recover_on_start protects this call because there is no onboarding op. FakeHerdr refuses the second call with pane_not_available, so the code parks the live reviewer in Unknown without ever delivering its job. Probe 2 reproduces this through tick. Record durable startup intent and reconcile evidence of that same start on recovery; never blindly repeat an accepted/possibly accepted start. Recover the matching started reviewer and its packet, or explicitly park an uncertain start without another start call.
- [P1] **Commit activation and the review delivery together, or recover the missing delivery** — `crates/gear-engine/src/review.rs:388`. finish_onboard commits Active before the separate insert_op transaction at line 411. A crash or insertion error between them leaves a live, jobless reviewer. tasks_to_review excludes any Active temp at line 157, so every later tick skips it permanently, occupying the slot without starting the review. Probe 3 seeds exactly this reachable persisted state and proves three ticks never create or send the packet. Make activation plus the unique initial Deliver atomic, or recover an Active binding with a missing initial Deliver idempotently.
- [P1] **The lane still waits for settlement instead of taking its next task** — `crates/gear-engine/src/dispatch.rs:221`. lane_view always sets safe_for_next=false; decide returns None for every Submitted attempt at line 123. T-5's tick still uses this path, so a lane that hands in T-1 remains idle with independent Ready T-2 even while its reviewer runs, and time/cooldown does not resolve it (probe 4). This guard predates the diff, but T-5 explicitly promises lane continuation and does not implement it. Implement the safe-point/baseline checks and permit the next assignment when they pass, without waiting for the review/acceptance verdict; do not merely force the guard true and bypass those checks.
- [P3] **Review-verdict evidence is labelled as a view that never existed** — `crates/gear-engine/src/ops.rs:288`. The new review-verdict confirmation path shares the formatter `view <seat>/<generation> @ <timestamp>`, although its timestamp came from a verdict row and no such view is required. Record a verdict/task/attempt reference for this path so the stored explanation can be traced. This does not prevent startup and does not block the skeleton verdict.
