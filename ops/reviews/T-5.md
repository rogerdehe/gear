## Findings

- [P1] **R2-1: an accepted start is still repeated when its agent is absent after restart** — `crates/gear-engine/src/review.rs:395` and `:410`. Reproduction: interrupt tick immediately after FakeHerdr accepts agent_start but before its receipt is returned; let that agent exit while the engine is down; run recover_on_start and subsequent ticks. `accepted_start_without_visible_agent_is_started_again` observes **two accepted agent_start calls** for the same reviewer seat. There is no durable distinction between a start that has not been attempted, an explicitly refused busy start, and a possibly accepted start: agent_get(None) always falls through to another launch. This does not fulfill round-1 #1 or plan-v17's explicit “otherwise park it Unknown without another start” direction. Preserve durable start-attempt/outcome evidence: permit the first start and the proven agent_pane_busy retry, adopt a matching surviving agent, and park an ambiguous interrupted start without launching another session.

- [P1] **R2-2: cancellation during startup or before packet recovery still dispatches an obsolete review and occupies its slot** — `crates/gear-engine/src/review.rs:429`, `:483`; execution also bypasses the task check at `crates/gear-engine/src/ops.rs:210`. The original eligibility read is not revalidated in the activation/Deliver transaction. The new recover_missing_packets path does not require Verifying/Submitted at all, and the reviewer exception in check_op suppresses the last task/attempt guard. `cancelled_while_starting_still_receives_review_packet` uses the real plan::apply cancellation handler on a second database connection immediately before and immediately after agent_start. In both cases T-1 is Cancelled before activation commits, yet the temp becomes Active and receives “Review T-1 attempt 1.” A subsequent valid submitted T-2 remains Queued across ticks because this obsolete reviewer holds the only temp slot. `cancelled_legacy_active_reviewer_gets_packet_on_restart` additionally proves the newly added recovery path sends a cancelled task's packet after restart. Re-read the current task, attempt, candidate and binding when committing activation/delivery, filter legacy recovery by the same eligibility rule, and void obsolete review Deliver ops before execution. Handle an already accepted cancelled start conservatively through the seat lifecycle; do not dispatch its cancelled job or blindly free a possibly occupied slot.

- [P1] **R2-3: a supported concurrent config update can start a reviewer over the current temp quota** — `crates/gear-engine/src/review.rs:97`, `:355`. `quota_reduced_before_reservation_still_starts_reviewer` pauses at worktree_create, asserts the reviewer is still Queued and no slot has been reserved, then runs the real admin::init handler on a second connection with temps=0. The update succeeds as config version 2. The ongoing tick nevertheless creates the worktree, reserves/activates the seat, starts Codex and sends the packet: **one Active temp against current quota zero**. This is not grandfathering an already Starting/Active reviewer: the command observed it Queued. The slot check uses a stale config snapshot in a separate transaction, and begin_onboard does not check quota again. Reserve quota against the latest config and current occupancy atomically before the external startup steps. This is newly demonstrated integration evidence with T-6 on current dev; round 1 set aside speculative quota races when no such supported update path was available.
