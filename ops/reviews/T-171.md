## Findings
F1 [P1, blocking] The landing's default command selects an old voyage once the current voyage finishes — `crates/gear-cli/src/main.rs:897`. With completed M1 and freshly completed M4, the open-work set is empty and ascending milestone order returns M1; the landing item explicitly tells the captain to run `gear report voyage` without an argument. This breaks done-sentence (3), “this voyage's landing starts with that review with the user,” and the STABLE usability bar. Smallest fix: replace this command's default-selection logic with the existing `gear_app::plan::current_voyage` latest-departure rule, preserving NoTarget when none exists (about 10 lines). Add a CLI fixture with two completed voyages and a later M4 departure; the default must print M4.

F2 [P1, blocking] Fleet quota stops count any paused lane rather than all lanes being paused together — `crates/gear-app/src/time.rs:568`. `fleet_stopped` unions every lane's quota spans after discarding seat identity. Two lanes, with only A paused for one hour and B working throughout, incorrectly produce one hour of fleet stoppage instead of zero; partially overlapping pauses likewise count the union instead of the intersection. This violates §5.4 and the STABLE correctness bar. Smallest fix: retain the seat id when collecting intervals and sweep the merged per-seat spans, accumulating only intervals whose distinct paused-seat count equals the participating lane count; union those full-fleet intervals for the stop count (about 35–50 lines). Test disjoint pauses, partial overlap, and a lane with no pauses.

F3 [P1, blocking] Voyage work and waiting totals include the project's other voyages — `crates/gear-app/src/time.rs:527`. Every round and pause for a seat is summed without checking the requested milestone or clipping to departure/current report time. A round and quota pause fully before M2's departure still increase M2's work and fleet stoppage, and can force idle or elapsed-without-quota to zero. This violates §5.4 and the STABLE correctness bar in an ordinary multi-voyage project. Smallest fix: build the requested voyage's task-id set and filter rounds by it; intersect pause intervals with the voyage's measurement window before summing or collecting quota spans, dropping empty intersections (about 25–35 lines). Add a fixture with M1 history and M2 work on the same lane and assert M2 excludes M1.

F4 [P1, blocking] An ongoing quota park or declared wait is reported as idle — `crates/gear-app/src/time.rs:535`. Open pause rows have no end_at and are skipped, so a lane parked for two hours currently reports zero quota wait and zero fleet stopped time until the quota resets. A time report during those hours is normal use. This violates §5.4 and the STABLE bar. Smallest fix: use `pause.end_at.unwrap_or(now)` as the interval end, then clip it as in F3 (about 3–5 lines). Test an open quota pause and an open declared wait at an injected now, including the fleet line.

F5 [P1, blocking] Task and voyage token/cost totals omit every review round — `crates/gear-app/src/time.rs:360`. The lookup selects only role=dev/rework for each attempt, even though the rounds table and §4.2 explicitly assign review work to the reviewed task/attempt. A task with dev cost $1 and review cost $2 is reported as $1. The comment claiming reviewer work is not the task's cost has no basis in the ownership rule. This breaks done-sentence (3)'s tokens/cost per round and the STABLE accuracy bar. Smallest fix: include every stored role for the task in task/voyage sums and retain each role's counts for round output; do not add review active time to the lane's work line (about 25–40 lines alongside F6). Test distinct dev, review and rework costs and assert all are counted once.

F6 [P1, blocking] The text time report never prints a round's tokens or cost — `crates/gear-app/src/time.rs:631`. The renderer emits only task and voyage lines; `TaskTime.rounds` is never rendered. Even when JSON contains two populated attempts, the normal `gear report time` output cannot show their individual consumption. This directly misses contract v1 / §4.5 and done-sentence (3)'s per-round visibility. Smallest fix: after each task line, render its stored work/review rounds with attempt, role, tokens and cost (about 15–25 lines; keep individual roles available as in F5). Add a CLI fixture with distinct counts/costs in two rounds and assert the separate text lines, not just an aggregate substring.

F7 [P1, blocking] Voyage part 3 omits token and cost totals per lane — `crates/gear-app/src/voyage.rs:288`. Its lane rows call `lane_line`, which contains only work/quota/wait/idle; only one whole-voyage token total is printed, and neither LaneWork nor another field carries per-lane token totals in JSON. §7.5 explicitly requires “Time and tokens: totals, per lane”. This misses the contract and the STABLE usability bar. Smallest fix: aggregate the requested voyage's stored round usage by lane seat, expose those totals in the report, and print a token/cost row for each lane next to its existing work/wait row (about 25–40 lines). Preserve the two §5.4 line formats. Test two lanes with different counts and costs in both text and JSON.

F8 [P1, blocking] The voyage report includes friction from every voyage in the project — `crates/gear-app/src/voyage.rs:189`. Decisions, task times and rework are voyage-filtered, but frictions_of_project is copied without filtering the friction's task milestone. Reviewing M4 therefore shows previous voyages' open/closed issues as M4's friction, including with explicit --voyage. This violates §7.5 and the STABLE accuracy/usability bar. Smallest fix: filter friction rows through the requested voyage's task-id set before mapping them (about 8–12 lines). Add a two-voyage fixture with one open and one closed friction each and assert only the requested voyage's rows appear.

F9 [P1, blocking] Open rounds are never counted for reports and missing counts are displayed as zero — `crates/gear-app/src/time.rs:367` and `:59`; report runners at `crates/gear-cli/src/main.rs:869` and `:937`. Reports only read persisted counts. `gear-engine/src/rounds.rs:99` skips open rounds, so the last task on each lane can still have NULL counts at landing, before the user is asked about releasing lanes. The renderer then turns NULL into “tokens 0 in / 0 out”, falsely reporting no consumption. §4.3 requires reads of open rounds to count their sessions and unreadable usage to stay unknown, never zero. This breaks done-sentence (3) and the STABLE accuracy bar. Smallest fix: use the existing read-only `gear_engine::rounds::count_round` in the CLI report runners to obtain open-round counts through injected now, pass those overrides into the report construction and recompute task/lane/voyage sums; render absent input/output and cost as unknown (about 60–90 lines across the runners and token helpers). Keep the report read-only. Add a readable session-log fixture for an open round and an unreadable-log case; assert actual nonzero counts in the first and explicit unknown values in the second.
