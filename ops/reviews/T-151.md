## Findings
F1 [P0, blocking] Reviewer confirmation overwrites the developer attempt's session — `crates/gear-engine/src/ops.rs:649` and `:797`. `confirm_pending` confirms temp-reviewer Deliver ops from their verdict and then unconditionally calls `record_attempt_session`. Review delivery ops name the developer's task/attempt, while their binding belongs to the reviewer. Thus a writer attempt with `session_ref=ses_A`, `session_cli=opencode` becomes `ses_REVIEWER`, `codex` when the reviewer verdict confirms its delivery. A failed review then resumes the wrong conversation or loses eligibility to resume the writer's conversation. This corrupts persisted attempt data and breaks done (1), rework resuming its attempt's session and follow-ups keeping their session. Smallest fix: in `record_attempt_session`, return early for reviewer ops using existing `is_reviewer`, or verify that the attempt belongs to `op.seat` and `op.generation` before writing (about 3–8 lines). Add a regression with a writer attempt carrying A, a temp reviewer carrying R, a Submitted reviewer Deliver op naming that attempt, and a verdict; after `confirm_pending`, both writer session fields must remain unchanged.

F2 [P1, blocking] Closing a released round drops its final observed session — `crates/gear-engine/src/rounds.rs:68` and `:82`. The closure loop runs before the session loop. Reproduce: create an open round, tick with binding A, update the binding to B and release the seat, then tick again. The round closes correctly but its sessions remain `[A]`; B is never appended because `open_round_of_seat` now returns None. The real engine refreshes bindings in observation, releases seats later in the same tick, and only then calls this module, so a restarted reviewer that finishes before the next tick can reach this normally. Its final work is omitted from the round's usage window. This breaks the STABLE bar for normal operation and done (3)'s per-round token/cost accounting. Smallest fix: in `rounds::tick`, close superseded rounds first, append the latest session to the remaining open round, then close Released/Retired rounds (move the release block after session collection, about 15–20 lines). Add the A→B plus release-in-one-tick regression and assert `[A,B]` exactly once with the release timestamp preserved.

F3 [P3, blocking mechanical fact] New contract test fails the zero-warning build requirement — `crates/gear-engine/tests/it/rounds_contract.rs:13` and `:219`. Independent `cargo build -p gear-engine --all-targets` reports the three warnings above. Smallest fix: remove unused `OpKind` from the import and remove the unused `let mut herdr = FakeHerdr::new();` in the check-in test (two lines). This blocks solely under the required mechanical zero-warning rule.
