### Progress notes

- 2026-10-22 `mail::send` implemented; the 10 new tests in `crates/gear-app/tests/app_send.rs` pass (all 10 were red before) and `cargo build -p gear-app --all-targets` is warning-free.
- One write transaction, one `run_request`: the identity check (`require_seat`, lane/temp/captain in active/standby/retiring) runs **before** the request is recorded, so a rejected caller stores nothing.
- Routing: `--reply-to M-x` → the sender of M-x and M-x's thread; `--to <seat>` → that seat, captain only (a lane gets Forbidden); otherwise the project captain. `--to` and `--reply-to` together are BadFormat, `--about` is BadFormat (slice 2).
- States: progress → Info, question and instruction → Open. Ack, result, blocked, reply and system are BadFormat in slice 1 (their side effects belong to slice 2 / `gear reply`).
- **Deviation to decide (see "Open questions"):** the packet asks for the thread id `<task or seat>:<M-id>`, but the store allocates the message id inside `insert_message`, so the id is not known before the insert. Reserving it with `next_id` would waste one id per message and make the first message `M-2`, which breaks the captain's slice-1 acceptance (`sent.msg_id == "M-1"` and no `M-2` after a replay). The thread is therefore numbered: `<task or seat>:<seq>` (design/07's `<task>:<seq>`), the first free sequence for that prefix.
- Judgement calls to note: the thread prefix is the task id when the message carries one, otherwise the sender's seat name; the sender is written as the seat id `<project>:<name>`; `needs_ack` is always false in slice 1; the reply target of `--reply-to` must exist in the same project (NoTarget otherwise).
- No public signature changed, no dependency added, no existing contract test touched.
