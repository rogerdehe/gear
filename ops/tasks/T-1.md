# T-1 实现 gear-store

任务：T-1　合同版本：v1　负责线：A　依赖：无

## 目标

实现 `crates/gear-store/src/lib.rs` 里所有 `todo!()`，让 `crates/gear-store/tests/contract.rs` 的全部测试通过。

## 背景（必读）

## 允许修改

- `crates/gear-store/src/lib.rs`：只填函数体、增加私有辅助函数；可以把实现拆到新的私有模块文件 `crates/gear-store/src/*.rs`（在 lib.rs 用 `mod xxx;` 引入，不加 `pub`）。
- 可以删掉 lib.rs 顶部的 `#![allow(unused_variables, dead_code)]`，前提是删掉后零警告。

不允许改：`schema.sql`、`tests/contract.rs`、任何 `pub` 签名、Cargo.toml。

## 实现要点

1. `Store::open`：创建父目录；`PRAGMA journal_mode=WAL`、`busy_timeout = BUSY_TIMEOUT_MS`、`foreign_keys=ON`；执行 `SCHEMA_SQL`；`meta.schema_version` 不存在则写入 `SCHEMA_VERSION`；存在且大于 `SCHEMA_VERSION` → `ErrorCode::BadFormat`。
2. `Store::write`：`rusqlite::TransactionBehavior::Immediate`；闭包 `Ok` → commit，`Err` → rollback 并原样返回错误。SQLite busy/locked → `ErrorCode::Locked`。其他 rusqlite 错误统一映射为 `GearError`（可新增私有转换函数；code 用 `BadFormat` 表示数据损坏/类型不符，`NoTarget` 不在这里用）。
3. `Store::read`：`TransactionBehavior::Deferred`，结束时 rollback 或 commit 都行（只读）。
4. `next_id`：`id_seq` 表 upsert 自增，返回 `"{kind}-{n}"`，从 1 开始。
5. `run_request`：`args_key` 的哈希用 **FNV-1a 64 位**（自己写，十几行，结果存十六进制字符串）；已有记录同哈希 → `Replayed(stored)`；不同哈希 → `RequestConflict`；无记录 → 执行闭包，成功后写 `requests` 表并返回 `Executed`。闭包失败不写记录（错误直接返回，外层事务会回滚）。
6. JSON 字段（`payload`、`shown_msgs`、`shown_ops`）用 `serde_json` 序列化成 TEXT。
7. 布尔存 0/1；枚举存 `as_str()`，读出用 `parse()`。
8. `actionable_for`：`state='open'` 或 (`state='waiting'` 且 `wait_until` 非空且 `<= now`)，按 `created, id` 升序。
9. `slot_ops`：`kind IN ('deliver','doorbell')` 且 `state IN ('intended','executing','submitted','unknown')`。
10. `last_op`：同座位同 kind 按 `created DESC, id DESC` 取第一条（id 是 `O-<n>`，排序时按数字部分，或用 rowid 降序）。
11. `testing::seed_project`/`seed_active_seat`：按 lib.rs 文档注释的约定填值。
