- `--to <seat>` now only accepts kind `instruction` (design/07:21): a captain `--to heat --kind question` is `BadFormat` and nothing is stored. New test `to_requires_instruction`, red without the rule.
- The thread number is now computed **inside** the `run_request` closure, i.e. after the replay check: a replay returns the stored result and numbers no thread at all.
- `next_thread_seq` reads the recipient's unhandled threads in one query and takes their highest number for the prefix; the numbers a resolved thread already took are then skipped one by one, so a number is never reused (a new question never joins a resolved thread) and the pathological "10 000 queries" case of R-9 is gone.
- The thread format is pinned by the test now: `heat:1`, then `heat:2`, and `T-1:1` for a message with a task.
- Judgement call to note: the packet says "one query (max existing seq for the prefix)". The store has no query for "the threads of a prefix", so the implementation reads the unhandled threads of the recipient in one query and then checks the candidate number once (more only if a resolved thread took it). One query less than before, and the number is never reused.
- No public signature changed, no dependency added, no existing contract test touched.
