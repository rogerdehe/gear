- 2. `recover_on_start`: every Executing op of every known project becomes Unknown (with the reason "engine restarted before the call finished"); every other state is left alone; no Herdr call is made. **Store gap found:** `gear_store` reaches ops only per project (`ops_in_state`) or per seat (`slot_ops`/`last_op`) and has no "list the projects" query, so the engine cannot enumerate the projects of the database with the fixed signature. The engine therefore keeps the list of projects it wrote ops for in the store's `meta` table (key `projects`, private helper `remember_project`/`known_projects`). Every path that writes an op must register its project — an unregistered project would leave an Executing op unrecovered, and an unrecovered op may be sent again. The clean fix is a store method (`Tx::projects()`), which is the data lane's crate; the captain decides (see Open questions).
