# T-81 — the captain's GitHub side: `gear plan import-issues` and the skill

Scope: T-81 — `gear plan import-issues` prints `## NEW` blocks for the open
issues the plan does not carry yet (`gear_app::github::issue_block`), for the
captain to paste, edit and apply; and `gear --skill github` says when to choose
the mode, what the engine writes on GitHub and when, how an issue becomes a
task, and that only the engine writes.

Branch: base/t81 (code @ the hand-in commit; origin/dev merged before
verification, gate green on the merged result)

Files:
- `crates/gear-cli/src/main.rs` — the `plan import-issues` subcommand and its
  body. It reads the project's `[github]` mode from the store, asks the forge
  (`gear_forge::GitHub`) for the open issues, drops the ones the plan already
  names, and prints one block per issue through
  `gear_app::github::issue_block`. Also: it starts no engine (a read-only
  command should not open one), and its help line says what it does.
- `crates/gear-cli/Cargo.toml` — the `gear-forge` dependency.
- `crates/gear-cli/tests/it/import_issues_contract.rs` (+ `main.rs`) — 4 tests
  with a fake `gh` on the child's `PATH` (recorded JSON, as T-78's): the blocks
  of the issues the plan does not carry (the planned #12 is dropped, the block
  carries the goal, the accept from the body's first line, the priority label and
  `issue: #n`); the config's label and `--label` both narrow the query and a
  voyage file narrows the plan; a project without `[github]` says so and calls
  nothing; a lane is refused.
- `skills/gear/references/github.md` — the skill topic, short by subtraction:
  when to choose the mode, the config, the table of what the engine writes and
  when, how an issue becomes a task (import → paste and edit → apply → the
  merge closes it), and that only the engine writes with `gh` — and why that
  cannot be a hook.
- `crates/gear-app/src/skill.rs` — the `github` topic (the registry lives here;
  the same one-hunk pattern as T-85's `adopt`).
- `skills/gear/SKILL.md` — the topics table names `github`;
  `crates/gear-cli/src/main.rs`'s `--skill` help lists it; the two skill
  contract tests cover it and the install writes the file.
- `ops/reports/T-81.md` — this brief.

Decisions:
- **"already in the plan"** is the voyage file's own `issue: #n` lines when a
  path is given (the file the captain is editing, so a block pasted but not yet
  applied is not offered twice), and the store's tasks otherwise (the applied
  plan).
- **The labels**: the config's `[github.issues].labels` first, then every
  `--label` — the forge's filter is an AND on GitHub.
- **The mode is the project root's `[github]`**; importing a child repo's
  issues is not in this task (T-79 allows a child its own section; a `--repo`
  flag would be the follow-up).
- **Identity**: the captain's seat as the store knows it, without a Herdr
  fingerprint — the command only reads, and a read-only command should not
  depend on a pane.
- **A forge failure** exits 1 with the forge's own words. No `ErrorCode` fits an
  unreachable external forge, so it is `BAD_FORMAT` (the CLI's catch-all for
  "the world is not as expected"); a `Forge` code is a small `gear-model`
  follow-up if the captain wants the label exact.
