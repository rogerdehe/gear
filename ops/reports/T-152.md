# T-152 — Herdr's state decides busy and ready (design §10.2)

Whether an agent is busy is Herdr's state, never the text on its screen. Only
`idle` and `done` are ready: `working`, `blocked` and `unknown` are never ready
for a delivery, a typed command or a session action. A pi agent whose last
line says "Working tree clean" is not busy because of the word; an agent Herdr
cannot read is never handed a task.

## What changed

**The dispatch's readiness (`crates/gear-engine/src/dispatch.rs`).** A blocked
agent was the one exception: the dispatch handed a blocked seat a delivery op
("a blocked one is not working: it may be handed work"), which then waited in
the ops path for the dialog to clear (T-68). Design §10.2 says a blocked
agent is never ready, so the exception is gone: **only `idle` and `done` are
ready**, and a working, blocked or unknown agent gets no delivery at all. The
T-68 contract survives — a blocked seat is still not re-delivered every tick
and is still delivered once when the dialog clears — it just carries no op
while it waits.

**The screen text decides nothing (already true, now proved).** The profile's
busy class is gone since the profile task (T-136): `classify` keeps the quota,
blocked-dialog and error markers, and the engine's observation reads Herdr's
state for the readiness. The three rules of the design are now the contract of
`ready_state_contract.rs`:

- a **done** pi whose last line says "Working tree clean" gets its task;
- an **unknown** agent never gets one;
- a **working** agent gets only the at-once messages, as before.

**`crates/gear-engine/src/busy.rs`** reads Herdr's state as well (the
"a lane that works with no task" alert fires on a `working` agent ✓ and never
on an idle one ✓) — no change was needed there, and the contract test now
pins it.

## Files

- `crates/gear-engine/src/dispatch.rs` — the readiness rule: only `idle` and
  `done` are ready (the blocked exception is gone).
- `crates/gear-engine/tests/it/ready_state_contract.rs` (new, registered in
  `main.rs`) — the three rules of the acceptance.
- `crates/gear-engine/tests/it/blocked_delivery_contract.rs` — the T-68
  contract in its new shape: a blocked seat gets **no** delivery while it
  waits on its dialog, and it is delivered once when the dialog clears (and a
  retiring seat is never handed a task at all).
- `ops/reports/T-152.md` — this brief.

## Verification

- `scripts/test.sh` → **1060 tests run: 1060 passed, 0 skipped** (73 s; inside
  the 300 s red line). `cargo build --workspace --all-targets` → clean, zero
  warnings.
- The acceptance, in `ready_state_contract.rs`:
  - `a_done_pi_gets_its_task_whatever_its_screen_says` — the agent is `done`
    and its last line says "Working tree clean": the task is handed over and
    the packet is typed (the screen text does not make the agent busy).
  - `an_unknown_agent_never_gets_a_task` — an agent Herdr cannot read: two
    ticks, no delivery, nothing typed.
  - `a_working_agent_gets_only_at_once_messages` — a working agent gets the
    urgent message at once and the normal one waits for idle.

## Open questions

none — two decisions worth naming:

- **A blocked seat carries no pending delivery any more.** The T-68 fix was
  "not one op per tick"; now there is no op at all while the agent waits on a
  dialog. The delivery happens on the tick after the agent is idle again, and
  the blocked-seat alert (T-57) still carries the incident. A retiring seat
  is never handed a task (design/09), so its task waits for another lane.
- **A lane that works with no task** (`busy.rs`) still alerts only on a
  `working` agent: that is the T-46 incident, and Herdr's state is the only
  thing that says the lane is busy.

## Out of scope

- **The session action** (design §3.4: `/new`, `/compact`, `/resume`) belongs
  to hull's `session.rs` (T-145); it must use the same rule — never type into
  an agent that is not `idle` or `done`.
- **The typed commands of the model switch** (`switch.rs`, hull's) already
  read Herdr's state (it switches only an idle or done agent ✓).
- **The profile's markers** (the quota, blocked-dialog and error ones ✓) stay:
  they say what the agent is waiting for, not whether it is busy.
