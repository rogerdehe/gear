# T-2 — a reviewer can hand in a verdict

Scope: T-2 — `gear send --kind review --task T-n --attempt <a> --verdict pass|fail "<findings>"`: only a temp seat bound to that task may send one; the verdict is stored on the attempt's review record and reaches the captain as an action item; nothing is settled.
Branch: data/t2 (code @ 2d8fa06)
Files:
- crates/gear-store/src/schema.sql — new table `review_verdicts` (one record per attempt; `CREATE TABLE IF NOT EXISTS`, so an existing store picks it up on the next open).
- crates/gear-store/src/lib.rs — `ReviewVerdictRow` with insert/get/list, `SeatRow.task_id` (the task a temp seat is bound to), `Tx::set_seat_task`, `testing::seed_temp_seat`.
- crates/gear-model/src/state.rs — `MsgKind::Review` ("review"): the kind of the item in the captain's inbox.
- crates/gear-app/src/review.rs — the rule: a temp seat bound to that task only (lane → Forbidden, other task → NoTarget); the same verdict again changes nothing, a different one for the same attempt → BadTransition.
- crates/gear-app/src/mail.rs — `SendArgs.verdict`; the `review` kind stores the verdict in the same transaction and puts the item in the captain's inbox (Open), the verdict in its first line.
- crates/gear-app/src/plan.rs — the task packet (`gear --show T-n`) shows the review records under `## Review`.
- crates/gear-cli/src/main.rs — `--verdict pass|fail` flag; `--kind review` accepted; three CLI tests.
- skills/gear/SKILL.md — §3: one line for reviewers.
- crates/gear-app/tests/review_contract.rs — 8 tests: stored + visible to the captain, lane seat Forbidden, wrong task NoTarget, unknown task, missing verdict, replay, conflicting second verdict.
- crates/gear-store/tests/slice2_contract.rs — the new table (one record per attempt) and the seat binding.
- crates/gear-app/src/admin.rs, crates/gear-engine/src/dispatch.rs, crates/gear-engine/src/onboard.rs and six test files — `task_id: None` in the `SeatRow` literals (mechanical, forced by the new field).

Verification:
- `cargo build --workspace --all-targets` → clean, zero warnings and zero errors.
- `cargo test --workspace` → green (47 test binaries; the 13 new tests pass).
- Live smoke test of the binary against a scratch store: the verdict is stored (`review_verdicts`), the captain's home page shows `review pass on T-2 attempt 1` in the INBOX, `gear --show T-2` shows the record, a lane seat → `ERROR FORBIDDEN`, a temp seat naming another task → `ERROR NO_TARGET`, `--verdict maybe` → `ERROR BAD_FORMAT`.
- `git merge origin/dev` into the task branch before the hand-in; the merged result builds warning-free and the whole suite is green.

Open questions:
- A second, different verdict for the same attempt is refused with `BAD_TRANSITION` (the captain's own `settle` behaves the same way). If a reviewer must correct a verdict, the captain decides: allow a second record or a correction.
- The inbox item carries the verdict in its first line (`review pass on T-2 attempt 1`) so the captain sees it without opening the task; the raw findings stay in the record. Say so if the captain wants the body verbatim instead.
- `seats.task_id` existed in the schema but nothing wrote it. I exposed it as `SeatRow.task_id` and added `Tx::set_seat_task`; the engine that starts a temp reviewer must bind the seat to its task — a later task, not this one.

Out of scope:
- The engine does not settle a review: the task and the attempt keep their state (T-2 says the engine does that later).
- `docs/design/07-mail.md` does not list the `review` kind yet; the design docs are the captain's.
- The temp-reviewer onboarding (starting the temp seat and binding it to the task) is not part of this task.
