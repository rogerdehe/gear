# T-63 — The reviewer is sent the contract the hand-in was made against

Attempt 2, contract v1 — the rework of the blocking finding of attempt 1 (F1:
the packet followed the attempt's adopted version, but a hand-in could name a
version the task had already left, so the reviewer could still be sent a stale
contract).

The review packet carries the contract version the hand-in named — the newest
one at hand-in time — and that version's goal and accept, not the version the
attempt once started on (M2.1: T-58's reviewer got v1 after the lane reworked
to v2 and asked the captain which governs).

## What changed

`crates/gear-app/src/tasks.rs` (the rework's fix):

- **`submit_result` refuses a hand-in that names an older contract than the
  task's.** After it loads the task and before it writes anything, a
  `--contract` that differs from the task's current `contract_version` is a
  `BAD_FORMAT`: "… is on contract v2, not the v1 this hand-in names: run `gear`
  and `gear --show T-1` to work to v2, then hand in again". The adopted-version
  check stays (the attempt must have worked to the version it names), and the
  freeze after a hand-in stays (`adopt_contract` still adopts nothing for a
  handed-in attempt). So the version a hand-in binds is always the task's
  current one, and the reviewer is never sent a contract the task has left.

`crates/gear-engine/src/review.rs`:

- **The packet names the contract version.** A new line after the opening
  line: `Contract: v<k> (the version this hand-in was made against)`. The
  opening line keeps its shape (`Review <task> attempt <n>. Run `gear` first…`),
  so nothing that reads it changes.
- **The goal and accept come from that version.** `review_packet_for` reads the
  attempt's `adopted_version` — the version the lane worked to and handed in
  under (`gear send --kind result` refuses a hand-in whose contract differs from
  it, T-8) — and loads that contract row. The attempt's *first*
  `contract_version` is never used, so a contract rewritten mid-attempt is the
  one the reviewer judges against.

## Acceptance evidence

- `the_review_packet_follows_the_hand_ins_contract_version` (in
  `crates/gear-engine/src/review.rs`) — the attempt starts on contract v1, the
  captain rewrites the contract to v2 while the lane works (v2's goal and
  accept, the task at v2, a pending update on the attempt), the lane's page
  shows v2 and it hands in under v2. The packet then says
  `Contract: v2 (the version this hand-in was made against)`, carries
  `Goal: the revised goal` and `Accept: the revised criteria`, and does not
  carry the first goal.
- `a_handed_in_attempt_keeps_its_submitted_contract` (rework, in
  `crates/gear-app/tests/it/adopt_contract.rs`) — the same stale hand-in is
  refused with the line that reads the task again and writes nothing; after the
  lane reads its page (adopting v2) the hand-in under v2 is accepted and the
  candidate stays bound to v2.
- `a_page_built_before_the_hand_in_adopts_after_a_refused_hand_in` (rework) —
  a stale hand-in freezes nothing: the page built before it then adopts v2 and
  the hand-in works.

## Validation

- `cargo test --workspace` → **778 passed, 0 failed** on the merged result (the review module: 25).
- `cargo build --workspace --all-targets` → exit 0, no warnings.
- `git diff --check` → clean.
- The tests fail when the engine does the wrong thing (each mutation reverted
  afterwards):
  - the packet given the attempt's first version (`contract_version` instead
    of `adopted_version`) → the packet test fails;
  - the task-version check dropped from `submit_result` → both stale hand-in
    tests fail.

## Out of scope

- A contract rewritten **while the attempt is in review** is not covered here:
  the hand-in's version is fixed at the hand-in, and `settle_review` already
  refuses a verdict made against an older contract than the task's ("review
  passed attempt N on contract v1, but the task is on v2 — attempt rejected,
  rework on the current contract"), which is the captain's call, not the
  reviewer's.
- The packet's other lines (done, bar, candidate, diff, the review rules) are
  unchanged.
