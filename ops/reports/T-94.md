# T-94 — An OpenCode lane starts on its chain's model with no `[models.switch]` entry

Attempt 2, contract v1 — the rework of the review's F1, F2, F3 and F5:
the provider's display name comes from `provider.list`, the catalogue is read
for the seat's own worktree, the acceptance is driven at lane level, and this
branch no longer changes the voyage plan.

A model without `[models.switch]` labels no longer parks the seat: its labels
are derived from OpenCode's own catalogue, and an explicit entry still wins.

## What changed

- **`crates/gear-engine/src/opencode.rs`** — `derived_labels(herdr, model,
  variant, directory)`: reads `model.list`, finds the model by
  `providerID`/`id`, and builds the switch's texts as
  `<model name> <provider display name>` — the entry's `name` (else its `id`)
  and, from `provider.list` (F1), the provider's own name ("MiniMax
  (minimax.cn)", "OpenCode Go"), else the provider id. The same text is the
  status bar and the picker. The variant is the one passed in; a model the
  catalogue does not hold has no labels to derive (`None`), so the caller keeps
  its own refusal.
- **`crates/gear-engine/src/switch.rs`** — `ensure_model` first takes an
  explicit `[models.switch]` entry (unchanged: it overrides), and only when
  there is none derives the labels from the catalogue, reading it for the
  seat's own worktree (`engine.worktree_path.<seat>`, F2). When neither is
  available it still fails with the config-fault reason, now naming both facts:
  no labels and not in the model list.

## Acceptance evidence

- `a_model_without_labels_takes_them_from_the_catalogue` (in
  `crates/gear-engine/src/opencode.rs`, fake `model.list`): a model with no
  config labels gets `bar` and `picker` `MiniMax-M3.1-Flash minimax-cn`, and no
  variant; a model absent from the list derives nothing; a variant passed in
  (the chain's) rides along.

- `a_lane_starts_on_a_model_with_no_switch_labels` (F3, in
  `crates/gear-engine/src/onboard.rs`, lane level with a realistic
  `model.list`/`provider.list`): the lane has a chain and no
  `[models.switch]` entry; the engine derives the labels, the API switch puts
  the session on the model, and the seat is **Active** — with no model keys
  typed. The explicit-labels path is covered by
  `api_start_records_session_before_tui_and_sends_no_model_keys`, and an absent
  model still parks the lane (`a_model_list_that_lacks_the_model_parks_the_lane`).
