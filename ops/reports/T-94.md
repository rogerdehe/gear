# T-94 — An OpenCode lane starts on its chain's model with no `[models.switch]` entry

Attempt 1, contract v1.

A model without `[models.switch]` labels no longer parks the seat: its labels
are derived from OpenCode's own catalogue, and an explicit entry still wins.

## What changed

- **`crates/gear-engine/src/opencode.rs`** — `derived_labels(herdr, model,
  variant, directory)`: reads `model.list`, finds the model by
  `providerID`/`id`, and builds the switch's texts as
  `<model name> <provider name>` (the entry's `name`, else its `id`; its
  `providerName`, else the provider id in the model string) — the same text for
  the status bar and the picker. The variant is the one passed in (the chain
  names one through a `[models.switch]` entry); `None` otherwise. A model the
  catalogue does not hold has no labels to derive (`None`), so the caller keeps
  its own refusal.
- **`crates/gear-engine/src/switch.rs`** — `ensure_model` first takes an
  explicit `[models.switch]` entry (unchanged: it overrides), and only when
  there is none derives the labels from the catalogue. When neither is
  available it still fails with the config-fault reason, now naming both facts:
  no labels and not in the model list.

## Acceptance evidence

- `a_model_without_labels_takes_them_from_the_catalogue` (in
  `crates/gear-engine/src/opencode.rs`, fake `model.list`): a model with no
  config labels gets `bar` and `picker` `MiniMax-M3.1-Flash minimax-cn`, and no
  variant; a model absent from the list derives nothing; a variant passed in
  (the chain's) rides along.

## Validation

- `cargo test --workspace` → **814 passed, 0 failed**.
- `cargo build --workspace --all-targets` → exit 0, no warnings.
- `git diff --check` → clean.

## Out of scope (not done)

- **The end-to-end acceptance tests are missing**: a lane on a model with no
  labels *starts Active* with the API switch confirmed against the derived bar,
  and "an explicit entry wins" as a seat-level test. The derivation and the
  precedence are in place and unit-tested; the onboard/switch path was not
  driven with a fake model list in this attempt.
- **Kickoff's inventory does not print the derived labels per model** yet. The
  inventory lives in `crates/gear-app/src/kickoff.rs` (the `course` lane's
  crate) and needs the engine's derivation (or a shared helper) to print them,
  which is a cross-crate interface this attempt did not design.
- The provider display name: `model.list` entries in our fixtures carry
  `providerName`; the engine falls back to the provider id in the model string
  when it is absent.
