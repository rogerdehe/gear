# T-85 — `gear --skill adopt`, a first frame

Scope: T-85 — the adoption skill for a project that already runs: its
instruction layer, its exemplars and no-go patterns, its gate, and what to
keep / replace / drop; the two templates a captain copies into a project; and
the line that makes the standard travel with the work.

Branch: base/t85 (code @ the hand-in commit; origin/dev merged before
verification, gate green on the merged result)

Files:
- `skills/gear/references/adopt.md` — the skill text, four steps of a few
  lines each: (1) find the auto-loaded instruction layer and archive it to a
  path no CLI reads, leaving one short project file; (2) name exemplars and
  no-go patterns, with "new code meets the standard even if its neighbours do
  not"; (3) measure the gate — time, red, flaky — and build a trusted one
  first if there is none; (4) keep / replace / drop for branches, CI, release,
  tracker and docs. It ends with what the first voyage (the adoption voyage)
  must have done, what this frame does not do, and a line marking it as a
  first frame to grow from feedback.
- `skills/gear/templates/adopt.md` — the analysis template, written to
  `gear/adopt.md`, whose answers become the kickoff sheet (the instruction
  layer it found, the exemplars and no-go zones, the gate's measurement, the
  keep/replace/drop table, the adoption voyage's done-line).
- `skills/gear/templates/standard.md` — the standard template, written to
  `gear/standard.md`: what the project is, its exemplars, its no-go zones, the
  rules that differ from GEAR's, and the closing line that makes it usable.
- `crates/gear-app/src/skill.rs` — the `adopt` topic (so `gear --skill adopt`
  prints the text) and a `TEMPLATES` list that `install` writes next to the
  topics, so `gear admin install-skill` ships both templates. The registry of
  topics lives here, so this is the one hunk outside this lane's paths.
- `crates/gear-cli/src/main.rs` — the `--skill` help names `adopt`, and
  `gear --show <task>` appends the project's own `gear/standard.md` when it
  keeps one: the standard travels in every task packet, which is the packet a
  lane actually reads (the delivery says "Task packet: `gear --show T-n`"). A
  project without one is unchanged.
- `crates/gear-cli/tests/it/skill_contract.rs`, `install_skill_contract.rs` —
  the topic prints its file, names no path of the gear repo, and the install
  writes `references/adopt.md`, `templates/adopt.md` and
  `templates/standard.md`.
- `skills/gear/SKILL.md` — the topics table names `adopt`.
- `ops/reports/T-85.md` — this brief.

Decisions:
- The templates are files installed with the skill, not `--skill` topics: they
  are copied into a project, not read as instructions.
- The standard travels with the task packet through `--show` (this lane), and
  not through the review packet: that one is rendered in `gear-engine`'s
  `review.rs` (steady's path). The done-sentence's "every task and review
  packet" is therefore half-done here — the task half — and the review half
  needs one line in `review.rs`; the captain knows, and it is small.

Verification:
- `env -u GEAR_DB -u GEAR_CTX cargo test -p gear-cli` — 50 unit + 24 CLI
  tests, including `show_carries_the_projects_standard`, the `adopt` topic and
  the installed templates.
- `env -u GEAR_DB -u GEAR_CTX cargo build --workspace --all-targets` — exit 0,
  zero warnings.
- `env -u GEAR_DB -u GEAR_CTX cargo test --workspace` — 764 passed, 0 failed,
  0 ignored, zero warnings.

Open questions: none.

Out of scope: the review packet's copy of the standard (steady's `review.rs`,
above); the adoption *voyage* itself (the captain's live run on the `running/`
fixture from T-87); and any automatic edit of a project's instruction files —
steps 1 and 4 are proposed by the captain and confirmed by the user.
