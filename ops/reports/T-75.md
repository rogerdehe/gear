# T-75 — A provider back-off is not a stall

Attempt 1, contract v1.

Branch: `course/t75`; the candidate named in the hand-in includes this
report. Base: `origin/dev` at 5a1eab4, merged with the current `origin/dev`
before the hand-in.

## What shipped

Codex's provider back-off is recognised from the screen, recorded, and left
alone: a seat that waits for its provider raises no stall item, and the home
page says "provider back-off" instead of "working".

**The signs, and where they come from.** While Codex retries a request (a
429 from the provider, a dropped stream) its own source notifies the UI with

```rust
format!("Reconnecting... {retry_count}/{max_retries}")   // and "Reconnecting... waiting for network"
```

(`codex-rs/core/src/responses_retry.rs`, codex-cli 0.164.0 — the version
installed here), and the TUI renders that message as the status header above
the composer (`codex-rs/tui/src/chatwidget/streaming.rs`, `on_stream_error` →
`set_status`). The status line therefore reads, for example,
`• Reconnecting... 3/5 (2m 12s • esc to interrupt)` while the agent waits.

A **real capture** of the same run confirms the text (codex-cli 0.164.0, a
local provider answering every request `429 Too Many Requests` with
`Retry-After`, `codex exec`):

```
ERROR: Reconnecting... 1/5
ERROR: Reconnecting... 2/5
ERROR: Reconnecting... 3/5
ERROR: Reconnecting... 4/5
ERROR: Reconnecting... 5/5
ERROR: exceeded retry limit, last status: 429 Too Many Requests
```

The interactive TUI was also started in a pty against the same fake provider,
but its prompt did not submit inside the capture window, so the screen quote
above comes from the source and the message from the `exec` capture. The
marker is `Reconnecting...` and nothing more: the error text (`Rate limit
exceeded`, `exceeded retry limit, last status: 429`) stays in the transcript
after the retries are exhausted, so marking *it* would keep a genuinely stuck
seat marked as "waiting" forever. The retry header is gone the moment the
retries end.

**Changes:**

- `crates/gear-herdr/src/profile.rs`: `Profile.backoff_markers` (empty for
  every kind but codex — the other kinds' signs are M4),
  `Profile::backoff(&self, screen)` (matches only the tail window, like every
  other marker), `ScreenFlag::Backoff`, and `ProfilePatch.backoff_markers` so
  a project may set its own kind's signs.
- `crates/gear-engine/src/observe.rs`: the screen of a **working** agent is
  now read for a kind with back-off markers (and only for such a kind); the
  seat's flags carry `ScreenFlag::Backoff`. Every other working agent still
  costs no read, and `idle` is unchanged (a working seat is never idle).
- `crates/gear-engine/src/stall.rs`: `waiting_for_provider(profiles,
  observed)` — the check the goal names, with the call `profile.backoff(screen)`
  — and no stall item for a seat that waits: `alert` returns without writing.
- `crates/gear-engine/src/lib.rs`: each tick records the waiting seats per
  project (`seats_in_backoff`, in the store's meta like the captain quota, so
  it survives a restart) and reports them in `TickReport.backoff`.
- `crates/gear-store/src/lib.rs`: `seats_in_backoff` / `set_seats_in_backoff`
  (nothing is written when the set did not change).
- `crates/gear-board/src/lib.rs`: the lane's agent state reads
  "provider back-off" before any Herdr state — the home page's snapshot and
  `gear board` share the model, so both say it.
- The `gear-engine` test fixtures gained the new profile field (one line
  each, no assertion changed).

## Acceptance evidence

- `profile::tests::the_codex_back_off_is_recognised`: the codex profile
  recognises `• Reconnecting... 3/5 (2m 12s • esc to interrupt)` (and
  `Reconnecting... waiting for network`), with the 429 line below it.
- `profile::tests::ordinary_output_is_not_a_back_off`: ordinary work output,
  `Reconnected. All set.` and the bare word "reconnecting" are not a back-off.
- `profile::tests::only_the_codex_kind_has_back_off_signs_yet`: opencode,
  claude and grok keep an empty list and never match codex's sign.
- `profile::tests::a_back_off_outside_the_tail_window_is_not_current` and
  `a_project_may_set_its_own_back_off_markers`.
- `backoff_contract::a_working_codex_seat_in_a_back_off_is_recorded_and_shown`:
  a tick over a working codex seat whose screen shows the retry records
  `p:heat` and reports it; `stall::alert` for that seat opens **no** item.
- `backoff_contract::ordinary_output_is_not_a_back_off`: the same seat with
  ordinary output is not recorded, and a flagged seat rings the captain as
  before (one item).
- `backoff_contract::the_back_off_ends_when_the_screen_has_moved_on` and
  `the_wait_survives_reopening_the_store`.
- `backoff_contract::the_observation_carries_the_back_off_and_the_seat_is_found`:
  the observation carries the flag and the screen, and the seat is still not
  idle.
- `backoff_home_contract::the_home_page_shows_the_seat_waiting_for_its_provider`:
  the captain's home page line reads
  `heat · agent provider back-off · …`, and nothing says it when the seat is
  not waiting; the third test clears it when the provider answers.

## Out of scope

- The other kinds' back-off signs (M4): opencode, claude and grok keep an
  empty `backoff_markers`; their quota/rate-limit markers were moved to M4
  by the kickoff, and this task does not add them.
- A back-off seat that Herdr reports **idle** may still get one Continue
  nudge per cooldown: the dispatch's "not nudged through" list covers
  ratelimit/quota/auth, not back-off. The nudge is harmless (it waits in the
  agent's input) and the trial's stall item is what this task removes; adding
  `ScreenFlag::Backoff` to `dispatch.rs` is steady's file and a separate
  decision.
- An **already open** stall item is not resolved when the seat enters a
  back-off; it stays until the captain resolves it (the item was raised for a
  real stall). Only a new item is suppressed.
- Codex's own TUI capture in a pty: the message is captured from `exec` and
  the rendering from the source; a TUI screenshot needs a terminal harness
  this task did not build.
