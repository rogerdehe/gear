# T-91 — GitHub driven from the store (attempt 2)

Scope: T-91 rework — F2 (a later event must not run before a failed
predecessor) and F3 (an outage must not tombstone queued work), with F5 fixed
as the review asked while addressing F2; F1 is descoped by the captain to M4,
and the config now refuses `merge = "pr"` so no project is configured for a
landing that cannot work.

Branch: base/t91 (code @ the hand-in commit; origin/dev merged before
verification, gate green on the merged result)

What changed in this rework:
- `crates/gear-forge/src/sync.rs`
  - **F2**: `run_call` now answers an `Outcome` — `Done(result)` (it ran now),
    `Already` (a confirmed call from an earlier tick) or `Pending` (a failed or
    unknown call, this tick's budget spent, or the branch not there yet). A
    `Pending` call stops the task's later calls, so a close never runs before
    its merge and a verdict never overtakes a hand-in; `Already` lets the later
    ones through.
  - **F3**: the lifetime three-attempt tombstone is gone. A failed call stays
    pending and is tried again on the next tick, however long the outage, so a
    claim whose branch appears late still opens. The per-tick work is bounded by
    `MAX_CALLS_PER_TICK` (8): a backlog catches up over the next ticks instead
    of holding the tick for every call's timeout.
  - **F5**: a confirmed call is `Already`, not "done again", so a tick no longer
    reports events it reported before.
  - **F1's descope**: the pull-request landing mode is removed from the forge:
    a landing comments the engine's merge and closes the issue, which is what
    the `push` path always did. `Forge::merge` stays (T-78's contract, and M4's
    landing will use it); `sync` no longer calls it, and the config refuses the
    mode.
- `crates/gear-app/src/config.rs` — `validate` refuses `merge = "pr"` at the
  project and at each `[[repos]]` entry, with a field (`github.merge`,
  `repos[i].github.merge`) and a reason ("not in this release … use
  `merge = "push"`"). This is the one hunk in course's tree; the captain
  authorized it in the settlement of this review.
- `crates/gear-app/tests/it/github_contract.rs` — T-79's config tests moved to
  `merge = "push"`, plus a new test that the `pr` landing is refused at both
  levels.
- `crates/gear-cli/tests/it/admin_init_contract.rs` — a CLI test: `init` refuses
  a config with `[github] merge = "pr"` and registers nothing.
- `crates/gear-forge/tests/it/sync_contract.rs` — the new promises as tests
  (below); the pull-request-landing test is removed with the mode.
- `ops/reports/T-91.md` — this brief.
