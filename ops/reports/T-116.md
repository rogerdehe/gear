# T-116 — a dead temp seat frees its slot

Scope: T-116 — a reviewer seat that runs no reviewer (parked, its binding ended, no agent ever ran in it) is released: it holds no temp slot, the count of temps in use never passes `[quota].temps`, and the next review takes the seat. A detached worktree answer from Herdr — no `branch` field — is read as detached instead of "worktree reply is incomplete".

Branch: `hull/t116`; the candidate named in the hand-in carries this report.
Base: `origin/dev` merged into the branch before the hand-in (never rebased).

## The case (trial B02-04)

The trial showed `temps 4/2` with no reviewer running. Two things made that
possible:

1. A reviewer seat parked as `Unknown` (its start failed — the pane was never
   looked at again) **holds a temp slot for ever**: a parked seat is never
   retried (design/10), so nothing frees it and no review starts.
2. The start that parked it was the worktree open: when the seat's checkout is
   **detached** (its HEAD kept, the branch let go of — T-69's holder detach),
   Herdr answers without a `branch` field, and `worktree_from_reply` called
   that "worktree reply is incomplete" → `Uncertain` → the seat parked as
   `Unknown`.

## The change

**1. A dead temp seat is released.** `release::release_dead_temps` (new): a
temp seat that is parked (`Unknown`) and holds no live reviewer — its binding
ended, or its pane hosts no agent — is released: its binding ends, its pane is
closed, the seat becomes `Released` (the state that holds no slot, design/10).
Its worktree stays; the next job on the seat reopens it.

A seat whose agent still runs keeps its slot: that is a reviewer a human has
to look at, not a dead one. A pane that cannot be read is an observation
failure, not an absence (design/08) — the seat keeps its slot.

The release runs in the tick **before** the reviews start (step 6a), so the
review takes the freed seat in the same tick.

**2. The count of temps in use never passes the quota.** The seats that hold a
slot are exactly the ones that run (or are starting) a reviewer; with the dead
ones released, the engine's own slot check (`has_free_slot`) and the board's
`in_use` count stay within `[quota].temps`. The trial's `temps 4/2` with no
reviewer running becomes `temps 0/2`, and the next review takes the free seat
(`temps 1/2`, one reviewer).

**3. A detached worktree answer is detached, not incomplete.**
`worktree_from_reply` requires the workspace, the pane and the path; a reply
**without a `branch`** is a named worktree whose checkout is detached (the
branch field is simply absent). The engine never needs the branch — its pane
and path are what it starts the reviewer with — so the review goes on.

And the review start no longer parks the seat on an answer it could not read:
an `Uncertain` worktree open leaves the seat as it is (waiting, no slot held)
and the next tick opens the worktree again — the seat is never left unknown.

## Live check (2026-10-26, Herdr 0.19.1, macOS)

A scratch git repo, a worktree on `home/review-x`, then its HEAD detached:

```
$ git -C <worktree> checkout --detach          # HEAD is now at eb1e0e5 one
$ herdr worktree list --cwd <repo>
  branch='home/review-x' detached=False ...
  branch=None           detached=True  path=/Volumes/Data/.herdr-worktrees/repo/home-review-x
$ herdr worktree open --cwd <repo> --path <worktree> --label t116-check --no-focus
  {"type":"worktree_opened", "workspace_id":"w9T", "pane_id":"w9T:p1",
   "worktree":{"is_bare":false, "is_detached":true, "is_linked_worktree":true,
               "is_prunable":false, "label":"repo", "open_workspace_id":"w9T",
               "path":"/Volumes/Data/.herdr-worktrees/repo/home-review-x"}}
```

The reply has **no `branch` field** for the detached checkout — the exact
answer that used to park the seat. The scratch workspace and worktree were
closed and removed again; the scratch repo was deleted.

Out of scope:
- A seat parked `Unknown` **with a live agent** keeps its slot: it runs a
  reviewer a human has to look at (design/10). Releasing it would leave an
  orphan agent; the captain's item still names it.
- `Releasing` seats that never go (a pane that cannot be closed) keep their
  slots: they run something, and the existing release step retries them.
- The **board's** count (`gear-board`, deck's crate) needed no change: it
  counts by seat state, so a released seat stops counting.
