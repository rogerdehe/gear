# T-136 — the profile session fields, attempt 1

Scope: T-136 — the profile fields of design §2 and §13.3 in
`crates/gear-herdr/src/profile.rs`, with the live checks of §12 (items 4 and 6),
and the busy class of §10.2 (the profile part).

Branch: `deck/t136` (code @ the hand-in commit; `origin/dev` merged before
verification, the gate green on the merged result)

## What changed

**`crates/gear-herdr/src/profile.rs`** — the fields of §2 and §13.3:
- `Profile` gains `new_session: String` (the slash command the engine types to
  start a new session), `compact: String` (empty = the CLI has none),
  `usage_log: Option<String>` (the reader of §4.3 that reads this CLI's
  records) and `error_markers: Vec<String>` (the signs that the provider
  answered with an error, §12 item 6);
- the built-in profiles carry the values of the §2 table: pi, codex and
  opencode get `/new` and `/compact`, claude gets `/clear` and `/compact`;
  the usage logs are `pi-jsonl`, `codex-rollout`, `claude-jsonl` and
  `opencode-db`. Grok is not one of the kinds of §2 and was never checked
  live, so its session fields stay empty and its usage log is None;
- §12 item 4: the codex profile exits with the typed `/quit` command and has
  **no exit keys** any more (a second ctrl+c reached the shell after Codex
  had gone and broke the next typed start);
- §12 item 6: the pi profile's error markers are `overloaded_error` and
  `Retry failed after` — a provider error, not a spent quota (§9.2). They
  have their own class, `ScreenFlag::Error`;
- `ProfilePatch` accepts the new fields, so `[profiles.<kind>]` can override
  `new_session`, `compact`, `usage_log` and `error_markers`;
- §10.2: `classify_screen` returns **no busy class** any more. The busy
  markers stay in the profile (and in the patch) so that an old config still
  loads, but they decide nothing: whether an agent is busy is Herdr's state.
  The busy markers are also out of `validate_template`, which used to refuse a
  template that held one.

**The engine's callers of the busy class** (three lines, in two files of other
lanes — they had to change with it, or the code would not build):
- `gear-engine/src/observe.rs`: the idle of a seat is Herdr's state
  (`idle_or_done`), not the absence of a busy marker on its screen;
- `gear-engine/src/switch.rs`: the two guards that kept the switch from
  typing into an agent that looked busy on screen are gone. Both places
  already read Herdr's status (idle or done) right before they type.

**The tests that carried the old rule** (in the same two lanes' test files):
- `gear-engine/tests/it/eng_reconcile.rs`: an idle agent with a busy marker on
  screen is idle — Herdr's state decides;
- `gear-engine/tests/it/slice1_messaging.rs`: an idle captain is rung even
  when its screen carries the old busy sign;
- `gear-engine/tests/it/reviewer_quota_contract.rs`: the codex reviewer is
  told to exit with the typed `/quit`, and no key is sent any more;
- the `Profile` literals of the engine's tests name the new fields.

**`crates/gear-herdr/tests/it/session_fields_contract.rs`** — the tests of the
acceptance: the four fields per kind (pi, codex, claude, opencode), a patch
that overrides them (and one that empties the compact command), the screen
never classifying busy (`Working tree clean`, `esc to interrupt`), the codex
exit and the pi provider error.

## Open questions

- **The name of the provider-error markers.** §12 item 6 says "the pi
  profile's error markers include `overloaded_error` and `Retry failed after`",
  and §10.2 says `classify` keeps "quota, blocked-dialog and error markers".
  The profile had no such list, and neither the quota markers, the rate
  limit markers nor the back-off markers fit (the overload is a 529, not a
  429, and pi had already given up, so it is not a back-off either). The
  profile therefore gains `error_markers` and the screen class
  `ScreenFlag::Error`; T-148 (the quota of §9.2) reads that class to tell a
  provider error from a spent quota. If the captain meant another list, it
  is a rename in one file.
- **The models' `context_window_k`.** The task names it, but the `[[models]]`
  entries are parsed in `crates/gear-app/src/config.rs` — hull's file under
  the M4 ownership split — and T-147 (hull) names "models'
  `context_window_k`" itself. The profile side of §2's row is done here: the
  profile carries no context window, the value comes from the model config.
  I did not edit hull's file, to keep the lanes apart.
