# T-250 — The review packet names a diff of the task's own change

Scope: `crates/gear-engine/src/review.rs` (the packet line in `fn
review_packet` and the asserts on it), one integration assert in
`crates/gear-engine/tests/it/multi_repo_contract.rs`, and this report.

Candidate: the tip of `hull/t250`, started from `origin/dev` (`699c4d7e`).

## What changed

`fn review_packet` now prints:

```
Diff to review: `git diff {integration}...{candidate}` (three dots: the change since the merge base)
```

`{integration}` is the same value as before — the task's repo integration
branch (`web-dev` in the multi-repo config, the task's original base after a
rebind, the per-repo base in the two-repo case). Three dots ask `git diff` for
the change since the merge base, so a lane that merged the integration branch
(or an integration branch that moved on) no longer adds other tasks' changes
to the reviewer's diff. The rest of the packet is unchanged.

## The tests

Updated the asserts that named the old two-dot line:

- `review::tests::a_result_in_starts_one_reviewer` (the packet text delivered
  to the seat: `git diff dev...abc1234`);
- `review::tests::a_review_works_in_the_repo_of_the_task` (`web-dev`);
- `review::tests::review_after_a_rebind_uses_the_tasks_original_repo_and_base`
  (`original-base`);
- `review::tests::a_warm_reviewer_returns_to_its_saved_repo_checkout` (the
  per-base case, formatted from `{base}`).

The packet shape is asserted in full (the literal line, not just a fragment),
so a packet that kept the two-dot form cannot pass.

`crates/gear-engine/tests/it/multi_repo_contract.rs` asserted the same line for
the two-repo contract (`feat`); it was updated with the same expected string so
`make gate` stays green. That is the only change outside `review.rs`; the task
packet counted three, this is the same line seen from the integration test.
