# T-117 — every lane in the tail while required work remains

Scope: T-117 — when every lane is in the tail and a required task is still
ready or waiting, the captain gets **one** item in the inbox naming the tailed
lanes and the required tasks; a later tick adds none, and the item closes when
the tail is cleared or no required task remains.

Branch: `hull/t117`; the candidate named in the hand-in carries this report.
Base: `origin/dev` merged into the branch before the hand-in (never rebased).

## The case (trial B02-08)

`- tail:` silences a lane's dry/idle warnings until it is cleared — the plan
says it is for a lane with no valuable work left, never for a dependency wait.
The trial's captain tailed **every** lane during a wait and forgot: every
warning was off and nothing said that required work was standing (the feed's
`lane X is IDLE` items are exactly what the tail suppresses).

## The change

A new engine step, `tailed::watch`, runs in the tick after the keep-lanes-fed
watch (step 6c) and keeps **one** item per project in the captain's inbox:

- **The state**: every lane of the project (its lane seats, retired ones left
  out) is in the tail **and** a required task is `Ready` or `Waiting`. A
  running or verifying required task is in a lane's hands; a done, failed or
  cancelled one is gone.
- **The item**: one `System` item in the project's `all-tail` thread, written
  once when the state begins, naming the tailed lanes and the required tasks
  (`T-3 (ready), T-5 (waiting)`), and saying how to clear the tail. It is not
  urgent: it is a fact the captain should see, not a stuck lane — it waits in
  the inbox (`Open`) until the state ends.
- **One per state**: a second tick finds the open item and adds nothing.
- **Closing**: when the state ends the item is resolved, with the reason —
  *the tail is cleared* (a lane is out of the tail again) or *no required task
  remains* (the work ended). A state that begins again opens a fresh item.

The tail itself is unchanged: it still only silences warnings, and a tailed
lane still takes work it is given.

## Files

- `crates/gear-engine/src/tailed.rs` — the step: the state, the item, the
  close, with four unit tests (one item and no second, closed when the tail is
  cleared, closed when no required task remains, nothing when a lane is free
  or the project has no lanes).
- `crates/gear-engine/src/lib.rs` — tick step 6c, and the tick report names
  what happened (`all-tail:opened|closed`).
- `crates/gear-engine/tests/it/all_tail_contract.rs` — the contract through
  the engine's tick: all lanes tailed with a required task → one item (naming
  the lanes and the task, not urgent); the next tick adds none; clearing one
  lane's tail resolves it; the required task ending resolves it; one lane out
  of the tail opens nothing.
- `ops/reports/T-117.md` — this brief.
