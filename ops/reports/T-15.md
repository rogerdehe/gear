## How a limit turns into a switch

1. The observation reads the lane's screen (idle/done only) and sets the `Quota` flag from `Profile::quota_markers`.
2. Each tick counts consecutive quota screens in the store's meta; the profile's `confirm_rounds` (2) confirms it.
3. `fallback`: the chain is `[models].lanes` (or the lane's own `models`), the current model is the one the last switch recorded (else the first), and the next one is taken. Two ticks: the exit keys, then — with the pane a shell again — the environment line with the new model, the agent with the unattended args, `--standalone` (opencode) and the resume args with the binding's session reference, and `Continue T-<n>: run \`gear\` first`.
4. `wait` or an exhausted chain: `Parked` with `now + [models].quota_reset_h` hours in the reason and in the meta; at the deadline the same sequence brings the lane back on the first model.
5. The switch or park is one line in `TickReport.quota` (the engine log) and one information line to the captain's inbox.

## Rework (round 2)

The review sent this back with three P1s:

- **F1 — an OpenCode restart began a new conversation.** The resume args were only used when the binding had a session reference, and the OpenCode profile reports none (`session_ref = false`), so the lane came back on the next model with an empty context. The engine now takes the id the CLI prints on exit (`Continue  opencode -s <id>`, the SOP's own line), stores it on the binding, and resumes that conversation. No id anywhere → the lane is **not** restarted blind: the seat goes NeedsCheck for a human.
- **F2 — the restart tick still flagged the lane.** `begin_restart` reset the consecutive-quota counter before `confirm_pending`, which then spent the delivery's check budget and flagged the seat. The counter is no longer reset there: the old agent's screen still shows the limit, and the counter returns to zero when the screen does.
- **F3 — the environment line could be typed into an agent.** `finish_restart` typed it without looking. It now reads the pane first: a shell takes the environment line and the start; an agent of the seat's kind means the start was accepted before the engine died, so it is adopted (the seat goes Active and gets its Continue delivery); another agent, or an unreadable pane, parks the seat for a human.

Three regressions cover them (`an_opencode_restart_resumes_the_same_conversation`, `without_a_session_id_the_lane_is_not_restarted`, `the_restart_tick_does_not_flag_the_lane`, `the_environment_line_is_not_typed_into_an_agent`), each walking the restart tick by tick, which is the restart-between-steps case the review asked for.

## The one judgement call

The engine's per-seat state (the quota counter, the current model, the reset deadline, the restart in progress) is kept in the store's `meta` table under `engine.<what>.<seat>`. The `seats` table already has `park_until`, which is where the deadline belongs, but gear-store exposes no setter for it (`gear-store` is the data lane's crate). A `set_seat_park` API — and then moving the deadline there — is the follow-up; until then the reason on the seat also carries the time, so a human reading the seat sees it.
