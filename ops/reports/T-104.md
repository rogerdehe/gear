# T-104 — A seat claim is proven by the caller's real pane, and the captain can be handed over

Attempt 2, contract **v2** — the rework of the review's F1, F2 and F3.

Branch: `course/t104` (the rework continues on the task's branch); the candidate
named in the hand-in includes this report. Base: `origin/dev` merged into the

## Rework (attempt 2)

**F1 [P0] — the ancestry walk never runs `ps` from `$PATH`.**
`process_ancestors` used `Command::new("ps")`, so a shell that prepends a
directory with an executable `ps` could print the captain pane's pid and fake a
whole ancestry. The walk now asks the OS itself: `/proc/<pid>/stat` on Linux
(no process spawned), else the system `ps` at an **absolute path**
(`/bin/ps`, `/usr/bin/ps`) — `$PATH` is never consulted.
Regression `a_path_provided_ps_cannot_fabricate_ancestry`: a fake `ps` (a
script printing `424242`) is put in a temporary directory, the test binary is
run as a **child** with that directory as its whole `PATH` and a probe that
prints the ancestry it computes; the probe asserts the forged pid is not in it,
and the outer test asserts the probe ran.

**F2 [P1] — the seat-binding half of the claim raises the item too.**
`observe_identity` validated only the pane. A caller with the captain's
`GEAR_CTX` and its own genuine `HERDR_PANE_ID` (a correct pane, the wrong seat)
passed observation and was then refused by `require_seat` **without** an item.
The claim is now proven in one place, `identity::prove_seat`: observe (real pane
= claimed pane), then `require_seat` against the seat's binding in a read
transaction; a `NotRegistered` from either step is reported once to the captain
naming the real pane. The CLI is a one-line call to it.
Regression `a_partial_claim_is_refused_with_one_item`: the captain's context
with the lane's own pane id → `NotRegistered`, exactly one urgent
`identity:w1:p2` item, and a repeat adds nothing.

**F3 [P0] — a registered project's `gear admin init` proves the captain too.**
The command never observed Herdr: a lane (or any shell with `GEAR_ADMIN=1`) could
send the captain's `GEAR_CTX` and change the project's configuration. The
`init` path now goes through `admin::init_checked`, which — when a context is
present **and the project is already registered** — opens Herdr, proves the
caller is the captain in its bound real pane (`identity::observe` +
`require_seat(..., Captain, ...)`), and reports a refusal with the same one
urgent item before anything is written. The first registration (no seats yet)
and the user's own shell keep their flow and need no Herdr; an unreachable
Herdr refuses the claim (fail closed) instead of skipping it.
Regression `a_forged_captain_claim_cannot_re_init` (fake Herdr + fake process
table): the captain's context with the lane's pane → `NotRegistered`, the
project stays at config v1 with its old text, exactly one urgent item naming
`w1:p2`; the captain in its own real pane then re-applies the same config (v2).
The two CLI tests that re-initialised from a captain's context without a Herdr
now assert that refusal (the successful re-apply is covered by the library test,
which has a fake Herdr for the pane).

## Still as shipped (attempt 1, contract v2)

- Identity: the pane the caller really runs in — its process ancestry matched
  against Herdr's `pane.process_info` (`shell_pid`, foreground pids) over every
  pane of the session (`panes()` via `pane.list`, agents and shells alike).
  `GEAR_CTX`/`HERDR_PANE_ID` only say which seat is claimed; a `NotRegistered`
  refusal names both panes and raises one urgent, deduplicated item.
- Role is the store's binding: a captain restarted in the same pane is still the
  captain.
- Handover: `gear captain handover --pane <id>` rebinds the captain seat at a
  new generation (old bindings voided, kind from the agent in the new pane),
  allowed only from the captain's real pane or an agent-free shell (the user's
  terminal, project from the cwd when there is no `GEAR_CTX`); a lane or
  reviewer asking is refused with one urgent item; the command never starts the
  engine.

## Notes / out of scope

- The ancestry walk asks the OS, so it still runs on a platform where neither
  `/proc` nor an absolute `ps` exists — then it stops at the caller itself and
  the claim is refused (fail closed).
- A process that detaches from its pane (`setsid`) is in no pane's process tree
  and is refused; the skill has agents run `gear` in their pane.
- `pane.process_info` is Herdr 0.9.0's method; an older daemon fails the read
  and the identity is refused (fail closed).
- The CLI's seat commands still cannot be exercised end-to-end without a Herdr
  socket; the identity/handover/init proofs are covered with the fake Herdr and
  a fake process table at the library level.
