# T-104 — No agent can claim another seat

Attempt 1, contract v1.

Branch: `course/t104`; the candidate named in the hand-in includes this report.
Base: `origin/dev` merged into the branch before the hand-in.

## The hole

`gear` took a caller's seat from `GEAR_CTX` (and cross-checked `HERDR_PANE_ID`),
both ordinary environment variables: any agent could export the captain's
context and pane id in its own shell and act as the captain. The pane check in
`require_seat` compared two environment values, so it proved nothing.

## The check

The seat is the pane the caller **really runs in**, and the fact that says so is
Herdr's: `pane.process_info` (Herdr 0.9.0) reports the pane's `shell_pid`, its
foreground process group, the terminal and each foreground process.

- `gear-herdr`: `PaneProcessInfo` / `PaneProcess` and
  `HerdrRead::pane_process_info` — the real client calls `pane.process_info`
  and parses `process_info`; the fake reports per-pane processes and, by
  default, claims the process that asks (every existing fixture runs `gear` as
  itself), with `set_pane_processes` to make a pane claim someone else.
- `gear_app::identity::observe` now reads the claimed pane's processes and
  refuses a caller that is not in them: `claims_pane` is true when the pane's
  shell or a foreground process is an **ancestor** of this process (its PPID
  chain, read with `ps`), or when the pane's terminal is this process's
  controlling terminal. Both are Herdr's facts; an environment variable cannot
  produce either.
- The refusal is `NotRegistered` and names the truth: `pane w1:p1 is claimed as
  a seat, but this process runs in pane w1:p2: GEAR_CTX and HERDR_PANE_ID can be
  set by any shell; the pane's processes cannot`. `pane_of_this_process` finds
  the real pane by asking every observed pane for its processes.
- `identity::report_claim` writes **one urgent item** to the claimed project's
  captain, naming the real pane, deduplicated per real pane while it is open.
  The CLI calls it on every refused identity (`observe_identity`), so the
  command still fails with the refusal and the captain is rung; a repeat claim
  from the same pane adds nothing.

The engine uses none of this (it never claims a seat), and the
`gear admin init` path (no `GEAR_CTX`) is untouched.

## Acceptance (tests)

`crates/gear-app/tests/it/app_identity.rs`, with `FakeHerdr`:

- `a_caller_outside_the_bound_pane_is_refused_and_the_captain_hears_it` — the
  captain's pane reports a process that is not this caller's; a caller using
  the captain's `GEAR_CTX` and pane id is refused `NotRegistered`, the message
  names both the claimed pane and `w1:p2` (where it really runs) and says why
  pids beat env; `report_claim` writes exactly one **urgent**, open item in
  `identity:w1:p2` naming the real pane, and a second claim writes nothing.
- `a_caller_in_the_bound_pane_is_accepted` — the lane in its own pane is
  observed and `classify` makes it `Caller::Seat` for `p:heat`.
- `the_captains_own_commands_pass` — the captain in its own pane is still the
  captain.

## Notes / out of scope

- A process that detaches from the pane (`setsid`) loses both signals and is
  refused; the skill has agents run `gear` in their pane, which keeps the
  ancestry and the terminal.
- The real-pane search looks at panes that host an agent (what `HerdrRead`
  exposes); a caller in a pane with no agent is still refused, and the item says
  the session does not know the pane. `pane.list` could widen it.
- `pane.process_info` is Herdr 0.9.0's method; an older daemon fails the read,
  which refuses the identity (fail closed, like every other identity read).
- The `push-check` hook keeps its best-effort identity read: its decision is
  the allow-list, not a seat action.
