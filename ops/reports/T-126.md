# T-126 — A captain is started with plain `claude` or `codex` and becomes the captain with one command

Scope: T-126 — three parts, all shipped: Codex is a daemon kind like OpenCode; a caller needs no `GEAR_CTX` (its pane's active binding is the seat); and `gear captain take` makes the pane the captain in one command, with an urgent item saying which pane took it and which it left.

Branch: deck/t126 · contract v1 · cut from `origin/dev` 1e6298b.

Files:
- `crates/gear-app/src/identity.rs` — `is_daemon_kind` (one list: `opencode`, `codex`) replaces the opencode-only exception in `observe`, so a Codex TUI's tools — which run in the shared `codex app-server`, not under the pane — keep their claim on a Codex pane, still checked against the binding by `require_seat`. New: `caller_pane` (ancestry, else `HERDR_PANE_ID`), `seat_bound_to` (the seat whose **active** binding is on a pane), `daemon_pane` (the one daemon-kind pane bound to a seat, or to none), `resolve_env` (no `GEAR_CTX` → the pane's seat gives project, seat and generation — the same `GearCtx` the env would have carried; `GEAR_CTX` stays an override; a pane with no seat stays anonymous; a caller in no pane in a session with agent panes gets the error naming `gear captain take`).
- `crates/gear-app/src/captain.rs` — `take()`: the caller's pane (ancestry, `HERDR_PANE_ID`, or the one unbound daemon pane), the project from the cwd (as handover), the pane must host an agent and must not be a lane's or a reviewer's, then the shared `rebind()` (extracted from `handover`) moves the captain seat to a new generation, voids the old bindings and writes one urgent item (`captain:take`) naming the pane it took and the pane it left. ## Out of scope

- `gear admin init` / `admin stop` / `admin install-skill` / `plan import-issues` do not resolve a caller from its pane: they are user commands (or, for `import-issues`, need no Herdr), and resolving `init` from a pane would decide who may register a first project. Logged, not reworked.
- With **two** daemon-kind panes bound to seats, a caller whose tools run in a daemon gets no answer instead of a guess (`resolve_env` → the `gear captain take` hint); it must name itself.
- The T-104 trust model is relaxed exactly as far as a daemon CLI forces: a caller whose ancestry reaches no pane keeps the **env** claim on a pane of a daemon kind (so a Codex tool shell can claim the captain's Codex pane by setting `GEAR_CTX`/`HERDR_PANE_ID`). This is the packet's rule ("Codex daemon mode passes like OpenCode"); closing it needs a per-session fact the adapter carries (the open item for OpenCode in `ops/plan/m3.1-backlog.md`, item 9).
- `captain take` starts no engine (it moves a binding, like a handover) and never starts a CLI: the pane must already host one.
