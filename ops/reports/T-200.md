# T-200: reviewer reservation and current model

An Active reviewer being released now loses its old task binding, and reserving a free or previously bound reviewer clears the binding while recording the new pending job. Pending-job lookups prefer that reservation, including release and checkout checks; a stale pending reservation is cleared before checking an Active reviewer's actual job. A same-task re-review no longer treats its previous delivery as the new pending job.

Before delivering to a Standby reviewer, the selected model is compared with the current `engine.model` as well as the saved startup entry and arguments. A mismatch follows the existing release and restart path. Unmanaged review models retain their existing behavior.

The regression tests exercise an Active cancellation, Released seat reuse, a busy first start and release sweep, then successful delivery of the new task. Another test drives `restart::advance` from sol to astra, returns the reviewer to Standby with the writer on astra, and verifies no re-review delivery until sol is restored. Additional cases cover stale same-task deliveries and stale invalid reservations.

Validation: the reviewer unit group passed 37 tests; the final `scripts/test.sh` run passed all 1,150 tests with zero failures or skips on integration base 3bd4ccc1bed8d4f8138c736a79866caaf6ca8e59. The build took 45 seconds and the suite took 83 seconds wall time under shared load; several existing tests exceeded the 10-second warning threshold.
