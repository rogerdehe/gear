# T-68 — A blocked seat is not re-delivered every tick

Attempt 1, contract v1.

While Herdr reports a seat blocked, the engine typed the same delivery into the
dialog every ~4 s, and each attempt filed a failed op (trial G09). Now a
blocked seat keeps **one pending delivery** and gets no new op; the
blocked-seat alert carries the reason to the captain; when the seat works or is
idle again it is delivered once.

## What changed

- **`crates/gear-engine/src/dispatch.rs`** — a blocked agent is not a working
  one: it may be handed work (`decide`: `!obs.idle && !blocked` is the "not
  idle" refusal). Its delivery then waits in the store instead of being typed
  into the dialog. A delivery already pending still holds the seat's slot, so
  no second op is made.
- **`crates/gear-engine/src/ops.rs`** — a `Deliver` op whose seat is in a
  blocked spell (`blocked::holding`, the timer `blocked::check` started) is
  **not prepared**: it stays `Intended` and the next tick looks again. That is
  the "one pending delivery, no failed ops" rule: the prompt is never sent into
  a dialog, so nothing fails and nothing is retried.
- **`crates/gear-engine/src/blocked.rs`** — `holding(tx, seat)`: whether the
  seat's blocked timer is live. It is cleared by the existing recovery when the
  seat is not blocked any more, so the delivery goes out then, once.

## Acceptance evidence (`crates/gear-engine/tests/it/blocked_delivery_contract.rs`, fake Herdr)

- `a_blocked_seat_keeps_one_pending_delivery_and_gets_one_after_it_clears` — a
  lane whose agent is blocked, one ready task, ten ticks: exactly **one**
  delivery op, still `Intended`, and **nothing typed** into the pane (no failed
  ops to pile up). The dialog is dismissed (the agent idle): the same op is
  submitted, exactly one prompt reaches the lane, and it is the task's.

## Validation

- `cargo test --workspace` → **790 passed, 0 failed**.
- `cargo build --workspace --all-targets` → exit 0, no warnings.
- `git diff --check` → clean.
- The test fails when the engine does the wrong thing (each mutation reverted
  afterwards):
  - the blocked guard dropped from the executor → the delivery is attempted
    into the dialog and the op is `Failed` (`agent_blocked`) instead of
    pending;
  - the blocked allowance dropped from the dispatcher → no op is made at all.

## Out of scope

- **The stall alert** for a seat whose delivery waits: the seat is idle-with-a-
  pending-delivery, which the existing stall check judges like any other
  unconfirmed delivery (its budget and flag). The blocked-seat alert (T-57) is
  the one that names the dialog; making the stall check skip blocked seats is a
  separate concern (T-70's alert life cycle).
- A **reviewer** seat that is blocked keeps its packet pending by the same
  rule; its nudge (L-53) still only fires for an idle agent, so a blocked
  reviewer is not nudged.
