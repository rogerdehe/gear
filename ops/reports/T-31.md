# T-31 — Any agent kind Herdr supports can be a captain, lane or reviewer

Scope: T-31 — `[profiles.<name>]` in `gear.toml` defines or overrides a profile (the fields of `gear_herdr::Profile`); the engine's table is the built-ins with the project's own on top; a seat's `profile = "<name>"` resolves against it; a profile without unattended args is refused at `gear admin init`; `gear admin kickoff` prints a skeleton for a detected kind without a built-in profile.
Branch: data/t31 (code @ pending, see the hand-in)
Files:
- crates/gear-herdr/src/profile.rs — `ProfilePatch` (the configurable fields, every one optional) and `Profile::patched` (the given fields win, the others keep their value); `builtins()` (the built-in table); `Profile` derives `Default` so a new profile name starts from the defaults.
- crates/gear-app/src/config.rs — `profile_table(base, config)`: the base table with the project's `[profiles.<name>]` on top. A block that does not parse is `BadFormat`, naming the profile. A configured profile is one GEAR may drive (the user wrote the kind, the args and the exit keys); `gear admin init` refuses the ones that cannot run unattended.
- crates/gear-app/src/admin.rs — `gear admin init` resolves every seat's profile (captain, lanes, temps) against the table: an unknown name is `BadFormat` (naming the profile), and a profile without `unattended_args` is refused — an agent that stops on a permission dialog cannot run unattended.
- crates/gear-engine/src/onboard.rs — the onboarding uses the project's table (built-ins + the project's own), so a lane on a configured profile is started with that profile's kind and args.
- crates/gear-engine/src/lib.rs — the tick observes with the same table, so a configured profile's markers count too.
- crates/gear-app/src/kickoff.rs — the kickoff skeleton prints a commented `[profiles.<kind>]` block (kind, unattended args, markers, exit keys, resume args) for every detected kind without a built-in profile.
- crates/gear-app/tests/profiles_contract.rs — 6 tests: a block defines a profile; a partial block overrides only the given fields (the built-in's others stay); a profile without unattended args is refused at init; an unknown profile is refused at init; a configured profile is accepted; the kickoff prints the skeleton for an unknown kind (and not for a built-in one).
- crates/gear-engine/tests/config_profile_onboard.rs — a lane on a configured `grok` profile is onboarded through FakeHerdr as a grok agent with the configured args.
- README.md — one line: an agent kind GEAR does not know needs a `[profiles.<kind>]` block.

Open questions:
- A configured profile is trusted (it may onboard a seat): the user wrote its kind, args and exit keys, and `gear admin init` refuses a profile that cannot run unattended. The built-in `verified` flag stays about GEAR's own probe; a configured profile is trusted by the user's declaration.
- `verified` is not configurable — it is not one of the profile's fields.
- The kickoff prints the skeleton for the kinds it **detects** (installed here) without a built-in profile; the kinds Herdr knows but that are not installed are listed as missing, without a block (a config full of skeletons for kinds nobody installed is noise).
- A profile name that is not a built-in and not configured is refused at init (the engine would fail closed on it).
