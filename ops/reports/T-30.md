# T-30 — GEAR carries the knowledge it needs

Scope: T-30 — GEAR's knowledge ships with the binary: `gear --skill review` (the review rules, project-neutral), `gear --skill captain` (kickoff, plan format, daily loop), `gear --skill agent:claude` (the Claude Code SOP), and `gear admin install-skill --agent claude|codex|opencode` writes the skill where that CLI loads skills. The engine's review packet points at `gear --skill review` instead of a file of this repo.

Branch: board/t30 (code @ pending, see the hand-in commit)

Files:
- `skills/gear/references/review.md` — new: what a temp reviewer must deliver (mechanical acceptance run by the reviewer, severities P0–P3, the verdict judged against the milestone's done-sentence, the re-review rule), how to deliver it (`gear send --kind review` with the findings text or the path to the review file — GEAR keeps the text) and the review template. No path of this repo is named.
- `skills/gear/references/captain.md` — new: the captain's guide — kickoff (inventory, what the user confirms, the config, `gear admin init`, no popups afterwards), the plan draft format (header, sections, queue fields, verdicts, staff, one complete example, the rules that matter), the daily loop (`gear`, `gear reply`, `gear plan apply`, 2–3 valuable steps per lane, holding the course) and what the captain never does.
- `skills/gear/references/agents/claude.md` — new: the Claude Code SOP, same shape as the codex/opencode ones (facts, check the pane, start, prompt, session id, exit, resume, switch model, pitfalls). - `crates/gear-app/src/skill.rs` — new: the skill's topics (name → file → text) and the install (`SkillAgent::Claude|Codex|OpenCode`, the CLI's skills directory, one file per topic).

- `crates/gear-engine/src/review.rs` — the review packet names `gear --skill review` and the hand-in command takes the reviewer's own file or text; no `ops/` path is left in it.
- `skills/gear/SKILL.md` — the topics of §5 (review, captain, agent:<kind>), the install command, and three stale lines fixed (`ack`/`blocked` kinds, the `ops/CONVENTIONS.md` mention).
- `docs/design/17-conventions.md` — §5 and §8 no longer point at `ops/bin/inbox.sh` and `ops/reviews/T-<n>.md`: the inbox is `gear`, and the reviewer's findings travel in the message.

**What in the proof needed a file of this repo: nothing.** The guide, the plan format, the config and the install all came from the binary. The scratch store has no `engine.lock` and no `engine.log`: the store is not registered for a Herdr session, so `gear` starts no engine on it (L-54).

Gaps the proof and the texts still carry:
- **`gear plan apply` does not accept `# Review` conclusions and `temp` staff lines** in this version (parsed, then `BAD_FORMAT`). The captain guide says so; the engine starts the reviewers itself.
- **`agent:grok` is not a `--skill` topic yet** (the SOP file arrived in `c9824aa`), so it is neither printed nor installed. The install list follows the topics, so registering the topic installs it too.
- The conventions text keeps one cross-reference to a design section (`design/01`); it names no file to open.
- The review packet and the review guide promise that GEAR keeps the findings text — that is **T-21's** behaviour (in review, not merged yet). T-21 must land before or with this task; the hand-in command works either way.

Open questions:
- **Should `install-skill` be a user command only?** It writes into the user's home, so an agent is refused (`FORBIDDEN`). The captain cannot install the skill for itself without asking the user.
- **One convention file or several?** The installed skill writes the conventions as `references/conventions.md` (the same text `gear --skill conventions` prints) so the installed copy is complete on its own. The binary stays the authority.
- The captain guide repeats the plan format that `gear --skill decompose` also carries (the task packet). Keeping both in sync is a job for the next change that touches either.
