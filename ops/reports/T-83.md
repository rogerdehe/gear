## Rework

**F1 [P1, blocking] — `init` now refuses a kind whose GEAR skill is not
installed.** The check the review asked for, with the explicit home it asked
for:

- `skill::installed(agent, home)` is the one filesystem check
  (`<skills root>/gear/SKILL.md`); `kickoff.rs` uses it too, so the kickoff's
  report and the init guard cannot drift;
- `admin::init_with_home(store, env, config_text, home, now)` — `init` keeps its
  signature and passes `None` (the process's `HOME`); the CLI passes the user's
  `HOME`. A home that is not set is a `BadFormat` (the guard is never skipped);
- every **kind the project uses** is checked — the captain's, every lane's and
  the reviewers' (`[temps]`) — by the resolved profile's kind, before anything
  is written (the check sits above `store.write`, so a refusal leaves the store
  exactly as it was, re-init or not);
- the refusal names the seat and the fix:
  `captain runs codex, whose GEAR skill is not installed in /home/…: run `gear
  admin install-skill --agent codex` and init again`; a kind GEAR has no skill
  install for says so;
- GEAR never installs a skill behind the user's back.

Tests: two new app tests — no skill at all → `BadFormat` with the command and
nothing registered, then the same config registers with a home that has the
skills; a re-init that moves a **lane** and then the **reviewer** to a kind with
no skill → refused, with the project left at version 1 and its old config text.
One new CLI test runs the real binary against a skill-less `HOME`: exit 1, the
message, and no project in the store. Success fixtures now install the selected
skills into their own scratch homes (a shared `skill_home()` in both test
binaries; the CLI fixture installs into its test home).

**F2 [P2, logged] — a failed branch fetch now refuses.** `require_pushed`
checked the fetch's exit status before comparing ancestry: a branch deleted on
the remote after the lane fetched it no longer passes on a stale
remote-tracking ref, and the message says
`cannot fetch origin/heat/t1 … push the task branch first` with git's own
words. New regression `base_gate::a_branch_deleted_on_the_remote_is_refused`
(push, fetch, delete from the seed, hand in → refused, nothing stored); the
unpushed case keeps its own refusal, and a candidate that is not on an existing
branch keeps the "is not on" message.
