Attempt 1, contract v1.

Branch: `course/t83`; the candidate named in the hand-in includes this
report. Base: `origin/dev` merged into the branch before the hand-in.

## What shipped

**1. Kickoff's inventory (trial G03, G06).** `crates/gear-app/src/kickoff.rs`:

- an **empty** `opencode models` list is `model list not loaded yet` — the
  probe looks once more (500 ms apart) before saying so — and the "no models"
  wording is gone for every kind: an empty list that says nothing now reads
  "model list not loaded yet";
- the report says, **per CLI kind**, whether the GEAR skill is installed:
  `· GEAR skill installed`, or
  `· GEAR skill MISSING — run `gear admin install-skill --agent <kind>``, or
  `· no GEAR skill for this kind` for a kind GEAR has no skill install for.

**3. A hand-in must be pushed (M2.1's T-60).** `crates/gear-app/src/base.rs`
gained `require_pushed(worktree, branch, candidate)`: it fetches
`origin/<branch>` and refuses unless the candidate is reachable from it, with

```
<candidate> is not on refs/remotes/origin/heat/t1: push the task branch before handing in (`git push origin heat/t1`)
```

`mail::send` runs it after the T-19 base gate, for every result that carries a
gate, on the branch of the task's lane (`base::task_branch`, `<lane>/t<n>`,
conventions 17 §3). Nothing is stored on a refusal — the attempt stays as it
was, exactly like the base gate.

## 2. The `init` refusal — not done in this attempt

The goal's third piece ("`init` refuses a config that uses a kind whose skill
is not installed") is **not in this candidate**. Two facts decided it:

- On this machine (and, by the trial's own G06, on the trial's) **no kind has
  the skill installed** — I checked `~/.config/opencode/skills/gear`,
  `~/.claude/skills/gear`, `~/.codex/skills/gear` and `~/.grok/skills/gear`:
  none exist. `init` refusing would therefore refuse **this project's own
  re-init** (the next config change, T-6) until the captain installs four
  skills — a hand fix in the middle of a voyage, which is the M3 bar's target.
- Done honestly, the check needs the caller's `home` (the CLI's `HOME`), which
  `gear_app::Env` does not carry: every one of the ~20 `admin::init` call
  sites in the tests would need a temp home with the skill installed to keep
  passing. That is a fixture upgrade, not a line.

The kickoff report above already surfaces the same fact where the captain can
act on it (the kickoff is read *before* `init`), which is the trial's G06
finding. I am flagging the refusal as open rather than shipping a check that
would block this very voyage.

  against pushed candidates.
