## The review's F1 (P1, blocking) — fixed

The guard walked the seats' resolved `profile.kind` only. A supported model
chain can name another CLI than the seat's profile (`ModelEntry::cli`, T-35):
"a Codex lane with an OpenCode primary model registers without the OpenCode
skill, then the engine starts OpenCode without GEAR instructions."

`admin::init_with_home` now collects **every kind the config can start** and
passes the deduplicated list through the same check, before any store write:

- each seat's resolved profile kind — captain, every lane, the reviewers
  (`[temps]`) — as before;
- every entry of **each lane's effective chain** (`lane.models` when it names
  any, else `models.lanes`), for every CLI an entry names — the primary and the
  fallbacks, since a quota switch runs a fallback on its own CLI;
- every entry of the **review chain** (`[models].review`) and the **captain
  chain** (`[models].captain`).

A missing skill is still a `BadFormat` that names the seat or chain and the
command (`… whose GEAR skill is not installed in <home>: run `gear admin
install-skill --agent <kind>` and init again`); a kind GEAR has no skill for
says which kinds do. Nothing is auto-installed, and the check stays above
`store.write`, so a refusal leaves a first registration and a re-init exactly as
they were.

New helper `config::lane_chain(config, lane)` is the one rule for "the chain a
lane runs on" (own models, else `models.lanes`); the guard and the tests use it.
No engine changes (the engine already reads the same chain).
