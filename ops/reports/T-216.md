# T-216 — Finish T-190, round 2 (F2, F4) (contract v1)

Scope: T-216 — F2 `gear plan check` resolves and proves its caller like
`gear plan apply` does; F4 `run_plan` reads the session's agents on every
apply, so an ordinary apply ends an expired park whose lane's agent is still
running.

Branch: mast/t216 (code @ the hand-in commit; origin/dev merged in before the
final verification)

## The bug

T-190's rework left two blockers.

F2 — `gear plan check` (the command T-190 promised) never resolved or proved
its caller: it read `GEAR_CTX`, took the project from it and wrote. A stale
captain (an old generation) or a seat the store does not hold could end a
park; a captain found from its own pane (no `GEAR_CTX`) was refused before
anything was resolved. The command `gear plan apply` uses
`resolve_caller` → `observe_identity` → `identity::require_seat` (role
Captain, state Active) inside the write transaction; the check did not.

F4 — `run_plan` read the session's agents only when the draft held a
`- release` of a lane. An ordinary apply (a hold of another lane, say) passed
`None` to the plan's `end_parked_lanes`, and a park whose time had come with a
**live** binding was left standing: the expiry is fail-closed without the
agents, and the apply had none.

## The fix

- `crates/gear-cli/src/main.rs` — `cmd_plan_check` opens Herdr, resolves the
  caller (`resolve_caller`) and calls `run_plan_check`, which observes the
  caller's identity (`observe_identity`) and, inside the write transaction,
  requires the seat (`identity::require_seat`, role Captain, state Active)
  before `gear_app::plan::end_parked_lanes` writes. The project's own context
  is the one the check uses. A caller that cannot be proved (a stale
  generation, an unknown seat, no seat at all) is refused, and the transaction
  writes nothing.
- `crates/gear-cli/src/main.rs` — `run_plan` reads the session's agents for
  **every** apply, not only for a release. A read that fails still refuses an
  explicit release (nothing is applied); without the agents an automatic
  expiry stays fail-closed: a park whose lane has a live binding stays, a park
  whose lane has none still ends.

Nothing in `crates/gear-app/src/plan.rs` changed: `end_parked_lanes` and the
apply's call to it were already right (T-190, round 2).

## The tests

`crates/gear-cli/src/main.rs` (CLI tests, over the injected Herdr):

- `plan_check_refuses_a_stale_captain_and_writes_nothing` — the store holds
  the captain at generation 2, the caller carries generation 1: the check is
  refused with `StaleGeneration` and the park stays `Parked`.
- `plan_check_from_the_captains_pane_without_geom_ctx_ends_an_expired_park` —
  the caller has no `GEAR_CTX` and runs in the captain's pane: the seat is
  resolved from the pane, the check ends the expired park and the lane is
  `Active` with the reason `park ended`.
- `an_ordinary_apply_ends_an_expired_park_with_a_live_agent` — an ordinary
  apply (a hold of another lane) ends heat's expired park: `Active`,
  `park ended`.

`crates/gear-cli/tests/it/plan_check_contract.rs` (the real binary):

- `the_check_command_refuses_a_caller_it_cannot_prove_and_writes_nothing` —
  the command exists and refuses a caller it cannot prove; the park stays.
- `the_check_command_refuses_an_unknown_captain_and_writes_nothing` — a
  `GEAR_CTX` naming a seat the store does not hold is refused; the park stays.
