# T-72 — every GEAR worktree pushes only where the project registered

Scope: T-72 — GEAR's pre-push check installs itself in every worktree GEAR
makes (lane, reviewer, merge), for that worktree only, chained to the
repository's own hook; the engine's own merge push is checked in-process before
it runs. A refusal: no push, no retry, one urgent captain item.

Branch: base/t72 (code @ the hand-in commit; origin/dev merged before
verification, gate green on the merged result)

Files:
- `crates/gear-engine/src/hooks.rs` (new) — the installer. It finds the
  worktree's own git dir, writes `<git dir>/gear-hooks/pre-push`, and points
  `core.hooksPath` at it with `git config --worktree`, so the main checkout and
  every other worktree keep their hooks. The script runs
  `gear push-check "$1" "$2"` first, then the repository's own `pre-push` hook
  by absolute path — from the repo's `core.hooksPath` when it sets one, else
  from the shared hooks directory — read from the repository's own config, so a
  re-install cannot lose the chain. Idempotent; a path that is not a git worktree
  is left alone (the engine's merge check still guards the landing).
- `crates/gear-engine/src/onboard.rs` — installed after a lane's worktree exists
  and before its agent starts; a failure parks the seat (an unprotected
  worktree may not run).
- `crates/gear-engine/src/review.rs` — the same for a reviewer's worktree.
- `crates/gear-engine/src/merge.rs` — the hook in the integration worktree, and
  the in-process check: `push_allowed` reads the worktree's `origin` push URL
  and calls `gear_app::push::check(store, project, repo, url)` on the tick
  thread (workers keep owning only git inputs) before the worker starts. A
  refusal sets the op `Failed` with the refusal, starts no worker (no push, no
  retry) and rings the captain once — `tell_captain_refused`, an urgent item in
  `push:<task>` naming the repo, the destination and the command.
- `crates/gear-engine/src/merge.rs` (tests) — the fixture stores now freeze
  their own origin as the registered destination (T-72 makes "no destination =
  no push" bite), plus `a_refused_destination_stops_the_merge_with_one_item`:
  an unregistered destination stops the merge, pushes nothing, leaves the op
  `Failed`, and leaves exactly one urgent item.
- `crates/gear-cli/tests/it/push_hook_contract.rs` (new) — the hook contract
  with real git: a local bare repository as the registered destination, another
  bare repository, a worktree, and the **real** `gear push-check` reached
  through a PATH wrapper as the lane's own push (its context and store in the
  environment). A push to the registered destination goes through; a push to
  the other is refused by the hook and nothing lands; the repository's own
  `pre-push` still runs behind GEAR's after a re-install.
- `ops/reports/T-72.md` — this brief.

**One thing the captain must do before the next merge** — the live store has
**no frozen push destinations** (the project was registered before T-73), and
an empty list refuses every push by design. Until the captain re-inits:

```bash
GEAR_ADMIN=1 gear admin init gear/gear.toml     # in the captain's pane
```

every merge stops with the urgent item above, and any lane whose worktree has
been reopened since this lands has its pushes refused. The refusal item says
exactly this, so it is visible rather than mysterious.

breaking a written rule, and the engine's own pushes are checked regardless).
