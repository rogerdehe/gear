# T-33 — Change an agent's model in place, never by closing it

Scope: T-33 — the engine switches a live agent's model with the CLI's own picker (`/model`, the filter, the variant dialog, then the status bar must show the model): no exit keys, no restart, the conversation stays. Used (a) right after an OpenCode lane/reviewer starts when its bar is off the chain's model and (b) by the quota fallback (T-15). It never types into a working agent; two failed tries flag the seat. Quota markers left on the screen by an earlier switch no longer count (M-266).
Branch: data/t33 (rebased on current `origin/dev`; the T-23 work that leaked into the first candidate is gone — F1)
Files:
- `crates/gear-engine/src/switch.rs` — the switch as a **state machine across ticks**: the plan (the status-bar text to reach, the next step, failed tries, how long the step has waited) is written to the seat's meta **before the first key**, one UI submission happens per tick, and the whole **visible** screen is re-read before each one. Steps: `esc` → `/model` → the picker filter → the variant dialog when `Select variant` opens → the status bar. `pane_run` already submits text **plus** Enter, so no extra `enter` is sent (F2). A step that has not rendered yet waits (bounded, 6 ticks) instead of burning a try (F3). Before any key the pane's occupant and status are read again; a working agent is `Waiting`, another kind in the pane is `Failed` (F8). Only OpenCode's verified protocol is implemented (P2).
- `crates/gear-herdr/src/lib.rs`, `fake.rs` — `HerdrRead::read_screen` (the whole visible pane, `ReadSource::Visible`): the variant dialog is drawn mid-screen, above the 16-line tail (F3). The fake renders a screen after a submission (`screen_after`) and after an agent starts (`start_screen`), so the tests see what a real UI renders, one action at a time.
- `crates/gear-app/src/config.rs` — `[models.switch."<model id>"]` with `picker` (the picker filter — specific enough to leave one row, L-29), `bar` (what the status bar must show) and an optional `variant`.
- `crates/gear-engine/src/quota.rs` — the quota fallback and the parked-lane wake-up both **switch in place**; the exit/restart machinery is gone (F4). No labels for the model → the seat is flagged `NeedsCheck` with the missing key, nothing is typed, nothing is closed. A pending switch resumes **before** quota detection on every later tick, whatever the screen says now (F6). The confirmed switch commits the model, the quota counter, the cleared plan, the seat state and the one `Continue` op in **one** transaction (F7), then tells the captain.
- `crates/gear-engine/src/onboard.rs`, `review.rs` — after an OpenCode lane/reviewer starts (or is adopted), its bar is checked against the chain's model; the seat stays `Starting` and no packet is queued until the bar confirms (`ModelGate`), a missing label flags the seat (F5).
- `crates/gear-engine/src/dispatch.rs` — a pending switch suppresses ordinary deliveries for that seat (F6): no prompt lands in an open picker.
- `ops/gear.toml` — the real chain's labels: `minimax-cn/MiniMax-M3.1-Flash` and `opencode-go/deepseek-v4.1-flash` (the exact provider-specific filter, not the free tier).

## Real proof — the exact commands for the captain to watch one in-place switch

1. The labels are in `ops/gear.toml` (see above); re-register:

```bash
GEAR_ADMIN=1 gear admin init ops/gear.toml
```

2. Watch the engine do it (quota fallback, or a lane start off its chain's model):

```bash
tail -f ~/.local/state/gear/engine.log | grep -E 'switched|switch|quota'
```

3. Or the same steps by hand in a lane that has stopped (SOP `agent:opencode`):

```bash
herdr pane send-text <pane> "/model" && herdr pane send-keys <pane> enter
herdr pane read <pane> --source visible            # the picker
herdr pane send-text <pane> "DeepSeek V4.1 Flash OpenCode Go"   # text+Enter selects
herdr pane read <pane> --source visible            # "Select variant" mid-screen, if any
herdr pane read <pane> --source visible | grep 'Build auto'      # the bar shows the model
```

The engine sends no exit keys and starts no agent: the pane keeps its session, and the next `gear send` shows the lane still on the same attempt.

Open questions:
- The engine matches the model only on the OpenCode status-bar line (`Build auto · …`); a conversation that quotes the model name is not a confirmation.
- A failed switch flags the seat (`NeedsCheck`, "did not confirm twice"), never a park: a human looks at the pane.
- M-266's rule is "count a marker only while the agent has stopped", as the packet allows; a working lane is never parked or switched on screen text alone.

Out of scope:
- Other CLIs' pickers: only OpenCode's protocol is verified (`SwitchSteps::for_kind` returns `None` for the rest, which flags the seat rather than guessing).
- A model variant/effort switch on its own (`/effort`): the switch answers the dialog when it appears; a standalone effort change is not this task.
