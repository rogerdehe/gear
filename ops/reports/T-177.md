# T-177 — the forge side of the PR landing (design §11.2-§11.3)

Scope: the forge edge of landing a task through its pull request: the merge
carries the head the gate checked, the pull request's own state says what
happened to a merge whose outcome is unknown, and the sync runs the land op
the engine inserted.

## What changed

**`Forge::merge` takes the head** (`crates/gear-forge/src/lib.rs`,
`github.rs`): the merge names the head the gate checked
(`--match-head-commit <sha>`), so GitHub merges exactly that commit and never
a head that landed in between. A merge without a head (an empty one) merges
the pull request as it is — the old command line, unchanged.

**`Forge::pr_state`** (new): the pull request's own state, read with
`gh pr view --json state,mergeCommit,headRefOid` — the state (`OPEN`,
`MERGED`, `CLOSED`…), the merge commit and the head it points at. It is what
a merge whose outcome is unknown asks the forge.

**`Forge::pr_by_head`** (new): the open pull request of a branch, read with
`gh pr list --head <branch> --json number,url`. A claim that was interrupted
is adopted by its branch (T-91, F4).

**The sync runs the land op** (`crates/gear-forge/src/sync.rs`): the engine
inserts the op `{task}:{n}:land` with the pull request, the gated head and
the method (design §11.2 step 4); the sync merges the pull request with that
head and records the merge commit the pull request names
(`{"merge_commit": …}`).

**The reconciliations** (design §11.3):

- a land op whose outcome is unknown is read by the pull request: `MERGED`
  confirms it (with the merge commit), `OPEN` **with the same head** runs the
  merge again, any other state fails it — and the engine raises the captain
  item for the failure;
- a claim whose outcome is unknown is adopted by its branch: the pull request
  that is there is confirmed as the claim, and the claim is never opened
  again.

A forge that cannot answer leaves the op as it is: the next tick reconciles
it again. A merge that ran but whose commit could not be read leaves the op
unknown, and the pull request says the rest on the next tick.

## Files

- `crates/gear-forge/src/lib.rs` — the trait (`merge` with the head,
  `pr_state`, `pr_by_head`) and `PrState`.
- `crates/gear-forge/src/github.rs` — the three calls over `gh`.
- `crates/gear-forge/src/local.rs` — the same three calls for a project
  without a forge (they do nothing).
- `crates/gear-forge/src/sync.rs` — the land op, the reconciliations.
- `crates/gear-forge/tests/it/github_contract.rs`, `sync_contract.rs`,
  `local_contract.rs` — the tests.

## Tests

`crates/gear-forge/tests/it/github_contract.rs` (the fake `gh`):

- `the_merge_passes_the_head_it_must_merge` — the command line carries
  `--match-head-commit abc1234`;
- `the_state_of_a_pull_request_is_read` — the state, the merge commit and the
  head, read with `--json state,mergeCommit,headRefOid`;
- `the_open_pull_request_of_a_branch_is_found` — `--head heat/t1` finds the
  pull request; a branch without one is none, not an error.

`crates/gear-forge/tests/it/sync_contract.rs` (the fake forge):

- `the_land_merges_the_pull_request_with_the_gated_head` — the merge carries
  the head, the op is confirmed with the merge commit the pull request names;
- `an_unknown_land_op_is_reconciled_by_the_pull_request` — `MERGED` confirms
  the op without a second merge, `OPEN` with the same head runs the merge
  again, `CLOSED` fails the op;
- `an_unknown_claim_adopts_the_open_pull_request` — the claim is confirmed by
  the pull request of its branch and is not opened again;
- `a_restart_does_not_repeat_a_call_it_may_have_made` — the claim is still
  never opened again; only the branch is looked up (the adoption).

## Open questions

The land op's payload is read as the design writes it: `{"forge":"land",
"pr":<number>,"head":<sha>,"method":"squash|merge"}`; the engine's side (the
merge op's result and the insertion of the op) is T-178's, and the two must
agree on that payload.

## Out of scope

The engine's side of the landing (the gate, the review commits onto the pull
request's head, the merge op's result and the captain's item for a failed
land): T-178. The config's `merge = "pr"`: T-179.
