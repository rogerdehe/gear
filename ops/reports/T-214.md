# T-214 — "The review waits" is told once per attempt (contract v2)

Scope: T-214 — in `crates/gear-engine/src/review.rs`, `tell_captain` also holds
its "already" check when the meta key
`engine.review_wait_told.<project>.<task>.<attempt>` is set, and the function
sets that key when it inserts the item. Nothing else changes.

Branch: keel/t214 (code @ the hand-in commit; origin/dev merged before the
final verification)

## The bug

"The review of T-1 (attempt 1) waits: every temp seat is in use, so the
reviewer is queued." was told again on every tick after the captain resolved
the item — the notice came back six times for T-212 (M4 06:05), once after
each resolve.

The reason: `tell_captain` decided with the captain's **actionable** messages
only. A resolved message is no longer actionable, so the next tick found no
open item and inserted the same news again. The check had to remember the
notice itself, not the state of the message that carries it.

## The fix

- `crates/gear-engine/src/review.rs` — a new `review_wait_told_key(project,
  task, attempt)` builds the key
  `engine.review_wait_told.<project>.<task>.<attempt>`.
- `crates/gear-engine/src/review.rs` — in `tell_captain` the check `already`
  also holds when that key is set; the key is written in the same transaction
  that inserts the item, so the notice is told once per attempt.
- Nothing else changes: the notice is still one open item per task, the
  reason is still the one the tick has, and a **new attempt** of the same task
  has its own key, so it is told once again.

## The tests

`crates/gear-engine/src/review.rs` (engine tests):

- `the_review_waits_notice_is_told_once_per_attempt` — a project whose quota
  has no temp slot, so the review waits: the captain is told once; the captain
  resolves the item; the two later ticks add no item (no second item in the
  thread); the next attempt of the same task is told once again ("attempt 2").

The test fails on the code before the fix (the notice comes back after the
resolve: `the notice comes back: [MessageRow { … id: "M-2", thread: "T-1:2" … }]`)
and passes with it.

- The captain's item of a review that waits is still one open item per task:
  the fix only keeps the notice from coming back after it was resolved.
- The other captain notices (quota, merge, stall) keep their own rules; the
  packet names only the review notice.
