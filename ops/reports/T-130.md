# T-130 — A message for a lane reaches it while it works (attempt 2)

Scope: T-130 — an urgent message, and every captain instruction to a lane whose
agent queues input while it works (pi, claude), is typed into the pane at once;
the doorbell names the message ids and says "run `gear` now"; one doorbell per
message; and `gear send` types the doorbell itself before it returns.

Attempt 2 is the rework the review of attempt 1 asked for, **two small fixes and
nothing else** (attempt 1's implementation is unchanged otherwise):

- **F2 — a definitely failed doorbell covers nothing.** `doorbell_inputs` used
  to drop only VOID ops from the coverage; a doorbell Herdr *refused* became
  FAILED and then suppressed its message for ever. `ops::doorbell_covers` now
  says what "covered" means in one place — everything except VOID and FAILED —
  and `ops::covered_messages(tx, seat)` is the one reader of it, used by the tick
  (lanes and reviewers) and by the sender's claim. A refused message is rung
  again on the next eligible tick; SUBMITTED/UNKNOWN still cover (an unconfirmed
  or uncertain doorbell is never resent), and the captain's T-40 reminder stays
  the documented exception. Test: `doorbell_while_working.rs::
  a_refused_doorbell_is_rung_again_on_the_next_tick` — a refused doorbell leaves
  the op FAILED and no text, the next tick (21 s later, Herdr healthy) types the
  same message and records SUBMITTED.
- **F1, the cheap form — the sender claims the message before Herdr.** The race
  the review reproduced: an engine tick intends a doorbell for M-1, then the
  sender's `deliver_doorbell_now` typed M-1 anyway and recorded a second op, so
  `execute_intended` typed it once more. `deliver_doorbell_now` now does its
  seat/binding checks, the coverage check and its own doorbell op in **one write
  transaction before the prompt**: if any earlier doorbell of the seat still
  covers the message (INTENDED/EXECUTING/SUBMITTED/UNKNOWN/CONFIRMED) it skips
  and lets that path type it; otherwise it writes the op as EXECUTING (the claim
  — `execute_intended` only drains INTENDED ops, so nobody types it again) and
  finishes it with the Herdr answer: SUBMITTED when taken, FAILED when refused
  (so F2 rings it again), UNKNOWN when uncertain (never resent). The T-40
  reminder clock is recorded with the SUBMITTED result, as before. Tests:
  `eng_execute.rs::a_sender_does_not_type_a_message_the_engine_already_intends`
  (intend → sender skips → the engine's execute types it once: 1 prompt, 1 op)
  and `::a_sender_claim_keeps_the_engine_from_ringing_the_same_message` (sender
  first → a second send and an `execute_intended` add nothing: 1 prompt). The
  CLI test for a refused prompt now asserts the FAILED claim and that the engine
  still rings the message.

## Open questions

none — four decisions worth naming:
- **The captain keeps its stale reminder.** `feed_contract`'s
  `a_twenty_minute_old_viewed_item_rings_urgently_once_per_period` (T-40)
  requires the same captain item to be reminded once per configured period; a
  literal "never twice" for every seat would delete that feature. So per-message
  dedupe is for lanes and reviewers, where the contract's problem lives; the
  captain's reminder clock stands, and `docs/design/07-mail.md` says so.
- **A reviewer is not a lane.** A captain instruction reaches a **lane** whose
  agent queues input, literally as the packet says; a pi/claude **temp reviewer**
  still waits for idle (`reaches_while_working` checks the role). One line to
  widen if the captain wants it.
- **"Herdr fails" means the prompt.** A `gear send` with no reachable Herdr
  socket fails before storing, as it did before: since T-104 the sender's
  identity is proven through Herdr, so no seat and no write. A prompt Herdr
  refuses or leaves uncertain stores the message, records no doorbell and the
  engine rings it on the next tick — the CLI test covers the refused case.
- **The send's doorbell holds the seat's slot** until a view confirms it or the
  existing expiry frees it, so an unrelated message for that seat waits a tick.
  That is the unchanged slot rule (design/07, /09) and the reason the T-71
  swallow does not come back.
- **The one window the cheap form leaves** (named, not hidden): a tick that has
  already *read* the coverage but not yet *written* its intent, while a sender
  claims in that same instant. Between the two there is only pure computation in
  the tick (no Herdr call, no await), and the sender's claim is a committed
  write, so the window is a few microseconds. Closing it entirely is the claim
  protocol the captain deferred; the two deterministic interleavings the review
  reproduced are fixed and tested.
- **A sender that dies between its claim and its prompt** leaves the op
  EXECUTING, which recovery turns UNKNOWN; it covers the message and is never
  resent (design/07's "uncertain is never resent"). That is the same edge the
  review set aside.
