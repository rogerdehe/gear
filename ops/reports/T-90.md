# T-90 — A review fail is settled where it can be

Attempt 2, contract v1 — the rework of F1 and F2.

Branch: `course/t90` (a rework continues on the task's branch); the candidate
named in the hand-in includes this report. Base: `origin/dev` merged into the
branch before the hand-in.

## Rework

**F1 [P1, blocking] — a failed-merge item stayed a verdict item after it was
decided.** `tasks::verdict_hint` treated the *existence* of a Failed merge op
as a permanent need for a verdict, so after the captain wrote the suggested
line the merge question could still not be resolved, and the page kept
suggesting a verdict that was already applied. The hint now excludes a failed
merge whose attempt already has the captain's reopening fail verdict for the
same candidate (`reopened`): the historical op stays Failed, the item is an
ordinary one, and a reply resolves it. The regression extends
`a_failed_merge_is_settled_by_a_verdict_too`: after the plan reopens the task,
the page names no verdict, resolving the merge item succeeds, and both stay
true after the lane starts the rework attempt.

**F2 [P1, blocking] — an ordinary task question was forced through a fail
verdict.** The handed-in branch checked only the attempt and task state, so
any Open question about a task whose attempt had been submitted became
unresolvable, with a `fail rework="…"` suggested. The branch is now limited
to the items that are actually a decision:

- the reviewer's **fail** verdict on this attempt (`MsgKind::Review` and a
  stored review verdict that failed — a pass is information and exempt);
- the engine's captain decision item for a handed-in attempt, the
  `<task>:cap` thread (a fail without blocking findings, a rework over the
  cap).

The failed-merge classification stays separate. New regression
`an_ordinary_question_is_answered_without_a_verdict`: a passing review, a
submitted attempt, an Open ordinary question → the page offers
`gear reply … --resolve`, the reply goes through, the task stays Verifying
and no verdict is written.

## What shipped (attempt 1, unchanged)

The captain's home page names the `# Verdicts` line for an item only a
verdict settles, with the task, attempt, contract and candidate filled in —
`next: gear plan apply gear/voyages/<M>.md (# Verdicts: T-<n> attempt=<a>
contract=<c> candidate=<sha> fail rework="…")` — instead of
`gear reply … --resolve`; `gear reply --resolve` on such an item is refused
with that same line. An information line (a pass, a result) is bookkeeping
and a reply still closes it. The engine's merge item carries its task and
attempt (`merge.rs`), and a failed merge's fail reopens the task for a
rework on a new attempt (the accepted attempt keeps its state; the task goes
`Done → Ready`, the model's explicit reopen).

## Acceptance evidence

- `verdict_item_contract::the_home_page_names_the_verdicts_line_not_a_reply`:
  a review fail whose task still verifies → the page shows
  `next: gear plan apply gear/voyages/M3.md (# Verdicts: T-1 attempt=1 contract=1 candidate=abc1234def5678 fail rework="…")`
  and no `gear reply M-1 --resolve`.
- `verdict_item_contract::resolving_the_fail_by_reply_is_refused_and_leaves_it_verifying`:
  the reply is refused (`BadFormat`) with that line; the task still Verifies,
  the item stays Open, no verdict was written.
- `verdict_item_contract::after_the_plan_settles_it_resolving_works`: the
  plan's fail rejects the attempt and readies the task with the rework note,
  then a reply resolves the item.
- `verdict_item_contract::a_failed_merge_is_settled_by_a_verdict_too`
  (extended, F1): the merge item names the verdict, the plan's fail reopens
  the task (the accepted attempt stays), and the item is resolvable — before
  and after a new attempt starts.
- `verdict_item_contract::an_ordinary_question_is_answered_without_a_verdict`
  (new, F2): an ordinary question is answered and closed by a reply; the task
  stays Verifying and no verdict appears.
- `tasks_contract::pass_and_fail_settle` (extended in attempt 1): a fail then
  a pass on one attempt is still a conflict; a pass then a fail reopens a
  Done task (the failed merge) instead of being a conflict.
