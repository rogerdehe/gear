# T-19 — The hand-in refuses a stale base

Scope: T-19 — `gear send --kind result` proves that the candidate contains the project's current `origin/<integration>` before anything is written: a stale candidate is refused with "merge dev into your branch, build, then hand in again" and stores nothing; a fetch that fails refuses too, never accepts unchecked.
Branch: data/t19 (code @ 014a359)
Files:
- crates/gear-app/src/base.rs — the gate: `require_current_base(worktree, integration, candidate)` runs `git fetch origin` and `git merge-base --is-ancestor origin/<integration> <candidate>` in the lane's worktree; `gate_for(store, env)` builds it from the process's working directory and the project's `[conventions].integration` (no `GEAR_CTX` or an unreadable config → refused).
- crates/gear-app/src/mail.rs — `SendArgs.base`: the gate runs **before** the transaction, so a refused hand-in stores no message and leaves the attempt untouched.
- crates/gear-cli/src/main.rs — a result carries the gate (built by `gate_for`); other kinds carry none; the test call sites pass an explicit gate.
- crates/gear-app/tests/base_gate.rs — 6 tests over scratch repos with a bare origin: candidate containing `dev` accepted; candidate behind `dev` refused with the merge sentence; failing fetch refused; unplaceable candidate refused; a stale hand-in stores nothing (no message, attempt still Started); a current hand-in is accepted and submits.
- The other `SendArgs` literals (tests, engine tests) gain `base: None`.

## Real proof

Stale candidate (`origin/dev~3`, which does not contain the current `origin/dev`):

```
$ ./target/debug/gear send --kind result --task T-19 --attempt 1 --contract 1 --candidate origin/dev~3 "x"
ERROR BAD_FORMAT: origin/dev~3 does not contain the current origin/dev: merge dev into your branch, build, then hand in again
```

The same command with the branch head is the hand-in itself (accepted, one message stored).

Open questions:
- The gate runs on `--kind result` only (the hand-in); a review verdict, a progress line or a question is not gated.
- The integration branch comes from the project config (`[conventions].integration`, default `dev`); a project whose config cannot be read refuses the hand-in instead of guessing.
- `base: None` exists for callers that are not a lane hand-in (tests); the CLI always sets the gate for a result.

Out of scope:
- The captain's own merge gate (T-12) and the reviewers' checks are untouched.
- A gate for a *rework* hand-in (a second result on a new attempt) is the same path: every result is checked.
