# T-19 — The hand-in refuses a stale base

Scope: T-19 — `gear send --kind result` proves that the candidate contains the project's current `origin/<integration>` before anything is written: a stale candidate is refused with "merge dev into your branch, build, then hand in again" and stores nothing; a fetch that fails refuses too, never accepts unchecked.
Branch: data/t19 (code @ pending rework commit, see the hand-in)
Files:
- crates/gear-app/src/base.rs — the gate: `require_current_base(worktree, integration, candidate)` runs `git fetch origin` and `git merge-base --is-ancestor origin/<integration> <candidate>` in the lane's worktree; `gate_for(store, env)` builds it from the process's working directory and the project's `[conventions].integration` (no `GEAR_CTX` or an unreadable config → refused).
- crates/gear-app/src/mail.rs — `SendArgs.base`: the gate runs **before** the transaction, so a refused hand-in stores no message and leaves the attempt untouched.
- crates/gear-cli/src/main.rs — a result carries the gate (built by `gate_for`); other kinds carry none; the test call sites pass an explicit gate.
- crates/gear-app/tests/base_gate.rs — 6 tests over scratch repos with a bare origin: candidate containing `dev` accepted; candidate behind `dev` refused with the merge sentence; failing fetch refused; unplaceable candidate refused; a stale hand-in stores nothing (no message, attempt still Started); a current hand-in is accepted and submits.
- The other `SendArgs` literals (tests, engine tests) gain `base: None`.

Verification:
- `cargo build --workspace --all-targets` → clean, zero warnings and zero errors.
- `cargo test --workspace` → green (61 test suites; 6 new tests).
- `origin/dev` merged before the hand-in and the whole suite re-run on the merged result.
- Real proof in this worktree against this repo (see below).

## Real proof

Stale candidate (`origin/dev~3`, which does not contain the current `origin/dev`):

```
$ ./target/debug/gear send --kind result --task T-19 --attempt 1 --contract 1 --candidate origin/dev~3 "x"
ERROR BAD_FORMAT: origin/dev~3 does not contain the current origin/dev: merge dev into your branch, build, then hand in again
```

The same command with the branch head is the hand-in itself (accepted, one message stored).

Open questions:
- The gate runs on `--kind result` only (the hand-in); a review verdict, a progress line or a question is not gated.
- The integration branch comes from the project config (`[conventions].integration`, default `dev`); a project whose config cannot be read refuses the hand-in instead of guessing.
- `base: None` exists for callers that are not a lane hand-in (tests); the CLI always sets the gate for a result.

Out of scope:
- The captain's own merge gate (T-12) and the reviewers' checks are untouched.
- A gate for a *rework* hand-in (a second result on a new attempt) is the same path: every result is checked.

## Rework (review round 1: F1–F4)

- **F1 (blocking)** — `git fetch origin` follows `remote.origin.fetch`, so a
  lane clone with a restricted refspec left `origin/dev` stale and a stale
  candidate passed. The gate now fetches the configured source **explicitly**
  into its own tracking ref (`git fetch --quiet origin
  +refs/heads/<integration>:refs/remotes/origin/<integration>`) and compares
  against that refreshed ref; a remote branch that does not exist makes the
  fetch fail and the hand-in is refused. Regressions:
  `a_restricted_fetch_refspec_cannot_hide_a_stale_candidate` and
  `a_deleted_remote_integration_branch_is_refused` (BAD_FORMAT, nothing stored,
  the attempt untouched).
- **F2** — a committed request replays its receipt before the gate: `mail::send`
  looks up the request id in a read transaction first (same args key = same
  seat, generation and arguments) and returns the stored `SendResult`
  (`replayed: true`) without touching git, so a lost receipt followed by an
  outage no longer reports a committed hand-in as failed. The fetch stays
  mandatory for every new submission, and git stays outside transactions.
  Regression: `a_committed_hand_in_replays_its_receipt_after_a_fetch_failure`
  (one message, same id, attempt still Submitted).
- **F3** — the refusal now says `merge origin/dev into your branch, build, then
  hand in again` (the remote ref, not the lane's possibly stale local `dev`);
  the test asserts that phrase.
- **F4** — a failed fetch reports a bounded stderr excerpt with the
  `fatal:`/transport reason (e.g. the unusable remote path), not only git's
  trailing boilerplate; the test asserts the reason survives.

Verification after the rework: `cargo build --workspace --all-targets` clean;
`cargo test --workspace` green (61 suites; 3 new tests, 2 updated).

## Rework (review round 2: F5, F6)

- **F5 (blocking)** — the fetch-failure excerpt cut the message at byte 400, so
  a long multibyte path (a valid name, an unavailable remote) panicked instead
  of refusing. It now keeps the **head and tail** of the excerpt, cut on
  characters: an ordinary `BAD_FORMAT` whose tail still carries git's reason
  (`does not appear to be a git repository`). Regression:
  `a_long_multibyte_fetch_failure_is_a_bad_format_not_a_panic` (a real failed
  fetch, a 150-character component plus 60 `界`, BAD_FORMAT and the reason).
- **F6** — the early receipt replay skipped identity. The replay now runs in a
  **read transaction that validates the seat, role/state, generation, binding
  and fingerprint** (`require_seat`) before it compares the args key, so a
  caller without an agent fingerprint, from a stale generation or with a void
  binding gets `NotRegistered` / `StaleGeneration` and no receipt. New
  submissions keep the write-transaction revalidation and the mandatory fetch.
  Regression: `a_replay_needs_the_live_seat` (three cases, one message).

Verification after the rework: `cargo build --workspace --all-targets` clean;
`cargo test --workspace` green (62 suites; 2 new tests, 11 base-gate tests).
