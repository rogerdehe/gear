## Rework

**F1 [P1, blocking] — the candidate did not build.** The merge with
`origin/dev` brought T-62's two `TaskRow` test literals, written before the
new `tasks.issue` field; the all-targets build and the workspace suite failed
with E0063. Fixed in `e2af704` (both literals say `issue: None`) — already on
the branch before this attempt. On this candidate:
`cargo build --workspace --all-targets` exits 0 with no warnings and
`cargo test --workspace` exits 0 with 766 passed, 0 failed.

**F2 [P1, blocking] — a child repo inherited the root's GitHub identity.**
`repo_of_section` fell back to the project's `[github]`, so a `[[repos]]`
entry without a section was handed the root's `owner/name` and PR mode: a
GitHub mode that points a child at another repository, and no way to keep a
child local-only while the root is on GitHub. The fallback is gone: a repo
resolves only its own section, the project's section is the *root*'s, and the
docs say so. Regression
`github_contract::a_child_repo_without_a_section_is_local_only`: with a GitHub
root, a child without a section and a configured child — the root keeps
`root/project` with `merge = pr`, the bare child is `None` through both
`repos()` and its lane's repo, and the configured child keeps `root/api`.

**F3 [P2, logged; fixed anyway] — invalid issue numbers.** A `#` and any
`u64` used to pass, and apply narrowed it unchecked: `#0`, `#+12` and
`#9223372036854775808` became 0, 12 and a negative number in the store. The
parser now takes ASCII digits only, a positive number, and one that fits the
store's integer; apply uses `i64::try_from` instead of a cast. The
regression's bad-input list gained `#0`, `#+12`, `#9223372036854775808` and
`#18446744073709551615`. (The review logged it; it is my own field and cheap
to close, so it travels with the rework rather than waiting.)

## What shipped (attempt 1, unchanged)

**Config.** An optional `[github]` for the project root and per `[[repos]]`:
`repo = "owner/name"`, `[github.issues] labels = [...]`, `merge = "push" |
"pr"`, `merge_method = "squash" | "merge"`. The resolved `Repo` carries
`github: Option<Github>`, `None` = local-only for that repo. Validation
refuses a section with no repo or one that is not `owner/name`, and a blank
issue label; an unknown merge mode or method fails to parse.

**Plan.** A queue block gains `issue: #<n>`, kept across applies — a new
`tasks.issue` column, store schema **v4** with the step from v3.
`Priority::from_label`/`label` map `priority/now|must|should|could|wont`.

**`gear_app::github::issue_block`** renders the `## NEW` block one issue
becomes: the title as the goal, the body's first line as the accept, the
priority from the labels (`must` otherwise), `issue: #<n>`, and the lane,
milestone and estimate for the captain to fill in.
