# T-10 — kickoff support: `gear admin kickoff`

Scope: T-10 — `gear admin kickoff` prints what the machine offers, for the captain to turn into a kickoff proposal: the agent kinds Herdr can start that are installed, the models each one can list, the kinds that are missing, and a `gear.toml` skeleton with the detected kinds and proposed model chains. Read-only: nothing is written, nothing is started, no Herdr state is touched.

Branch: board/t10. The hand-in commit carries the code and this brief; the candidate sha in the result names it (a brief inside a commit cannot name its own sha).

Files:
- `crates/gear-app/src/kickoff.rs` — the inventory: the kinds `herdr agent start --kind` accepts (herdr 0.9.1) with their executables, the PATH probe, the two parsers (`opencode models`, `~/.codex/models_cache.json`), the report, the `gear.toml` skeleton and its JSON form.
- `crates/gear-app/src/lib.rs` — the module.
- `crates/gear-cli/src/main.rs` — the `kickoff` subcommand: it needs no store, no seat and no `GEAR_ADMIN`, because the kickoff comes before the project is registered and the captain has no `GEAR_CTX` yet.
- `crates/gear-app/tests/kickoff_contract.rs` — the parsers on captured outputs, the skeleton parsed back as a real config, the empty machine, the JSON.

Open questions:
- **The task touches `gear-cli` and `gear-app`, which the project config gives the data lane.** The assignment is lane=board (plan v7 said data, the store says board), and the kickoff has no home in the board crate. The change is additive: one module, one subcommand, one test file; no existing signature or test moved.
- **No `GEAR_ADMIN` gate.** The other admin commands write, so they are user-only; kickoff only reads PATH and two model lists, and the kickoff happens before any project, seat or `GEAR_CTX` exists — a gate would make it impossible for the captain to run the very inventory it proposes from.
- **The model proposal is a heuristic:** a fast model is one whose id contains `flash`, `haiku` or `free` (not `mini`, which also matches MiniMax); the review takes non-fast models that the lanes do not run. The user confirms the chain at kickoff, and `init` validates that every model is reachable by the role's kind.
- **The kind/executable table** is from the Herdr 0.9.1 docs; `cursor` also looks for `cursor-agent` and `agy` for `antigravity-cli`. A kind whose binary is named differently is reported as missing, never guessed.

Out of scope:
- Writing or registering the config (`gear admin init` does that, and it reports every unfinished TODO as an error).
- The kickoff dialogue itself (the captain proposes, the user corrects) — this is only the inventory.
- Model *validation* against the CLI (init's job, design/01).
