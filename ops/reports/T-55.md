# T-55 — the skill tells the captain how to run a multi-repo project

Scope: T-55 — the shipped skill and the README say how a captain runs a project made of several git repositories: the `[[repos]]` config entry and a lane's `repo =`, one lane per repo, a cross-repo requirement cut into a contract task and then one task per repo.

Branch: docs/t55 (code @ c5b56d7; origin/dev 6f0e0ab merged before final verification)

Files:
- `skills/gear/references/conventions.md` — new §9 "A project of several repos": the `[[repos]]` entry (`name` `[a-z][a-z0-9-]*` and unique, `path` relative to `project.repo`, optional `integration`/`release`/`gate` defaulting to `[conventions]`) and a lane's `repo =`; a lane's worktree holds only its repo — cut from that repo's integration branch, reviewed against it, merged into it with that repo's gate; `owns` paths are relative to the lane's repo, so two lanes may own the same path in two repos; one lane per repo; a lane without `repo` works in the project root exactly as before. §1 (a project is one repo or a folder of several), §3 (the task branch is cut from the lane's repo), §4 (the worktree holds only its repo), §5 (the task branch starts in the lane's repo) and §7 (the merge runs the task repo's gate) point at it.
- `skills/gear/references/captain.md` — kickoff: the skeleton lists the git repositories it found under the project root; the captain lists only the repos this voyage changes (a repo joins the config in a later voyage, when it is needed); one lane per repo; the kickoff sheet carries the repos and each lane's repo. The config example gains a `[[repos]]` block and a second lane bound to it with `repo = "api"`.
- `skills/gear/references/decompose.md` — rule 1: the paths are relative to the lane's repo and a task changes one repo; rule 4: a requirement that crosses repos is cut into a contract task (the interface between the repos) first, then one task per repo, linked by `deps`; the goal carries the absolute path of the parent repo's documents a lane in a child repo cannot see; the self-check asks for one repo.
- `README.md` — Requirements: the project is one git repository, or a folder of several, each with an integration branch (e.g. `dev`) pushed to a remote.
- `ops/reports/T-55.md` — this hand-in.
