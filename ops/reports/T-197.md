# T-197 — the board frame finished (T-156 round 2)

Scope: the four findings of the review of T-156 that the board frame still
had: the canvas that scrolled the screen (F2), the viewport that dropped the
rows the user scrolled to (F8), the panel whose box lost its right border and
the footer's row (F3), and the test reader that accepted half a frame (F6).

## What changed

**F2 — the frame no longer scrolls the screen.**
`crates/gear-board/src/screen.rs`: `draw` wrote the canvas with a newline
after it. The newline after the footer's row scrolled the terminal by one
line, so the title left the top and every visible row sat one line above
where the hit testing expected it: a click on the visible Graph tab did
nothing, and a click on a lane picked the wrong row. The canvas is written
**without** a trailing newline now (the title stays on row 1, the tabs on row
4, the footer on the last row).

**F8 — one viewport offset, shared by the frame and the mouse.**
`crates/gear-board/src/frame.rs` and `src/lib.rs`: the frame bounded the row
*before* the scroll offset, so on an 80x24 screen only the first sixteen rows
could ever be drawn: selecting the twentieth task moved some rows up and never
drew the selected one. The rows are drawn **from** the offset now and the
screen row is what is bounded. The offset is a shared function
(`frame::scroll_of`), and the mouse hit testing adds it to the clicked row,
so a click picks the task that is drawn. A click outside the rows of the
view does nothing.

**F3 — the panel is one box.**
`crates/gear-board/src/frame.rs`: the box's width was the interior width, so
its borders ran past the right edge of the canvas and the panel had no right
border; its bottom border also replaced the footer's row. The panel has now
one total width (borders included), the left edge is computed from it, every
interior row is padded or cut to the interior width, and the footer's row is
reserved: the bottom border stands above it.

**F6 — the test reader takes only complete frames.**
`crates/gear-board/tests/it/board_contract.rs`: the reader returned a frame
as soon as the clear-screen prefix arrived, so a body without the footer was
accepted. It buffers and takes the text between a clear-screen and the
footer line that ends it now; the predicates are read of whole frames, and a
timeout fails instead of returning half a frame. The reader still waits by
`poll(POLLIN)` and never sleeps.

## Tests

`crates/gear-board/tests/it/board_contract.rs`:

- `a_frame_without_the_footer_is_never_accepted` — a clear-screen and a body
  without the footer are not a frame; with the footer they are (F6);
- `a_long_graph_draws_its_last_task` — the frame draws the last task of a
  graph that is longer than the viewport (F8);
- `a_long_graph_scrolls_and_a_tall_panel_keeps_its_borders` — a pty of 80x24
  with thirty tasks: a click on the visible Graph tab switches to the graph,
  repeated `Down` keeps the last task visible, `Enter` opens it, a panel that
  is taller than the terminal keeps both borders and the footer's row (F2,
  F3, F8).

The pty test reads a frame after every key: the board redraws on its own too,
and a pty whose output is not read blocks the board.

## Open questions

The graph's legend (the line that says what the symbols mean) is drawn after
the task rows, so a graph longer than the viewport pushes it off the screen.
The review set the legend aside ("no independent correctness defect"), and
fixing it means the view's own layout, not the frame's.
