# T-97 — An unconfirmed delivery never holds a seat forever

Attempt 1, contract v1.

Branch: `course/t97`; the candidate named in the hand-in includes this report.
Base: `origin/dev` merged into the branch before the hand-in.

## What changed

The live case (multi, T-3): a delivery stayed `submitted` past its check budget,
the seat was flagged every tick, the captain restarted the agent by hand, and
the task was never delivered again — the unsettled op held the seat's delivery
slot forever.

**1. The budget spent fails the delivery (frees the slot), rings the captain
once.** `ops::confirm_pending`: a `Deliver` op at its check budget becomes
**Failed** with the reason (`delivery not confirmed after N checks (the lane
never showed task T attempt n): it is delivered again in a new agent session`)
and the seat is flagged once. The flag opens the existing stall item (one open
item per seat; no flag follows, because the op is gone) — the captain is rung
once, not every tick. `OpState` gains `Submitted → Failed`: the one way a
submitted op ends without being confirmed; a confirmed op stays settled.

**2. The open attempt is delivered again, once per new agent session.**
A new `delivery` record (store meta `engine.delivery.<seat>`: task, attempt,
generation, session, `retry_now`) says what was sent and never confirmed.
`dispatch::lane_view` carries it; `decide` blocks a `Delivered` attempt whose
record belongs to **this** session, and allows it when the pane reports a new
session (a hand restart) or the seat has a new generation (a restart GEAR did).
`intend_dispatch` clears the record when the attempt is on its way again; a
confirmed delivery clears it too. `lane_view` keeps a `Delivered` attempt whose
task is still `Ready` — a delivery that was never confirmed never started the
task, and the attempt is the seat's open one (before, the view was empty and
dispatch tried to start a second attempt).

`observe::SeatObs` now carries the agent session the pane reports, and
`observe::record_sessions` keeps the binding's `session_ref` equal to it: the
session a delivery was sent into is the binding's, and after a hand restart the
store must say so — otherwise every later failure still looked like "a new
session" and the attempt would be re-delivered every tick.

**3. A quota screen on the first turn is the quota path, not a stall.**
An in-place model switch types into the agent after the delivery, so the prompt
cannot be trusted: `quota::finish_switch` now retires the seat's unconfirmed
`Deliver` ops (Failed, reason names the switch) **without flagging** — the
policy is handling the seat — and the Continue op the switch already writes is
the delivery again. No stall item is raised for a lane the quota path is
switching.

## The acceptance

`crates/gear-engine/tests/it/undelivered_delivery_contract.rs` (`FakeHerdr`,
budget 2, real `tick`s):

- `an_unconfirmed_delivery_fails_once_and_goes_again_in_a_new_session`: the
  delivery is submitted, never confirmed → op Failed with the reason, **one**
  captain item (one open message in `stall:p:heat`), the prompt not repeated in
  the same session (two more ticks: still one op, one prompt, one item); the
  pane then reports a new session (`set_agent_session`, what a hand restart
  looks like) → **one** new delivery of the same attempt (`Continue T-1`), which
  a view confirms (op Confirmed, attempt Started, task Running), and the item
  count stays one.
- `a_second_failure_waits_for_the_next_session`: a second failure in the new
  session gives exactly one retry, not a loop; the record follows the session
  that failed.

`quota.rs` unit test `a_switch_retires_an_unconfirmed_delivery_without_a_stall_item`:
a submitted delivery + a quota screen → the switch retires the op with its
reason, the switch's Continue is the delivery again, no stall item, the seat
stays Active.

`delivery.rs` unit tests: the record round-trips; a damaged record is no record
(never a start into a pane nobody checked).

Fixtures: `SeatObs` literals in the tests carry `session: None`; the two T-68
blocked-delivery tests now insert the view a real lane produces when it reads
the delivery (a delivery nobody confirms is now, by design, failed) and assert
the assignment went once.

## Found while running the suite (and fixed)

The engine's own git subprocesses inherited the seat identity of whoever started
them: with `GEAR_CTX` in the environment (the suite run from a seat), T-72's
pre-push hook resolved the push against the starter's project and refused every
merge (`NO_TARGET: … belongs to no repo of project gear`) — ten merge tests red
on the base. `merge::git_with_lock` now runs git with `GEAR_CTX`, `GEAR_DB` and
`GEAR_ADMIN` removed; the engine is not a seat, and its own push is checked in
process (`push_allowed`) before it runs.

## Notes / out of scope

- A kind that reports no agent session has no hand-restart signal; a new
  generation (a restart GEAR did) still retries, and the captain's item says
  the lane is stuck.
- The captain's item is the existing stall item; resolving it is the captain's
  step, and it never blocks the retry.
- A re-delivery is a Continue of the same attempt, not a new attempt.
