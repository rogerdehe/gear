# T-97 — An unconfirmed delivery never holds a seat forever

Attempt 2, contract v1 — the rework of the review's F1 and F2.

Branch: `course/t97` (the rework continues on the task's branch); the candidate
named in the hand-in includes this report. Base: `origin/dev` merged into the
branch before the hand-in.

## Rework (attempt 2)

**F1 [P1, blocking] — the failure names the session the prompt went into.**
The record was built from the binding's `session_ref` *at failure time*, and
`observe::record_sessions` refreshes that binding every tick. A hand restart
between the send and the budget expiry therefore made the record name the **new**
session (B) as the one that failed to confirm, so dispatch saw "same session"
and the open attempt was never delivered into B — a second hand fix.

Now the session is fixed when the op is prepared for its send:
`ops::execute_intended` writes `engine.deliver_session.<op id>` from the
binding as the prompt goes out (same transaction as the `Executing`
transition), and `confirm_pending` builds `FailedDelivery.session` from that
snapshot — the current binding is only the fallback for an op prepared before
this change. The key is cleared when the op settles. The record now names the
session that received the prompt, so a restart *before* expiry is exactly the
"new session" the retry belongs to.

Regression `a_restart_before_the_budget_expires_gets_the_open_attempt`
(budget 2, cooldown 5, the review's tick sequence): session A, tick 1 (prompt),
tick 5 (first check), session B, tick 9 (the delivery fails) → B receives
**exactly one** delivery of attempt 1 in the same tick, a view confirms it, and
the attempt starts.

**F2 [P1, blocking] — a failed continue is not repeated in the same session.**
`confirm_pending` fails unconfirmed deliveries of every open state, but
`dispatch::decide` applied the failed-delivery guard only to
`AttemptState::Delivered`, so a failed **Continue** (a Started/Stopped attempt)
was re-delivered at once — the same session, the same budget, a loop. The guard
now covers the whole `Started | Stopped | Delivered` arm (task/attempt match and
the session/generation checks unchanged).

Regression `a_failed_continue_is_not_repeated_in_the_same_session`: session A,
tick 1, view, tick 5 (the assignment is confirmed), tick 9 (a Continue goes),
ticks 13 and 17 (its budget is spent → it fails) → **no** replacement op in A at
ticks 17 and 21, nothing retyped; session B then receives exactly one delivery
of the same attempt.

## What shipped in attempt 1 (unchanged here)

- The budget spent fails the `Deliver` op with the reason (the seat's slot is
  free) and flags the seat once — one stall item, not a flag every tick.
  `OpState` gains `Submitted → Failed`.
- The open attempt is delivered again at most once per agent session: the
  `engine.delivery.<seat>` record (task, attempt, generation, session,
  `retry_now`) blocks the session that failed and allows a new one (a hand
  restart, which `observe::record_sessions` also writes into the binding, or a
  new generation). A confirmed delivery clears it. `lane_view` keeps a
  `Delivered` attempt whose task is still `Ready`.
- A quota screen on the first turn: `quota::finish_switch` retires the seat's
  unconfirmed delivery without a flag (no stall item) and the switch's Continue
  is the delivery again.
- The engine's own git runs without `GEAR_CTX`/`GEAR_DB`/`GEAR_ADMIN` (found
  while running the suite inside a seat; dev has since fixed the tests the same
  way — kept, it is the engine's own correctness and costs nothing).
