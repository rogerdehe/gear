# T-213 — A doorbell queued behind a working agent is not a stall (contract v1)

Scope: T-213 — in `crates/gear-engine/src/ops.rs`, `confirm_pending_with` takes
the seats whose agent Herdr reports **working** this tick; a doorbell of such a
seat spends no check budget, so the budget counts only the checks made while the
agent is idle or done. A delivery keeps its wall-clock window.

Branch: keel/t213 (code @ the hand-in commit; origin/dev merged before the final
verification)

## The bug

The push reminder and the overrun question rang a lane in the middle of a 4-7
min build or suite (M4 05:45 mast, 05:50 keel). pi queues the typed text
behind its running turn, so the doorbell op stays `Submitted` until the lane
comes back. Every check without a view of the lane's home page bumped the op's
check budget; when the budget was spent the engine flagged the seat and opened
"lane is stuck" — for a lane that was busy, not stuck.

## The fix

- `crates/gear-engine/src/ops.rs` — `confirm_pending_with` takes a new
  argument `working: &[String]`: the seat ids whose agent Herdr reports
  working this tick. A `Doorbell` op of such a seat `continue`s before its
  check budget is bumped, exactly as the `on_quota` branch does; the budget
  therefore counts only the checks made while the agent is idle or done. The
  branch is guarded by `op.kind == OpKind::Doorbell`, so a delivery is
  untouched: its window is wall clock (`timing.delivery_grace_s`) and a
  working agent is not spared it.
  `confirm_pending` (the wrapper without a window) passes an empty set, so a
  caller that knows nothing about the agents behaves as before.
- `crates/gear-engine/src/lib.rs` — the tick hands the set over: the seats of
  this project's `observed` whose agent is `Present` and whose status is
  `AgentStatus::Working`. The observed seats are the ones the tick already
  has; no second observation and no new store state.

## The tests

`crates/gear-engine/tests/it/doorbell_working_budget_contract.rs`:

- `a_doorbell_to_a_working_seat_spends_no_budget_and_flags_nothing` — four
  checks with a budget of 2: the op stays `Submitted`, its check budget stays
  0 and no seat is flagged.
- `the_budget_counts_again_once_the_agent_is_idle` — the same op: while the
  agent works nothing is spent; the first check with an idle agent spends the
  first check, the second spends the budget and flags the seat.
- `a_delivery_keeps_its_window_while_the_agent_works` — a Deliver op with a
  window of 8 s and a working agent: it fails after the window as before and
  the seat is flagged.
- `a_working_lane_opens_no_stall_item` — the whole tick (`FakeHerdr`, a lane
  whose agent is `Working`): three ticks over a budget of 2 open no stall item
  (`stall:p:heat` stays empty), the lane is not flagged, the doorbell op stays
  `Submitted` and its check budget stays 0.

The first two and the fourth fail on the code before the fix (the budget is
spent and the seat is flagged) and pass with it. The delivery test passes
before and after: the window of a delivery is unchanged.
