# T-230 — A passing direction check is not sent to the lane (contract v1)

Scope: `crates/gear-engine/src/review.rs` only (plus this report).

Candidate: `5fa255f5` on `hull/t230` (cut from `origin/dev`, the integration
branch).

## The bug

`fn finish_direction_results` decided a direction check by the whole body:

```rust
if result.body.trim().to_lowercase() != "ok" {
```

A reviewer that annotates a pass — `ok. Candidate follows contract v4 …` —
was read as a problem list and the lane got an urgent instruction. M4.1: keel
handed in already and spent minutes chasing it.

## The fix

`crates/gear-engine/src/review.rs`:

- `fn direction_passed(body: &str) -> bool` — true when the **first word** of
  the trimmed body, lower-cased and with a trailing `.`, `,`, `;`, `:` or `!`
  removed, is exactly `ok`. `finish_direction_results` now tests
  `if !direction_passed(&result.body)`.
- The direction packet (`job_packet`, `direction == true`) ends with the asked
  sentence: `Hand in: gear send --kind result --task {} --attempt {}
  --direction "ok" when nothing is misread, else --direction "<up to three
  problems: the contract sentence misread and what to do instead>".`

## The tests

- `direction_passed_reads_only_the_first_word` — `"ok"`, `"OK."`,
  `"ok. Candidate follows contract v4"` pass; `"okay"`,
  `"F1: misread the contract sentence"` and `""` do not.
- `direction_checks_follow_pushes_and_report_results` — the first direction
  result of the existing flow is now the body
  `ok. Candidate follows contract v4; src/base is the right place` (was `ok`),
  and the test asserts that the lane's inbox holds **no** urgent instruction
  after `finish_direction_results`. The rest of the test is unchanged: the
  later problem-list result still produces exactly one urgent instruction.
