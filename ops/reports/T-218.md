# T-218 — the first unconfirmed delivery waits for its one automatic retry

Task: T-218, attempt 1, contract v1. Lane: keel. Branch: `keel/t218`.
Goal: finish T-206 (ops/reviews/T-206.md, round 2 F3, still open in round 4).

## What the contract asked

In `crates/gear-engine/src/ops.rs` `confirm_pending_with`, the failed Deliver
op's seat has its one automatic retry pending (the marker T-206 sets to
`allowed`/`pending`): the seat must not be pushed into `flagged`. The stall
item opens only when the retried delivery itself fails or is not confirmed in
its own window.

## What I changed

### `crates/gear-engine/src/ops.rs` (`confirm_pending_with`)

The failure branch of a Deliver op keeps the retry marker of T-206 and now
reads it before the seat is flagged:

- no marker yet: this is the **first** failure. The marker `allowed` is set
  **only** when the delivery can still get the one automatic retry — a lane
  seat whose attempt waits for its check-in (`Delivered`), the rule
  `lane_nudge::retry_eligible` checks. Every other seat (a reviewer, the
  captain) has no such retry, so its unconfirmed delivery still reaches the
  captain at once, as before.
- marker `allowed`: the retry may still come — the captain is not rung.
- marker `pending`: the retried delivery failed too. The marker is cleared
  and **the captain is rung** — the one stall item.
- marker cleared (empty): the one retry is spent; a new failure stands and is
  rung. The empty value never counts as permission.

`flagged.push(...)` happens only when no retry is pending
(`lane_nudge::retry_pending`).

### `crates/gear-engine/src/lane_nudge.rs`

- `retry_pending(tx, seat, task, attempt)`: true for `allowed` and `pending`,
  false for the cleared empty value.
- `may_retry(tx, seat)`: now uses `retry_pending`, so the cleared empty value
  is not permission any more (it used to be "the marker is there").
- `retry_eligible(tx, project, seat, task, attempt)`: the seat is a lane and
  its attempt is `Delivered` — the delivery the lane's own path may deliver
  again once.

### `crates/gear-engine/src/lib.rs` (the outstanding-failure sweep, step 10)

The sweep re-flags a seat whose failed delivery is still outstanding while a
stall item is active. It now skips that while the one automatic retry of the
delivery is still ahead (`retry_pending`), so an earlier active stall cannot
restore the suppressed first-delivery flag. The independent causes are kept:
a missing agent, an escalation and the "the work ended" branch (which clears
the failed-delivery record and resolves the item) are unchanged.

slot is free, the record blocks a second delivery in the same session, the

## Edge cases (logged, not fixed here)

- A lane whose delivery fails while its agent never goes idle (the agent
  works, the attempt never starts) gets no automatic retry, so the first
  failure is held back and no captain item opens. The contract says the item
  opens only when the retried delivery fails, so I did not add a timer of my
  own; the fix would be a design decision (a deadline on the `allowed`
  marker).
- The marker is kept per seat/task/attempt. A later failure of another
  delivery op of the same attempt while the marker still says `allowed` is
  held back as well; the lane's own path redelivers once more and the retry's
  failure then rings the captain.
