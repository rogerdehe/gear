## What changed

**`crates/gear-usage/src/quota.rs`** (new) — the API of §13.2:

```rust
pub enum QuotaReader { Minimax, OpencodeGo, Codex }
pub struct Window { pub name: String, pub used_percent: f64, pub resets_at: Option<Ts> }
pub struct Reading { pub provider: String, pub windows: Vec<Window>, pub read_at: Ts }
pub fn read_quota(reader: QuotaReader, key: &str, codex_session: Option<&str>, now: Ts) -> Result<Reading, String>;
pub fn read_quota_in(reader, key, codex_session, now, home) -> Result<Reading, String>;
```

- **minimax** — `GET https://api.minimaxi.com/v1/api/openplatform/coding_plan/remains`
  with the key as a bearer token. Per entry of `model_remains` two windows:
  the 5 h one (`current_interval_remaining_percent`, `end_time` in ms) and the
  weekly one (`current_weekly_remaining_percent`, `weekly_end_time`). The
  provider says how much is **left**, the reading says how much is **used**
  (`100 − remaining`).
- **opencode-go** — `GET https://opencode.ai/zen/go/v1/usage` with the key as a
  bearer token. `usage.rolling/weekly/monthly`, each a `percent` that is used
  and a `resetsAt`.
- **codex** — the newest `token_count` line of the reviewer's rollout (§4.3):
  `rate_limits.primary/secondary`, each a `used_percent` and a `resets_at` (in
  seconds). The reader looks for the file of the thread in the Codex sessions
  of the last fourteen days, as the reader of §4.3 does. It reads the line
  that carries the rate limits; the rule of §4.3 that a `token_count` whose
  `info` is null is skipped is about **counting tokens** (the totals of the
  session), and a line that carries the rate limits but no token totals still
  carries a quota fact — so the quota reader does not drop it.

**The call** (§9.1): `curl -sS --max-time 15 -H @- <url>`. **The key never
appears on the command line**, where `ps` would show it: it is written to
curl's standard input as the header `Authorization: Bearer <key>`. The
`codex` reader calls no HTTP at all — it reads the rollout file.

**The reasons**: `Err` says what happened — curl could not be started, curl
failed (its exit code and what it said on stderr, which is how a timeout —
code 28 — and an HTTP error — code 22 — come back), the answer is not JSON,
or the answer is not the one of the provider (no `model_remains`, no `usage`,
no window, no rate limits).

**`crates/gear-usage/tests/it/quota_contract.rs`** — the tests of the
acceptance, with a **fake curl on the PATH** (the tests that need it hold a
lock, so only one of them changes the PATH at a time). The fake curl prints a
recorded body (hand-written from §9.1), writes the header it was given to a
file, writes its arguments to a file, and **refuses to run when the key is
among its arguments** — so a reading that comes back proves the key was not
on the command line.
