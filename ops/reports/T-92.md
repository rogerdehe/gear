# T-92 — The captain retries a failed merge from the plan

Attempt 1, contract v1.

A merge that failed on something that can clear (M3: T-89's merge failed on a
flaky test) can be retried from the plan instead of by hand. The failed-merge
inbox item names the line to use.

## What changed

- **`crates/gear-app/src/draft.rs`** — the plan's `# Staff` accepts
  `- remerge T-<n>`: the verb, one task id, nothing else. A malformed id is a
  `BAD_FORMAT` at that line, like every staff line.
- **`crates/gear-app/src/plan.rs`** — `remerge` queues a **new merge op** for
  the task's accepted attempt and candidate, with the payload the engine
  writes when a review passes (the lane's branch as a hint for closing it, the
  candidate, the review branch). It is applied in the plan's transaction, so
  the op and the plan version land together.
  What it accepts, and what it refuses with the reason (the line's number in
  the error):
  - **the task's latest attempt is accepted** and has a candidate — otherwise
    refused ("not accepted: only an accepted attempt is merged");
  - **the task's last merge op is `Failed`** — otherwise refused: `Confirmed`
    is "already merged", `Intended`/`Executing`/`Submitted`/`Unknown` is "a
    merge … is already <state>, not failed: nothing to retry", and no merge op
    at all is "no merge to retry: the engine queues one when its review
    passes";
  - an unknown task is "no task T-<n> in this project".
- **`crates/gear-engine/src/merge.rs`** — the failed-merge item:
  - its body names the line: `to retry it: `- remerge T-<n>` under `# Staff` in
    the plan, then `gear plan apply` (only while the candidate is not on the
    integration branch)`;
  - it has a stable thread per task (`merge-failed:<task>`), so a second
    failure of the same task refreshes one item instead of filing another;
  - it **closes when the merge goes through**, retried or otherwise.

## Acceptance evidence

- `a_failed_merge_is_retried_from_the_plan_and_its_item_closes` (real git, in
  `crates/gear-engine/src/merge.rs`) — the gate fails once (a flaky test) and
  passes the next time: the first merge leaves the op `Failed` with nothing
  pushed and one item saying `merge of T-5 failed` and naming `- remerge T-5`;
  `gear plan apply` with that line queues a second op, the merge lands, and
  the item is resolved.
- `a_remerge_is_refused_without_a_failed_merge` — an `Intended` merge is
  refused ("already intended… not failed"), a `Confirmed` one with "already
  merged".
- `a_remerge_needs_a_task_with_a_merged_attempt` — a task with no merge op is
  refused ("no merge to retry"), an unknown task with "no task T-99".

## Validation

- `cargo test --workspace` → **756 passed, 0 failed** (the merge module: 39).
- `cargo build --workspace --all-targets` → exit 0, no warnings.
- `git diff --check` → clean.
- The tests fail when the engine does the wrong thing (each mutation reverted
  afterwards):
  - the retry line dropped from the failed item → the end-to-end test fails;
  - the item not resolved on a successful merge → the end-to-end test fails;
  - a `Confirmed` merge accepted by `remerge` → the refusal test fails.

## Out of scope

- **The git half of "its candidate is not yet on the integration branch".**
  The plan apply is a store transaction and has no worktree to ask git in, so
  the condition is enforced by the store facts above plus the merge itself: if
  the accepted candidate is already on the integration branch, the engine's
  merge finds it there and confirms without pushing (T-61). The captain's two
  refusal cases in the acceptance (a merged task, a task with no failed merge)
  are store facts and are refused at the plan line.
- **The staff line persists in the plan file**, like `hold` and the other
  staff lines: a later apply with the same `- remerge T-<n>` in it is refused
  with the reason above, so the captain removes the line after it is applied
  (the same convention as the `retry <lane>` line T-82 adds).
- `crates/gear-app` is the `course` lane's crate; the contract names the plan
  line, so this branch changes `draft.rs` and `plan.rs` (the parse and the
  apply) and nothing else there. The engine side stays in `gear-engine`.
