# T-175: engine-side lane rebind

The engine waits for a rebound lane's old attempt to finish and its agent to become idle, exits the old agent, retains its checkout, and moves the lane through normal onboarding in the new repository. Dispatch remains blocked until the new binding is active; the next round starts a fresh session. Ready tasks whose saved repository belongs to the old lane are not dispatched into the new checkout.

Review and merge resolve a task's saved repository, integration base, and gate rather than the lane's current repository. This preserves the target of tasks created before the rebind, including merges that finish after the move.

Tests cover the two-repository rebind through first dispatch, waiting for an open attempt and working agent, preserving the old checkout, a fresh follow-up session, old task review routing, and a real Git merge using the old repository and gate.

`scripts/test.sh` passed all 1,288 tests after merging current development (build 273 seconds, suite 101 seconds; concurrent workspace builds contributed contention).
