# T-220 — "The merge waits" is told once per attempt (contract v2)

Scope: T-220 — in `crates/gear-engine/src/merge.rs`, `tell_captain_waiting`
holds its insert when the meta key
`engine.merge_wait_told.<project>.<task>.<attempt>` is set, and the function
sets that key when it inserts the item. Nothing else changes.

Branch: mast/t220 (code @ the hand-in commit; origin/dev merged in before the
final verification)

## The bug

"the merge of T-2 waits for T-1: their candidate is in T-2's commits and is
not on the integration branch yet" was told again on every tick after the
captain resolved the item — the notice came back for T-184 and T-215 (M4
07:55), once after each resolve, like T-214's review waits.

The reason: `tell_captain_waiting` decided with the **open** items of the wait
thread only. A resolved item is no longer open, so the next tick found no
open item and inserted the same news again. The check had to remember the
notice itself, not the state of the message that carries it.

## The fix

- `crates/gear-engine/src/merge.rs` — a new `merge_wait_told_key(project,
  task, attempt)` builds the key
  `engine.merge_wait_told.<project>.<task>.<attempt>`.
- `crates/gear-engine/src/merge.rs` — in `tell_captain_waiting` the insert
  is skipped when that key is set; the key is written in the same transaction
  that inserts the item, so the notice is told once per attempt.
- Nothing else changes: the notice is still one open item per merge, an
  **open** item's body is still updated as before, and a **new attempt** of
  the same task has its own key, so it is told once again.

## The tests

`crates/gear-engine/src/merge.rs` (engine tests):

- `the_merge_waits_notice_is_told_once_per_attempt` — a merge of T-5 waits
  for T-1, which has not passed: the captain is told once; the captain
  resolves the item; the two later ticks add no item (the thread still holds
  one message); the next attempt of the same task is told once again (the
  thread holds two messages).

The test fails on the code before the fix (the notice comes back:
`the notice comes back: [MessageRow { … id: "M-2", thread: "merge-wait:T-5" … }]`)
and passes with it.

## Verification

- `cargo test -p gear-engine --lib merge::tests::the_merge_waits_notice_is_told_once_per_attempt`
  → 1 passed, 0 failed.
- `scripts/test.sh` → the whole workspace passes (1355 tests, 0 failed).
- `cargo build --workspace --all-targets` → no warning from this change.
- `git diff --check` → clean.

## Out of scope

- The captain's item about a waiting merge is still one open item per merge:
  the fix only keeps the notice from coming back after it was resolved.
- The other captain notices (quota, review, stall) keep their own rules; the
  packet names only the merge notice.
