## The rework's three fixes

**(a) The three merge tests are inside 10 s, without an allowlist entry.** The
fixtures and the merge's per-attempt work were both too expensive:

- Each fixture shape is now written by one `git fast-import` (a stream built
  from the shape's data) plus one shell that checks the checkout out of it:
  three processes for a whole repo, where every task branch used to cost eight
  git calls — a shape with three tasks was twenty-odd.
- The merge's own attempts spawn less. One `rev-list` names everything a
  candidate carries *and* answers "already merged", replacing up to three git
  processes per other task per attempt (a waiting merge runs an attempt on
  every tick). The merge lock's path is read from the worktree's `.git` instead
  of `git rev-parse --git-path` — `the_merge_lock_is_the_file_git_names` holds
  the two equal for a plain checkout and a linked worktree. An older engine's
  hook is cleaned once per worktree, not once per attempt. The tests' runner
  remembers a checkout's origin path. A candidate the op already names by full
  sha is not resolved again, and `for-each-ref --contains` proves it is here
  while it proves it is pushed. The branch-closing step reuses that listing
  (one `--points-at` and one `rev-parse` per landing fewer).
- The tests read the integration branch's log once and their assertions read
  the string (`log_has`); each `dev_has`/`grep -qx` used to be a git process.

**(b) Review F2 — the typed-input settle is Herdr's, not a test's.** The 300 ms
after typed text belongs to the terminal (`L-71`: an agent's TUI must take the
keystrokes before the Enter). It is now `HerdrAct::type_settle`, required of
every implementation: `SocketHerdr` sleeps the new
`gear_herdr::TYPE_SETTLE_MS`, `FakeHerdr` and the live example's `NoKeys` wait
for nothing. `switch.rs::text` no longer sleeps, and the integration tests go
through the same boundary, so no caller of a fake waits.
`switch::tests::the_switch_uses_the_production_sequence_one_submission_per_tick`
drops from 0.66 s to 0.27 s: the two 300 ms waits are gone, and its assertions
(input order, one submission per tick) are untouched. The previous report's
blanket claim that no engine test slept was wrong; this is the fix and the
correction.

**(c) Review F3 — the strict completion-time assertion is back.**
`a_gate_that_is_still_running_does_not_block_the_merge_step` launches the tick
at `wall_time() - 1`, a deterministic second before the completion, and asserts
`op.updated > launched_at` again, plus `op.updated >= released_at` (sampled
before the gate is let go) and the attempt-time equality. A merge that recorded
the launching tick's time fails it, exactly as before, and nothing sleeps to
make the second pass.

## The engine test binaries, and why they are cheap now

- `EngineCfg.merge_retry_wait: merge::RetryWait` (attempt 1) — the retry wait
  is a field and a hook: the default sleeps 2 s doubling to 30 s (T-61's
  behaviour), a test injects `RetryWait::immediate()` or `instead(f)` where the
  wait must do something (the late-push test publishes the branch there).
- `MergeWorkers::{progress, wait_progress, running}` — the worker bumps a
  counter under a condvar when it reports and when its result is collected;
  `tick_step`, `wait_merge`, `drive`, `ticks` and the `it` crate's `wait_merge`
  block on that instead of polling on 10-20 ms sleeps against 120 s and 30 s
  deadlines.
- Gates that must be held open are fifo handshakes (`await_fifo` /
  `release_fifo`), disarmed after their first run so a recovery or a retry does
  not block on a fifo nobody feeds.

## Assertions: restored, changed, none weakened

- (c) above restores the original strictness.
- `a_killed_worker_recovers_from_origin_without_a_half_merge` waits for the
  orphaned gate with `assert!(done.exists())` instead of a 10 ms poll loop: the
  gate holds the merge lock, so recovery cannot finish before it exits — the
  same fact, no clock.
- `dispatch_and_doorbells_continue_while_the_gate_sleeps` and
  `a_sleeping_gate_does_not_block_the_merge_step` are renamed to
  `…while_the_gate_runs` and `a_gate_that_is_still_running_does_not_block…`;
  their assertions are unchanged.
- `a_candidate_pushed_late_merges_after_the_retry` publishes the lane's branch
  from the retry wait itself instead of a thread that slept 500 ms; same
  assertions, and the order the test is about is now exact.
- `tick_step` panics when a merge step had nothing to run, where the old loops
  spun until a deadline: stricter, and it keeps a test from passing on a no-op
  tick.
