# T-107 — No push allow-list in the engine, and no `git push` in its tests

Contract v1, from the user (2026-10-26). GEAR's engine installed a pre-push
check in every worktree it made and ran the same check in-process before the
merge pushed. Both are gone: the engine has no allow-list at all, and its tests
never run `git push`.

## What changed

- **`crates/gear-engine/src/hooks.rs` is deleted**, with its module line and
  every call. The engine no longer writes a `pre-push` script, no longer reads
  `core.hooksPath`, and ships no `gear push-check` chain.
- **an old hook is removed on onboarding** — `onboard::forget_gear_hooks` reads
  the worktree's `core.hooksPath`; when it is GEAR's own (`…/gear-hooks`), it
  unsets it and removes the directory, so an existing lane or reviewer loses
  the hook the next time its worktree is opened. A repository's own hooks are
  never touched. It runs for lane worktrees (`onboard.rs`), reviewer worktrees
  (`review.rs`) and the merge's integration worktree (`merge.rs`).
- **the in-process destination check is gone** — `merge.rs` no longer calls
  `push_allowed`, no longer writes the "push refused" op failure, and
  `tell_captain_refused` is deleted. The merge pushes as before.
- **one runner for the remote** — `merge::Remote` is the single place a merge
  touches the remote: `push(dir, dst)` and `delete(dir, branch)`. Production is
  `GitRemote` (the only `git push` in `crates/gear-engine`); `EngineCfg` carries
  an `Arc<dyn Remote>` (default `GitRemote`), and the merge worker, the retries,
  `merge_one` and the branch closing all go through it.
- **the tests' runner moves refs from the remote's side** — `merge::FetchRemote`
  learns the origin's path from the worktree and runs
  `git -C <origin> fetch <dir> HEAD:refs/heads/<dst>` (no force, so a
  non-fast-forward is still refused like a push) and
  `git -C <origin> update-ref -d refs/heads/<branch>` for a delete. Every
  engine test that merges uses it (`EngineCfg` in `merge.rs`, `multi_repo_contract.rs`).
- **the fixtures publish without pushing** — the engine's test fixtures seed
  their branches with a `publish(work, branch)` helper that fetches the ref into
  the bare origin and then fetches it back (`merge.rs` tests,
  `multi_repo_contract.rs`), and the two gate fixtures that moved `dev` during
  the gate do the same. The merge's own push failures are produced by the
  runner, not by a hook.
- **tests removed or reworked**: the two T-72 allow-list tests
  (`a_second_unregistered_push_url_stops_the_merge`,
  `a_refused_destination_stops_the_merge_with_one_item`) and the CLI's
  `push_hook_contract.rs` are gone with the feature; the retry test
  (`a_push_that_a_hook_rejects_once_is_retried_and_lands`) became
  `a_push_that_fails_once_is_retried_and_lands`, driven by a `FailOnceRemote`.
- **no `gear_app::push` call remains in `crates/gear-engine`**, so course can
  delete `gear-app/src/push.rs` next.

## Acceptance evidence

- `grep -rn '"push"\|push -q\|push origin' crates/gear-engine` → two lines, both
  the one production runner (`GitRemote`). No test and no fixture runs
  `git push`.
- `crates/gear-engine/src/hooks.rs` does not exist.
- `an_old_gear_hooks_path_is_unset_on_onboarding` (in
  `crates/gear-engine/src/onboard.rs`) — a real repo with a linked `home/heat`
  worktree that sets `core.hooksPath` to its own `gear-hooks` directory (and a
  script in it) is opened by the engine for the lane; the lane is onboarded,
  the worktree config no longer sets `core.hooksPath`, and the directory is
  gone. A repository's own hooks are not touched.
- `a_push_race_is_retried_and_the_merge_lands`, `dev_moving_during_the_gate_is_a_race`,
  `a_clean_merge_is_pushed_and_the_branches_are_gone` and the rest of the merge
  suite pass on `FetchRemote`: a merge lands, closes its branches on the remote
  and still detects a race.
- `cargo test --workspace` passes.

## Validation

- `cargo test --workspace` → **830 passed, 0 failed**.
- `cargo build --workspace --all-targets` → exit 0, no warnings.
- `git diff --check` → clean.

## Out of scope

- **`gear-app/src/push.rs` and the CLI's `push-check`** still exist and are
  still tested by `push_check_contract.rs`; the task leaves their removal to
  course. The engine no longer calls them.
- **Lane pushes are unguarded now.** That is the user's decision: the gate is
  the project's own CI and the merge's gate, not a destination allow-list. A
  project that wants to restrict pushes does it in its own git hooks, which
  GEAR leaves alone.
