# T-134 — Every seat's agent keeps its Herdr name (attempt 2)

Attempt 2 is the rework the review of attempt 1 asked for — **F1 only** (F2 and
F3 are logged by the review, not required here):

- **F1 — a reviewer's agent keeps its task-based name.** Attempt 1 derived every
  seat's desired name as `<project>-<seat>`, so a warm `review-10` seat's agent —
  started by `review::start_reviewer` as `<project>-review-t<n>` — was renamed to
  `p-review-10` on the next restore or delivery, and restored to that wrong name
  after a clear. There is now one seat-aware helper, `names::desired(&seat)`: an
  assigned Temp reviewer is `names::review_agent_name(project, task)` =
  `<project>-review-<normalized task id>` (the `review::agent_name` rule, which
  now delegates to it so the start name and the restore name cannot drift), and
  the captain and lanes are `<project>-<seat name>`. It is derived from the
  store's seat (role + `task_id`), never from what Herdr reports now — a cleared
  or wrong name is exactly what is being repaired. It replaces the inline
  `<project>-<seat>` at **every** naming site: the tick's `names::restore`, both
  ops paths (`execute_intended`'s prepared op and `deliver_doorbell_now`) and the
  pre-send ensures in `restart.rs`, `release.rs` and `switch.rs`.
  Tests (`agent_names_contract.rs`): `a_correctly_named_reviewer_gets_no_rename`
  (a `review-1` seat assigned T-7 whose agent is `p-review-t7` is not renamed,
  and the restore reports no rename for it) and
  `a_cleared_reviewer_is_restored_to_its_task_name_before_delivery` (cleared
  agent + an Intended packet delivery: `execute_intended` renames to
  `p-review-t7` **before** the packet prompt goes out, and never to
  `p-review-1`). Both fail with attempt 1's rule (checked by temporarily
  restoring it) and pass with this one.

Scope: T-134 — Herdr clears an agent's name when it re-detects the occupant (a
server restart, a CLI that changes its session) and `agent.prompt` refuses an
unnamed agent ("agent <pane> is not an active named agent"; in M3.1 the captain
and both lanes lost their first deliveries to it). Now every tick gives each
seat with an active binding its name back; a name another pane holds is
reported to the captain once and never stolen; before every prompt, doorbell or
key send to a seat's pane the engine makes sure of the name, so a delivery to a
pane whose agent lost its name renames it and delivers in the same tick; and
`gear captain take` names the new captain's agent.

## Open questions

none — four decisions worth naming:
- **Where the name lives.** `agent.list`'s payload is read straight from the
  socket because the board client's `AgentInfo` drops `name`; adding a field to
  a third-party typed view was not an option, and a `session.snapshot`-based
  parse would have been the same raw read for more data.
- **The fake refuses unnamed prompts.** That is what Herdr does, and it makes
  every existing test exercise the ensure path rather than only the new ones.
  Fixtures that assert exact call lists now name their agents, as a real started
  agent is named.
- **Who is renamed before a key send.** The deliveries (prompt/doorbell), the
  two exits (restart, temp release) and the model switch. The onboard teardown
  is exempt (its occupant is leaving; the next start names its replacement).
- **The captain's own name collision is not reported to the captain** (nobody
  else to tell; its doorbell is the signal) and is retried every tick. A
  lane/reviewer collision is one item per spell, in `name:<seat>`.

## Out of scope

- The name is not written to the store: Herdr is its owner, and a stored copy
  would be one more thing to keep true. The store keeps the seat's name, from
  which the agent name is derived.
- No retry budget or back-off for a rename that Herdr leaves *uncertain*: the
  next tick (and the next prompt) looks again; only a proven-taken name is
  reported.
- The skill text is untouched: `gear --skill` never speaks about agent names,
  and the M3.1 rule is that skill additions are reviewed by subtraction before
  the release.
