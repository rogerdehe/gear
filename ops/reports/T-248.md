# T-248 — the doorbell says exactly what to run, attempt 1

Scope: the doorbell text ended with "Run `gear` now." (and, with no task, "Run
gear, answer them, …"). Pasted or shown without the backticks it reads "Run
gear now", which an agent can take for a command `gear now`.

Branch: hull/t248, `origin/dev` merged in before the hand-in.

What changed (`crates/gear-engine/src/doorbell.rs` and the tests that assert the
text):
- With a task: `GEAR: <n> item(s) waiting for you[ (<k> urgent)]: <ids>. Run the
  command `gear` (no arguments) in your own shell; it shows only your items.`
- With no task: `GEAR: <n> item(s) for you: <ids>. Run the command `gear` (no
  arguments) in your own shell, answer them, then end your turn. You have no
  task now: do not continue earlier work.`
- The doc comment above `fn text` states both texts verbatim and says why the
  command is spelled out: the backticks are lost as soon as the text is pasted
  or shown (T-248). The `DoorbellAction::text` example and the `decide` doc line
  that quoted the old sentence were updated with it.
- Tests updated: `doorbell_contract.rs` (three expected texts, the `contains`
  assertion, and the test renamed `the_text_names_every_id_and_the_command_to_run`),
  `delivery_grace_contract.rs` (both texts), `eng_execute.rs` (the action
  fixture), `eng_intend_recover.rs` (its fixture text, kept in the new form).

Second pass (attempt 2): the acceptance says no test or source line under
`crates/` may contain the old sentence, and one fixture still did —
`ops.rs`'s `doorbell_for` (a doorbell payload fixture added by T-241) carried
`GEAR: 1 item(s) waiting for you. Run `gear` now.`. It now carries the new
sentence, so the acceptance holds for every file under `crates/` and not only
for the tests the packet named.

Verification (attempt 2, on the merged tree — `origin/dev` merged in again
before this hand-in):
- `make check CRATE=gear-engine` → 620 tests run, 620 passed, 0 skipped.
- `rg 'Run `gear` now|Run gear, answer' crates/` → no match.
- `cargo build -p gear-engine --all-targets` → no warnings.

Open questions: none.

Out of scope: everything else in the doorbell; the server/CLI side has no copy
of this text. `friction.rs` still says "Run gear friction." — that names the
`gear friction` subcommand, not `gear`.
