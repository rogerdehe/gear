# T-236 — A dependency counts when it is merged, not when it passed (contract v2)

Scope: `crates/gear-engine/src/dispatch.rs`,
`crates/gear-engine/tests/it/lane_view_contract.rs` (one fixture, one new test)
and this report.

Candidate: `f26abbde` on `hull/t236`; merged with `origin/dev` (`2343a033`) as
`84dad739`.

## The bug

`ready_tasks_of` answered "are this task's dependencies satisfied?" from
`TaskState::Done` alone. `Done` is written by the review pass, before the merge
op reaches the integration branch, so a dependant was dispatched while its
dependency's work existed only on the other lane's branch — M4 F-76: the lane
built on that branch and merged twice.

## The fix

`crates/gear-engine/src/dispatch.rs`, `fn ready_tasks_of`: `done` is now built
by a loop that keeps a task id only when the task is `Done` **and**
`gear_app::tasks::merged_at(tx, &seat.project, &task.id)?` is `Some` — the
merged time of one of its attempts. The loop runs before the final filter so the
`?` works. The task filter chain below is unchanged.

## The tests

`crates/gear-engine/tests/it/lane_view_contract.rs`:

- `a_done_dependency_counts_only_once_its_work_is_merged` (new, the packet's
  acceptance): B depends on A; A is `Done` with an attempt and no merged time →
  B is not ready; after `AttemptStep::Merged` is written on A's attempt → B is
  ready.
- `ready_tasks_are_this_lanes_ready_with_done_deps_in_rank_order`: the same
  fixture, whose `Done` dependency T-1 has no attempt at all; it now gets one
  (`AttemptState::Accepted`) with a merged time, so the same expectation
  (`["T-3", "T-2"]`) holds for the right reason. No other test asserted a
  dependency on a `Done` task that is not merged, so nothing else changed.

`cargo test -p gear-engine` passes (296 unit + 306 integration, 0 failed) on the
branch with `origin/dev` merged in; `cargo check -p gear-engine --all-targets`
gives no warning.

## Out of scope

- `tx.attempt_times_of_task` is read once per `Done` task on every readiness
  call; for a project with many done tasks that is more store reads than before.
  Nothing measured it as a cost and the packet says nothing else changes.
- `require_merged_at` (the stricter check: `Done` **and** a confirmed merge op)
  is not what the packet asked for here, so `ready_tasks_of` accepts a merged
  time without the op check.
