# T-65 — The engine finishes a lane's retirement

Attempt 1, contract v1.

A lane the plan puts in `Retiring` is taken out by the engine: its agent gets
the profile's goodbye, its pane is closed and the seat becomes `Retired` — in
that order, once. A lane still working finishes after its current hand-in.
(M2 and M2.1 landings: the captain closed the panes and set the seats by hand.)

## What changed

- **`crates/gear-engine/src/release.rs`** — `retire_finished_lanes`: for every
  `Lane` seat in `Retiring`
  - **busy?** an attempt that is not handed in (Started, Delivered, Stopped,
    Unknown) keeps the lane: it is finished after its current hand-in. A
    handed-in attempt (Submitted) is the lane's safe point — design/10:
    "submitted ones continue through acceptance" without the lane;
  - **a turn in progress?** the lane must be idle in this tick's observation,
    or already have no agent (a lane mid-turn is not cut off);
  - **then, in order**: the profile's `exit_command` (a `Prompt`) if it has
    one, else its `exit_keys` (a `SendKeys`) → the pane is closed (a closed
    pane ends an agent that ignored its exit; a pane already gone is fine) →
    the seat becomes `Retired` and its binding is voided, so a later
    re-registration opens a fresh pane.
  - The worktree is kept: its build cache is the lane's, and design/10 removes
    it only when all the lane's results are merged, which is not this step.
- **`crates/gear-engine/src/lib.rs`** — the tick calls it right after the
  reviewers' release, with this tick's observations and the project's profile
  table; the retired seats are reported in the tick's `released` list.

Once is structural: the seat is `Retired` afterwards, so the next tick's loop
skips it.

## Acceptance evidence (`crates/gear-engine/src/release.rs`, fake Herdr)

- `a_retiring_lane_is_exited_closed_and_retired_in_order` — a retiring lane,
  idle, with no attempt: the recorded calls are `exit` (the opencode profile's
  `ctrl+c`), then `close`; the seat is `Retired`; the next tick adds no call.
- `a_retiring_lane_with_an_open_attempt_is_not_closed` — the same lane while
  its attempt is Started: no call at all and the seat stays `Retiring`; after
  the hand-in the next tick retires it.

## Validation

- `cargo test --workspace` → **786 passed, 0 failed** on the merged result (the release module: 9).
- `cargo build --workspace --all-targets` → exit 0, no warnings.
- `git diff --check` → clean.
- The tests fail when the engine does the wrong thing (each mutation reverted
  afterwards):
  - the open-attempt check removed → the busy-lane test fails (it is cut off
    mid-work);
  - setting `Retired` removed → both tests fail (the seat never leaves
    `Retiring`).

## Out of scope

- **Removing the lane's worktree**: design/10 removes it only when the lane is
  retired *and* all its results are merged; this task finishes the seat, not
  the worktree (the worktree keeps the lane's build cache, and the design's
  ordering is a rule of its own).
- **Pre-empting an in-flight attempt**: design/10 speaks of a safe point via
  the preemption flow; this task waits for the hand-in instead, as the goal
  states ("a busy one is finished after its current hand-in").
- A lane whose agent is `Missing` is retired without the goodbye (the
  observation says there is nothing to exit); the pane close is still tried.
