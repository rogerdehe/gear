# T-100 — no agent acts as the user, and a captain opens no dialog

Scope: T-100 — (1) a **first** `gear admin init` is the user's own act: an agent
is refused, whatever `GEAR_ADMIN` says, while re-applying a registered
project's config from its captain's pane stays allowed; (2) the captain's skill
asks in chat, never through a dialog tool, says the three nevers once, and the
first registration is the user's again.

Branch: base/t100 (code @ the hand-in commit; origin/dev merged before
verification, gate green on the merged result)

Files:
- `crates/gear-cli/src/main.rs` — `cmd_admin_init` checks, before anything is
  written, whether the config's project is registered. If it is **not**,
  `refuse_first_registration_by_an_agent` refuses the caller when it carries a
  `GEAR_CTX` of any project, and when its Herdr pane hosts a recognized agent
  (a shell left in a pane is still the user; a pane that cannot be read is a
  no). The refusal is `FORBIDDEN`, says which seat or which agent it saw, and
  rings nobody — nothing is written. A registered project goes on to
  `admin::init`, whose T-86 rule (the caller must be that project's captain, at
  the registered generation) is unchanged, so a captain's config re-apply is
  still allowed.
- `crates/gear-cli/tests/it/admin_init_contract.rs` —
  `a_first_registration_is_the_users_own`: the user's shell registers it; an
  agent — the captain of that very project — is refused with `FORBIDDEN` and
  nothing is registered; a plain shell then registers it. The captain's
  re-apply, a lane, another project's captain, a stale generation and the
  missing consent keep their tests.
- `skills/gear/references/captain.md` — the kickoff confirms **in chat, in two
  steps** (the bar, then the sheet), never through a dialog tool; the captain
  asks the user to register the project the first time and only re-applies after
  a config change; §4 "What you never do" now says the three nevers once:
  never act as the user (no `GEAR_ADMIN`, no registration, no dialog tool),
  never change the board by hand, and never start an agent outside the plan's
  lanes and reviewers.
- `skills/gear/references/course.md` — at landing the captain reports in chat
  and asks reclaim/release as a plain question in the conversation, never
  through a dialog tool.
- `README.md` — step 3 is the user registering from their own shell again
  (creating a project is the user's act; the captain re-applies a change), and
  the `GEAR_ADMIN=1` line in the captain's pane says what it is for.
- `ops/reports/T-100.md` — this brief.
