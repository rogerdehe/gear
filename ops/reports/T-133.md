# T-133 — a held lane can be released from the plan (attempt 1)

Scope: T-133 — `# Staff` gains `- release <lane>`: a lane in Held goes back to
the state the engine continues or onboards from (`Active` while its agent runs,
`Queued` when it is gone), so the captain no longer edits the store by hand.

Branch: mast/t133 (code @ the hand-in commit; origin/dev merged before
verification)

Files:
- `crates/gear-app/src/plan.rs` — `release_lane`, applied before the generic
  staff match like `retry`/`remerge`, and reported as `staffed: ["release
  heat"]`. Reads the seat, refuses a non-lane and any state but Held
  (`BadTransition`, detail: "… only a lane in Held is released (`- hold heat
  reason=…` puts it there)"), then picks the target from the seat's own
  **binding**: an active binding for the seat's generation is the agent GEAR
  started and has not ended → `Active` (reason "released by the captain: its
  agent continues"); no active binding → `Queued` (reason "released by the
  captain: its agent is gone"). Both transitions go through the shared table.
- `crates/gear-model/src/state.rs` — the lane transition table gains
  `(Held, Queued)`; `(Held, Active)` was already there, so both targets are the
  model's own answer rather than a bypass.
- `crates/gear-app/src/draft.rs` — `StaffItem::Release { line, lane }` and its
  parser (`- release <lane>`, one lane only); the unknown-verb message lists it.
- `crates/gear-board/src/lib.rs` — a held lane's down-seat line now names its
  way back, `- release <lane>`, next to the existing `- retry <lane>` for
  NeedsCheck/Unknown (T-82's convention: the plan line that acts on the seat).
- `skills/gear/references/captain.md` — the `# Staff` list names `- release
  <lane>` in one line, with what it does to a running and to a gone agent.
- `docs/design/10-staff.md` — the HELD row names the verb and both targets.
- Tests: `crates/gear-app/tests/it/plan_staff_contract.rs`
  (`release_brings_a_held_lane_back`: hold → release → Active with its reason;
  a held lane whose binding ended → Queued with its reason; a running lane
  refused with the reason and nothing written; unknown seat and the captain
  refused as `BadFormat`), `crates/gear-engine/tests/it/slice2_dispatch.rs`
  (`a_held_lane_gets_its_next_task_after_release`: held lane is assigned
  nothing, release puts it back, the next tick delivers its task on its
  branch), `crates/gear-board/tests/it/board_contract.rs` (the held line names
  the verb and the reason), `crates/gear-app/tests/it/draft_contract.rs` (parse
  and both malformed forms).
- `ops/reports/T-133.md` — this report.

Verification:
- `cargo build -p gear-app -p gear-board -p gear-engine` → clean, zero warnings.
- The new tests, run alone: 4 passed, and `scripts/test.sh` → **908 tests run,
  908 passed, 0 failed** (build 51 s, run 63 s) on the merged result.
- A leftover `- release heat` line refuses the next apply with `BadTransition`
  ("seat p:heat is active, not held") — the same shape as a leftover `- remerge`
  line, and the reason `captain.md` says to delete the line after the apply
  (T-120's automatic removal is in the M4 backlog, not merged).

Open questions: none.

Out of scope:
- Presence is read from the store, not from Herdr: a plan apply touches Herdr
  only for the captain's identity (design/03), so a pane that vanished **under a
  live binding** is not seen here — that lane returns to `Active`, the engine's
  own observation flags it (L-56), and `- retry` is then the way back. Logged
  per the bar, not reworked.
- T-120 (used `# Staff` lines removed after an apply) is not in this cut, so
  release lines are the captain's to delete like `remerge`/`retry` lines.
- The held seat's board reason reads "held: hold: …" (the plan prefixes
  "hold: " to the captain's reason and the board prefixes the state); that
  wording predates this task and is untouched.
