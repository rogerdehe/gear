# T-164 — plan hygiene and tails that end (B5, B6)

Scope: T-164 — design §10.7 row B5 (a `# Staff` line the apply used is gone
from the plan file, an empty `# Staff` section goes with it, a failed merge's
`next:` names `- remerge T-<n>`, the apply says which lanes the captain's tail
silences) and row B6 (`- tail: <lanes> until=T-<n>` / `until=<RFC3339>` ends
the tail by itself). Attempt 2 fixes the review's F1, F2 and F3: the deadline
and the end of a tail.

Branch: mast/t164 (code @ the hand-in commit; origin/dev merged before final
verification)

## Rework (attempt 2: F1, F2, F3)

- **F1 (P1, blocking) — a deadline may carry fractional seconds and a zone
  offset.** `parse_rfc3339` read the seconds field as a plain number, so the
  stamps a serializer writes (`2026-10-26T18:00:00.123Z`) were refused and the
  whole plan apply failed. The fraction is now parsed and validated (digits
  only), and a nonzero fraction rounds the moment **up** to the next second:
  the tail must not end before the instant the captain named. `Z`, `+hh:mm`
  and `-hh:mm` are all read.
- **F2 (P1, blocking) — a tail that has ended stays ended.** The end was
  evaluated afresh on every read, so a task that was reopened for a rework (a
  failed merge) brought the tail back with it. The end is now **written once**:
  the lanes the tail silences go back to "not tailed" and the declaration is
  marked spent. A reopened task never revives a tail that has ended, and the
  same declaration replayed (its line is still in the plan file) does not
  revive it either — only a genuinely new declaration does.
- **F3 (P2, logged) — a date that does not exist is refused.** The day is
  checked against the length of its month, and the 29th of February needs a
  leap year: `2026-02-31` and `2026-02-29` are refused instead of counting
  into March.

Out of scope: the engine's side of a tail that ends by itself is the one the
plan already has: `lane_in_tail` is the single reader of the tail state (the
engine's feed, attention and all-tail watch call it), and it now reports a
tail that has ended — so the engine needs no change and no engine file was
touched. Two things the captain should know: the deadline is compared with
the wall clock when the caller has none (a deadline is a wall-clock stamp; the
plan apply and the tests pass their own clock), and a tail that waits for a
task ends when that task is *over* — done, failed or cancelled — not only when
it is done.
