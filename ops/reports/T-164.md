# T-164 — plan hygiene and tails that end (B5, B6)

Scope: T-164 — design §10.7 row B5 (a `# Staff` line the apply used is gone
from the plan file, an empty `# Staff` section goes with it, a failed merge's
`next:` names `- remerge T-<n>`, the apply says which lanes the captain's tail
silences) and row B6 (`- tail: <lanes> until=T-<n>` / `until=<RFC3339>` ends
the tail by itself).

Branch: mast/t164 (code @ the hand-in commit; origin/dev merged before final
verification)

Files:
- `crates/gear-app/src/draft.rs` — `rewrite_applied` takes the staff lines the
  apply used (by their line number) and drops them: a staff line is an
  instruction, and an instruction that was carried out must not be carried out
  again (a `- remerge T-<n>` line would be refused the second time). A
  `# Staff` section that keeps no line goes with them — no empty section and no
  second one (the parser refuses a repeated section).
- `crates/gear-app/src/plan.rs` — the tail (B6): the decision line takes an end
  (`- tail: heat until=T-12`, `- tail: heat until=2026-10-26T18:00:00Z`), the
  end is stored with the declaration, and `lane_in_tail` (the one every reader
  of the tail uses, in the engine too) reports the lane as tailed only while
  the tail lasts: a task tail ends when the task is over (done, failed or
  cancelled), a time tail ends at that moment. `tailed_lanes` names the lanes
  the tail silences (B5). `parse_rfc3339` reads an RFC3339 moment (no time
  library: the civil date is counted from the Unix epoch, as `utc_date`
  counts back).
- `crates/gear-app/src/tasks.rs` — the verdict hint of a failed merge carries
  the task to remerge (B5).
- `crates/gear-app/src/home.rs` — the captain's `next:` for a failed merge
  names the `- remerge T-<n>` line (B5) instead of a verdict line; the reply's
  refusal names the same line and still names the verdict line as the way to
  send the work back for a rework.
- `crates/gear-app/src/mail.rs` — the refusal of a reply that would close a
  failed merge names the plan line that settles it.
- `crates/gear-cli/src/main.rs` — the apply passes the used staff lines to the
  rewrite (the file is edited in place, so the lines are gone after the apply)
  and prints the lanes the tail silences ("tail: lane heat is silenced until
  T-12 (it may stand idle)").
- `crates/gear-app/tests/it/tail_contract.rs` — the tail's contract: a tail
  until a task ends when the task is done, a tail until a time ends at that
  time, a tail without an end lasts until it is cleared, the tailed lanes are
  named, and a broken tail (unknown lane, unknown task, a time that is not
  one, two ends, an end on a clear) is refused.
- `crates/gear-app/tests/it/verdict_item_contract.rs` — a failed merge's
  `next:` names the remerge line; the rework line is named too.
- `crates/gear-cli/src/main.rs` (tests) — an applied `- remerge T-1` line is
  gone from the plan file (and the empty `# Staff` section with it); the apply
  prints the tailed lanes.
- `skills/gear/references/captain.md` — the captain's guide: a tail can end by
  itself (`until=T-<n>`, `until=<RFC3339>`), and a staff line is gone after
  the apply.
- `ops/reports/T-164.md` — this hand-in.

Out of scope: the engine's side of a tail that ends by itself is the one the
plan already has: `lane_in_tail` is the single reader of the tail state (the
engine's feed, attention and all-tail watch call it), and it now reports a
tail that has ended — so the engine needs no change and no engine file was
touched. Two things the captain should know: the deadline is compared with
the wall clock when the caller has none (a deadline is a wall-clock stamp; the
plan apply and the tests pass their own clock), and a tail that waits for a
task ends when that task is *over* — done, failed or cancelled — not only when
it is done.
