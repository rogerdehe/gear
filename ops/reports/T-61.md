# T-61 — The engine merges the approved commit, wherever it is, and a failed merge can be retried

Attempt 2, contract v1 — the rework of the two blocking findings of attempt 1
(F1: a transient push error was terminal; F2: a candidate that is in the local
object store but not pushed yet was terminal). F3 (a pushed tag is not a
pushed ref) is logged, not reworked, as the captain decided.

The merge works from the approved candidate's **commit**, not from the branch
the lane named, and a merge that failed for a reason that can clear is retried
a bounded number of times before the captain is rung once.

## What changed

`crates/gear-engine/src/merge.rs`:

- **The fetch names every branch of origin** (`git fetch --prune origin
  '+refs/heads/*:refs/remotes/origin/*'`): the candidate may sit on any
  branch, and a clone that restricts its refspec would not bring it in.
- **The candidate is resolved to a commit** (`rev-parse --verify
  <candidate>^{commit}`). A commit that is not known here yet (the lane's push
  has not landed) is a reason that can clear: it is retried.
- **The commit must be reachable from a pushed ref** (`for-each-ref
  --contains=<sha> refs/remotes/origin/`). Work that was never pushed — or
  whose branch is gone — is not merged, and the reason says so.
- **The merge is by commit.** The branch the op names may hold the candidate,
  hold more than it, or be gone; "the branch moved after the review" is no
  longer a failure. The approved work lands, the unreviewed commits that
  followed it on that branch do not.
- **The review branch still merges with it and is still required** (F6 of the
  T-12 review). A candidate that is already on the integration branch needs no
  merge commit, but its review branch still merges with it.
- **The branches the merge consumed are closed**: the review branch, and every
  branch of this task whose tip is the candidate (the task's own branch, or
  the branch a rework round used, `engine/t53-v2`). A branch that holds more
  than the candidate keeps its commits and is left alone; the integration and
  release branches are never closed; a branch that is not this task's is left
  alone and named in the merge result.
- **Failures are classified.** A reason that can clear — a push race, **any
  other push failure** (the network, the remote, a hook that rejects the push
  once: F1), a gate that could not run (the gate's own 126/127, or a gate that
  cannot be started), a candidate that is not fetchable yet, **a candidate
  that is on no pushed ref** (the lane may not have pushed it yet: F2), a
  fetch that failed — is retried **three times with a growing wait** (2 s,
  4 s, 8 s, capped at 30 s) inside the merge worker, which restarts from the
  new tip of the integration branch each time. Only then does the bounded
  retry decide, and the op ends and rings the captain **once**. A reason that
  stands — a conflict, a gate that said no, a missing review branch — ends the
  op at once, as before. The push race keeps its `push race: ` prefix, and the
  worker retries it where the wait can grow.

## Acceptance evidence (tests with real git, in `crates/gear-engine/src/merge.rs`)

- `a_candidate_on_another_branch_merges` — the candidate sits on
  `heat/t5-v2` while the op names `heat/t5`: the candidate and the review
  land on `dev`, and the branch that held the candidate is closed.
- `the_engine_merges_a_candidate_on_another_branch_itself` — the whole path
  with no hand edit in the store: the review passes, the engine queues the
  merge op itself and runs it, the candidate lands.
- `a_candidate_on_no_pushed_ref_fails_with_a_clear_reason` — the lane
  committed but never pushed: the reason is "the approved candidate \<sha\> is
  on no pushed ref of origin" and it is a reason that can clear (F2), `dev` is
  untouched.
- `a_candidate_on_no_pushed_ref_fails_the_op_and_rings_the_captain_once` —
  the public path: the retries are used up, the op is `Failed` with that
  reason (naming the retries) and the captain's inbox holds exactly one item.
- `a_push_that_a_hook_rejects_once_is_retried_and_lands` (F1) — the repo's own
  pre-push hook says no once: the merge waits, tries again and lands.
- `a_candidate_pushed_late_merges_after_the_retry` (F2) — the first attempt
  finds the candidate on no pushed ref (a reason that can clear); the lane
  pushes it and the next attempt lands it.
- `a_push_race_is_retried_and_the_merge_lands` — the integration branch moves
  while the gate runs: the first push loses the race, the next attempt starts
  from the new tip and lands.
- `a_gate_that_could_not_run_is_retried_and_the_merge_lands` — the gate
  cannot find its toolchain (127): the merge retries and lands.
- `a_candidate_that_is_not_fetchable_yet_is_retried` — a candidate that is not
  in the repo yet is a reason that can clear, not a failure.
- `a_branch_that_moved_past_the_candidate_merges_the_candidate_only` — the old
  test ("is refused") now states the new rule: the approved candidate merges,
  the commit pushed after the verdict does not, and the branch that holds it
  is not closed.
- `a_retry_merges_once_and_pushes` — a restart after the push still merges
  once and loses nothing.

## Validation

- `cargo test --workspace` → **679 passed, 0 failed** (the merge module: 31).
- `cargo build --workspace --all-targets` → exit 0, no warnings.
- `git diff --check` → clean.
- The tests fail when the engine does the wrong thing (each mutation reverted
  afterwards):
  - the reachability check removed → `a_candidate_on_no_pushed_ref_*` fail
    (the unpushed work is merged instead of refused);
  - the task branch merged instead of the candidate's commit →
    `a_candidate_on_another_branch_merges`,
    `the_engine_merges_a_candidate_on_another_branch_itself` and
    `a_branch_that_moved_past_the_candidate_merges_the_candidate_only` fail;
  - a push that is not a race made terminal again (F1) →
    `a_push_that_a_hook_rejects_once_is_retried_and_lands` fails;
  - the candidate on no pushed ref made terminal again (F2) →
    `a_candidate_pushed_late_merges_after_the_retry` and
    `a_candidate_on_no_pushed_ref_*` fail.

## Out of scope

- The skill's conventions still say "the engine merges only what is on
  `origin/<lane>/t<n>`" (`skills/gear/references/conventions.md`): the engine
  now merges the approved candidate from any pushed ref. `base` owns
  `skills/`.
- The hand-in gate that refuses a candidate that is not on
  `origin/<lane>/t<n>` (T-60's lesson) is T-83's, in the `course` lane: this
  task changes what the engine does with the candidate, not what a hand-in
  accepts.
- A task whose candidate carries another task's unreviewed commits still
  merges: T-62 (in rework on this lane) owns that.
- A pushed tag is not counted as a pushed ref (F3 of the attempt-1 review):
  the reachability check reads `refs/remotes/origin/` only. Logged, not
  reworked.
- A branch that is not this task's (a human's branch) is never closed by the
  merge, even when its tip is the approved candidate; the merge result names
  it, and the captain decides.
