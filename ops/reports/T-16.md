Open questions:
- **Handed in** counts the attempts that reached `submitted`, `accepted` or `rejected`; **rejected** counts `rejected`. So `rework 1/2` reads "one of two hand-ins came back" — the field note's definition.
- **Per lane means the attempts of the lane's tasks**, the same grouping as the lane's task list. An attempt whose seat is a temp worker still counts for the task's lane; that coincides with the seat's own work everywhere but temp tasks.
- **`last task` is the lane seat's last Deliver op.** A lane that never received one reads `no task yet`, not `0s ago`.
- **The dependency view shows the totals line** (so the overall rate) but has no per-lane lines to hang the lane measures on; the measures stay in the lane view and in the JSON.
- **The reader is per task** (`attempts_of_task` per task of the lane): N small queries per frame. Fine at this size; a project-wide attempts query would be a `gear-store` change for later.
- `Totals: 2 tasks` still says "2 tasks" (the line is shared with the earlier contract); a one-task project reads `1 tasks`. Out of scope here.

Out of scope:
- The other field-note measure (idle time with no startable task): the packet defines the second measure as the time since the last delivery, which is what is implemented.
- Changing what the engine records; the board only reads.
