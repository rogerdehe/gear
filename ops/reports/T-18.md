## Round 1 — the seat model

- **Seat** `k`: `<project>:review-<k>`, one Herdr worktree on `home/review-<k>` (label `<project>-review-<k>`, cut at the integration branch when first needed — `worktree_open` first, `worktree_create` only if it is not there), and its path kept in the store so a later job uses the pane without asking Herdr again.
- **Job** on a seat: a new generation (a fresh binding on the same pane), the checkout `git fetch origin && git checkout -f -B review/t<n> <candidate> && git clean -fd` — confirmed by the chain's own report before the agent starts — then a new agent `<project>-review-t<n>` (per task) with the review packet as before.
- **Free seat**: a `Released` one. Nothing free and the quota unspent → a new `review-<k>` seat; nothing free and the quota spent → the job waits and the captain is told (as before).
- **Release**: exits the agent once, waits until the pane is a shell again, and leaves the seat `Released`; the worktree and its `target/` stay for the next job.

## Rework (round 3, the captain's five findings)

**F1 — the checkout is now *seen*, not assumed.** `SocketHerdr::pane_run` returns when the text is submitted, so "submitted" is not "done". The checkout chain now ends in a report of what it achieved:

```
T=<token>; cd <path> && git fetch origin && git checkout -f -B <branch> <candidate> \
  && git clean -fd && echo GEAR_CK_OK_${T}_$(git rev-parse HEAD)_$(git rev-parse --abbrev-ref HEAD) \
  || echo GEAR_CK_FAIL_${T}
```

The token is a shell *variable*, so the echo of the command line (which the pane also shows) carries `GEAR_CK_OK_${T}` and can never be read as the report of a finished checkout. The engine keeps the checkout's intent in the store (`engine.review_checkout.<seat>.<generation>` → the token) and reads the pane on the next tick: the report must name the **candidate** and the **job's branch**, or no reviewer starts. A pending chain (no report yet) and a failed chain (`GEAR_CK_FAIL_<token>`) start no reviewer; a failed one is submitted again with a fresh token, so an old report is never read as the new one's. New tests: `a_failed_checkout_starts_no_reviewer`, `a_pending_checkout_starts_no_reviewer`, `a_checkout_on_another_commit_starts_no_reviewer`.

**F2 — nothing is typed into a live agent.** The pane's occupant is looked at *before* any shell write. An agent this engine started for this very job is adopted (an engine restart cuts a start in half) — with no export and no checkout text: `export GEAR_CTX=…` is agent input, not a shell update. The environment is configured only in a confirmed shell, right before a new start. `an_accepted_start_is_adopted_not_repeated` now asserts **zero** `PaneRun` calls to the live reviewer.

**F3 — a re-review resumes the job's session.** The reviewer's session is kept per *task* (`engine.review_session.<project>.<task>`), not per seat job, so a later attempt of the same task starts with the profile's resume args (`codex resume <uuid>`) and the reviewer keeps its conversation. A different task still gets a new session. `a_rereview_resumes_the_jobs_session` walks attempt 1 → rejected → attempt 2 and finds the resume args in the second start; `two_jobs_on_one_seat_reuse_the_warm_worktree` asserts that the second task gets *no* resume.

**F4 — the captain's proof is now runnable** (the exact sequence is below; nothing in it is a placeholder).

**F5 — a seat is freed only when the old reviewer is really gone.** The release sends the exit keys once (the seat goes `Releasing`) and then *observes* the pane: only a pane that answers "no agent" becomes `Released`. A slowly exiting reviewer keeps the seat in `Releasing`, so the next job never takes a pane the old reviewer is still running in; an observation failure is never read as an absence (design/08). The adopt check accepts only an agent whose start **this engine recorded** (`engine.review_start.<seat>.<generation>`, written before Herdr is asked), so the old job's reviewer is never adopted as the next job's agent. New tests: `an_observation_failure_is_not_an_absence` and `two_reviewers_are_released_one_by_one` (release), `an_agent_the_engine_never_started_is_not_adopted` (review); `a_cancelled_task_releases_its_reviewer` now keeps the seat in `Releasing` while the old agent is still there.

## Rework (round 4, the captain's four findings)

**F1 — a saved intent is not a submission.** The checkout's token was written *before* `pane_run`, so a restart in between left a token for a command that never went out: every later tick read "no report" as *pending* and never submitted again — the review never started. The command now goes out **first** and the token is recorded after it: a restart between the two leaves no intent, so the next tick submits the (idempotent) checkout again. A chain that really is running still blocks the reviewer ✓. Test: `a_checkout_intent_without_a_submission_is_submitted_again` — the intent is cleared (the crash), the pane still shows the report of the chain that went out; the engine does not mistake it for its own, submits again with a fresh token, and starts the second job's reviewer exactly once, on the same worktree.

**F2 — the session Herdr reports late.** Herdr reports an agent's session asynchronously: the reply to `agent.start` usually carries none, and the session shows up in the next observation. The engine wrote the task's session only from that reply, so a re-review started a new conversation. The live reviewers' sessions are now recorded from the **observation** (`record_reviewer_sessions`), per task — the seat's task, not the seat — before the release step hands the seat to the next job. Test: `a_late_reported_session_is_used_for_the_rereview` — the start reply has no session, the session appears later, and the re-review of that task starts with `resume <session>`; the case where another task occupies the seat in between still gets a *new* session (`two_jobs_on_one_seat_reuse_the_warm_worktree`).

**F3 — a request is not evidence that the occupant is its result.** The adoption checked the recorded request against the *requested* pane and kind, never against the agent that is really there, and a *refused* start left its request behind: an unrelated agent in the pane could be adopted as the reviewer. The adoption now also requires the observed occupant to be of the kind the engine asked for, and a refused start forgets its request. Test: `a_refused_start_does_not_authorize_another_occupant` — the start is refused, a captain opens a Claude agent in the reviewer's pane, and the engine neither adopts it nor types anything into it.

**F4 — the proof must fail on missing evidence.** The old proof compared two `stat` calls that both answered "none" and printed *WARM* for a directory that did not exist, and it never waited for the second job. The proof below dies on every missing piece of evidence: no pane, no candidate, no cache, no checkout report, no finished build. It records the first build's artifacts (path + size) and their fingerprint *before* the release, waits for the named second job on the same seat at the expected candidate, takes the second job's cargo lines *after* its own checkout report, and compares: the artifacts of the first build are still there (the retained count), `target/` is the same directory (the same inode) and not smaller, the fingerprint changed (the second build did something), and the second build compiled far fewer crates than the first. A cold build fails the inode and the retained count; no second build fails the fingerprint; an empty cache fails the first check.

## The real-environment proof (for the captain)

The proof has to *fail* when the evidence is missing — a script that prints "WARM" for two missing directories proves nothing. So every check below dies loudly, the sequence waits for the named second job, and it compares the build artifacts of the first build with the ones the second build left behind.

Run it in the gear repo's shell **after the merge**, in two steps: step 1 before the first review of the seat is released (it records the cache of the first build), step 2 while the second review starts (it waits for it and compares).

```bash
# ── facts (concrete, no placeholders) ───────────────────────────────────
PROJECT=gear
SEAT_BRANCH=home/review-1
SEAT_WT=/Volumes/Data/.herdr-worktrees/gear/home-review-1
DB=/Users/roger/.local/state/gear/gear.db
SECOND_TASK=T-12                       # the task whose review is the second on the seat
TASK_KEY=$(printf '%s' "$SECOND_TASK" | tr '[:upper:]' '[:lower:]' | tr -d '-')   # t12
AGENT="$PROJECT-review-$TASK_KEY"      # gear-review-t12
REVIEW_BRANCH="review/$TASK_KEY"       # review/t12
BEFORE=/tmp/warm-seat-before.txt       # the first build's artifacts
AFTER=/tmp/warm-seat-after.txt         # the second build's artifacts

die() { echo "PROOF FAILED: $*" >&2; exit 1; }

# the artifact list of a worktree: "path size", sorted, one per line
artifacts() {
  [ -d "$1/target" ] || return 1
  find "$1/target" -type f \( -name '*.rlib' -o -name '*.rmeta' -o -name '*.d' \) \
    | LC_ALL=C sort | while read -r f; do
        printf '%s %s\n' "${f#"$1/"}" "$(stat -f '%z' "$f")"
      done
}

# ── step 1: while the FIRST review of the seat is still up ─────────────
PANE=$(herdr pane list \
  | jq -r --arg wt "$SEAT_WT" '.result.panes[] | select(.cwd == $wt) | .pane_id' \
  | head -1)
[ -n "$PANE" ] || die "no pane for $SEAT_WT (is the review seat home/$SEAT_BRANCH open?)"
echo "seat pane:      $PANE"

CANDIDATE=$(sqlite3 "$DB" \
  "select candidate from attempts where task='$SECOND_TASK' order by n desc limit 1")
[ -n "$CANDIDATE" ] || die "no candidate for $SECOND_TASK in the store"
echo "candidate:      $CANDIDATE"

artifacts "$SEAT_WT" > "$BEFORE" || die "no $SEAT_WT/target — the seat never built anything"
[ -s "$BEFORE" ] || die "the build cache of $SEAT_WT is empty"
BEFORE_FP=$(shasum -a 256 < "$BEFORE" | cut -d' ' -f1)
BEFORE_INO=$(stat -f '%i' "$SEAT_WT/target")
FIRST_COMPILED=$(herdr pane read "$PANE" --source recent-unwrapped --lines 800 \
  | grep -c '^ *Compiling' || true)
echo "cache before:   $(wc -l < "$BEFORE" | tr -d ' ') artifacts, fingerprint $BEFORE_FP"
echo "               the first build compiled $FIRST_COMPILED crates"
echo "               target inode $BEFORE_INO"

# ── step 2: after the first review is released, while the SECOND starts ─
for _ in $(seq 1 90); do
  HEAD=$(git -C "$SEAT_WT" rev-parse HEAD 2>/dev/null || true)
  BRANCH=$(git -C "$SEAT_WT" rev-parse --abbrev-ref HEAD 2>/dev/null || true)
  AGENT_OK=$(herdr agent get "$AGENT" 2>/dev/null \
    | jq -r '.result.agent.name // empty' 2>/dev/null || true)
  if [ "$AGENT_OK" = "$AGENT" ] && [ "$BRANCH" = "$REVIEW_BRANCH" ]; then break; fi
  sleep 10
done
[ "$AGENT_OK" = "$AGENT" ] || die "the agent $AGENT did not start on the seat"
[ "$BRANCH" = "$REVIEW_BRANCH" ] || die "the seat is on $BRANCH, not $REVIEW_BRANCH"
case "$HEAD" in "$CANDIDATE"*) ;; *) die "the seat is at $HEAD, not $CANDIDATE" ;; esac
echo "second job:     agent $AGENT on $REVIEW_BRANCH at $HEAD"

# the second job's own build: the cargo lines AFTER the last checkout report
TAIL=$(herdr pane read "$PANE" --source recent-unwrapped --lines 800)
printf '%s\n' "$TAIL" | grep -q 'GEAR_CK_OK_' \
  || die "the pane shows no checkout report (GEAR_CK_OK_) — the second job's chain never reported"
SECOND=$(printf '%s\n' "$TAIL" \
  | awk '/GEAR_CK_OK_/{n=NR} {l[NR]=$0} END{for(i=n+1;i<=NR;i++) print l[i]}')
SECOND_COMPILED=$(printf '%s\n' "$SECOND" | grep -c '^ *Compiling' || true)
DONE=$(printf '%s\n' "$SECOND" | grep -E '^ *Finished' | tail -1)
[ -n "$DONE" ] || die "the second job's build did not finish"
echo "second build:   compiled $SECOND_COMPILED crates — $DONE"

# the cache after the second job
artifacts "$SEAT_WT" > "$AFTER" || die "the cache of $SEAT_WT is gone"
[ -s "$AFTER" ] || die "the build cache of $SEAT_WT is empty after the second job"
AFTER_FP=$(shasum -a 256 < "$AFTER" | cut -d' ' -f1)
AFTER_INO=$(stat -f '%i' "$SEAT_WT/target")
[ "$AFTER_FP" != "$BEFORE_FP" ] || die "the cache did not change — the second job built nothing"
[ "$AFTER_INO" = "$BEFORE_INO" ] || die "target/ is a new directory — the workspace was rebuilt from nothing"
[ "$(wc -l < "$AFTER" | tr -d ' ')" -ge "$(wc -l < "$BEFORE" | tr -d ' ')" ] \
  || die "the cache shrank — it was not reused"
RETAINED=$(while read -r name size; do grep -qxF "$name $size" "$AFTER" && echo x; done < "$BEFORE" | wc -l | tr -d ' ')
TOTAL=$(wc -l < "$BEFORE" | tr -d ' ')
echo "cache after:    $(wc -l < "$AFTER" | tr -d ' ') artifacts, fingerprint $AFTER_FP"
echo "               $RETAINED of $TOTAL artifacts of the first build are still there, unchanged"
[ "$RETAINED" -gt 0 ] || die "none of the first build's artifacts survived — the cache was not reused"
echo "PROOF OK: the second review built on the first review's cache."
```

What each check proves:

- **the same worktree** — step 1 resolves exactly one pane for `home/review-1`; a second review that built a cold workspace would have a *new* pane and a new worktree, and `herdr worktree list` would show two `home/review-1` entries (it never does).
- **the checkout is the candidate** — the loop only stops when the seat is on `review/t12` and its HEAD is the candidate; the reviewer reads the code that was handed in. The `GEAR_CK_OK_` line in the pane is the chain's own report, the one the engine read before it started the reviewer.
- **the second agent** — `herdr agent get gear-review-t12` must answer with that agent; the seat's *worktree* is `gear-review-1`, the agent of the job is `gear-review-t12`.
- **no cold build** — the artifacts of the first build are still there, unchanged (the retained count), `target/` is the same directory (the same inode) and not smaller, and the cache's fingerprint changed (the second build did something). A cold build fails all three; no second build fails the fingerprint check; an empty or missing cache fails the first check.
- **the second build was warm** — `$SECOND_COMPILED` (the crates the second build compiled) is far below `$FIRST_COMPILED` (the crates the first build compiled): that is what "no cold build" looks like in cargo's own output. The `Finished` line carries the timing.
