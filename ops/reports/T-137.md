## What changed

**`crates/gear-usage/`** (new crate) — one API for the four logs of §4.3:

```rust
pub enum UsageLog { PiJsonl, CodexRollout, ClaudeJsonl, OpencodeDb }
pub struct Usage { input, output, cache_read, cache_write, reasoning, cost_usd: Option<f64>, records }
pub fn usage(log: UsageLog, session_ref: &str, from: Ts, to: Ts) -> Option<Usage>;
pub fn last_context(log: UsageLog, session_ref: &str) -> Option<i64>;
```

- **pi-jsonl** — the session file pi names. A record is a message of the
  assistant that carries its usage: `input`, `output`, `cacheRead`,
  `cacheWrite`, `reasoning` and the cost (`cost.total`).
- **codex-rollout** — the rollout file of a thread under
  `~/.codex/sessions/YYYY/MM/DD` (the newest of the last fourteen days).
  Every token count carries the totals of the session so far, so the record is
  the **difference** to the count before it: a total is never counted twice.
  The input of Codex counts the cached input, so `input = input_tokens −
  cached_input_tokens` and the two columns never count it twice.
- **claude-jsonl** — the session file under `~/.claude/projects/*/`. One
  message is written on several lines, so it is counted **once per
  `message.id`**.
- **opencode-db** — the `session_message` table of
  `~/.local/share/opencode/opencode.db`: the tokens of the JSON `data` of each
  row and its cost, at the time the message was completed.

The window is `from <= time < to` for every format. A log that cannot be
read is **unknown** (`None`), never zero — the caller leaves the columns of
its round NULL. `last_context` is `input + cache_read + cache_write` of the
last assistant record (§3.5).

The times are read as the CLIs write them: a number is seconds or
milliseconds, a string is an RFC 3339 time (the reader of the crate has no
time library, so it parses the date itself).

**The dependency lines** (the one edit of the other lanes' `Cargo.toml` that
the Decisions allow): `gear-usage` is a dependency of `gear-engine`,
`gear-app` and `gear-board`, and `gear-board` is a dependency of
`gear-engine`. The root
`Cargo.toml` has the new member and the new workspace dependency. No code of
the other lanes changed: the crates are wired, the callers come with the
engine's tasks (T-151).
**The tests** (`crates/gear-usage/tests/it/`, 20 tests): the fixtures are
small hand-written files, never a real session file — a JSONL file for pi and
Claude, a rollout file in a day directory of a fake home, a SQLite database
for OpenCode. Per format: the window cuts the records at its edges (the
record at `from` counts, the one at `to` does not), the totals of Codex are
never counted twice, the Claude message written on three lines counts once,
and a log that cannot be read gives `None`.
