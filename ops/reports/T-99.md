# T-99 — prepare v0.3.0 (M3's release)

Scope: T-99 — the version is 0.3.0 everywhere a user meets it, and a release
note says in plain words what M3 brings, grouped as fit in, push safety, runs
without hands, and known limits.

Branch: base/t99 (code @ the hand-in commit; origin/dev merged before
verification, gate green on the merged result)

Files:
- `Cargo.toml` — `[workspace.package] version = "0.3.0"`; `Cargo.lock`
  followed with `cargo build`, and `cargo build` now reports the crates at
  0.3.0.
- `herdr-plugin.toml` — the plugin manifest's `version = "0.3.0"`, the same
  release (the install helper reads it for the archive name).
- `README.md` — the status line (now with a link to the release note), the
  `herdr plugin install … --ref v0.3.0` line, and the check
  "`gear --version` prints `gear 0.3.0`".
- `docs/releases/v0.3.0.md` (new) — the release note for users, no internal
  task numbers, in the four groups the packet asked for:
  - **Fit in** — the adoption frame (`gear --skill adopt`) with its two
    templates; the project's `gear/standard.md` carried in every task packet;
    the `[github]` mode in push merge (issues into plan entries, a draft claim
    pull request, hand-in/verdict/landing as comments, the merge closing the
    issue); projects of several repositories, and the two fixture projects for
    trying a voyage end to end.
  - **Push safety** — the destination allow-list frozen at registration; the
    pre-push check in every GEAR worktree, chained to the repository's own
    hook; a refusal rings the captain once, with the repository, the
    destination and the command.
  - **Runs without hands** — a failed merge retried by itself and by
    `- remerge T-<n>`; a failed review settled in `# Verdicts`; a cancelled
    task freeing its lane; a slow shell waited for instead of parking the lane;
    a lane's model checked against OpenCode's own list; unconfirmed deliveries
    worked out rather than repeated or lost; Codex back-off and start-up
    dialogs answered by the profile.
  - **Known limits** — landing *through* a pull request is not in this release
    and `merge = "pr"` is refused until M4, with a pointer to
    `ops/plan/m4-backlog.md` for the rest.
- `ops/reports/T-99.md` — this brief.

Verification:
- `cargo build --workspace` — reports the crates at 0.3.0; `gear --version`
  prints `gear 0.3.0` (that is what the README's check says).
- `Cargo.lock` carries `version = "0.3.0"`.
- `env -u GEAR_DB -u GEAR_CTX cargo build --workspace --all-targets` — exit 0,
  zero warnings.
- `env -u GEAR_DB -u GEAR_CTX cargo test --workspace` — 832 passed (the version
  contract included), 0 failed, 0 ignored, zero warnings.
- The note was read against the code on dev: every claim in it names a
  behaviour that ships (the push check and its chaining, the remerge action, the
  `# Verdicts` settlement, the cancel and busy-start fixes, the model list, the
  unconfirmed delivery, the Codex back-off and trust), and the known limit
  matches the config's refusal of `merge = "pr"`.

Open questions: none.

Out of scope: tagging the release and releasing to `main` (the user's own
decision at the landing); the M4 items themselves.
