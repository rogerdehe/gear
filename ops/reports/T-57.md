# T-57 — no agent GEAR starts stops on a dialog unnoticed

Scope: T-57 — the built-in codex profile turns the start-up update check off, so Codex never shows its "Update available" dialog; and the engine rings the captain when a lane or reviewer seat stays Herdr `blocked` for more than two minutes, with the last screen lines in the item (lesson 7b).

Branch: docs/t57 (code @ c148020; origin/dev ed0285f merged before final verification)

Files:
- `crates/gear-herdr/src/profile.rs` — the built-in codex profile's `unattended_args` also pass `-c check_for_update_on_startup=false`. Without it Codex shows the "Update available" dialog at start and the agent sits blocked (2026-10-25, codex 0.163.0 → 0.164.0: the reviewer was blocked and nothing noticed).
- `crates/gear-engine/src/blocked.rs` (new) — the watch: a lane or reviewer seat that Herdr reports `blocked` for more than 120 seconds gets one urgent item in its captain's inbox, with the last screen lines and the seat's name; the timer and the alert live in the store's meta (so they survive a restart), the item is resolved when the seat works again, and a later blocked spell rings again.
- `crates/gear-engine/src/observe.rs` — `SeatObs` carries `screen`: the last screen lines of an agent Herdr reports `blocked` (the dialog it waits on). Read only for a blocked agent; a screen that cannot be read is None.
- `crates/gear-engine/src/lib.rs` — the new module, the watch in the tick (after the busy watch) and the new `TickReport.blocked` field.
- `crates/gear-engine/tests/it/blocked_contract.rs` (new), `crates/gear-engine/tests/it/main.rs` — six contract tests: a blocked lane rings once after more than two minutes and not again in the same spell, the tick rings the captain, a reviewer seat rings too, a seat that works again resolves the item and a later spell rings again, the timer and the alert survive reopening the store, a seat that is never blocked never rings.
- `crates/gear-herdr/tests/it/builtin_contract.rs` — the unit test for the codex args: the profile is built in, verified, and its unattended args are `--dangerously-bypass-approvals-and-sandbox -c check_for_update_on_startup=false`.
- `crates/gear-cli/src/main.rs`, `crates/gear-engine/src/review.rs`, `crates/gear-engine/src/quota.rs` — the assertions on the codex start args now carry the new flag (the reviewer's start and the cross-CLI quota fallback both build the args from the profile).
- `crates/gear-engine/src/dispatch.rs`, `crates/gear-engine/src/switch.rs`, `crates/gear-engine/src/quota.rs`, `crates/gear-engine/tests/it/dispatch_contract.rs`, `crates/gear-engine/tests/it/dispatch_tick_contract.rs`, `crates/gear-engine/tests/it/reviewer_nudge_contract.rs` — the `SeatObs` fixtures carry the new field.
- `skills/gear/references/agents/codex.md` — the SOP states the flag and the start and resume examples carry it, so a hand-started Codex does not show the dialog either.
