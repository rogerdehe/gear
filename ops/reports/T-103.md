# T-103 — A seat sees only what is addressed to it

Attempt 2, contract v1 — the rework of the review's F1: a **Retiring** lane
still finishes the attempt it holds, so an answer to its question must reach
it. F2 (a parked/held seat) is logged, not reworked, as the review decided.

Trial (2026-10-26): a lane read a captain status note about a
re-queued review seat. Two leaks fed it: the inbox batch showed *any* reply in a
thread as that thread's context, and `gear reply --note` wrote its text into
the sender's inbox as a Reply. A released (or reused) reviewer seat could read
a note meant for an earlier job.

Now a thread's context is the latest Reply **addressed to the reader**; a note
is the captain's record on the item and goes to nobody; and `--resolve` /
`--wait` answer only a seat that is still running **at the generation that
asked**.

## What changed

- **`crates/gear-app/src/mail.rs`, `select_batch`** — `last_reply` keeps only
  `MsgKind::Reply` messages whose `recipient` is the seat reading the batch
  (`m.recipient == recipient`). A reply the captain wrote to the engine, to
  himself or to another seat is no longer shown to a lane as its context.
- **`crates/gear-app/src/mail.rs`, `reply`** — the text of every handled item
  is now written to the item itself (`result`): a note keeps the item's state
  and its wait fields, and **no message is created** for it. `--resolve` and
  `--wait` still change the state and then answer the original sender, but only
  when the sender is a **live seat of the current generation**: the seat exists,
  `seat.generation == message.sender_gen`, and it is `Starting`, `Active` or
  `Standby`. The engine has no seat (`sender = "engine"`), a released/reused
  reviewer has another state or another generation, so neither gets the text.
- **`crates/gear-cli/src/main.rs`** — the help of `--resolve`, `--wait` and
  `--note` says what each does now: answer a live sender, or keep the text as
  the captain's record and send it to nobody.
- **`skills/gear/references/captain.md` (§3, step 2)** — the line the task
  asks for: **"Text sent to an agent is an instruction for that agent; your own
  bookkeeping goes in `gear reply M-<n> --note -m "<text>"` (kept on the item,
  sent to nobody) or in the plan."**

## Acceptance evidence

- `a_reply_to_another_seat_is_not_this_seats_context` (in
  `crates/gear-app/tests/it/app_select_batch.rs`) — the lane's open item in a
  thread plus a captain reply addressed to `engine` and one to `p:pricing`: the
  lane's batch shows **no** `last_reply`; a reply addressed to `p:heat` is shown.
- `note_keeps_state` (updated) and `a_note_reaches_no_seat` (in
  `crates/gear-app/tests/it/app_reply.rs`) — a note leaves the item open, keeps
  its text as the item's record, writes **no message** anywhere, and adds no
  reply to the lane's batch.
- `a_retiring_lane_still_gets_its_answer` (F1 of the review) — a lane's
  question resolved while the lane is `Retiring` is answered to that lane.
  Without `Retiring` in the live check the test fails.
- `a_resolve_to_a_released_reviewer_sends_nothing` — the reviewer's item is
  resolved; no reply is written.
- `a_reused_reviewer_gets_no_answer_to_an_earlier_jobs_item` — the same seat
  reused through `begin_onboard` (generation 2) resolves a generation-1 item
  and gets nothing.
- `a_resolve_of_the_engines_item_sends_nothing` — the trial's case: the engine's
  item about the re-queued review seat is resolved, nothing is sent.
- `resolve_closes_and_replies` (existing) — a lane's question is resolved and
  the answer reaches `p:heat`.
- Mutation checks: dropping the recipient filter, letting a note create its
  reply, and dropping the live-seat check each make the matching tests fail.

## Out of scope

- **A reply addressed to a seat that is `Standby`** is delivered (the seat is
  running but idle); a `Parked`, `Held` or `NeedsCheck` seat is not, because a
  human must look at it first. Logged, not reworked.
- **The item's `result` is where a note lives** (the same column a resolve
  writes its text to). A note is therefore visible to whoever reads the item,
  which is the point: it is the captain's record, not a message.
