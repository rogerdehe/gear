# T-112 — A done task whose merge was given up can be cancelled, and its items close with it

Attempt 1, contract v1.

Branch: `course/t112`; the candidate named in the hand-in includes this report.
Base: `origin/dev` merged into the branch before the hand-in.

## The case

T-102 passed review and became Done; its merge was then refused, and the change
was dropped with the push allow-list. The plan refused `state: cancelled` for a
Done task; its merge item could not be resolved without a verdict, and a fail
verdict would have reopened it as rework. The captain had no way to drop it.

## The change

`gear plan apply` now accepts `state: cancelled` for a **Done** task whose
accepted candidate is **not** on its integration branch:

- before the write transaction (the store is never held while git runs) and
  only for the done tasks the draft cancels, `cancellable_done_tasks` reads the
  task's lane and its accepted attempt's candidate, then asks git: `git fetch
  origin <integration>:refs/remotes/origin/<integration>` first (the local
  tracking ref may be stale), then `git merge-base --is-ancestor <candidate>
  refs/remotes/origin/<integration>`. `not an ancestor` = not merged = may be
  cancelled; **any doubt** (a fetch that fails, a candidate git cannot place) is
  a `BadFormat` error — a cancellation is never accepted unchecked;
- a Done task with no accepted candidate is **not** opened by this (the plan
  refuses it as before), and a Done task whose candidate *is* merged stays
  uncancellable;
- applying it: `cancel_task` runs as for any cancel (a done task has no open
  attempt, so the lane gets no line), the task becomes `Cancelled`, and its open
  items in `merge-failed:<task>` and `push:<task>` are **resolved "cancelled by
  the captain"** (state `Resolved`, the text in the item's result);
- the failed merge op is left exactly as it is — history — and **no op is
  created**;
- `ApplyResult` gains `cancelled` (task ids) and `resolved` (message ids), and
  `gear plan apply` prints `cancelled T-n` and `resolved M-n` lines.

## Acceptance (tests)

`crates/gear-app/tests/it/cancel_contract.rs`, with a real git repo (bare
origin + clone; the lane branch carries one commit, on `dev` or not):

- `a_done_task_whose_merge_was_given_up_is_cancelled_with_its_items`: a Done
  task with an accepted attempt whose commit is not on `origin/dev`, a failed
  merge op and open `merge-failed`/`push` items → the apply succeeds, the result
  lists `T-1` cancelled and the two resolved ids, the task is `Cancelled`, both
  items are `Resolved` with `cancelled by the captain`, the failed merge op is
  still there with its reason and no other op was created;
- `a_done_task_whose_work_is_merged_cannot_be_cancelled`: the same world with
  the candidate merged into `dev` → `BadFormat` naming T-1 ("cannot be
  cancelled"), the task stays Done and its items stay open;
- the existing cancel tests (T-93) still pass, including a Done task with no
  accepted attempt, which stays uncancellable.

## Notes / out of scope

- The check is about the **origin** integration branch (fetched first): that is
  where a merge lands. A project without an `origin` remote cannot answer, so
  the cancellation is refused with the git error rather than guessed.
- "Merged" means the candidate is an ancestor of the integration branch; a
  candidate merged and later reverted stays "merged" (the plan still refuses).
- Cancelling a done task resolves only the merge/push items; a verdict item is
  not touched (a pass verdict belongs to the done task that stays done).
