# T-21 — a review's findings live in the store

Scope: T-21 — `gear send --kind review ... "<findings>"` stores the **text** of the findings: an argument that names a file in the reviewer's working directory is read (bounded at 64 KiB, with a note when cut), anything else is the text itself, and a path that does not exist is `BAD_FORMAT` before anything is written. `settle_review` puts that text into the rework note (no more `git show origin/review/t<n>:<path>` pointer) and `gear --show T-n` shows the latest review's findings, so rework never depends on a reviewer's worktree or branch.

Files:
- `crates/gear-app/src/review.rs` — `findings_text` (a path is read, text is kept, a missing file is `BAD_FORMAT`), the 64 KiB bound with its cut note, and three unit tests.
- `crates/gear-app/src/mail.rs` — a review's findings go through `findings_text` inside the write transaction, so a missing file rolls back and stores nothing.
- `crates/gear-app/src/tasks.rs` — `settle_review` uses the findings text directly (the `findings_pointer` git-show helper is gone).
- `crates/gear-app/tests/review_contract.rs` — a path is stored as its text, the rework note and the packet carry it (and no review-branch pointer), and a missing path stores nothing (`BAD_FORMAT`).
- `crates/gear-app/tests/settle_review_contract.rs`, `crates/gear-cli/src/main.rs` — the findings fixtures are text now (a path would be a file read).
- `ops/reports/T-21.md` — this brief.

Real proof on a scratch store (`/tmp/gear-t21/gear.db`, the built binary, a temp reviewer bound to this pane):

```
$ GEAR_DB=/tmp/gear-t21/gear.db GEAR_CTX=demo:r-1:1 gear send --kind review --task T-1 --attempt 1 --verdict fail /tmp/gear-t21/findings.md
Delivered to demo:captain inbox M-1 (thread T-1:1)

$ sqlite3 /tmp/gear-t21/gear.db "select findings from review_verdicts"
# Findings
P1: the header count is stale after a reload.
...
```

and the packet the lane reads:

```
## Review
attempt 1 · fail · demo:r-1
# Findings
P1: the header count is stale after a reload.
P2: the empty state has no text.
```

Verification:
- `cargo build --workspace --all-targets` → clean, no warnings; `cargo test --workspace` → 26 test targets, no failures (the three unit tests, the review contract's 10 tests including the path/text and missing-file regressions, and the settle test asserting the note and packet carry the text).
- The proof above: the verdict row holds the file's text (not its path) and the packet carries it.

Open questions:
- **Path vs text** is decided by shape: one line, no spaces, and a slash or a `.md`/`.txt` ending is a path. A findings *sentence* that ends in `.md` would be read as a path and fail loudly (never silently stored as a path), which is the safe direction.
- The bound is 64 KiB with a note naming the file and its size, so the store never carries a whole book.

Out of scope:
- The reviewer's own packet rendering (unchanged); the engine's settle cadence (unchanged).
