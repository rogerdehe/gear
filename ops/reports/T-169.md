# T-169 — the friction ring (design §6.4, engine side)

Scope: T-169 — when the captain has no actionable item and open friction
reports exist, the engine opens one item on the thread `friction` naming them,
at most once per 30 minutes; a new report updates the item's list; the item
closes itself when every report it lists is closed.

Branch: keel/t169

## What was built

- `crates/gear-engine/src/friction.rs` — the ring itself:
  - the captain is idle when it has no actionable item (`actionable_for` is
    empty, design §6.4); only then may the ring open;
  - one item per project, on the thread `friction`, kind `system`, for the
    captain, not urgent: "3 friction reports: F-1 F-2 F-3. Run gear friction.";
  - at most once per 30 minutes: the ring's clock (`at`) and the item it
    opened (`item`) live in the project's meta (`friction-ring:<project>`), so
    a restart neither rings twice nor loses the open item;
  - a report that arrives while the item is open updates the list (the body);
  - the item closes itself (`resolved`, "every friction report is closed") as
    soon as no report is open any more.
- `crates/gear-engine/src/lib.rs` — the tick calls the ring (step 6d, after
  the lane warnings and before the doorbells, so a captain that is rung in the
  same tick sees the item) and reports what it did in `TickReport::friction`
  (`friction:opened|updated|closed`).
- `crates/gear-engine/tests/it/friction_ring_contract.rs` — the contract: no
  ring while the captain has an open item, one ring when it is idle, a new
  report updates the item, closing every report closes it, and the 30-minute
  window between two rings.

## The choices (and why)

- **The item is a message to the captain** (kind `system`, thread `friction`),
  like the lane warnings and the all-tail item: it shows up in the captain's
  inbox and in `gear` without a new command. It is not urgent: it waits in
  the inbox until its reports are closed.
- **The list is the open reports**; a closed report leaves the list (the body
  changes, the item stays while another report is open). The item closes
  itself when the last report it listed is closed — the same condition,
  whichever way it is read.
- **The ring's state is in the meta**, not only in the message: a captain who
  resolves the item by hand must not make the engine open a second one in the
  same minute, and a restart must not ring twice.

# T-169, attempt 2 (the rework: F1 and F2 of ops/reviews/T-169.md)

Branch: keel/t169 (two commits, one per fix; origin/dev merged before the
final verification)

## F1 — the friction item is not an ordinary stale item

`crates/gear-engine/src/attention.rs`: `stale()` now excludes the `friction`
thread from the generic stale reminders, as it already excluded the parallel
warning. The friction item waits in the captain's inbox until its reports are
closed; the ordinary reminder turned it urgent 15 minutes after it was opened
and rang the captain a second time for the same reports — which broke §6.4's
"once, and only for a new report" and interrupted a working captain.

Regression: `the_friction_item_is_not_promoted_and_does_not_ring_the_captain_again`
— the first tick opens the item and rings the captain once, the captain reads
it, the captain works, and a tick 15 minutes later (and another 30 minutes
later) finds the item still an information item and no second prompt.

## F2 — a ring needs a report the captain has not been told about

`crates/gear-engine/src/friction.rs`: the persisted `State` keeps the ids of
the reports an item has named (`listed`). A new item is created only when at
least one open report is still unseen, beside the idle captain and the
30-minute cooldown. The list grows when the item's own list changes, so a
report that arrived while the item was open is not unseen either. The state
lives in the store, so a restart keeps the gate.

Regression: `a_resolved_item_rings_again_only_for_a_new_report` — the first
ring names F-1; the captain resolves the item by hand; the cooldown is over
and nothing new arrived, so there is no second item; the store is reopened
and the gate still holds; a new report F-2 rings exactly once, and the item
names F-1 and F-2.

Both regressions fail on attempt 1's code (checked: the old sources make
exactly these two tests fail) and pass with the fixes.
