# T-7 — the engine keeps the lanes fed

Scope: T-7 — each engine tick, every lane that may take work is counted: fewer than two ready tasks and the captain gets **one item in the inbox** — `lane <x> has <n> ready tasks left`, or `lane <x> is IDLE` when it has nothing left and nothing running — so the doorbell rings before the lane stops. One item per lane, updated while the condition lasts, closed when the queue is refilled.

Branch: board/t7. The hand-in commit carries the code and this brief; the candidate sha in the result names it (a brief inside a commit cannot name its own sha).

Files:
- `crates/gear-engine/src/feed.rs` — the watch: per lane, the ready count (the dispatch's own readiness rule, shared), the in-progress attempt, the item text, the open-or-create-or-close step, and the thread key `lane:<lane>` that makes a second tick or a restarted engine find the same item.
- `crates/gear-engine/src/lib.rs` — step 6 of the tick (`feed::keep_lanes_fed`), and `report.feed` (`lane:action`) so the engine log shows what happened.
- `crates/gear-engine/src/dispatch.rs` — `ready_tasks_of` is `pub(crate)`: one readiness definition for the dispatcher and the watch.
- `crates/gear-store/src/lib.rs` — `update_message_body`: the item is updated in place, never duplicated.
- `crates/gear-engine/tests/feed_contract.rs` — the acceptance tests.

Decisions:
- **The message mechanism, not the `reviews` table.** Messages already ring the doorbell (`actionable_for`), show on the captain's page in the INBOX batch and can be settled with `gear reply`; the `reviews` table exists in the schema but has no store API and no reader. This is the smallest change that rings the doorbell.
- **One item per lane, found by its thread** (`lane:<lane>`, sender `engine`, kind `system`, recipient the captain): the second tick finds the open item and updates it; a fresh engine run finds it too, so a restart duplicates nothing.
- **`IDLE` means nothing left and nothing running** (no in-progress attempt). A lane working its last task reads `has 0 ready tasks left` — that is the moment to add work, and `IDLE` is the moment after.
- **Only Active and Standby lanes are watched.** Parked, held, retiring, missing, needs-check lanes are not supposed to take work and are not warned about.
- **No nagging:** once the captain settles an item, the same condition is not reported again for ten minutes (design/11's reminder interval).
- **Plural:** `1 ready task left`, `0 ready tasks left` (the T-16 P3 was exactly this).

Verification:
- `cargo test --workspace` → 326 tests, all ok; `cargo build --workspace --all-targets` → no warnings.
- `crates/gear-engine/tests/feed_contract.rs` → 4 tests:
  - a lane with one ready task and a busy agent → exactly one item (`lane heat has 1 ready task left`), a second tick adds none, a second ready task closes it (`resolved`, `the queue is refilled (2 ready)`);
  - a lane with no tasks at all, idle agent → `lane heat is IDLE`;
  - a parked lane and a held lane → no item at all (the watch over the store, the observation out of the way);
  - an item left open by a previous engine run → the next tick does not duplicate it.

Open questions:
- **The live engine is not restarted by this branch**: the running engine is the merged binary, so the watch appears on the gear project after the merge (or after the user's next `gear admin stop` + `gear` call). The tests drive `tick` directly with a `FakeHerdr`, which is the same path.
- **A captain who settles the item while the lane is still dry** gets the item back after ten minutes, not on the next tick: the condition is real, but repeating it every four seconds would be noise.
- **Nothing is sent to the lanes themselves**: the item is for the captain (the packet's ask); a lane that is idle stays idle until work exists.

Out of scope:
- The full design/11 review scheduling (`timer`, `milestone`, `staff_change`, checkpoints, reminders, the `reviews` table) — this is the `low_ready`/`idle_lanes` warning, delivered through the inbox.
- Changing the dispatch (the ready counts are read, not changed).

## Round 2 — the rework (the review of round 1)

Two fixes, exactly the ones the review asked for; R1 and R2 are left for the follow-up it mentions.

- **R4 — a task taken by a delivery is not ready work** (`crates/gear-engine/src/feed.rs`): a task whose attempt is Delivered/started (it occupies the seat) is still `ready` in the table until the delivery is confirmed, and the watch counted it. The count now skips those, so the lane reads `has 1 ready task left` when one of two queue entries is already on its way to an agent. A test pins it (a Delivered attempt on one of two ready tasks).
- **R3 — a parked or held lane closes its warning** (same file): the watch skipped a lane that is not Active/Standby but left its open item behind. It now closes it (`the lane is parked or held`), so a warning never outlives the condition on a lane that is not supposed to work. A test parks a lane whose warning is open.

Verification of round 2: `cargo test --workspace` → 332 tests, all ok; no warnings; `crates/gear-engine/tests/feed_contract.rs` → 6 tests (the four of round 1 plus the two above).
