## Tests without `git push`

`crates/gear-app/tests/it/base_gate.rs` seeded and moved remote branches with
`git push` in its fixtures. The bare origin now learns a branch the way a remote
does — it **fetches** it and the ref is set:

- `publish(origin, source, from, branch)`: `git -C <origin> fetch <source>
  <from>` for the objects, then `git -C <origin> update-ref
  refs/heads/<branch> <sha>`;
- `unpublish(origin, branch)`: `git -C <origin> update-ref -d
  refs/heads/<branch>`.

Every former push (the seed's `dev`, a candidate branch, `advance_dev`, the
`origin/dev` → `heat/t1` case, `dev` → `other`, and the two remote deletions) uses
one of them. The gate's own assertions now name `push the task branch first` and
the branch, not the command text.

Merging the current dev brought T-112's `cancel_contract.rs`, whose fixture also
pushed its branches into the bare origin; it now publishes them the same way
(`publish`: fetch the ref, set it with `update-ref`). No test in the two crates
pushes with git.
