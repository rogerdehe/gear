# T-38 — every step of an attempt has its own timestamp, and time is accounted

Scope: T-38 — the store keeps the time of every step of an attempt (delivered, started, handed in, verdict, settled, merged; `updated` is overwritten at every step and could not say when a step happened), the plan carries the estimate of a task in minutes, and `gear report time` (captain) prints where the time went: per task and per voyage — estimate, dev time, review time, the wait for the captain, merge time, rework rounds and their time, actual over estimate.

Branch: course/t38 @ candidate identified by the hand-in command

Files:
- `crates/gear-store/src/schema.sql` — six nullable columns on `attempts` (`delivered_at`, `started_at`, `handed_in_at`, `verdict_at`, `settled_at`, `merged_at`) and one on `tasks` (`estimate_min`); the old `attempts.started` stays what it was (the row's creation time).
- `crates/gear-store/src/lib.rs` — `AttemptStep` (the six steps, each with its own column) and `AttemptTimes` (what is known of an attempt); `Tx::set_attempt_time` writes **one** column and never another's (the first time wins, so a replayed step does not move a fact); `Tx::attempt_times` / `attempt_times_of_task` read them; `update_attempt` does not touch them, so a row replacement can never clear a time; `TaskRow.estimate_min`; the additive migration (`MIGRATIONS`) gives an older database the columns when it is opened — they are nullable, so an older binary keeps working on the migrated database.
- `crates/gear-app/src/tasks.rs` — the delivery (`start_attempt`), the start (`on_delivery_confirmed`), the hand-in (`submit_result`) and both settlements (`settle`, `settle_review`) write their own time.
- `crates/gear-app/src/review.rs` — the reviewer's verdict writes its own time (the review time ends, the wait for the captain begins).
- `crates/gear-engine/src/merge.rs` — the merge writes its own column when its op is confirmed; the stale tick timestamp defect (F2) is assigned to T-36.
- `crates/gear-app/src/draft.rs` — the plan's `estimate:` field (minutes); an unknown value is `BAD_FORMAT`.
- `crates/gear-app/src/plan.rs` — a `NEW` block without `estimate:` is refused (`BAD_FORMAT`, nothing written); the estimate is stored on the task; an existing task keeps the estimate it has when the draft says nothing; the task packet shows `Estimate: N minutes` to the lane.
- `crates/gear-app/src/time.rs` (new) — the report: the durations between the steps (dev, review, wait, merge), the rework rounds and their time, the actual time (first start → last step) and the ratio actual/estimate, per task and per voyage; the render (`gear report time`).
- `crates/gear-cli/src/main.rs` — `gear report time [--task T-n] [--voyage M2] [--json]`: the captain's view; a lane is refused (`FORBIDDEN`); it only observes, so it starts no engine.
- `crates/gear-store/tests/it/time_contract.rs` (new) — the store contract: every step writes its own time, no step overwrites another, the first time of a step stands, a row replacement keeps the times, a time of an unknown attempt is `NO_TARGET`, an older database gains the columns.
- `crates/gear-app/tests/it/time_contract.rs` (new) — the plan contract (a plan with `estimate:` parses; a `NEW` task without one is refused) and the loop (every step of the loop writes its own time; a later step does not move an earlier one).
- `crates/gear-app/tests/it/time_report_contract.rs` (new) — the report on a seeded store: the durations, the ratio and the voyage line; only the captain may read it.

Open questions: none. The captain confirmed the following choices in the M2 plan (ba23240).
- Every `NEW` block needs `estimate:`; an existing task may keep the estimate it has (a draft without one does not clear it).
- **The estimate of a task without the field.** The report falls back to the `Estimate: 2.5h` sentence in the task's goal — the rule the M2 plan itself uses until the field exists ("Until a task-estimate field exists (course, first task), each task's estimate is the 'Estimate:' sentence in its goal"). Without the fallback the report of the current voyage shows no estimate at all; with it, the tasks that exist today are already counted.
- **The schema version is not stamped.** That is T-41's task (`meta.schema_version`, migrate up, refuse a newer store). This task only adds the columns, additively and idempotently, so the version stays where it is.
