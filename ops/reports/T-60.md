# T-60 — Failed model switches ring the captain

Attempt 1, contract v2.

Failed quota switches now create an urgent open system item for the captain,
with the seat ID and failure reason. The existing doorbell consumes these
items. Successful switches retain their single non-urgent info item.

Changes:
- `quota.rs`: missing labels, labels removed during a pending switch, an empty
  chain at reset, and failed/timed-out switches use `flag_and_alert`. The
  NeedsCheck transition and message insertion share a transaction. Reading the
  current state suppresses duplicate items even with a stale seat observation;
  a later failure after recovery gets a new item.
- `restart.rs`: ModelGate::Failed and the other cross-CLI restart failure flags
  use the same helper, including restart timeouts. Failure items use the seat's
  current generation after a restart reserves a new binding.
- `onboard.rs`: startup model-gate failures, removed labels while resuming, and
  switch timeouts alert the captain before the seat is parked in NeedsCheck.
  Later onboarding ticks skip the parked seat.

Acceptance evidence:
- Missing quota-switch labels: one urgent item naming the seat and labels;
  later ticks produce no duplicate.
- Labels removed mid-switch: one urgent item, pending switch cleared.
- In-place timeout: one urgent item after the bounded switch attempts;
  additional ticks produce no duplicate.
- Cross-CLI restart model gate: missing labels produce exactly one failure
  item, with the new generation; later ticks produce no duplicate.
- Cross-CLI restart timeout: one urgent item, restart plan cleared.
- Startup model gate: missing labels, removed labels, and timeout each produce
  one urgent item; repeated onboarding ticks leave the count at one.
- Repeated helper calls with a stale row produce one item; recovery followed
  by another failure produces a second item.
- Successful in-place and cross-CLI switches each produce exactly one info
  item and no urgent action item.
