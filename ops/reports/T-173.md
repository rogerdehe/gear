# T-173: in-place lane kind and model changes

The engine tracks each lane's desired kind and model configuration and applies a reconfigured target through the existing durable restart state machine. It waits without timing out while the old agent is still working, then exits and starts the replacement in the same pane and worktree. Dispatch waits while the restart owns the lane. The configured target profile is retained, and existing quota fallbacks do not repeatedly trigger a configuration restart.

A cross-CLI replacement records a fresh session for the open round and does not resume the old CLI's session. A same-CLI model change supplies the open session's resume arguments and keeps its round. Fake-Herdr tests cover both paths, a working agent beyond the old timeout, a custom target profile, the unchanged worktree and `target/`, and no worktree or pane teardown.

For an open same-CLI round, the restart waits if the session ID is not yet known instead of silently starting a fresh session. The completed session action is stored against the new generation so later ticks do not repeat the resume.

All four focused restart regressions passed. `scripts/test.sh` passed all 1,188 tests (48 s build, 114 s suite); concurrent load produced slow-test warnings in existing fixtures.

An existing in-place model switch now finishes before a configuration restart starts. After merging T-152 and T-167, the affected 21 engine tests passed; the subsequent full suite, including the switch-guard regression, passed all 1,200 tests (30 s build, 75 s suite).
