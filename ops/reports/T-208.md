# T-208 — the overlap with the integration branch is an information line

Scope: the F1 finding of the review of T-188 — the scan writes the overlap
metadata, but nothing showed it. The captain could not see that a task
shares files with the integration branch it will be merged into.

## What changed

**`crates/gear-board/src/lib.rs`**

- `pub struct Overlap { task, repo, integration, files }` — one task that
  overlaps the integration branch of its repo.
- `pub fn integration_overlaps(store, project)` and
  `pub fn integration_overlaps_of(tx, project)` — the overlaps of the
  project, read from the meta keys `parallel:<project>[:<repo>]:integration:<task>`
  that the scan of T-188 writes. A key with an empty value (the scan clears it
  when the overlap is gone) shows nothing; a key whose value holds no file
  shows nothing either.
- `pub fn overlap_line(overlap)` — the line the board, the frame and the
  queue all print: `overlap: T-2 shares crates/gear-board/src/lib.rs with dev`.
- `ProjectBoard.overlaps` carries the list; `project_with_agents` fills it in
  the same read transaction as the rest of the plan.
- The board text view prints one line per overlap, above the captain's inbox
  line. The board JSON carries the same list as `overlaps`.

**`crates/gear-board/src/frame.rs`** — the first view (Now) prints the same
lines under the lanes.

**`crates/gear-app/src/queue.rs`** — `gear queue` prints the same lines after
its lane lines, and its JSON carries them as `overlaps`.

**`crates/gear-board/Cargo.toml`** — `serde` (the overlap is serialized in
the queue's JSON).

## The reading of the metadata

The contract says the value of the key holds the shared files; the scan of
T-188 writes a JSON object with the task, the integration branch and the
files. The reader takes the files and the branch from that object, and it
also reads a value that is only a list of files (or a plain comma-separated
list), so the line never depends on the writer's exact shape. The branch
name falls back to the repo of the key, and then to `integration`.

## Never a waiting item

An overlap is information: the lane merges the integration branch in and the
merge gate catches a conflict. Nothing is written, no captain item is opened,
and the captain's inbox count does not move — a test asserts it.

## Tests

- `crates/gear-board/tests/it/overlaps_contract.rs` — one key shows one line

- `crates/gear-app/tests/it/queue_contract.rs` — the queue text shows the line
