# T-111 — the suite is offline by construction

Scope: T-111 — `cargo test --workspace` never reaches the network or a real
forge (user, 2026-10-26: a trial team in a restricted company network ran the
tests; GitHub mode must not drag them onto the network).

Branch: base/t111 (code @ the hand-in commit; origin/dev merged before
verification, gate green on the merged result)

What changed:
- `crates/gear-forge/src/github.rs` — `GitHub` runs the executable named by
  `GEAR_GH` when it is set and else `gh` (new `GH_ENV` constant). A test can
  still name its fake directly (`with_path(dir)` now runs `dir/gh`, not a
  `PATH` search). A call that cannot start while `GEAR_GH` named it returns
  `Error::Tool("no gh in tests: GEAR_GH=<path> could not be run …")`, so the
  failure names the test harness instead of looking like a missing `gh`.
- `.cargo/config.toml` — `GEAR_GH` is forced to `/nonexistent/gear-test/gh`
  for every process cargo runs, so a test that forgets its fake fails at once
  and no test can ever call the real `gh`; `GIT_ALLOW_PROTOCOL = "file"`, so
  any git transport other than a local path is refused inside a test. The file
  is read by cargo, never by the installed binary: production is unchanged.
- `crates/gear-cli/tests/it/import_issues_contract.rs` — the tests that spawn
  the `gear` binary name their fake with `GEAR_GH` (per child, so parallel
  tests cannot race).
- `crates/gear-forge/tests/it/github_contract.rs` — a new probe,
  `without_a_fake_no_test_reaches_a_real_gh`: it asserts `GEAR_GH` names a
  path that does not exist and that `GitHub::new()` fails with `no gh in
  tests`. It panics *before* any spawn if the variable is wrong, so it can
  never call a real `gh`.
- `crates/gear-cli/tests/it/offline_contract.rs` (new) — a probe that runs
  `git clone https://example.com/owner/repo.git` and asserts git refused the
  transport (`not allowed`) and wrote nothing.
- `scripts/test-offline.sh` (new) — the proof: builds first (that step may
  fetch crates), then runs `cargo test --workspace --offline` with outbound
  network denied — `sandbox-exec` on macOS (unix sockets and `localhost` stay
  open, everything else is denied), `unshare -rn` on Linux when user
  namespaces are available (otherwise it says so and exits non-zero). The
  exit status is the suite's.
- `README.md` — "Developing GEAR" gains a "Tests" part: how to run the suite,
  that it is offline and pushes nothing, the four reasons it cannot reach out
  (local bares, `GEAR_GH` naming nothing, the file transport only, no user git
  config and no seat identity), how to run the offline proof, and the opt-in
  live convention: a network test is `#[ignore]`d and run only with
  `GEAR_LIVE=1 cargo test -- --ignored` (none today).
- `ops/reports/T-111.md` — this brief.

includes T-107's removal of the engine's pre-push hook):
