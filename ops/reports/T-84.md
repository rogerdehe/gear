# T-84 — The project standard travels in every packet

Attempt 1, contract v1.

Branch: `course/t84`; the candidate named in the hand-in includes this
report. Base: `origin/dev` merged into the branch before the hand-in.

## What shipped

`crates/gear-app/src/standard.rs`:

- `standard::line(project_root) -> Option<String>` — when
  `<root>/gear/standard.md` exists, one line with its **absolute** path (the
  file's canonical path, so a symlinked root names where the file really is):
  `Project standard: <path> — new and changed code follows it, even where the
  code around it does not; the reviewer judges against it.`; `None`
  otherwise, and nothing at all for an empty root;
- `standard::standard_path(root)` — the path alone, for a caller that wants it;
- `standard::line_for(tx, project)` — the same line for a registered project,
  reading the root from its config.

**Both packets carry it** — and the two engine call sites are the one-line
additions the goal allowed, so they are written here (no TODO left):

- the **task packet**: `plan::render_task_packet` (`gear --show T-n`) appends
  the line after `Estimate:` — course's own file;
- the **dispatch delivery** (`crates/gear-engine/src/dispatch.rs`): the
  assignment and the continue text carry it (`intend_dispatch` computes it
  once per call, from the project's config);
- the **review packet** (`crates/gear-engine/src/review.rs`):
  `review_packet_for` appends it to the packet the reviewer receives, so the
  writer and the reviewer judge against the same text.

A project without the file is byte-for-byte unchanged (the existing packet and
dispatch tests pass untouched, because their fixtures have no config root).

## Acceptance evidence

- `standard_contract::the_line_names_the_absolute_file_and_what_it_is_for`:
  no file → `None`; with the file → exactly the sentence above, with the
  canonical absolute path; an empty root → `None`.
- `standard_contract::the_task_packet_carries_the_line_only_when_the_standard_exists`:
  a registered project (a temp root) and one task → the packet has no
  `Project standard:`; after writing `<root>/gear/standard.md` the same packet
  carries it (with the file's path and the reviewer sentence) and still has
  its goal and commands.
- `review::tests::the_review_packet_carries_the_project_standard`: the review
  packet for a task in a project with a temp root has no line; with the file
  it does, and the packet's own content (`Review T-1 attempt 1`,
  `Diff to review`) is unchanged around it.
