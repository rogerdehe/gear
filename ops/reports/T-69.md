# T-69 — A re-review on another seat does not fight the previous checkout

Attempt 3, contract v1 — the rework of the second review's R4 and R1: a
reviewer that was **released** still owns the checkout it left behind, but
`holder_to_detach` only looked at live bindings, so the re-review went to
another seat and found the branch held by a worktree the engine could not name
(the checkout failed three times). R2 (start the review in the holder's seat)
is moved to M4.

Trial G10: the re-review of a task started on a second reviewer seat while the
first seat's worktree still held `review/t<n>`, so `git checkout -B` refused
and the checkout was retried every tick. Now a clean holder of the branch is
detached (its HEAD kept) and the review goes on; a holder with uncommitted
changes is left alone, and the engine stops after three tries and tells the
captain. The temp slots are shown as running / starting / blocked.

## What changed

- **`crates/gear-engine/src/review.rs`, the engine names one holder (R1)** —
  `holder_to_detach` finds at most one worktree to detach: a **known reviewer
  seat** (its worktree path and the branch its checkout took are recorded in
  the store), not the seat starting now, whose **bound pane has no live agent**
  in Herdr. A live reviewer, a seat with no recorded checkout for the branch,
  and any holder the engine does not know are never named.
- **a released reviewer still counts as a holder (R4)** — the pane is taken
  from the seat's binding when it is **Active**, or when it **ended at release**
  (a `Void` binding on a `Released` seat). The released reviewer left its
  checkout on the job's branch, and the next review of that task runs on a
  different seat, so its clean worktree is the one the engine detaches. A
  `Pending` binding is a start that has not reached its agent yet and is never
  named. The branch a seat's checkout took is now kept after the release
  (`engine.review_branch.<seat>.<repo>`), which is what makes the released
  holder findable.
- **only a positive "no agent" counts (R1 of the second review)** — `Ok(None)`
  from Herdr names the holder; a live agent (`Ok(Some)`) and an observation
  **error** are both passed over. A pane that cannot be looked at is never an
  absence, so nothing is detached on a guess.
- **the checkout command** — it receives that one path, quoted, and detaches it
  only while it is **clean** (`git -C '<path>' status --porcelain` empty;
  `checkout --detach`, its HEAD kept). A dirty holder is left untouched and the
  chain reports the failure marker, so the engine does not fight it. The shell
  no longer scans the repo's worktrees (R3's quoting came with this).
- **`crates/gear-engine/src/review.rs`, `checkout_ready`** — a failed checkout
  is counted per seat generation; after `CHECKOUT_TRIES` (3) the seat is
  **parked** (NeedsCheck, for a human) and the captain gets **one item** naming
  the branch, the candidate and the worktree with the last line the pane showed.
  Below that, a fresh token resubmits as before.
- **`crates/gear-board/src/lib.rs` and `crates/gear-app/src/home.rs`** — the
  temp slots are no longer one number: `Temps` gains `running`, `starting` and
  `blocked` (a temp seat is blocked while the engine's blocked timer for it is
  live), the board prints `Temp slots: N running · M starting · B blocked (I of
  Q in use)` and the captain's snapshot line reads `temps N running · M
  starting · B blocked (I of Q)`.

## Acceptance evidence

- `only_an_idle_clean_reviewer_is_named_as_the_holder` (R1, in
  `crates/gear-engine/src/review.rs`) — with two reviewer seats recorded on the
  same branch, the one whose pane has no live agent is named; a live reviewer
  is not, and a branch nobody recorded has no holder at all. A **released**
  reviewer (a `Void` binding on a `Released` seat, its branch still recorded)
  is named (R4); with Herdr's observation failing, nobody is named (R1).
- `a_clean_holder_of_the_review_branch_is_detached_a_dirty_one_is_not` (real
  git) — a scratch repo with `origin`, `review/t1` at a candidate, the previous
  seat's worktree checked out on it and a second seat's free: the checkout
  command, given that one path, reports success, the old worktree is detached
  with its HEAD unchanged, and the new one is on `review/t1` at the candidate.
  The same holder **with an uncommitted file** is not detached and the command
  reports the failure marker; and a holder the engine names no path for (an
  unowned worktree on the branch) is left alone and the checkout fails.
- `a_released_reviewers_clean_worktree_is_detached_and_the_review_starts` (real
  git, engine level, through the `release_finished_reviews` lifecycle) — a
  scratch repo with `origin`, `review/t1` at a real candidate and two real
  worktrees; `review-9` finishes its job and is released (its binding ends
  `Void`), leaving `review/t1` checked out. The next review of the task takes
  the **other** seat (`review-1`, warm and free); the engine names `review-9`'s
  worktree in the checkout. The command is run for real: the holder is detached
  with its HEAD kept, the new seat lands on `review/t1` at the candidate, and
  the reviewer starts. With the released-holder lookup removed the test fails,
  so it is the regression guard for R4.
- `a_dirty_released_holder_keeps_its_files_and_the_checkout_stops_after_three_tries`
  (real git, same lifecycle) — the released holder has an uncommitted file: the
  real command reports the failure marker, the holder keeps its branch and its
  file, three submissions are made in all, the seat is parked
  (`Unknown` with "failed 3 times") and the captain gets **one** item. With
  `Err` counted as an absence the unit test above fails; with the released
  lookup removed this one fails.
- The temps line: `the_captain_home_starts_with_the_snapshot_before_the_inbox`
  (gear-app) and `the_board_shows_the_captains_inbox_and_the_temp_slots`
  (gear-board) now assert the three counts.
