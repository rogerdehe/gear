# T-9 — the captain's home page starts with a snapshot

Scope: T-9 — the captain's `gear` page starts with a short snapshot before the inbox: the totals, one line per lane (the task it is on and how much is queued), the deliveries not confirmed, the temp slots — built from the board's model, so the two views of the plan never disagree.

Branch: board/t9. The hand-in commit carries the code and this brief; the candidate sha in the result names it (a brief inside a commit cannot name its own sha).

Files:
- `crates/gear-board/src/lib.rs` — the model is shared: `project(tx, project, now)` builds one project's plan for both views, `state_word` is public (the two pages use the same words), and `ProjectBoard` carries `unconfirmed_deliveries` (the Deliver ops that are not settled), which the board itself does not draw but the captain's snapshot shows.
- `crates/gear-app/src/home.rs` — the snapshot for the captain only, after the identity line and before the inbox: a `SNAPSHOT` line with the totals, one line per lane (its current task and state, how many are queued), then the deliveries not confirmed and the temp slots. At most 10 lanes, so the block stays under 15 lines.
- `crates/gear-app/Cargo.toml` — gear-app uses gear-board (the model is not duplicated).
- `crates/gear-app/tests/app_home.rs` — the test with 2 lanes checks the snapshot lines, that they come before `INBOX`, and that a lane's page has no snapshot.

Open questions:
- **I could not run `gear` as the captain.** The identity is bound to the captain's pane (`GEAR_CTX` generation + pane + the occupant fingerprint), so a lane cannot impersonate it — by design. The page above is the same code path on the same store; the captain's own `gear` will show it. (The probe was a throwaway test, deleted before the commit.)
- **The snapshot is the captain's only.** A lane's page keeps its current-task line and goes straight to unshown replies/instructions; a lane does not need the whole fleet's plan.
- **`unconfirmed_deliveries` lives in the board model** even though the board does not draw it: the model is the project's plan snapshot and the captain's page is its second reader.
- **A delivered task behind a submitted attempt.** The page shows `deliveries not confirmed: 1` for T-9: the engine delivered it, but the home page shows the first open attempt (`T-14 submitted` sorts before `T-9 delivered`), so the delivery cannot be confirmed until T-14 is settled. That is an engine gap this snapshot now makes visible.
