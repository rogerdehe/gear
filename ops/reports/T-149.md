## The rule (design §10.1)

The text the engine sends to a seat — a task packet, a doorbell, a lifecycle
exit command — used to go to the **pane id**. Herdr then typed it wherever
the pane's foreground was: an agent that had just exited left a shell behind,
and the text was typed into it. Now:

- the text goes to the live **agent name**, never to the pane id — Herdr
  refuses a prompt when no agent of that name runs, so a pane that lost its
  agent never receives the text;
- when Herdr refuses, `agent_get` alone decides: an agent of the seat's kind
  is there → it lost its name (M3.1) → the naming gives the name back and the
  text goes again **next tick**, nothing is restarted; no agent of the seat's
  kind in the pane → the op fails **at once** with the reason `agent-gone`;
- `pane_run` (a shell command) runs only in a pane that hosts **no** agent.

## What changed

**Aiming (`crates/gear-engine/src/names.rs`, `crates/gear-engine/src/ops.rs`).**
`names::resolve_target` reads the pane's occupant first (`agent_get`): only an
agent of the seat's kind (`bindings.kind`) is the seat's agent — another CLI in
the pane is not ours, and a pane with only a shell has no agent at all. Then it
reads the name that agent carries (one `agent.list` per tick, shared by every
op of the tick):

- it carries a name → `Target::Prompt { name }`: the text goes to **that**
  name. The name belongs to the agent of this pane, so the text cannot reach
  another pane;
- it lost its name (`None`) → it is renamed to the seat's name now and the text
  goes next tick (`Target::Renamed`); the rename is refused when another pane
  holds the name (`Target::Blocked`: nothing is typed), and an unknown outcome
  is an observation failure, never "the agent is gone"
  (`Target::Unreadable`).

`ops::aim` is the one place that talks to Herdr about it. It prompts by the
name, and on a refusal it calls `agent_get` and nothing else (**F2**): an
agent of the seat's kind is there → the naming (`names::ensure`) gives the
name back and the op goes back to `Intended`, so the text goes on the next
tick and nothing is restarted; no agent of the seat's kind → `Aimed::Gone` →
the op fails at once with `agent-gone: …`; the pane could not be read → the op
waits (an observation failure is never "the agent is gone", design/08).

**The sender has no exception (F3).** `deliver_doorbell_now` used to rename an
unnamed agent and type in the same call. Now every `Target::Renamed` — the
sender's too — is `Aimed::Retry`: the agent is named and the op stays
`Intended`; the next tick types the doorbell by name. An agent that already
carries its name is still typed at once, as before.

**Every prompt call site aims at a name (F1).** The four calls in the engine
are now:

| Call site | Text | Target |
|---|---|---|
| `ops.rs` — the delivery and the doorbell of the tick | the packet, the doorbell | the live agent name |
| `ops.rs` — `deliver_doorbell_now` (the sender) | the doorbell | the live agent name |
| `onboard.rs` — the teardown of a leftover agent | the profile's exit command | the live agent name of the occupant |
| `restart.rs` — the exit of the CLI that is replaced | the profile's exit command | the live agent name |
| `release.rs` — the goodbye of a released reviewer | the profile's exit command | the live agent name |

The three lifecycle calls (in hull's files) changed only their target: the
command now goes to the name the occupant carries
(`names::live_name`), and when no name can be established the command is
**withheld** rather than typed into a shell. The trait comment in
`crates/gear-herdr/src/lib.rs` no longer allows a pane id.

**`pane_run` only without an agent.** The real door (`SocketHerdr::pane_run`)
reads `agent_get` first and refuses a pane that hosts an agent (the new
refusal code `agent_present`); the fake models the same refusal.

**The fake (`crates/gear-herdr/src/fake.rs`).** `prompt` takes a *target*: an
agent name or a pane id, and resolves it the way Herdr does (a name no agent
carries is refused). The call log keeps both (`pane`: where the text went,
`target`: what the engine aimed at), so a test can assert that the engine
aimed at the name.

**The op state (`crates/gear-model/src/state.rs`).** One transition added:
`Executing → Intended`. An op whose text was never typed goes back to the queue
instead of failing — the text is typed on the next tick, and the seat's
delivery slot stays held by the same op. (This file is deck's crate; the
transition is the smallest change the design's "retried next tick" needs.)

**Names of seats that expect their agent (`crates/gear-engine/src/names.rs`).**
The tick's name step also names the agent of a seat with a **Pending** binding
(the engine asked Herdr to start it and has not confirmed it yet — the
adopted reviewer of the T-18 review). Without that, a reviewer whose agent was
accepted before the crash would lose its first packet to a tick of delay.
