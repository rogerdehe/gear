# T-149 — Never type into the wrong thing (design §10.1)

The text the engine sends to a seat — a task packet, a doorbell — used to go to
the **pane id**. Herdr then typed it wherever the pane's foreground was: an
agent that had just exited left a shell behind, and the packet was typed into
it. The rule is now the design's §10.1, word for word:

- the text goes to the live **agent name**, never to the pane id — Herdr
  refuses a prompt when no agent of that name runs (`agent_not_found` /
  `agent_not_ready`), so a pane that lost its agent never receives the text;
- when Herdr refuses, `agent_get` decides: an agent of the seat's kind is
  there → it lost its name (M3.1) → it is renamed now and the text goes again
  **next tick**, nothing is restarted; no agent of the seat's kind in the pane
  → the op fails **at once** with the reason `agent-gone`;
- `pane_run` (a shell command) runs only in a pane that hosts **no** agent.

## What changed

**Aiming (`crates/gear-engine/src/names.rs`, `crates/gear-engine/src/ops.rs`).**
`names::resolve_target` reads the pane's occupant first (`agent_get`): only an
agent of the seat's kind (`bindings.kind`) is the seat's agent — another CLI in
the pane is not ours, and a pane with only a shell has no agent at all. Then it
reads the name that agent carries (one `agent.list` per tick, shared by every
op of the tick):

- it carries a name → `Target::Prompt { name }`: the text goes to **that**
  name. The name belongs to the agent of this pane, so the text cannot reach
  another pane;
- it lost its name (`None`) → it is renamed to the seat's name now and the text
  goes next tick (`Target::Renamed`); the rename is refused when another pane
  holds the name (`Target::Blocked`: nothing is typed), and an unknown outcome
  is an observation failure, never "the agent is gone" (`Target::Unreadable`).

`ops::aim` is the one place that talks to Herdr about it. It prompts by the
name, and on a refusal it calls `agent_get` again: an agent of the seat's kind
is there and carries **no** name at all → it is renamed and the op goes back to
`Intended` (the next tick types it; the op is not failed and not resent into
the same tick); no agent of the seat's kind → `Aimed::Gone` → the op fails at
once with `agent-gone: …`; any other refusal (a dialog, a busy pane) fails the
op as before.

**The op state (`crates/gear-model/src/state.rs`).** One transition added:
`Executing → Intended`. An op whose text was never typed goes back to the queue
instead of failing — the packet is typed on the next tick, and the seat's
delivery slot stays held by the same op. (This file is deck's crate; the
transition is the smallest change the design's "retried next tick" needs.)

**`pane_run` (`crates/gear-herdr/src/lib.rs`, `crates/gear-herdr/src/fake.rs`).**
The real door and the fake both refuse a shell command in a pane that hosts an
agent (`agent_present`, a new refusal code: nothing was typed). With §3.7 the
reviewer's checkout no longer goes through a pane at all, so the only callers
left are the environment export before an agent start and the restart's own
command — both in panes without an agent.

**The fake (`crates/gear-herdr/src/fake.rs`).** `prompt` takes a *target*: an
agent name or a pane id, and resolves it the way Herdr does (an agent name
first, a name no agent carries is refused). The call log keeps both (`pane`:
where the text went, `target`: what the engine aimed at), so a test can assert
that the engine aimed at the name. `pane_run` refuses a pane with an agent.

**Names of seats that expect their agent (`crates/gear-engine/src/names.rs`).**
The tick's name step now also names the agent of a seat with a **Pending**
binding (the engine asked Herdr to start it and has not confirmed it yet — the
adopted reviewer of the T-18 review). Without that, a reviewer whose agent was
accepted before the crash would lose its first packet to a tick of delay.

**The sender's own doorbell (`ops::deliver_doorbell_now`).** The captain's
`gear send` types its doorbell before it returns (T-130), so the sender names
the agent and types at once; the engine's tick waits for the next one. Both
aim at the live name, and both never type into a pane without the seat's
agent.

## Open questions

none — three decisions worth naming:

- **The live name, not the seat's name.** The text goes to the name the agent
  carries now, not to the seat's name. The name of the pane's own agent can
  never belong to another pane, so the text cannot reach a foreign agent; the
  seat's name is what the engine *gives* the agent when it lost it (and what
  the tick's name step keeps).
- **A lost name costs a tick.** The engine renames the agent and the text goes
  on the next tick, as the design says ("the prompt is retried next tick,
  nothing is restarted"). The tick's own name step has usually given the name
  back long before, so in a running voyage this is rare.
- **The sender types at once.** `gear send` promises that the doorbell is
  typed before it returns (T-130), so the sender names the agent and types in
  the same call; the engine's tick waits for the next one.

## Out of scope

- **The exit, release and model-switch commands** (`restart.rs`, `release.rs`,
  `switch.rs`) still aim at the pane id: they are commands for the seat's own
  agent, and they live in hull's files. They cannot type into a *lane's*
  packet, but a shell would receive a stray `/exit` — the next task that
  touches those paths should aim them at the name too.
- **The seat's restart path after `agent-gone`** (design §3.3 S1: resume the
  round's session) is hull's `session.rs` work (T-144/T-145). Until it lands,
  a seat whose agent is gone is flagged to the captain as before, and the
  failed delivery says `agent-gone`.
- **The seat's name is not stored** (as in T-134): Herdr owns it, and the
  store keeps the seat's name, from which the agent's name is derived.
