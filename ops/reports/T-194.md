# T-194: quiet lanes and loop guard

Task packets end with the exact requested instruction. Each project tick checks Started lane attempts against the later of their start time and the local `refs/remotes/origin/<lane>/t<n>` commit time, without fetching. After more than 20 minutes without a push and 20 minutes since the previous ask, it sends the urgent lane instruction and a captain info item. Parked, held, provider-backoff and declared-wait lanes are excluded.

A working lane whose bound session file is unchanged for 10 minutes receives one escape per 10-minute period, the same instruction and a captain info item. The interruption is reserved durably before the external call; the next task delivery waits for the profile's compact command through the existing session state machine. Already-intended deliveries are also held, while obsolete operations can still be voided. Session and ops glue is included to enforce that ordering.

Tests cover the exact packet line, the push clock and reset, repeated ticks, excluded seats, fresh and stale session files, one escape and one pair of messages, and compact-before-delivery including an already-intended op. `scripts/test.sh` passed on the merged candidate: 1,270 tests, 0 failures (59 s build, 90 s suite). Nextest marked the existing store test `a_pause_opens_and_closes_and_the_project_reads_them_back` leaky. The earlier full run exposed and prompted the declared-wait suppression; another build was restarted after development was merged during compilation.
