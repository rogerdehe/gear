## Implementation notes

1. `classify_screen`: take the last `profile.tail_lines` lines of `tail`; **literal substring** match per line (no regex); each of the four marker lists maps to a `ScreenFlag`.
2. `validate_template`: if the template contains any marker (all four lists) → `Err(message naming the marker)`.
3. `outcome_from_error`:
   - `HerdrError::Protocol { code }` with a code that proves nothing ran → `Refused`. That set: `agent_blocked`, `not_found`, `invalid_request`, `invalid_params`, `agent_not_found`, `pane_not_found`, `pane_not_available`. Any other code → `Uncertain`.
   - `Io`, `Deadline`, `Disconnected`, `Decode` → `Uncertain`.
4. `SocketHerdr::connect`: `HerdrClient::connect(path)` then `require_supported_protocol()`; failure → `ObserveError(description)`.
5. Reads:
   - `agents()` → agents from `session_snapshot()`;
   - `agent_get(pane)` → `agent_get`; pane missing or no agent → `Ok(None)` (tell "missing" apart from other failures by protocol error code; other errors → `ObserveError`);
   - `read_tail(pane, lines)` → `pane_read`, source `RecentUnwrapped`, `lines` lines, return the text.
6. Writes: success → `Outcome::Ok`; error → `outcome_from_error`.
   - `prompt`: `agent_prompt`, **no wait**;
   - `pane_run`: if board-herdr has a single call that sends text + Enter atomically (check `client.rs`; Herdr's CLI `pane run` does this), use it; otherwise `pane_send_text` then `pane_send_keys(["enter"])`, and a failure of the second step → `Uncertain`;
   - `agent_start`: `AgentStartParams { name, kind, pane_id, args, timeout_ms: Some(60_000) }`; return the pane's `AgentInfo` (call `agent_get` again if needed);
   - `send_keys`, `pane_close`, `notify` (`notification_show`): the matching methods;
   - `set_title`: Herdr `pane.report_metadata` (title field, source fixed to `"gear"`). If board-herdr has no wrapper, use `client.call("pane.report_metadata", json!{...})`; check field names against the schema.
   - `worktree_create(repo, branch, base, label)`: `client.call("worktree.create", {cwd: repo, branch, base, label, focus: false})` (params: `WorktreeCreateParams`). Build `Worktree` from the result: `workspace.workspace_id`, `root_pane.pane_id`, `worktree.path`, `worktree.branch`. Example of a real reply (shortened):
     `{"type":"worktree_created","workspace":{"workspace_id":"w3",…},"root_pane":{"pane_id":"w3:p1",…},"worktree":{"branch":"t1-store","path":"/Volumes/Data/.herdr-worktrees/gear/t1-store",…}}`. A reply missing any of these fields → `Uncertain` (the worktree may exist).
   - `worktree_open(repo, branch, label)`: `worktree.open` with `{cwd: repo, branch, label, focus: false}`; same result mapping (if the reply shape differs, check the schema's `ResponseResult` variants and say so in the report).
   - `worktree_remove(workspace_id)`: `worktree.remove` with `{workspace_id, force: false}`. Never pass `force: true`.
7. No integration test against the real Herdr (it would touch the live session). It must compile and the logic must be clear; the captain runs live probes separately.
