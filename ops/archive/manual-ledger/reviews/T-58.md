## Findings

- none at P0–P2. The four below are P3; none stops the walking skeleton and none needs writer action.

- [P3] `env_command` interpolates `db_path` (and `project`, `seat`) into a shell line with no quoting — `crates/gear-engine/src/onboard.rs:88-91`. A `GEAR_DB` holding a space or a shell metacharacter would export a different path than intended, and onboarded agents would then open the wrong store (`NoTarget`, or a second empty database). Not fixable inside this packet: the exact string is pinned by `onboard_contract.rs:19,30` and by design/03:17, and quoting it would be a contract change — raised as a question instead.
- [P3] Both refusal messages name the agent `kind`, while the profile is looked up by `seat.profile` — `crates/gear-engine/src/onboard.rs:56` and `:71`. Today that reads correctly (`engine_cfg` keys `cfg.profiles` by kind, `crates/gear-cli/src/main.rs:725-729`, and `opencode` is the only key), but the moment a named profile is added the reason written into `state_reason` would point the captain at the wrong key.
- [P3] The resume substitution is a silent no-op if a profile's `resume_args` contain no `{session}` — `crates/gear-engine/src/onboard.rs:73`. `str::replace` returns the argument unchanged, so a `resume: Some("ses_1")` request would be accepted and the session reference quietly dropped. Only `builtin("opencode")` can reach this today and it carries the placeholder; rejecting a placeholder-less `resume_args` would be a `Profile`-level decision, which is not this packet's file.
- [P3] The M-8 progress note lists the merged imports incompletely — `ops/tasks/T-58.md:44` says "with the combined imports (`HerdrAct`, `GearResult`, `Ts`, `Store`)" while `onboard.rs:5-7` has seven names, `Profile`, `SeatRole` and `SeatRow` among them. A reader could take the omission for a dropped name; I checked the file and they are all present.

## Set aside

- Temp worktrees — `plan_onboard` gives a `WorktreeStep` to `Lane` only and `None` to every other role, while design/10:30 says a temp gets `worktree create --branch <task-branch> --label <project>-<task-id>`. The doc comment this task is told to implement fixes it the other way, the contract test pins `None` for a non-lane, and the engine does not onboard temps in this cut (`onboard_queued`'s doc: "captain and temps are not onboarded by the engine yet"). Design/10's temp rule is T-62-and-later work, not a T-58 gap.
- `plan_onboard` never checks that `kind` and `profile` agree — a lane declaring `kind = "claude"` with `profile = "opencode"` would be started as `claude` with opencode's args. The doc comment fixes `kind` as the caller's input and the refusal list as closed ("an unverified profile, or an agent name longer than 32 chars"), so adding a check here would contradict the spec this task implements. Raised as a question instead.
- `profile.session_ref == false` for `opencode` (`crates/gear-herdr/src/profile.rs:120`) while its `resume_args` are present. `onboard_queued` step 6 needs a `session_ref` from Herdr to call `finish_onboard`, so the resume path cannot yet be driven end to end for opencode. Not T-58's contract — its test requires the resume args to be appended, and it does not — but T-62 should know.
- `generation` is not range-checked here (0 or negative would produce a `GEAR_CTX` that `GearCtx::parse` rejects, since it requires `> 0`). The caller computes `seat.generation + 1`, so this cannot happen through the intended path, and the doc comment does not promise the check.
- The pane-readiness precondition and the "environment setup and start are confirmed as separate steps" rule (design/03:23) are Herdr-side concerns: `onboard_queued`'s doc gives them steps 3–5 (T-62). Nothing in this pure planner is responsible for them.
