## Set aside
- `plan_dispatch` still calls `lane_view` (and thus the store reads behind it) for a seat whose `obs` is None, then `decide` short-circuits to `None`. The doc only requires the view+decide shape, and `decide`'s first checks make the None-obs path correct, so the extra reads are harmless; not a bug.
- `intend_dispatch`'s `Continue` arm silently skips (rather than errors) when no open attempt matches the action's `task`, while `Assign` propagates `start_attempt`'s validation error. In the normal flow `decide` emits `Continue { task: attempt.task }` so the match always holds; the skip is a defensive guard against a stale/raced action, and the contract test only exercises the matching case, so this is not a covered-case defect.
- `plan_dispatch`/`intend_dispatch` are run in separate read/write transactions by the contract test; wiring them (and any error handling for a raced `start_attempt`) into `tick` is the next task and out of scope here.
