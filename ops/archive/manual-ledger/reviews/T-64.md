## Findings

- [P1] `gear admin init` cannot be run by the only caller the design gives it — `crates/gear-cli/src/main.rs:228` (`let mut store = open_store()?;`) with `main.rs:247-256` (`open_store_at` → `GEAR_DB` or `NoTarget`) and the doc claim at `main.rs:241`. design/13:27 puts ops commands in the user's own shell with no `GEAR_CTX`; design/14:32 says user ops commands locate the database via `~/.config/gear/targets.toml` (execution host/session → database path, recorded at install time). `GEAR_DB` is the *agents'* variable — the only thing that sets it is the onboarding env command, `crates/gear-engine/src/onboard.rs:88-91` (`export GEAR_CTX=…; export GEAR_DB=…`, pinned by design/03:17) — and that code does not run until a project is already registered. Verified on the reviewed commit: `env -u GEAR_CTX -u GEAR_DB GEAR_ADMIN=1 ./target/debug/gear admin init project.toml` → `ERROR NO_TARGET: GEAR_DB is not set`, exit 1; with `GEAR_DB` exported it succeeds. There is no `~/.config/gear/` on this host and no runbook anywhere in `ops/` that exports `GEAR_DB`. Why it matters: this is step 0 of the loop (design/00:109 "The user registers the project with `gear admin init`; the engine starts and onboards the captain and long-lived lanes", and T-62's packet Goal: "after it, `gear admin init` + `gear run` start a real lane on a real Herdr"). As committed, the walking skeleton cannot be started the way the design describes, and the error the user hits names a variable they have no way to know about. Fix — pick one inside this branch and make the code say which: (a) resolve the admin store per design/14 (`~/.config/gear/targets.toml`, falling back to `GEAR_DB` when the file is absent, with the existing `NoTarget` when neither resolves); or (b) if the MVP decision is that the user exports `GEAR_DB`, then ship that as documented behaviour — the command's doc comment and help must say so, and a runbook/STOPGAPS row must record it (T-60 is the removal trigger for the stopgaps table) — and fix the doc comment at `main.rs:241`, which currently claims an admin-target branch that does not exist. `cmd_run` (T-32, `main.rs:733`) has the identical dependency, so (a) or (b) probably wants to cover both commands rather than just this one.
- [P2] The new command has no test, and the one test that reaches it now asserts the opposite, passes for the wrong reason, and goes red in the shell the command is for — `crates/gear-cli/tests/skill_contract.rs:61-65` and `crates/gear-cli/src/main.rs:217-239`. `not_yet_commands_fail_cleanly` still runs `gear admin init x` and asserts `ERROR FORBIDDEN: `, carrying the comment `// slice 3; `plan apply` is implemented since T-52` (`skill_contract.rs:62`). After this branch that assertion passes *only* because the test environment has no `GEAR_ADMIN`: the `Forbidden` now comes from the new caller check (`main.rs:219-224`), not from "not implemented yet" — the very error the branch replaced. Verified: `GEAR_ADMIN=1 cargo test -p gear-cli --test skill_contract` → `not_yet_commands_fail_cleanly ... FAILED` with `ERROR BAD_FORMAT: cannot read x: No such file or directory`; the identical command on `origin/dev` (e3be5fe) passes, so this is a branch regression, not pre-existing. Two consequences: (a) `GEAR_ADMIN=1` is exactly the environment this command exists for, so the first person who exports it gets a red `cargo test -p gear-cli` — the acceptance gate for every later CLI task (CONVENTIONS "Acceptance"); (b) the only automated coverage of the new dispatch claims the command does not exist, so the dispatch could be deleted and the suite would stay green in a default shell. There is also no unit test for the command itself, which breaks the file's own pattern — every other command here has a `run_*` body over injected state (`run_send`, `run_reply`, `run_plan`, `run_home`, `run_show`, `run_engine`) precisely so the glue cannot hide behaviour (T-54's finding was exactly that). Fix: `skill_contract.rs` is a contract test, so a lane may not touch it — the captain rewrites it to assert what is now true (from an admin shell a missing config gives `ERROR BAD_FORMAT: cannot read …`; from a non-admin shell `ERROR FORBIDDEN:`; an agent ctx + `GEAR_ADMIN=1` is refused) and drops the "slice 3" comment; and add a private `run_admin_init` over an injected store/env with a unit test next to the others, which also pins the ordering that is currently only true by inspection (caller refused before the file is read).
