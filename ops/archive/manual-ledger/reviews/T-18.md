## Set aside
- The `require_transition` check sits inside the per-op loop on a constant predicate; it cannot fail here, but it guards the raw `set_op_state` write and the whole recovery is one transaction that rolls back on error, so there is no behaviour issue — kept.
- `project_ids()` can only see projects that have a `projects` row, while `operations.project` has no foreign key and `insert_op` checks nothing; an Executing op in a project without a row would not be recovered. That is the store's data-integrity surface and the enumeration the captain fixed in M-1; `intend_doorbells` gets its project from `decide` over known projects, so it is outside this task.
- The op payload does not carry `DoorbellAction::pane_id`; T-19 can resolve the pane with `Tx::get_binding(seat, generation)`, and the packet fixes the payload to `text` + `covers` — not changed.
- design/08's recovery check "the execution host/session must match the current Herdr; refuse to run on mismatch" is not in `recover_on_start` (no Herdr handle in its signature); it belongs to engine start/tick (T-4).
- Submitted/Unknown ops are deliberately untouched by recovery (design/08: Submitted stays pending check, nothing re-sent); only Executing is changed.
- The Progress notes keep the pre-rework bullet about the temporary `meta.projects` registry; the next bullet supersedes it and the section is a chronological log, so it is not flagged as stale documentation.
- No test for an empty store (no Executing op → empty result); it is not a packet-named test and follows trivially from the loop — coverage gap only.
- The test helpers `insert_op`/`walk_to` use raw state writes without a transition check (the T-10 gap); they are scaffolding for this task only.
