# 05 Plan: Draft Format, Apply, Views

Files: `gear/plan/draft.py`, `apply.py`, `render.py`. Budget 270–330 lines.
Invariants upheld: single authoritative plan; an invalid draft is rejected in full; completion requires a passing acceptance verdict; a draft cannot overwrite runtime facts.

## File locations (one directory per project: `<state_dir>/projects/<id>/`)

| File | Written by | Read by | Notes |
|---|---|---|---|
| `plan.draft.md` | exported by the engine, edited by the captain | captain | carries `base=<version>` |
| `PLAN.md` | engine | captain, user | bounded view, read-only |
| `tasks/T-17.md` | engine | lane | task packet, read-only |
| `handover.md` | engine | new captain | only during handover |

**The draft is not written back automatically**: after a successful apply the engine does not overwrite `plan.draft.md`. When a new base is needed, the captain exports one to a new file with `gear --show draft` (it does not overwrite an existing uncommitted draft file). PLAN.md and task packets are still generated by the engine.

## Draft format (strict, one only)

```markdown
<!-- gear-plan project=harbor base=12 -->
# Goal
Goal and completion criteria.

# Milestone M2: Login system
Scope; explicitly out of scope: ...

# Decisions
- 2026-10-21 T-31 jumps to the front: production login crash; T-17 resumes after its safe point

# Queue
## T-31 [now] lane=heat milestone=M2 required
goal: Fix the iOS login crash
accept: Repro case passes; regression tests all green
estimate: 90
evidence-files: notes/T-31-repro.md
evidence-due: 60
deps: -

## T-17 [must] lane=wire milestone=M2 required
goal: …
accept: …
deps: T-12

# Staff
- temp R-4 task=T-45 profile=opencode-review
- temp R-2 task=T-31 resume
- park heat until=2026-10-21T15:30Z
- park media until-task=T-12
- hold wire reason=waiting for user authorization
- retire prompts

# Verdicts
- T-29 attempt=2 contract=3 candidate=abc1234 pass evidence=logs/T-29-verify.md
- T-33 attempt=1 contract=1 candidate=def5678 fail rework="Edge cases not covered, see review.md"

# Review
V-9 keep plan=12: dependency unresolved, keep the order; next=2026-10-21T16:00Z
```

Rules:

- The block order in `# Queue` determines rank; `[now|must|should|could|wont]` is an independent priority field, and neither overrides the readiness gate (dependencies, capacity, write resources, authorization). Non-terminal tasks that do not appear in the draft **keep their state and relative order** (placed after the tasks listed in the draft) and are listed as "not mentioned" in the result. Deletion can only be written as `state=cancelled`.
- Allowed fields: `goal`, `accept`, `estimate` (the planned time in minutes), `evidence-files`, `evidence-due` (minutes), `deps`, `state`, `followup-of`, `reopen` (required only for DONE→READY); block headers allow `lane=`, `milestone=`, `required`. **Any unknown field or disallowed state value → the whole draft is `BAD_FORMAT`**. `state=` only allows `ready` and `cancelled`.
- New tasks are written `## NEW [should] lane=…` and are assigned `T-<n>` at apply time. A `NEW` block needs `estimate:` (minutes): the time the task is planned to take, which the time report compares with what it really took. An existing task may keep the estimate it has; a draft that gives one changes it.
- **Completion only through `# Verdicts`**: each line names the task, attempt, contract version, and candidate.
  - `pass`: must match the candidate submitted by that attempt and its adopted contract, and that contract must equal the current contract after this transaction's proposed apply; and there must be passing evidence (12 evidence header, result=pass).
  - `fail`: targets the candidate and contract originally submitted by that attempt under verification, gives a `rework=` reason, does not require equality with the task's latest contract, and does not require an evidence header; the original attempt becomes REJECTED, the task READY, the next attempt adopts the latest valid contract, and old results and evidence are kept. An old-contract candidate may be explicitly sent back, but cannot complete a new contract.
  - An identical already-settled Verdict appearing again only returns the existing result; same task and attempt but conflicting content is rejected; an exported new draft does not require resubmitting historical Verdicts.
- **Same-item rework of a completed task**: do not append fail to an ACCEPTED attempt, do not overwrite historical verdicts. In the draft, write `state=ready` for the DONE task together with a `reopen: <rework reason>` field; plan apply validates and moves DONE→READY, then creates a new attempt (a temp-worker task resumes the original temp worker). It is reopened only when written explicitly; replaying an old draft or follow-up questions never reopen it. New work gets a new task and a new temp worker.
- `# Staff` is a **target**, not a command: when the same R number/target is already realized or has an in-flight action, no duplicate operation is generated; when quota is full the item is queued and noted in the result, the whole plan is not rejected.
- `resume` is only allowed for rework, follow-up questions, or supplementary material on that R number's originally bound task; a new task must use a new R number. `followup-of` only expresses task association and does not authorize reusing an old temp worker. The same resume target appearing repeatedly across multiple applies is not resumed repeatedly; a new round of rework/follow-up for the same R must be linked to a new rework attempt or follow-up item, and is identified as a new resume need on that basis, not by string comparison alone.
- Each `# Review` line references a review item ID and the plan version it is based on, and only closes the items it lists.

## Apply flow (`gear plan apply`, one transaction, via run_request)

1. Parse → any format error is `BAD_FORMAT` (with line number), nothing is written.
2. Identity: captain seat, generation matches, not in HANDOVER/UNAVAILABLE.
3. `base` ≠ current plan version → `STALE_VERSION`, returning a summary of changes since base.
4. Validation: dependencies exist and are acyclic; wont is not dispatched; Verdicts rules; resume rules; park/hold/retire only target this project's long-lived lanes.
5. Write: contract changes → new version (an in-progress attempt gets a pending-adoption notice, 06); rank; milestones and required; park/hold/retire change seat state directly in the transaction (pure data); temp worker starts/resumes are written as operations(INTENDED); Verdicts → 06 `settle`; Review conclusions → reviews; plan version +1; audit.
6. Return: new version number, change list, pending staff actions, queued items, tasks not mentioned, warnings.

## Views

- `PLAN.md`: goal/milestones/last 10 decisions/all in-flight tasks/first 15 recently ready/all urgent and blocked; the rest is written as "N more, oldest waiting X days, `gear --show queue`". ≤ 250 lines, 12KB.
- Task packet `tasks/T-17.md`: rendered according to **the contract version adopted by that attempt** (a pending update, if any, is appended and marked); the header lists directly copyable commands:

```text
gear send --kind progress "…"
gear send --kind result --task T-17 --attempt 3 --contract 4 --candidate <commit> "Report: <path>"
gear send --kind ack --reply-to <message ID> …
```

## Test points

Line numbers for format errors; an illegal state rejects the whole draft; stale base; dependency cycle; unmentioned tasks keep relative order; Verdict with mismatched candidate/contract is rejected; evidence file exists but verdict fail does not allow DONE; resume used for a new task is rejected; the same Staff target applied multiple times does not open twice; the draft is not overwritten after apply; resubmitting a historical Verdict does not settle twice; fail needs no evidence header; changing the contract and accepting in the same apply validates against the final contract.


### Tail declaration (T-40)

A decision line `- tail: heat wire` replaces the set of lanes intentionally
finishing their queue; `- tail: -` clears that set. A draft without a tail line
preserves it. Names must resolve to lane seats in the project; an invalid name
rejects the whole apply. The state is persisted in `meta` under
`lane-tail:<project>:<lane>` and suppresses feed warnings without parking lanes.
