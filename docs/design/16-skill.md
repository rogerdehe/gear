# 16 Agent skill

Implementation: [skill.rs](../../crates/gear-app/src/skill.rs).
The shipped entry point is [SKILL.md](../../skills/gear/SKILL.md);
`gear --skill` prints the version embedded in the binary.

## Why it exists

Agents must know GEAR's rules, but **they cannot be broadcast through nudge messages** (old keeper incident: changing one word of the nudge text amounted to changing the rules of every lane). Following Herdr's approach, "how to work inside GEAR" is made into a skill released with each version: fixed content, versioned, released in sync with the program.

## Division of labor: skill, lane instructions, task packet

| File | Content | Change frequency |
|---|---|---|
| **skill** (common to all projects) | How to use the `gear` commands, report kinds, ACK rules, safe end points, when the captain must be contacted, prohibitions; the default working conventions (17: duties, naming, branches, worktrees, commits, review and merge); captain part: how to read the inbox, reply modes, plan draft format, Verdicts, Staff, review conclusions, handover confirmation | With the GEAR version |
| **Lane instructions / captain instructions** (one per seat, generated by the engine from the project config) | This lane's duty, worktree, project shared documents to follow (e.g. INTERFACES.md), authorization boundaries | With the project config version |
| **Task packet** (one per task) | This task's contract, evidence points, complete commands that can be copied directly | With the contract version |

Common operating instructions are centralized in the skill to avoid duplicated maintenance; lane instructions and task packets still carry project constraints, task contracts and the necessary complete commands. Identity, generation, permissions, state transitions and safety conditions are still validated by the program; checks are not skipped because a rule is written in the skill or because the Agent has ACKed it. The presence of `GEAR_CTX` is only a hint for the reading entry point; whether it is valid is checked by `gear`.

**Default conventions**: the skill ships GEAR's default working conventions (17), with the project's `[conventions]` overrides applied, so the captain and every lane read the same rules via `gear --skill` rather than from per-lane copies.

## Content and installation

The authoritative topics and embedded files are listed in
[skill.rs](../../crates/gear-app/src/skill.rs). Use `gear --skill captain`
for planning, `gear --skill review` for review rules, and
`gear --skill agent:<kind>` for verified CLI operation.
`gear admin install-skill --agent <kind>` installs the matching content.

The former generated `plan-format.md`/`errors.md` layout and skill-adoption
ACK protocol are removed here: they do not describe the shipped implementation.
