# GEAR v0.7.31

A codex captain whose limit is spent is paused like a Claude captain: no new tasks, no rings, one wake when the limit resets.

## Fixed

- **A spent codex captain was still rung.** The captain's limit was read only from Claude's session log or Claude's footer bar, so a codex captain at "You've hit your usage limit" kept getting doorbells and its lanes new tasks (selina, 2026-11-17). The engine now also reads the captain's spent limit from its screen with the profile's quota markers (codex: "You've hit your usage limit" and the other spent-limit texts) on the idle screen it already reads. The reset is the clock after "try again at" on that line, a 12-hour clock (`11:36 PM`) included; without one, `[models] quota_reset_h` is the fallback. Work in flight goes on and hands in; nothing new starts and nothing rings until the reset, then one "Your quota is back" wake.

## Upgrading

Install the new binary (`herdr plugin install rogerdehe/gear --ref v0.7.31`); the engine restarts on it by itself. Nothing to configure.
