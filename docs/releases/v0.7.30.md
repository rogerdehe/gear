# GEAR v0.7.30

No prompt of a seat reaches another agent sitting in the seat's pane, and a landing's records go only into an integration branch that is on the remote.

## Fixed

- **Another agent in a seat's pane gets nothing.** The engine called a seat's agent present when the agent in its bound pane was of the binding's CLI, so another project's agent of the same CLI started in a reused pane got the seat's doorbells, deliveries and name (pharos, 2026-11-16; v0.7.29 closed only the take's handover ask). The engine now records the repository a seat's agent works in the first time it sees it, and an agent in the pane with another session **and** another repository is another agent: the seat counts as changed, nothing is typed into the pane, its agent keeps its own name, the pane is never closed for the seat and a lane move sends it no exit. `/new` or a hand restart of the seat's own agent (a new session in the same repository or a worktree of it) keeps the seat present as before; once the seat's agent is back, the pane is the seat's again. A delivery waits for the seat's agent or a new binding; a captain whose pane was taken over binds again with `gear captain take`.
- **Records go only into an integration branch on the remote.** A landing whose `[conventions].integration` branch was not on the remote merged the captain's records into a stale local branch of that name, or failed on a git error (Lawrence M4.1). The records step now refuses with one item naming the branch and the config key, and deletes nothing.

## Upgrading

Install the new binary (`herdr plugin install rogerdehe/gear --ref v0.7.30`); the engine restarts on it by itself. Nothing to configure.
