# GEAR v0.7.23

A project can run with its captain alone, and the board stops showing finished voyages as sailing.

## New

- **The captain alone.** A small job needs no fleet. Register the project with `quota.lanes = 0`, `quota.temps = 0` and no `[[lanes]]`, and the captain plans and works it:
  - a task with no `lane=` is the captain's own (a project with lanes still needs `lane=` on every task);
  - the captain records a task done in `# Verdicts` with `- T-n done commit=<sha> evidence=<text>`; GEAR refuses a commit that is not on the integration or release branch, and otherwise records the task done and merged;
  - the engine never reports such a voyage as stopped because no lane can start its tasks; it rings the captain only when the captain sits idle with tasks left;
  - the board shows the captain's tasks in a `capt` row.

  The skill's "Working alone" paragraph says how: one worktree of the captain's own on its seat branch, the gate, `git push <remote> HEAD:<integration>`, then the done line. GEAR's own M7.2 was planned, built and landed this way.

## Fixed

- **A finished voyage no longer shows as sailing once a later voyage has departed.** A voyage whose land order was last answered `keep course` stayed under sail on the board for good, even after later voyages departed and landed (four of GEAR's own voyages read as sailing).
- **A cancelled task is never an item to handle.** A task cut at landing whose last attempt took several rounds was listed under TO HANDLE as "round 3: the captain scopes what is left".
- **The friction item takes one line on `gear`.** The page printed every open report in its body (251 of them on every call); it now shows the count and `gear friction`.
- **The board restarts on a new binary.** A board left open kept drawing with the build it started from; it now starts the new build in its place.
- The goal-check line on the board is cut before the milestone column instead of running into it.

## Upgrading

Install the new binary (`herdr plugin install rogerdehe/gear --ref v0.7.23`) and restart the engine. Nothing to configure. A board opened before this release still runs the old build: close it and open it once more; from then on it follows new builds by itself.
