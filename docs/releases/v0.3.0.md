# v0.3.0 — fit in, and run without hands

M3 of GEAR: a project that already runs can take GEAR on, and from the kickoff
to the landing nobody has to patch the store, repoint a branch, close a pane or
restart the engine by hand. One line per change.

## Fit in

- **Take on a project that already runs:** `gear --skill adopt` walks the
  captain through archiving the instruction layer the agent CLIs load by
  themselves, naming the exemplars and the no-go patterns, measuring the gate,
  and deciding what to keep, replace or drop — with two templates to fill in
  (`gear/adopt.md`, `gear/standard.md`).
- **The project's standard travels with the work:** a `gear/standard.md` is in
  every task packet and every review packet, so a lane and a reviewer read the
  rules of *this* project, not only GEAR's.
- **GitHub, as a window onto the work:** a `[github]` mode turns issues into
  plan entries (`gear plan import-issues` prints the blocks), opens a draft
  claim pull request at a task's first delivery, comments the hand-in, the
  verdict and the landing, and closes the issue on the merge. The plan and the
  store stay the source of truth; only the engine writes.
- **Projects of several repositories:** a project can name child repositories,
  each with its own integration branch and gate; a lane works in one of them.
- **Try a voyage end to end, offline:** `scripts/fixtures/make.sh` builds a
  parent repo with two child repos, and a project that already has its own CI
  and habits for the adoption.

## Runs without hands

- **A merge that could not start is retried:** a push race or a gate that could
  not run (a missing command, a broken shell) retries by itself.
- **A red gate needs a remerge:** `- remerge T-<n>` under `# Staff` in the plan
  retries the accepted candidate once the cause is addressed — no follow-up
  task to write.
- **A failed review is settled in the plan:** `# Verdicts` puts the task back at
  the head of its lane with the exact fix; a reply settles nothing.
- **A cancelled task frees its lane:** its open attempt closes, so the lane
  takes its next task instead of looking busy.
- **A slow shell is waited for:** onboarding waits (across ticks) for the
  agent's prompt instead of parking the lane at the first "pane busy".
- **A lane's model label comes from OpenCode:** the text the in-place switch
  types and the status bar shows is derived from OpenCode's own model list, so
  a new model needs no hand-written labels.
- **A model list that is not loaded yet is waited for:** an empty first list is
  "not loaded yet" — the start waits for it, bounded; only a list that is there
  without the model parks the lane, with that reason.
- **An unconfirmed delivery is worked out:** the engine reconciles it from the
  store and the screen instead of repeating it or dropping it.
- **Codex runs without a hand at its start:** a provider back-off (a 429 it
  retries for minutes) shows as a back-off, never a stalled lane, and the
  start-up folder-trust and update dialogs are answered by the profile.

## Known limits

- **Landing *through* a pull request is not in this release:** `merge = "push"`
  is the landing (the engine merges, the pull request is commented, the issue
  closes); `merge = "pr"` is refused by the config until the next milestone.
- Everything else deferred — every agent CLI fully described by its profile,
  the captain's decision record at landing, a cross-CLI hand-over — is in
  [`ops/plan/m4-backlog.md`](../../ops/plan/m4-backlog.md).

## Upgrading

### New to GEAR

Install it as the [README's install section](../../README.md#install) shows, then
start a project. Nothing else.

### From 0.2.x, with no voyage running

Run the stop and the skill install in your own shell: a seat is refused them.

1. Stop the engine: `gear admin stop`
2. Replace the binary: `herdr plugin install rogerdehe/gear --ref v0.3.0` — its
   build step fetches the release binary, or builds it — or, from a checkout,
   `git pull && cargo build --release && herdr plugin link .`
3. Install the skill for every CLI your project uses — it changed in 0.3.0:
   `gear admin install-skill --agent claude`, and again for `codex`, `opencode`
   or `grok` wherever a lane or reviewer runs on it.
4. Restart the agents, so each loads the new skill: the captain first, then the
   lanes and reviewers.
5. Call `gear` once: the store migrates up by itself and the engine starts
   again. A store written by a *newer* GEAR is refused with `SCHEMA_TOO_NEW` —
   that means this binary is the old one.

### During a running voyage

1. Wait until nothing is merging. The page marks a task done *before* its merge
   runs, and merges in different repositories finish out of order, so no single
   line proves it: wait until every task you have seen pass has ended — a
   `merged: ["…"]` line in the engine log, or a merge-failed item — including
   any that passed while you waited. Look again just before you stop. (The log
   sits next to the store; the path below is the default one.)

   ```bash
   tail -n +1 -f ~/.local/state/gear/engine.log    # e.g. merged: ["T-5 @ heat/t5"]
   ```
2. Stop the engine: `gear admin stop` (your own shell)
3. Replace the binary, as above.
4. Install the skill for every CLI in use, as above.
5. Start the engine again with any `gear` call — the captain's `gear` is enough.
6. Your lanes and reviewers keep their tasks. Each agent picks up the new skill
   when it is restarted: the captain restarts a lane between its tasks, never
   mid-task.

What changes on upgrade, without a hand:

- The push allow-list is gone, with the pre-push hooks it installed; a hook left
  in a worktree is removed when that seat comes online.
- A seat sees only the messages addressed to it.
- An agent's claim is checked against its real pane, not against an environment
  variable.
