# v0.3.0 — fit in, and run without hands

M3 of GEAR: a project that already runs can take GEAR on, and from the kickoff
to the landing nobody has to patch the store, repoint a branch, close a pane or
restart the engine by hand. What follows is what a user gets, in plain words.

## Fit in

- **Adoption, as a frame.** `gear --skill adopt` walks the captain through
  taking over a project that already runs: archive the instruction layer the
  agent CLIs load by themselves, name the exemplars and the no-go patterns,
  measure the gate, and decide what to keep, replace or drop — with two
  templates the captain fills in (`gear/adopt.md` for the analysis, and
  `gear/standard.md` for the standard the project then works to).
- **The project's standard travels with the work.** When a project keeps a
  `gear/standard.md`, every task packet carries it, so a lane reads the rules of
  *this* project and not only GEAR's.
- **GitHub, as a window onto the work.** A project can name a `[github]` mode:
  its issues become plan entries (`gear plan import-issues` prints the blocks to
  paste), a task's first delivery opens a draft claim pull request, the hand-in,
  the verdict and the landing are commented on it, and the merge closes the
  issue. The plan and the store stay the one source of truth, and only the
  engine writes.
- **Projects of several repositories.** A project can name child repositories,
  each with its own integration branch and gate; a lane works in one of them.
  Two fixture projects come with the source (`scripts/fixtures/make.sh`) so a
  whole voyage can be tried end to end, offline.

## Push safety

- **A project pushes only where it registered.** At registration GEAR freezes
  each repository's own push destinations (as git resolves them, after your
  `url.*.insteadOf` rewrites). A push anywhere else is refused — never retried,
  never routed around.
- **Every GEAR worktree carries the check.** A lane's, a reviewer's or the
  engine's own push runs GEAR's pre-push check first and then the repository's
  own hook, whichever worktree it is and whatever it pushes. A refused push
  rings the captain once, naming the repository, the destination and the
  command.

## Runs without hands

- **A failed merge is retried, and can be retried.** A merge that failed on
  something that can clear (a push race, a flaky gate) retries by itself; one
  that stays failed is retried with `- remerge T-<n>` under `# Staff` in the
  plan — no follow-up task to write.
- **A failed review is settled in the plan.** A verdict that fails is written
  into the plan's `# Verdicts`, which puts the task back at the head of its lane
  with the exact fix. A reply to the reviewer settles nothing, and the captain
  guide says so.
- **A cancelled task frees its lane.** Cancelling a task closes its open attempt,
  so the lane takes its next task instead of looking busy with work that no
  longer exists.
- **A slow shell no longer parks a lane.** Onboarding waits for the agent's
  prompt and retries, instead of stopping at the first "pane busy".
- **A lane's model is checked against what OpenCode reports.** An empty first
  model list means "not loaded yet", never "no such model" — and a lane is not
  parked for it.
- **Unconfirmed deliveries are not lost.** A delivery the engine could not
  confirm is worked out from the store and the screen instead of being repeated
  or dropped.
- **Codex runs without a hand at its start.** A provider back-off (a 429 it
  retries for minutes) is shown as a back-off, never as a stalled lane; the
  start-up folder-trust and update dialogs are answered by the profile, so no
  seat waits on one.

## Known limits

- **Landing *through* a pull request is not in this release.** `merge = "push"`
  is the landing: the engine merges, the pull request is commented, and the
  issue closes. `merge = "pr"` is refused by the config until the next
  milestone.
- The rest of what is deferred — every built-in agent fully described by its
  profile, the captain's decision record at landing, a cross-CLI hand-over of
  the conversation, and more — is in
  [`ops/plan/m4-backlog.md`](../../ops/plan/m4-backlog.md).
