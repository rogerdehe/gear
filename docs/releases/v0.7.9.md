# GEAR v0.7.9

A Claude captain whose plan limit stopped it is seen on every machine, so GEAR stops ringing it until the reset.

## Fixed

- **The captain's limit stop is read from Claude Code's own session log.** GEAR read a Claude captain's quota only from a `5h N%` segment of the status line, and Claude Code prints that segment only when the machine's own status-line script adds it. On a machine without such a script the limit was never seen: the captain was stopped, but GEAR kept typing doorbells into its pane and dispatching new tasks. Claude Code writes every limit stop in the session log as a record with `quotaLimits.status = "rejected"` and the exact reset time (`resetsAt`). GEAR now reads the end of the captain's session file each round. A rejected record as the last reply pauses doorbells and new tasks until its reset; the captain then gets one "Your quota is back" prompt. The status-line reading stays as a second source.

## Upgrading

Install the new binary (`herdr plugin install rogerdehe/gear --ref v0.7.9`) and reinstall the skill copies (`gear admin install-skill --agent <agent>`): the Claude guide's quota section changed. A running engine restarts itself on the new binary. Nothing to configure.
