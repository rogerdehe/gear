# GEAR v0.6.95

Merges into different feature branches no longer starve each other on the one merge worktree.

Fixed:
- **One waiting member merge kept every other feature's member merge from running** (Lawrence M2, 11:00-11:20Z: F-5's T-94 waits for F-3 members it carries; its worker took the one merge worktree's lock on every tick, so T-105 (F-4) and T-108 (F-1) only ever reported "merge will retry from the remote" and never ran). Each merge worker records the worktrees it holds, and a merge whose worktree is held waits in the queue for that tick instead of failing on the lock; waiting merges keep going last, so the merges that can land run first.

## Upgrading

From 0.6.94: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.95`, then any `gear` call, and restart the engine — the binary changed.
