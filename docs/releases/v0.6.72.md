# GEAR v0.6.72

A landing is complete or it is refused; a finished voyage stays out of a captain's output.

Fixed:
- **The landing order closed itself:** the finished-voyage sweep resolved the voyage's "ready to land" item on the tick it opened, so the captain had nothing to land with. It now stays open until `station <id>: land`.
- **A landing over unmerged work:** `station <id>: land` is refused while a done task's accepted work is not on the integration branch, naming the tasks (a stale `carried-by` kept Prometheus T-588 off dev).
- **A landing left the lanes up:** the landing apply retires every lane and releases every reviewer itself; the skill and the item no longer tell the captain to ask.
- **Leftovers after a landing:** once the voyage has landed, the captain is told of every worktree, `<project>/…` branch and `<project>-…` Herdr workspace still there, until none is left.
- **A finished voyage in every `gear` call:** a captain whose voyage finished sees only its seat and what people sent it: no voyage report, goal, snapshot or engine item. A paused voyage is still shown in full.
- **`gear` before every reply:** the skill told agents to start every turn with `gear`; they now run it when GEAR wakes them, and answer a user message that is not about GEAR directly.
- **Subagents from the captain seat:** the captain skill now names a subagent of the captain's own CLI as an agent outside the plan; captain judgement is done in person.

## Upgrading

From 0.6.71: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.72`, then any `gear` call, and restart the engine — the binary changed. The skill changed: run `gear admin install-skill --agent <cli>` for each agent CLI you use.
