# GEAR v0.7.8

The merge gate runs with the project's dependencies installed, and a Codex seat no longer stops on the hook review.

## Fixed

- **`[conventions] worktree_setup` also runs in the merge worktree, before every gate.** It ran only in the worktrees of lanes and reviewers. The merge worktree held only what git tracks, so a gate that needs installed dependencies failed every merge: a client's five accepted tasks failed in `tsc` because `node_modules` was missing. The setup runs before each gate because a merged commit may change what has to be installed. Make the command cheap when nothing changed, for example `cd web && npm ci --prefer-offline`. A setup that fails is reported as `worktree_setup failed in the merge worktree` and the merge is retried; it is never counted against the work.

- **A Codex seat starts without the "Hooks need review" dialog.** GEAR starts Codex with `--dangerously-bypass-hook-trust` (codex-cli 0.164.0 on), so the hooks of the seat's Codex config run without a trust prompt. Before, a new or changed hook, such as Herdr's agent-state hook after a Herdr update, stopped every Codex seat at start until someone answered the dialog by hand.

## Upgrading

Install the new binary (`herdr plugin install rogerdehe/gear --ref v0.7.8`). Reinstall the skill copies (`gear admin install-skill --agent <agent>`): the Codex guide and the `worktree_setup` line changed. A running engine restarts itself on the new binary. A project whose gate needs installed dependencies sets `worktree_setup` and re-applies its config (`GEAR_ADMIN=1 gear admin init <config>`). Then it retries each failed merge with `- remerge T-<n>` under `# Staff`.
