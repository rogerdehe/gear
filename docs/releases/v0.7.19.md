# GEAR v0.7.19

Between two voyages a project's missing integration branch is no longer an error, and the skill says what to do with work the next voyage needs before it departs.

## Fixed

- **The parallel-changes check reads nothing when no task is left to pair.** A landing deletes the integration branch once its tip is on the release branch, and the next voyage cuts it again at its first worktree. In between, the check failed on every tick with "integration branch … is unavailable". With no task to compare it now stops before reading any branch.

## Skill

- **Work for the next voyage goes on that voyage's branch.** The landing paragraph now says that the integration branch is cut again when the next voyage makes its first worktree. Code that voyage needs, a skeleton included, is its first task. It never goes as a commit on another branch: in a shared repository the mainline can be another project's integration branch. If the code must be there before departure, the captain cuts the branch from the release branch itself, and GEAR keeps an integration branch that holds work of its own.

## Upgrading

Install the new binary (`herdr plugin install rogerdehe/gear --ref v0.7.19`), reinstall the skill and restart the engine. Nothing to configure.
