# GEAR v0.6.73

Every worktree GEAR opens can run the project's setup; the reclaim item names only fresh landings.

Added:
- **`[conventions] worktree_setup`:** a shell command run once in every worktree GEAR opens for a lane or reviewer, before its agent starts, e.g. `worktree_setup = "cd web && npm ci"`. A fresh worktree has only what git tracks, never the installed dependencies (Carthage: a Vitest step could not run without `web/node_modules`). It is marked done in the worktree's git dir, so a restart does not run it again; a failure is printed in the pane and the agent still starts.

Fixed:
- **The reclaim item rang a voyage that landed long ago:** it now names only the leftovers of a voyage landed in the last 24 hours (Lawrence's M1 landed days before and was rung at the 0.6.72 restart).
- **The reclaim item was hidden on a quiet home page:** a captain whose voyage finished sees the reclaim item, the one engine item that still needs it.

## Upgrading

From 0.6.72: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.73`, then any `gear` call, and restart the engine — the binary changed. The skill changed: run `gear admin install-skill --agent <cli>` for each agent CLI you use.
