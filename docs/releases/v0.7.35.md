# GEAR v0.7.35

The board opens at departure by itself; four frictions from the MissHerAI captain are fixed.

## Fixed

- **The board did not open at departure.** Opening it was a line in the skill for the captain to remember, and MissHerAI's M2 departed without it. The `gear plan apply` that departs a voyage now opens that project's board in the captain's workspace, as `gear board --open` does. A board that does not open never undoes the apply; the apply's output names what went wrong.
- **A captain's page named stale skill copies of CLIs the project never starts.** The page now names only the copies of the CLIs the project's captain, lanes, reviewers and model chains start (every copy when the config cannot be read).
- **A refused departure did not say what to write.** The refusal of a departure, a move between milestones or a raise now gives the exact `confirmed:` line to copy, and says that an authorization the user gave earlier counts when the why names where. The departure is still the user's call.
- **The shared-file warning counted paths a goal only mentions.** A path a task's goal names now counts only when it lies in the task's lane's own paths (`owns`): a goal that names another lane's file as a shape to match does not edit it. Evidence files count as before.

## Upgrading

Install the new binary (`herdr plugin install rogerdehe/gear --ref v0.7.35`); the engine restarts on it by itself. Nothing to configure.
