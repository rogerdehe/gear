# GEAR v0.6.66

Two projects on one repository each integrate into a branch of their own.

Changed:
- **Registration refuses a shared integration branch:** a project whose repository another project of the store already integrates into on the same branch is refused, naming that project and branch. Two voyages on one branch cannot be released apart: the branch carries both voyages' unfinished work. The branch name stays the team's (`[conventions] integration`, or `integration` on a `[[repos]]` entry). A project that already shared its branch before this release keeps working; only a new sharing is refused.
- **The gate is told its integration branch:** `$GEAR_GATE_INTEGRATION` names the branch the merge goes into, beside `$GEAR_GATE_PROJECT`, `$GEAR_GATE_ROUND` and `$GEAR_GATE_TASKS`. A CI that compares a candidate with the integration branch reads it there instead of a branch name written into the CI.

## Upgrading

From 0.6.65: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.66`, then any `gear` call, and restart the engine — the binary changed. The skill changed: run `gear admin install-skill --agent <cli>` for each agent CLI you use.
