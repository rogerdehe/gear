# GEAR v0.6.0

M6, the fleet that needs no nursing: a voyage can depart at an agreed time and rest outside working hours, a captain cannot lower the bar on its own, a delivery counts as landed only when the agent took it, a rework's review continues the review it answers, a lane keeps its conversation, and the board and the engine stay near idle.

Changed:
- **T-444 — a reviewer is told when its direction check is closed without its result:** a running job closed with no result sends its reviewer one instruction ("The direction check of T-<n> attempt <n> is closed … Send nothing for it; end your turn"), so it stops checking a job that is gone.
- **T-445 — the board's voyage list shows only voyages a plan described:** a milestone with no done sentence, such as `M1.1-cancelled`, no longer sits next to the real voyages, while an explicitly named milestone still shows.
- **T-446 — two gear-cli tests no longer share a scratch directory:** each has its own tag, so a plain `cargo test` no longer fails on a shared scratch tag.
- **T-447 — a lane onboarding starts on its chain's head is never restarted for a "config change":** onboarding records the restart fingerprint with the model it started, so the seat's generation is not bumped and its `gear` calls do not fail with STALE_GENERATION; a real later change still restarts it.
- **T-448 — a voyage can depart at an agreed time:** with `[schedule] depart_at` the lanes are not started and nothing is delivered before that time, and at it the engine starts them by itself, with nobody asked.
- **T-449 — while a voyage waits for its departure, `gear` and the board say `departs at HH:MM`.**
- **T-450 — working hours:** with `[schedule] hours`, lanes and reviewers are told before the end, parked at the end (agent exits, pane, worktree, branch and session kept), queued merges still run, and come back by themselves at the next start; with `depart_at` and no hours, the end is departure plus the voyage's eta and nothing comes back.
- **T-451 — while the fleet rests outside its working hours, `gear` and the board say `off hours until HH:MM`.**
- **T-452 — the tree stays rustfmt-clean:** `cargo fmt --all --check` runs in `make check` and in `make gate`.
- **T-453 — a delivery counts as landed only when the agent shows it took it:** the attempt's first check-in or the agent's idle-to-busy turn after the text was submitted with an empty composer, within a bounded window, then one resend and a captain item; this covers text left in the composer, a command joined to the packet, a delivery typed into a busy agent, and a fresh Codex conversation that starts empty.
- **T-454 — a notice to a working agent waits for its next idle moment,** so it never interrupts a running command; the direction-check-closed notice is urgent and interrupts the reviewer that still works on that check.
- **T-455 — a review seat is free only when its agent is idle and its last job's verdict or direction result is recorded:** a live review never has its worktree switched under it, and a job that loses its binding is told at once.
- **T-456 — every review and direction packet opens with the seat's binding** (task, attempt, current candidate, branch, worktree) and says which kind of job it is; a hand-in for any other candidate is refused, and a rework round's packet shows the latest applied rework first.
- **T-457 — the codex profile handles Codex 0.165's startup screens:** after `/new` it answers "Where should the new conversation run?" with the current worktree, on a resume it chooses the seat's own directory, Herdr's done/idle on those screens is read as blocked, and slash commands are typed in one go.
- **T-458 — smaller M5 fleet bugs:** a lane that reports blocked gets its next startable task, a held seat may still report a finished hand-in, a repeated confirmed goal/bar/eta change records its second decision, the lost-merge scan runs before the old filters, and the slow-step report includes a failed observation.
- **T-459 — `gear admin init` names each reviewer by its entry's CLI and checks its model against that CLI.**
- **T-460 — `gear queue` and the board name an attempt whose review is in and waits for the captain as "waits for your verdict (M-<id>)",** not only "submitted".
- **T-461 — a captain cannot lower the bar on its own:** the goal, done, bar or eta of a departed milestone, a new departure, and moving a task between milestones need `--confirmed` and a `confirmed:` decision line in the same apply; a cancel line changes only the state; `station <id>: land` is refused while a done clause is open or more than 20 % of the departure's tasks were cut, unless confirmed; the captain writes the goal check, and the voyage report lists every confirmed line, every cut or moved task and each done clause with its evidence.
- **T-463 — an instruction the captain sent while the lane worked on a task does not pin the lane as "helping the captain"** after that task is handed in, so it gets its next packet.
- **T-464 — a seat's model is switched in place when the new model runs on the seat's current CLI:** the engine switches it through the CLI's own model command at the next idle moment, and the agent and its conversation stay, with no handover written.
- **T-466 — captain handover:** on the user's request the outgoing captain writes the handover document from a template GEAR prints (goal, done clauses, bar, eta, state, open threads, the user's standing orders, files to read first); `gear captain take` asks the previous captain for it and, when that captain does not answer in a bounded time, points the new captain at the previous session to read and summarise; `gear captain handover --facts` prints the template's facts.
- **T-480 — a rework's review is a short continuation, not a new review:** attempt n >= 2 starts no direction check; its review goes to the seat that reviewed attempt n-1 and waits for it while it lives; the packet shows the captain's rework and the diff between the two candidates first.
- **T-481 — a lane keeps its conversation from one task to the next:** attempt 1 keeps the same session when the CLI matches (compacting when the context is large), `fresh: <why>` marks unrelated work and opens a new one, and a rework or follow-up that cannot use the earlier session gets one line pointing at it and is marked `new-session recovery`.
- **T-483 — a review of a new attempt can push its review:** when the engine starts the review it points the task's review branch at that attempt's candidate, and a confirmed merge deletes the review branch it merged.

## Skill

- The departure sheet: `gear --skill departure` gives its form (goal, done clauses, bar and eta, scope, stations and tasks, staffing and loads, open points); the captain shows it after the whole plan is written and starts nothing before the user's word.
- The departure sheet is shown only when the captain's own work is done, and open points are the user's decisions only.
- The departure sheet is not the plan: one line per station and seat, no task list.
- The departure sheet is one table, one line per item.
- The captain fixes a few-line block or an urgent fault itself (commit, merge gate, one decision line, release if users wait); at the round cap the captain decides.
- A contract's estimate counts its gate, suite and release-build runs; its acceptance runs every crate that uses the changed code; a new config key is named with its default.
- The skill changes of T-461 (the bar's changes are the user's), T-466 (the handover), T-480 (a re-review continues its own review) and T-481 (a lane keeps its conversation) are described in the task lines above.

## Upgrading

From 0.5.6: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.0`, then any `gear` call. The engine changed, so the restart matters. Nothing in an existing config has to change.
