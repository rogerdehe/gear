# GEAR v0.4.10

The skill review before release (lessons of M4, M4.1 and M4.2, read against the shipped skill). Nothing new in the engine. Every change rewrites an existing line; no rule was added on its own.

Changed:
- **decompose — Independence and balance:** the lanes' startable work (after `deps:`) ends near the same time; when one lane holds most of it, re-split the owned paths for the whole wave, not one task per run-dry.
- **decompose — Reachability:** every function, field, list and test a task names exists — grep each one, and read what a list it feeds into triggers.
- **captain — the plan's `# Queue`:** a decision that changes what the lane builds or what the reviewer checks is a contract rewrite, never only a reply.
- **course — landing:** the voyage report opens with the goal (each clause of `done:` judged with measured evidence), then names every task or item cut or moved out, and where it went.

Fixed (contradictions):
- **conventions:** "one lane per repo" was wrong; a repo may have several lanes, each owning its own paths.
- **README:** the captain registers the project (your confirmed kickoff sheet is the consent), checking the config first with `gear admin init --check`.

Kept in the lessons only (project-specific or not yet recurring): the full build and suite run once in the merge gate; "build it to the prototype" is accepted side by side.

## Upgrading

From 0.4.9: `herdr plugin install rogerdehe/gear --ref v0.4.10`. `gear --skill` prints the new text; the engine is unchanged, so no restart is needed.
