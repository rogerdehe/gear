# GEAR v0.4.3

Lanes follow the work: a lane moves to another repo of the project, changes its agent kind in place, and a task can land through a GitHub pull request.

- **`- rebind <lane> repo=<name> owns=[…]`** under `# Staff`: the lane moves to another repo of a multi-repo project. It waits until its open attempts close (`rebind <lane>: waits for T-a, T-b`), then gets that repo's home worktree through the usual onboarding and a fresh session. Its old tasks still review and merge on their own repo and gate. A move back to a repo the lane used before reopens its checkout. A move whose exit is lost parks the lane in NeedsCheck for a captain retry instead of hanging.
- **A lane's kind changes in place**: at its next safe point the old agent exits and the new kind starts in the same pane and worktree.
- **Landing through a pull request**: with `merge = "pr"` in `[github]` the gate runs as before, the review commits go to the task's pull request head, and the engine asks the forge to merge it (`--match-head-commit`), confirms the merge from the pull request's state, and only then closes the branches. A refused land tells the captain the forge's reason; `- remerge T-n` tries again. A restart or a lost push reply recovers without a second head.

## Upgrading

From 0.4.2: stop the engine (`gear admin stop` in your own terminal), `herdr plugin install rogerdehe/gear --ref v0.4.3`, start the engine with any `gear` call. No store change. For pull request landing set `merge = "pr"` (and optionally `merge_method`) in the project's or the repo's `[github]` section, next to `repo = "owner/name"`, and run `gear admin init gear/gear.toml`.
