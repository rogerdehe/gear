# v0.7.54

## Fixed

- A merge no longer waits for a task whose work landed another way. A
  candidate that carries another task's commits waits for that task to land;
  the engine judged "landed" only by that task's own merge op. A task whose
  own merge failed but whose work landed with a carrier (its attempt carries
  a merge time) was waited for forever: under squash merges its commits
  never become ancestors of the integration branch (alfred M1, 2026-11-19:
  T-35's merge retried "waits for T-34" for 1 h 50 while T-34 had landed
  with T-57). The wait now reads the merge time as well.
- A long merge wait is told. A wait for tasks that have all passed, and
  whose own merges did not fail, was kept quiet as a moment's wait. After 30
  minutes the captain is now told which tasks it waits for and how long.
