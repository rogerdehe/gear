# GEAR v0.6.38

Fixed:
- **A merge that waited for another task runs once that task has landed:** waiting merges went to the back of the queue and were only looked at again when nothing else was ready, so on a busy merge line a merge kept waiting for hours after the task it waited for had merged (Prometheus T-482 behind T-481). Each tick now checks the tasks a waiting merge names, and a merge whose tasks have all landed goes back into the ordinary queue.

Added:
- **A gate may say it could not judge:** a gate that exits 75 (EX_TEMPFAIL), for instance because a CI service refused a request, is retried like a gate whose toolchain is missing, instead of failing the merge. Every other non-zero exit still means the work is refused.

## Upgrading

From 0.6.37: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.38`, then any `gear` call, restart the engine, and install the skill again (`gear admin install-skill --agent <cli>`): it changed.
