# GEAR v0.6.17

Two fixes found while two projects share one Herdr session and one machine.

Changed:
- **A Codex or OpenCode captain is recognized among several:** an agent whose tools run in a shared daemon runs in no pane, and GEAR used to find its pane only when the session held exactly one daemon-kind pane. With two projects in one session (a Codex captain, an OpenCode captain, Codex reviewers) every `gear` answered NOT_REGISTERED. The caller's own daemon session (`CODEX_THREAD_ID`, `OPENCODE_SESSION_ID`) now keeps only panes of its CLI and leaves out panes running another known session.
- **build-slot under Herdr can use a machine wrapper:** with `HERDR_ENV=1` and an executable `~/.config/build-slot/herdr-wrap` on the machine, build-slot runs the command through it. On macOS the wrapper can run commands over `ssh localhost`, whose `sshd-session` is a Developer Tool, so new test binaries skip the first-launch scan that Herdr panes cannot be exempted from (herdr issue #808). Without the wrapper nothing changes. See tools/build-slot/README.md.

## Upgrading

From 0.6.16: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.17`, then any `gear` call, and restart the engine — the binary changed. The skill did not change.
