# GEAR v0.3.1

A fix release for v0.3.0, from the fixture re-run of M3's done sentence (a parent repo with cloned child repos, a lane in a child repo, reviews and merges in the child).

- **A lane with no `[models.switch]` labels starts and stays up.** v0.3.0 derived the labels at the start but looked only in the config when it continued the switch on the next tick, so such a lane went to "needs check" right away. Both paths now use the derived labels.
- **A retried seat never gets shell lines typed into its agent.** When a seat was retried while its agent still ran in the pane, v0.3.0 typed the environment line into the agent's prompt (the agent took it as an instruction) and the start failed with `agent_name_taken`. The engine now asks the agent to exit first and starts only in a shell.
- **An OpenCode lane can call `gear` again** (already in the v0.3.0 tag, listed here for 0.3.0 users who built earlier): OpenCode runs its tools in its own service, outside the pane, and v0.3.0's real-pane check refused every such call.

## Upgrading

From 0.3.0: the steps of [the v0.3.0 guide](v0.3.0.md#upgrading) — stop the engine, replace the binary (`--ref v0.3.1`), install the skill, start the engine again. No store change. A lane stuck in "needs check" with "has no [models.switch] labels any more" comes back with `- retry <lane>` under `# Staff` after the upgrade.
