# GEAR v0.6.4

M6, station S5: a seat that fell back on quota comes back to its first model at the reset, a lane starts its first task from a clean home worktree, and a captain holding several projects sees them all in one page.

Changed:
- **T-486 — a captain that holds several projects sees them all in one `gear` page:** `gear` with no arguments shows every held project — its voyage line, then its inbox, each item line naming the project (`gear M-6741 …`), urgent items of all projects first — and `gear friction`, `gear reply` and `gear --show` accept the qualified ids (`<project>:M-12`, `<project>:T-5`, `<project>:F-1`); with one project the page reads as before.
- **T-487 — one pane with several captain seats gets one doorbell:** the engine joins the items of every seat bound to that pane into one ring, each line naming its project, urgent first, with the same idle and at-once rules — and a project outside its working hours still rings nothing while the others go on.
- **T-491 — a project on v0.5.x upgrades to v0.6 with no hand step:** its store (v0.5.6 schema) migrates when the new engine or any `gear` command first opens it, its v0.5 `gear.toml` loads unchanged, and its running voyage, seats and open items carry on.
- **T-497 — Antigravity CLI (`agy`) starts as a lane or a reviewer:** a built-in `agy` profile starts it unattended, resumes with `--conversation`, and reads agy's own quota, back-off and dialog markers from its screens; `gear admin install-skill` has an agy target and kickoff knows agy's models.
- **T-498 — an agy seat's tokens show:** agy's conversation transcript is read for input, cached and output tokens, so a seat's usage appears on the board instead of as unknown (agy writes no cost, so the price comes from the round's model or the project's `[prices]`, and a session with no transcript stays unknown, never 0).
- **T-499 — a re-review resumes the review it continues:** attempt n's review goes back to the seat that reviewed attempt n-1 and resumes *that* review's own session, so the reviewer still has its earlier findings; when the session cannot be resumed the packet names it and the earlier review file.
- **T-500 — the captain picks a task's review model:** `review-model: <model>` in a queue block, naming an entry of `[models] review` that differs from the task's lane model, sends every review of that task (first and re-review) to that entry and its CLI; a task without the field behaves as before.
- **T-501 — a seat that fell back on quota returns to its first model after that model's reset:** the fallback records the reset of the model it left (the quota source's window, else the reset on screen, else `quota_reset_h`), and once it passes the lane switches back at its next task boundary — never mid-task — by the same switch the fallback used; a source that still reads the window as spent keeps it on the fallback and moves the time, a reviewer takes its next job on the first entry again after the reset, and the return is one event line, `back on <model>: quota reset`.
- **T-502 — on the board's Tasks tab the live tasks stand out:** the stage words of a row are drawn in the stage's own colour and bold for a live stage, a merged row's id, title and time are dim, and a live row keeps its bold id and title — so `working`, `in review` and `reworking` no longer look like `merged`.
- **T-503 — a lane starts its first task from a clean home worktree on the fresh integration branch:** at onboarding a reused worktree is fetched and, if it holds anything, those changes are kept on `gear/archive/<lane>-<time>` (never discarded) and the home branch is put at `<remote>/<integration>`, with one captain item naming the archive branch and the path count; a clean worktree at the tip is left alone, and a git step that fails leaves the tree as it was, names the step and still starts the lane.
- **T-505 — the captain plans a voyage audit as tasks the reviewers run, and a gap they find goes back onto the fix path:** `audit: true` in a queue block makes a task that is never assigned to a lane — once its deps are merged the engine hands it in as a review of the integration branch with an audit packet ("check the promise end to end, name every gap"), a captain pass marks it done and merged at that candidate, and a captain fail sends it back to Ready with no lane rework while the fix tasks added to its deps bring the next attempt.
- **T-492 — end to end: one captain pane, two projects, two time zones:** a test runs both fleets through a simulated day on the fake Herdr — each works only in its hours, both in the overlap, one doorbell names both projects' items, and a reply with a qualified id settles the right project's item.

## Skill

- `decompose.md` rule 3: a lane keeps its conversation from one task to the next, so related tasks of one lane go next to each other; `followup-of: T-<n>` is only for a task that continues an earlier one after other work ran in between, and `fresh: <why>` marks a task unrelated to what the lane just did.
- `decompose.md` rule 7 (T-505): a voyage ends with an audit split by promise — one slice per station promise and per cross-cutting `done:` clause, run end to end in normal use, a gap ruled by a fail verdict plus fix tasks or a pass with `why=` for the backlog.
- `captain.md` queue field list (T-500): `review-model: <model>` picks the entry every review of that task runs on.
- `captain.md` and the agy lines (T-497): `gear admin install-skill` names agy as a target beside the other CLIs.

## Upgrading

From 0.6.3: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.4`, then any `gear` call. The engine changed, so the restart matters. Nothing in an existing config has to change.
