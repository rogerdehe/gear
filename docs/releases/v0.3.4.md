# GEAR v0.3.4

Faster tests, messages that reach a working agent, and no more programs started behind your back.

- **A message reaches a lane while it works.** `gear send --urgent`, and every captain instruction to a lane whose agent queues input while working (pi, Claude Code), is typed into the lane's pane inside the `gear send` call; the engine does not ring the same message again. A Herdr refusal leaves the message stored and the engine rings it later.
- **Delivery never fails on a lost name.** Herdr clears an agent's name when it re-detects the occupant (a server restart, a new session). The engine renames every seat's agent each tick — captain, lanes, reviewers (by their task) — and before every prompt, so a task is never lost on "is not an active named agent".
- **`gear` starts no external program to learn who calls it.** The ancestry check read each parent with `/bin/ps`; it now asks the OS in process. On a busy Mac those `ps` processes piled up behind the system's program check.
- **A held lane can be released from the plan.** `- release <lane>` under `# Staff`: a lane whose agent still runs continues, one whose agent is gone is started again.
- **Tests are much faster.** The merge retry wait is injectable (zero in tests), fixtures are built once, waits are on results instead of sleeps; `[profile.dev]` keeps line tables only, so test binaries are smaller and link faster. `scripts/test.sh` prints the build time, every test's time and a warning for each test over 10 s.

## Upgrading

From 0.3.x: stop the engine (`gear admin stop` in your own terminal), `herdr plugin install rogerdehe/gear --ref v0.3.4`, start the engine with any `gear` call. No store change. A working captain need not restart.

On macOS, if agents build and run many new programs (tests), add the program that starts your Herdr server to System Settings → Privacy & Security → Developer Tools: Herdr for a local session, `/usr/libexec/sshd-keygen-wrapper` and `/usr/libexec/sshd-session` when you reach the machine over SSH. Otherwise every new binary waits for the system's malware check, and a burst of them can stall the machine.
