# GEAR v0.6.94

Work that landed with another task's merge closes its open merge items, and a member of a landed feature is never waited for.

Fixed:
- **A merge-failed or merge-lost item of a task whose work lands with another task stayed open, and a reply could not close it** (Lawrence M2: T-96's M-1062/M-1063, landing with T-107, F-1's new integration task). The lost scan closes both once the task's candidate is on the integration branch.
- **A member of a feature that already landed was still waited for** (Lawrence M2: T-108 merges lawrence/dev, which holds F-2's members since T-97, into F-1). A member whose feature's integration task merged is on the integration branch, so a candidate that carries it is not held.
