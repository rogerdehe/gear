# GEAR v0.3.3

A captain cannot be lost any more.

- **`gear captain take`: start your CLI, run one command, you are the captain.** In any pane of the project's Herdr session, start plain `claude` or `codex` (daemon mode or not, no flags, no environment variables), `cd` into the project and run `gear captain take`. The captain seat moves to that pane at a new generation; the old captain's pane may be gone or still open. One urgent item says which pane took it and which it left. A pane bound to a lane or a reviewer cannot take it.
- **No `GEAR_CTX` needed.** A `gear` call without `GEAR_CTX` finds its seat from the pane it runs in (or, for a CLI whose tools run in a daemon outside the pane, from the one unbound pane of that kind). `GEAR_CTX` still works as an override.
- **A lane registered again reuses its home worktree** instead of failing on "already exists".
- **`scripts/test.sh`** runs the whole suite in parallel, prints every test's time and warns about each test over 10 s (`scripts/slow-tests.allow` lists the exceptions; it is empty).

## Upgrading

From 0.3.x: stop the engine (`gear admin stop` in your own terminal), `herdr plugin install rogerdehe/gear --ref v0.3.3`, start the engine with any `gear` call. No store change. Do not restart a working captain for the upgrade.

A dead captain (its pane gone, or every `gear` call refused on identity): start `codex` or `claude` in a new pane, `cd` into the project, run `gear captain take`, then `gear` must show `captain · generation <n>`.
