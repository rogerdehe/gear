# v0.7.49

## Fixed

- A merge whose gate fails is run once more before the captain is told. A gate
  also fails for what clears by itself on a loaded machine: the gate's database
  in recovery, a suite over its time budget (alfred M1, 2026-11-19: three
  accepted tasks in an hour, each needing a `- remerge`). The engine now queues
  the merge again once per attempt; a gate that fails again opens the
  merge-failed item as before. A conflict or any other failed step is told at
  once, as before.
- A failed merge rings once. The lost-merge scan opened "accepted but not
  merged and nothing will merge it" seconds after the merge-failed item that
  already said so and named the remerge. While a task's merge-failed item is
  open, no lost-merge item is opened for it.
