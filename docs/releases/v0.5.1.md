# GEAR v0.5.1

Station S2 of M5: the small-task procedure (a task the captain marks `mechanical` skips review and the merge gate decides), each role's place in the skill, lanes that count as busy while they help on a captain's instruction, a lane that gives up its agent through a long quota wait and comes back at the reset, and a build that sizes itself to the machine.

Changed:
- **T-272 — a plan task can be marked `mechanical`, with the reason the gate alone proves it:** a queue block carries `mechanical: <reason>`; setting, changing or clearing it opens a new contract version, `gear plan show` prints the reason back, and the lane's packet reads "Review: none — mechanical (<reason>): the merge gate is the only check". A `mechanical` field without a reason is refused.
- **T-273 — a mechanical task merges on its gate alone:** a mechanical hand-in gets no reviewer and no direction check; the engine settles it as a pass with `mechanical: <reason>` as its evidence and tells the captain, so the merge follows as after any pass. A task without `mechanical`, or a mechanical hand-in whose contract changed during the attempt, is reviewed as today.
- **T-275 — each role's place in the skill:** the captain is the brain of the work — it designs, decides, writes every contract so a lane implements it without thinking, writes no product code (a hand fix is only operational, its root fix a task) and keeps its own scripts outside the repository; lanes implement what the packet says without designing; reviewers bring what the lanes built into line with the captain's intent. The captain also decomposes the whole voyage before departure instead of planning in waves.
- **T-323 — a lane that is helping on a captain's instruction is shown as helping:** a lane with no attempt that holds an unanswered instruction (up to 30 minutes) reads "helping <lane>: <words>" on the board and the home page instead of "no current task", and its reply ends it; an older instruction returns the lane to the normal idle rules.
- **T-324 — a helping lane draws no IDLE, run-dry, busy or stall item:** the engine closes the lane's IDLE item and skips the busy and stall checks while the instruction is unanswered, so a lane giving another lane evidence is not woken.
- **T-325 — a kickoff option for a long quota wait:** `[models] on_wait` (`keep` by default, or `release`) says whether a lane parked on a quota wait keeps its agent or gives it up until the reset; the kickoff sheet and the captain's example config carry it.
- **T-326 — `on_wait = "release"` lets a lane leave its agent at a long quota wait:** a lane parked at least 15 minutes has its agent exit while its pane, worktree and session are kept, and the captain is told; a CLI whose sessions cannot be resumed keeps its agent and the line says why.
- **T-327 — a released lane comes back at the reset:** in the same pane and worktree, on the model its chain names, its session resumed, and told to continue its task.
- **T-328 — a tool shell of a daemon proves it is its own seat's session:** a caller whose tools run inside `opencode serve` or a codex session matches its `OPENCODE_SESSION_ID` or `CODEX_THREAD_ID` against the sessions GEAR recorded for the seat, so one OpenCode lane can no longer claim another lane's seat by posing as it; a Codex thread that does not match is reported to the captain.
- **T-338 — the plan's park check reads the quota path's own meta key** (`engine.resume.<seat>`), so a lane parked by a quota is recognised as parked instead of by luck.
- **T-419 — the Makefile's heavy commands size themselves to the machine:** `make check` and both commands of `make gate` run through `tools/build-slot/build-slot.sh`, which divides the free cores among the builds alive on the machine instead of a fixed job count, so a shared machine is neither starved nor wasted.

Also released here, as v0.5.0's notes promised (station S1 tasks merged since):
- **T-400 — changing a lane's model mid-voyage is documented and proven, a held lane included:** a lane that was held comes back on the model the registered config names, since a hold no longer takes it out of the config reconciliation.
- **T-402 — a merged task branch whose only commits past the candidate write the lane's report is deleted without ringing the captain,** since lanes push their report after the hand-in.
- **T-406 — the overrun step examines only the rounds that can still change,** so a tick no longer holds the store for seconds and every multi-tick step finishes in one.
- **T-415 — the board's task totals count only live work:** a cancelled task no longer counts in the done bar, and it stays visible in the Tasks view as today.

## Skill

Nothing: the release review changed nothing in `skills/`.

## Upgrading

From 0.5.0: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.5.1`, then any `gear` call. The engine changed, so the restart matters. Nothing in an existing config has to change: `on_wait` defaults to `"keep"`. A plan may mark a task `mechanical` from now on; a plan without it is reviewed as before.
