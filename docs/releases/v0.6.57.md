# GEAR v0.6.57

Fixed:
- **The merge train comes back after a red streak:** a red batch halves the batch size, and only a batch that landed could grow it again; at size 1 no batch runs, so after a few red rounds every merge ran alone until the engine restarted. A merge that lands alone now doubles the size again, up to `[conventions] merge_batch`.
- **A remerge of work already on the integration branch closes every merge item of the task** (its lost-merge item too).

Changed (skill): after a captain take, the outgoing agent is reached by its pane id, never by the captain's name, which the take moved to the new pane.

Why: Prometheus, 2026-11-04: 23 merges reached dev one at a time while up to ten waited, with `merge_batch = 8`.

## Upgrading

From 0.6.56: `gear admin stop`, install v0.6.57, then any `gear` call, and restart the engine (the binary changed). The skill changed: run `gear admin install-skill --agent <cli>` for each agent CLI you use.
