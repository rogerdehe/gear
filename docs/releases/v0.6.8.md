# GEAR v0.6.8

M6, station S5's speed work, continued: a tick reads only the operations it needs, not the store's whole history.

Changed:
- **T-523 — a tick reads only the ops it needs, not the store's whole history:** the merge step's key scan asked the store for all seven op states every tick — 5900 ops, about 10 MB of payloads, nearly all of them deliveries and doorbells — and kept the few hundred merge ops after parsing each payload, and the lane nudge read every delivery a seat ever had to find one attempt's ops. The store now selects in SQL what the callers filtered in Rust: ops by project and kind with an optional state list, and ops by seat, kind, task and attempt, each with its own index (`operations (project, kind, state)` and `operations (seat, kind, task, attempt)`, added in `schema.sql` and by the 8 → 9 migration, so an existing store gains them on its next open), and the merge keys read only the task and attempt columns instead of the payload.

## Skill

Nothing outside the tasks above.

## Upgrading

From 0.6.7: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.8`, then any `gear` call. The engine and the store's schema changed, so the restart matters; the store is stamped version 9 on its next open. Nothing in an existing config has to change.
