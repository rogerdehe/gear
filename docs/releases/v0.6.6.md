# GEAR v0.6.6

M6, station S5's speed work: the engine reads only the rows it needs, and parses a project's config once per version instead of many times a tick.

Changed:
- **T-517 — the engine reads only the rows it needs:** `operations` gets an index for a project's ops in a state and `messages` one for a project's thread, so the engine's most-called reads (`ops_in_state`, `thread_messages` — merge, feed, mail, names, stall and every tick's op walk) take their rows from the index instead of scanning the whole table, and an existing store gains the indexes on its next open.
- **T-518 — a project's config is parsed once per config version, not many times a tick:** the parsed config is kept in a process-wide cache keyed by the project (and the text it was parsed from), so the many per-tick readers — dispatch's ready tasks and branch names, the stale-item period, the feed, `latest` and every other tick step — share one parse; a changed config is parsed once and replaces the entry, one entry per project.

## Fixed by the captain

- A lane's delivery is no longer held by another task's declared wait: the compaction owed before a delivery used to skip any seat with a task in a wait, so a lane waiting on one task never got the packet of the next task it was given — now only the delivery's own task in a wait holds it.

## Skill

Nothing outside the tasks above.

## Upgrading

From 0.6.5: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.6`, then any `gear` call. The engine changed, so the restart matters. Nothing in an existing config has to change.
