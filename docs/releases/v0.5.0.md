# GEAR v0.5.0

Station S1 of M5: the faults found in real use are fixed, and the conventions become configuration — the remote, the voyage folder, the commit messages and the task cap are the project's, and the engine, the fleet and the board follow them.

Changed:
- **T-257 — the remote and the voyage folder are configuration:** `[conventions] remote` (default `origin`) and `voyage_dir` (default `gear/voyages/{milestone}`) are read everywhere the captain's hints, the plan's paths and the lane packet's `Report:` line are built, so a project keeps one folder per voyage on its own remote.
- **T-258 — a direction check never outlives its attempt's hand-in:** a hand-in closes the job and frees its seat, and a late result goes to the captain instead of an urgent instruction to a lane that already handed in.
- **T-259 — a NeedsCheck reviewer whose agent is gone is released:** a seat whose session resume failed holds no temp slot and asks the captain for nothing.
- **T-260 — the home page shows the lanes a `- tail:` has silenced:** a silenced lane no longer reads as a quiet one.
- **T-261 — init prints the fleet it starts:** `gear admin init` and `--check` list every lane with its kind and model and the reviewer count with its model, so a wrong model shows before the fleet runs.
- **T-262 — the engine uses the project's remote and voyage folder:** every `origin` in the engine comes from `conventions.remote`, and a push that touches only a voyage's `reports/` or `reviews/` starts no direction check.
- **T-263 — the board's friction reports are the measured voyage's:** a finished voyage's reports no longer crowd the Log view.
- **T-264 — a reviewer whose agent died mid-review is freed:** the engine releases the seat and starts the review again, so a dead process no longer needs a captain verdict nobody reviewed.
- **T-265 — `gear admin stop` never cuts a merge in half:** the engine finishes its tick before it leaves and the stop waits for it, so a gate that is running still completes.
- **T-266 — a lane that hands in after a rework is told what to do:** the refusal says a rework is waiting for it and that its packet arrives when its turn ends.
- **T-267 — a reviewer's packet is confirmed by the reviewer's own first `gear`:** a lost packet shows at once and the home page's count of unconfirmed deliveries is true.
- **T-268 — `- remerge` uses the project's review branch:** it expands `conventions.review_branch` and orders merge ops by their numeric id, so a project with its own template remerges the branch it has.
- **T-269 — init refuses a project of another Herdr session:** a config naming a session the caller does not run in fails with the two session names, instead of landing in a store whose engine never reaches the panes.
- **T-270 — no "name is held by another pane" item for a name that frees in the same tick:** seats whose own name is free are renamed before seats named after a task ask for one.
- **T-271 — the home page names the deliveries it counts as not confirmed:** up to three, with their seat, task and age.
- **T-274 — the engine crate's tests are much faster:** 245.6 s down to 157.6 s on this machine, so every review round and every engine task pays less.
- **T-277 — a delivery is confirmed by the lane's own work on it:** the first progress message, question or result for that task and attempt counts as reading the packet, so a lane that skips `gear` is not re-delivered in a new session.
- **T-278 — `gear board` names its Herdr tab:** the tab reads `<project> board` (or `GEAR board`) instead of a number.
- **T-279 — a task is never longer than the project's cap:** `[conventions] max_task_min` (60 minutes by default), and `apply` refuses an estimate above it with the text that says to cut the task.
- **T-280 — a merge that loses the push race goes back to the queue:** a remote that moved under the push merges again from the new tip instead of failing and ringing the captain.
- **T-281 — the overlap check sees every project of the repository:** two fleets editing one file each get their captain an item naming both tasks, instead of a surprise conflict at the merge.
- **T-282 — a reviewer always knows which contract governs:** a direction packet carries the task's current contract, and a review packet whose hand-in predates a newer contract says so.
- **T-283 — a failing direction result on a candidate the lane has moved past goes to the captain,** so a lane is never sent chasing a sha it already fixed.
- **T-284 — a reviewer that stopped mid-review is nudged whatever state its earlier packet op is in.**
- **T-285 — a captain whose agent name another pane holds gets its item,** and an onboarding teardown names an unnamed leftover agent before it prompts it.
- **T-286 — a seat whose CLI is not installed says so at once:** "the <kind> CLI is not installed or not on PATH" as a captain item, and no walk down the model chain.
- **T-287 — the stall item says what to do** when the engine's one restart came back to the same end, instead of asking for the same restart again.
- **T-288 — a lane that stays busy with no task while ready work waits is interrupted after 5 minutes,** so its next packet goes.
- **T-289 — the silent alert fires only for the seat's current work** and never tells the captain to stop an agent by hand.
- **T-290 — a rework packet reaches a lane that queues input while it still works:** the fail verdict interrupts the lane with "end your turn".
- **T-291 — a lane is told when its worktree still holds uncommitted edits:** its new packet names them, so stray edits no longer ride into the next task.
- **T-292 — a lane that works 15 minutes with nothing changing in its worktree is asked to stop thinking.**
- **T-293 — a stuck alert says what it is about, and IDLE says what it means,** so an alert names the fact, the wait and the command to run.
- **T-294 — proof that the engine carries on after its Herdr server goes away and comes back.**
- **T-295 — a live proof through the engine tick that a lane parked on a quota wait resumes its own session at the reset.**
- **T-296 — the engine's merge commit message is the project's template:** `[conventions] merge_message`, the default as before.
- **T-297 — a merge test whose gate handshake never happens fails within a minute** instead of hanging the suite.
- **T-298 — stopping the engine says which projects it pauses,** so a captain restarting for its own upgrade knows what else it interrupts.
- **T-299 — commit messages are configuration:** `merge_message` and `review_message`, their defaults as today, so a team with ticket keys or Conventional Commits gets its own form.
- **T-300 — the reviewer's packet names the commit message the project asks for.**
- **T-301 — a voyage id need not start with `M`,** and the voyage orders sort ids numerically (`M10` no longer before `M9`).
- **T-302 — several fleets on one repository:** two projects can no longer share a voyage folder or take the same GitHub issue label, and init refuses both.
- **T-303 — `- release <reviewer>` takes a reviewer whose agent is gone** even while it holds a task, and a staff line that does nothing says so.
- **T-304 — the lane quota counts the lanes that can run,** so a retired lane no longer takes a slot and a ready task wakes one.
- **T-305 — a rebind says what it changes:** a pending one can be withdrawn, an applied one says how to undo it, and the captain's guide says to rebind an idle lane.
- **T-306 — `- remerge` of a candidate already on the integration branch queues nothing** and settles its failed-merge item.
- **T-307 — an OpenCode catalogue that cannot be read is not reported as "model absent":** it says the catalogue could not be read.
- **T-308 — a reset time read from a provider's own limit text** gives providers GEAR has no quota reader for a real reset instead of a fixed window.
- **T-309 — a lane parked on a provider limit wakes at the reset its own screen states,** not after the fixed `quota_reset_h`.
- **T-310 — the board's PTY test waits on the descriptor, not on the clock,** so it cannot fail on a slow machine.
- **T-311 — moving a running task to another lane in the plan moves its work:** the open attempt goes with it and the old lane stops working on it.
- **T-312 — a rework round's budget grows with the blocking findings it carries,** so a rework of nine findings is not timed like one.
- **T-313 — a plan may say `# Voyage`,** one word for the same thing the skill and the home page call a voyage.
- **T-314 — the identity refusal names the Herdr socket it asked and the ancestry it saw,** so a refusal can be traced afterwards.
- **T-315 — init and `--check` warn when a configured model id is not one its CLI lists,** instead of leaving the seat to be pinned at its first round.
- **T-316 — a test fixture never registers into the user's store:** the live acceptance tests use their own scratch store.
- **T-317 — a board opened without a project shows the session's projects one at a time** with a key to switch.
- **T-318 — a source checkout has an install step:** `make install` links `gear` into `~/.local/bin` as a link, so every release build is what the agents run.
- **T-319 — the captain's doorbell and its home page list the same open items,** proven with more items than one batch holds.

- **T-371 — a delivery whose text sits unsent in the agent's input box gets its Enter,** so a lane no longer idles with its packet typed and unread.
- **T-372 — init refuses a seat branch that collides with a task or review branch as git refs** (a ref and a directory of one name cannot both exist) and says how to give the seats their own folder.

## Upgrading

From 0.4.10: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.5.0`, then any `gear` call. The engine changed, so the restart matters. Nothing in an existing config has to change: `remote` defaults to `origin`, `voyage_dir` to `gear/voyages/{milestone}`, `max_task_min` to 60, and `merge_message` and `review_message` to the texts the engine and the reviewers used before. A voyage's plan, reports and reviews now live in its own folder — `gear/voyages/{milestone}/plan.md`, `/reports` and `/reviews` by default — and the captain's hints and the lanes' packets name those paths; a project moves its existing voyage files there, or sets `voyage_dir` to another template with `{milestone}` in it.
