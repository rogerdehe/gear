# GEAR v0.6.11

M6, station S5's speed work, continued: a tick reads the live work, not the whole history.

Changed:
- **T-529 — a tick reads the live work, not the whole history:** with every task of a project done, a running engine still spent about 12 % of one core reading all 528 tasks of six voyages every tick — for the dispatch step's ready tasks and lane view, for the board's idle view the engine calls each tick, for `merged_at` on each of them, and for the rounds and attempts the rounds and busy steps walk. The store now has the reads those callers keep: the tasks that are not terminal plus the tasks of a voyage that still has one, the rounds with no end, and the ended rounds whose usage is still unknown (up to the back-off's last mark); each is index-served (`tasks (project, state)`, `tasks (project, milestone, state)` and `rounds (project, end_at)`, added in `schema.sql` and by the 9 → 10 migration, so an existing store gains them on its next open). A landed voyage's tasks are read only where a report asks for them, and the decisions are the same as before.

## Skill

Nothing outside the tasks above.

## Upgrading

From 0.6.10: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.11`, then any `gear` call. The engine and the store's schema changed, so the restart matters; the store is stamped version 10 on its next open. Nothing in an existing config has to change.
