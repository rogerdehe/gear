# GEAR v0.7.14

A landing's reclaim never removes a worktree it was told to keep, a voyage departs from the latest release, and the departure sheet's table reads cleanly in a terminal.

## Fixed

- **The departure sheet's table no longer repeats its title or wraps into blank rows.** The template put the title in the table's header cell, and long Goal and Done-when cells made the table wider than the window. A terminal shows such a table as one card per row, each prefixed with the header, and captains split long cells into rows with an empty first cell. The title is now a bold line above the table, and the header is `| Item | Value |`. Each done clause, station and lane gets its own row, every value cell stays within 60 columns (a CJK character counts as two), and a row never has an empty first cell.
- **The reclaim never removes a worktree it leaves.** After a landing, a worktree with uncommitted changes or unpushed commits is left and named. But the reclaim then closed the Herdr workspace of that worktree, and closing it removed the worktree, changes and all. A client lost the next voyage's captain worktree (its config and plan) right after departing; only a push saved the work. A worktree the reclaim leaves now keeps its workspace.

- **A voyage departs from the latest release.** `gear admin init` created the integration branch from the release branch only when it was missing. An integration branch left at the last landing stayed there while the release branch moved on, and the next voyage's lanes started from an old commit. Now an integration branch that is behind the release branch, with no work of its own, moves forward to it. One with work of its own is left as it is.

## Upgrading

Install the new binary (`herdr plugin install rogerdehe/gear --ref v0.7.14`) and reinstall the skill copies (`gear admin install-skill --agent <agent>`): the departure guide changed. Nothing to configure.
