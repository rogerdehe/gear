# GEAR v0.6.30

Added:
- **The merge train (`[conventions] merge_parallel`, default 1):** with a value above 1, merges into the same integration branch gate side by side. Each merge is built on the commit the merge ahead of it will land, so every gate checks the branch exactly as it will be; they land in that order, each a fast-forward of the one before. A gate that says no fails its merge as it would alone, and the merges behind it go back to the queue and gate again from the new tip. A merge that cannot be built (a conflict) steps aside and the next one is built in its place. A reason that can clear stops the train, and the next merge of that branch runs alone with its bounded retries. Each stage has its own worktree (`<project>-merge-2`, `-3`, …). Pull-request mode still lands one merge at a time. With the default 1 nothing changes.

## Upgrading

From 0.6.29: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.30`, then any `gear` call, and restart the engine — the binary changed. The skill changed: run `gear admin install-skill --agent <cli>` for each agent CLI you use. To use the train, set `merge_parallel` in the project's `[conventions]` and re-apply the config.
