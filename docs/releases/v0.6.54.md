# GEAR v0.6.54

Fixed:
- **The board says merged only when the work is on the integration branch:** a done task shows as merged only once one of its attempts has landed; an accepted task whose merge has not landed shows as passed, merging, or merge failed (waiting for the captain), from its newest merge. The words name the project's own integration branch (`on dev`, `passed, not on main yet`), and the header counts the tasks on it and the passed ones not on it yet. The board called 58 accepted tasks merged while their work was not on the integration branch.

Changed (skill):
- **Lane and reviewer checks stay light:** a packet is 15–30 minutes of work, so a check of 5–10 minutes is a fifth to a third of the round. A lane or reviewer checks what its task changed; the whole suite runs once, at merge. The captain skill says never to put the merge gate or a whole-suite run into an `accept`, a rework note or a verdict; a project whose own rule is a full run on every hand-in keeps it.
- **Friction names heavy checks:** lanes and reviewers add `--friction` when the checks the captain asked for took a fifth of the round or more, with the checks and their minutes; the captain trims them.

Why: the user saw two full CI rounds at once on SelyraAI: a rework note told a lane to run the whole merge gate before handing in, while the merge batch ran it again; and the board did not match what was on dev (2026-11-04).

## Upgrading

From 0.6.53: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.54`, then any `gear` call, and restart the engine — the binary changed. The skill changed: run `gear admin install-skill --agent <cli>` for each agent CLI you use. Nothing to set.
