# GEAR v0.6.56

Fixed:
- **A stalled voyage rings the captain:** when no lane can start anything while the open voyage still has tasks left, one urgent `stalled` item names the voyage, how many tasks are left and what each of the first ones waits for. It stays open while the state lasts and closes when a task can start again (T-560).
- **A retired reviewer leaves no agent behind, and an outage retires none:** a review seat retired for failed checkouts has its pane closed like a released seat, so the reviewer count matches the quota. A checkout that failed because the remote could not be reached is retried instead of retiring the seat (T-561).
- **The board and the queue say what a task waits for:** "waits for T-563, T-665 to merge" names only the deps not merged yet ("waits for 5 of 47 to merge" when there are many), and a lane's next task is the first whose deps are all merged (T-562).
- **A task on a retired lane is named:** `gear plan apply` warns about each open task on a lane with no working seat, the board says `retired: T-a, T-b are on it and will not start`, and a failed gate's item leads with the gate's own refusal (T-563).
- **The merge never publishes a lane commit nobody reviewed:** on the task-branch path the merge refuses when the task branch holds commits after the approved candidate that are not the review's, naming them ("a change after hand-in needs a new attempt"). Commits of the integration branch merged into the task branch to fix a conflict are not counted, so the documented conflict fix (merge the integration branch into the task branch, resolve, push, `- remerge`) still works (T-564).
- **A changed default seat branch moves the seat branches:** a project that sets no `seat_branch` gets its seat worktrees moved from the previous default `{project}/{seat}` to `{project}/{seat}/home` when the engine starts or onboards a seat, merge seats included, so `gear/merge` no longer blocks `gear/merge/home`. A ref of another name in the way is named and left alone (T-565).
- **One merge-wait cause rings one item:** a merge that waits on the same cause keeps one item per project and cause (`merge-wait:<project>:worktree`), updated while it lasts and closed when the next merge starts, instead of one item per retry (T-566).
- **The board's time line shows no impossible forecast:** a lane that can never finish is left out of "expected", and the line names what blocks it: `blocked: T-570 waits for T-665, which nothing will merge` (T-567).
- **A remerge of work already on the integration branch closes every merge item of the task:** its lost-merge item too, not only the failed-merge one.

Why: Prometheus sat stopped for two hours with nothing ringing, the board read "expected 16716h", GEAR's own merges waited on a seat branch the new default never moved, and one worktree failure rang 47 items (2026-11-04).

## Upgrading

From 0.6.55: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.56`, then any `gear` call, and restart the engine (the binary changed). The skill did not change. A project on the default seat branch needs no step: the engine moves its seat branches at start.
