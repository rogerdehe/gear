# v0.7.53

## Fixed

- A feature member's merge runs beside the train again. A member planned
  since v6 carries its repo as well as its base, and the check that tells a
  feature merge from an ordinary one compared the base with itself, so every
  member's merge was taken for an ordinary one: it queued for the
  integration worktree and waited behind whatever train held it (alfred M1,
  2026-11-19: T-49 waited 25 minutes behind a running integration merge
  while its sibling T-52 and its lane sat idle). The check now reads the
  repo's own integration branch from the config, and a member merges in the
  feature's own worktree.
- An audit's verdict tells the captain once. The attempt stays handed in
  until the captain rules, and every tick wrote the same "audit review is
  in" line again (alfred M1: eleven lines in a minute for T-30).
