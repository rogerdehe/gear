# GEAR v0.6.90

A lane's conversation is compacted only when it has used half a window GEAR knows.

Fixed:
- **A model entry with no `context_window_k` compacted its lane before every new task** (Lawrence M2: at 9-22 % of a 500k-1M window), and so did a context GEAR could not read. The window is now the config's, else the one the CLI itself keeps: pi's `~/.pi/agent/models.json` (`contextWindow`), Codex's rollout (`model_context_window`), OpenCode's `opencode.json` (`limit.context`), Claude's model name (`[1m]` is 1M, else 200k). A window or a context that cannot be read keeps the session; a lane continuing related work keeps its conversation, an unrelated task (`fresh:`) starts a new one.

## Upgrading

From 0.6.89: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.90`, then any `gear` call, and restart the engine — the binary changed.
