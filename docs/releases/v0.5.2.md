# GEAR v0.5.2

Station S3 of M5: a departed voyage's goal and staffing change only with the user's yes, a hand-in names a commit, and the review queue serves the oldest hand-in first without losing or releasing a reviewer that is still needed. The board's header and Now view are the prototype's.

Changed:
- **T-331 — a departed voyage's title and stations change only with the user's words:** a re-plan that changes them is refused with GOAL_LOCKED unless the user asked for it and the change is confirmed, the way `done:`, `bar:` and `eta:` already were; a confirmed change is applied and recorded.
- **T-333 — a voyage file carries the `# Milestone` block of every milestone its tasks name:** a plan whose task names a milestone with no block is refused, and applying the plan writes the stored words back into the file when the block is missing.
- **T-335 — every goal change is in the board's model and in the voyage report:** each confirmed change of a departed voyage's goal is a starred decision with before and after, so the board can draw it in red and the voyage report lists it.
- **T-421 — a hand-in names a commit, never a branch:** a candidate that is a branch name is refused, so a second attempt on the same branch is judged on its own commit instead of being refused as "already failed".
- **T-422 — the merge gate takes at least 4 jobs:** the gate is the one run every task waits on, so it no longer shares the machine's cores as an equal with every other build; its suite runs the same on an idle machine and finishes in minutes when the machine is busy.
- **T-423 — a seat never resumes a conversation another live pane holds:** a resume of a session that another live pane still has open is refused by the CLI and left the seat locked; the engine now finds the session closed first and starts the seat clean, so a seat is never started into a conversation another pane holds.
- **T-424 — a standby reviewer is never released while a hand-in waits for a reviewer:** a reviewer that went Standby with a review waiting for it was released as surplus and cold-started again for the next review; it now counts as holding a job, so a long queue of hand-ins no longer restarts its reviewers all day.
- **T-426 — a reviewer that quits its agent to resume an earlier conversation is not released as "agent gone":** a seat in the middle of a session switch is no longer released and started cold before its agent can show up.
- **T-427 — hand-ins get their reviewers oldest first:** a hand-in is reviewed in the order it was handed in, not by where it stands in the plan, so a queue of twenty-six no longer serves the newest first.
- **T-428 — a plan never leaves a task depending on a cancelled one:** an apply that would leave a live task depending on a cancelled task fails with "`<id>` depends on cancelled `<dep>`", naming every such pair, instead of leaving a task that is never delivered.
- **T-429 — a review chain change reaches the warm reviewers:** a captain that changes `[models].review` sees the reviewers switch on the next review, instead of every warm seat keeping the model it started on.
- **T-430 — the eta is among the changes a captain confirms with the user:** the skill's step 6 names it next to the goal, the bar and the staffing.
- **T-431 — one unresolvable candidate no longer stops the overlap scan:** a task whose stored candidate git cannot resolve is skipped, so the scan for the whole project keeps running instead of failing on every pass for hours.
- **T-432 — a Standby reviewer stuck in a conversation switch is released after a bounded wait:** a seat reserved for a review with no agent in its pane and a session step that never advances is released after a bounded wait, so the hand-in it was reserved for gets a reviewer.

Also released here, as v0.5.1's notes promised (earlier stations' tasks merged since):
- **T-380 — the review packet names the diff against the remote integration branch,** not the reviewer's local copy of it, so a reviewer diffs once instead of fetching and re-diffing by hand.
- **T-386 — the engine says what each tick costs and reads its branches with one git call per repository:** a tick runs one `git` process per repository instead of one per started attempt and per lane, and the tick's cost is in the log.
- **T-420 — every seat GEAR starts gets its own TMPDIR,** not only a lane's first start: reviewers and restarts too.
- **T-407 — the engine logs how long its multi-step operations take:** one probe line per finished operation and per step, through the tick log, so a slow session switch, delivery, restart or merge is found from the log.

S4's board work, merged early and so in this release (the rest of S4 makes v0.5.3):
- **T-350 — the board can be built for any voyage of the project and shows that voyage only,** a landed voyage keeping its data ("retired at the landing") instead of "time unknown" and empty lanes.
- **T-351 — a task moved to another voyage is recorded in the voyage it left,** so that voyage's board can name it as "moved out: T-n" without counting it.
- **T-352 — the golden fixture carries the prototype's stations,** so the board's model shows the stations the header draws.
- **T-353 — the head of the board is the prototype's:** the voyages on the first line, the picked voyage named on the second, and the goal in a yellow bold box with the quality bar.
- **T-354 — the folded header gives the goal check, the current milestone, the time against the plan and the tasks in three rows with bold labels,** and `d` unfolds it.
- **T-355 — `d` unfolds every clause, every milestone, the time in words and the legends.**
- **T-356 — the views are a tab bar that looks like one:** framed, each tab separated, the picked one lit, and a view starts where the prototype's does.
- **T-357 — the user picks the voyage the whole board shows with `[` and `]` or a click on the first line,** the selection going back to the stored one.
- **T-358 — a red line under the goal box says when the voyage's goal was changed with the user's yes, before and after.**
- **T-359 — the Now view is one table, one row per lane:** what it does, its stage, its time, its progress and when it ends, with one line on whether the work is balanced.
- **T-360 — under the lanes the Now view lists what to handle, each item with who acts, and the quota on one line,** so a merged overrun or a rework no longer crowds the open tasks.
- **T-362 — the Tasks view paints the git graph** the prototype draws, in place of M4's dev / rev / lane-dot layout.
- **T-363 — Cost (was Time & tokens) is one row per lane with development and review apart,** and Enter on a lane shows its tasks; a flat list of every task is gone.
- **T-364 — Log (was Decisions) starts with what changed the course,** then every decision and the friction reports, instead of the wall of text M4's Decisions view was.

M5 tasks not merged when this note was written, so v0.5.3's notes: T-365, T-425; T-332 and T-396 are cancelled.

## Skill

The skill changed only through T-424 (reviewers follow the reviews waiting: no standby reviewer is released while a hand-in waits) and T-430 (the eta is among the changes a captain confirms with the user); the release review found nothing else that recurs for other captains.

## Upgrading

From 0.5.1: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.5.2`, then any `gear` call. The engine changed, so the restart matters. Nothing in an existing config has to change.
