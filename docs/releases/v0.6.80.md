# GEAR v0.6.80

Feature integration, stage 1: the small tasks of one capability merge into the feature's own branch with no CI, and the feature reaches the integration branch once, with one review and the full gate.

Added:
- **`feature: F-<n>`** on a queue block makes the task a member of feature F-n. A member starts from the feature branch (`[conventions] feature_branch`, default `{project}/feature/{feature}`, created from the integration branch when missing) and merges into it with a conflict check and the optional `[conventions] feature_check` command, no full gate. Deps between members release on that merge. At most `[conventions] feature_max_tasks` members (default 10).
- **The feature's integration task** is created by plan apply: its deps are the members, its lane the lane holding most of them, its candidate the feature branch tip, handed in by GEAR once every member has merged. It gets one review and the full gate, then merges the feature branch into the integration branch. Members share one `issue:`, which moves to the integration task.
- **A landing merges the captain's records:** the captain's seat branch of the landed voyage is merged into the integration branch and deleted; a conflict opens one item and keeps the branch.

Fixed:
- **The current voyage follows open work:** a voyage that departed earlier but still has open tasks is the current one (home page, doorbell, take, release); before, the last departure won even when it had finished.
- **The stalled-lane nudge** named a hand-in kind that does not exist; it now says `--kind result`.

A project with no `feature:` line runs exactly as before.

## Upgrading

From 0.6.79: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.80`, then any `gear` call, and restart the engine — the binary changed.
