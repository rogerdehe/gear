# GEAR v0.6.2

M6, station S3: a captain pane holds the captain seats of several projects and the board and the `gear` page follow the project a captain picks; the fleet watches its own machines; task and direction branches are cleaned up when their work lands; omp (oh-my-pi) joins the CLIs GEAR drives; and a reviewer's agent carries its seat name.

Changed:
- **T-482 — a reviewer's agent is named after its seat:** a reviewer's Herdr agent is `<project>-review-<k>` with the task in its title, and keeps the name across tasks, so the panes and the board name a reviewer the same way for every job it takes.
- **T-485 — one captain pane holds the captain seats of several projects:** `gear captain take <project> [<project>...]` binds each named project's captain seat to the caller's pane and keeps the seats it already holds, `gear captain release <project>` lets one go; every project keeps its own fleet, plan, voyage, departure sheet and seats, and a captain command acts on a project named by a qualified id (`<project>:M-12`, `<project>:T-5`), the plan file's header or `--project`.
- **T-490 — the captain skill covers several projects:** `skills/gear/references/captain.md` gains a paragraph on taking a second project from the same pane, each project's own kickoff and departure sheet, doorbells naming the project, and urgent items first and then the project whose station is nearer its eta; `departure.md` says the sheet's title names the project.
- **T-474 — branch hygiene and coverage:** a cancelled task's branch is deleted; a merged task's branch is deleted even when its tip moved past the merged candidate (its extra commits are listed to the captain first); `gear report coverage` lists accepted attempts not on the integration branch; a direction branch's name comes from a conventions template (default `{project}/direction/{task}`) and is deleted, local and on the remote, when its job closes; a task moved to another lane has every branch its template gives for any lane that held it deleted when it is an ancestor of the integration branch, and listed otherwise.
- **T-495 — omp (oh-my-pi) starts as a lane or a reviewer like the other CLIs GEAR knows:** a built-in `omp` profile (unattended `--auto-approve`, the rules through `--append-system-prompt`, `/quit`, its quota, rate-limit, back-off and error signs), `gear admin install-skill --agent omp` writing into `~/.omp/agent/skills`, and kickoff listing omp with its models.
- **T-472 — fleet and machine health watch, costing almost nothing:** the CPU and memory of each seat's own processes (children included) and the machine's load, memory and disk are sampled each minute; a seat over the safe line is interrupted and stopped and the captain is told; a machine short for other reasons is an urgent captain item naming the top processes (never touched).

## Upgrading

From 0.6.1: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.2`, then any `gear` call. The engine changed, so the restart matters. Nothing in an existing config has to change.
