# GEAR v0.6.55

Changed:
- **A review leaves no branch of its own on the remote:** the reviewer still works on a local review branch in its own worktree, but pushes its review commit onto the task's branch (`git push <remote> HEAD:refs/heads/<task branch>`; when the lane pushed meanwhile, `git pull --no-rebase` and push again). The verdict is refused until the task branch holds the reviewer's commit. The engine no longer pushes a review branch when a review starts, and the merge takes the task branch, checking that it still holds the approved candidate. A Rework or Resume text now tells the lane to pull its branch after switching to it, since the review commit is on it.

Upgrading in flight: a task whose old review branch is still on the remote merges from it as before, and that branch is deleted after the merge. A reviewer that started before the upgrade and pushed to the old review branch is refused at hand-in and told to push to the task branch.

Why: every review left one more branch on the remote while the review never changes the code (user, 2026-11-04).

## Upgrading

From 0.6.54: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.55`, then any `gear` call, and restart the engine — the binary changed. The skill changed: run `gear admin install-skill --agent <cli>` for each agent CLI you use. Nothing to set.
