# GEAR v0.6.55

Changed:
- **A seat's own branch is named project / seat / home:** `[conventions] seat_branch` defaults to `{project}/{seat}/home` (it was `{project}/{seat}`), so `prometheus/web/home` reads like a task's `prometheus/web/t675` instead of `prometheus/home/web`, and a seat branch sits beside its lane's task branches rather than above them. A project that re-applies a config with a changed `seat_branch` types nothing: GEAR renames the branch of every seat worktree that stands on the old name inside that worktree (`git branch -m`), and when the old name was pushed, pushes the new one and deletes the old. The apply lists what it moved, and names a seat whose worktree is on another branch — it is left alone.

Fixed:
- **A review leaves no branch of its own on the remote:** the reviewer still works on its review branch locally, but pushes its commits to the task's own branch (`git push origin HEAD:<task branch>`, a plain merge and a second push if the lane pushed meanwhile), and the merge takes the task branch. A task already in review whose old review branch is still on the remote merges that branch exactly as before, so nothing in flight is stranded; the branch sweep and the post-merge cleanup still delete an old review branch when one is there.

Why: the user read `prometheus/home/captain` backwards and asked for the shape a task has, and one extra remote branch per review was clutter (2026-11-04).

## Upgrading

From 0.6.54: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.55`, then any `gear` call, and restart the engine — the binary changed. The skill changed: run `gear admin install-skill --agent <cli>` for each agent CLI you use. A project that set `seat_branch = "{project}/home/{seat}"` or its own `review_branch` explicitly changes or deletes those lines and re-applies its config (`gear admin init <config>`): the seat-branch change moves each seat worktree's branch by itself, and the default seat branch and review branch need no line at all.
