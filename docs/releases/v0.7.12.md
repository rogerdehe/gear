# GEAR v0.7.12

A Codex seat no longer starts with `--dangerously-bypass-hook-trust`, and an OpenCode seat's bare `gear` finds its seat.

## Fixed

- **Codex seats start without the hook-trust flag.** v0.7.8 started every Codex seat with `--dangerously-bypass-hook-trust` to skip the "Hooks need review" dialog. On a client's codex-cli 0.167.0, every start with that flag asked for a new login, so no Codex seat could work. GEAR now starts Codex without it and answers the dialog with `Trust all and continue`. Codex records that trust in its config, so the dialog comes back only when a hook changes.
- **A bare `gear` from an OpenCode seat finds its seat.** OpenCode runs a seat's commands in its shared `opencode serve` process, outside the seat's pane, so GEAR could not tell which pane called and refused every bare `gear`. Only `gear --session <s> --pane <p>` worked, and a lane that forgot the arguments was refused again and again (a client saw it twice in one voyage). Each such command carries `OPENCODE_SESSION_ID`, and GEAR records the OpenCode session of every seat it starts. A bare `gear` now finds the one seat with that session among the stores on the machine and runs as if it had named its session and pane. The full form still works.

## Upgrading

Install the new binary (`herdr plugin install rogerdehe/gear --ref v0.7.12`) and reinstall the skill copies (`gear admin install-skill --agent <agent>`): the Codex guide changed. A running engine restarts itself on the new binary. A Codex seat already running keeps its start flags until it restarts; restart the seats that ask for a login. Nothing to configure.
