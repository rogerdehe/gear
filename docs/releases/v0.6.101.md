# GEAR v0.6.101

Work that landed with another merge reads as landed everywhere, and the board puts a landed feature's members on the integration branch.

Fixed:
- **An integration task a newer one superseded stayed "merge failed, waits for the captain" after its work landed** (Lawrence M2: T-96 and T-107 landed with T-112, T-98 with T-115). The lost scan marks a done task's attempt merged once its candidate is on the integration branch, so the board, the landing and the forecast read it as landed; its open merge items close as before. No `integrated-by` verdict is needed.
- **The board's branch column put the members of a landed feature on the feature branch** (Lawrence M2: T-106, T-108 and others read "on lawrence/feature/f-1" after F-1 landed). A member of a feature whose integration task merged reads as on the integration branch.

## Upgrading

From 0.6.100: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.101`, then any `gear` call, and restart the engine — the binary changed. Restart a running `gear board` to see the branch column change.
