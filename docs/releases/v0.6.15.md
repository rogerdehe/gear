# GEAR v0.6.15

M6.2, a smooth captain handover: what the first real handover between two CLIs (Codex to Claude) exposed.

Changed:
- **The new captain learns it from GEAR alone:** `gear captain handover --pane <id>` now does what `gear captain take` does after the rebind: the captain's agent name moves to the new pane and leaves the old one, and the new captain gets one urgent item naming the handover document with its branch and commit (a document on a notes branch is found). The doorbell wakes it; nobody needs to prompt it by hand.
- **`gear captain handover --facts` is short and true:** a retired lane is one line, a lane's owned paths are a count and the first three; with no version tags it names the release branch's tip instead of "none"; an older handover request is no longer printed as an instruction; the plan file is named clean, draft or STALE (a stale file must not be applied); another project's captain is reached with `herdr --session <session> agent prompt <project>-captain`, never `gear captain take`.
- **A checkout of no registered project** says so and lists the registered projects with their checkouts.
- **Skill (captain.md):** a captain-only registration (`quota.lanes = 0`, no `[[lanes]]`) holds the captain seat while a voyage is still planned; after `handover --pane`, do not prompt the new captain yourself.

## Upgrading

From 0.6.14: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.15`, then any `gear` call, and restart the engine — the binary changed. The skill changed: run `gear admin install-skill --agent <cli>` for each agent CLI you use.
