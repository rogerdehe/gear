# GEAR v0.6.47

Fixed:
- **Accepted work that never landed is reported, urgently:** the lost-work scan skipped a carried task while its carrier was unmerged, even when the carrier's merge had failed or was not queued, and it skipped a task whose failed-merge item was still open. 63 accepted tasks of one session sat off the integration branch for hours, under-reported. Now a carried task waits only while its carrier's merge is queued or running; an open failed-merge item no longer counts as settled; and the lost-work item is urgent, so it rings at once.
- **A paused project still records a merge that was already running:** `gear admin pause` skipped the project entirely, so a merge that landed during the pause stayed `executing` in the store. The engine now collects a paused project's finished merge; it still starts nothing new for it.

## Upgrading

From 0.6.46: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.47`, then any `gear` call, and restart the engine. The skill did not change.
