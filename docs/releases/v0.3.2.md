# GEAR v0.3.2

pi lanes, and fixes from the second batch of trial feedback.

- **pi can run a lane.** `kind = "pi"` in a lane (or a chain entry with `cli = "pi"`). The engine starts `pi --model <provider>/<id>` (plus the entry's args, e.g. `--thinking high`) in the lane's worktree. On a quota stop it exits pi and starts it again on the next chain model, then delivers the lane's task again. `gear admin install-skill --agent pi` installs the skill in `~/.pi/agent/skills/gear/`, and `gear --skill agent:pi` prints how GEAR drives pi. When pi's guardrails refuse an action, the captain gets an item.
- **Codex's spent-limit screen is a quota stop.** "You've hit your usage limit" and "Usage limit reached" are no longer mistaken for an idle reviewer; the "only N% left" warning is still not a stop. Known gap: the engine does not yet move a spent reviewer to the next `models.review` entry. That is coming in M4. Until then, a review on a spent Codex waits for its reset.
- **A dead reviewer seat frees its slot.** A reviewer seat with no reviewer running is released, and temps in use never exceed `[quota].temps`. A worktree reply from Herdr without a `branch` is read as detached, so the seat no longer gets stuck in "unknown".
- **A rework packet leads with this round's rework.** `gear --show T-n` after a fail opens with the captain's rework text; older reviews follow as history. A lane can no longer hand in the candidate that already failed.
- **A reply never rings its own sender.** The captain answering its own item gets no doorbell.
- **The captain hears it once when every lane is in the tail** while required tasks remain.
- **A lane registered again reopens its worktree** instead of failing on "already exists".

## Upgrading

From 0.3.0 or 0.3.1: follow [the v0.3.0 guide](v0.3.0.md#upgrading): stop the engine, replace the binary (`--ref v0.3.2`), install the skill (add `--agent pi` if you use pi), and start the engine again.
