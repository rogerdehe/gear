# GEAR v0.6.91

A feature member's merge no longer waits forever for work that already landed, and the board never prints a blocked lane as thousands of hours.

Fixed:
- **A feature member that carried an already merged task waited for it forever** (Lawrence M2: T-65 and T-66 carried T-63, merged into `lawrence/dev` after `lawrence/feature/f-1` was cut; the merge said nothing and showed "merging" for half an hour, and its worker held the merge worktree so F-2's members got "merge will retry from the remote"). A task whose merge landed on the integration branch is no longer waited for: the candidate that carries it merges its commits with it. A feature member that landed only on its own feature's branch is still waited for.
- **The board forecast printed a dependency nothing merges as ~16675 h** (Lawrence M2: `ENDS ~16675h42m`, "web will sit idle ~16671h"). A dependency on a cancelled task is dropped, as plan apply drops it for dispatch; a job that truly can never start takes none of its lane's time and is named as blocked, never as a duration.

## Upgrading

From 0.6.90: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.6.91`, then any `gear` call, and restart the engine — the binary changed.
