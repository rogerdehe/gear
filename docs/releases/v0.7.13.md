# GEAR v0.7.13

Codex seats start with `--dangerously-bypass-hook-trust` again.

## Changed

- **v0.7.12's hook change is undone.** v0.7.12 dropped `--dangerously-bypass-hook-trust` from a Codex seat's start, because on one machine every start with it asked for a new login, and answered the "Hooks need review" dialog with keys instead. The flag was not the cause. That machine has no Codex credentials on disk (`codex doctor`: `no Codex credentials were found`), and only a long-running shared Codex server still holds a login. Any start with `-c` runs outside that server, and GEAR always starts Codex with `-c`. The fix belongs on that machine: log in to Codex there. The flag is Codex's own switch for automation and changes nothing in the user's Codex config, so GEAR uses it again.

v0.7.12's other fix stays: a bare `gear` from an OpenCode seat finds its seat.

## Upgrading

Install the new binary (`herdr plugin install rogerdehe/gear --ref v0.7.13`) and reinstall the skill copies (`gear admin install-skill --agent <agent>`): the Codex guide is back to v0.7.11's. A running engine restarts itself on the new binary. A Codex seat started under v0.7.12 keeps its start flags until it restarts.
