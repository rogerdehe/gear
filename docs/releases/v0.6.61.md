# GEAR v0.6.61

Added:
- **`- merge-first T-<n>`** under `# Staff`: the task's queued merge runs next and alone, ahead of every other ready merge, `now` ones included. The line is one-shot (T-574).

Fixed:
- **A merge that adds nothing is merged, not gated:** when a task's branches are already on the integration branch (they landed with another merge), the merge is recorded as merged. Before, the gate refused the empty candidate and the done task kept a merge-failed item.
- **A lost-merge item closes once the task's merge is queued again:** a red batch's members that were named lost, then queued, no longer keep an item nothing could settle.
- **A red batch sends its members back queued, not unknown:** the next batch takes them, the lost scan does not call them lost, and `- remerge` accepts an unknown op no worker runs (T-576).
- **A merge that carries only reports skips the gate** (T-573).
- **A finished voyage sends nothing:** no doorbells or items for a voyage whose tasks are all done or cancelled (T-571).
- **The stall check never calls a delivered task queued** (T-575).

Why: Prometheus, 2026-11-05. T-745 and T-746 were on dev but recorded as failed merges. Lost items stayed open for queued merges. A red batch stranded seven merges as unknown. A fix every red round waited for was merged last. A finished Lawrence voyage kept ringing its new captain.

## Upgrading

From 0.6.60: `gear admin stop`, install v0.6.61, then any `gear` call, and restart the engine. The skill changed (captain reference: `merge-first`): reinstall it for each agent CLI.
