# GEAR v0.6.112

A voyage takes GitHub issues by its own label; the reclaim closes the merge workspace and never sweeps a voyage that has not landed.

Added:
- **Voyage-scoped GitHub issue intake by label** (M7 F-4: T-636 to T-638, T-643, T-645, T-648, T-649, T-651). `[github.issues] voyage_label` (default `{project}/{milestone}`, `""` turns it off; it must contain `{milestone}`). At departure the engine creates the label on GitHub. Every 120 s it lists the open issues carrying it: a new one becomes one captain item, a changed one or one that lost the label becomes an item, and nothing is cancelled silently. A GitHub error is never read as an empty list. The store records each issue; the board shows them by state (pending, planned, in progress, awaiting verification, done, deferred, unlabeled); a land is refused while one is pending (no confirmation overrides it), and the ready-to-land item lists them. An issue is planned by a task with `issue: #n`, deferred by resolving its intake item. GitHub lets only a collaborator with triage rights set a label, so a label set there enrolls the issue.

Fixed:
- **The reclaim could not close a workspace whose worktree was gone** (M7 T-639; GEAR M6.3 M-8482): when Herdr refuses the worktree remove, the reclaim closes the workspace.
- **An earlier landing swept a later voyage** (GEAR M7): the reclaim took the newest landing of the last day and ran while a later voyage, every task done, still had its last merge running. It now runs only for the project's current voyage.

## Upgrading

From 0.6.111: install the new binary (`herdr plugin install rogerdehe/gear --ref v0.6.112`); a running 0.6.111 engine restarts itself on it once its merges finish.
