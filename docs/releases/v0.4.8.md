# GEAR v0.4.8

Fixes from real use (voyage M4.2): conventions become configuration, a config can be checked without registering it, and several stalls and false alerts are gone.

## Conventions are configuration

- **Branch names come from the config.** `[conventions] task_branch` (default `"{lane}/t{n}"`), `review_branch` (default `"review/t{n}"`) and `seat_branch` (default `"{project}/{seat}"`, which replaces `home/<seat>`). Two projects on one repository must put `{project}` in the task and review templates; `init` refuses them otherwise. The engine refuses a worktree that belongs to another repository.
- **No Rust gate by default.** A project names its own gate (`[conventions] gate`, or a gate per repo); a config without one gets an issue at `init`.
- **A gate whose pipe hides a failure is refused** (`cmd | head` returns the status of `head`).

## Checking and registering

- **`gear admin init --check <config>`** validates a config and changes nothing: no store write, no agent started, no `GEAR_ADMIN` needed. It also catches two projects on one repo with clashing branch names.
- init refuses a provider prefix on a claude model id (`anthropic/claude-…`); the kickoff skeleton writes `wait` for a role with a single model.
- A config re-apply keeps retired lanes retired; a ready task wakes them. Lowering `[quota] temps` retires the extra reviewer seats.

## The loop

- A dependency counts when it is merged, not when its review passed.
- A milestone emptied of its tasks loses its departure, so a reused id starts its clock with its new tasks.
- An operation stuck in Executing no longer holds a lane's delivery slot.
- An urgent message reaches a lane or reviewer in the middle of a long tool call.
- A direction check that stops is nudged like a review; a passing check ("ok. …") is not sent to the lane.
- A hand-in in a project with no reviewers reaches the captain.
- One project's failure no longer stops the other projects' tick in a shared engine.
- No run-dry or IDLE item while no lane has work left to start.
- The review packet names the task's own change: `git diff <integration>...<candidate>` (three dots).

## The captain and the board

- The doorbell says exactly what to run: "Run the command `gear` (no arguments) in your own shell; it shows only your items", and names only the items `gear` shows.
- The home page's next command runs as printed.
- The board and the home page show the current voyage only; `gear board --project <id>` shows that project.
- Time & tokens shows fresh tokens and cache reads apart, and says once when no prices are set. "Deliveries not confirmed" counts only live deliveries. A session file never written no longer blanks a round's tokens.

## The skill

- The captain guide settles a voyage's backlog at kickoff (what the user placed in it is decided; every other item is taken, postponed with its reason, or dropped with its reason; an item postponed twice is taken or dropped) and closes it at the landing.
- `gear admin init --check` is the way to check a config before registering it.

## Upgrading

From 0.4.7: `gear admin stop`, `herdr plugin install rogerdehe/gear --ref v0.4.8`, then any `gear` call. Before re-applying your config, check it with `gear admin init --check gear/gear.toml`: a config with no gate now gets an issue, and a second project on the same repository needs `{project}` in its branch templates. Lanes start on new seat branches (`<project>/<seat>`); the old `home/<seat>` worktrees are no longer used and can be removed once clean.
