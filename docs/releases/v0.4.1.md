# GEAR v0.4.1

Progress you can see: a board with five views, a queue that says why every idle lane waits, and an overrun question when a task runs past its estimate. And a fleet that keeps going by itself through the things that stopped it on a long run.

## See the voyage

- **`gear board`** is rebuilt to the M4 prototype: five views (Now, Graph, Workload, Decisions, Time & tokens), keys, a frame that fits the terminal and keeps its borders, long goals clipped instead of hidden, clicks only on data rows.
- **`gear queue [--json]`**: each lane's working task with its actual/estimate minutes, the tasks left, and for an idle lane the reason (held, parked on quota, a declared wait, nothing left). `gear plan show T-n` prints one task's block; `gear whoami` names the caller's seat.
- **Every idle lane says why**, on the board and in the queue. A lane with nothing left next to a lane with a long queue is one balance item; a lane that will run dry soon is a warning.
- **The overrun question.** A task past its estimate asks its lane once for minutes left and the blocker (`gear send --kind progress --left --blocker`), and the answer reaches the captain. `--kind blocked --on T-n` declares a wait: no nudges, no stall item, until that task merges.
- **The course station** every 60 minutes of voyage time: elapsed against eta, projected finish per lane, tasks left.

## The fleet keeps going

- **A lane that stopped on a server error goes on.** An idle lane with a task in progress is told to continue in the same session; an unconfirmed delivery is sent again once before the captain is told; an agent that exited from its pane is started again once with the same model and arguments.
- **Role rules at agent start.** Lanes and reviewers start with their rules (pi: a system prompt file; Codex: a pointer to the rules file), with the voyage's goal and bar appended.
- **Quiet lanes are asked.** No push for 20 minutes brings one question to the lane; a working agent whose session has not been written for 10 minutes gets one interrupt.
- **A hand-in is not refused for a dev that moved during its suite**: a candidate that contains a dev tip at most `timing.handin_base_window_min` (default 30) minutes old and merges without conflict is accepted. The merge gate still runs the suite.
- **A new task's packet says how to start its branch** from the integration branch.
- **A lane restart carries its delivered task to the new seat generation**, and a plan park ends when its time passes (`gear plan check`, or any apply).
- **Codex quota is read from its source**, like MiniMax and OpenCode Go.

## Less noise for the captain

- One item per fact: overlap notices ring only for two open tasks that share a source file (an overlap with dev is an info line); "the review waits" and "the merge waits" are told once per attempt; a doorbell queued behind a working agent is not a stall; retired lanes are not counted.
- A failed merge gate names the failing tests, not only the last lines of output.
- Settling a task closes its review item; a tail that ended stays ended.

## Upgrading

From 0.4.0: stop the engine (`gear admin stop` in your own terminal), `herdr plugin install rogerdehe/gear --ref v0.4.1`, start the engine with any `gear` call. No store change. To use Codex quota readings add `[[quota.sources]] provider = "codex" reader = "codex"` to `gear/gear.toml` and run `gear admin init gear/gear.toml`.

This release fixes v0.4.0's known issue: Codex lanes and reviewers start again.
