# GEAR v0.7.34

GEAR deletes only the branches it made; a project's own command runs its checks, with no Makefile asked for.

## Fixed

- **The reclaim deleted a project's integration branch.** A landing deleted every branch under `<project>/` that sat on the integration branch, and the project's own integration branch once everything on it was released. MissHerAI's registered config named `dev` while the project worked on `selina/dev`, so M1's landing deleted `selina/dev` and GitHub closed its two open pull requests; a later scan asked the captain to delete it again. Now GEAR deletes, and names for deletion, only a branch made from one of the project's own templates (`[conventions]` `task_branch`, `review_branch`, `direction_branch`, `feature_branch`, `seat_branch`), with each placeholder filled the way GEAR fills it: a configured lane or seat, a task number, a feature id, a milestone. An integration, release or staging branch of any repo of the project is never deleted, and neither is any other branch under the project's name (`selina/dev`, `selina/docs/flow`): it is people's work, and the landing does not name it.
- **The skill asked every project for a Makefile.** The captain's kickoff required a Makefile with `check`, `gate` and `full` targets, and the lane, review and decompose rules said the merge gate runs `make gate`. The gate has always been the project's own `[conventions].gate`; the skill now asks only for two commands in the tool the project already uses (npm scripts, a Makefile, a shell script): a capped check of what changed, and the gate.

## Upgrading

Install the new binary (`herdr plugin install rogerdehe/gear --ref v0.7.34`); the engine restarts on it by itself. Nothing to configure. A project whose task branches sit under a template GEAR no longer recognises (a lane renamed since) keeps them; delete them by hand.
