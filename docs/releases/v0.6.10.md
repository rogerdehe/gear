# GEAR v0.6.10

M6, station S5's speed work, continued: the overlap scan starts a few git processes per pass, not one per ref.

Changed:
- **T-527 — the overlap scan starts a few git processes per pass, not one per ref:** the scan asked git for one branch tip at a time (one `git rev-parse --verify` for the integration branch, the remote integration branch and, per open task, its candidate and its local and remote branch) and one `git merge-base --is-ancestor` per candidate, and it runs at every hand-in and every ten minutes — a CPU sample of a running engine put most of its on-CPU time in those spawns. Every tip a pass needs now comes from one `git for-each-ref`, the candidate ids are resolved with one `git cat-file --batch-check`, and an ancestor answer is kept for the life of the process, as the diff cache is, since it never changes. Same findings as before.
