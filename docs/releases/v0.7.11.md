# GEAR v0.7.11

GEAR never asks a captain to merge into the release branch or to delete the integration branch, and a lane with no task never rings as stuck.

## Fixed

- **The release branch is the project's, not GEAR's.** After a landing, GEAR names what is left of the voyage until it is gone. It named the integration branch too, while its work was not on the release branch (`branch dev (not on main)`), and the item asked the captain to merge it and delete it. In many projects the release branch is reached only through a human review, and the voyage is finished once its work is on the integration branch (a deploy runs from there). That item rang until the next voyage departed. GEAR still deletes the integration branch once everything on it is released; otherwise it keeps it and never names it, and a deletion the remote refuses (a protected branch) is not named either. The conventions now say that GEAR's work ends on the integration branch.
- **A lane that holds no task is never reported stuck.** The stuck-lane item rang for a lane with no task and no check-in, and after a landing, with no voyage departed, nothing could clear it (a client saw it again and again). A lane with no task keeps nobody waiting: no item opens for it, and one left open closes. Work given to it later rings as before if it is not delivered.

## Upgrading

Install the new binary (`herdr plugin install rogerdehe/gear --ref v0.7.11`) and reinstall the skill copies (`gear admin install-skill --agent <agent>`): the conventions changed. A running engine restarts itself on the new binary and closes such open items on its next scan. Nothing to configure.
