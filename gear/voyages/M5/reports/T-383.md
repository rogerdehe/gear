# T-383 — report

The board's QUOTA lines show only the providers the project reads now, name
each window by its length, and give a reset that is not today a date.

## What changed

**`crates/gear-board/src/lib.rs`**

- `quota_readings(tx, project)` now takes the project's id. A new
  `quota_providers(tx, project) -> Option<Vec<String>>` reads the stored config
  with `tx.get_project` and a `toml::Value` lookup of
  `quota.sources[].provider`; a reading whose `provider` is not one of them is
  skipped. `None` (the project is not there, or the config does not parse)
  skips the filter: the readings stay rather than vanish.
- the orphan doc comment "The quota readings of the providers …" that sat above
  `tokens_of` moves to `quota_readings`, where it belongs.

**`crates/gear-board/Cargo.toml`**: `toml = { workspace = true }` (the crate
had no TOML dependency; `gear_app` still is not one).

**`crates/gear-usage/src/quota.rs`**: the Codex reader names a window by its
`window_minutes` through a new `window_name(key, entry)`: `5h` for 300,
`weekly` for 10080, else `<minutes / 60>h` when the minutes divide by 60, else
`<minutes>m`. The API's own key (`primary`/`secondary`) is the name only when
`window_minutes` is absent.

**`crates/gear-board/src/idle.rs`**: a new `pub fn day_clock(until: Ts)` beside
`clock`, with `libc::localtime_r` as `clock` does, printing `<Mon D> <HH:MM>`
(`Oct 30 00:35`). When the machine's local time is not readable it falls back
to a UTC month/day (`civil_from_days`, the inverse of the days-to-civil
algorithm) and the same hour/minute fallback `clock` uses.

**`crates/gear-board/src/frame.rs`**: `view_now` takes the board's `now`
(`view` passes `board.now`). The QUOTA line prints `idle::clock(resets_at)`
when the reset is within the next 24 hours and `idle::day_clock(resets_at)`
otherwise, and a reading read more than 30 minutes ago ends with
`  (read <n> min ago)`.

## Tests

**`crates/gear-usage/tests/it/quota_contract.rs`**: the Codex rollout test now
expects `5h` and `weekly`; a new `a_codex_window_is_named_by_its_length` checks
10080 → `weekly`, 300 → `5h`, 120 → `2h`, 90 → `90m`, and no `window_minutes`
→ `primary`.

**`crates/gear-board/tests/it/board_contract.rs`**: `world_with_a_voyage`'s
project now stores a config that reads `minimax-cn`, so its reading is one the
project reads (the pty test still shows that provider). Three new tests:

- `the_quota_shows_only_the_providers_the_project_reads`: a config reading
  `codex` alone shows `codex` and not `minimax-cn`, though both meta rows exist.
- `a_reset_days_away_prints_the_day_and_a_later_one_the_clock_alone`: six days
  out prints a three-letter month, a numeric day and a `HH:MM` time (the same
  `day_clock`); three hours out prints `resets HH:MM` alone.
- `a_reading_half_an_hour_old_says_its_age`: a reading 45 minutes old carries
  `(read 45 min ago)`.

## Out of scope

- The golden frames in `gear/voyages/M5/board/golden` are the prototype's
  output and no test compares the board with them yet; they still read
  `codex week … resets Oct 30`, and this change renames the board's side
  (`weekly`, `… resets Nov 4 00:35`). The prototype is the captain's.
- The engine still writes `name` from the reader as before: the Codex rows it
  stores get the new names on the next read, old rows keep `primary` until
  they are rewritten.
- A project whose config parses but lists no `[[quota.sources]]` now shows no
  QUOTA rows at all (the filter keeps the readings of "those providers", and
  there are none). The packet's "skip the filter when it does not parse" covers
  only a config that does not parse.
- `day_clock`'s no-localtime fallback is UTC, while `clock`'s fallback is the
  UTC clock too; no test pins either fallback.
