# T-270 — report

`fn restore` (`crates/gear-engine/src/names.rs`) now walks the seats in two
passes, so a name that a finished reviewer gives back is free before another
seat asks for it in the same tick. No other design changed; the tick call site
(`crates/gear-engine/src/lib.rs`) is untouched.

## What it does

`restore` partitions the project's seats (`Store::seats_of_project`, still
`ORDER BY id`) into

1. the seats whose desired name is their own seat name
   (`desired(&seat) == agent_name(&seat.project, &seat.name)` — the captain,
   every lane, and a Temp seat with no task, i.e. a finished reviewer in
   Standby), and
2. the seats named after a task (`<project>-review-<task>`),

and runs the existing per-seat body over `own.chain(task_named)`. Within a
pass the order is the store's own id order, as before.

One further line was needed inside `restore` to make the pass do what the two
passes promise: `ensure_snapshot` reads a *snapshot* of Herdr's names taken
before the pass, so after a rename the map still said the finished reviewer's
pane held `gear-review-t1` and the later seat saw it `Taken` anyway. `restore`
now clones the snapshot into a local `names` and, on `Ensure::Renamed`, writes
the pane's new name into it. The caller's snapshot is untouched (its lifetime
is the tick's read), so nothing outside `restore` changed.

The taken-name item is still written by the same `report_taken`, once per
spell, for a name a pane of no seat really holds.

## Tests (`crates/gear-engine/tests/it/agent_names_contract.rs`)

- `a_name_freed_in_the_same_pass_is_named_to_the_seat_that_asks_for_it`: seat
  `review-9` (Temp, Standby, no task) whose pane holds `p-review-t1`, and seat
  `review-11` (Temp, task `T-1`, unnamed) — the ids order `review-11` first, so
  one pass in id order saw the name held. One `restore` renames `review-9` to
  `p-review-9` and then `review-11` to `p-review-t1`, the freeing rename comes
  before the asking one, `restored.taken` is empty, and thread
  `name:p:review-11` holds no item. Verified red against the old single-pass
  body (`Restored { renamed: [...], taken: ["p:review-11"] }`).
- `a_name_held_by_a_pane_of_no_seat_is_still_reported_once`: `p-review-t1` held
  by `w1:p9`, no seat of that pane; two passes still report `p:review-11` taken
  once and never rename or steal.

  `restore` as unnamed and defers to the next tick (`Target::Renamed`). That is
  the existing T-149 behaviour, not this task's; noted in case the captain
  wants it.
