# T-295 — report

The live proof, through `gear_engine::tick`, that a lane parked on a quota wait
resumes **its own session** at the reset. The code change is none: the test is
`crates/gear-engine/tests/it/quota_wait_resume_contract.rs` plus its `mod` line
in `tests/it/main.rs`.

## What the test does

`crates/gear-engine/tests/it/quota_wait_resume_contract.rs` (new, one test):
`a_lane_parked_on_a_quota_wait_resumes_its_own_session_at_the_reset`.

- A project with one pi lane (`kind = "pi"`, `profile = "pi"`),
  `[models] lanes = ["tokenrhythm/deepseek-v4.1-flash-1017"]`,
  `on_quota = { lanes = "wait" }` and `quota_reset_h = 1`; the lane has T-1
  Started (`start_attempt` + `on_delivery_confirmed`) and the binding's
  `session_ref` is `sess-before-park`. `FakeHerdr` runs the pi agent in the
  lane's pane with that session and the pi quota marker
  (`429: … "You exceeded your current quota" … "insufficient_quota"`).
- Tick at T0+10: one marker is no fact — the seat stays Active.
- Tick at T0+20: the second marker confirms it — the seat is Parked, its
  reason carries the deadline T0+3620 (`quota_reset_h = 1`), no delivery.
- Two ticks before the reset (T0+100, T0+700): the seat stays Parked and
  nothing is delivered.
- Tick at T0+3620 with the marker gone: the seat is Active, the one delivery
  text is `Continue T-1: your quota is back.`, the seat generation is the one
  from before the park and the binding's `session_ref` is still
  `sess-before-park`; `herdr.calls` after the park hold no
  `Call::AgentStart`, no `ctrl+c`/`ctrl+d` keys and no `/quit` (pi's exit
  command).

## One deviation from the packet, and why (asked as a question)

The packet asked for **no `[[quota.sources]]`** *and* said "the park is the
unreadable-source park". On today's code those two do not meet, and the test
written that way fails at the reset step:

- With no sources, `sources_of` is empty, `source_of` returns `None`, and the
  quota step takes the config policy: `on_quota = wait` → `park()`, which
  writes only `engine.resume.<seat>` and **no** wait.
- At the reset `wake_from_source` finds no wait, so `change_model(chain.first())`
  runs; pi has no in-place picker, so it is `restart::advance`. The seat became
  `Missing` ("restarting on pi (tokenrhythm/deepseek-v4.1-flash-1017)"), no
  Continue in that tick, and pi closed and started again — not the packet's
  Active + Continue + same session + no `AgentStart`.

This was sent to the captain as a `question` (request
`r-1793233260464-32146`, thread T-295:1) with the failing step and its tick
report. Its default, which this branch takes, is option 2: the project names
**one** `[[quota.sources]]` (`provider = "tokenrhythm"`, `reader = "minimax"`,
`key_file = "/nonexistent/gear-t295/auth.json"`). `read_source` reads the key
file **before** it calls the provider, so the key read fails, the park is the
real `park_unreadable`, and no network is touched. That park writes the wait
the reset wakes from in place — the invariant the packet asks for.

## Out of scope

- The gap itself is not fixed (the packet: test code only). A project with
  `on_quota = wait` and no `[[quota.sources]]` still parks via `park()` and a
  pi lane is restarted at the reset instead of resuming its own session. The
  captain's question names this; a code fix is option 3 there.
- The pre-reset ticks assert Parked + no delivery, not that the pane is
  untouched; the pane assertions are the packet's own (`AgentStart`, exit keys)
  over everything after the park.
- The `quota.wait` Continue is read from the lane's delivery ops whatever state
  the delivery reached; no assertion is made on how the delivery op settles.
