# T-308 — report

A reset time is now read from a provider's own limit text, for the providers
GEAR has no quota reader for (`[v0.5.0 S1]`, M4 #20). No new API reader: the
text the agent shows is the source, and only when it states the time.

## What changed

**`crates/gear-usage/src/quota.rs`**

- `pub fn reset_from_text(text: &str, now: Ts) -> Option<Ts>` — reads the lines
  from the last to the first and returns the first match. Only a line that
  contains `reset`, `try again`, `retry` or `available again` (ASCII
  case-insensitively) is considered; such a line gives, in this order:
  1. an RFC 3339 timestamp among its whitespace-separated words, trailing
     `.,;:)` trimmed (the crate's `fn rfc3339`) → that time;
  2. `retry-after: <n>` → `now + n` seconds (the number in the same word or the
     next one, so `Retry-After: 120` and `retry-after:120` both read);
  3. `in <duration>` or `after <duration>` → `now` + the sum of the
     `<number><unit>` groups, with or without a space between number and unit
     (`2h 13m`, `45 minutes`, `3 hours 5 min`, `90s`), units
     d/day/days, h/hr/hrs/hour/hours, m/min/mins/minute/minutes,
     s/sec/secs/second/seconds.
- Helpers, private to the module: `fn speaks_of_a_reset`, `fn reset_of_line`,
  `fn trim_punctuation`, `fn duration_seconds`, `fn unit_seconds`.
- A result that is not after `now`, or more than 8 days after it, is `None`
  **for the whole call**: the last line that states a reset is the provider's
  latest word, and an earlier line may be stale (contract v3, the captain's
  answer M-4693 to my question `r-1793221670626-77459`). A matching line that
  states no time at all — `resets 3pm`, whose time zone GEAR does not know — is
  no match, so the scan goes on to the earlier lines and the fall-through is
  `None` too.

**`crates/gear-usage/src/lib.rs`**

- `pub use quota::{read_quota, read_quota_in, reset_from_text, QuotaReader, Reading, Window};`
  — exported beside `read_quota`. No other line of the crate changed.

## Tests (`crates/gear-usage/tests/it/quota_contract.rs`, where the crate keeps them)

Every acceptance case of the packet, one test each where it reads cleanly:

- `a_reset_time_is_read_from_the_text_of_the_provider` — `"Usage limit
  reached. Try again in 2h 13m."` → `T13 + 7980`; `"rate limit, resets in 45
  minutes"` → `T13 + 2700`; `"Retry-After: 120"` → `T13 + 120`; `"quota resets
  at 2026-10-29T05:00:00Z."` → `T13 + 230400` (that time); `"resets in 90s"` →
  `T13 + 90`; `"available again in 3 hours 5 min"` → `T13 + 11100`.
- `the_last_line_that_states_a_reset_wins` — last to first.
- `a_matching_line_followed_by_an_unrelated_line_still_matches`.
- `a_clock_time_is_not_a_reset` — `"resets 3pm"` → `None`.
- `a_duration_without_a_reset_word_is_not_a_reset` — `"in 2h"` → `None`.
- `a_reset_out_of_the_window_is_not_a_reset` — `"resets in 0s"` → `None`, an
  already-past RFC 3339 time → `None`, `"resets in 9 days"` → `None`,
  `"resets in 8 days"` → `T13 + 691200` (the edge is inside the window), and a
  last matching line out of the window with an earlier matching line inside it
  → `None` for the whole call (contract v3).
