# T-297 — report

A merge test whose gate handshake never happens now fails within a minute instead of hanging the
suite. The two blocking test helpers in `crates/gear-engine/src/merge.rs`'s `mod tests` no longer
block the test thread for ever on a fifo whose other end a dead worker never opened.

## What changed

**`crates/gear-engine/src/merge.rs`** (only file changed, test code only):

- New `fn await_fifo_within(path: &Path, bound: std::time::Duration)`: the blocking
  `File::open` + `read_exact` runs in a `std::thread::spawn`; the test waits on a
  `std::sync::mpsc::Receiver::recv_timeout(bound)` for that thread's `()`. No sleep, no polling.
- New `fn release_fifo_within(path: &Path, bound: std::time::Duration)`: same shape for the
  blocking `fs::write` (a fifo write blocks until the gate opens its end).
- `fn await_fifo` and `fn release_fifo` are now one line each, calling the `_within` helper with
  the module's `WAIT` (60 s), so every existing caller is unchanged.
- On a timeout both panic with
  `fifo handshake on {path} did not happen within 60 s (the merge worker never reached its gate)`.

**New test** (where the crate keeps them, in `merge.rs`'s `mod tests`):

- `a_fifo_handshake_that_never_happens_gives_up_instead_of_hanging` (`#[should_panic(expected =
  "did not happen within")]`): `await_fifo_within` on a fresh fifo nobody opens the other end of,
  with a bound of 1 s, gives up in ~1 s instead of blocking.

No production code, no behaviour change: every existing merge test passes as before.
