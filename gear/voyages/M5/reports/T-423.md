# T-423 — report

A seat never resumes a conversation another live pane holds: `choose` turns
such a `resume` into `fresh`, and the facts name the sessions the other panes'
live agents run.

## What changed

`crates/gear-engine/src/session.rs` only.

1. `Facts` gains `pub sessions_elsewhere: Vec<String>` — the `agent_session`
   value of every live agent of a pane that is **not** this seat's bound pane
   (`sessions_elsewhere`, read through `herdr.agents()`). Empty strings are
   dropped, as `seat_session` already does for the seat's own session.
2. Both facts builders (`lane_facts`, `review_facts`) fill it next to
   `seat_session(store, herdr, seat)`.
3. `fn choose`: the S1 action and the role rules are computed as before; a
   `Action::Resume(s)` whose `s` is in `sessions_elsewhere` becomes
   `Action::Fresh`. Nothing else is touched: no pane is closed, no round row
   changes, L1 keeps its meaning (`fresh` needs nothing from Herdr).
4. The test builders (`lane_facts` and the two review `Facts { .. }` literals)
   set it to `Vec::new()`.

New tests:

- `s3_a_review_of_a_session_held_elsewhere_starts_fresh` — the same review
  round resumes `session-r` with no such agent, is `Fresh` when
  `session-r` is held elsewhere, and still resumes when another session is the
  one held.
- `s3_an_s1_resume_of_a_session_held_elsewhere_starts_fresh` — an S1 resume
  (dead agent in an open round, and the restarted-agent case) becomes `Fresh`;
  with no holder it resumes as before.
- `s3_the_facts_name_the_sessions_the_other_panes_hold` — both builders name
  the other panes' sessions and never the seat's own (lane seat on `w1:p1`,
  review seat on `w2:p2`, holders `w3:p3`/`w4:p4`).

## Out of scope (noticed, not changed)

- When the round row already exists, `prepare_lane`/`prepare_review_role` call
  `s1(&facts)` directly instead of `choose`, so S3 does not apply to that path
  (the packet names `fn choose` only). An open round whose session another
  pane's agent took over still resumes it.
- `sessions_elsewhere` leaves a failed `herdr.agents()` read as "no other
  pane" (the rules then resume as before) rather than failing the tick; the
  packet does not say which way a read failure should go.

## Rework (attempt 2, F1 of the review)

F1: the open-round recovery called `s1` directly — `prepare_lane` (the `Some(_)`
arm of the action match) and `prepare_review_role` — and so bypassed `choose`:
an open round still resumed a session another pane's live agent held.

`crates/gear-engine/src/session.rs` only:

- `fn without_a_held_resume(facts, action)` — new: an `Action::Resume(s)` whose
  `s` is in `facts.sessions_elsewhere` becomes `Action::Fresh`; every other
  action passes through. `choose` now ends with it, and both open-round
  recoveries wrap their `s1`/recorded-action result in it, so S1 obeys S3 on
  every path that picks an action.

New tests:

- `s3_an_open_lane_round_held_elsewhere_is_not_resumed` — an open `dev` round
  on `round-session`, its agent gone and another pane's live agent on
  `round-session`: `prepare_lane` is `Prep::Ready` with the step's action
  `fresh`, and no `AgentStart` names `round-session`.
- `s3_an_open_review_round_held_elsewhere_is_not_resumed` — the same for an
  open `review` round: the recorded review action is `fresh`.

Both were shown to fail with the guard removed (`Prep::Wait`: the step resumed
and waited for the pane).
