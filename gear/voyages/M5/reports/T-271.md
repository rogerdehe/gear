# T-271 — the home page names the deliveries it counts as not confirmed

The count alone made the captain ask the store which deliveries were in
flight. The board now carries the list, and the snapshot prints it.

## crates/gear-board/src/lib.rs

- `pub struct Unconfirmed { pub op: String, pub seat: String, pub task:
  Option<String>, pub age_s: i64 }` — `seat` is the seat's **name** (not its
  id), `age_s` is `now − op.created` (never negative).
- `ProjectBoard` gains `pub unconfirmed: Vec<Unconfirmed>` next to
  `unconfirmed_deliveries`. It is filled in the same loop that counts the
  deliveries: only a `Deliver` op of the live incumbent (`Active`/`Standby`/
  `Starting` at the op's generation) is named, so a retired seat or an older
  generation stays history. The list is sorted oldest first (largest `age_s`
  first, ties by op id), so the delivery that waited longest comes first.
  `unconfirmed_deliveries` is unchanged and stays the count.

## crates/gear-app/src/home.rs

`fn snapshot`, right after the "deliveries not confirmed" line: when the list
is not empty, one line per delivery, at most `SNAPSHOT_DELIVERIES` (3):

```
    <op> <seat> <task or -> <age in minutes>m
```

then `    +<n> more` when there are more. An empty list adds no line.

## Tests

- `crates/gear-board/tests/it/deliveries_contract.rs`, new helper
  `seed_delivery_at` (a delivery with a chosen `created`), and
  `the_unconfirmed_deliveries_are_named_oldest_first`: two live `Submitted`
  deliveries 300 s and 120 s old plus one of the retired seat give
  `unconfirmed_deliveries == 2`, a list of two, oldest first, seat `data`
  (the name), task `T-1`, ages 300 and 120; the retired op is absent.
- `crates/gear-app/tests/it/app_home.rs`, new helper `deliver`, and
  `the_snapshot_names_the_unconfirmed_deliveries`: four deliveries 4, 3, 2 and
  1 minutes old print `O-1 heat T-1 4m`, `O-2 … 3m`, `O-3 … 2m`, then
  `    +1 more`. `the_snapshot_names_no_delivery_when_there_is_none`: the count
  is 0 and no line starts with `O-`.
