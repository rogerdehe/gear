# T-352 — report (contract v4)

The golden fixture now carries the prototype's stations: after
`golden_fixture::load()` the M5 board's `stations` are S1 Reached
"small-task procedure merged", S2 Now "board views to the prototype", S3 Next
"goal lock + v0.5.0", in order, from the existing model and store APIs.

## What changed

`crates/gear-board/tests/it/golden_fixture.rs` and the board tests only; no
change in `crates/gear-board/src` or `crates/gear-store`.

- `FixtureVoyage` reads the fixture's `STATIONS` as `(id, what, state, at_m)`
  (the `at_m` minute is not stored or drawn).
- `load()` seeds each voyage with `Tx::set_voyage_stations` (`id`, `needs` =
  `what`) and gives each station its tasks with `Tx::set_task_station`, so
  `stations::progress` derives the states:
  - a `done` station gets the fixture's merged tasks (`stage == "done"`, the
    tasks with a merge time), spread over the reached stations;
  - the stations ahead (`now`, `next`) get the fixture's open tasks (review,
    passed, rework, working, deps, queued), spread over them in plan order, so
    each has at least one open task and the first is Now, the following Next;
  - two asserts guard the shape if the fixture data changes: enough merged
    tasks for every reached station and enough open tasks for every station
    ahead.
- `crates/gear-board/tests/it/stations_contract.rs`: the acceptance test
  `the_golden_fixture_carries_the_prototypes_stations` builds the M5 board from
  `golden_fixture::load()` and asserts the three `(id, needs, state)` triples
  in order.
