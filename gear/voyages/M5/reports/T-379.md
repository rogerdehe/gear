# T-379 — report

A `gear` call waits for the store instead of failing with LOCKED, and a write
that holds the store long is named (F-129: a reviewer's `gear --show` got
LOCKED; the captain's `gear plan apply` got "ERROR LOCKED: database is locked"
at station M-4797; M4.2's O-3206 was stuck after the same error).

## Rework (attempt 2, review F1)

F1: the slow-write clock started just *before* `transaction_with_behavior`,
so a caller that only queued for the lock was charged with the wait and could
be named as the slow holder. Fixed exactly as the review asks: in
`Store::write` the single `let started = Instant::now();` now sits immediately
after the successful
`transaction_with_behavior(TransactionBehavior::Immediate).map_err(map_sqlite)?`
and before the `Tx` wrapper, so the span runs from the acquired write
transaction to its commit or rollback. Nothing else changed: the completion
measurement, the `> SLOW_WRITE_MS` threshold, the format and the
`#[track_caller]` location capture are as before, and the doc comment now
says why the clock starts after acquisition.

**No unit test of the ordering fits without a longer sleep** (the rework
allowed either): the only observable of the span is the stderr line, which
appears only for a span over `SLOW_WRITE_MS` (1 000 ms). To tell the two
orderings apart a writer must therefore *wait* for the lock for more than
1 000 ms — i.e. the fixture has to hold the write for longer than the
packet's 200 ms ceiling — and stderr would additionally have to be captured.
Every span that fits in 200 ms looks identical either way (no line), so a
test at that cost would assert nothing about the ordering. The waiting itself
is covered by `a_second_writer_waits_for_the_first_and_is_not_locked`.

## What changed

**`crates/gear-store/src/lib.rs`** only; no other design.

- `BUSY_TIMEOUT_MS` 5 000 → **30 000**, with a doc comment naming T-379/F-129.
  Both places that already read the constant (`prepare_connection`,
  `open_read_only`) pick it up unchanged.
- New `pub const SLOW_WRITE_MS: u64 = 1_000`.
- New `pub fn slow_write_line(ms: u128, caller: &'static std::panic::Location)`
  → `gear-store: a write held the store for <ms> ms (<file:line:col>)`.
  It is public because the acceptance asks for the helper to be tested; the
  crate keeps its tests in an integration binary, which can only see `pub`.
- `fn write` takes `#[track_caller]`, starts its `Instant` **after** the
  `BEGIN IMMEDIATE` has been acquired, and stops it after the commit or the
  rollback (the `Err` branch still drops the `Tx`, so the rollback is inside
  the measured span). Over `SLOW_WRITE_MS` it prints exactly one line to
  stderr with `std::panic::Location::caller()`, i.e. the caller of `write`.
  The engine's stderr is its log, so the slow writer shows there.
- The commit/rollback semantics are unchanged: `commit().map_err(map_sqlite)`
  then `map(|()| value)` where the old code used `?` in the matched arm.

## Tests

`crates/gear-store/tests/it/lock_contract.rs` (new, registered in
`tests/it/main.rs` where the crate keeps its suite):

- `the_busy_timeout_is_thirty_seconds` — `BUSY_TIMEOUT_MS == 30_000`.
- `a_second_writer_waits_for_the_first_and_is_not_locked` — two connections
  opened on one file *before* the lock; the first thread holds a write for
  200 ms, the second connection's `write` starts meanwhile and returns `Ok`
  (no `Locked`), with distinct ids.
- `the_slow_write_line_names_the_caller` — the formatted line is exactly
  `gear-store: a write held the store for 1500 ms (<location>)` and the
  location holds this test's file and the `Location::caller()` line.
- `the_slow_write_threshold_is_one_second` — `SLOW_WRITE_MS == 1_000`.

No test sleeps past the 200 ms hold (the 1 000 ms line itself is not exercised
by a sleep; only its formatter is tested).
