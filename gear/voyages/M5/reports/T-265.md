# T-265 — report

`gear admin stop` no longer cuts a merge in half. The engine leaves its
loop only between ticks, so a running tick — and the merge gate inside it —
always finishes, and `admin stop` waits for it. Change is confined to
`crates/gear-cli/src/main.rs`.

## What it does

1. **The engine stops between ticks** (`cmd_run`, `run_engine_with`):
   - `static STOP: AtomicBool`; `extern "C" fn on_sigterm` only stores
     `true` in it (async-signal-safe); `install_stop_handler()` installs it
     with `libc::signal(SIGTERM, …)` right before the real loop starts.
   - `run_engine_with` takes `stop: &dyn Fn() -> bool`, asks it before every
     tick and once per second of the sleep between ticks (the old one sleep
     of `cfg.tick_s` seconds is now `cfg.tick_s` one-second sleeps), and
     leaves the loop when it is true. The tick that is running — including
     its merge gate — is never interrupted, and its report is written.
   - `run_engine` passes `&|| STOP.load(Ordering::SeqCst)`.

2. **`cmd_admin_stop` waits for the lock** after the `SIGTERM`:
   `wait_for_lock(try_lock, sleep, tries)` tries the engine lock once a
   second for at most 20 minutes (`STOP_TRIES = 1200`). The first failed try
   prints, once, `waiting for the engine to finish its tick (a merge gate may
   be running)`; success prints `engine stopped (pid <pid>)` and drops the
   lock at once so the next `gear` call can start an engine. Past 20 minutes
   it fails with `ERROR FORBIDDEN: the engine (pid <pid>) is still running
   after 20 min` and exits 1 — the process really is stuck, so the user is
   told rather than lied to.

## Tests (`crates/gear-cli/src/main.rs`, `mod tests`)

- `stop_during_a_tick_leaves_the_loop_after_it` — no tick limit; the tick
  sets the flag during its own run and returns a report; the loop runs that
  one tick, writes its report (`p:T-1/1` is in the output), then returns.
  The sleep checks the flag before it sleeps, so no wall-clock wait.
- `stop_already_set_runs_no_tick` — the flag is true from the start: no tick
  runs.
- `wait_for_lock_retries_until_the_engine_lets_go` — succeeds on the third
  try, `sleep` called twice.
- `wait_for_lock_gives_up_after_tries` — 1200 failed tries, 1199 sleeps.
- The existing `tick_error_does_not_stop_the_loop` call passes `&|| false`.

`make check CRATE=gear-cli`: 135 passed, 0 failed.

## Out of scope (noticed, not changed)

- The early "engine not running" path of `admin stop` takes and drops the
  lock just to test it; a `gear` call in the microsecond between the drop and
  the engine's own take can start a second engine attempt, which fails on the
  lock. Harmless, not this task.
- Whether the 20-minute ceiling should follow the merge gate's own timeout
  (a gate slower than 20 min would still report the engine as stuck) is a
  design question, not decided here.
