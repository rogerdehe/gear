# T-391 — report

A reviewer started for a pending review is never released as idle before it gets
that review. `fn release_idle_standby` (`crates/gear-engine/src/release.rs`)
treated every Standby temp as jobless ("A standby reviewer has no job"), but a
seat started for a pending review sits in `Standby` until its agent is idle and
`fn start` (review.rs) hands it the review. When the Standby seats outnumbered
the lanes with a `Started` attempt, the sweep released such a seat, the pending
review started it again, and the loop repeated — 844 temp-seat starts in one
voyage, about every 20 s, each start a login shell and a codex launch.

## What changed

**`crates/gear-engine/src/release.rs`, `fn release_idle_standby` only**

- The Standby set the sweep works on is now read with `engine.review_pending.<seat id>`
  per seat inside the same `store.read`: a seat whose pending is set (non-empty)
  is **left out of the sweep** — it has a job and waits for it.
- The excess is therefore counted over the seats left in:
  `excess = standby.len().saturating_sub(W)`, where `standby` is the filtered
  list (before it counted the pending seats too, which is what released a seat
  that had work).
- Everything else is untouched: the sort by `state_since` (idle longest first),
  the "already Standby before this tick" filter of M-2603, and `release_one(…,
  None, now)`. A reservation whose review is gone is still ended before the
  sweep by the existing `under_review` check in `release_finished_reviews`
  (which also clears `engine.review_pending`), so the sweep never has to decide
  that.
- The doc comment of the fn says why a pending seat is not idle.

## Tests (`crates/gear-engine/src/release.rs`, its `mod tests`)

New helper `fn handed_in(store, task)`: attempt 1 of `task` with
`AttemptState::Submitted` and no verdict — the task is under review.

- `a_standby_reviewer_with_a_pending_review_is_not_released` — W = 0. `p:r-1` is
  Standby with `engine.review_pending.p:r-1 = T-1` (T-1 Verifying, attempt 1
  Submitted); `p:r-2` is Standby with no pending. Two ticks. Expected: `p:r-1`
  stays `Standby` and keeps its pending, `p:r-2` is `Released`, `exits == 1`
  (only the idle reviewer's pane is closed).
- `a_pending_review_is_not_counted_in_the_idle_excess` — W = 1
  (`world_with_a_working_lane()`: the lane has a `Started` attempt) and two
  Standby temps of which `p:r-1` has the pending. Expected: nothing released
  (`1 - 1 = 0`), `exits == 0`, `p:r-1` Standby with its pending kept, `p:r-2`
  Standby (waits for the next review).
- The existing release tests (including
  `with_one_lane_working_the_longest_waiting_standby_reviewer_is_released`,
  `with_no_lane_working_every_standby_reviewer_is_released` and
  `a_reviewer_that_just_got_its_verdict_waits_for_the_next_tick`) pass
  unchanged.

## Out of scope

- `crates/gear-app/src/admin.rs` has an own notion of "idle standby" for the
  captain's `- release <reviewer>` view; the packet names `release_idle_standby`
  only, so it was not touched.

  (the `under_review` check does not guard the manual path). Not in the packet.
