# T-412 — report

A run of tests no longer writes to the system disk, and a passing run leaves
none of its own temp directories behind (2026-10-29: the system disk filled to
1 GB free; the system temp directory held about 168 000 leftover test
directories, mostly `gear-engine-tests-*`, `gear-forge-*`, `gear-init-*`; a
full disk then failed T-408's merge gate).

## What changed

**(1) `Makefile`.** A run's temp files stay with the checkout:

```make
export TMPDIR := $(CURDIR)/target/tmp
prune-tmp:
	mkdir -p $(TMPDIR)
	find $(TMPDIR) -mindepth 1 -maxdepth 1 -mmin +60 -exec rm -rf {} +
```

`check`, `gate` and `full` depend on `prune-tmp`, so every run first creates
`target/tmp` and deletes what an earlier run left there more than an hour ago
(a lane killed mid-run leaves its scratch behind), then runs its cargo
commands with `TMPDIR` set. `export` (not a per-command prefix) so
`scripts/test.sh` and the nextest children inherit it too. `install` is
untouched.

**(2) The tests' own scratch directories.** `crates/gear-forge/tests/it/
github_contract.rs` — the test file the packet names — gets a drop guard: the
per-test directory is a `Scratch` (its `Drop` removes the tree, `Deref<Target
= Path>` so the helpers read as before), and the one fake `gh` every test
hard-links is a `SharedFake` behind an `Arc` in a `OnceLock<Mutex<Weak<…>>>`:
each test keeps it alive while it runs, and the file goes when the last test
holding it is done. T-128's one executable image per test file stays.

Every other test that named a directory under `std::env::temp_dir()` by hand
(`rg -n 'temp_dir\(\)' crates`) now asks a per-test janitor for it:

- `crates/gear-engine/src/testtmp.rs` (test-only module, `#[cfg(test)]` in
  `lib.rs`), `crates/gear-app/src/testtmp.rs` likewise;
- one copy per integration-test binary root: `crates/gear-engine/tests/it/
  main.rs`, `crates/gear-cli/tests/it/scratch.rs`,
  `crates/gear-app/tests/it/main.rs`;
- `crates/gear-cli/src/main.rs`'s `mod tests` (one copy, `default_store_tests`
  reaches it as `crate::tests::scratch`).

The janitor registers each directory on the test's own thread and removes
them in a `Drop` when that thread ends — the harness gives every test its own
thread, so that is the end of the test. It is keyed by name, so the same name
in one test is still the same directory (tests call a `cfg()` helper twice and
compare), and the path carries a per-thread number so two tests never share
one. The call sites keep their shape: each `scratch(tag)`/`cfg()` helper is
now one line, and the returned type is still `PathBuf`.

The two `/tmp/t209.db` and `/tmp/t226.db` fixtures of `gear-engine`'s unit
tests moved into the same janitor: they made the engine write its rules files
into `/tmp` on the system disk.

Already guarded before this task, and left alone: `merge.rs`'s `Scratch`/
`Pair`/`Chain` (`impl Drop`), and `gear-app`'s `tests/it/base_gate.rs`
`Scratch`.

**(3) The rules.** One line each in `skills/gear/references/rules/lane.md`
(after the "search only inside your worktree" line) and `…/review.md` (after
the "check the mechanical facts first" line), word for word as the packet
gives it.
