# T-372 — report

`init` now refuses a config whose seat branch and task or review branch are a
ref and a folder of the same name, which git cannot hold together — the case
where a lane had to delete its own seat branch to cut a task branch.

## What changed

**`crates/gear-app/src/config.rs`**

- `fn validate` gains, after the branch-template checks and before `[timing]`,
  a loop over `cfg.lanes`: with the project id, the lane's name as `{lane}` and
  `{seat}`, and `T-1` as the sample task, it expands
  `conventions.task_branch` and `conventions.review_branch`
  (`gear_model::branch::expand`) and the seat branch
  (`gear_model::branch::expand_seat`) of the lane's own seat, of the merge seat
  (`merge`) and of a reviewer (`review-1`). Every seat branch against both
  branches: when one equals the other or is a prefix of it followed by `/`,
  `issue("conventions.seat_branch", …)` names the two branches, the kind
  (`task`/`review`) and the fix (`seat_branch = "{project}/home/{seat}"`) —
  one issue per pair.
- `const MERGE_SEAT`/`REVIEW_SEAT` and `fn one_branch_holds_the_other` (same
  name, or one as a folder of the other, on a `/` boundary).
- The `validate` doc-comment lists the new rule.

**Tests** (`crates/gear-app/tests/it/`)

- `config_contract.rs`: new
  `a_seat_branch_that_holds_a_task_or_review_branch_is_refused` — a
  `{project}/{lane}/t{n}` task branch with the default seat branch gives one
  `conventions.seat_branch` issue naming `p/heat` and `p/heat/t1` and the
  suggested fix; `seat_branch = "{project}/home/{seat}"` gives none; the
  defaults give none; a `{project}/review-1/t{n}` review branch against
  review-1's seat branch gives the review issue.
- Two existing fixtures that paired `{project}/{lane}/t{n}` with the default
  `{project}/{seat}` now name `{project}/home/{seat}`, the shape this rule
  asks for (`config_contract::branch_templates_default_to_the_names_gear_uses`,
  `admin_init_contract`'s `TEMPLATED` and its inline templated config).

## Checks

`make check CRATE=gear-app`: 511 tests, all pass.

## Out of scope

- `skills/gear/references/conventions.md` and the v0.4.8 release note still
  present `seat_branch = "{project}/{seat}"` as the default, without warning
  that it collides with a `{project}`-prefixed task branch. Worth a docs task.
- `validate` checks the sample lane names; a project whose lane is literally
  named `merge` or `review-1` would collide with the fixed seats, which this
  check does not report.
