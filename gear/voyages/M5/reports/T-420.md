# T-420 — report

Every seat GEAR starts now gets its own scratch directory as `TMPDIR`, not only
a lane's first start: a reviewer's start and a restart (or model-switch resume)
build the same prefix T-413 built for onboarding, from one shared function.

## What changed

**(1) `crates/gear-engine/src/onboard.rs`.** New `pub(crate) fn tmpdir_prefix(
conventions, project, seat, worktree) -> Option<String>`: it resolves the
seat's scratch directory with the existing `scratch_dir` (project
`[conventions].scratch_dir`, else `<worktree>/.gear/tmp`), quotes it with
`shell_quote`, and returns the line prefix
`mkdir -p '<scratch>'; export TMPDIR='<scratch>'; `. When the scratch is the
worktree default it also appends `.gear/` to the repository's
`info/exclude` via the existing `exclude_gear_dir` — the same `git status`
quieting onboarding had, now also for reviewers and restarts, whose worktrees
would otherwise carry an untracked `.gear/` into the next review's
`stash_review_tree`. `onboard_seat` now just prepends the returned prefix to
`plan.env_command`; its behaviour is unchanged.

**(2) `crates/gear-engine/src/review.rs`.** In `start_reviewer`, the reviewer's
`env_command` (built next to `export GEAR_CTX=`) starts with the same prefix,
pointing at the reviewer seat's own worktree (`<reviewer worktree>/.gear/tmp`,
or its `<scratch_dir>/<project>/<seat>` when the project names one), and the
checkout it names is recorded as the seat's worktree before that line is built
(attempt 3, below).

**(3) `crates/gear-engine/src/restart.rs`.** `env_command` gains the project's
`Conventions` and the seat's recorded worktree path, and prepends the same
prefix; the caller reads both just before the environment step. This covers a
restart and the model-switch resume, which both go through this line.

Release stays as T-413 left it: `release.rs::remove_scratch` removes the
directory from the same `scratch_dir` rule, so a reviewer's or restarted
seat's scratch goes when the seat is released.

## Rework (attempt 3): F1 of the review of attempt 2

The reviewer was right: `start_reviewer` built the prefix from the reviewer's
checkout (`engine.review_path.<seat>`) but never wrote
`engine.worktree_path.<seat>`, and `release.rs::remove_scratch` reads only the
latter — so with the default conventions (no `[conventions].scratch_dir`) a
released reviewer resolved no scratch path and kept `<worktree>/.gear/tmp`.
Every default reviewer release leaked its temp files.

The fix is the one the review named, in `review.rs` only: after
`fn worktree_path` resolves the checkout and before the environment line is
built, `start_reviewer` writes that path under
`crate::onboard::worktree_path_key(&seat.id)`. It runs on every start, so a
reopened checkout is the one a release removes. Nothing else changed:
`release.rs`, `onboard.rs` and `restart.rs` are as attempt 2 left them.

The regression in `review.rs`,
`a_released_reviewer_leaves_no_scratch_in_its_worktree`, does not seed the
missing key (which is how `release.rs`'s own cleanup test misses this seam):
a reviewer seat comes back to its checkout (its review path is a real
directory under this worktree's `TMPDIR`, a binding on its pane), the start's
environment line names `<checkout>/.gear/tmp`, the start's metadata is read
back as the seat's worktree, and after the agent leaves and the seat is freed
by `release::release_one` the scratch directory is gone.

## Out of scope

- A captain seat is bound by `gear admin init`, not started by the engine, so
  it still gets no `TMPDIR` line (T-413 logged the same).
- The prefix builder creates the directory; the engine does not remove an empty
  `<scratch_dir>/<project>/<seat>` parent on release — unchanged from T-413.
- `shell_quote`/`exclude_gear_dir` stay private to `onboard.rs`; only the
  prefix builder is shared, as the packet names.
- The fake Herdr's worktrees live at `/fake-worktrees/<branch>`, outside any
  worktree, so a test cannot make a scratch directory at the path a *fresh*
  review start records (a lane may not write outside its worktree). The
  regression therefore runs the warm-seat path — the reviewer reopens the
  checkout its first job recorded — which is the same metadata seam F1 is
  about, with a real directory under this worktree's `TMPDIR`.
