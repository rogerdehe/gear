# T-419 — report

The Makefile no longer caps jobs at 2 and 4: `check` and `gate` run each heavy
command through `tools/build-slot/build-slot.sh`, which sizes the run to what
is on the machine now.

## What changed

`Makefile` only, and `tools/build-slot/` taken in as it stands (see Friction).

**Header comment** — the "caps live in the targets" sentence is now "the job
counts come from tools/build-slot/build-slot.sh, which sizes each run to what
is on the machine now: no fixed caps, no global config, no locks, no queues
(user, 2026-10-29; the rule is in tools/build-slot/README.md)". The first
sentence ("one target per situation, pick the right cost by name") is
unchanged, and so is its meaning.

**`check`** — `##` comment: "one crate, jobs from build-slot;
TESTS=<nextest filter> runs only the tests it matches". The recipe is

```sh
tools/build-slot/build-slot.sh cargo nextest run -p $(CRATE) --no-fail-fast $(if $(strip $(TESTS)),-E '$(TESTS)')
```

with `CARGO_BUILD_JOBS=2 NEXTEST_TEST_THREADS=2` gone. The `CRATE` guard line
is untouched.

**`gate`** — `##` comment: "the merge gate on the shared machine: workspace
build and the whole suite, each sized by build-slot (the test run measures the
machine after the build)". The recipe is two calls, so the test run samples the
machine again after the build:

```sh
tools/build-slot/build-slot.sh cargo build --workspace --all-targets && tools/build-slot/build-slot.sh scripts/test.sh
```

with `CARGO_BUILD_JOBS=4` and `NEXTEST_TEST_THREADS=4` gone.

**Unchanged** — `full`, `install`, `export TMPDIR`, `prune-tmp`, `.PHONY`.

## Friction

The packet says the tool is "in tools/build-slot/ with its README and test",
but `origin/dev` has no `tools/` at all: it exists only on the captain's local
`dev`, in commit 74da203c, unpushed. Acceptance and the merge gate both need
the script, so I asked (thread T-419:1) and went with my default: commit
8562ae34 takes the three files from 74da203c byte for byte, leaving that
commit's `gear/voyages/M5/plan.md` edit to the captain. If `dev` is pushed as
it is, the two additions are identical and merge clean.

## Out of scope (noticed, not changed)

- `scripts/test.sh` builds the test binaries itself (`cargo nextest run
  --workspace --no-run`), so `gate` still builds the workspace twice — once
  through its own `cargo build`, once inside the test script. The packet keeps
  `scripts/test.sh` as it is; a later task could drop the outer build or the
  inner one.
- With a busy machine the same sample gives N=1 for the build and for the test
  run, so `gate`'s two samples mostly differ only when the machine changed in
  between — which is what the packet asks for.
