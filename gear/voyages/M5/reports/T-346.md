# T-346 — report

Each task has one stage of the sixteen the README names, read from the facts the
store already has: a hand-in that waits for a reviewer and one a reviewer works
on are no longer both "in review", a failed merge no longer reads as merging,
and a rework no longer shows as queued.

## Rework (attempt 2, review F1 and F2)

**F1** — the lane panel kept the five-stage behaviour. `styled_lane_panel` now
receives the lane's `GraphTask` records (the already computed `project.graph`)
and reads nothing from `TaskState`:

- `pub fn lane_panel(lane: &LaneBoard, tasks: &[graph::GraphTask]) -> Vec<String>`
  and `pub fn styled_lane_panel(lane, tasks, color)`; the panel keeps the
  lane's own tasks (`graph::GraphTask::lane`, an empty lane shows in the
  `unassigned` lane).
- DONE lists its `Stage::Merged` tasks, NOW its `stage.is_open()` tasks (the
  prototype's `OPEN`), LEFT its `Stage::Deps | Stage::Queued` tasks (the
  prototype's `queued`, `deps`), each row with `stage.symbol()`, `stage.color()`
  and `Stage::words(task)`; the DONE row carries ` {rounds}r` when the task had
  more than one round, and a LEFT row names `needs {deps}`.
- The synthetic `GraphTask` with `rounds: 0` is gone.
- `crates/gear-board/src/lib.rs`'s `open_panel` passes `&project.graph`, so the
  interactive panel and the printed frame both use it.

The review's assertion is in `graph_contract.rs::the_lane_panel_shows_each_task_in_its_stage`,
on the `stage_world()` fixture: T-29 (`◎`, "handed in, waits for a reviewer")
against T-30 (`◎`, "in review"), T-27 (`✗`, "merge failed, waits for the
captain"), T-25 (`↺`, "reworking (round 2)"), T-22 (`◉`, "waits for the
captain's answer"), and T-20's LEFT row naming `needs T-1` (with
`left: 2 tasks, 40m of estimates`).

**F2** — `stage_of` now filters the abandoned attempt *after* `max_by_key`, so
a newest abandoned attempt counts as no attempt and the older attempt is not
resurrected: `graph_contract.rs::an_abandoned_newest_attempt_counts_as_no_attempt`
inserts an Abandoned attempt 2 over T-21's Started attempt 1 and expects
Queued / "queued".

The lane-panel tests in `workload_contract.rs` follow the new signature; the
"running and reviewing in NOW once" test gives T-4 a Started attempt (Working)
and T-5 a Submitted one (Handed), since the panel now reads the stage and not
the task state.

## What changed

**`crates/gear-board/src/graph.rs`**

- `GraphStage` (Queued, Working, Review, Merging, Done) is replaced by
  `pub enum Stage { Deps, Queued, Delivered, Working, Asking, Handed, Review,
  Verdict, SentBack, Rework, Passed, Merging, MergeFailed, Merged, Failed,
  Moved }` (the prototype's STAGE, SYM, STAGE_COL, OPEN), with
  - `pub fn symbol(self) -> &'static str` — ○ ○ ◌ ◉ ◉ ◎ ◎ ◎ ↺ ↺ ◍ ◍ ✗ ● ✗ →,
  - `pub fn color(self) -> Color` — Dim Dim Dim Warn Warn Acc Acc Warn Bad Warn
    Acc Acc Bad Ok Bad Dim,
  - `pub fn is_open(self) -> bool` — true for Delivered through MergeFailed,
    false for Deps, Queued, Merged, Failed, Moved,
  - `pub fn words(task: &GraphTask) -> String` — the prototype's STAGE text
    ("waits for {deps} to merge" with `-` when there is none, "queued",
    "delivered, not started", "working", "waits for the captain's answer",
    "handed in, waits for a reviewer", "in review", "waits for the captain's
    verdict", "sent back, rework queued", "reworking (round {rounds})",
    "passed, waits to merge", "merging (gate running)", "merge failed, waits for
    the captain", "merged", "failed (rounds used up)", "moved to {moved_to}").
- `GraphTask` gains `pub moved_to: Option<String>` (`None` here from the store)
  and its `stage` is a `Stage`.
- `fn stage_of` returns `Stage`, first rule that holds, with `a` = the task's
  attempt with the highest `n` (an Abandoned one counts as none):
  Done → Merged; Failed → Failed; a Rejected and no newer attempt → SentBack;
  Verifying with a passed `VerdictRow` for `a.n` → the task's newest Merge op
  (`newest_merge_op`: the project's ops of kind `OpKind::Merge` with this task,
  gathered from `tx.ops_in_state` over every `OpState`, newest by `created`
  then by the number after `O-`) Failed → MergeFailed, Executing, Submitted or
  Unknown → Merging, else Passed; Verifying with a review verdict for `a.n`
  (`tx.get_review_verdict`) → Verdict; Verifying with a Temp seat of the
  project in `SeatState::Active` whose `task_id` is the task → Review; Verifying
  when the project's `quota_temps` is 0 → Verdict; Verifying → Handed; a
  Started, Stopped or Unknown with an Open `MsgKind::Question` for this task
  among `tx.messages_from_since(project, &a.seat, a.started)` → Asking;
  `a.n > 1` and Delivered → SentBack; `a.n > 1` and Started, Stopped or
  Unknown → Rework; Delivered → Delivered; Started, Stopped or Unknown →
  Working; Submitted → Handed; Accepted → Passed; no attempt and a dependency
  whose task is not Done → Deps; else Queued.
- `fn order` is the prototype's `order_of`: the Deps and Queued tasks first,
  then the open stages (one group, plan order), then Merged newest first.
- `stage_color` follows `Stage::color`. `info` is `words` plus the time
  (`actual/esti m`, ` · N rounds`, and for a merged task `merged HH:MM · ` in
  front), so every row's info column speaks the new words.
- `styled_lines`: the lane symbol and the colour of the review column come from
  the stage; the rev-column connector (the `◎` at column 9 and the line to the
  lane) is drawn for the stages a reviewer or the merge holds (Handed, Review,
  Verdict, Passed, Merging, MergeFailed) and shows that stage's own symbol; the
  `●` merge line, the `✓` and the `↺` of a rework stay as they were. The
  legend names the new symbols.

**`crates/gear-board/src/frame.rs`** — `fn styled_lane_panel`'s NOW section uses
`Stage::symbol`, `Stage::color` and `Stage::words` instead of a hand-written
`◉`/`◎` pair and `task.state.as_str()` (the prototype's lane panel shows
`words(t)`). The store was already able to answer every
question; no migration, no new store call.

**Tests** (`crates/gear-board/tests/it/graph_contract.rs`, where the crate keeps
them)

- The old `world()` sets each attempt's state from what the task does (Running
  → Started, Verifying with a verdict → Accepted, Verifying without one →
  Submitted), because the stage rules read the attempt, not the task alone. Its
  expectations follow the new words and the new order (the queued/deps group,
  then the open ones in plan order: T-141 Passed and T-142 Handed, then the
  working T-143/T-144, then the merged).
- `fn line_of` finds a row by the id in the id column (in characters, the box
  signs are more than one byte): a Deps row now names another task in its info
  ("waits for T-142 to merge"), which the old "contains" lookup would have
  mistaken for that task's row.
- `fn stage_world()` is one store fixture built once, one task per stage:
  T-20 Deps ("waits for T-1 to merge", T-1 not merged), T-1 Queued, T-23
  Delivered, T-21 Working, T-22 Asking (an Open question of the attempt's seat
  since its start), T-29 Handed (no reviewer seat), T-30 Review (an Active temp
  seat holds it), T-31 Verdict (a review verdict for attempt 1), T-24 SentBack
  (Rejected and no newer attempt), T-25 Rework (attempt 2 started, "reworking
  (round 2)"), T-28 Passed, T-26 Merging (an Executing merge op), T-27
  MergeFailed (a Failed merge op), T-32 Merged.
  `each_stage_comes_from_a_fact_of_the_store` checks stage and words of all 14.
- `the_sixteen_stages_have_their_symbols_colours_and_words` checks symbol,
  colour and `is_open` of all 16 against the packet's table, and the words of
  the two stages this store cannot give (Failed, Moved with `moved_to: Some`).
- `board_contract.rs`: the two waits for the graph frame's legend now expect
  `○ not started`.
