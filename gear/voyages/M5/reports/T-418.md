# T-418 — report

A reviewer whose start failed is released on the next tick, so it never holds
a temp slot: its review goes back to `start_reviews` and starts again on a free
seat, and the captain hears about it once.

## What changed

`crates/gear-engine/src/release.rs` only, as the packet says — no other file in
the crate, no other crate.

**`const START_FAILED_S: i64 = 180`** — how long a `Starting` reviewer whose
pane holds no agent may keep its slot.

**`fn failed_start(store, herdr, seat, now)`** — the packet's condition, in one
place: the seat's binding is `BindingStatus::Pending` and
`now - binding.created > START_FAILED_S`, and `herdr.agent_get(&pane)` is
`Ok(None)`. `Ok(Some(_))` (a slow start, not a failed one) and `Err` (an
observation failure is not an absence, design/08, T-264) both keep the seat.
Before the pane is closed, its tail (`read_tail(pane, 16)`) gives the last
non-empty line — the line the captain needs ("No saved session found"). A tail
that cannot be read names nothing; it does not keep the seat.

**`fn tell_start_failed(store, project, seat, pane, last_line, now)`** — one
`Info` message (`MsgKind::System`, `MsgState::Info`, not urgent) to the project's
captain, thread `review:start-failed:<seat id>`, body = the seat's name and id,
the pane, and its last line. The seat is `Released` afterwards, so the rule
cannot fire again for it: one message per failed start. A project with no
captain gets no message (`captain_of` is `None`), as the agent-gone message
does.

**`fn release_finished_reviews`, the `Starting` arm** — before the "its job is
gone" cancellation, `failed_start` is asked; when it answers, the seat is
released with `release_one(…, caller "start-failed")` and pushed to
`report.released`, then the captain is told, and the loop moves on. A failed
release lands in `report.failed` like every other one.

**`fn release_seat`** — a `Starting` seat now pays out a start-failed release in
one step (no `Releasing` in between, the model has `Starting → Released` for a
cancelled start, B03-05): its pane is closed through `bound_pane` (the binding
is `Pending`, so the `Active`-only `binding_pane` would not see it), and in one
write its binding is voided, its task cleared, `engine.review_pending.<seat>`
cleared and the seat set to `Released` with reason `its start failed`; the
release is logged with `release_line(seat, from, reason, caller)` like every
other (`caller=start-failed` in `engine.log`). The pending review is cleared in
that same write, so no seat is left holding a reservation of a review nobody
runs (T-399's rule). No existing caller passes a `Starting` seat to
`release_one`, so nothing else changes: `Releasing`, `Active` and `Standby`
seats go through the steps they always did.

## Tests

In `release::tests` (unit tests, `make check CRATE=gear-engine
TESTS='test(/release::/)'`):

- `a_reviewer_whose_start_failed_is_released` — a temp `Starting`, `Pending`
  binding 200 s old, no agent, the review still under review: the seat is in
  `report.released` and `Released`, its task is gone, its pane closed once, its
  binding `Void`, `engine.review_pending.p:r-1` is `""`, and exactly one
  `Info` message sits on `review:start-failed:p:r-1` naming `r-1` and the pane's
  last line (`No saved session found`).
- `a_starting_reviewer_inside_the_grace_is_left_starting` — the same seat at
  100 s: not released, `Starting`, no pane close, no message.
- `a_starting_reviewer_with_an_agent_is_left_starting` — the same seat with an
  agent in its pane at 200 s: not released, `Starting`.
- `a_starting_reviewer_whose_pane_cannot_be_read_is_left_starting` — the same
  seat with `agent_get` erroring at 200 s: not released, `Starting`.

Helper `failed_start_world(pane)` builds that seat (with a captain, so the
message has a recipient) and `handed_in` puts its attempt under review, so the
`Starting` arm's existing cancellation of a review whose job is gone cannot
stand in for the new rule.

## Out of scope (noticed, not changed)

- A failed start without a `Pending` binding (nothing was opened, or the
  binding is already `Void`) is not covered by this rule: the packet's condition
  is per binding. Such a seat is the `Queued`/parked cases the existing sweep
  already owns.
- `cancel_start` (the job-gone cancellation) still clears the same three things
  in its own steps; the two paths are not merged. Merging them would be a
  change of `cancel_start`'s design, which the packet keeps out.
- The message names the last non-empty line of the tail's 16 lines; a pane whose
  failure line is further up shows only what `read_tail` returns.
- `release_seat`'s `Starting` branch is unconditional for a `Starting` seat:
  no caller passes one today, so this is the start-failed payoff, but a future
  caller gets it too.
- The message's `attempt` field is `None` (the seat's task is named, the
  attempt is not): the packet asked for the seat and the pane's last line.
