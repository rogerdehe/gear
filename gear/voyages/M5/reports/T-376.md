# T-376 — report

A hand-in that waits 20 minutes without its review packet reaching a reviewer
now rings the captain: once per attempt, urgent and open, on
`review-stall:<task>:<attempt>`, naming every temp seat with its state and
task.

## What changed

`crates/gear-engine/src/review.rs` only: the `start_reviews` tick calls the new
`tell_captain_of_a_review_stall` after the hand-in pass (after the
late-hand-in / direction branch, so a hand-in that got its seat in this tick is
no longer in `tasks_to_review`), plus `REVIEW_STALL_S = 1200`,
`review_stall_key`, and the `OpState` import.

**The condition.** For every task of `tasks_to_review` (the same set the
hand-in pass uses: a Submitted attempt with a candidate, no verdict, no live
temp seat) whose `tx.attempt_times(project, task, n)?.handed_in` is at least
1200 s before `now`, and for which **no** Confirmed `Deliver` op of a Temp seat
exists for that task and attempt.

**The message.** One per attempt, remembered under the meta key
`engine.review_stall.<task>.<attempt>` (a second tick adds none, a resolved
item stays resolved):

```
T-1 attempt 1 was handed in 21 min ago and no reviewer has its packet: the
seats are p:review-1: active, T-9; p:review-2: active, T-8; look at the
reviewer panes, or settle it in # Verdicts after reading the candidate yourself
```

`MsgKind::System`, `urgent = true`, `MsgState::Open`, sender `engine`, the
task and attempt set. The seats are the project's temp seats that are not
retired, `id: state, task` (`-` when the seat holds no task), joined by `; `.

**Where it does not fire.** The project-without-`[temps]` branch returns before
this call: `tell_captain_of_hand_ins_without_reviewers` already gives the
captain an urgent item on `verdict:<task>:<attempt>` there, and a second one
for the same hand-in would be the same news twice.

## Tests (`crates/gear-engine/src/review.rs`, `mod tests`)

- `a_review_stall_rings_the_captain_once_per_attempt` — two busy temp seats so
  the hand-in waits: at 19 minutes `review-stall:T-1:1` is empty; at 21 minutes
  it has one urgent open System item for `p:captain` naming `p:review-1:
  active, T-9; p:review-2: active, T-8`, the meta key is set and it is one of
  the captain's actionable items; a tick a minute later adds none.

  message and no meta key.

## Out of scope (noticed, not changed)

- The meta key is `engine.review_stall.<task>.<attempt>` exactly as the packet
  writes it, so it carries no project id (unlike
  `engine.review_wait_told.<project>.<task>.<attempt>`). With two projects
  sharing one store, the same task id and attempt in both would share one key.
  Whether the key should carry the project is a design decision.
- The seats listed are the temp seats only, not the lane and captain seats.
  The message says "look at the reviewer panes", and in a project with no temp
  seat at all (no free slot, no reviewer model, an unverified profile) the
  list is empty: `the seats are ; look at the reviewer panes …`.
