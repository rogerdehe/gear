# T-394 — report

A stop the user asked for now stays stopped: `gear admin stop --hold` writes
`engine.hold` in the engine dir, and `fn ensure_engine` starts nothing while it
exists; `gear admin start` lifts the hold. Code change in
`crates/gear-cli/src/main.rs` only, tests where the crate keeps its CLI tests;
no other design taken.

## What changed

**`crates/gear-cli/src/main.rs`**

- `AdminOp::Stop` gained `#[arg(long)] hold: bool`; the new `AdminOp::Start`
  is listed with `run`, `admin stop`, … in `starts_engine` (it starts the
  engine itself, so it must not go through `ensure_engine` first).
- `hold_path(dir)` = `engine.hold` in the engine dir; `write_hold` writes
  `<UTC time> held by gear admin stop --hold`, `hold_engine` writes it and
  prints `engine held: no gear call starts it until \`gear admin start\``.
- `cmd_admin_stop(hold)`: after the stop, or when no engine runs, it writes the
  hold with `--hold`; a plain stop writes nothing (unchanged).
- `ensure_engine`: before the engine-target check and the lock it returns early
  when `engine.hold` exists, printing to stderr
  `gear: the engine is held (gear admin stop --hold); \`gear admin start\` resumes it`
  — once per call. The hold lives in the store's own engine dir, so a hold on
  one store never silences another.
- `cmd_admin_start()`: the same ctx check as `cmd_admin_stop` (agents may run
  neither), removes `engine.hold` (the user asked for it gone, so it goes
  whichever way the start goes), then starts the engine as `ensure_engine`
  does — registered store only (L-54), lock free → `spawn_engine` and
  `engine started (pid <pid>)`; lock held → `engine already running`.
- `stop_notice` (T-298) is unchanged; its call site keeps the same order: the
  projects' notice, then the wait, then the stop line, and with `--hold` the
  held line last.

**`crates/gear-cli/tests/it/engine_hold_contract.rs`** (new, registered in
`tests/it/main.rs`) — five CLI tests over a scratch engine dir, no Herdr, no
seat, no real store:

- `stop_with_hold_writes_the_hold_when_no_engine_runs`: stdout has
  `engine not running` and the held line; `engine.hold` holds the time and
  `held by gear admin stop --hold`.
- `a_plain_stop_writes_no_hold`.
- `a_held_engine_stays_down_and_the_call_says_so`: a `gear` call that starts the
  engine when its lock is free prints the held line on stderr and spawns
  nothing (no pid in `engine.lock`, no `engine.log`), the hold stays.
- `start_lifts_the_hold`: `admin start` removes `engine.hold`, and a second
  `start` with no hold only starts (and writes no hold).
- `agents_hold_and_start_nothing`: with `GEAR_CTX` set both commands are
  `FORBIDDEN` and neither a hold nor a lock is written.

## Checks

- `make check CRATE=gear-cli`: 162 tests run, 162 passed, 0 skipped (the five
  new ones among them).
- Hand run on a scratch store, as the user's shell (no `GEAR_CTX`):
  `admin stop --hold` → `engine not running`, held line, hold file
  `2026-10-29T02:08:11Z held by gear admin stop --hold`; the next bare `gear` →
  the held line on stderr and no engine; `admin start` → hold gone, exit 0.
- `cargo fmt` was not run: the tree is not rustfmt-clean (L: lane rules).

## Out of scope

- No doc/help text outside the new `#[arg]`/subcommand docs (`docs/PRD.md`,
  `docs/design/14-plugin.md`, the skill references still say a stop starts again
  on the next `gear` call) — the contract names `main.rs` only.
- `admin start` on a store that is not this Herdr session's store lifts the hold
  and starts nothing, silently, exactly as `ensure_engine` is silent there;
  a user outside Herdr gets no reason from `admin start`. Reporting that reason
  would be a usability call, not this contract.
- A held engine that the user stops without `--hold` behaves as before
  (restarts on the next call).
