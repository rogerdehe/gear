# T-329 — report

The store now owns a voyage's stations and the station of each task, so the
board's course is read from the store instead of a private helper that guessed
the meta format (M-4616). No schema step: both live in `meta`, so schema stays
v7.

## What changed

**`crates/gear-store/src/lib.rs`**

- `VoyageStation { id, needs }` with `#[derive(Debug, Clone, PartialEq, Eq)]`,
  beside the other row structs.
- In `impl Tx`, a section `// ---- stations (M5 S3)`:
  - `set_voyage_stations(project, milestone, stations)` writes the meta
    `voyage-stations:<project>:<milestone>` as one `<id>: <needs>` line per
    station, in order, joined by `"\n"`; an empty list writes `""`.
  - `voyage_stations(project, milestone)` reads it back; missing or `""` is
    empty, each line splits at its first `": "`.
  - `set_task_station(project, task, station)` writes
    `task-station:<project>:<task>` (`None` writes `""`).
  - `task_station(project, task)` returns `None` for missing or `""`.

**`crates/gear-board/src/stations.rs`** (T-334 was already on `origin/dev`, so
its temporary helper is removed, not added): `stations_of` and `station_of`
are gone; `progress` calls `tx.voyage_stations(project, milestone)` and
`tx.task_station(project, &task.id)` and maps `VoyageStation` straight into
`StationProgress`. No other board change.

## Tests

`crates/gear-store/tests/it/contract.rs`:

- `voyage_stations_round_trip_in_order` — two stations come back in plan order,
  and the raw meta is `S1: …\nS2: …`.
- `voyage_station_needs_keep_their_colons` — `"the board: all four views"`
  round-trips (the line splits at its first `": "` only).
- `an_empty_or_other_voyage_has_no_stations` — an empty list writes `""` and
  reads empty; another milestone and another project read empty.
- `a_task_station_round_trips_and_clears` — a station round-trips, another task
  and another project read `None`, `None` clears it.

## Out of scope

- Nothing writes stations yet: no plan parser, kickoff or CLI command fills
  either meta key (that is the later station-plan task). The board shows a
  voyage's stations only once something writes them.

  returns what was written. Nothing writes padded values today, so the visible
  behaviour is unchanged — logged rather than papered over.
