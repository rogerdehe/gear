# T-328 — report

A caller whose tools run in a daemon (OpenCode's `opencode serve`, Codex's
`codex app-server`) reaches no pane, so until now any tool shell of the same
daemon could keep another lane's `GEAR_CTX` claim: the pane only had to host an
agent of a daemon kind. Each daemon gives its tool shells the session they work
for (`OPENCODE_SESSION_ID`, `CODEX_THREAD_ID`); the claim is now checked against
the sessions GEAR records for the seat.

## What changed

**`crates/gear-app/src/identity.rs`**

- `pub struct DaemonSessions { opencode, codex }` (`Debug, Clone, Default,
  PartialEq, Eq`) with `from_vars(vars)`: `OPENCODE_SESSION_ID` and
  `CODEX_THREAD_ID`, an empty value read as `None`.
- `observe_via(env, herdr, ancestors) -> GearResult<Option<(Fingerprint, bool)>>`
  holds the body of the old `observe`; the bool is true exactly on the daemon
  branch (`real.is_none() && tools_outside_pane`). `observe` is now
  `observe_via(…).map(|found| found.map(|(fp, _)| fp))` — every existing caller
  (admin, whoami, classify) is unchanged.
- `prove_seat` takes `daemon: &DaemonSessions` after `ancestors`. After the
  existing `require_seat` check, when the daemon branch was taken and
  `env.ctx` is `Some`, it checks the session in a store read
  (`fn prove_daemon_session`): the seat's known sessions are its binding's
  `session_ref` (`tx.get_binding(&seat_id, ctx.generation)?`), the
  fingerprint's `session_ref` and the `sessions` of
  `tx.open_round_of_seat(&seat_id)?`, empty values dropped and duplicates
  removed. No known session → pass (nothing to prove against, as today).
  - `opencode`, `daemon.opencode` `None` → `NotRegistered`
    "… is claimed from outside every pane without OPENCODE_SESSION_ID: an
    OpenCode tool shell always carries it, so this caller is not the seat's
    OpenCode session".
  - `opencode`, a session that is not one of the known ones → `NotRegistered`
    "… is claimed by OpenCode session <value>, but the seat's sessions are
    <known>: a caller may act only as the seat of its own session".
  - `codex`, `None` → pass; a thread that is not one of the known ones passes
    too — that the thread id equals the session GEAR records is not yet seen
    live, and this voyage's reviewers are Codex — and owes one captain item
    (`fn report_codex_thread`): thread `identity-codex:<seat>:<generation>`,
    `MsgKind::System`, `MsgState::Info`, not urgent, body "seat <seat> was used
    by Codex thread <value>, while the seat's sessions are <known>: if this
    repeats, a Codex agent may be acting as another seat", skipped when that
    thread already holds a message.
  - Every refusal goes through `fn report_claim`, as the other refusals of
    `prove_seat` — with no real pane the item lands in `identity:unknown`.
  - The kind checked is the seat's: the binding's `kind`, the fingerprint's
    when there is no binding (the spec names the binding's session only).

**`crates/gear-cli/src/main.rs`** — `fn observe_identity` passes
`&gear_app::identity::DaemonSessions::from_vars(|name| std::env::var(name).ok())`.

**`crates/gear-app/tests/it/app_identity.rs`** — the two existing `prove_seat`
calls take `&DaemonSessions::default()`, and three tests are added:

- `daemon_sessions_come_from_the_tool_shells_variables` — both names read, an
  empty value is `None`, nothing set is `DaemonSessions::default()`.
- `an_opencode_daemon_caller_proves_its_own_session` — lane `heat` bound with
  `session_ref` `ses_a`, the T-126 service ancestry: `ses_a` passes; `ses_b` is
  refused with the text above and writes one urgent item; no
  `OPENCODE_SESSION_ID` is refused; a seat with no known session (`heat2`)
  passes; a caller whose ancestry reaches its own pane (`LANE_CALLER`) is
  unaffected and needs no variable.
- `a_codex_daemon_caller_of_a_foreign_thread_owes_one_notice` — captain bound
  with `session_ref` `th_1`: `th_1` passes quietly, no `CODEX_THREAD_ID` passes
  quietly, `th_2` passes and writes one `Info` item (a second call writes no
  second one).

## Out of scope

- `whoami` still reports with `observe`, not `observe_via`: it never refuses, so
  it says nothing about the daemon session (the packet keeps the change to
  `prove_seat` and the CLI wiring).
- The Codex notice is written per seat and generation only; a different foreign
  thread on the same seat adds no second item — the packet's "skipped when that
  thread already holds a message".
- Whether a Codex thread id really equals the session GEAR records is not
  verified here: such a thread passes with a notice, as the packet decides.
