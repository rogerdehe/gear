# T-301 — report

A voyage id need not start with `M`. Nothing parsed or required the prefix (the id is the first word after
`# Milestone` / `milestone=`, taken as it is); the only place an id's shape mattered was the order of the snapshot's
voyage lines, which sorted by id, so `M10` came before `M9` whatever their departure. Two edits, as the packet says,
and no other design.

## What changed

**`crates/gear-app/src/home.rs`**, `fn snapshot` — the voyage lines sort by departure, then id:

```rust
voyages.sort_by(|left, right| {
    (left.departure.unwrap_or(i64::MAX), &left.milestone)
        .cmp(&(right.departure.unwrap_or(i64::MAX), &right.milestone))
});
```

The earliest departure first, a voyage that has not departed last, the id breaking the tie (so the list stays stable
when two voyages depart in the same second). The comment above it says why the id alone is no order.

**`skills/gear/references/conventions.md`**, §1, the first bullet that defines a voyage: one sentence added after the
folder convention — "Its id is any word without spaces (`M1`, `sprint-3`, `2026-q4`); this guide writes `M<n>`."

Nothing else changed: `crates/gear-app/src/time.rs` keeps its order (its voyages carry no departure), and no other
file was touched.

## Tests (`crates/gear-app/tests/it/voyage_contract.rs`, where the crate keeps its voyage/home-snapshot tests)

- `a_voyage_id_need_not_start_with_m` — a plan with `# Milestone sprint-3: the third sprint` and a task
  `milestone=sprint-3` applies; the voyage is stored as `sprint-3` (id, title, departure `NOW`, 1 task at
  departure), the task carries `milestone=sprint-3`, the home page shows `Voyage sprint-3 the third sprint`, and
  `gear_app::voyage::report(tx, "p", "sprint-3", …)` names the task (`report.time.tasks` → `["T-1"]`).
- `the_snapshot_lists_the_voyages_by_departure_not_by_id` — two open voyages; `M10` departed first is listed before
  `M9`, and the mirror case (`M9` departed first) is listed before `M10`. The second half is what the change decides:
  the id order alone puts `M10` first both times. (The acceptance's case alone passes before and after, so I asked;
  the captain answered B, both cases, contract v3 — which is what this test does. Test only, no code change.)
