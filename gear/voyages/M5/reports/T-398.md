# T-398 — report

The engine now says which build it runs, notices when the binary on disk is a
newer build, and writes one engine-log line for every release with the step
that asked for it and why (T-398; 2026-10-29: an hour on a replaced pre-fix
binary, and a log that said only `released: [seat]`).

## What changed

Four files, no other design.

**`crates/gear-cli/build.rs` (new)** — sets `GEAR_BUILD_SHA` from
`git rev-parse --short HEAD`, `unknown` when git is absent or fails, and
`cargo:rerun-if-changed` for `build.rs` and `../../.git/HEAD` so a new commit
rebuilds the sha.

**`crates/gear-cli/src/main.rs`**

- `fn engine_start_line(pid, db, version, build)` builds the start line; the
  engine prints `engine start pid=… db=… version=<CARGO_PKG_VERSION>
  build=<GEAR_BUILD_SHA>`.
- `struct BinaryWatch` reads the modification time of the engine's own
  `std::env::current_exe()` at start and `changed_once()` compares it each
  tick — once per engine run (`changed_once` sets `announced`). The watch is
  created in `run_engine`, passed to `run_engine_with`, where a change before a
  tick logs
  `engine: the binary on disk changed since this engine started; restart it to
  run the new build` and calls `announce_binary_changed`, which puts one
  `System` item in every project's captain inbox on thread
  `engine:binary-changed` (a project with no captain is skipped). A failing
  announcement is logged (`binary watch failed: …`) and never stops the loop.
- after every tick (a failing one included) the loop writes the lines
  `gear_engine::release::take_release_log()` returns into the engine log — the
  stamped writer lives here, not in `gear-engine`.

**`crates/gear-engine/src/release.rs`**

- `fn release_line(seat, from, reason, caller)` formats
  `release <seat> gen=<n> from=<state> reason=<reason> caller=<caller>`;
  `log_release` records it in a thread-local buffer (`take_release_log` drains
  it, capped at 256 lines) — thread-local so tests running side by side never
  share a buffer, and the engine (single thread) hands them to its log.
- `release_one` takes `caller: &str` and writes one line per release:
  - where it decides one (`Active`/`Standby` → `Releasing`): `from` is the
    state it leaves, `reason` its own (`review done` / `idle reviewer
    released`), `caller` the step that asked (`job-gone`, `idle-standby`,
    `checkout`, `repo`, `model`);
  - where it frees a seat another step put on its way out (the `Releasing`
    sweep, reached from the captain's release or a lowered quota): `from=
    releasing`, `reason` the one the seat carries, `caller=captain` — or
    `agent-gone` when the seat's reason is the engine's agent-gone release
    (`fn releasing_step`). A release this module decided is not logged twice.
- the three call sites in this file pass `job-gone`, `idle-standby` and the
  derived sweep step.

**`crates/gear-engine/src/review.rs`** — the three callers of `release_one`
pass `checkout` (a review checkout that failed three times), `repo` (a standby
reviewer moved to another repo) and `model` (a changed review model).

## Tests

- `gear-cli`, `the_engine_start_line_names_the_build_it_runs`: the exact line,
  and this binary's own line carries `version=` and a non-empty `build=`.
- `gear-cli`, `a_changed_binary_on_disk_is_told_once_over_two_ticks`: a scratch
  "binary" whose mtime moves after the watch started → one
  `engine: the binary on disk changed …` line and one captain item
  (`p:captain`, thread `engine:binary-changed`) over two ticks.
- `gear-engine`, `a_release_logs_its_reason_and_its_caller`: the idle sweep
  logs `release p:r-1 gen=1 from=standby reason=idle reviewer released
  caller=idle-standby`, and the next tick, which frees the seat, adds no second
  line.
- `gear-engine`, `a_seat_the_captain_released_names_its_caller_in_the_log`:
  `from=releasing … caller=captain`.
- `gear-engine`, `a_reviewer_whose_job_is_gone_logs_the_step_and_the_job`:
  `from=active reason=review done caller=job-gone`.

## Out of scope / notes

- **Question sent (M-5172)**: `gear-engine` has no engine-log writer
  (`lib.rs`/`TickReport` were not allowed edits), so my default was a
  thread-local buffer in `release.rs` drained by `gear-cli` into the stamped
  log; and the `Releasing` sweep has no name in the packet's caller list, so it
  logs `captain` (or `agent-gone` when the seat's own reason is the engine's
  agent-gone release). If the captain wants the line written elsewhere or a
  different label, it is a small change in `release.rs` and the drain in
  `main.rs`.
- The `Releasing` sweep frees a seat at most one tick after the decision, so a
  captain's release is visible in the log one tick later than the release.
- `release_dead_temps` and `cancel_start` release seats without `release_one`
  and so write no `release …` line: the packet named `release_one` only.
- Modification times come from the file system; a build that replaces the
  binary within the same second and preserves the mtime would not be noticed
  (the packet asked for the modification time).
