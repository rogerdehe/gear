# T-421 — report

`gear send` sends a commit, never a branch: a `--candidate` that is a ref is
resolved in the caller's working directory to the commit it points at, and a
value that names no commit there is refused before anything is stored.

## What changed

**`crates/gear-cli/src/main.rs`**

- New `candidate_commit(value)`: a value of 7 to 40 hex digits is a sha and is
  returned as it is; any other value is resolved with `git rev-parse --verify
  <value>^{commit}` (in the process working directory, which is the caller's)
  and the full sha printed by git is what is sent. A git that fails, or prints
  nothing, is a refusal (`BadFormat`) with exactly

  ```
  --candidate <value> is not a commit here: hand in the commit itself, e.g. --candidate $(git rev-parse HEAD)
  ```

- `run_send` resolves `c.candidate` before it builds `SendArgs`, so the store
  keeps `candidate` (the resolved sha); the "A result's candidate (T-45)"
  comment now says "the commit handed in".

**`crates/gear-app/src/tasks.rs`** — the T-118 refusal
(`submit_result`, a candidate that already failed) now ends with
` (commit your rework and hand in its sha: git rev-parse HEAD)`.

**Tests** — where each crate keeps them.

- `crates/gear-cli/src/main.rs` unit tests: `candidate_branch_is_sent_as_its_commit`
  (a scratch repo with a commit and branch `heat/t421`; the hand-in with
  `--candidate heat/t421` reaches the store as that branch's full sha),
  `candidate_that_is_no_commit_is_refused_and_stores_nothing` (the exact
  refusal text; attempt still `Started`, no candidate, the captain's inbox
  empty), `candidate_sha_is_sent_unchanged` (a 40-hex value in a directory that
  is not a repository goes through untouched, no git run). A shared
  `world_with_attempt()` fixture and the `git_in` / `in_dir` helpers.
- Existing candidates that are not shas were changed to shas, since a name is
  now resolved: `send_candidate_reaches_mail` `abc123` → `abc1234`,
  `direction_result_rejects_lane_and_other_reviewer` `abc123` → `abc1234` (it
  tests the `Forbidden` refusal, so its candidate has to be a sha),
  `direction_result_after_lane_submission_preserves_submitted_state`
  `candidate123` → `c0ffee1`.
- `crates/gear-app/tests/it/result_contract.rs`:
  `a_result_with_an_already_failed_candidate_is_refused` now asserts the
  refusal ends with `hand in its sha: git rev-parse HEAD)`.

## Out of scope (noticed, not changed)

- The resolution runs for every message kind that carries `--candidate`, not
  only results; only a result's candidate is stored as a commit, so the other
  kinds now cost one git call for a non-sha value. Harmless, but it could be
  limited to `kind == result`.
- `gear send` resolves against the process working directory. A caller whose
  shell is outside the worktree (or a lane that hands in from another
  directory) gets the refusal instead of a resolved sha; the message already
  says what to hand in.
