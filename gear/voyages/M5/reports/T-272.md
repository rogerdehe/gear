# T-272 — report

The plan and store half of the mechanical-task procedure: a plan task can be
marked mechanical, with the reason, as part of its contract. The engine's skip
of the review is a later hull task; nothing here makes a review be skipped.

## What changed

**`crates/gear-store` (schema v7).**

- `schema.sql`: `contracts.mechanical TEXT` — the reason; NULL means reviewed
  as today.
- `ContractRow` gains `pub mechanical: Option<String>`; `insert_contract`
  writes it (one more bind, `?10`), and the contract select of `get_contract`
  reads it back through `contract_from_row` (index 9). There is only that one
  contract select in the crate.
- `migrate.rs`: `SCHEMA_VERSION = 7`, a `step_6_to_7` in `STEPS` that adds the
  column when `column_exists` says it is missing (so a store a first attempt
  migrated is left alone), and the module comment says what v7 adds. Every
  existing contract ends NULL: the migration invents no reason.

**`crates/gear-app/src/draft.rs`.** `QueueItem` gains
`mechanical: Option<String>`; `parse_queue_field` reads a `mechanical` field as
its reason and refuses an empty one with ``mechanical` needs the reason the
gate alone proves this change`. The field takes part in the repeated-field and
unknown-field checks like every other one.

**`crates/gear-app/src/plan.rs`.**

- A `NEW` block's contract v1 takes `mechanical` from the item.
- `mechanical_changed` is compared the way `due_changed` is
  (`item.mechanical != contract.mechanical`), so setting it, changing it and
  dropping the field (which clears it) all open a new contract version.
- `contract_body` writes `mechanical: <reason>` after `evidence-due`, so the
  stored body carries it; `show` (`gear plan show`) prints it as a field the
  captain can copy back into the plan file.
- `render_task_packet`, in the Evidence section right after `Due:`, adds
  `Review: none — mechanical (<reason>): the merge gate is the only check, so
  run its command before you hand in.` when the adopted contract has a reason.

**`skills/gear/references/captain.md`.** The `# Queue` fields list gains
`mechanical` (the reason), with the rule: the task skips review and merges when
its gate passes — only for a change the gate proves on its own (deletions, a
rename, a named line); never for test logic or behaviour.

**The struct field's cost.** `ContractRow` is a plain struct with no
`Default`, so every literal in the workspace needs the new field: 69 test
fixtures across `gear-store`, `gear-app`, `gear-engine`, `gear-board`,
`gear-forge` and `gear-cli` now say `mechanical: None` (that is the whole of
the engine/cli/board/forge change — no behaviour).

## Tests

`crates/gear-store/tests/it/v7_contract.rs` (new module in `main.rs`):

- `a_v6_store_migrates_to_v7_with_existing_contracts_null` — a store of two
  tasks and two contracts, with the column dropped and `schema_version`
  stamped 6, opens as v7 and both contracts read `mechanical: None` with their
  rows intact.
- `a_mechanical_contract_round_trips` — a contract written with the reason
  reads back as the row it was written as; one without stays NULL.

`crates/gear-app/src/plan.rs` (tests module):

- `a_mechanical_task_stores_its_reason_and_the_block_shows_it` — `NEW` with
  `mechanical: delete three dead fns` stores it on contract v1, and `show`
  prints `mechanical: delete three dead fns`.
- `clearing_the_mechanical_reason_opens_a_contract_version` — re-applying the
  block without the field reports `("T-1", 2)` in `contract_changed` and v2 has
  NULL.
- `a_mechanical_field_without_a_reason_is_refused` — `mechanical:` with an
  empty value is `BadFormat` with the exact text.

`crates/gear-app/tests/it/packet_contract.rs`:

- `a_mechanical_task_says_the_gate_is_the_only_check` — the plain task's packet
  has no `Review: none`; with a contract v2 the open attempt adopted, the
  packet carries the whole Review line.
