# T-360 attempt 2 — what to handle under the lanes, and the quota on one line

## What changed

- `crates/gear-board/src/lib.rs`
  - `ProjectBoard.waiting_on: Vec<String>`: for the shown tasks in plan order,
    a Review task names the Active temp seat holding it and the minutes since
    its open round (`tx.open_round_of_seat`, else the seat's `state_since`),
    an Asking task names its lane and the captain's answer, a Verdict task the
    captain's verdict, a MergeFailed task the captain.
  - `TaskBoard.rank`: the store's plan rank, so the Now view's items follow the
    plan across lanes (F2).
- `crates/gear-board/src/idle.rs`: `pub fn month_day(ts)` — the local date as
  `Oct 30` (the month names moved to a module constant, `localtime_r` as
  `clock`), for a quota reset more than a day away.
- `crates/gear-board/src/frame.rs`
  - `needs_a_look` returns strings for the shown tasks in plan order (flattened
    lanes sorted by rank, then id) whose stage is open: `round <n>,
    <actual>/<est>m: the captain scopes what is left`, else `<actual>/<est>m,
    past its estimate: the captain scopes what is left`. The "overloaded" item
    and the merged history are gone.
  - `view_now` from `top + lanes + 3`: `TO HANDLE (n)` (Bold+Warn when n > 0,
    else Bold); each item `<mark> <text>` at 3 in its colour — needs-a-look
    `⚠` Warn, a forecast wait `⚠` Bad, `waiting_on` `⏳` plain (the wide glyph
    keeps its two cells) — or `nothing` Dim at 3; one blank row; `Quota` Bold
    at 1 and, from x = 9, every window of every reading ordered by reset (none
    last, then provider) as `<provider> <window> <n>% · resets <clock within a
    day, else month_day>` (`-` with no reset) coloured from 90 %/60 %/below, or
    `none read yet` Dim; then a blank row and the T-188 overlaps plain at 1.
    The old NEEDS A LOOK, QUOTA block and DONE SENTENCE are gone.
- `crates/gear-board/tests/it/golden_fixture.rs`: the project now configures
  the two providers the prototype's quota line draws (`tokenrhythm`, `codex`).
  T-383 shows a reading only when the project reads it now; without the config
  the board drew `none read yet` where the golden has the line.

## F1 of the review: the block is compared at its anchor

The two `T-360` PENDING entries are removed. `failures` in
`golden_contract.rs` now finds the `TO HANDLE (` block in both the board frame
and the golden frame and, from the prototype's block minus one row (the blank
row above it), compares the board's row `r − (prototype row − board row)` with
the prototype's `r`. The footer keeps its absolute row. So the task's whole
block — heading, items, quota line, overlaps and the blank rows after — is
checked cell by cell at its documented `top + lanes + 3` anchor, independent of
the header rows other tasks still change. The new
`the_to_handle_block_sits_at_its_anchor` names the remaining difference apart:
the prototype's block is `14 − layout.top` rows lower (one row until T-356
lands), and zero after. `now_folded` and `now_open` pass with the entries gone.

TO HANDLE heading and the item mark colours instead of the removed heading.
