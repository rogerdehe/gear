# T-303 — report

`- release <reviewer>` now takes a reviewer whose agent is gone even while it
holds a task, and a staff line whose target is already reached says so in the
apply result instead of passing silently. The code change is
`crates/gear-app/src/plan.rs` only; the tests are in the crate's
`tests/it/plan_staff_contract.rs`.

## What changed

**`crates/gear-app/src/plan.rs`**

- `fn release_seat` passes `agents` through to `fn release_reviewer`, whose
  signature is now `(tx, seat, name, agents, now)`.
- `fn release_reviewer`, for a reviewer **with a task**, reads the seat's
  binding at its generation (Active only, as `release_lane` does) and decides
  on the session's agents:
  - **binding Active, `agents` Some, an agent of the binding's `kind` in its
    `pane_id`** — its agent is there: refused as today, `"<name> is reviewing
    <task>"`, nothing written.
  - **binding Active, `agents` Some, no such agent** — its agent is gone
    mid-review: `tx.clear_seat_task`, then the seat goes to `Releasing` with
    the reason `"released by the captain: its agent is gone mid-review"`. The
    task is untouched (stays `Verifying` with its attempt handed in), so the
    engine's normal `start_reviews` pass starts the review again.
  - **binding Active, `agents` None** — refused with `"<name> is reviewing
    <task> (the session's agents were not read, so GEAR cannot tell whether
    its agent is gone)"`; nothing written (an unread observation is not
    "gone", as for a lane).
  - **no Active binding** — refused as today (`"<name> is reviewing <task>"`):
    the packet's release branch is stated for an Active binding, and anything
    outside it keeps today's refusal.
  A reviewer **without a task** behaves exactly as today (Standby →
  `Releasing`, other states refused). The doc comments of `fn release_seat`
  and `fn release_reviewer` say the new behaviour.
- In the lane staff loop (`fn apply_queue`), the `seat.state == target` branch
  (already there — the decision is still recorded once, and `staffed` is still
  not extended, as before) now also pushes to `warnings`:
  `"- <verb> <lane>: the lane is already <state>, nothing to do"`, with the
  line's verb (`park`/`hold`/`retire`) and `target.as_str()`.

## Tests

**`crates/gear-app/tests/it/plan_staff_contract.rs`**

- `release_takes_a_reviewer_whose_agent_is_gone` — a world with `T-12`
  `Verifying` and attempt 1 `Submitted` (inserted rows), plus `seed_temp_seat`
  `review-1` on `T-12` in pane `w1:p5` (kind `codex`). With an agent of that
  kind in that pane the line is refused with `"review-1 is reviewing T-12"`
  and nothing is written; with `agents` `None` the refusal still contains
  `"review-1 is reviewing T-12"` (and `"the session's agents were not read"`)
  with nothing written; with a session that has only `heat`'s agent the line
  is applied (`staffed == ["release review-1"]`), the seat is `Releasing` with
  the new reason and no task, `T-12` is still `Verifying`, and its attempt is
  still `Submitted`.
- `a_staff_line_that_does_nothing_says_so` — `- hold heat reason=x` on a lane
  that is already `Held` applies and its result warns
  `"- hold heat: the lane is already held, nothing to do"`; the seat stays
  `Held`.
- `release_brings_a_standby_reviewer_back` (T-140) is unchanged and still
  passes: its `review-1` refusal runs with `agents` `None` in `run_at`, so it
  takes the new "agents were not read" path; its assertions are on the
  substring `"review-1 is reviewing T-12"` and on nothing being written, both
  still true.

## Out of scope

- A reviewer with a task and **no Active binding** (or a binding of another
  generation) is refused as today. The packet states the release only for a
  binding that is Active; whether a missing binding should also count as
  "gone" is a design question I did not take.
- `gear plan check` (the dry run) does not print the new "already …" warning:
  the packet asks for it in `apply_queue`'s staff loop, and the check path
  does not run that loop.
- The T-140 doc comment on `fn release_reviewer` still says a reviewer in any
  other non-Standby state is refused; a reviewer in `Releasing` with a task
  gets the "is reviewing" refusal first, as before. No behaviour change was
  asked for there.
