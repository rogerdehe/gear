# T-307 — report

An OpenCode catalogue that cannot be read is no longer reported as "model
absent" (T-94 F6). Before, `derived_labels` returned `None` both when
`model.list` answered without the model and when the call failed, its data was
not a list, or the list was empty; `ensure_model` then flagged the seat with
"… is not in OpenCode's model list", sending the captain after a model id that
was right.

## What changed

`crates/gear-engine/src/opencode.rs`, `derived_labels` now returns
`Result<Option<ModelSwitch>, String>`:

- `Ok(Some(labels))` — the model is in the catalogue (labels exactly as before,
  `<model name> <provider name>`).
- `Ok(None)` — the id has no `/`, or the list was read, is not empty, and has no
  such model. That is a real absence; the caller keeps its own refusal.
- `Err(<reason>)` — the catalogue could not be read: the `opencode_api` error
  text, `model.list did not return a list` when `data` is not an array,
  `the model list is not loaded yet` when the list is empty, and
  `provider.list has no name for <provider>` when `provider_display_name`
  returns `None`. The old fallback to the provider id as a label is gone: it was
  a text no status bar shows.

`crates/gear-engine/src/switch.rs`:

- `ensure_model` — `Ok(None)` keeps today's Failed text. Any `Err(reason)`,
  the not-loaded case included (a `Waiting` gate would keep a start pending with
  nothing that ends it), fails with
  `OpenCode's model list could not be read (<reason>), so <model> could not be
  checked; it is not known to be absent: name [models.switch."<model>"] labels
  (picker, bar), or check `opencode models``.
- `plan_target` uses only `Ok(Some(labels))`, ignoring `Ok(None)` and `Err` as
  it ignored `None` before.

No other file changed.

## Tests

`crates/gear-engine/src/opencode.rs` (the fakes of
`a_model_without_labels_takes_them_from_the_catalogue`): that test now pins the
found case (`Ok(Some(..))`), the absent case (`Ok(None)`), and the variant ride
along. New `an_unreadable_catalogue_is_an_error_not_an_absent_model`: a failed
API call yields `Err` with its own text (`connection refused`), a non-array
`data` yields `model.list did not return a list`, an empty list yields
`the model list is not loaded yet`, and a provider missing from `provider.list`
yields `provider.list has no name for minimax-cn` (no provider-id label).

`crates/gear-engine/src/switch.rs`: new
`an_unreadable_catalogue_is_not_reported_as_an_absent_model` (a failed call
fails the gate with "could not be read" plus the reason, and the text never
contains "is not in OpenCode's model list") and
`an_empty_catalogue_says_it_is_not_loaded_yet` (the gate fails with "the model
list is not loaded yet", again never the absent-model text). A `chain_config()`
helper gives a config with no `[models.switch]` entry so the derived path runs.
