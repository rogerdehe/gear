# T-402 — report (contract v2)

A merged task branch whose only commits past the candidate are the lane's
report is now closed quietly: it is deleted with the other closed branches and
the captain is not rung for it.

## The change

`crates/gear-engine/src/merge.rs`, `fn close_branches` only. In the branch that
keeps a task branch with commits not on the integration branch, the files those
commits change are listed with

    git diff --name-only HEAD...<remote>/<branch>

When the list is non-empty and every path lies in a `reports/` directory (a
`/reports/` path segment, per `is_report_path`), the branch is deleted exactly
as the other closed branches are and is added to `closed`. Otherwise it is kept
and its commits are named in `left`, as today, so the captain still gets the
`left on …` item.

## Tests

Both are in the crate's own `mod tests` at the bottom of `merge.rs` (unit
tests, no integration test file added):

- `a_branch_whose_only_commits_past_the_candidate_are_reports_is_closed` — a
  queued merge of T-5 whose task branch carries one commit past the candidate
  that adds only `gear/voyages/M1/reports/T-5.md`: the merge result names the
  closed branches and carries no `left on` line, `heat/t5` and `review/t5` are
  gone from origin, and the captain's messages since 0 are empty (no item).
- `a_branch_that_moved_past_the_candidate_merges_the_candidate_only` (T-61,
  extended) — the extra commit adds `sneaky.txt`, a source file: the branch
  stays, `review/t5` is closed, and the merge line names the commit after
  `commits after the approved candidate, not merged:` as before.

## Checks

`make check CRATE=gear-engine` — 761 tests run, 761 passed.

## Out of scope

- A branch ahead of the candidate whose commits change no file at all (empty
  commits only) keeps the old behaviour: it stays and is named, because the
  diff list is empty and the rule only closes a non-empty list of report
  paths.
- `git diff` failing (a ref the fetch did not bring) also keeps the old
  behaviour: the branch stays and is named.
- Paths are taken literally as the spec says (`/reports/` as a segment), so a
  top-level `reports/T-5.md` in a repository whose root is the reports
  directory does not count.
