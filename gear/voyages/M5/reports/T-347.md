# T-347 — report

The lane lines name a task's stage in the same words as the board's views
(backlog "Finer task stages": board, Now view, lane lines and the home
snapshot use the same words). The board's lane line and the captain's home
snapshot no longer fall back to the state words (`in progress`, `waiting`,
`in review`): they read the stage the graph gives the task (`working`,
`handed in, waits for a reviewer`, …).

## What changed

**`crates/gear-board/src/graph.rs`**

- `Stage::words_of(stage, deps, rounds, moved_to)` is the new helper: the
  prototype's STAGE words, from the facts alone — no `GraphTask` needed.
- `Stage::words(task)` is now one line: it calls `words_of` with the task's
  `deps`, `rounds` and `moved_to`, so there is one wording for both readers.
- `fn stage_of` is `pub(crate)`: the board's lane model reads the same stage
  as the graph.

**`crates/gear-board/src/lib.rs`**

- `TaskBoard` gains `pub stage: graph::Stage` and `pub stage_words: String`.
- `fn project_with_agents` fills them from `graph::stage_of(tx, project, task)`
  and `graph::Stage::words_of(stage, &task.deps, rounds, None)` (a `TaskRow`
  has no `moved_to`; the graph's is `None` too). `rounds` is read once and
  used both for the field and for the rework word.
- `fn lane_line`: the current task is the first task of the lane whose
  `stage.is_open()`, printed `<id> <stage_words>`; a lane with no open task
  keeps `no current task` (and the `helping …` text of T-323 when it helps).

**`crates/gear-board/src/frame.rs`, `fn styled_lane_panel`** — NOW lists every
task whose stage is open with its `symbol()`, its colour and the same words
(now via `graph::Stage::words_of`); LEFT lists the `Deps` and `Queued` ones,
as before.

`crates/gear-app/src/home.rs` needed no code change: its snapshot lines come
from `gear_board::lane_line`. Only the tests' expected strings moved.

## Tests

**`crates/gear-board/tests/it/board_contract.rs`**

- the fixture `world()` now carries the attempts behind its states (T-2
  `Started`, T-3 `Submitted`), because the lane line names the stage: a task
  row that says `Running`/`Waiting` with no attempt has no stage to name.
- `the_lane_line_names_the_stage_in_the_words_of_the_graph` (new): the lane
  line reads `runtime · agent unknown · T-2 working · 1 queued` (a lane
  working on attempt 1) and `data · agent unknown · T-3 handed in, waits for
  a reviewer · 0 queued` (a lane whose task waits for a reviewer); the
  `TaskBoard` carries `Stage::Handed` and that same `stage_words`.
- the queue and observation tests that carried `T-2 in progress` /
  `T-3 waiting` in the lane line now expect the stage words (the per-task
  listing lines below the lane head keep the state words, unchanged).

**`crates/gear-app/tests/it/app_home.rs`** —
`the_captain_home_starts_with_the_snapshot_before_the_inbox` seeds the
`Started` attempt of T-1 and expects the snapshot line
`heat · agent working · T-1 working · 1 queued`.

## Out of scope

- A task row in a state that implies work (`Running`, `Waiting`,
  `Verifying`) with **no attempt row** now has no open stage, so its lane
  reads `no current task` where it used to read the state word. The engine
  always writes the attempt with the delivery, so this is a hand-made or
  legacy store, not normal use; logged here rather than worked around.
- A `Cancelled` task that the voyage filter keeps (it is terminal but of the
  current milestone) gets its stage from `stage_of`, which has no cancelled
  ending; it can read `queued` instead of `cancelled` in `TaskBoard::state`'s
  neighbours. The lane line's open-stage rule does not pick it up.
- The JSON `state` of a lane's tasks and the per-task lines under a lane head
  still use `state_word`; the packet names the lane line and the Now view
  only.
