# T-314 — report

The identity refusal now names the Herdr socket it asked and the ancestors it
matched, so a "no pane of this session runs this process" refusal can be traced
afterwards (M4.2 #18).

## What changed

**`crates/gear-herdr/src/lib.rs`.**

- `trait HerdrRead` gains `fn socket(&self) -> Option<String> { None }` — the
  door's own socket, for an error a reader can trace. The default keeps every
  other implementor (`FakeHerdr` before this task, the `NoKeys` example wrapper
  in `crates/gear-engine/examples/opencode_live.rs`) compiling unchanged.
- `SocketHerdr` gains `socket: std::path::PathBuf`, set in `connect` from the
  `socket_path` it was given; `HerdrRead::socket` returns it lossily as a
  `String`.

**`crates/gear-herdr/src/fake.rs`.** `FakeHerdr` gains
`pub socket: Option<String>` (default `None` through the derived `Default`),
returned by its `socket`.

**`crates/gear-app/src/identity.rs`.** `observe`'s refusal message now ends with
` (asked Herdr at <socket, or "an unnamed Herdr">; this process's ancestry: <ancestors joined by " < ">)`.
The rule itself is unchanged: the `where_` text, the daemon exception and the
error code are as before.

## Tests

`crates/gear-app/tests/it/app_identity.rs`,
`the_refusal_names_the_herdr_socket_and_the_ancestry`: with
`herdr.socket = Some("/s/herdr.sock")` and ancestors `[30, 20, 10]` the refusal
contains `asked Herdr at /s/herdr.sock; this process's ancestry: 30 < 20 < 10`;
with no socket it contains `an unnamed Herdr`. The pane agent is `claude`, not a
daemon kind, so the daemon exception cannot accept the claim.
