# T-286 — report

A seat whose CLI is not installed now says so and stops: the start failure is
classified by the shell line on the pane, and a missing CLI is never mistaken
for a quota stop that walks the model chain.

## What changed

**`crates/gear-engine/src/start.rs`**

- `pub(crate) fn cli_missing(screen: &str, kind: &str) -> Option<String>` — the
  first line of `screen` that contains `kind` and either `command not found` or
  `: not found`, trimmed. Covers zsh (`zsh: command not found: codex`), bash
  (`bash: codex: command not found`) and dash (`sh: 1: codex: not found`).
- `pub(crate) fn cli_missing_text(kind: &str, line: &str) -> String` — the
  reason: "the {kind} CLI is not installed or not on PATH (the pane says:
  {line}); install it or fix PATH, then resolve this item — GEAR does not move
  this seat to another model for it".

**`crates/gear-engine/src/onboard.rs`**

- New private `start_failure(herdr, pane, kind, outcome)`: reads
  `herdr.read_tail(pane, 16)` and returns `cli_missing_text` when the pane names
  the missing CLI, else today's `step_failure("agent_start", …)`.
- Both failed-start arms (`onboard_seat`, `resume_busy_start`) return
  `start_failure(...)` instead of the generic text. A failed start without the
  line keeps today's behaviour.

**`crates/gear-engine/src/review.rs`**

- `start_reviewer`'s failed-start arm reads the pane's last 16 lines before
  `park`; a missing CLI parks the reviewer with `cli_missing_text(kind, …)`.

**`crates/gear-engine/src/restart.rs`**

- `start`'s generic `Refused` arm flags with `cli_missing_text(&plan.cli, …)`
  when the pane names the missing CLI (else today's
  `agent_start refused (…)` text), clearing the plan as before.
- `start`'s `Uncertain` arm with a missing CLI flags and clears the plan like
  the `Refused` arm instead of `wait` — a fallback whose next CLI is missing is
  no longer a switch that never ends.

Tests (in the crate's own test modules, plus the quota fixtures of
`a_quota_stop_restarts_the_lane_on_another_cli`):

- `start::tests::the_three_shells_that_say_a_cli_is_missing` — the three shell
  lines give `Some` for `codex`; `command not found: pi` gives `None`.
- `onboard::tests::a_lane_whose_cli_is_missing_parks_with_the_install` — lane
  with a codex CLI, `refuse_starts = ("agent_start_timeout", 1)`, pane screen
  `zsh: command not found: codex`: the lane parks in NeedsCheck with the text.
- `onboard::tests::a_refused_start_without_a_missing_cli_keeps_its_reason` — the
  same refusal with `error: provider timeout` keeps
  `agent_start: refused (agent_start_timeout)`.
- `review::tests::a_reviewer_whose_cli_is_missing_parks_with_the_install` — the
  reviewer parks (Unknown) with the text.
- `quota::tests::a_cross_cli_restart_to_a_missing_cli_flags_the_seat_once` — the
  cross-CLI restart of the quota fixture refuses with
  `agent_start_timeout`, the pane says the codex CLI is missing: the seat is
  flagged with the text in NeedsCheck, `restart::pending` is None, and the next
  tick sends no second `agent_start`.
- `quota::tests::an_uncertain_cross_cli_start_with_a_missing_cli_flags_instead_of_waiting`
  — an `Uncertain` start with that screen flags and clears instead of waiting,
  and no later tick starts again.

No other file changed (`quota.rs` changes are its test module and a test-only
`Inject` import). The only `next_entry` call is still
`quota::QuotaPolicy::Fallback` on a confirmed quota/error signal of an idle
agent; nothing on a failed start steps the chain.
