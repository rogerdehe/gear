# T-278 — report

`gear board` now names its own Herdr tab, so a captain who opens the board in a
new tab no longer sees a bare number in the tab bar.

## What changed

**`crates/gear-herdr/src/lib.rs`.**

- `trait HerdrAct` gains `fn tab_rename(&mut self, tab_id: &str, label: &str) -> Outcome<()>`.
- `impl HerdrAct for SocketHerdr`: `tab.rename` with
  `{"tab_id": tab_id, "label": label}`, like `agent_rename`, its errors through
  the same `outcome_from_error` (a transport error is `Uncertain`, a protocol
  refusal `Refused`).

**`crates/gear-herdr/src/fake.rs`.** `Call::TabRename { tab_id, label }`; the
fake records the call and answers `Ok` (injection still applies, so a test can
make it `Refused`/`Uncertain`). `FakeHerdr::tab_renames_to(label)` returns the
tab ids renamed to a label, in call order, next to `renames_to`.

**`crates/gear-engine/examples/opencode_live.rs`.** `NoKeys` forwards
`tab_rename` to the wrapped client, as it does every other trait method.

**`crates/gear-cli/src/main.rs`.**
- `cmd_board` ends with `draw_board(&mut store, &opts, herdr.as_mut(), herdr_tab_id(), &mut out)`.
- `draw_board<H: HerdrAct>` renames the tab first, then calls
  `gear_board::run` with the same client as `&mut dyn HerdrRead`. When
  `opts.json` is set, or `HERDR_TAB_ID` is absent/empty, it renames nothing.
- `board_tab_label(project)` is `<project> board`, or `GEAR board` when the
  board shows every project (`opts.project` is `None`).
- The rename's outcome is dropped (`let _ =`): a refused or uncertain rename
  is ignored and the board still starts and draws.
- `herdr_tab_id()` reads `HERDR_TAB_ID`, treating an empty value as absent — a
  shell outside Herdr has none.

**`skills/gear/references/captain.md`.** The departure sentence now reads "a
Herdr tab running `gear board` (the board labels its tab `<project> board`)".

## Tests

**`crates/gear-herdr/src/fake.rs`** (tests module):
`tab_rename_is_recorded_with_its_tab_and_label` — the call is recorded as
`Call::TabRename { tab_id: "w1:t2", label: "gear board" }`, `tab_renames_to`
finds it, and an injected refusal still records the call and answers
`Refused`.

**`crates/gear-cli/src/main.rs`** (tests module):
`the_board_names_its_herdr_tab_before_it_draws` — with `HERDR_TAB_ID=w1:t2`:
- a board of project `p` draws and renames tab `w1:t2` to `p board`;
- a second run whose stdout refuses the write (`NoDraw`) still leaves the tab
  named, which is what proves the rename comes before the draw;
- the board that shows every project renames to `GEAR board`;
- with `json: true` the fake recorded no call at all, so `--json` renames
  nothing.

## Out of scope

- The tab label is fixed at departure: a board that switches to another
  project inside the interactive view does not relabel its tab (the packet
  names the label at start only).
- `HERDR_TAB_ID` is read but not validated; an id Herdr does not know is a
  refusal the board ignores, as the packet asks.
- Other tab-naming opportunities (a lane's own tab, a review seat's tab) were
  not touched.
