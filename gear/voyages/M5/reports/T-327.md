# T-327 — report

A lane released for a quota wait (T-326) now comes back at the reset **in the
same pane and worktree**, with its session resumed, and is told to continue.
Before, the Parked branch offered two wakes that both need a live agent: the
source wake types the Continue into the pane (a shell after the release) and
the `parked_until` wake switches the model of a live agent in place. Neither can
work for a released lane, so `crate::restart` now starts the same CLI again and
delivers the Continue when the agent is up.

## What changed

**`crates/gear-engine/src/quota.rs` only.**

- New `fn end_wait_pause(tx, project, seat, wait, now)` factors the pause writes
  out of `wake_from_source`: for a source wait with `pause` true it closes the
  open `quota` pause row and adds the round's pause for the wait
  (`now - wait.started_at`). `wake_from_source` and `bring_back` both call it,
  so the books are written the same way in both wakes.
- `apply_quota_policy_with`, `if seat.state == SeatState::Parked` branch, after
  `release_for_wait` and before `wake_from_source`: when the meta
  `meta_key("wait_released", &seat.id)` is `"1"` and the wait is over — the
  source wait of `load_wait` with `until <= now`, else `parked_until(store,
  &seat.id)?` with `until <= now` — it calls the new
  `fn bring_back(store, herdr, cfg, profiles, project, &config, seat, now)`,
  pushes its line when `Some`, and `continue`s. A Parked seat without the
  released meta (or before its reset) falls through to today's paths unchanged.
- New `fn bring_back(...) -> GearResult<Option<String>>`:
  1. in **one** write: `end_wait_pause` for a source wait, then clears the wait
     meta (`wait_meta_key`), `quota_meta_key`, `meta_key("quota_error_ticks",
     …)`, `meta_key("resume", …)` and `meta_key("wait_released", …)` (the
     counters to `"0"` like the in-place wake, the rest to `""`);
  2. builds the target entry as `restart_missing_jobs` (lib.rs) builds a lane's:
     the first entry of `crate::model::role_chain(&config, &seat.name)`, as
     `gear_app::config::ModelEntry::Entry(ModelSpec { model, cli: Some(entry
     .cli() or the lane's kind), args: entry.args().to_vec(), context_window_k:
     None })`. An empty chain flags the seat with `flag_and_alert(store,
     project, seat, "quota: the lane's chain is empty; no model to bring it
     back on", now)` and returns `None`;
  3. calls `crate::restart::advance(store, herdr, cfg, profiles, project, seat,
     Some(&entry), now)` and returns its line. Its same-CLI plan resumes
     `crate::session::round_session`, phase `Stop` sees the shell and goes to
     `Start`, and `finish` sets the seat `Active` on the new generation and
     delivers the Continue line of `crate::quota::resume_delivery`. A restart
     still pending continues on later ticks through the `crate::restart::pending`
     check at the top of the loop.
- Test fixtures only (`#[cfg(test)]`): `world` now delegates to
  `world_kind(config, kind)`; new `config_pi(chain, policy, on_wait)` (the
  `config_full` project with the lane's kind/profile on pi — pi's profile has
  `session_ref` and `--session` resume args), `cfg_pi(dir)` (the builtin
  profiles, including pi, plus a writable `db_path` for the rules file),
  `source_world_pi(key, on_wait)` and `released(store, wait, until)` (the state
  a release leaves: round open with session `s-1`, seat Parked, release marked,
  wait books written, an open quota pause row for a source wait).

## Tests

`crates/gear-engine/src/quota.rs`:

- `a_released_lane_comes_back_at_the_reset_and_is_told_to_continue` — a released
  pi lane (open round session `s-1`, pane a shell, open `quota` pause) at its
  reset: one `AgentStart` for `pi` in the same pane whose args carry
  `["--session", "s-1"]`; the seat ends `Active` on generation 2 with the
  binding `Active` on `s-1`; exactly one Deliver op, "Continue T-1: run
  `gear` first"; no "Continue T-1: your quota is back." prompt ever typed; the wait is
  empty and the `wait_released`/`resume` metas are empty; the pause row is
  closed at the reset and the round's clock paused for the wait.
- `a_released_policy_park_comes_back_at_its_deadline` — the same comeback for a
  `fallback` policy park (no source wait, only `parked_until`): same start, same
  resume args, same one delivery; no pause row and no round pause (a policy park
  has none).
- `a_kept_lane_at_its_reset_gets_todays_continue` — a lane whose wait is too
  short to release (T-326) at its reset: today's `Continue T-1: your quota is
  back.` delivery, the seat `Active`, nothing started, no release meta.
