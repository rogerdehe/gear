# T-341 — report

The board has the four views the user chose (Now, Tasks, Cost, Log) and one
render state instead of M4's five tabs; the Workload view and its burn-up are
gone; the footer is the prototype's.

## What changed

**`crates/gear-board/src/frame.rs`**

- `Tab` is `Now`, `Tasks`, `Cost`, `Log` (numbers 1-4, titles "Now", "Tasks",
  "Cost", "Log"; `next`/`previous` cycle through the four; `all()` returns the
  four). `of_number` maps 1-4 and nothing else, so key 5 changes nothing.
- `pub struct Screen { pub tab: Tab, pub selected: usize, pub detail: bool, pub size: (usize, usize) }`.
  `detail` is carried and not read yet (the `d` key comes with the folded
  header task).
- `fn canvas(board, screen: &Screen, panel: Option<&[Line]>) -> Canvas` and
  `fn frame(board, screen: &Screen, panel: Option<&[String]>) -> String`.
- `fn view` dispatches: `Tasks` → today's graph view, `Cost` → today's
  Tokens view, `Log` → today's Decisions view. `fn view_workload` (and its
  burn-up) is deleted; `VoyageReport.burn_up` stays.
- `FOOTER` is the prototype's footer text, without its trailing
  `PROTOTYPE …` part, drawn at column 1 of the last row in Dim:

  `←→ / Tab / 1-4 / click: views · click a voyage · [ ] older / newer voyage · d header details · ↑↓ select · Enter: a lane's work / a task's rounds / a lane's tasks · q quit`

**`crates/gear-board/src/lib.rs`**

- `run_with` keeps a `Screen` (size refreshed from `keys.size()` each frame);
  keys 1-4, arrows and Tab as before; `detail` stays `false`.
- `tab_of`: `View::Lanes` → Now, `View::Deps`/`View::Graph` → Tasks.
- `open_panel`: Now → the lane panel, Tasks → the task panel, Cost → the task
  panel of `frame::token_tasks` (as Tokens did), Log → none.
- `print_once` builds the `Screen` for the static frame.

`gear_board::View` and gear-cli are unchanged.

## Tests

`crates/gear-board/tests/it/main.rs` gains a small `screen(tab, selected, size)`
helper (the new call shape); every existing frame/canvas call in the crate's
tests uses it.

- `board_contract.rs` — new `the_tab_row_has_the_four_views_of_the_user`:
  `Tab::all()` labels are ` 1 Now `, ` 2 Tasks `, ` 3 Cost `, ` 4 Log `;
  `Tab::of_number(5)` is `None` (key 5 changes nothing); `Tab::Log.next()` is
  `Tab::Now` (Right from Log wraps to Now); the tab row of a 160-column frame
  holds the four labels; no view draws `BURN-UP`; the last row of a
  160-column frame starts with ` ←→ / Tab / 1-4` and column 1 is Dim.
  The pty tests now delimit a frame by the footer's visible start
  (`←→ / Tab / 1-4`) and check the footer's row against it — the prototype's
  footer is longer than an 80-column terminal, so `q quit` is no longer on the
  visible row. Tab-label clicks follow `2 Tasks`.
- `workload_contract.rs` — the two Workload-view tests (and the
  `finished_world` fixture only they used) are deleted with the view; the lane
  projection, burn-up data and lane-panel tests stay. The module doc no longer
  names the Workload view.
- `colour_contract.rs` — the Workload column-alignment block is deleted; the
  remaining blocks use the new tab names (Tasks, Log, Cost).
- `decisions_contract.rs`, `golden_contract.rs`, `overlaps_contract.rs` — call
  shape and tab names only.
