# T-318 — report

A source checkout now has an install step: `make install` builds `gear-cli` in
release mode and puts a **link** — not a copy — at `$PREFIX/bin/gear`, so every
later `cargo build --release` is the binary the agents run.

## What changed

**`Makefile`**

- `PREFIX ?= $(HOME)/.local` next to the targets.
- New target, first after the header comment:

      install: ## a source checkout's gear on PATH: release build, then a link in $(PREFIX)/bin
      	cargo build --release -p gear-cli
      	mkdir -p $(PREFIX)/bin
      	ln -sf $(CURDIR)/target/release/gear $(PREFIX)/bin/gear

- `install` joins `.PHONY` (`.PHONY: check gate full install`).

Nothing else in the Makefile moved: `check`, `gate` and `full` are unchanged.

**`README.md`**, after §Install (just before `## Start a project`), one
paragraph:

> **From a source checkout?** A checkout has no `gear` on PATH. Run
> `make install`: it builds `gear-cli` in release mode and links
> `$PREFIX/bin/gear` to `target/release/gear`. It is a link, not a copy, so
> every later `cargo build --release` is the binary the agents run. `PREFIX`
> defaults to `~/.local`, and `$PREFIX/bin` must be on PATH.
