# T-281 — report

Several fleets on one repository: the overlap check now compares a project's
open tasks with the open tasks of every other project of the store whose lane
works in the same directory, so two fleets that edit one file hear of it
before the merge conflicts. The change is confined to
`crates/gear-engine/src/parallel.rs` and its tests in
`crates/gear-engine/tests/it/parallel_contract.rs`; the board is untouched.

## What it does

- **`TaskIn` carries its task's own project and branch template.**
  `TaskIn` gained `project: String` and `task_branch: String`; `fn inputs`
  fills them for this project's tasks from the scanned `project` and
  `config.conventions.task_branch`. `Input.task_branch` is gone: every task
  now reads its branch from its own project's template.
- **The other projects of the store join each repo group.** `fn inputs`
  reads `tx.project_ids()`, skips the scanned project and any project whose
  config does not parse (`gear_app::config::parse`), and adds the open tasks
  (state not Draft, Cancelled or Failed) of every other project whose lane's
  repo (`other_config.repo_of_lane(lane).path`) is the same directory as the
  group's repo path. "Same directory" is equal after `std::fs::canonicalize`,
  or equal as text when either path does not canonicalize. Their latest
  candidate is read from their own `tx.attempts_of_task(other, task)`.
- **Their hand-ins are in the snapshot too.** Every attempt (with project,
  task, attempt number and candidate) of the other projects' tasks in the
  repo joins `handins`, so another project's hand-in restarts this project's
  scan inside the back-off period, exactly as the project's own hand-in does.
- **`fn scan` compares and names.** Each task's branch is read with
  `crate::dispatch::task_branch(&task.task_branch, &task.project, ...)`. An
  integration finding is recorded only for this project's tasks (another
  project's task with the same id would otherwise overwrite this project's
  information line). A pair is formed only when at least one side is this
  project's task; two tasks are on different lanes when `(project, lane)`
  differs.
- **The pair's names and keys.** This project's side stays `T-1 (heat)`. A
  pair with another project's task has the key
  `tasks:<this task>:<other project>/<other task>` and names that side
  `T-1 (q/heat)` in the same `parallel changes{where_}: <left> and <right>
  share files: <files>` text. Each project's own engine pass therefore writes
  its own captain's item, and both captains hear of a shared pair. A pair of
  two other projects' tasks is theirs to report, never this captain's.
- Projects of another store (another Herdr session) are not in
  `tx.project_ids()` and are not seen.

## Tests

`crates/gear-engine/tests/it/parallel_contract.rs`. The file's existing
`template()`/`Repo` fixture is reused (one git repo built once for the file);
the new helpers `seed_on` (a project whose config sets `task_branch =
"{project}/{lane}/t{n}"`, as T-256 requires of projects sharing a repo),
`add_task` and `shared_store` build a store with two or three projects:

- `two_projects_on_one_repo_each_hear_of_a_shared_pair` — p's T-1 (heat) and
  q's T-1 (heat) both change `src/lib.rs` on `p/heat/t1` and `q/heat/t1`:
  `parallel::check(store, "p", T0)` opens one item for `p:captain` whose text
  is `parallel changes: T-1 (heat) and T-1 (q/heat) share files: …`, and the
  check for "q" opens one for `q:captain` naming `T-1 (p/heat)`. Neither
  rings again on the next pass.
- `a_project_working_in_another_repository_is_not_paired` — project r changes
  the same file name in a second repository directory; neither p nor r raises
  an item.
- `two_tasks_of_another_project_alone_raise_no_item_here` — q's T-1 (heat)
  and T-2 (steady) share a file, p's T-1 does not: p's scan opens nothing,
  while q's own scan opens q's pair.
- `another_projects_hand_in_restarts_this_projects_scan` — p's scan backs off
  at T0+599; q hands in work that now changes the same file and p's scan at
  T0+599 opens the pair.
- `another_projects_integration_overlap_is_its_own_information_line` — q's
  task overlapping `dev` writes `parallel:q:integration:T-1`, and p's scan
  writes no line for q's task even though the ids collide.
- The existing parallel tests pass unchanged (16 before, 21 after).

`make check CRATE=gear-engine`: 650 tests run, 650 passed, 0 skipped.
`origin/dev` (681f327e) is merged in.

## Out of scope (noticed, not changed)

- A name collision is still possible between two projects' pair keys when
  both name the same other project and task, but the key carries this
  project's task first, so the two projects' items are distinct.
- The hand-ins snapshot includes this project's attempts of tasks in every
  state (as before, T-281 only added the other projects' open tasks); a task
  moving to Cancelled therefore still changes the snapshot once. Left as it
  was to keep the back-off behaviour unchanged.
- The scan reads the other project's lane repo from its config, not from the
  task's own repo snapshot (`task.repo`), exactly as the packet asked; a task
  whose lane moved to another repo after creation is compared by its current
  lane's repo.
- `cargo fmt --check` is not clean on the workspace before this change; the
  new code follows the file's existing style rather than reformatting it.
