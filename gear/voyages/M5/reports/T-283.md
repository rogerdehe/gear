# T-283 — report

A failing direction result on a candidate the lane has already moved past is
the captain's information, not the lane's instruction (M4.2 T-237,
M-4110/M-4119: the check took `a275bb32` while mast pushed `d1d24363` with the
fix, and the "misread" reached mast as an urgent instruction; it spent its
budget working out which candidate was current). T-258 covered a result after
the hand-in; this covers a live attempt (`Started`) whose job sha is no longer
the branch tip.

## What changed — `crates/gear-engine/src/review.rs` only

**`fn finish_direction_results`** now takes `cfg: &EngineCfg` and
`config: &ProjectConfig` (`fn start_reviews` passes its own).

- Before the write transaction it walks the tasks and attempts, and for each
  job in state `running` whose attempt is `AttemptState::Started` it reads the
  tip of `refs/remotes/<config.conventions.remote>/<task branch>` with
  `review_git(cfg.review_git.as_ref(), &repo.path, &["rev-parse", "--verify",
  …])`, exactly as `fn start_direction_checks` reads it (branch from
  `gear_model::branch::expand(&config.conventions.task_branch, project, lane,
  task)`, repo from `config.repo_of_task(&row)`), into a map keyed by the job's
  meta key. A read that fails (or an empty tip) leaves the job out of the map.
- Inside the transaction a live failing result is **superseded** when the map
  holds a tip that differs from the job's `sha`. A superseded result is sent
  only to the captain, as the after-hand-in path does (`MsgKind::System`,
  `MsgState::Info`, same `direction:{task}:{attempt}:{sha}` thread), with the
  body

      Direction check of {task} attempt {n} on {sha:.8} (superseded: the branch
      is at {tip:.8} now, so the lane is not told): {result body}

- The job closes as today (`checked_sha` = the job's sha, its seat to
  `Standby`), so `fn start_direction_checks` starts a new check on the tip by
  itself on the next pass.
- A passing result, a result whose sha is still the tip, and a tip that cannot
  be read behave exactly as before.

## Tests (same file, `review::tests`)

The direct callers (T-258's and the push/result test) now pass their fixture's
`cfg` and a `ProjectConfig` parsed from the same config text.

- `a_failing_direction_result_on_a_candidate_the_lane_moved_past_reaches_only_the_captain`
  — job on A, the branch pushed to B, a failing result on A: the lane's inbox
  stays empty, the captain gets exactly one `System`/`Info` message containing
  `superseded`, the job closes with its own sha, and the next `start_reviews`
  pass starts a check on B.
- `a_failing_direction_result_whose_branch_cannot_be_read_reaches_the_lane` —
  the remote-tracking ref is deleted: the failing result is the lane's one
  urgent instruction as today, no `superseded` message.
- The existing `direction_checks_follow_pushes_and_report_results` keeps the
  "result on the current tip still goes to the lane" case.
