# T-304 — report

The lane quota now counts the lanes that can run: a lane seat in `Retired` keeps
its seat but takes no quota slot, and a config lane without a seat yet does take
one. `config::validate` no longer refuses `lanes.len() > quota.lanes` (it cannot
see the seats), and the finding moved to `admin::lane_quota_problem`, which the
registration paths, `admin init --check` and the plan's revival loop call.

## What changed

**`crates/gear-app/src/config.rs`**

- `fn validate` drops the `quota.lanes` finding and its doc-comment bullet,
  replaced by a note that only the seats know which lanes are retired, so
  `admin::lane_quota_problem` makes that finding.

**`crates/gear-app/src/admin.rs`**

- New `pub fn lane_quota_problem(config: &config::ProjectConfig, retired: &[String]) -> Option<String>`:
  counts the config's lanes whose name is not in `retired`; over
  `config.quota.lanes` it returns
  `quota.lanes: <n> lanes would run but the quota allows <q> (a retired lane does not count)`.
- New `fn retired_lane_names(tx, project) -> GearResult<Vec<String>>`: this
  project's `SeatRole::Lane` seats in `SeatState::Retired`, by name.
- `fn register` calls `lane_quota_problem(config, &[])` right after
  `check_other_projects` and refuses with `ErrorCode::BadFormat` before the
  project row or any seat is written. `fn re_register` calls it with
  `retired_lane_names(tx, &project_id)` at the same place, so a retired lane in
  the new config takes no slot, and the refusal happens before the config
  version, the quotas or the seats are touched.

**`crates/gear-cli/src/main.rs`**

- New `fn retired_lanes_of(project: &str) -> GearResult<Vec<String>>` beside
  `other_projects`, with the same path rule (`GEAR_DB`, else the session's
  default store), only an existing store opened read-only, and `Vec::new()`
  when there is no store.
- `fn cmd_admin_init`'s `--check` path calls
  `admin::lane_quota_problem(&parsed, &retired_lanes_of(&parsed.project.id)?)`
  right after the branch check and fails with `BadFormat`.

**`crates/gear-app/src/plan.rs`**

- In `fn apply_queue`'s revival loop (the `"a task names it again"` block) the
  seats are read once, the project's `quota_lanes` once, and the lanes that run
  are counted once **into a mutable `running`** that is incremented after each
  revival of this apply (attempt 2, review F1: a `set_seat_state` writes the
  store, not the snapshot, so a second retired lane used to see the same free
  slot). Before a `Retired` seat becomes `Queued`: if the seats in `SeatRole::Lane` that are not `Retired`
  already number `quota_lanes` or more, the seat stays `Retired` and the apply
  pushes the warning
  `lane <name> stays retired: <count> lanes run and the quota allows <q>; retire another lane or raise [quota] lanes`.
  Otherwise it revives as before, so the existing T-247 test still passes.

## Tests

- `crates/gear-app/tests/it/config_contract.rs` — `quota_conventions_and_timing`:
  the expected issue list no longer holds `quota.lanes` (the `quota.lanes = 1`
  case now reports only `conventions.release` and `timing.cooldown_s`), with a
  comment naming the new home of the finding.
- `crates/gear-app/tests/it/admin_init_contract.rs` —
  `a_first_registration_over_the_lane_quota_is_refused` (three lanes,
  `lanes = 2`: `BadFormat` with the exact text, no project row, no seat) and
  `a_retired_lane_takes_no_quota_slot_on_re_apply` (two lanes registered,
  `pricing` retired in the store, then a config listing `heat`, `pricing` and a
  new `sail` under `lanes = 2` applies as version 2: `pricing` stays `Retired`,
  `sail` is `Queued`).
- `crates/gear-app/tests/it/config_change_contract.rs` —
  `a_full_lane_quota_leaves_a_retired_lane_retired`: three lanes registered
  under `lanes = 3`, `sail` retired, the config re-applied with `lanes = 2`
  (heat and pricing fill it). A Ready task on `sail` leaves it `Retired`, does
  not staff it, and the apply carries the warning with
  `2 lanes run and the quota allows 2`; after `pricing` retires too, the next
  apply revives `sail` (`Queued`, reason `a task names it again`).
  `a_retired_lane_stays_retired_until_a_task_names_it` (the existing revival
  test) still passes.
  `two_ready_tasks_revive_only_one_lane_when_one_slot_is_free` (attempt 2, the
  review's F1 regression): three lanes under `lanes = 3`, `pricing` and `sail`
  retired, the config re-applied with `lanes = 2` (heat fills one slot, one
  free). One plan with two Ready tasks, one on each retired lane: exactly one
  `start …` in `staffed`, the other lane keeps its `Retired` seat and the apply
  carries `lane <name> stays retired: 2 lanes run and the quota allows 2; …`,
  and the lane seats that are not `Retired` number at most 2.
- `crates/gear-cli/tests/it/admin_init_contract.rs` —
  `check_refuses_more_lanes_than_the_quota_allows`: `admin init --check` of a
  three-lane, `lanes = 2` config with no store fails with `ERROR BAD_FORMAT`
  and the exact text, and creates no store.
