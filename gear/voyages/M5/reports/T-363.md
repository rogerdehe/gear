# T-363 — report (contract v4)

The Cost view (formerly Time & tokens) is one row per lane, with the
development and the review counted apart, and `Enter` on a lane shows its
tasks under it (README change 11; prototype.py `fn view_cost`). Contract v4
adds one lane order for every per-lane view, so this view's rows match the
prototype's.

## What changed

**`crates/gear-board/src/lib.rs`**

- `TaskBoard` gains `dev_tokens`, `review_tokens`, `dev_cost`, `review_cost`:
  `Option`s. Each is the rule of `tokens_of` / `cost_of` over the task's rounds
  of one side only — `role` `dev` or `rework` for development, `review` for
  review (`fn side_of`). `tokens_of` and `cost_of` keep their meaning over all
  rounds; their bodies moved into `tokens_of_rounds` / `cost_of_rounds`, which
  the side functions filter into, so both keep the F5 rule (a round that
  counted nothing makes the sum unknown, an empty set of rounds is `None`).
- **The lane order (v4).** Where the board model is built, `lanes` is sorted
  by each lane's first task in plan order (`tasks.iter().position(...)`), a
  lane with no task after them in its present (seat) order; the sort is
  stable, so those keep their order. One rule for every per-lane view: `Now`,
  `Tasks`, `Cost` and the lane colours all read `project.lanes`, and the
  fixture now reads hull, mast, keel as the prototype does. T-362's view-local
  ordering stays and agrees with it.
- `run_with`: `Screen` is opened with `opened: Vec::new()`. `Enter` in the Cost
  tab adds the selected lane to `screen.opened` or removes it, and opens no
  panel; the other tabs keep `open_panel`. `open_panel`'s Cost arm now returns
  `Ok(None)` (its task panel and its `token_tasks` lookup are gone).

**`crates/gear-board/src/frame.rs`**

- `Screen` gains `pub opened: Vec<String>` (the lanes the Cost view expands).
- `fn view_tokens` and `fn token_tasks` are gone. `fn view_cost` draws the
  prototype's third view: the heading `Dim` at 3 ("lane / task" in 22, then
  est 6, act 7, ratio 7, rounds 8, dev tokens 12, dev $ 8, review tokens 15,
  review $ 10, total $ 9), one pick per `project.lanes` — mark `›` in `Acc` at
  1, `▾ ` / `▸ ` + the lane padded to 19 in the lane colour Bold at 3,
  `{est:>5}m{act:>6}m` plain at 25, `{r:>6.1}x` at 38 in Bad > 1.5, Warn >
  1.0, else Ok, and
  `{rounds:>8}{dev_k:>11}k{dev_c:>8.2}{rev_k:>14}k{rev_c:>10.2}{total:>9.2}`
  Bold at 45 — and, under an opened lane, one `Dim` row per task: id in 20 at
  5, the same est/act at 25, its ratio at 38, its rounds and sides at 45.
  `mine` = the lane's shown tasks with actual > 0, in plan order; an unknown
  part counts as 0 in the sums. One blank row, then Bold at 3:
  `this voyage: …M tokens (development …, review …), $…` from the k sums over
  the lanes and the raw cost sums (so the total is not the sum of the rounded
  cells: the fixture's $3.34 against 1.36 + 1.24 + 0.74), `no prices set`
  instead of the dollars when no shown task has a cost, and
  ` (known so far; <n> unknown)` when n of those tasks have an unknown token
  or cost part (an unpriced project counts the tokens only, as before).

## Tests

- `golden_contract.rs`: `Screen` gains `opened`. `fn view_differences` takes
  the view's `tab` now, so the same helper holds any view to the golden frame
  at the prototype's own origin; new `the_cost_view_paints_the_prototype_rows`
  paints the Cost view at row 14 (folded) and 22 (open) and compares rows
  14-44 / 22-44 cell for cell, lane-colour swap and the prototype-data cells
  allowed. The two cost `Pending` entries stay, labelled
  `T-363 (T-356 removes it)` — only the header's four rows keep the board's
  view at row 5.
- `decisions_contract.rs`: the old flat-view tests became: the lane row's
  columns and the voyage total
  (`the_cost_view_shows_a_lane_with_the_development_and_the_review_apart`),
  `Enter` opening and closing a lane (`enter_opens_a_lane_and_closes_it`), the
  acceptance case of a 1 000 000-token dev round and a 200 000-token review
  round on both the lane row and the task row
  (`a_task_shows_its_development_and_its_review_tokens`), the F4 rounds-table
  count (model only now: the view shows the attempts), and the F5 cases
  reworded for the new sums (unknown counts as 0 and is named; an unmeasured /
  unpriced review round hides no part; cache reads are not added to the fresh
  tokens; a project without prices names them once).
- `colour_contract.rs`: the Cost section checks the padded lane column and the
  estimates under their heading.
- `voyage_scope_contract.rs`, `voyage_select_contract.rs`: the Cost view's row
  list is the lanes' own tasks now, asserted from `project.lanes` (the
  `token_tasks` helper is gone).

## Out of scope (noticed, not changed)

- The lane order rule changes every view's lane order, so the existing
  lane-order assertions in other tests now read the plan order (they passed
  unchanged here); a lane with no task keeps its seat order, so an empty lane
  can still sit after the working ones where the prototype would draw it in
  its `LANES` place.
- A click on a task row of an opened lane selects nothing (only lane rows are
  picks), which is what the packet's "each a pick" says.
- `[prices]` absent: the view still shows `0.00` in the dollar columns (the
  prototype's cells) and names the missing prices only in the total; the old
  view showed the cost column empty.
- The Cost view no longer shows cache reads at all (the prototype's columns
  are fresh tokens only); the JSON keeps `cache_read` and
  `the_json_carries_the_fresh_tokens_and_the_cache_reads_apart` still passes.
- The lane colour is still positional (hull, mast, keel → Acc, Mag, Warn); the
  prototype's `mast` is blue by name, which the golden gate's swap entry
  covers.

## Friction

- The task's shape moved twice while it was built: contract v2's acceptance
  (remove both golden entries; nothing about lane order) could not hold — the
  Cost view is painted at screen row 5 until the header chain T-353..T-356
  merges, and the board's `project.lanes` was seat order (hull, keel, mast).
  Questions M-5930 and M-5935 were answered by v4, which added the lane order
  rule, the anchored golden test and the "T-363 (T-356 removes it)" label; the
  second half of the work (lane sort + anchored test + relabel) came after the
  first hand-in attempt was refused with the contract change. Most of the diff
  outside the two source files is the old flat-view F5 tests in
  `decisions_contract.rs`, written against columns the prototype removes,
  which had to be reworded.
