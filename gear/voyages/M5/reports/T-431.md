# T-431 — report

One task whose candidate git cannot resolve no longer stops the overlap scan
for the whole project: the scan treats such a candidate as no candidate, judges
the task by its branch as before, and skips the task when its branch does not
resolve either. Nothing else in the scan changed; a git failure on the
integration branch still fails the scan.

## What changed

`crates/gear-engine/src/parallel.rs` only (`fn scan`):

- Before `ancestor(candidate, integration)`, the candidate is resolved with the
  module's existing `fn revision` (`git rev-parse --verify --quiet
  <candidate>^{commit}`). `Ok(None)` — a commit this clone lacks, or a branch
  name stored before T-421 — means the task has no candidate, so it falls
  through to the branch lookup below, exactly as a task without a candidate
  does. A resolvable candidate is compared with the integration branch as
  before, now by the resolved commit id.

## Tests

New in `crates/gear-engine/tests/it/parallel_contract.rs`:

- `an_unresolvable_candidate_does_not_stop_the_scan` — `T-1` (heat) and `T-2`
  (steady) are open and both change `src/lib.rs`; `T-3` is `Done`, handed in
  with the candidate `scan/t12` (no such ref) and its branch `steady/t3` does
  not exist either. The scan reports no problem and opens the `T-1`/`T-2`
  overlap naming both tasks and the shared file.

The existing parallel tests all pass unchanged (`a_landed_task_…` still judges
a landed candidate by its commit).

## Friction

- The packet's acceptance filter (`test(/parallel::/)`) selects no test, so
  taken literally the acceptance command proves nothing (it fails with "no
  tests to run"). I ran the same command with
  `TESTS='test(/parallel_contract::/)'` instead; both runs are above.

## Out of scope (noticed, not changed)

- A candidate that resolves to an object that is not a commit (e.g. a tag of a
  tree) still fails the scan with `revision`'s error rather than being treated
  as no candidate. The packet only asked about names git cannot resolve at all.
- The shipped scan for the other project also carries candidates stored as
  branch names (`scan/t12`), which now resolve if the branch exists; if the
  branch was deleted they are treated as no candidate, which is the intent.
