# T-287 — report

The stall item now says what to do when the engine's one restart came back to
the same end (M4.2 #17: a refused model id pinned a seat, the item said only
"its agent is gone from its pane", and the captain restarted it again with the
same result).

## What changed — `crates/gear-engine/src/lib.rs` only

**New `fn restart_spent(tx, seat)`** (next to `fn restart_missing_jobs`): true
when the restart marker of the seat's **current job** is `"started"`.

- Lane: each attempt of `tx.in_progress_attempts_of_seat(seat)` in state
  `Started` or `Delivered`.
- Temp: `seat.task_id`, else the `engine.review_pending.<seat>` meta (the same
  key `restart_missing_jobs` reads to find a temp's job), with the task's last
  attempt (`attempts_of_task(..).last()`).
- The marker is `engine.restart.<seat>.<task>.<attempt>`; any job whose marker
  is `"started"` makes the seat restart-spent.
- Other roles: never (`_ => Vec::new()`).

**`fn tick`, the loop over `report.flagged`**

- `let again = (missing, tx.get_seat(&seat)?)`: for a missing seat with a seat
  row, `restart_spent(tx, &row)?`; otherwise false.
- The fact becomes, when `again`:

      its agent exited again after the engine restarted it once on the current
      config; the cause is in its pane or its config (a refused model id, a
      missing CLI, a login): fix that first, since another restart on the same
      config ends the same way

  (one line in the source). `missing` alone keeps `its agent is gone from its
  pane`; everything else keeps `a delivery was not confirmed or continuing it
  made no progress`. Nothing else in the tick changed; the alert is still one
  `stall::alert_fact` call, so an open item is re-bodied rather than duplicated.

## Tests — `crates/gear-engine/src/lib.rs`, `mod t209_tick_tests`

- `exited_lane_and_reviewer_restart_once_replay_their_packets_and_stall_after_second_exit`
  (existing) now also asserts the stall item's body contains `exited again
  after the engine restarted it once`, for the lane and the temp arm.
- New `a_missing_seat_never_restarted_keeps_the_plain_fact`: the seat's pane is
  closed (`herdr.pane_close`), so the engine has nowhere to restart it; one
  tick, no `AgentStart`, the single item's body contains `its agent is gone from
  its pane` and not the restart-spent sentence. Run for both roles.

The temp arm of the first test is why the `engine.review_pending.<seat>` fallback
is there: the release of an idle reviewer ("idle reviewer released") clears
`seat.task_id` while the attempt is still `Submitted` and the pending review is
still recorded, so `task_id` alone leaves the seat without a job. Contract v2
(hull's question M-4702) writes exactly that: `task_id`, else the task in
`engine.review_pending.<seat>`, with the task's last attempt.
