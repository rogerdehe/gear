# T-378 — report

The packet's pending-contract section now tells the lane what the newer version
asks for, not only its number (F-133, T-287: the packet ended with a bare
`## Pending update: v2`, the wording was readable only through `gear plan show`,
and the lane could not hand in until a bare `gear` adopted it).

## What changed — `crates/gear-app/src/plan.rs` only

In `render_task_packet`, where the packet appended
`## Pending update: v{}`, the newer contract row is now read with
`tx.get_contract(project, task, row.contract_version)` (a missing row is the
same `NoTarget` the adopted version's lookup already gives — it cannot happen
for a stored `contract_version`) and the packet carries:

    ## Pending update: v<m>
    Goal (v<m>):
    <goal>

    Acceptance (v<m>):
    <accept>

    Run `gear` (no arguments) to adopt it, then work and hand in to v<m>.

Nothing else changed; the section is still appended only when
`row.contract_version > adopted`, so a packet whose attempt adopted its current
version stays exactly as before.

## Tests — `crates/gear-app/tests/it/packet_contract.rs`

- `pending_update_and_missing_task` (existing) now also asserts the pending
  version's own words: `Goal (v2):\nFix it better`, `Acceptance (v2):\na2` and
  the adopt line naming v2.
- New `a_task_that_adopted_its_current_version_has_no_pending_section`: the
  plain packet has neither the header nor the adopt line.
