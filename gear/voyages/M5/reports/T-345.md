## What changed — `crates/gear-board/tests/it/golden_contract.rs` only

- **(1) `fn render(tab: Tab, detail: bool) -> Planes`** — `golden_fixture::load()`,
  `gear_board::build(&mut store, &Options { project: Some("gear".into()), ..Default::default() }, now)`,
  `board.engine = EngineState::Running` (the fixture has no engine and the
  prototype draws no warning), then
  `gold::planes(&canvas(&board, &Screen { tab, selected: 0, detail, size: (160, 48) }, None))`.
- **(2) `fn golden(name: &str) -> Planes`** — reads
  `concat!(env!("CARGO_MANIFEST_DIR"), "/../../gear/voyages/M5/board/golden/")`
  + `<name>.txt`, `.col`, `.rev` through one `fn plane(name, ext)`: split on
  `\n`, a last empty piece dropped. A missing file panics naming it.
- **(3) `struct Pending { frame, rows, cols, swap, by }`** and
  **`const PENDING: &[Pending]`** — rows and cols are inclusive ranges counted
  from zero. A cell inside a skip entry (`swap: None`) is not compared; a cell
  inside a swap entry and inside no skip entry is compared with the swap
  exception `golden colour == want` ⇢ the board may draw `got`, compared
  exactly (case kept: `u` with `m`, `U` with `M`). A `FRAMES` table holds the
  eight `(name, Tab, detail)` triples, so a frame's tab is written once.
- **(4) Eight tests** — `now_folded`, `now_open`, `tasks_folded`, `tasks_open`,
  `cost_folded`, `cost_open`, `log_folded`, `log_open` — all call one `fn gate`:
  `failures(frame, &golden(frame), &render(tab, detail), PENDING)` must be
  empty. A difference is reported as
  `row R col C: want 'x' o . got 'y' . R`, at most the first 30, under a
  `"<frame> differs from the prototype in N cell(s), the first M:"` line. A
  `by` starting with `NEW:` whose cells all match now (for a swap entry: no
  cell needed the swap) fails with
  `pending <by> on <frame> rows a-b matches now: remove the entry`; the
  `prototype data` entries are never checked that way.
- **(5) The starting `PENDING`** is exactly the packet's list, `cols: (0, 159)`:
  rows (0, 6) of all eight frames (T-353); folded rows (7, 9) (T-354) and
  (10, 12) (T-356); open rows (7, 17) (T-355) and (18, 20) (T-356);
  now-folded (13, 18) / now-open (21, 26) (T-359); now-folded (19, 46) /
  now-open (27, 46) (T-360); tasks-folded (13, 46) / tasks-open (21, 46)
  (T-362); cost-* likewise (T-363); log-* likewise (T-364). Row 47, the
  footer, is compared from the start.
- **(6) The `prototype data` entries** — `expected finish` (folded row 8, cols
  43–84; open row 13, cols 51–136), `merge clocks` (tasks-folded rows 23, 26,
  30, 33, 35 and tasks-open rows 31, 34, 38, 41, 43, cols 144–158),
  `T-267 stage` (tasks-folded row 19 and tasks-open row 27, cols 92–122), each
  as a skip entry; and `lane colour` as a swap `Some(('u', 'm'))` over rows
  0–47 cols 0–159 of the six Now/Tasks/Cost frames.
- **The acceptance check** `a_difference_is_reported` compares two `Planes`
  that differ in one colour letter at row 3 col 7 against no pending list and
  asserts the message names `row 3 col 7`. (It passes an empty list because row
  3 of every frame is inside T-353's skip entry; the frame name it uses,
  `uncharted`, is not one of the eight.)
