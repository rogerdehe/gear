# T-300 — report

The reviewer's packet now names the commit message the project asks for, so a team with commit
rules reads one form everywhere. The engine only fills what it knows: `{what}` stays in the text,
because what the commit does is the reviewer's to write.

## What changed

`crates/gear-engine/src/review.rs` (the only code file touched):

- `fn review_packet` takes one more argument, `commit: &str` (last parameter). Its sentence is now
  "Write the review in your worktree at the path your project uses for reviews, commit it on
  `{branch}` with the message `{commit}` (replace `{what}` with what the commit does) and push it
  (the candidate stays untouched)."
  `{{what}}` is escaped in the `format!` so `{what}` reaches the reviewer literally.
- `fn review_packet_for` builds that message with
  `gear_model::commit::fill(&config.conventions.review_message, &[("project", &config.project.id), ("task", task), ("attempt", &attempt.to_string())])`
  and passes it as `&commit`. `{what}` is not in the values, so `fill` leaves it in the text.
- The direction packet (`fn job_packet`, its non-review arm) is unchanged: a direction check
  commits nothing.

## Tests

New, in the crate's own test module (`mod tests` in `review.rs`):

- `review::tests::the_review_packet_names_the_projects_review_message` — the review packet of
  T-1 attempt 2 with the default config contains "with the message `review(T-1): {what}`"; with
  `[conventions] review_message = "{task}#{attempt} review: {what}"` it contains
  "`T-1#2 review: {what}`".

No existing test asserted the old sentence, so none needed its expected text changed.
