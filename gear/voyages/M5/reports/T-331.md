# T-331 — report

After departure a voyage's goal belongs to the user: an apply that changes its
`title`, `done:`, `bar:` or stations is refused with `GOAL_LOCKED` and writes
nothing. `eta:` is not locked.

## What changed

**`crates/gear-model/src/error.rs`** — `ErrorCode::GoalLocked`, `as_str()`
`"GOAL_LOCKED"`, exit code 1 (the `_` arm). A unit test
`a_locked_goal_has_its_code` asserts both.

**`crates/gear-app/src/goal.rs`** (new, `pub mod goal;` in `lib.rs`) —

- `GoalChange { milestone, field: &'static str, before, after }`.
- `changes(tx, project, draft)`: for every `draft.milestones` block (read with
  `milestone_parts`, `milestone_fields`, `milestone_stations`), the stored
  voyage (`tx.get_voyage`) is locked when its `departure` is `Some` **and** its
  stored `done` is non-empty after trim — a voyage whose words were never
  written may still be described once, as T-22 allows. For a locked voyage it
  compares `title`, `done` and `bar` (an absent block field reads as `""`) with
  `decision::collapsed` on both sides, and `stations` when
  `tx.voyage_stations` is not empty (a departed voyage without stations may be
  given its first list once). Stations compare as `<id>: <needs>` joined by
  `"; "`. Each differing field is one `GoalChange`; `eta` is not compared. A
  malformed `station` line is `BadFormat` naming the milestone, like
  `record_voyages`.
- `check(tx, project, draft)`: with changes, `Err(GearError::new(GoalLocked,
  …))` whose text is `voyage <M> has departed: its goal belongs to the user and
  is locked. This apply changes it:` then `  <field>: «<before>» → «<after>»`
  per change and `Put the stored words back.`; otherwise `Ok` with the empty
  list.

**`crates/gear-app/src/plan.rs`** — `apply_queue` calls
`crate::goal::check(tx, project, draft)?` right after `reject_sections(draft)?`,
so a refused apply writes nothing and the departure read is the one from
before `fix_departures`. The `apply` and `record_voyages` doc comments name the
rule.

T-331 supersedes T-410 on this path (see the questions below): the T-410 guard
in `record_voyages` and `departed_voyages` are removed. A wordless departed
voyage takes its first block freely, `eta:` moves freely, and a confirmed apply
no longer changes the goal. `Draft.confirmed` and the CLI `--confirmed` flag
remain (outside this packet's files) but nothing on the voyage path reads them.

## Questions sent

- **M-5648** — T-331 locks the goal even with `--confirmed`, which makes T-410's
  confirmed `done`/`bar` path unreachable; asked whether T-331 supersedes T-410
  and whether `eta:` stays behind `--confirmed`.
- **M-5651** — corrected default after reading the acceptance: the wordless
  first block and "an `eta:` change applies" both contradict T-410's guard, so
  T-331 supersedes it and `eta` is free. Default taken: implement T-331
  literally, remove the T-410 guard, keep the now-unused flag.
- **M-5660** (garbled by shell backticks) / **M-5661** — the packet says no
  gear-cli test applies a `# Milestone` block, but
  `plan_apply_takes_the_confirmed_flag` does; default taken: update it to T-331.

## Tests

Changed in `crates/gear-app/tests/it/voyage_contract.rs` (every test changed):

- `a_voyage_is_stored_with_its_departure_and_shown` — the later apply moves
  only `eta: 8h → 9h`; the words and the departure stay.
- `a_departed_voyage_changes_only_with_the_users_confirmation` — replaced by
  `a_departed_voyages_goal_is_locked`: `title`, `done` and `bar` each refused
  with `GoalLocked`, the exact header and `field: «before» → «after»` line and
  `Put the stored words back.`, and the plan version, voyage words and tasks
  untouched; an `eta` change applies with no confirmation and no decision; an
  unchanged block applies.
- `a_voyage_that_has_not_departed_changes_without_confirmation` — renamed
  `a_voyage_that_has_not_departed_changes_freely` and extended from eta to all
  of title/done/bar/eta before departure.
- `the_departure_is_the_first_task_creation_even_without_the_block` — its third
  apply changes `eta` only; `done` stays and the departure does not move.
- `editing_a_grandfathered_milestone_keeps_its_historical_departure` — the
  second apply (first block on a wordless departed voyage) now applies freely
  and stores the words at the historical departure; the third apply edits all
  three and now expects `GoalLocked`, nothing written, the stored words and
  departure unchanged.
- `an_eta_that_is_not_a_duration_is_refused` — the departed-voyage eta change
  uses plain `run`, not the confirmed helper.
- The `run_confirmed` helper is removed (unused now).

New tests:

- `voyage_contract::a_whitespace_only_difference_is_no_change` — extra spaces
  and a tab are not a change, so the apply is not refused.
- `voyage_contract::a_departed_voyage_gets_its_first_stations_once` — a
  departed voyage with no stations takes `S1`/`S2` once; changing `S2` then
  gives `GoalLocked` with the joined `stations:` line and writes nothing.
- `gear-model::error::tests::a_locked_goal_has_its_code`.

Changed outside the packet's stated set:
`crates/gear-cli/src/main.rs::tests::plan_apply_takes_the_confirmed_flag` — the
flag still parses and an apply carrying it runs, but a bare `eta` change now
applies (T-331), so its T-410 refusal assertion is gone.

## Out of scope (noticed, not changed)

- `Draft.confirmed`, the CLI `--confirmed` flag and its help text, and
  `skills/gear/references/captain.md` still describe T-410; nothing on the
  voyage path reads the flag now. Removing or repurposing it touches
  `draft.rs`/`gear-cli`, outside this packet.
- T-410's starred `user` decisions for goal changes are no longer recorded
  (the guard that wrote them is gone).
- An apply that changes several departed voyages reports only the first
  voyage's changes; fixing it reveals the next.
- A whitespace-only difference is not a lock refusal, but the block still
  rewrites the stored words' spacing (the apply succeeds as T-331 says).
- A malformed `station` line on a locked voyage returns `BadFormat` before the
  `GoalLocked`; the block could not have been stored as written anyway.
