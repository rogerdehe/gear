# T-262 — The engine uses the project's remote and voyage folder

Attempt 1, contract v1. Branch `hull/t262`, started from `origin/dev` and with
`origin/dev` merged in before the hand-in (`969affdd`, T-258's hand-in change
resolved by hand in `review.rs`'s direction test).

## What shipped

**(1) A report-only push starts no direction check** (`review.rs`,
`start_direction_checks`). The `ops/` test is gone. The skip is now:

- the milestone is the **task's** milestone (`row.milestone`);
- a changed path is a document when it starts with
  `layout::reports_dir(&config.conventions.voyage_dir, project, milestone) + "/"`
  or with the `layout::reviews_dir` equivalent;
- the check is skipped when **every** changed path is a document. A task with
  no milestone has neither folder (`dirs` is empty), so only an empty diff is
  skipped and any real path starts a check, as the contract says.

The two folders come from `gear_model::layout` and the project's
`conventions.voyage_dir` (T-257), never from a fixed string.

**(2) `origin` is the project's `config.conventions.remote`** everywhere in
`crates/gear-engine/src` outside test code. The name is taken from the config
each caller already holds and passed down:

- `review.rs`: `start_direction_checks` reads the branch from
  `refs/remotes/<remote>/<branch>` and the base from
  `merge-base <remote>/<integration>`; the direction packet names
  `diff from <remote>/<integration>`; `prepare_review_tree` fetches `<remote>`
  (its `remote` parameter, threaded through `prepare_seat_tree` from
  `start_reviewer`, which holds the `ProjectConfig`).
- `merge.rs`: the `Remote` trait's `push`/`delete` now take the remote name, and
  a small `Target { name, runner }` carries the pair through
  `merge_with_retries` → `merge_one_locked` → `pr_head` / `close_branches` /
  `delete_remote`. Inside the merge every ref follows it: the fetch
  (`fetch --prune <remote> +refs/heads/*:refs/remotes/<remote>/*`), the
  resets, the `for-each-ref` prefix, the `rev-list` range, the review ref, the
  pull-request head ref, the messages, and the closure of the consumed
  branches. `merge_passed` builds the `Target` from the `ProjectConfig` it
  parses; `close_pr_branches` does the same. `FetchRemote` (the tests' runner)
  learns the path with `git remote get-url <remote>`; `origin_path` caches per
  (checkout, remote).
- `quiet.rs`: the push clock reads `refs/remotes/<remote>/<branch>` from
  `dispatch::conventions`.
- `dispatch.rs`: the first-attempt packet says
  `git fetch <remote> && git switch -c <branch> <remote>/<integration>`, from
  the conventions `intend_dispatch` already reads.
- `parallel.rs`: the overlap scan reads `refs/remotes/<remote>/…` from
  `Input.remote`, set from `config.conventions.remote`.

Test fixtures keep their own remote names: every existing fixture still calls
its remote `origin`, and the new one calls it `upstream`.

## Tests

  task milestone `M5`; a push of `gear/voyages/M5/reports/T-1.md` alone leaves
  `engine.direction.p.T-1.1` unset; the same branch plus one `src/` file starts
  the check, whose job carries the new sha.
- `review::tests::direction_checks_follow_pushes_and_report_results` (the old
  `ops/`-only test) now uses `gear/voyages/M5/reports/T-1.md` with milestone
  `M5`: the report-only push starts no check (its `checked_sha` stays the
  previous one).

  `the_engine_fetches_merges_and_pushes_through_the_projects_remote`. Real git,

  → `merge_passed`: the dev log on `upstream` holds the task's and the review's
  commits, and `heat/t1` and `review/t1` are closed **on upstream**.
- Updated to the new signatures: `dispatch.rs`'s packet test,
  `tests/it/dispatch_tick_contract.rs`, and the review fixtures that call
  `prepare_seat_tree`/`prepare_review_tree` (they pass `"origin"`).
