# T-415 — report

The board's totals count only live work: a cancelled task stays in the Tasks
view, but it no longer inflates what the voyage still has to deliver.

## What changed

**`crates/gear-board/src/lib.rs`**, `project_with_agents`, the loop that counts
`Totals` and builds the lane queues:

- The `TaskState::Draft` skip stays. For a `TaskState::Cancelled` task the
  counting block is bypassed (`totals.tasks`, `done`, `in_progress`,
  `waiting` all untouched), and the loop goes on to build the task's
  `TaskBoard` line and push it onto its lane exactly as before.
- The per-lane `done_count` / `left_count` and the graph are untouched: a
  cancelled task still lists in the views, as the packet asks.
- One comment names the rule and the stations' precedent (`station.rs` leaves
  out Draft, Cancelled and Failed).

No other file changed except the test below and this report.

## Test

`crates/gear-board/tests/it/board_contract.rs`:

- `cancelled_tasks_are_not_counted_in_the_totals` — one voyage M5 with 3 done,
  2 ready and 4 cancelled tasks: `plan.totals.tasks == 5`,
  `plan.totals.done == 3`, the rendered Lanes view reads
  `Totals: 5 tasks · 3 done`, and all four cancelled ids still sit in the
  lane's queue (the Tasks view they are drawn from).

## Acceptance

```
$ make check CRATE=gear-board
Summary [   7.259s] 175 tests run: 175 passed, 0 skipped
```

Every golden-frame test passes unchanged: the prototype fixture carries no
cancelled task, so no expected count moved.

## Out of scope (noticed, not changed)

- `gear` SNAPSHOT reads the same `Totals` (`crates/gear-app/src/home.rs`), so
  it now reads the live count too; no gear-app test asserts a count over
  cancelled tasks, so none changed.
- `crates/gear-board/src/voyage.rs` (the report behind the header's "N of
  estimates left", the projected finish and the lane `left_min` / `left_count`)
  puts every task that is not `Done` into the remaining work, so a cancelled
  task still adds its estimate there. The packet scopes this task to `Totals`,
  so that path is untouched; after this change the header can read `3/5 done`
  while the estimates-left figure still carries the cancelled tasks.
- Whether `Totals.handed_in` / `Totals.rejected` should ignore attempts of
  cancelled tasks is another reading; the packet scopes the change to the
  task-state count, so the attempt totals stay as they were.
