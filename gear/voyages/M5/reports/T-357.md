# T-357 — report (contract v2)

The user picks the voyage the whole board shows: `[` goes one voyage older,
`]` one newer, and a left click on a voyage label on the first row picks that
voyage. Every pick starts the selection over and closes a panel.

## What changed

`crates/gear-board/src/lib.rs` — `run_with` only:

- `let mut milestone: Option<String> = opts.milestone.clone();` keeps the
  voyage the board shows, so the board starts where it always did (the options'
  voyage, else the measured one).
- Every frame is built with
  `Options { milestone: milestone.clone(), ..opts.clone() }`
  (`build_with_agents(store, &shown_opts, …)`), so the whole head, the header
  and the view measure the picked voyage.
- `[` / `]` (`Event::Key(character @ ('[' | ']'))`): the shown voyage is looked
  up in `ProjectBoard::voyage_list` (newest first, as the frame draws it), `[`
  takes the entry after it and `]` the entry before it, clamped — the oldest
  voyage stays the oldest, the newest stays the newest. A pick sets
  `milestone`, `screen.selected = 0`, `panel = None` and `kept = None`, so the
  next frame is built for the pick. A press that cannot move (no voyage shown,
  or already at that end) leaves the board as it is.
- A left click (`Event::Mouse { button: 0, … }`) with the terminal's `y = 1`
  (`row == 0`) whose column lies in a `Layout.voyages` range picks that voyage
  the same way. The existing tab-row and view-row clicks are unchanged: `row 0`
  is a new branch before them, and a row that is neither falls through exactly
  as before.

Nothing else in the crate changed: the frame still draws the shown voyage from
the board, the prototype's `pick(…)` clamping and its row-0 hit test are the
model.

## Tests

`crates/gear-board/tests/it/board_contract.rs`:

- New `world_with_two_voyages`: M1 landed (its one task done) and M2 sailing
  (one ready task), so the measured voyage is M2 and the list is `[M2, M1]`.
- New `the_voyage_keys_and_a_click_on_a_label_pick_the_shown_voyage`, with the
  file's `Events` fake keys on a 160x40 screen:
  - the first frame shows M2 (row 1 holds `M2:`);
  - after `[` row 1 holds `M1: voyage M1 · ⚓ landed`, no `M2:` is left, and the
    M1 label on row 0 is the lit one (`\x1b[1;7m M1 ⚓`);
  - `[` again stays on M1 (the oldest stays the oldest);
  - `]` returns to M2;
  - a click at the M1 label's first column (`x = first + 1`, `y = 1`) picks M1,
    and after two `Down` keys the pick starts the selection over: the frame's
    lit rows are the ones the board of M1 draws at selection 0.
- New helper `lit_picks`: the rows a frame draws in reverse video, the first
  row's labels and the tab row left out.

## Out of scope

- A click on the first row that misses every label (the blank space between
  labels, the clock, `[ older   ] newer`) selects nothing, as before; the
  prototype's `for x0, x1, i in VOYX` does the same.
- A pick does not survive a project switch (`p`): the milestone is the pick for
  the run, not a per-project pick. The prototype has one project.
- A shown voyage that is not in `voyage_list` (no departure) leaves `[` and `]`
  with nothing to move from, so they do nothing rather than invent a voyage.
- The pool of voyage labels is clipped at the terminal's width as it always
  was: a label drawn past the edge is not clickable, but the head still draws
  it (a wide terminal is what the golden frames use).
