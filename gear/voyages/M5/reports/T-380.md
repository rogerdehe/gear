# T-380 — report

The review packet now names the diff against the **remote** integration branch
and fetches first, so a reviewer's stale local copy cannot widen the diff:

```
Diff to review: `git fetch origin && git diff origin/dev...<candidate>` (three dots: the change since the merge base)
```

## What changed

- `crates/gear-engine/src/review.rs` only (plus the tests that follow it):
  `fn review_packet` takes a new `remote: &str` parameter, placed after
  `candidate` and before `integration`, and its "Diff to review:" line writes
  `git fetch {remote} && git diff {remote}/{integration}...{candidate}`.
  `fn review_packet_for` passes `&config.conventions.remote` where it already
  reads the config, so a project that names its remote (`remote = "upstream"`)
  gets that name; the default is `origin`.
- `skills/gear/references/review.md`: the diff it names is
  `<remote>/<integration>...<candidate>` after a fetch (was
  `<integration>..<candidate>`). The integration-branch sentence after it is
  unchanged.

No other behaviour changed: the candidate, the worktree, the rules and the
verdict command in the packet are as before.

## Out of scope (noticed, not changed)

- The reference in `skills/gear/references/review.md` writes
  `<remote>/<integration>...<candidate>` (three dots); the old text had two
  dots, so this line now agrees with the packet's own three-dot range. Nothing
  else in that file was touched.
- The packet does not say what to do if the fetch fails (no network, no
  remote of that name): the reviewer runs the command as written and the
  failure is theirs to report. Naming a fallback in the packet would be a
  design decision.
