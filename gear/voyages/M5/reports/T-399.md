# T-399 — report

A `Standby` reviewer whose agent is gone is released, so it no longer holds a
temp slot while reviews wait for a seat.

## What changed

`crates/gear-engine/src/release.rs` only.

**`const STANDBY_AGENT_GONE_S: i64 = 60;`** — the grace a `Standby` reviewer
is left alone (a review can be handed over to it on any tick, and Herdr may
report its agent a moment late, as `START_GRACE_S` above does for a fresh
start).

**`fn release_finished_reviews`, a new `SeatState::Standby` arm** in the seat
loop. Such a seat is released when

- its live binding has a pane (`binding_pane`; no live binding → the seat is
  left to the dead-temp sweep, out of this rule's scope),
- it has been in `Standby` for more than 60 s (`now - seat.state_since`),
- and `herdr.agent_get(pane)` is `Ok(None)` — a bare shell.

The release is `release_one_ending_its_review(store, herdr, project, &seat,
now)`, so `start_reviews` starts that review again on a free seat instead of
waiting for a seat that never gets one.

**Attempt 2, rework F1 — the reservation is cleared atomically.** Attempt 1
cleared a non-empty `engine.review_pending.<seat>` in a `store.write` of its
own, before `release_one`'s pane close and its separate transition write: a
refused close left the `Standby` seat holding its slot with the review
already taken from it. `release_one`'s body is now `fn release_seat(…,
ending_its_review: bool)`, and `release_one` passes `false`; the new
`release_one_ending_its_review` passes `true`, which adds
`tx.set_meta("engine.review_pending.<seat>", "")` to the **same** write that
does `clear_seat_task` and `set_seat_state(Releasing)`. A refused close still
returns before that write, so the seat and its review stay whole; once the
transition commits, the key goes with it. `false` keeps the reservation of a
seat released with its agent alive — the repo/model move in `review.rs`
(`start_reviewer` → `release_one(…, None, …)`) releases a `Standby` seat that
restarts on the very review it reserved, and
`standby_reviewer_releases_before_moving_to_another_repo` asserts that.

In the arm itself, `Ok(Some(_))` (agent alive) and `Err(_)` (pane unreadable)
both keep the seat, as T-264 does for a reviewing seat.

Nothing else changed besides that flag: the existing idle-surplus sweep stays as it is, and a seat this
arm sends to `Releasing` is freed by the next tick's `Releasing` arm as usual.

## Tests

Five, in the crate's own test module (`release.rs`):

- `a_standby_reviewer_whose_agent_is_gone_is_released_with_its_review` — a
  `Standby` seat for over 60 s with a bare-shell pane goes `Releasing`, its
  pane is closed once, `engine.review_pending.p:r-1` is `""`, and the next tick
  frees it (`Released`, no second close).
- `a_standby_reviewer_with_its_agent_keeps_its_slot` — an idle agent in the
  pane: `Standby`, pending key `T-1`, pane open.
- `a_standby_reviewer_whose_pane_cannot_be_read_keeps_its_slot` —
  `observe_fails`: `Standby`, pending key kept, pane open.
- `a_standby_reviewer_of_a_moment_is_not_released` — bare shell, `Standby`
  since `T0`, tick at `T0 + 30`: `Standby`, pending key kept, pane open.

- `a_refused_close_keeps_a_standby_reservation_until_the_release_commits`
  (attempt 2, rework F1) — `inject_next = Inject::Refuse`, tick at `T0 + 120`:
  the seat stays `Standby` **and** the pending key stays `T-1`; the next tick
  at `T0 + 140` with a working close puts it in `Releasing` with the key `""`.
  The surplus sweep cannot mask it: `release_idle_standby` leaves a seat with a
  pending review out (`T-391`).

Shared fixture `standby_for_a_pending_review(store, since)`: T-1 handed in and
unjudged, the seat `Standby` since `since`, `engine.review_pending.p:r-1` set.
