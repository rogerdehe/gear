# T-409 — the contract forge in the github tests gets a wide bound

`crates/gear-forge/tests/it/github_contract.rs`, `fn forge_with` only: the forge
it returns is now built with a 300 s call bound instead of the 30 s the forge
ships with.

```rust
let forge = GitHub::new()
    .with_path(&dir)
    .with_timeout(Duration::from_secs(300));
```

The 30 s is a production setting; at load 43 (T-392's gate, 2026-10-29) four
github_contract tests hit it while the same tests run in 14 s on an idle
machine — the tests say nothing about the bound, so it must not fail them.

`a_call_past_its_bound_is_a_timeout` is unchanged: it takes the forge from
`forge_with` and calls `with_timeout(Duration::from_millis(250))` itself, and
still asserts the error carries 250 ms and returns well inside 5 s.

The function's doc comment gained one sentence saying why the bound is wide,
so the next reader does not narrow it back.

Validation: `make check CRATE=gear-forge` — 42 tests, 42 passed
(`a_call_past_its_bound_is_a_timeout` among them).

## Out of scope

- The forge's own default bound (30 s) is untouched — it is the production
  setting the packet keeps.
- `a_missing_tool_is_a_typed_error` builds its own `GitHub::new().with_path(&dir)`
  after removing the fake; it tests a missing tool, not the bound, and the
  packet limited the change to `fn forge_with`, so it was left as it is.
