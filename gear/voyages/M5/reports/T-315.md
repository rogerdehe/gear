# T-315 — report

`gear admin init --check --models` now asks each seat's CLI for its models and
warns about a configured model id that CLI does not list; a plain `--check` and
a plain `init` stay offline and run no CLI.

## What changed

**`crates/gear-app/src/kickoff.rs`**

- `fn models_of` is now `pub fn models_of` — the one place that knows how each
  CLI lists its models (`opencode models`, `pi --list-models`, the Codex cache).
- New `pub fn model_warnings(config: &crate::config::ProjectConfig, listed: &mut dyn FnMut(&str) -> (Vec<String>, Option<String>)) -> Vec<String>`:
  it walks, in this order, every lane's chain (`config::lane_chain`), the
  review chain `config.models.review` (only when the project names `[temps]`)
  and the captain chain `config.models.captain`. An entry's CLI is
  `entry.cli()`, else the kind of the seat that runs it (the lane's kind, the
  temps seat's, `captain.kind`).
  - a CLI's list is asked once and kept for the rest of the walk (`listed` runs
    a CLI, and `opencode models` waits 500 ms on an empty list);
  - models listed and the entry's `model()` not among them →
    `lane <name>: model <m> is not among the models <cli> lists`
    (`reviewers:` / `captain:` for the other two chains);
  - no models but a note → one line per CLI, however many entries name it:
    `model ids of <cli> not checked: <note>`;
  - no models and no note (a CLI that prints none) → nothing.
- A small private `Asker` holds the per-CLI answers and the CLIs whose "not
  checked" line is already said.
- `mod tests` at the end of the file: seven unit tests with an injected
  `listed`, no process runs — the lane line for an unlisted model (and silence
  for a listed one), an entry naming `cli = "codex"` checked against the codex
  list, one "not checked" line for a CLI with a note, silence for no list and
  no note, each CLI asked once across all three chain kinds, the `reviewers:`
  line and the `[temps]`-only rule, the `captain:` line.

**`crates/gear-cli/src/main.rs`**

- `AdminOp::Init` gains `#[arg(long, requires = "check")] models: bool`, so
  `--models` without `--check` is a clap error.
- `fn cmd_admin_init(config, check_only, with_models, json)`: with
  `--check --models` it computes `gear_app::kickoff::model_warnings` with
  `gear_app::kickoff::models_of` as `listed`, then — text form — prints each
  warning to stderr as `warning: <line>` after the seat lines, and adds
  `"model_warnings": [...]` to the `--json` object. Without `--models` nothing
  runs and the JSON carries an empty array. Exit codes are unchanged.

**`skills/gear/references/captain.md`, §1 step 4**: the check is
`gear admin init --check --models gear/gear.toml` and "a model warning is fixed
before departure".

**`crates/gear-cli/tests/it/admin_init_contract.rs`**: one CLI test,
`check_models_warns_about_a_model_its_cli_does_not_list` — a PATH holding only a
fake `pi` that prints `provider model context` / `tok deep-1 600K` and writes a
marker when it runs; a lane of kind `pi` on `tok/deep-2` gives
`warning: lane heat: model tok/deep-2 is not among the models pi lists` on
stderr and exit 0, and a plain `--check` on the same config leaves the marker
absent.
