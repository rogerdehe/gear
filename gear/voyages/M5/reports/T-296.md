# T-296 — report

The engine's merge commits are now the project's own message. `merge_passed` fills
`{project}` and `{task}` once per merge op from `config.conventions.merge_message` and moves the
result into that op's worker; the worker fills `{source}` on every attempt, with what that attempt
merges (the pinned candidate sha, the review ref). With the default template the log reads exactly
as before.

## What changed

**`crates/gear-engine/src/merge.rs`** (only file changed):

- `merge_passed`: after the review fallback, one
  `gear_model::commit::fill(&config.conventions.merge_message, &[("project", project), ("task", &task)])`
  per op; the `String` is moved into the spawned worker.
- `merge_with_retries` and `merge_one_locked` take it as a last parameter `commit: &str`;
  `merge_with_retries` hands it to every attempt.
- `merge_one_locked`: the `git merge --no-ff <pinned> -m …` call uses
  `gear_model::commit::fill(commit, &[("source", pinned)])`.
- `pr_head` (the PR-mode second merge call, design §11.2 step 2) takes `commit: &str` and uses
  `fill(commit, &[("source", review_ref)])`; its now-unused `task` parameter is gone.
- Test helpers `merge_one` and `merge_retried_on` pass
  `gear_model::commit::fill(gear_model::commit::MERGE_MESSAGE, &[("task", …)])`, so every existing
  `merge(T-5): …` expectation of the module stands unchanged (e.g.
  `a_clean_merge_is_pushed_and_the_branches_are_gone` counts two `merge(T-5)` subjects).
- New helper `queued_merge_templated(scratch, gate, template)`: a queued merge whose project config
  carries its own `merge_message` (the line is appended to the config text's last section,
  `[conventions]`).

**New tests** (in `merge.rs`, where the crate keeps them):

- `the_default_merge_message_names_the_task_and_what_it_merged`: run through `merge_passed` with the
  default template; `origin/dev`'s subjects hold exactly `merge(T-5): <candidate sha>` and
  `merge(T-5): origin/review/t5`.
- `a_project_merge_message_replaces_the_default`: with
  `merge_message = "chore(merge): {task} [{project}] {source}"` the log holds
  `chore(merge): T-5 [p] <candidate sha>` and `chore(merge): T-5 [p] origin/review/t5`, and no
  `merge(T-5)` subject is left.
