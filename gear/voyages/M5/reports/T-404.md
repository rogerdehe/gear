# T-404 — report

A delivery whose text never reached the lane's input is typed again once, so a
codex lane does not sit idle with queued work.

## What changed

`crates/gear-engine/src/ops.rs` only (plus tests).

**`fn retype_key(op_id)`** — `engine.retype.<op id>`, the meta key that marks a
delivery as already typed again.

**`fn resubmit_unsent`** — the candidate set is unchanged (a lane `Deliver` op
of the project, `Submitted`, at least `UNSENT_RESUBMIT_AFTER_S` (30 s) old, its
seat `Active` at the op's generation, its binding `Active`, its agent `Idle` or
`Done`). A candidate is skipped when it already got its Enter
(`engine.resubmit.<op id>`) **or** was already typed again
(`engine.retype.<op id>`); the delivery's text now travels with the candidate
tuple.

Per candidate, after the pane tail is read:

- tail **shows** the needle → the Enter path as before (one `enter`, then
  `engine.resubmit.<op id>`); a refused key changes nothing.
- tail **does not show** the needle → the text never reached the input box
  (T-404): the delivery is typed again once with `herdr.prompt(&pane, &text)`
  (the trait's `agent prompt`: text + Enter), and `engine.retype.<op id>` is
  set; a refused prompt changes nothing (no meta, the next tick looks again).
  The retyped op id goes into the same `resubmitted` list of the tick report.

The doc comment of `resubmit_unsent` now names both halves.

## Design note (asked, defaulted)

The packet writes the retype as `herdr.agent_prompt(pane, text)`; the
`HerdrAct` trait has only `prompt(target, text)`, and design §10.1 says a prompt
targets the agent's **name**, never the pane id. The code change is limited to
`ops.rs`, so no new trait method and no name resolution were added: the retype
is `herdr.prompt(&pane, &text)`, the literal reading of the packet. Herdr itself
accepts a pane id as target (the fake resolves it, and it refuses an *unnamed*
agent — the M3.1 message names a pane), and a refused prompt just leaves the op
for the next tick. Question sent as M-5314 (`hull:207`) with that default.

## Tests (in `ops.rs`'s own test module)

- `a_delivery_that_never_reached_the_input_is_typed_again_once` — an idle named
  agent, an empty-input tail, delivery 90 s old: one `prompt` carrying the
  delivery's text, `engine.retype.O-1` = `T0 + 90`, no `enter`, no
  `engine.resubmit` key; a second call at `T0 + 120` sends nothing and types
  nothing.
- `a_delivery_younger_than_the_window_is_not_typed_again` — 20 s old, empty
  input: no prompt, no meta.
- `a_refused_retype_changes_nothing` — `inject_next = Inject::Refuse`: empty
  result, no `engine.retype` meta.
- `an_unsent_delivery_gets_one_enter_and_never_a_second` (T-371) — unchanged,
  plus: the tail shows the text, so nothing is typed again.
- `a_working_agent_gets_no_enter` — unchanged, plus: no prompt.
- `a_working_agent_with_an_empty_input_is_not_typed_again` — `Working`, empty
  input: neither Enter nor prompt.
- `a_confirmed_delivery_is_never_touched` — a `Confirmed` op gets neither the
  Enter nor a retype, and neither meta key.

`a_tail_without_the_text_gets_no_enter` (T-371) is gone: a tail without the
text is now exactly the case that is typed again (split into the tests above).

## One integration test adjusted

`crates/gear-engine/tests/it/onboard_run_contract.rs`,
`a_released_lane_whose_agent_is_gone_is_onboarded_and_given_its_task` ticked
twice, 100 s apart, with a fake whose screen never changes after a prompt: the
second tick saw "idle agent, text not in the tail" and retyped the delivery.
The fixture now sets `herdr.prompt_starts_turn = true`, so a delivered prompt
starts the fake lane's turn as a real agent does (a working agent is never a
retype candidate) — the test's intent (one delivery of its next task) is
unchanged.

## Out of scope (noticed, not changed)

- `resubmit_unsent` shares `UNSENT_RESUBMIT_AFTER_S` for both halves, as the
  packet says ("the same candidates"): 30 s is now also the retype deadline. If
  the captain wants the retype later than the Enter (the case was observed at
  2–8 minutes), a separate constant and age check would be the change.
- The retype is `prompt(&pane, …)`, not the agent name (§10.1). A pane whose
  agent lost its name is refused, not renamed here — the naming pass restores
  the name on the same tick's `names::restore`, and the following tick retypes.
- The fake's `prompt` does not put the text on the pane's screen, so an
  integration test that ticks more than 30 s after a delivery sees a "lost"
  delivery unless it models the turn start or the screen (see above).
