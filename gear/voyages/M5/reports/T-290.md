# T-290 — report

A rework packet now reaches a lane that queues input while it still works.
The fail verdict (`gear_app::tasks::settle` / `fn settle_review`) leaves the
attempt Rejected and the task Ready with a rework note; pi and claude queue
text typed mid-turn and read it after the current step, so their packet goes
at once instead of waiting for the agent to be idle.

Contract v1 defined the three gates; the captain's direction check (M-4666,
contract v2) named the session step as the fourth and said where it belongs.
This report is against contract v2.

## What it does

**`crates/gear-engine/src/dispatch.rs`**

- `LaneView` gains `pub rework_mid_turn: bool`, documented next to
  `failed_delivery`. `fn lane_view` fills it as the packet says: the seat's
  binding kind (`tx.get_binding(&seat.id, seat.generation)?`) queues input
  (`gear_herdr::queues_input`), the seat has no open attempt that is not
  Submitted, and the first of `ready_tasks_of(tx, seat)?` carries a
  `rework_note` whose last attempt (`tx.attempts_of_task`) is this seat's and
  Rejected. `fn empty_view` sets it false; the `fn view` literal in the
  module's tests too.
- `fn decide`, rule 4: an agent that is not idle passes when
  `v.rework_mid_turn` and `obs.status == Some(AgentStatus::Working)`. Rules 5
  (ratelimit/quota/auth) and 6 (cooldown) still apply, and the action is the
  `Assign` of that first ready task as today. The rule list in the header and
  the comment on the gate say so.

**`crates/gear-engine/src/ops.rs`**

- `PromptPolicy::Delivery` is now `Delivery { working: bool }`.
- `fn check_op` sets `working` true for a Deliver op whose attempt
  (`tx.get_attempt(&op.project, task, n)`) has `n >= 2`, state Delivered and
  `sent_at` None, and whose binding kind queues input; every other delivery
  keeps `working: false`.
- `fn aim` treats a Working agent as ready when `Delivery { working: true }`
  (as it already did for an at-once doorbell). The delivery does not
  interrupt: `interrupt` is still only for an urgent doorbell, so no `esc` is
  typed before a packet.

**`crates/gear-engine/src/session_runner.rs`** (contract v2, item 4)

- `fn run`: for the actions `keep` and `fresh` — which do no pane work — a
  Working agent counts as ready when the binding's kind queues input
  (`gear_herdr::queues_input`). Both the "done" phase of an already recorded
  round and the recording of a fresh `keep`/`fresh` use it, so the round still
  records through its normal path (`record`). Every other action (`new`,
  `compact`, `resume`) types into the pane and still waits for idle, as does
  every non-queuing kind. The dispatch.rs bypass around `Prep::Wait` that the
  direction check found in candidate `eb6e6a8c` is gone.

Unchanged, as the packet asks: a first packet (no rework note, so
`rework_mid_turn` false, and `decide` rule 4 still holds it), a lane with other
work in flight, and an opencode or codex lane all wait for idle.

## Out of scope (noticed, not changed)

- The `session_runner` exception is not limited to lanes (contract v2 names
  the action, not the role): a temp reviewer whose binding kind queues input
  and whose review round records `keep`/`fresh` would also count a Working
  agent as ready. No packet reaches that point unless something else already
  let a review action through, and the whole gear-engine suite still passes.
- A `Continue` to a working pi lane still waits for idle: `decide` rule 4
  passes only a rework packet, so the session exception cannot let a continue
  land mid-turn.
- The report of the attempt that failed is not affected; the rework packet
  still uses the `assign_text` wording (branch and worktree already there).
