# T-381 — report

A review round now ends when its attempt is settled by anyone, so a settled
task's overrun alert no longer comes back (M-844 T-117, M-906 T-88, M-1074
T-104 fired "budget 10 min; active 196 min; no answer" for four hours after the
captain settled each in `# Verdicts`).

## What changed — `crates/gear-engine/src/overrun.rs` only

In `fn process`, a review round counted as live while it had no reviewer
verdict (`get_review_verdict`) and no `end_at`. A captain's verdict writes
neither, so the round stayed live for ever, its active time grew, and the
"no answer" item was reopened every 15 minutes.

- `settled` is computed once per round: `review && (attempt.state !=
  AttemptState::Submitted || task.state != TaskState::Verifying)`. A review
  round is live only while its attempt is still handed in and its task is still
  with the reviewer.
- The round's `stop` for a review round is unchanged when a reviewer verdict
  exists (the verdict's time); for a settled attempt without one it is
  `tx.attempt_times(…).settled` (else `now` via the existing `stop.unwrap_or(now)`,
  which also freezes the active time at the settlement). The dev-round stop
  (`times.handed_in`) is untouched.
- `live` for a review round is now `verdict.is_none() && round.end_at.is_none()
  && !settled`, so a settled round asks nothing, writes no item and is not
  reopened on later ticks.
- In the `!live` branch, when the round ended for that reason, its open overrun
  item(s) on thread `overrun:<task>:<role>` (i.e. `overrun:<task>:review`) for
  that attempt are set `MsgState::Resolved` with result `"the attempt was
  settled"`. The filter is `Open | Waiting`, so the resolution is written once;
  `item()` (which reopens a resolved item) is never reached for a settled round
  because the function returns before it.

No other file changed.

## Tests — `mod tests` in `crates/gear-engine/src/overrun.rs`

The crate keeps its overrun tests in that module, so the new ones are there.

- New helper `submitted()`: `world()` with attempt 1 handed in
  (`gear_app::tasks::submit_result`), i.e. attempt `Submitted`, task
  `Verifying` — what a review round really runs on.
- The two existing review tests (`review_budget_uses_model_history_and_stops_at_verdict`,
  `progress_before_review_verdict_is_processed_on_the_finished_round`) now use
  that world; their assertions are unchanged and still pass (the review round
  is live at its budget, stops at the reviewer verdict, processes a progress
  answer before the verdict).
- New `a_settled_attempt_ends_the_review_round_and_resolves_its_item_once`:
  the review round asks at 30 min and writes its urgent "no answer" item; the
  captain's fail verdict settles the attempt (`gear_app::tasks::settle`, no
  review verdict, no `end_at`); the tick then resolves the item with "the
  attempt was settled" (exactly once, `resolved` time stays the first one),
  stops the round's active time at the settlement (`active_s == 2401`), and
  later ticks at 6000/9000 ask nothing more and write nothing.

## Attempt 2 — review F1 (a settled round processed a queued answer)

F1: the answer-processing block ran before the `!live` branch, so a progress
answer already queued when the captain settled the attempt was processed on the
next tick: `item()` inserted a new overrun row with `created = now` (after the
settlement) and the `!live` branch then resolved it. The explicit acceptance
(the settled review writes no item on later ticks) was violated.

Fix, `fn process` only (about one line):

    let asked_at = state.get("asked_at").and_then(Value::as_i64).filter(|_| !settled);

A settled review round no longer processes a queued answer; the existing `!live`
branch still closes the round's question and resolves any open item once. The
live path and the reviewer-verdict path (which is not `settled` and still
processes a preceding answer, as its regression requires) are untouched.

New regression `a_queued_answer_after_settlement_writes_no_overrun_item` (in the
same module), the review's ordering: review round submitted, tick at 1800 asks at
its 30-min budget, reviewer progress inserted at 1801 (`left: 0, blocker:
"none"`), captain fail settles the attempt at 1802, then ticks at 1803, 1804,
6000, 9000 each assert `overrun:T-1:review` stays **empty** (and the round's
question is resolved). Without the fix it fails at tick 1803 with a newly
created item — checked by reverting the line locally.

The first regression (`a_settled_attempt_ends_the_review_round_and_resolves_its
_item_once`) and all other overrun tests stay unchanged and pass.

## Out of scope

- A review round whose task was **cancelled** (T-93) or **failed** rather than
  settled: `cancel_task` in `crates/gear-app/src/plan.rs` abandons the attempt
  but writes no `AttemptStep::Settled`, so `times.settled` is absent and the
  stop falls back to `now`. The round asks nothing and writes no item (the
  `live` condition is false, which is the bug this task fixes), but its
  recorded active time keeps growing on every tick instead of freezing. The
  packet names only the settled case, and closing that shape means either
  writing `Settled` on the cancel path (`gear-app`, outside this packet's
  "overrun.rs only") or giving the stop a fallback for terminal task states.
  Worth a backlog line if the board ever reads review active time for a
  cancelled task.
