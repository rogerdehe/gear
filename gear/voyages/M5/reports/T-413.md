# T-413 — report

Every seat GEAR starts now writes its temp files to its own scratch directory,
and `TMPDIR` points at it, so nothing a seat, its agent or its tools write as
temp goes to the system temp directory. The parent is configurable, as Claude
Code's own temp directory is; the seat's directory goes when the seat is
released or retired.

## What changed

**(1) `crates/gear-app/src/config.rs`.** `Conventions` gains
`scratch_dir: Option<String>`, read from `[conventions] scratch_dir` (a path;
`~` is the home folder). Its default is none: the seat's worktree holds its
temp files. `Conventions::default()` and the `deny_unknown_fields, default`
serde attributes make an absent key parse as `None`; nothing else reads it at
parse time (like `quota.sources[].key_file`, the `~` is expanded by the
reader).

**(2) `crates/gear-engine/src/onboard.rs`.** Where the lane's worktree path is
known, `onboard_seat` prefixes the environment line the plan built:

```
mkdir -p <scratch>; export TMPDIR=<scratch>; export GEAR_CTX=…; export GEAR_DB=…
```

`<scratch>` is `<scratch_dir>/<project>/<seat>` when the project names one
(`~` expanded from `HOME`), else `<the seat's worktree>/.gear/tmp`.
`plan_onboard` stays pure and keeps its contract: the worktree path only exists
after Herdr made it, so the prefix is added by the caller that has it.

The worktree default is also written into the repository's own ignore file:
`.gear/` is appended once to `<git rev-parse --git-common-dir>/info/exclude`
(the common dir, so every worktree of the repository shares it) when no line
of it says `.gear/`. A path that is not a git repository, or an exclude file
that cannot be written, is left alone — the ignore only keeps `git status`
quiet.

**(3) `crates/gear-engine/src/release.rs`.** `remove_scratch` removes the
seat's scratch directory with `std::fs::remove_dir_all`, errors ignored. It is
called where a seat becomes `Released` (the seat freed after its agent left,
and the seat whose start failed) and where a lane becomes `Retired`
(`retire_one`); the worktree and its build cache still stay (17 §8a). The
directory is computed from the project's `[conventions]` and the seat's
recorded worktree path, the same rule onboarding used.

**(4) The skill.** `skills/gear/references/conventions.md` lists `scratch_dir`
in the `[conventions]` block with its default and one paragraph on what a seat
gets and that it goes on release. `skills/gear/references/rules/lane.md` and
`…/rules/review.md` replace T-412's `target/tmp` line with the packet's
sentence, word for word: "Temp files and scratch copies go in $TMPDIR (GEAR
sets it to your own scratch directory), never /tmp."

## Out of scope

- Three other places build an environment line of their own and so still leave
  `TMPDIR` at the system default: `crates/gear-engine/src/restart.rs`
  (`env_command`, a restarted agent), `crates/gear-engine/src/review.rs`
  (a reviewer's start) and the model-switch resume in `onboard.rs`
  (`resume_start` → `switch.rs`). The packet names `onboard.rs`/`plan_onboard`
  and only these files, so they are untouched; a restarted lane or a reviewer
  still writes temp files to the system temp directory until a follow-up task.
- Captain seats are bound by `gear admin init`, not onboarded by the engine, so
  they get no `TMPDIR` line (and with `scratch_dir` set, no
  `<scratch_dir>/<project>/captain`).
- The `info/exclude` append is best effort: a repository whose common dir is
  not writable keeps `.gear/` untracked in its worktrees (the checkout stays
  correct; only `git status` is noisier).
- `~` expansion (`HOME`) has no test of its own: `HOME` is process-wide and the
  engine test binaries serialize on it (`HOME_LOCK`), so only the path rule is
  tested; `expand_home` is a copy of `quota.rs`'s private one, which could not
  be shared without editing a file the packet leaves alone.
- `release_dead` (a reviewer whose agent is gone) releases a seat without
  removing a scratch directory. No reviewer has one yet (see the first point),
  so it could not be tested end to end; the packet names `release_one` and
  retirement.

## Attempt 2 (rework: F1 of the review)

F1: a configurable `[conventions].scratch_dir` is a filesystem path, so a space
in it is normal use — the emitted line was `mkdir -p /data/scratch
parent/toy/heat; export TMPDIR=/data/scratch parent/toy/heat; …`, which `sh`
read as two words: `export` refused, `TMPDIR` truncated at the space, and the
seat wrote its temp files to the system temp directory again.

**`crates/gear-engine/src/onboard.rs`**

- New `fn shell_quote(path: &str) -> String`: the path as one shell word —
  single quotes around it, an embedded `'` written as `'\''`
  (`scratch parent's/toy/heat` → `'scratch parent'\''s/toy/heat'`).
- `plan_onboard` resolves the scratch directory as before and quotes it once
  for both places: `mkdir -p {scratch}; export TMPDIR={scratch}; <the rest>`.
  Nothing else in the line changes, so the default stays
  `<worktree>/.gear/tmp` and a configured parent stays
  `<scratch_dir>/<project>/<seat>`.

Tests (`onboard.rs`, plus the one integration fixture that spells the line out):

- New `a_scratch_dir_with_a_space_and_an_apostrophe_is_run_as_it_is`: a
  `scratch_dir` of `…/scratch parent's`, onboarded; the emitted line is run
  under `sh` and the test asserts the exit status, that `$TMPDIR` is exactly
  `<parent>/toy/heat` and that the directory exists.
- The three existing onboard tests and
  `crates/gear-engine/tests/it/onboard_run_contract.rs` now expect the quoted
  form (`mkdir -p '<path>'; export TMPDIR='<path>'; …`).
