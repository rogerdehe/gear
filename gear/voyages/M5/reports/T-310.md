# T-310 — report

The board's raw-mode PTY test now waits on the descriptor instead of on the
clock: `read_until` has no `thread::sleep` left, and the frame assertion no
longer pays two fixed sleeps.

## What changed

**`crates/gear-board/tests/it/board_contract.rs`, fn `read_until` only.**

- The master is still set `O_NONBLOCK` (a board that draws nothing must fail
  the test, not hang it).
- Each wait is `libc::poll` on the master with `POLLIN` and the time left to
  the deadline in milliseconds — the same call `Frames::wait` in the same file
  makes, without its 50 ms cap.
- A read follows only a ready descriptor; nothing is read speculatively.
- The loop returns as soon as the buffer holds the needle: the needle is
  `"q quit"`, which ends the footer, the last line of a frame, so nothing is
  waited for after it. The 50 ms "let the rest arrive" sleep is gone with it.
- On the deadline the function returns what it has, as before.
- The doc comment no longer promises a drain.

No other file touches the change.
