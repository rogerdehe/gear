# T-425 attempt 5 — the integration test follows the per-seat rule

The rework named one thing: `dead_temp_slot_contract.rs` fn
`a_stuck_checkout_is_not_restarted_by_a_recovered_seat` still asserted the old
rule (three failed checkouts on one seat park it `Unknown` and mark the attempt
stuck). It is rewritten; no source file changed.

## The test, to the new rule

`crates/gear-engine/tests/it/dead_temp_slot_contract.rs` only. Same name and
the same intent — a stuck checkout is never restarted by a seat that comes
back, and the seat serves the next hand-in — now driven by the contract's
sequence:

1. One hand-in (T-1), one temp slot. Two failed checkouts on `review-1`: T-1
   is **not** stuck, `engine.review_checkout_seats.p.T-1.1` names only
   `p:review-1`, and the seat is not retired yet.
2. The third failure retires `p:review-1`, with the worktree path and the Git
   error in the reason and the once-only "remove that worktree" notice
   (`Info`) to the captain; its `engine.review_pending` is cleared.
3. The same hand-in goes to a second seat in the same tick, which fails on the
   same candidate: `engine.review_checkout_seats.p.T-1.1` is
   `p:review-1,p:review-2`, only then is `engine.review_checkout_stuck`
   written, and the captain gets today's notice once — `System`, `Info`, and
   nothing in `actionable_for`, so it does not ring.
4. T-2 is handed in; the freed seat takes it (its checkout is submitted) while
   `review/t1` gets no further checkout, so no seat restarts the loop and the
   stuck review strands no slot.

The first half used to be observed after three failures on `review-1`; under
the contract the retirement and the second seat's failure fall in one tick, so
the "one seat does not make it stuck" assertion is made at two failures (and
again by the two-seat list before the stuck key appears).

## Out of scope

- When an earlier notice for the same task already told the captain something
  ("every temp seat is in use"), the engine's one-message-per-task-per-attempt
  rule suppresses the later stuck notice. The rework's "the captain is still
  told once" holds where the stuck notice is the first; the test lands in that
  shape (T-1's seat is retired before any queue notice for it is written). The
  suppression itself is existing behaviour in `tell_captain` and is not
  changed here, as the rework says.
