# T-425 — report

A review worktree that cannot check out stops its **seat**, never the task.
`crates/gear-engine/src/review.rs` only.

## What changed

### 1. The checkout failures are counted per seat

`prepare_seat_tree` (the `Err` arm) counts on
`engine.review_checkout_fails.<seat>` — no project, task or attempt in the key —
and a checkout that lands clears the count (`set_meta(key, "")`), so the count is
of failures in a row on that seat, not of its whole life.

On the **third** failure on one seat, `retire_checkout_seat` runs:

- the seat's pending review is cleared (`engine.review_pending.<seat> = ""`), so
  `tasks_to_review` hands the same attempt to another seat on the next tick;
- the seat is `Retired` (through `Released`, the transition a temp seat has to
  `Retired` in design/10) with the reason
  `its worktree <path> failed three checkouts: <git error>; remove that worktree`
  — the worktree path and the git error are both in it;
- the captain is told **once** (`engine.review_retired_told.<seat>`, thread
  `review-seat:<seat>`): the reviewer is retired and that worktree must be
  removed.

The task is **not** marked stuck by a seat's own failures: a `Retired` temp seat
is never reused (`temp_seat_of`, `free_seat`), so the attempt goes elsewhere.

### 2. An attempt is stuck only when two different seats failed on it

`engine.review_checkout_seats.<project>.<task>.<attempt>` holds the distinct seat
ids an attempt's checkout failed on. `mark_checkout_stuck` (and today's
`tell_captain` notice) runs only when a **second** seat fails too — the candidate
itself cannot be checked out. The `checkout_stuck` guard at the top of the
hand-in loop is unchanged; only its comment now says two seats instead of three
tries.

### 3. A half-done merge in a warm worktree no longer fails the checkout

`prepare_review_tree` runs `git merge --abort` in the seat's worktree **before**
the stash (git refuses both the stash and the checkout while an unresolved merge
sits in the worktree — the incident's "could not write index"), and
`git reset --hard` after the stash and **before** `fetch`/`checkout`. Both
errors are ignored: no merge in progress is no error. The order keeps the
evidence the stash preserves (a merge --abort keeps the pre-merge changes, the
stash then takes them).

### Tests (`crates/gear-engine/src/review.rs`)

- `a_seat_whose_checkout_fails_three_times_is_retired_not_the_task`: one broken
  worktree (`REVIEW_GIT_FAIL_ON`, the new path-scoped failure of the fake git)
  fails three times → the seat is `Retired`, the reason names its worktree path
  and the git error, its pending review is cleared, the captain has exactly one
  `review-seat:<seat>` message, the hand-in is not stuck, and another seat
  (`p:review-2`) receives its `Deliver` op.
- `a_hand_in_failing_on_two_different_seats_is_marked_stuck`: every checkout
  fails → the first seat is retired, the second seat's failure marks attempt 1 of
  T-2 stuck (the stored reason carries the git error), the captain gets today's
  notice on the task thread, and no reviewer starts for it afterwards.
- `a_warm_worktree_left_mid_merge_checks_out_after_the_reset`: a real git
  worktree left with a conflicted merge (`MERGE_HEAD` present) is checked out on
  the candidate after the reset.
- The old `standby_checkout_retries_then_releases_after_exhaustion` (three
  failures → stuck task) asserted the behaviour this task replaces; it is
  replaced by the first test above.

## Out of scope

- A retired seat whose pane still holds a live agent (the warm `Standby` path) is
  not closed here: the packet names the retirement, the pending review and the
  notice, and closing a pane on retirement is a design decision of its own. The
  seat can never be started again, and the captain removes its worktree.
- The dangling doc comment `/// Count one failed checkout for this seat
  generation.` above `checkout_stuck_key` was already there and is left alone.
