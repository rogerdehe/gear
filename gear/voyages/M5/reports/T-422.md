# T-422 — report

The merge gate is no longer sized by an equal share: both of its build-slot
calls take at least 4 jobs, at normal priority.

## What changed

`Makefile` only — the `gate` target, its `##` comment and its two commands:

```make
gate: prune-tmp ## the merge gate on the shared machine: workspace build and the whole suite, each sized by build-slot at least 4 jobs, at normal priority (the test run measures the machine after the build)
	BUILD_SLOT_MIN=4 BUILD_SLOT_PRIORITY=normal tools/build-slot/build-slot.sh cargo build --workspace --all-targets && BUILD_SLOT_MIN=4 BUILD_SLOT_PRIORITY=normal tools/build-slot/build-slot.sh scripts/test.sh
```

**Unchanged** — `check`, `full`, `install`, `export TMPDIR`, `prune-tmp`,
`.PHONY`, the header comment, and `tools/build-slot/` itself.

## Friction

`BUILD_SLOT_PRIORITY` did not exist when this branch was cut: the script
hardcoded `taskpolicy -c utility` / `nice -n 10`, and the packet said Makefile
only, so the variable would have been inert. I asked (thread mast:192) and went
on with the packet literal; the captain answered (M-5766) that `origin/dev`
gained `BUILD_SLOT_PRIORITY` a few minutes later, and that merge plus the
re-run above is the result.

The suite took 236 s against the 60 s pass mark, on a machine at load 28-50
with nine build-slot runs alive; with the floor it still got 4 jobs, which is
what this task asks for.

## Out of scope (noticed, not changed)

- `scripts/test.sh` builds the test binaries itself (`cargo nextest run
  --workspace --no-run`), so `gate` builds the workspace twice: once through
  its own `cargo build`, once inside the test script (also noted in T-419).
