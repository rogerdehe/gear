# T-370 — report

The "The review of T-n waits: every temp seat is in use" notice no longer rings
the captain. It was an item in the INBOX (and so a doorbell) for nearly every
hand-in in M5, and every time the captain answered "Information.": its own text
says the lane is not blocked.

## Cause

`crates/gear-engine/src/review.rs` `fn tell_captain` inserted the notice as
`MsgKind::Question` with `MsgState::Open`. `Store::actionable_for` lists only
`open` and due `waiting` messages, so the notice was an actionable item: it held
an INBOX slot and the doorbell rang for it.

## What changed

`crates/gear-engine/src/review.rs`, `fn tell_captain` only; no other design.

- The message is now `MsgKind::System` with `MsgState::Info` — the state the
  direction check's captain notice uses. The captain's information list shows
  it; `actionable_for` never returns it, so nothing rings and no INBOX slot is
  held.
- The once-per-attempt guard is unchanged: `review_wait_told_key` is still read
  before the message and set after it, so a second tick tells nothing.
- The `already` check still reads `actionable_for` for a message of the task, as
  the packet says: it now only catches some other open item of the task, and the
  meta key alone keeps the notice once per attempt.

## Attempt 2: the gate failure against dev

Attempt 1 was merged with dev and the gate ran on it: one test failed,
`crates/gear-engine/tests/it/dead_temp_slot_contract.rs`
`a_stuck_checkout_is_not_restarted_by_a_recovered_seat`. It reads the captain's
side of a stuck review checkout, and that notice is this very one — `tell_captain`
told with the reason `review checkout failed 3 times: review checkout <path>:
injected Git failure`. The test still asked `actionable_for` for it and expected
one item:

```
let items = store.read(|tx| tx.actionable_for("p", "p:captain", T0 + 40)).unwrap();
assert_eq!(items.iter().filter(|m| m.body.contains("injected Git failure")).count(), 1);
   -> left: 0, right: 1
```

The test follows the change (no code change beyond attempt 1's): it reads the
thread `T-1:1`, asserts exactly one message with the "injected Git failure" text,
its recipient `p:captain`, `MsgKind::System` and `MsgState::Info`, and asserts
`actionable_for` holds no such message. It is the one test outside
`src/review.rs` that named this notice; a grep for the notice's text,
`review_wait_told` and `actionable_for` over `crates/` finds no other.

`origin/dev` (`c071db05`) was merged in; the merge was clean.
