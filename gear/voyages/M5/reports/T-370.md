# T-370 — report

The "The review of T-n waits: every temp seat is in use" notice no longer rings
the captain. It was an item in the INBOX (and so a doorbell) for nearly every
hand-in in M5, and every time the captain answered "Information.": its own text
says the lane is not blocked.

## Cause

`crates/gear-engine/src/review.rs` `fn tell_captain` inserted the notice as
`MsgKind::Question` with `MsgState::Open`. `Store::actionable_for` lists only
`open` and due `waiting` messages, so the notice was an actionable item: it held
an INBOX slot and the doorbell rang for it.

## What changed

`crates/gear-engine/src/review.rs`, `fn tell_captain` only; no other design.

- The message is now `MsgKind::System` with `MsgState::Info` — the state the
  direction check's captain notice uses. The captain's information list shows
  it; `actionable_for` never returns it, so nothing rings and no INBOX slot is
  held.
- The once-per-attempt guard is unchanged: `review_wait_told_key` is still read
  before the message and set after it, so a second tick tells nothing.
- The `already` check still reads `actionable_for` for a message of the task, as
  the packet says: it now only catches some other open item of the task, and the
  meta key alone keeps the notice once per attempt.

## Tests

`crates/gear-engine/src/review.rs`, where the crate keeps its review tests.

New:

- `the_review_waits_notice_is_information_while_both_temp_seats_are_busy` — the
  packet's acceptance: a project with `[quota].temps = 2` and two temp seats
  bound to other tasks (T-9, T-8) gets its T-1 hand-in in one `System`/`Info`
  message on the thread `T-1:1` whose body carries
  "waits: every temp seat is in use"; `actionable_for` is empty; a second tick
  writes no second message (`T-1:2` stays empty). New fixture `CONFIG_TWO_SLOTS`
  next to `CONFIG_NO_SLOT`.

Updated, their expected kind and state follow:

- `without_a_free_slot_no_reviewer_starts` — the notice is read from the thread
  `T-1:1` and asserted `System`/`Info`; the captain's `actionable_for` is
  asserted empty instead of holding one item, and a second tick still leaves
  exactly one message.
- `the_review_waits_notice_is_told_once_per_attempt` — reads the notice from the
  thread, asserts `System`/`Info` and an empty `actionable_for`; the
  resolve-then-tick and next-attempt steps keep their assertions, the next
  attempt's message is read from `T-1:2` as `System`/`Info` and still rings
  nothing.

`make check CRATE=gear-engine TESTS='test(review)'` — 145 passed, 580 skipped;
the two new/updated tests also pass under `test(the_review_waits)`. No other
crate's tests read this notice (grepped for its text and `review_wait` across
`crates/`), so nothing else follows it. `make gate` is the merge gate's.

## Out of scope

`tell_captain_of_hand_ins_without_reviewers` (the same file) still writes
`MsgKind::System`, `MsgState::Open`, `urgent: true` on the thread
`verdict:<task>:<attempt>` for a project without `[temps]`: that one asks the
captain to settle the attempt by hand, so it is an action item by design and the
packet did not name it.
