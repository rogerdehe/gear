# T-294 — report

Proof that the engine carries on after its Herdr server goes away and comes
back (T-176's rest, open since M4).

## What changed

**`crates/gear-herdr/src/lib.rs`** — only the doc comment of `SocketHerdr`:
"Holds one blocking client connection." became

> Each call opens its own connection to the socket path (board-herdr
> `HerdrClient::call_inner`), so a Herdr server restarted on the same path is
> reached on the next call; nothing reconnects.

That is the whole code change; nothing was designed or redesigned. (The merge
with the latest `origin/dev` brought T-314's `socket` field next to this
comment; both stand.)

**`crates/gear-engine/tests/it/herdr_outage_contract.rs`** (new, `mod` line in
`tests/it/main.rs`): a project with an idle captain, one idle lane (`heat`) and
a ready task `T-1`.

- Tick 1 with `FakeHerdr.agents_fail = true`: `observe_failed` is `["p"]`, no op
  row in any state, the lane's stall thread is empty and `FakeHerdr.calls` is
  empty — nothing decided, no side effect.
- Tick 2 with `agents_fail` still `true`: same — two failed ticks in a row flag
  nothing (`report.flagged` empty too), still no op and no stall item.
- Tick 3 with `agents_fail = false` (the server back on the same path): the
  ready task's packet goes out, exactly one `Call::Prompt` to the lane pane
  carrying `T-1`.
