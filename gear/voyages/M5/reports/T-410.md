# T-410 — report

A departed voyage's `done:`, `bar:` and `eta:` change only when the user asked
for it and confirmed it: `gear plan apply --confirmed` carries that word, and
without it the whole apply is refused with nothing written.

## What changed

The four files the packet names, plus the tests each crate keeps.

**`crates/gear-app/src/draft.rs`** — `Draft` gains `pub confirmed: bool`,
`false` from `parse`.

**`crates/gear-app/src/plan.rs`** —

- `fn departed_voyages(tx, project)` — the milestones whose stored voyage had a
  departure, read **before** `fix_departures` runs in the apply closure. That
  set is what `record_voyages` guards, so a voyage whose departure this very
  apply fixes (a reused id, T-239) is not in it (M-5414 (a): a voyage that
  departs in this apply describes itself freely).
- `fn record_voyages(tx, project, draft, departed, now)` — after the existing
  `done`/`bar`/`eta` and eta-duration checks, for a milestone in `departed`,
  each of the three fields whose trimmed text differs from the stored one
  (a stored `None` reads as `""`, so nothing is exempt) is refused when
  `draft.confirmed` is false:

  ```
  milestone M1: eta changed after departure (stored "8h", got "10h"): the goal,
  the bar and the eta change only when the user asks; confirm it with them, then
  apply again with --confirmed
  ```

  — `bad(0, …)`, the first 40 characters of each value. With `confirmed` the
  change goes on to the upsert and each changed field records a starred
  decision of kind `user`, `what` = `eta of M1 changed from "8h" to "10h"`,
  `why` = `confirmed by the user`, `line` = the two joined with ` | why: `,
  `source` = `gear` (the same shape as the staffing lock's user decision,
  T-392).
- The doc comment of `record_voyages` names the rule.

**`crates/gear-cli/src/main.rs`** — `PlanOp::Apply` gains
`#[arg(long)] confirmed: bool` ("The user asked for this goal, bar or eta change
and confirmed it."), `cmd_plan` passes it, and `run_plan` sets it on the draft
right after `draft::parse`, before `plan::apply`. `run_plan` gained the
parameter; its call sites in the CLI tests now pass `false` (the confirmed path
is exercised by the new test).

**`skills/gear/references/captain.md`** — the `eta:` paragraph of §2 now ends:
"After departure apply refuses a change to `done:`, `bar:` or `eta:` until you
pass --confirmed; pass it only when the user asked for that change and confirmed
it in a dialog. A short clock is answered by working faster, never by moving the
eta."

## Design notes (asked, answered)

Two readings of the packet met existing behaviour; both were sent as questions
and are settled now:

- M-5403 (`hull:210`) — a stored field that is `None` (a milestone that
  departed before its block existed, T-22 R2): I proposed exempting it;
  **the captain answered (a)**, only a stored, stated value is guarded — then
  M-5410 (direction check) made it explicit: no exemption for missing stored
  fields either. The code has no exemption; a departure without words gets them
  only with `--confirmed`, and `editing_a_grandfathered_milestone_keeps_its_historical_departure`
  now asserts the refusal and then the confirmed apply.
- M-5405 (`hull:211`) — a milestone whose departure this apply fixes (a reused
  id emptied by T-239): **M-5414 answered (a)**, it describes itself freely.
  Implemented by reading the departures before `fix_departures` rather than by
  asking `fix_departures` what it did, so no signature of it changed.

## Tests

`crates/gear-app/tests/it/voyage_contract.rs`:

- `a_departed_voyage_changes_only_with_the_users_confirmation` — a departed M1
  (`FULL`): changing `done`, `bar` and `eta` (8h → 10h) one at a time is each
  refused with the text (including `stored "8h", got "10h"`), and the plan
  version, the stored words and the task count are untouched; the same draft
  with `confirmed: true` applies and records three starred `user` decisions
  with the exact `what`/`why`/`line`; an unchanged block applies again with no
  confirmation and records no new decision.
- `a_voyage_that_has_not_departed_changes_without_confirmation` — a block with
  no task: 8h → 10h without `--confirmed`, and no decision.
- `editing_a_grandfathered_milestone_keeps_its_historical_departure` — the
  first block on an already departed milestone is refused (`stored "", got
  "users install it"`), then applies with the confirmation; the departure stays
  the first task's.
- The tests that change a departed voyage's words on purpose now apply with
  `run_confirmed` (a new helper): `a_voyage_is_stored_with_its_departure_and_shown`,
  `an_eta_that_is_not_a_duration_is_refused`, and
  `the_departure_is_the_first_task_creation_even_without_the_block`.

`crates/gear-cli/src/main.rs` (`mod tests`):

- `plan_apply_takes_the_confirmed_flag` — `gear plan apply --confirmed plan.md`
  parses with the flag set and the path kept, without it the flag is false; an
  apply of a departed M2 with a changed `eta:` is refused, and the same file
  with the flag applies and stores `2h`.

## Out of scope (noticed, not changed)

- The refusal is `BadFormat` at `line 0`, the code `record_voyages` already
  uses for its other refusals; a draft with several milestone blocks reports
  the first offending one.
- `--confirmed` confirms whatever the draft changes: one apply that changes two
  fields records two decisions, one each.
- The decision's `source` is `gear` (GEAR's own entry, the T-392 shape); if the
  captain prefers `plan`, that is one string.
