# T-407 — report

The engine now logs how long its multi-step operations take: one line per
finished step and one total, `probe <op> <seat or task> <step> <ms>
total=<ms>`, through the engine log it already writes (stderr, which `gear
run` redirects into `engine.log`, as the store's slow-write line does). A
minute-long `/new` switch now says which step took the minute.

## What changed

**`crates/gear-engine/src/ops.rs`** — the probe writer, and the delivery's
steps.

- `fn probe_line(op, subject, step, ms, total)` formats the one line, and
  `fn probe(...)` (crate) writes it with `eprintln!` (the engine's stderr is
  its log — the same stream [`gear_store::slow_write_line`] uses, which the
  packet keeps as item 5) and keeps it in `static PROBE_LOG` for a test to
  read. `pub fn probe_log()` copies that buffer (capped at 1024 lines): it
  does not drain, because two tests running side by side would take each
  other's lines — each test reads its own by a seat or task id no other test
  shares.
- a delivery is `typed` (the op went Submitted; the text and its Enter are one
  Herdr call, so the step runs from the op's `created`), `enter` (the lost
  Enter of [`resubmit_unsent`], measured from the typing it waited behind; a
  retyped op logs `typed` again), then `confirmed` or `failed` — both measured
  from the op row read before the update, so `ms` runs from the typing
  (`updated`) and `total` from the intent (`created`).
- `Prepared::Run` carries `probe: Option<(task, created)>` for a Deliver op, so
  the step line names the task without re-reading the op.

**`crates/gear-engine/src/session_runner.rs`** — a session action (`new`,
`resume`, `compact`, `keep`, `fresh`) logs one line per step it leaves
(`initial`, `enter`, `wait_exit`, `wait_resume`, `start_fallback`, …) and one
`done` line whose `ms` and `total` are the whole action. `fn step` (which
every transition goes through) writes the line of the step it leaves; `record`
writes the `done` line. The times are the durable `step_at`/`t0` of the state
in the seat's meta, so an engine restart in the middle logs the right
durations. One field was added to that durable state — `started`, the time the
state was created — because `t0` is re-anchored when the action's own wait
begins (`enter`), and the whole must run from the first step to `done`.

**`crates/gear-engine/src/restart.rs`** — every `Phase` (`stop`, `exit`,
`start`, `finish`) is one line, the last one carrying the whole restart. The
plan had no time in it (only `waited`, a tick count), so it now carries `at`
(the phase began) and `started` (the restart began); each phase sets `at` when
it moves the plan on, and `advance` logs the phase that ended.

**`crates/gear-engine/src/merge.rs`** — `struct Probe` logs the five steps of
one attempt: `fetch` (with the reset to the integration branch), `merge`
(pinned candidate and review branch, plus the conflict paths), `gate`, `push`
(also in PR mode) and `close`. A merge is one worker's run and is re-run from
its first step when it is retried or when the engine dies, so its times are the
worker's own clock (`Instant`, millisecond resolution — an op's stored times
are whole seconds, which cannot show a 300 ms step).

## Tests

- `gear-engine` (`tests/it/session_dispatch_contract.rs`),
  `a_session_switch_to_done_logs_one_probe_line_per_step_and_one_total`: a
  lane of its own (`p:probe`) is switched to done by two ticks; the log is
  exactly `probe new p:probe initial 0 total=0`, `enter 1000 total=1000`,
  `wait_action 6000 total=7000`, `done 7000 total=7000`.
- `gear-engine` (`tests/it/deliver_confirm_contract.rs`),
  `a_delivery_confirmed_after_forty_seconds_logs_its_step_in_ms`: typed at
  `T0+11`, confirmed at `T0+51` → `probe deliver T-707 confirmed 40000
  total=41000`; and `a_delivery_that_was_never_read_logs_failed` → `probe
  deliver T-707 failed 180000 total=181000`.
- `gear-engine` (`src/restart.rs`), `a_restart_logs_one_probe_line_per_phase`:
  `stop`, `exit`, `start`, `finish`, the exit step showing the tick it waited,
  the last line the whole restart.
- `gear-engine` (`src/merge.rs`), `a_merge_logs_its_five_steps_in_the_engine_log`:
  `fetch`, `merge`, `gate`, `push`, `close`, each with its own ms and the
  attempt's time so far.

Every test uses a seat or task id of its own (`p:probe`, `T-707`, `T-9071`) and
reads the line by it, so the process-wide buffer of a parallel test cannot be
mistaken for its own.
