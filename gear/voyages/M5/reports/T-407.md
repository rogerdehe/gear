# T-407 — report

The engine now logs how long its multi-step operations take: one line per
finished step, and one completion line per finished operation, `probe <op>
<seat or task> <step> <ms> total=<ms>`, written through the tick log the engine
already writes (T-398's path, so the lines carry the same UTC stamp). A
minute-long `/new` switch now says which step took the minute.

## What changed

**`crates/gear-engine/src/ops.rs`** — the probe writer, and the delivery's
steps.

- `fn probe_line(op, subject, step, ms, total)` formats the line; `fn
  probe(...)` keeps it in `static PROBE_LOG`. `pub fn take_probe_log()` hands
  the lines to the engine, which drains them into `engine.log` every tick;
  `pub fn probe_log()` copies them for a test without draining (two tests in
  one process would otherwise take each other's lines — each test reads its own
  by a seat or task id no other test shares).
- a delivery logs `typed` (the text went in; the step runs from the op's
  `created`) and `enter` (the Enter that follows it in the same `herdr prompt`
  call, so its own step is 0 ms and its `total` still runs from the intent),
  then `confirmed` or `failed` (measured from the op row read before the
  update: `ms` from the typing `op.updated`, `total` from the intent
  `op.created`), then the delivery's own `done` line with the whole. The lost
  Enter of `resubmit_unsent` (T-371) logs `enter` with the wait it ended, and a
  retyped packet logs `typed` again.
- `Prepared::Run` carries `probe: Option<(task, created)>` for a Deliver op, so
  the step line names the task without a second read.

**`crates/gear-cli/src/main.rs`** — one drain beside the release drain (T-398,
allowed by contract v5/M-5795): `for line in gear_engine::ops::take_probe_log()
{ writeln!(out, "{line}") }`, so the probe lines are stamped by the same writer
and land in `engine.log`. Nothing is written to stderr.

**`crates/gear-engine/src/session_runner.rs`** — a session action (`new`,
`resume`, `compact`, `keep`, `fresh`) logs one line per step it leaves
(`initial`, `enter`, `wait_exit`, `wait_resume`, `start_fallback`, …) and one
`done` line whose `ms` and `total` are the whole action. `fn step` (every
transition goes through it) writes the line of the step it leaves; `record`
writes the `done` line. The times are the durable `step_at` of the state in
the seat's meta. One field was added to that durable state — `started`, the
time the state was created — because `t0` is re-anchored when the action's own
wait begins (`enter`), and the whole must run from the first step to `done`.

**`crates/gear-engine/src/restart.rs`** — every `Phase` (`stop`, `exit`,
`start`, `finish`) is one line and the restart has its own `done` line. The
plan had no time in it (only `waited`, a tick count), so it now carries `at`
(the phase began) and `started` (the restart began); each phase sets `at` when
it moves the plan on, and `advance` logs the phase that ended — including the
phase that ends a step which then waits.

**`crates/gear-engine/src/merge.rs`** — `struct Probe` logs `fetch` (with the
reset to the integration branch), `merge` (pinned candidate and review branch,
and the conflict paths), `gate`, `push` (also in PR mode), `close`, and the
merge's own `done` line.

## The merge's step times are durable (direction check M-5797/M-5803)

A step's **begin** and its end are written into the merge op's meta
(`engine.merge_probe.<op id>`) as they happen, from the merge worker, which
opens the engine's store for that one row. Every stamp is the wall clock and
every `total` runs from the op's durable intent (`created`), never from a clock
of the process: the attempt that runs after an engine restart **recovers the
durable beginning of the step it found interrupted**, so that step is measured
from the time it really started and its clock is not restarted. A test does
exactly that (below).

Two consequences, both intended: the probe writes one meta row at each step
boundary (10 writes per merge attempt; a store write over the slow threshold
still prints its own line, item 5 of the packet), and the worker is a second
writer on the store — the busy timeout added for T-379 is what makes that safe.

## Tests

- `gear-engine` (`tests/it/session_dispatch_contract.rs`),
  `a_session_switch_to_done_logs_one_probe_line_per_step_and_one_total`: a lane
  of its own (`p:probe`) is switched to done over two ticks; the log is exactly
  `probe new p:probe initial 0 total=0`, `enter 1000 total=1000`,
  `wait_action 6000 total=7000`, `done 7000 total=7000`.
- `gear-engine` (`tests/it/deliver_confirm_contract.rs`),
  `a_delivery_confirmed_after_forty_seconds_logs_its_step_in_ms`: typed at
  `T0+11`, confirmed at `T0+51` → `probe deliver T-707 confirmed 40000
  total=41000`, then `done 41000 total=41000`;
  `a_delivery_that_was_never_read_logs_failed` → `failed 180000 total=181000`,
  then `done`; `a_typed_delivery_logs_its_typed_and_enter_boundaries` (FakeHerdr,
  `execute_intended`): `typed 30000 total=30000`, `enter 0 total=30000`.
- `gear-engine` (`src/restart.rs`), `a_restart_logs_one_probe_line_per_phase`:
  `stop`, `exit`, `start`, `finish`, `done` — the exit step shows the tick it
  waited, the last line is the whole restart.
- `gear-engine` (`src/merge.rs`), `a_merge_logs_its_five_steps_in_the_engine_log`:
  `fetch`, `merge`, `gate`, `push`, `close`, `done`, each with its own ms and
  the operation's time so far; and
  `a_step_interrupted_by_a_restart_is_measured_from_its_durable_beginning`: a
  record whose `fetch` began a minute before the attempt makes the fetch line
  measure from that beginning (≥ 60 000 ms) and keeps it with its end.

Every test uses a seat or task id of its own (`p:probe`, `T-707`, `T-708`,
`T-709`, `T-9071`, `T-9072`) and reads the line by it, so the process-wide
buffer of a parallel test cannot be mistaken for its own.
