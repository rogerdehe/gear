# T-269 — report

`gear admin init` refuses a config whose Herdr session is not the one the
caller's shell runs in: since v0.4.5 there is one store per Herdr session, so
such a config would land in this session's store, and that store's engine
never reaches the panes. The change is confined to
`crates/gear-cli/src/main.rs` (`cmd_admin_init`), plus its contract tests in
`crates/gear-cli/tests/it/admin_init_contract.rs`.

## What it does

`cmd_admin_init` gains one closure, `refuse_a_foreign_session(&parsed)`,
called in both branches — in `--check` right after the config is validated
(before "config ok" and before the branch-clash check), and in a real init
right after the config is read (before the store is opened, so before anything
is written).

It refuses only when all of these hold:

- `HOME` is known and `HERDR_SOCKET_PATH` is set;
- `session_name_of(home, socket)` is `Some(name)` — the socket is a named
  session's (`~/.config/herdr/sessions/<name>/herdr.sock`), not the default
  one;
- `project.herdr_session != name`;
- `GEAR_DB` is unset, or names `default_store_in(home, socket)` itself. A
  caller who names another store gets no check, since that store need not
  belong to a session — this is the reading the captain confirmed (M-4392,
  contract v2), because `main` fills `GEAR_DB` with the session's own default
  store before `run`, so a plain "`GEAR_DB` is set" gate would be dead for a
  real init.

The refusal is

    ERROR BAD_FORMAT: project <id> names herdr_session <configured>, but this
    shell runs in session <name>: its store and engine are this session's; run
    init from a pane of session <configured>, or fix herdr_session

## Tests (`crates/gear-cli/tests/it/admin_init_contract.rs`)

`init_refuses_a_config_for_another_herdr_session`, over an injected `HOME` and
`HERDR_SOCKET_PATH`, with the helpers `config_in_session` and
`init_from_session`:

- socket `sessions/alpha/herdr.sock`, `herdr_session = "beta"`: `--check`
  exits 1 with `ERROR BAD_FORMAT: ` and that exact text, and prints no
  "config ok"; a real init exits 1 with the same text and creates no
  `<home>/.local/state/gear/alpha/gear.db`.
- `herdr_session = "alpha"` on that socket: `--check` passes and a real init
  registers into `alpha`'s own store.
- the default socket (`<home>/.config/herdr/herdr.sock`) with
  `herdr_session = "beta"`: `--check` and init both pass.
- `GEAR_DB` named by the caller with the alpha socket and `herdr_session =
  "beta"`: `--check` and init both pass, and the project is registered in that
  store.

`make check CRATE=gear-cli`: 140 tests, all pass.
