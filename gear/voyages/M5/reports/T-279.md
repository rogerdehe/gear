# T-279 — a task is never longer than the project's cap, 60 minutes by default

A lane works unattended and is reviewed only at its hand-in, so a task of hours
is a stretch nobody checks and one wrong turn costs all of it. The cap that
decompose rule 5 gave no number now has one, and `apply` enforces it.

## Code

`crates/gear-app/src/config.rs`

- `pub const MAX_TASK_MIN: u32 = 60` — the default cap.
- `Conventions` gains `max_task_min: u32`, read from `[conventions] max_task_min`
  like `review_max_rounds` (`serde(default)` through `impl Default`), default 60.
- `validate` pushes an issue on `conventions.max_task_min` when it is 0 (“must be
  at least one minute (the default is 60)”), and the doc comment above
  `Conventions` names the new default.

`crates/gear-app/src/plan.rs`

- Before the validation loop, `apply` reads the cap once:
  `[conventions].max_task_min` from the stored config, `MAX_TASK_MIN` when no
  config parses (a project with no stored config, or one that does not parse).
- Every estimate the draft sets is checked inside the validation loop, so the
  whole draft is refused before anything is written: task = the draft's id, or
  `NEW` for a new block. The reason is exactly the packet's text:

  ```
  {task}: estimate {estimate} min is over the project's cap of {cap} min: cut it into tasks of at most {cap} min, each with its own test cycle ([conventions] max_task_min)
  ```

  An estimate equal to the cap applies; a NEW block without `estimate:` keeps
  its own (earlier) refusal.
- A rework estimate (`estimate=` on a `# Verdicts` fail, `set_task_rework_estimate`)
  is untouched: it is the price of finishing a task that is already open.

## Docs

- `skills/gear/references/decompose.md`: rule 5 is now “**Right size: at most 60
  minutes** (the project's `[conventions] max_task_min`; apply refuses more) …”
  with the packet's wording; §4 Self-check gains “- **Size:** no estimate over
  the cap; the whole voyage is in the plan before departure.”
- `skills/gear/references/conventions.md` §8 lists `max_task_min = 60` in the
  `[conventions]` block, with the reason and the rework exemption.

## Tests

`crates/gear-app/tests/it/config_contract.rs`

- `max_task_min_defaults_to_sixty_and_a_project_may_raise_it`: the default is 60
  and validates clean; `max_task_min = 90` parses to 90 and validates clean.
- `a_max_task_min_of_zero_is_refused`: `max_task_min = 0` gives exactly the
  `conventions.max_task_min` issue.

`crates/gear-app/tests/it/plan_size_contract.rs` (new module, registered in
`tests/it/main.rs`)

- `a_new_block_over_the_default_cap_is_refused_and_nothing_is_written`: a NEW
  block with `estimate: 61` is refused with the exact text above and nothing is
  written — no task, plan version still 0.
- `an_estimate_of_exactly_the_cap_applies`: `estimate: 60` creates the task.
- `a_project_may_plan_longer_tasks_with_its_own_max_task_min`: with
  `max_task_min = 90`, 90 applies and 91 is refused.
- `raising_an_existing_task_over_the_cap_is_refused`: raising T-1 to 61 is
  refused, T-1 keeps its 30 and the plan version stays; 60 on an existing task
  applies.
- `a_rework_estimate_over_the_cap_applies`: a `# Verdicts` fail with
  `estimate=120` settles the attempt and stores the 120-minute rework.

`crates/gear-app/tests/it/voyage_contract.rs`: two tests plan long tasks to
exercise the voyage's pace and scope arithmetic (90/120 and 300 minutes); they
raise the cap with the new `lift_the_cap` helper so their subject is unchanged.
The 60-minute `time_contract` fixtures need nothing (its 90 is a parse-only
test).

Validation: `make check CRATE=gear-app` — 473 tests, all passed.

## Out of scope

- A stored `max_task_min = 0` (which `validate` now reports at kickoff and at a
  config change) would cap every estimate at 0 and refuse every plan. The packet
  names only the default-when-none-parses fallback, so the stored value is used
  as it is; this is outside normal use and not handled.
- `gear/voyages/M2/plan.md` (a landed voyage) and `M2.1`, `M3.1` hold historical
  plans; M2's 90-minute estimate is history, not a draft to apply.
