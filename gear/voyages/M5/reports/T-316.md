# T-316 — report

A project whose repository lives under the system temp directory is a fixture,
and a fixture now registers only into a store the caller names itself with
`GEAR_DB` — never into the Herdr session's own store, where it would show up in
the user's board (M4.2 #35).

## What changed

**`crates/gear-cli/src/main.rs`, `fn cmd_admin_init`**

- A new closure `refuse_a_fixture_into_this_store`, beside the T-269 one, called
  on a real init only — right after `refuse_a_foreign_session(&parsed)`, before
  `open_store()`, so nothing is opened or written:
  - `repo = canonical(&parsed.project.repo)` and
    `temp = canonical(&std::env::temp_dir())`; nothing is refused unless
    `repo` starts with `temp` (component-wise, so `/tmpfoo` is not `/tmp`);
  - when `GEAR_DB` is unset, or equals
    `default_store_in(&home, HERDR_SOCKET_PATH)` — the same test T-269 makes for
    "the caller named its own store" — it fails with
    `ErrorCode::BadFormat`:
    `project <id> lives under the temp directory (<repo>): a fixture registers
    only into a store named with GEAR_DB, never into this session's store <db>`,
    the canonical repo and the store this init would have written;
  - a `GEAR_DB` the caller named itself, and every repo outside the temp
    directory, register as today. `--check` is untouched (it writes nothing),
    and the message is the packet's text verbatim.

**`crates/gear-cli/tests/it/admin_init_contract.rs`**

- New contract test `init_refuses_a_fixture_into_the_sessions_store`, through
  the real binary and the file's `--check`/init helpers:
  - `--check` of the fixture config with no `GEAR_DB` still passes
    (`config ok: project p, 0 lanes, 0 reviewers`);
  - a real init with no `GEAR_DB` is refused with `ERROR BAD_FORMAT`,
    `lives under the temp directory`, `a fixture registers only into a store
    named with GEAR_DB`, and
    `never into this session's store <home>/.local/state/gear/gear.db`; the
    store file is not created;
  - the same in a named session (`~/.config/herdr/sessions/alpha/herdr.sock`)
    is refused naming `alpha`'s store, which is not created;
  - the same fixture with `GEAR_DB` set to a scratch file registers there
    (config v1);
  - a repository outside the temp directory (`CARGO_MANIFEST_DIR`) with no
    `GEAR_DB` registers into that session's default store, on a home of its own
    (a successful init registers its store for the session, so an earlier one
    would have made the named store the default).
- Two existing tests registered a temp-directory repo into the default store
  and would now be refused; their setup moves the repo outside the temp
  directory, everything they assert is unchanged:
  - `init_refuses_a_config_for_another_herdr_session` (T-269) — its subject is
    the session check and the default store, not the repo's location;
  - `check_reads_the_default_store_when_gear_db_is_unset` (T-256) — it
    registers `p` with no `GEAR_DB` and then `--check`s `q`; `elsewhere` stays a
    scratch dir because it is only ever `--check`ed.

## Out of scope

- Only `project.repo` is checked, as the packet says: a multi-repo project
  (`[[repos]]`) whose child repository lies under the temp directory is not
  examined, and neither is a repo under the temp directory reached through a
  symlink at the configured path — `canonical` resolves the config path, so
  that case is caught, but a child repo naming a temp path from an
  outside-temp parent is not.
- `gear admin init --check` does not warn about a fixture; the packet asks for
  the refusal on a real init only.
- The live acceptance scripts (`scripts/fixtures/make.sh` and the `gear admin
  init` it suggests) now need `GEAR_DB=<file>` to register a built fixture; no
  script in the repo calls `admin init`, so nothing was changed there.
