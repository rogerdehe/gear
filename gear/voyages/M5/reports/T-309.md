# T-309 — report

A lane parked on a provider limit **without a quota source** now wakes at the
reset its own screen states, plus a minute, instead of after a fixed
`quota_reset_h` window. The code change is in `crates/gear-engine/src/quota.rs`
only; the two tests live with the crate's other quota policy tests.

## What changed

**`crates/gear-engine/src/quota.rs`, `fn apply_quota_policy_with`, the
`None =>` arm of the policy match (wait, or the chain exhausted), for a lane:**

```rust
let hours = i64::from(config.models.quota_reset_h.max(1));
let from_screen = obs
    .screen
    .as_deref()
    .and_then(|screen| gear_usage::reset_from_text(screen, now));
let (until, reset) = match from_screen {
    Some(reset) => (reset + 60, "reset read from the screen"),
    None => (now + hours * 3600, "no reset on the screen: quota_reset_h"),
};
```

`until` keeps feeding `park(...)` and the `Wait` a `wait`-policy park writes
(T-295), and the event line is now

```
…: parked until <until> (provider limit, <policy>, reset read from the screen)
…: parked until <until> (provider limit, <policy>, no reset on the screen: quota_reset_h)
```

`<policy>` is `policy wait` / `chain exhausted` as before, so the existing
`an_exhausted_chain_parks_until_the_reset` assertions still hold.

Nothing else moved: `fn park_for_quota` (a source decided) and
`fn park_unreadable` (the source cannot be read) are untouched, as is the
reviewer arm of the `None =>` branch (a reviewer is flagged, never parked,
T-115).

## Tests

Two tests added beside `the_wait_policy_parks_even_with_a_longer_chain`, with
the same fixtures (`world(&config(chain, "wait"))`, `herdr_with_quota()`), plus
a `tick_quota_screen` helper that is `tick_quota` with `obs.screen` filled:

- `the_policy_parks_until_the_reset_the_screen_states` — a screen ending
  `Usage limit reached. Try again in 2h 13m.` parks the lane until
  `now + 7_980 + 60` with `reset read from the screen` (and the state reason and
  the exit keys agree: parked, nothing restarted).
- `the_policy_parks_for_the_configured_hours_without_a_reset` — the resetless
  `QUOTA_SCREEN` keeps `now + quota_reset_h (5) hours` with
  `no reset on the screen`.

## Out of scope

- The `no reset on the screen: quota_reset_h` text is taken literally from the
  contract (the constant's name, not the number). If the captain wants the
  hours spelled out (`…: 5`), it is a one-line change in the same format string.
- A reviewer parked path, `park_for_quota` and `park_unreadable` keep their
  fixed windows: the contract leaves them unchanged, even though their screens
  may state a reset too.
- The `Wait` a `wait`-policy park writes still stores `window: ""`; filling it
  from the screen is not this task.
