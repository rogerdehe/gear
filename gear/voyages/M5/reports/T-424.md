# T-424 — report

A Standby reviewer is no longer released while a hand-in waits for a reviewer:
`fn release_idle_standby` counts the hand-ins that wait and, while that count is
above zero, releases nothing. With none waiting the rule of design §3.6 stands,
and a Standby reviewer whose agent is gone still leaves by its own rule (T-399).

## What changed

`crates/gear-engine/src/release.rs` only (plus the one sentence of
`skills/gear/references/captain.md` that contract v2 allows):

- `fn hand_ins_waiting(store, project) -> GearResult<usize>` — the packet's
  count: a task in `Verifying` whose latest attempt is handed in (`Submitted`,
  with a candidate), no verdict for that attempt, and **no `Active` temp seat**
  with `task_id` = that task. The reservation reading is literal per the
  direction check of attempt 1: a `Standby` seat that only holds its
  `engine.review_pending` reservation is not `Active`, so the hand-in still
  counts as waiting in that interval.
- `fn release_idle_standby` — after the Standby list is built, before the
  `working_lanes` excess is worked out:

  ```rust
  // T-424: a hand-in that waits for a reviewer keeps every Standby reviewer:
  // the next review needs a seat that is already up.
  if hand_ins_waiting(store, project)? > 0 {
      return Ok(report);
  }
  ```

  Unchanged: the `review_pending` seats are still left out of the excess
  (T-391), the `state_since` tick rule, the oldest-first order, and the
  `agent-gone` release of `Standby` seats (T-399).
- `skills/gear/references/captain.md`, `# Staff` bullet: the old sentence is
  replaced by "Reviewers follow the reviews waiting, up to `[quota] temps`: while
  a hand-in waits for a reviewer no standby reviewer is released, even with every
  lane held (hold the lanes to clear a review backlog with every seat); with none
  waiting, standby reviewers beyond the working lanes are released, oldest first."

## Tests

New in `release::tests`:

- `a_standby_reviewer_is_kept_while_a_hand_in_waits` — two Standby reviewers, no
  lane with a `Started` attempt, `T-1` handed in and unjudged: two ticks, neither
  released, no pane closed, `T-1` still `Verifying`.
- `a_standby_reviewer_goes_when_no_hand_in_waits` — the same, with `T-1`'s verdict
  in: both released (`Released`, 2 panes closed).
- `a_hand_in_reserved_for_a_standby_reviewer_still_waits` — the direction check's
  case: `T-1`'s review reserved on a `Standby` seat (`engine.review_pending`),
  a jobless Standby reviewer beside it: nothing is released.
- `a_standby_reviewer_with_a_pending_review_is_not_released` (T-391) — its
  fixture now has an `Active` temp seat on `T-1`, so the hand-in does not wait and
  the sweep runs; it still tests its own point (the reserved one stays, the
  jobless one goes).

## Out of scope (noticed, not changed)

- `fn tasks_to_review` (review.rs) decides "the hand-in is served" with a wider
  set than `Active` — a `Parked`/`Held`/`NeedsCheck` seat bound to the task also
  makes it not wait there, while this task's count says it waits. The two
  definitions are now side by side; a later task could make one function of them.
