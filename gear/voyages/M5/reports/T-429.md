# T-429 — report

A review chain change reaches the warm reviewers. `fn start_reviewer` (the
`Standby` branch: the seat is warm, its agent idle in its pane) compares the
seat's `engine.model.<seat>` with the model of the review chain's chosen
entry, and the recorded start's kind with the entry's CLI. When the model
differs, or the CLI differs, the seat is released through
`crate::release::release_one` with the caller **`the review chain changed`**
and the function returns `Started::NotYet`; the next tick starts the review on
a free seat with the new model, as it does for any other job. A seat whose
model is unset, or the chain's model, is adopted as today.

## What changed

`crates/gear-engine/src/review.rs` only:

- `fn start_reviewer`, `Standby` branch — the old check
  (`engine.review_model_entry.<seat>` record vs the entry, plus
  "unset model counts as a mismatch") is replaced by the two the packet names:
  - `model_moved` — `engine.model.<seat>` is set and differs from
    `entry.model()`;
  - `cli_moved` — the entry names a CLI and the recorded start of the seat's
    generation names another kind.

  Either one releases the seat (`release_one(..., "the review chain
  changed")`) and returns `Started::NotYet`. `engine.review_model_entry.<seat>`
  is still written by a start; it is no longer what decides the reuse.
- new `fn recorded_start_kind(store, seat, generation)` — the `kind` of the
  seat's start record (`engine.review_start.<seat>.<generation>`), `None` when
  there is no record or it does not parse.

## Tests

New in `review::tests`:

- `warm_reviewer_of_a_changed_chain_is_released_and_restarted_on_the_new_model`
  — a review on `gpt-6.1-sol`, the seat then warm (`Standby`) and the
  project's `[models].review` changed to `gpt-6.1-luna`: the tick releases the
  seat (release log: `caller=the review chain changed`, no packet delivered),
  `release_finished_reviews` makes it `Released`, and the next tick starts it
  on `gpt-6.1-luna`.
- `warm_reviewer_of_an_unchanged_chain_is_adopted` — the same warm seat with
  the chain unchanged: no release line at all, the seat keeps the job
  (`engine.review_pending` = `T-2`, state `Standby`, no `Releasing`), still on
  `gpt-6.1-sol`.

## Out of scope (noticed, not changed)

- The `Standby` branch releases the pane's agent without asking whether that
  agent is *this seat's* recorded start (it only requires `Idle`/`Done`); the
  new check follows the existing one in that. A `recorded_start` gate there
  would be a behaviour of its own (`recorded_start` needs the pane and the
  generation), not this packet's.
- `entry.args()` is no longer compared on a warm reuse: a chain whose model and
  CLI stay the same but whose args move now adopts the warm seat. The packet
  names the model and the CLI only.
