# T-267 — report

A reviewer's packet is confirmed by the reviewer's own first `gear`, so a
lost packet shows at once and the home count of unconfirmed deliveries is
true. The change is confined to `crates/gear-engine/src/ops.rs` and one
string in `crates/gear-engine/src/review.rs`.

## What it does

1. **A review delivery is proven by a view or by the verdict, whichever came
   first** (`ops.rs`, `confirm_pending_with`, `OpKind::Deliver if
   is_reviewer(…)`):
   - `review_delivery_evidence` returns the earlier of
     `tx.views_since(&op.seat, op.generation, op.created)`'s first view and
     `review_verdict`'s time, and says which one it is.
   - Stored evidence is `view <seat>/<generation> @ <ts>` when the view came
     first, and `verdict <task> attempt <n> @ <ts>` as before when the
     verdict did.
   - The op still spends no check budget and flags nothing while it waits
     (R-46); with no view and no verdict it stays Submitted.

2. **The newer delivery wins** (`superseded`, new): while a newer Submitted
   Deliver op exists for the same seat, task and attempt, the older one is
   not confirmed at all — it is the older packet, not the one the reviewer
   got. This is required for the acceptance case: the tick walks Submitted
   ops oldest first (`ops_in_state ORDER BY created, id`), and any view that
   confirms the second delivery also satisfies the first one's rule, so
   "void older Submitted" alone would leave both Confirmed.

3. **Confirming a review delivery voids the older ones**
   (`supersede_older_review_deliveries`, new): every older Submitted
   Deliver op of the same seat for the same task and attempt is set Void with
   the result `superseded by <op id>`, so it no longer holds the seat's
   delivery slot and is never sent again. The write is raw (like
   `release.rs`'s void of a Submitted start op): the state machine has no
   Submitted → Void transition.

4. **The direction packet asks for `gear` first** (`review.rs`, `job_packet`):
   the text starts with `Run \`gear\` first (it records that you got this). `,
   as the review packet does. `nudge_stopped_reviewers` is untouched.

## Tests

`crates/gear-engine/src/ops.rs`, `mod tests`:

- `a_review_delivery_is_confirmed_by_the_reviewers_first_view` — a view of
  the seat and generation after the op confirms it before any verdict, with
  the result `view p:r-1/1 @ <ts>`.
- `the_first_evidence_of_a_review_delivery_is_the_one_stored` — a verdict at
  T0+5 and a view at T0+10 keep the verdict's evidence.
- `a_newer_review_delivery_supersedes_the_older_one` — two Submitted
  deliveries, one view: the second is Confirmed, the first is Void with
  `superseded by O-2`.
- `a_review_delivery_with_no_view_and_no_verdict_stays_submitted` — no
  evidence, no budget, nothing flagged, still Submitted.
- `a_lane_delivery_still_needs_a_view_of_its_task_and_attempt` — the lane
  path is unchanged: a view of the seat without the task proves nothing.

`crates/gear-engine/src/review.rs`,
`direction_checks_follow_pushes_and_report_results` — the direction packet
`starts_with("Run \`gear\` first")`.

`make check CRATE=gear-engine`: 640 tests run, 640 passed, 0 skipped (with origin/dev merged in).

## Out of scope (noticed, not changed)

- `OpState::can_transition` has no Submitted → Void edge, yet both
  `release.rs` and now this path write it raw for an op that did reach the
  pane. Whether the state machine should carry that edge is a design
  question for the captain, not decided here (asked as a question on this
  task, answered by the default taken).
- `superseded` and `supersede_older_review_deliveries` each scan the
  project's Submitted ops (`ops_in_state`) once per candidate op; at the
  scale of a tick that is a handful of rows, so no index or single scan was
  added.
- The home count of unconfirmed deliveries itself was not re-checked against
  a live project; it reads the same Submitted ops this task now settles.
