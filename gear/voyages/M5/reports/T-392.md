# T-392 — report

A departed voyage's staffing (`quota`, `lanes`, `temps`, `models`) can no
longer be changed by a mid-voyage re-init without the user's own words (user,
2026-10-29: "这种舰长他妈的中途还改自己的人员配置…"; another project's captain
lowered `[quota] temps` from 6 to 3 by `gear admin init` without asking). The
staffing is agreed at kickoff, like the goal (T-331).

## Rework (attempt 2)

Review F1, review F2 and the direction check, one commit (`22209a00`):

- **F1 — blank words are no words.** `re_register` normalises the caller's
  words once, `user.map(str::trim).filter(|words| !words.is_empty())`, before
  the guard and before the decision; `cmd_admin_init` does the same, so
  `--check --user ""` and `--user "   "` report the refusal instead of
  skipping it. Regressions: `blank_user_words_are_no_words` (three blank
  values: `StaffLocked` naming `quota.temps: 6 → 3`, version and config text
  unchanged, no staff decision) and, in `check_reports_a_staffing_change_of_
  a_departed_voyage`, `--check --user ""` / `"   "` still exit 1 with
  `STAFF_LOCKED`, while `--check --user "<words>"` exits 0 as `config ok`.
- **F2 — a model entry is rendered whole.** `chain_text` now maps each entry
  through a new `entry_text`: `describe()` (model and CLI) plus
  ` args [<args joined by space>]` and ` context_window_k <k>` when the entry
  sets them. A reasoning-effort change therefore reads
  `model_reasoning_effort=medium → high` in the refusal and in the starred
  decision, and the context window is kept when present. Regression:
  `a_changed_model_argument_is_named_in_the_refusal_and_the_decision` (lane
  models as entries with `args` and `context_window_k`; 200 → 300 as well as
  medium → high; nothing written on the refusal, one decision after the words).
- **Direction check — the sections decide, the text explains.** New
  `pub fn staffing_changed(old, new) -> bool` compares `quota`, `lanes`,
  `temps` and `models` with `PartialEq`; `re_register` and the CLI's
  `staffing_refusal_of` gate on it and call `staffing_changes` only to explain
  the difference. `staffing_changes` gained the one case where the sections
  differ but no field does — the same `[[lanes]]` in another order — which it
  names as `lanes: heat, keel → keel, heat` (the order is what the board and
  the lane list show). Regression:
  `a_reordered_lanes_section_is_a_staffing_change` (refused without words with
  the order named and nothing written; applied with words, one decision
  naming the order).

## What changed

**`crates/gear-model/src/error.rs`**: `ErrorCode::StaffLocked`, spelled
`STAFF_LOCKED`, next to the other codes (exit code 1, the default).

**`crates/gear-app/src/admin.rs`**:

- `init`, `init_with_home` and `init_checked` take the user's words as
  `user: Option<&str>` (before `now`) and pass them to `re_register`; a first
  registration ignores them.
- `re_register` compares the stored `project.config_toml` (via `config::parse`;
  a stored config that does not parse says nothing about the old staff) with
  the new config on the four sections, before any write:
  - a departed voyage is under way (`staffing_voyage`: a voyage with a
    departure — `plan::current_voyage` — and a task that is not terminal —
    `tx.tasks_of_project` + `TaskState::is_terminal`) and `staffing_changed`
    says a section differs and no words are given → `ErrorCode::StaffLocked`
    with `staffing_refusal`'s text, and nothing is written;
  - with the words the change applies as today, and the voyage gets one
    starred `staff` decision through `tx.insert_decision_if_new` (key built
    like `plan.rs` `record_gear_decision`; `what` = the changed fields as in
    the refusal, `why` = `user: «<words>»`, `star: true`, `source: "gear"`).
- New public helpers, used by `re_register` and by the CLI's `--check`:
  - `staffing_voyage(tx, project)` — the milestone of the voyage whose
    staffing is locked, `None` when no voyage is under way;
  - `staffing_changes(old, new)` — the changed fields, each as
    `section.key: old → new`, `; `-joined: `quota.lanes`, `quota.temps`,
    `quota.includes_captain`, `quota.sources`, `lanes.<name>.<field>` (and a
    lane only one config names as `lanes.<name>`), `temps.kind`,
    `temps.profile` (and `temps` itself for presence), `models.lanes|review|`
    `captain`, `models.on_quota.lanes|review`, `models.on_wait`,
    `models.quota_reset_h`, `models.switch.<id>`;
  - `staffing_refusal(voyage, changes)` — "the staffing of voyage <M> was
    agreed at its kickoff: <fields> — ask the user first, then run init again
    with --user \"<the user's words>\"".

All four section types already derived `PartialEq` (`Quota`, `LaneSection`,
`TempsSection`, `Models` and their parts), so `crates/gear-app/src/config.rs`
needed no change.

**`crates/gear-cli/src/main.rs`**: `AdminOp::Init` gains
`#[arg(long)] user: Option<String>`, passed to `cmd_admin_init` and through
`init_checked`. `--check` (without words) reports the same refusal text as a
problem through the new read-only `staffing_refusal_of` (the same store path
rule as `other_projects`/`retired_lanes_of`, `Store::open_read_only`), and
writes nothing.

**`skills/gear/references/captain.md`**: one sentence in the paragraph on
re-running init mid-voyage: "Staffing (`[quota]`, `[[lanes]]`, `[temps]`,
`[models]`) is agreed at kickoff; mid-voyage init refuses a change to it until
you pass the user's own words with `--user`."

The existing call sites of `init_with_home`/`init_checked` in the test suites
of gear-app and gear-engine pass `None` for the words (mechanical change; no
assertion touched).
