## Set aside

- A pass verdict turning a `Verifying` task into `Done` is evaluated as live by the pre-settle check, so a plan that finishes a Verifying task that has an (already stale) cancelled dep is refused. Such a task cannot normally reach Verifying under the engine's dispatch, so this is a conservative false refusal, not an error in normal use.
- A `Failed` dependency is the same dead end as a cancelled one, but the contract names `Cancelled` only; changing the engine or covering `Failed` is a separate task.
- A project that already carries, from before this fix, a live task depending on a cancelled task will see *any* subsequent apply refused one pair per line until the captain drops or replaces that dependency in a plan. That is the intended "drop or replace" instruction from the contract, not a defect.
- Re-apply and replay: the refusal runs before writes and returns `Err`, so nothing is recorded and a later corrected plan applies; a re-applied cancel that already dropped the dep applies cleanly (covered by the pre-existing no-op test).
