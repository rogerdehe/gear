## Findings

F1 [P1, blocking] An explicit CLI change is silently ignored when the old model/CLI remains a fallback — `crates/gear-engine/src/restart.rs:1079`. Reproduce with an Active pi lane running model M and an already-seeded restart_config; re-init to head `{model=M, cli=codex}` followed by fallback `{model=M, cli=pi}`, with unchanged head args. No quota event or other fault is needed. `on_later_entry` becomes true, so the new `!on_later_entry` condition suppresses kind_changed; model_changed is false because the model/args did not change, and stale is suppressed too. Reconciliation then records the new fingerprint without restarting: the requested CLI change is lost permanently. The isolated test below failed on the candidate's unchanged production implementation because pending() remained None. This breaks the promised model-or-CLI change workflow in normal use and therefore the DELIVERABLE bar. Smallest fix: in reconcile_config, restore `!quota_fallback` in the kind_changed expression (one line), so an explicit changed fingerprint can still change CLI; keep the later-entry exclusion for the new stale-drift check. Add the regression below to config_change_tests (about 20 lines), and retain the existing fallback test.
