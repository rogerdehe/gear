# T-633 — the engine branch item stays short

## What changed

`crates/gear-engine/src/merge.rs`:

- A done branch's line now names only its commit count and newest commit:
  `<name> (<task>, done, <n> commit(s) not on <integration>, newest: <first
  line of git log --oneline>)`. An unreadable log says `newest: none readable`.
- Each of the four sections (crowded, old, left, deleted) lists at most 10
  lines; when there are more, the last line is
  `- … and <k> more: `git branch -r --list '<remote>/<prefix>*'``, where the
  prefix is the task-branch template up to its first `{`, or `git branch -r`
  when the template starts with `{`. The section header keeps the full count.
- New helpers `branch_list_command` and `push_section`; nothing else in the
  item changed.

## Tests

`make check CRATE=gear-engine TESTS='test(merge::)'` passes (130 tests).

New tests in `merge.rs mod tests`:
- `a_sweep_over_many_left_branches_stays_short`: 25 done branches with 30
  commits each; the item lists 10 lines, each naming `30 commit(s) not on dev,
  newest: …`, then `- … and 15 more: `git branch -r --list 'origin/heat/t*'``;
  the header keeps `25 branch(es)` and the item is under 4000 chars.
- `the_branch_list_command_names_the_task_prefix`: the default `{lane}/t{n}`
  gives `git branch -r`, `heat/t{n}` gives `origin/heat/t*`.

## Out of scope

- The command lists branches by prefix; a template whose first placeholder is
  not at the start (e.g. `heat/t{n}`) lists `heat/t*`, which also matches
  `heat/team/...`-style names if a project uses them.
