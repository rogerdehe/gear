# T-641 — report

A review message carries the verdict and where the review is, not the whole
review.

## What changed

- `crates/gear-app/src/mail.rs`: the body of a `MsgKind::Review` is now
  `review::headline`, then one `blocking: <title>` line per id in
  `review.blocking` (or `blocking: none`), then `full review: <path>` when the
  reviewer handed in a file, then `findings: `gear --show <task>``. The
  blocking title is the first findings line that starts with the id followed
  by a space or `[` (after an optional `- `), cut to 160 characters; an id
  with no line of its own is named by itself.
- `crates/gear-app/src/review.rs`: `findings_path(arg)` names the trimmed
  argument when `findings_text` reads a file, so the message can point at it.
- The `review_verdicts` row keeps the whole findings, unchanged: the rework
  lane reads them there.

## Tests

- `review_contract::a_fail_review_names_the_blocking_titles_and_the_full_review_path`:
  a fail with `--blocking F1,F3` and a findings file stores a message under
  1000 chars naming both titles and the path, not the other findings; the
  verdict row holds the whole findings.
- `review_contract::a_pass_review_without_blocking_says_blocking_none`: a pass
  with no blocking says `blocking: none`, names no path and points at
  `gear --show T-1`.
- The existing pass test now checks the new body.

`make check CRATE=gear-app TESTS='test(review)'` — 77 tests, 77 passed.

## Out of scope

- The CLI and the engine are unchanged; only the stored message body moved.
