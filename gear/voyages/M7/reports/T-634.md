# T-634 — the idle-voyage item rings once per open land order

## What changed

`crates/gear-engine/src/quiet.rs` `captain_sailing`:

- When every task of the voyage is done (`left == 0`) and its land order is
  open, the item is now rung once per open land order: the land order's
  message id is read from `station:<project>:<milestone>:land`, and the meta
  `sailing-land:<project>:<milestone>` remembers the id it was rung for. While
  that id stays the same, nothing rings (no `CAPTAIN_AGAIN` repeat, no repeat
  after the item is resolved).
- The item's body is the one the packet names: `Voyage <m>: every task is done
  and its land order <id> is open. Land it (`gear` shows the order); if the
  land is refused for a decision only the user can make, tell the user and
  wait: this item is not repeated while that order stays open.`
- A new land order id rings once more.
- A voyage with tasks left keeps today's text and repeats after
  `CAPTAIN_AGAIN`.

## Tests

`make check CRATE=gear-engine TESTS='test(quiet::)'` passes (21 tests).

New tests in `quiet.rs mod tests`:
- `an_idle_voyage_with_an_open_land_order_rings_once`: one item for the open
  order, none after 30 more minutes idle, and one more for a new order id.
- `a_voyage_with_tasks_left_repeats_after_captain_again`: the tasks-left text
  repeats after `CAPTAIN_AGAIN`.
- The existing `an_idle_captain_of_a_sailing_voyage_is_told_to_go_on` was
  updated for the new land-order body.

## Out of scope

- The land-order item and the tasks-left item share the `sailing:<milestone>`
  thread; a new land order id inserts a second item while an older one may
  still be open, as the packet asks ("rings once more").
