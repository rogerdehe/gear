# T-632 — the merge workers can drain

## What changed

- `crates/gear-engine/src/merge.rs`
  - `MergeWorkers` carries a shared `draining: Arc<AtomicBool>` (cloned with the
    struct like `workers`).
  - `pub fn drain(&self)` sets it; `pub fn draining(&self)` reads it;
    `pub fn idle(&self)` is true when no worker is in `workers` and no bisect
    is still running (every bisect worker has reported).
  - While draining, nothing starts a worker:
    - the merge loop returns before the batch/train/single paths and before any
      op is moved to Executing (the op stays Intended/Unknown);
    - `launch_train` and `launch_batch` return at once (defensive: the loop
      never reaches them while draining);
    - `start_bisects` returns at once, so a pending bisect request stays
      pending for the next engine.
  - `collect_finished` is unchanged: a worker started before `drain()` still
    finishes and is collected.
- `crates/gear-engine/src/lib.rs`: `pub fn drain(cfg: &EngineCfg)` and
  `pub fn merges_idle(cfg: &EngineCfg) -> bool`.

## Tests

`make check CRATE=gear-engine TESTS='test(merge::)'` passes (130 tests).

New tests in `merge.rs mod tests`:
- `draining_starts_no_worker_and_leaves_the_op_intended`: a ready merge with
  `drain()` set starts nothing, the op stays Intended, `idle()` is true.
- `a_worker_started_before_drain_finishes_and_is_collected`: a worker started
  before `drain()` finishes, is collected, the op is Confirmed, and `idle()` is
  true afterwards.

## Out of scope

- Nothing in the engine calls `drain`/`merges_idle` yet; the restart work that
  replaces the binary (voyage item 2) will use them.
