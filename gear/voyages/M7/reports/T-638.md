# T-638 — [F-4 5/7] Labeled issues become captain items

## What changed

`crates/gear-forge/src/sync.rs`:

- `voyage_of` now answers the departed voyage of a GitHub project (milestone,
  repo, label) regardless of whether the label is created; the label step of
  T-637 uses it and checks `forge.label.<project>.<milestone>` itself.
- `intake` (new) runs once the voyage's label is `created`, at most every
  `INTAKE_EVERY_S = 120` s per project (meta `forge.intake_at.<project>`). It
  calls `issues(Filter { labels: vec![label], limit: 500 })`:
  - an error changes nothing (no row, no item) and is never read as an empty
    list;
  - a list of exactly 500 is treated as partial: nothing is marked unlabeled
    this poll.
- For each listed issue, against the voyage's `voyage_issues` rows:
  - unknown number: `upsert_voyage_issue` (labeled 1, `body_hash` = a hex hash
    of title + body, first/last seen) and one urgent captain item on thread
    `intake:<milestone>:#<n>`: `Issue #<n> "<title>" was labeled <label>: plan
    it as task(s) with \`issue: #<n>\` and their contracts and deps, or resolve
    this item to defer it. It never moves the eta or the bar.`
  - known with a different hash: update the row and one item `Issue #<n>
    changed on GitHub: check its tasks' contracts.`
  - known with labeled 0: labeled 1 and one item `Issue #<n> carries <label>
    again.`
- For each row with labeled 1 that a complete list no longer holds: labeled 0
  and one item `Issue #<n> no longer carries <label> (closed or unlabeled):
  its tasks keep running; cancel them in the plan if the user wants.`
- Items are written with the store's normal `insert_message` (sender `engine`,
  recipient `<project>:captain`, kind System, urgent, Open), so the doorbell
  wakes the captain once.

## Tests

`make check CRATE=gear-forge` passes (57 tests).

New `sync.rs mod tests` with a recording forge:
- `a_new_labeled_issue_makes_one_item`: one item with the exact body and the
  filter `labels: [p/M1], limit: 500`; the next poll makes none.
- `a_changed_body_makes_one_changed_item`.
- `a_vanished_issue_makes_one_item_and_sets_labeled_zero`.
- `a_forge_error_makes_no_item_and_changes_no_row`, then a later poll works.
- `two_polls_within_120_s_list_once`.

## Out of scope

- The 500-issue partial page is not exercised by a test (a 500-item fixture
  would be noise); the branch is a one-line guard.
- A row recorded under another milestone with the same number is moved to this
  voyage's milestone by the upsert, as the store's key is (project, number).
