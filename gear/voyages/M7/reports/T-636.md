# T-636 — [F-4 2/7] The forge can create a label

## What changed

- `crates/gear-forge/src/lib.rs`: the `Forge` trait gains
  `fn create_label(&self, repo: &str, name: &str, description: &str) -> ForgeResult<()>`.
- `crates/gear-forge/src/github.rs`: `GitHub::create_label` runs
  `label create <name> --repo <repo> --description <description> --color 0E8A16 --force`
  through `run`, so it is bounded, silent and typed like every other call.
  `--force` updates a label that exists, so the call is idempotent.
- `crates/gear-forge/src/local.rs`: `Local::create_label` is `Ok(())`.
- `crates/gear-forge/tests/it/sync_contract.rs`: the fake `Forge` records the
  call (`label <repo> <name> | <description>`) and honours `reachable`.

## Tests

`make check CRATE=gear-forge` passes (47 tests).

- `github_contract::create_label_creates_or_updates_a_label`: the `GEAR_GH`
  stub receives exactly the arguments above.
- `github_contract::a_failing_label_create_is_a_typed_error`: a non-zero exit
  is `Error::Failed`, carrying the stub's stderr and the command.
- `local_contract`: `Local::create_label` succeeds.

## Out of scope

  a later task of F-4.
