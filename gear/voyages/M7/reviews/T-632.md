## Set aside
- `idle()` stays false while a finished-but-not-yet-collected worker is still in `workers`: the pointer is only removed by the next tick's `collect_finished`. This is exactly the contract's literal "no worker is in `workers`", and the accept test pins it (false after `drain()` with a running worker, true once the tick collects it), so a restarter polling `merges_idle` simply waits one tick for collection.
- The scoped `std::thread::scope` gate threads (`merge.rs` ~4641) are not merge *workers* — they run and join inside one already-started worker's gate stage — so they are not counted by `workers` and correctly do not get a draining check.
