# M4.2 lessons

What M4.2 taught, recorded as it happened. A lesson holds for this voyage; only what the release review distils into the shipped skill (`skills/gear/`) carries over. Numbers are the ones lessons had in the old shared file, so earlier references still find them.

41 (M4.2 additions to M4.1's lesson 41: a contract names only what exists). When a contract lists the tests to change, grep for the bare string the code builds, not only its labelled line (M4.2 T-250: three named, five asserted it); a rework note after a failed gate states the symptom only after reading the failing assert and the fake it uses (M4.2 T-241: the note guessed "prompt count 0", the fake's one refusal hit the esc instead). A contract that removes a default counts who relied on it first and sizes the estimate on that count (M4.2 T-255: "fixtures that relied on the default get a gate" were 30 fixtures across three crates, found by four full runs).

42. **The full build and suite run once, in the merge gate.** M4.2's first contracts asked every lane and every reviewer to run `scripts/test.sh` (and lanes and reviewers ran `cargo build --workspace --all-targets`) on top of the gate, so three full builds plus suites ran at once and starved another project's fleet on the same machine (load 38, its merges and deliveries stalled). An accept line runs the touched crate's tests only; the gate is the one whole-workspace check.

43. **Balance the lanes with whole waves, not one task per run-dry.** In M4.2 the lanes were split by files (hull: the engine; mast: everything else), most collected bugs were engine bugs, and the captain fed mast one task each time it rang "runs dry", so the queues read hull 124 min against mast 60 min at the 120-minute station and the user asked whether it was a preference (2026-10-28). Plan each wave for every lane at once, sized so their queues end together; when one lane's area holds most of the work, move whole tasks with their files as allowed edits, or split the area, at the wave, then trim at stations. Balance on what each lane can start, not on minutes alone: a lane whose next task waits for another lane's merge needs a task it can start meanwhile (M4.2 17:25: moving T-254 off hull would have left hull idle behind T-252).

44. **A changed acceptance goes into the contract, not only into a reply.** In M4.2 T-243 the lane showed that the acceptance could not hold; the captain answered "use a refused profile block instead" as a reply (M-4127) and left the contract at v1, so the reviewer judged against v1, found the candidate "contradicting" it and had to stop and ask (M-4149). When an answer changes what the work must do or how it is accepted, edit the contract in the plan (a new version) in the same minute; a reply only points to it.
