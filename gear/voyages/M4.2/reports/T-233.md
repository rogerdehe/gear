# T-233 — "deliveries not confirmed" counts only live deliveries

Scope: T-233 (contract v2) — the home page's "deliveries not confirmed: N"
reads the board's `ProjectBoard::unconfirmed_deliveries`. It counted every
unsettled `Deliver` op of the project, including the ops of seats that are
retired or have been restarted since, so the page showed 3–7 with no lane
working and a trial captain read it as lost messages.

Branch: mast/t233 · contract v2 (contract v1 at the start).

## What changed

`crates/gear-board/src/lib.rs`, the one loop only:

- an unsettled `Deliver` op (`Intended`, `Executing`, `Submitted`, `Unknown`)
  now counts only when `tx.get_seat(&op.seat)` is a seat whose state is
  `Active`, `Standby` or `Starting` **and** whose `generation` equals
  `op.generation`;
- anything else (a retired seat, an older generation of a live seat, a seat the
  store no longer has) is history and is not counted.

Nothing else changed: the four-state scan, the field, the rendering in
`crates/gear-app/src/home.rs` and the JSON are as they were.

## Tests (`crates/gear-board/tests/it/deliveries_contract.rs`, new; the
existing fixtures `testing::seed_project` / `seed_active_seat` / `insert_op`)

- `only_a_live_delivery_is_unconfirmed` — a `Deliver` op in `Unknown` for a
  retired seat (`set_seat_state` → `Retired`) and one in `Unknown` for
  generation 1 of a seat now at generation 2 (`set_seat_generation` → 2) are
  not counted; one in `Unknown` for the live generation 2 is. Count = 1.
- `a_settled_or_non_deliver_op_does_not_count` — a `Confirmed` delivery and a
  `Doorbell` op in `Unknown` do not count. Count = 0.

## Out of scope

- `crates/gear-engine/src/quota.rs`'s `retire_unconfirmed_deliveries` and the
  engine's own op bookkeeping are untouched.
- The `Deliver` ops of a live seat whose state is `Parked`, `Held`,
  `NeedsCheck` or `Missing` are not counted either; the packet names only
  `Active`, `Standby` and `Starting`, and I did not widen it.
