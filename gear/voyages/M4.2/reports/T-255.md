# T-255 — no Rust gate by default: a project names its own gate

Scope: T-255 (contract v1) — `impl Default for Conventions` shipped
`gate = "cargo build --workspace --all-targets && cargo test --workspace"`, so a
Go or Python project that left the gate out got a merge gate that cannot run in
its repo. The default is now empty, `validate` asks for the command, and the
skill says the gate has no default.

Branch: mast/t255 · contract v1 · candidate a9416a4f (origin/dev cf1bcf65
merged in).

## What changed

- `crates/gear-app/src/config.rs`
  - `impl Default for Conventions`: `gate: String::new()` (no default). The
    struct's doc comment says so; the field's comment says why.
  - `validate` pushes `issue("conventions.gate", GATE_MISSING)` — "name the
    command the merge gate runs in the integration worktree; it must exit
    non-zero on any failure (e.g. `make gate`, `go test ./...`)" — when
    `conventions.gate` is empty and the project would run a merge with nothing:
    a `[[repos]]` entry without its own gate, or the root repo when it has work
    of its own. The root counts only when it is the whole project (no
    `[[repos]]`) or a lane works in it (no `repo`, or a `repo` that names
    nothing) — the captain's call on M-4220. With every repo naming a gate and
    no work in the root, no `[conventions] gate` is needed (the acceptance's
    third case).
  - The old "empty or TODO" finding is split: a `TODO` in `conventions.gate`
    keeps its message, the empty case carries the new one. The
    `gate_pipes_without_pipefail` check is unchanged, and the doc list of
    findings names the new rule.
- `crates/gear-app/src/kickoff.rs` — the skeleton's `[conventions]` writes
  `gate = ""` with the comment "fill in: the command the merge runs in the
  integration worktree; it must exit non-zero on any failure (e.g. `make gate`,
  `go test ./...`)". The skeleton still parses (`kickoff_contract` asserts it).
- `skills/gear/references/conventions.md` — §8: the gate line is marked "no
  default" and a paragraph says a project that names none is refused at
  `gear admin init` until it does; §9: a `[[repos]] gate` is optional "else
  `[conventions].gate`, which then must be named". §7's parenthetical that
  called the task repo's gate `[conventions].gate` now says
  "`[[repos]].gate`, falling back to `[conventions].gate`" — that is the T-55
  review's logged finding F1, one line, in the same file and about the same
  gate; logged here because the packet named only the "no default" sentence.
- `skills/gear/references/captain.md` — the config example said "(default:
  cargo)"; it now says "(no default: name it)". Same defect, the captain's own
  example.
- Fixtures that built a config without a gate now name one, all with
  `[conventions] gate = "make test"` (T-255's own comment where the fixture is
  new):
  - `crates/gear-app/tests/it/config_contract.rs` — `MINIMAL` and `MULTI` carry
    a `[conventions]` block; a new `REPOS_EACH_GATED` fixture, a `PRICING_LANE`
    const and a `GATE_LINE` const keep the fixtures composable; the
    `[conventions]`-appending tests (the T-252 branch-template ones merged in
    from dev, `partial_sections_keep_other_defaults`, the repo-conventions
    test) join that block by replacing `GATE_LINE` instead of opening a second
    `[conventions]` table.
  - `crates/gear-app/tests/it/{admin_init,config_change,decision,github,profiles,standard,temps_quota}_contract.rs`.
  - `crates/gear-cli/tests/it/admin_init_contract.rs` (five inline configs).
  - `crates/gear-engine/tests/it/{onboard_run,config_profile_onboard}_contract.rs`.

New tests in `config_contract`:

- `a_project_without_a_gate_is_told_to_name_one` — no gate and no repos → the
  `conventions.gate` finding with the new message; a repo without its own gate
  and an empty conventions gate → the same finding.
- `conventions_gate_or_every_repo_gate_satisfies_the_rule` — a `[conventions]
  gate` alone is enough; every repo with its own gate and no lane in the root
  is enough; the same config with a lane in the root is not (M-4220).
- `minimal_config_parses_with_defaults_and_is_valid` also asserts
  `Conventions::default().gate == ""`.
