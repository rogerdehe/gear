# T-232 — No run-dry or IDLE item while no lane has work left to start (contract v1)

Scope: `crates/gear-engine/src/feed.rs`, `crates/gear-engine/tests/it/feed_contract.rs`,
`crates/gear-engine/tests/it/slice2_dispatch.rs` (one assertion, see "Fixtures
that changed") and this report.

Candidate: `8984960d` on `hull/t232`; merged with `origin/dev` (`93678639`) as
`605b5541`.

## The bug

`fn feed` warned per lane without ever asking whether the project had work left
at all: with every lane dry, a project with nothing to start rang "lane X is
IDLE", "lane X runs dry in ~N min" and "lane X has nothing to start after T-n"
once per lane, every tick an item was missing. M4.1: a dozen such items.

## The fix

`crates/gear-engine/src/feed.rs`:

- `fn startable_tasks(tx, project)` — for every seat with role Lane and state
  Active or Standby: `dispatch::ready_tasks_of(tx, &seat)`, counting a task only
  when none of its attempts `occupies_seat()` — the same rule the per-lane loop
  uses for `ready`.
- At the top of `fn feed`, right after the captain lookup: count is 0 →
  `fn close_all_lanes` closes every lane seat's item with
  `"no lane has work left to start"` (a `FeedChange { action: "closed" }` per
  item it really closed), sets `feed-severity:<seat id>` to `"0"`, and returns —
  no per-lane loop, no imbalance item. Count above 0: everything as before.

## The tests

`crates/gear-engine/tests/it/feed_contract.rs`:

- `two_lane_world(ready)` — the fixture the packet asks for: `heat` works on its
  last task (Running + Started attempt), `deck` has nothing; `ready` adds one
  startable task to `heat`.
- `no_item_is_opened_and_the_idle_item_closes_when_no_lane_has_work_left_to_start`
  — no ready task anywhere, an IDLE item open on `deck`: the tick opens no item
  for either lane, closes the open one with the plain fact, leaves no balance
  item, sets both `feed-severity` metas to `"0"`, and the next tick is silent.
- `one_startable_task_keeps_the_lanes_talking` — the same fixture plus one ready
  task on the working lane: today's items unchanged (`lane heat has 1 ready task
  left`, `lane deck is IDLE`), two changes.

Fixtures that changed (same behaviour asserted, the project now has work to
start, otherwise the new rule is what is observed): `startable_elsewhere(w)`
adds a second lane `deck` with two ready tasks and no estimates — far from dry,
so its own thread stays quiet — and is used by `a_lane_with_nothing_at_all_is_idle`,
`measured_early_warning_stays_quiet_after_acknowledgment_until_worse`,
`tail_plan_closes_existing_idle_alert_and_prevents_its_doorbell`,
`measured_horizon_counts_the_current_task_before_the_ready_queue`,
`a_lane_one_task_from_dry_warns_once` and
`a_lane_that_hands_its_last_task_in_says_it_is_idle`.

`crates/gear-engine/tests/it/slice2_dispatch.rs`, step 6 of `full_work_loop`:
the fixture has one task and that task is in review, so after T-232 the project
has nothing left to start and the feed rings nobody. The step now asserts that
(the captain is not prompted) and that the result is still the captain's
(`messages_from_since` holds the `Result` for `T-1`) instead of asserting the
doorbell. The old assertion passed on the feed's IDLE item, not on the result:
a `Result` is stored `Info` and never doorbells the captain.

## Out of scope

- A lane whose only remaining ready task is already taken by a seat-occupying
  attempt (a `Started` attempt on a still-`Ready` task, what
  `measured_horizon_counts_the_current_task_before_the_ready_queue` sets up) now
  also counts as "nothing to start": its open item closes. That follows the rule
  the packet states; the test was adapted with `startable_elsewhere` and its
  horizon assertions are unchanged.
- `slice2_dispatch::full_work_loop` claims "captain rung for the result", but a
  `Result` is `MsgState::Info` and reaches the captain through the inbox/home
  page only, never by doorbell. Whether a hand-in should ring the captain is a
  product question, not this task's.
- The 159 s suite time is machine load (other lanes testing side by side), not
  this change: it adds two small in-memory tests.
