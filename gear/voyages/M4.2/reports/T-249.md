# T-249 — `gear board --project <id>` shows that project

Branch: `mast/t249`, started from `origin/dev`.

## What changed

1. `crates/gear-cli/src/main.rs`, `enum Cmd::Board`: a new
   `#[arg(long, value_name = "ID")] project: Option<String>`, documented as
   "the project to show; without it the caller's project, and with no caller
   every project in the store".
2. `crates/gear-cli/src/main.rs`, `fn cmd_board(deps, project, json)`: takes the
   flag and sets `gear_board::Options.project` from it, falling back to the
   caller's `env.ctx` project only when the flag is absent — so in a pane bound
   to no seat (the user's own board tab) `--project` is what keeps a fixture
   project off the screen. Before the board starts, an id that `tx.get_project`
   does not find is refused:
   `NO_TARGET no project <id> in this store; registered: <tx.project_ids()>`
   (ids ascending, as the store returns them).

## Tests (`crates/gear-cli/tests/it/board_project_contract.rs`, real binary)

A store with projects `a` and `b`; every case runs `CARGO_BIN_EXE_gear board`
as a child process with `GEAR_DB` pointed at the scratch store and no Herdr.

- `the_flag_shows_only_the_project_it_names`: `board --project b --json` lists
  `["b"]`.
- `the_flag_wins_over_the_callers_own_project`: with `GEAR_CTX=a:captain:1`,
  `board --project b --json` still lists `["b"]`.
- `an_unknown_project_is_refused_and_the_registered_ones_are_named`:
  `--project zz` exits non-zero, stderr names the typo and
  `registered: a, b`.
- `without_the_flag_a_caller_with_no_seat_sees_every_project`: plain
  `board --json` still lists `["a", "b"]` — today's behaviour unchanged.

## Out of scope (noticed, not changed)

- `gear_board::project_with_agents` already refuses an unregistered id
  (`lib.rs:400`, `project zz is not registered`), so the CLI check is about the
  message — it names every registered project, which the library error does
  not — and about failing before the terminal is taken over in the interactive
  view. The two errors cannot both be reached from the CLI: the flag is checked
  first.
- No test covers `--project` together with `--deps`; the flag sets
  `Options::project` independently of `view`, and the deps tab builds from the
  same option.
