# T-253 — The engine names branches from the project's templates

Attempt 1, contract v5 — reworked on attempt 2 after the review's F1.

Branch: `hull/t253`; the candidate named in the hand-in includes this report.
`origin/dev` is merged into the branch before the hand-in (624 engine tests
green on the merged tree).

## Rework (attempt 2, review F1)

`merge::is_task_branch` compared **segments**: it took the last segment of the
task's expanded branch and the last segment of a candidate branch. That is only
sound when the task's number is the final segment. With
`task_branch = "tasks/{n}/work"` it classified `tasks/2/work` as a branch of
T-1 and the cleanup after T-1's merge deleted another task's branch (P1, STABLE
bar: branches sharing a tip are ordinary Git use).

The fix compares the **whole** expanded branch and its `-` suffix variants:
`branch == task_branch || branch.starts_with(format!("{task_branch}-"))`
(`crates/gear-engine/src/merge.rs`, `fn is_task_branch`). Anything else is
retained, which is the conservative side the review asked for. The doc comment
says why (the template may put the number anywhere).

Regression test (new,
`branch_templates_contract::a_merge_closes_only_the_tasks_own_branches`):
real git, `task_branch = "tasks/{n}/work"`, the lane works on `tasks/1/work`,
and `tasks/1/work-v2` (the task's rework suffix) and `tasks/2/work` (another
task) are created at the same tip. After the review passes and the merge lands:
`tasks/1/work` and `tasks/1/work-v2` are closed, and `tasks/2/work` still
points at the candidate. Run against the pre-fix `is_task_branch` the test
fails (the branch is gone), so it is red before and green after.

## What shipped

**The name builders are the templates (T-252's `gear_model::branch`).**

- `dispatch::task_branch(template, project, lane, task)` is now
  `gear_model::branch::expand`; `dispatch::conventions(tx, project)` is the one
  reader of `[conventions]` inside a transaction (a gone project or a config
  that does not parse → the default conventions, so a branch is always named).
  `intend_dispatch` reads it once per call and passes it to the delivery text.
- `quiet::last_push` names the branch the push clock watches from the same
  conventions (the unparsable-config fallback quiet.rs already had stays).
- `parallel::Input` carries the project's `task_branch` template, so an overlap
  scan compares the branches the project actually uses.
- `merge::branch_of` / `merge::review_branch` take `(template, project, lane,
  task)`. `merge_passed` reads `config.conventions.task_branch` /
  `review_branch` (it holds a `ProjectConfig`). The worker thread does not hold
  a config, so the review branch it falls back to for an op without a `review`
  payload is computed once in `merge_passed` (lane read from the task row) and
  passed down (`merge_with_retries` / `merge_one_locked`); `close_pr_branches`
  takes the `ProjectConfig` from `confirm_pr_merges`. `close_branches`'s task
  branch comparison (`is_task_branch`) no longer builds the slug by hand: it
  compares a branch's last segment with the last segment of the task's own
  expanded branch (`t53` / `t53-v2`).
- `review::review_branch(template, project, lane, task)`; `job_packet` and
  `start_direction_checks` expand `config.conventions.task_branch`. The
  direction-check branch (`direction/<task>`) is not a template in the packet's
  list and is unchanged.

`rg 'to_lowercase\(\)\.replace' crates/gear-engine/src` now finds only
`names.rs` (agent names, as the packet says).

**Seat branches.**

- `onboard::plan_onboard` takes the `seat_branch` template and the lane's
  `WorktreeStep` is `expand_seat(template, project, lane)` — `<project>/<lane>`
  by default, instead of `home/<lane>`.
- `review::start_reviewer`'s `seat_branch` is the same expansion for the review
  seat (`<project>/<seat>` by default).
- `merge::integration_worktree` opens/creates the merge worktree on
  `expand_seat(template, project, "merge")` — `<project>/merge` by default.

A seat that is already bound keeps the checkout it has: the branch is only
computed when a worktree is opened or created.

**A worktree belongs to its repo.**

`onboard::foreign_worktree(repo, path)` compares
`git -C <path> rev-parse --path-format=absolute --git-common-dir` with the same
command in the repo's own path. `onboard::check_worktree` is called wherever the
engine gets a worktree path back from Herdr for a seat or the merge
(`onboard_seat`, `review::start_reviewer`, `merge::integration_worktree`): a
different repository's checkout is not used (the lane is parked, the review does
not start, the merge waits) and the captain gets one item on thread
`worktree:<seat>`: "the worktree <path> Herdr gave <seat> belongs to another
repository (<that dir>); rename one repo folder or set conventions.seat_branch
with {project}". The item is not repeated while it is open. A path git cannot
read (a fake Herdr, a path that is gone) is not evidence of another repository,
so it is let through.

## Tests

- New: `crates/gear-engine/tests/it/branch_templates_contract.rs` (3 tests).
  1. `task_branch = "b/{project}/{lane}/t{n}"`, `review_branch =
     "b/review/t{n}"`, `seat_branch = "w/{seat}"`: the lane's worktree step
     names `w/heat`, and the dispatch packet names `b/p/heat/t1`.
  2. The same config end to end with real git: the review seat's worktree is
     `w/review-1`, the review packet names `b/review/t1`, the merge op names
     branch `b/p/heat/t1`, the review commit from `b/review/t1` lands on `dev`
     (so the merge used the project's review branch), the task branch is closed
     on origin, and the merge opened `w/merge`.
  3. Two real git repos and a fake Herdr that answers the second repo's seat
     branch with the first repo's worktree: the seat is parked
     (`NeedsCheck`, "belongs to another repository"), nothing starts in it, and
     exactly one `worktree:heat` item is open.
- Updated to the new default `<project>/<seat>`: `onboard_contract`,
  `onboard_run_contract`, `multi_repo_contract`, `dispatch_tick_contract`, and
  the fixtures of `onboard.rs`, `review.rs`, `merge.rs`, `rebind.rs` that
  asserted or pre-created `home/…` branches/paths.
- `make check CRATE=gear-engine` → 624 passed, 0 failed (on the merged tree).
- `cargo build --workspace --all-targets` → exit 0, no warnings.

## Out of scope (noticed, not touched)

- The direction-check branch (`direction/<task>`, `review::start_reviewer`,
  `job_packet`) is still built by hand: the packet lists the two
  `format!("{}/{}", lane, …)` lines only.
- `crates/gear-engine/tests/it/dead_temp_slot_contract.rs` records a warm
  review worktree at `/fake-worktrees/home-review-1`; the fake gives that path
  back for its detached worktree, so the test does not depend on the branch
  name and is unchanged.
- `gear-app`'s own names (T-252) already expand the templates; nothing there
  changed.

## Friction

- The estimate was 30 minutes; the change itself was small, but changing the
  default seat branch moved ~45 fixture sites (`home/merge`,
  `home/review-1`, `home/heat`, `/fake-worktrees/home-…`) across `merge.rs`,
  `review.rs`, `onboard.rs`, `rebind.rs` and four `tests/it` files, including
  the fake Herdr's path convention (paths are derived from the branch), which
  cost most of the time. A fixture that names a worktree branch would not have
  needed the sweep.
