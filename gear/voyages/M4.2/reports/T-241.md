# T-241 — An urgent message cuts a working lane's or reviewer's turn

Scope: `crates/gear-engine/src/ops.rs` (the fix and five tests) and this report.

Candidate: the tip of `hull/t241` — the fix `416c4891`, merged with
`origin/dev` (`01e5784c`) as `790e43ce`, and this report on top.

## The problem

A doorbell or a `gear send` text typed into a pane whose agent is **working** is
queued by the CLI as steering; it is read only when the running command returns
(another project: a 3-minute `go test ./...`; this project: the 20-minute
no-push question sat unread behind a thinking turn). The status check in `aim`
already let an urgent text in while the agent works, but nothing cut the turn
first, so the text arrived too late to be useful.

## The fix

`crates/gear-engine/src/ops.rs`, three places, no other design:

1. `Prepared::Run` carries `interrupt: bool`. In `fn check_op`, where the
   doorbell policy is computed from the covered messages, it is true only when
   the op is a `Doorbell`, the seat's role is `Lane` or `Temp` (never the
   captain: its turn is not cut) and at least one covered message has
   `urgent == true`; false for every other op, `Deliver` included.
2. In `fn execute_intended`, step 2, before `aim(...)` for a `Run` with
   `interrupt`: a new helper `fn interrupt_working_turn` reads
   `herdr.agent_get(pane_id)` and, when the answer is `Ok(Some(info))` with
   `info.agent_status == gear_herdr::AgentStatus::Working`, sends
   `herdr.send_keys(pane_id, &["esc".into()])` (as `quiet.rs` does). A pane that
   reports idle, done, blocked or unknown, or that cannot be read, is left
   alone; then `aim` runs as today.
3. In `fn deliver_doorbell_now` (the `gear send` path) the same helper runs
   before its `aim(...)` when `urgent` is true and the seat's role is `Lane` or
   `Temp` (the role now comes out of the claim transaction).

The escape is best-effort by construction: what happens next is unchanged, and
the doorbell still aims at the live agent name with the same policy.

## The tests

`crates/gear-engine/src/ops.rs` (module tests, one new fixture
`interrupt_world` = captain + one `pi` lane + one `pi` temp reviewer, helpers
`message_for`, `doorbell_for` and `prompt_or_esc`, the latter asserting the
call order):

- `an_urgent_doorbell_to_a_working_lane_cuts_the_turn_first`: the `esc` is in
  `FakeHerdr::calls` before the prompt, and the op is `submitted`.
- `a_non_urgent_doorbell_to_a_working_lane_sends_no_escape`: no `SendKeys` at
  all.
- `an_urgent_doorbell_to_an_idle_lane_sends_no_escape`: the prompt goes, no
  `SendKeys`.
- `an_urgent_doorbell_to_the_captain_sends_no_escape`: the prompt goes, no
  `SendKeys` (a working captain is not cut).
- `an_urgent_send_to_a_working_reviewer_cuts_the_turn_first`: the `gear send`
  path, `urgent = true`, a working temp reviewer (`p-review-t1`) — the `esc`
  goes before the prompt and the call returns the reviewer's pane.

## Out of scope

- The escape is sent on the strength of `agent_get` alone, as the packet says:
  it does not confirm the agent's name or session first, as `quiet.rs` does
  before its own escape. An urgent doorbell therefore trusts the pane report.
- A non-urgent captain instruction for a `pi` lane still reaches it while it
  works (`doorbell::reaches_while_working`) but does not cut the turn; only
  `urgent == true` does, per the packet.
- `session.rs` and `quiet.rs` are untouched; `quiet.rs` keeps its own loop
  escape and its own reservation protocol.

## Rework (attempt 2)

The merge gate failed in `gear-cli`:
`tests::a_failed_herdr_leaves_the_message_stored_and_the_engine_rings_it`
(`crates/gear-cli/src/main.rs`). The fake injects exactly one refusal
(`FakeHerdr::inject_next`), consumed by the next side-effecting call; with T-241
an urgent doorbell to a working lane spends it on the Escape that cuts the turn,
so the prompt then succeeded and the op was `Submitted`, not `Intended`.

The test is about the refused prompt and its recovery, not about the Escape, so
the lane in it is now **idle** (captain's answer, M-4194): no Escape is sent, the
refusal lands on the prompt, the message stays stored, the op stays `Intended`,
and the next tick rings it — every assertion of the test is otherwise unchanged,
and one comment says why the lane is idle. The Escape-before-prompt order stays
covered by the five `ops.rs` tests (`docs/…` untouched; no other file changed).
