# T-237 — Lowering `[quota] temps` retires the extra reviewer seats

Scope: `crates/gear-app/src/admin.rs` (the config-change path of `re_register`
plus `fn retire_excess_temps`), the new test
`crates/gear-app/tests/it/temps_quota_contract.rs` (registered in
`tests/it/main.rs`) and this report.

Candidate: the tip of `mast/t237` — the change `64fbb2cf` (contract v1) and the
contract-v2 update on top of it, merged with `origin/dev` (`f49f6f32`) as
`ee61fee8`.

## What changed

`fn re_register` (the config-change path of `gear admin init`), right after
`tx.update_project(&row)?` — the row that carries the new `quota_temps` — now
calls `retire_excess_temps(tx, &project_id, config.quota.temps, now)?`.

`fn retire_excess_temps` (contract v2):

1. lists the project's seats with role `Temp` whose state is not `Retired`;
2. does nothing when there are no more of them than `config.quota.temps`;
3. keeps every `Active` or `Starting` seat — a working reviewer is never
   retired — and counts it in the quota (the same accounting as the engine's
   `seats_free_for_new`, where every non-retired temp seat counts);
4. fills the slots that are left with the `Released` / `Standby` seats, newest
   `state_since` first (the id breaks a tie, so a run is reproducible);
5. sends every `Released` / `Standby` seat past them on its way out with
   `Some("temps quota lowered to <n>")` as the reason:
   - `Released` (no agent left) → `Retired`;
   - `Standby` (its agent and pane are still there, and `Temp` has no
     `Standby -> Retired`) → `Releasing`, so the engine's own release path
     closes its pane and the next config apply retires it.

A seat in any other state (`Held`, `Parked`, `NeedsCheck`, `Releasing`, …) is
neither kept by rule 4 nor touched: the packet names `Released` and `Standby`
only. Nothing new is printed.

## The tests

`crates/gear-app/tests/it/temps_quota_contract.rs`, on the same `admin init`
fixture as `config_change_contract` (a registered `harbor` project, one lane,
one captain; reviewer seats inserted with `insert_seat`):

- `a_lower_temps_quota_retires_the_oldest_released_reviewers`: seats
  `review-7` (Active, `state_since` T0+10), `review-9` (Released, T0+20),
  `review-10` (Released, T0+30) and `review-11` (Released, T0+40); re-applied
  with `temps = 2`. The Active seat stays `Active` with no reason, `review-11`
  stays `Released`, and `review-9` / `review-10` are `Retired` with the reason
  `"temps quota lowered to 2"`.
- `a_quota_that_fits_the_seats_retires_nothing`: the same four seats re-applied
  with `temps = 4` — every seat keeps its state.
- `a_standby_reviewer_beyond_the_quota_goes_releasing`: `review-7` (Active,
  T0+10), `review-9` (Released, T0+10), `review-11` (Standby, T0+20) and
  `review-10` (Released, T0+30); `temps = 2` keeps the Active seat and the
  newest idle one (`review-10`, still `Released`), sends the `Standby`
  `review-11` to `Releasing` (not `Retired`) and retires the `Released`
  `review-9`.

## The two questions behind contract v2

Both contradictions were asked at once and defaulted, and the captain answered
them in v2; the code follows the answers.

- `T-237:1` (M-4080/M-4083): the packet retired a `Standby` seat with a raw
  write, which `SeatState::can_transition(Temp, Standby, Retired)` forbids and
  which would leave a live agent and its pane behind. Answer: option 2 — retire
  `Released` only, send a `Standby` seat to `Releasing`. Implemented, and the
  model's table is untouched.
- `T-237:2` (M-4086/M-4089): "keep the N seats with the newest `state_since`
  plus every Active/Starting seat" contradicted the acceptance case (it keeps
  three seats and retires one instead of two). Answer: option A — the quota is
  a total budget, the Active/Starting seats count in it and the newest idle
  seats fill the rest. Implemented.

## Out of scope

- The extra seats' worktrees and build caches are left on disk, as the engine's
  own retire leaves them.
- A `Releasing` seat only finishes when the engine's release path runs; a
  project whose engine is stopped keeps it `Releasing` until the engine is back.
  That is the engine's existing behaviour, not this packet's.
- `gear admin init --check` and the rest of M4.2 are untouched.
