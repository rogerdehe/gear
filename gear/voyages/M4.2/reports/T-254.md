# T-254 — the captain's doorbell names only the items `gear` shows — attempt 1

Branch: hull/t254 (origin/dev merged before verification; `make check
CRATE=gear-engine` green on the merged tree)

## What changed

`crates/gear-engine/src/lib.rs` (the tick's `waiting` builder): for the captain
seat only, after `waiting` is built, the items are kept only when their id is in
a thread of `gear_app::mail::select_batch(tx, project, &seat.id, now,
gear_app::mail::BatchLimits::default())` — i.e. in the `open` ids of the batch
the home page prints. Lanes and temps (reviewers) are untouched: their own rule
(`message_belongs` + not shown, and the overrun-question exception for a
reviewer mid-review) stands.

The order of the retained items is unchanged, so the doorbell text and its
`covers` are the batch's ids in the same order `gear` lists them.

## Tests (`crates/gear-engine/tests/it/doorbell_isolation.rs`)

New helper `engine_item` (an open `System` item from sender `engine`, one
thread each), plus:

- `the_captains_doorbell_names_only_the_items_its_gear_shows` — three open
  engine threads (`merge:1`, `merge:2`, `merge:3`, per_sender 2): the doorbell
  names exactly the first two, and the captain's own `gear` (`home::build` at
  the same instant) lists the same two and not the third.
- `a_resolved_item_lets_the_next_one_into_the_captains_doorbell` — the captain
  resolves the first item and the doorbell that named it is confirmed; the next
  tick's doorbell names the remaining two, the third included.

Both fail without the change (before it the first doorbell reads
`GEAR: 3 item(s) waiting for you: M-1 M-2 M-3`), and pass with it.
