# T-238 — a Makefile with one target per situation

Scope: T-238 (contract v2) — one target per situation, so whoever runs a build
or a test picks the right cost by name, with no global config: the machine is
shared with another project, so the caps live in the targets, not in machine
settings (no locks, no queues).

Branch: mast/t238 · contract v2.

## What changed

New `Makefile` (top level, exactly three targets, each with a one-line `##`
comment, all in `.PHONY`):

- `check` — the light run for lanes and reviewers: `CRATE` is required; empty,
  it prints `usage: make check CRATE=<crate>` and exits 1; otherwise
  `CARGO_BUILD_JOBS=2 NEXTEST_TEST_THREADS=2 cargo nextest run -p $(CRATE) --no-fail-fast`.
- `gate` — the merge gate on the shared machine:
  `CARGO_BUILD_JOBS=4 cargo build --workspace --all-targets && CARGO_BUILD_JOBS=4 NEXTEST_TEST_THREADS=4 scripts/test.sh`.
- `full` — full speed for one person alone on the machine:
  `cargo build --workspace --all-targets && scripts/test.sh`, no caps.

One recipe line per target, with no `@` on the `gate`/`full` lines, so
`make -n` prints exactly the commands the packet lists.

`skills/gear/references/rules/lane.md` and `skills/gear/references/rules/review.md`:
the instruction to run a workspace build / the whole suite is replaced with
"Run the packet's acceptance commands, normally `make check CRATE=<crate>`;
never `make full`; the merge gate runs `make gate`."

- `lane.md`, "Before handing in": was "zero warnings in `cargo build
  --workspace --all-targets` (or the project's gate), the tests pass, the latest
  integration branch merged in" — that is the one place the old instruction was
  written out. "The latest integration branch merged in" is kept.
- `review.md`, "Check the mechanical facts first": the clause "build with zero
  warnings, the tests" is the reviewer's copy of the same instruction (no other
  line in that file names `scripts/test.sh` or a workspace build); it now reads
  "run the packet's acceptance commands, normally `make check CRATE=<crate>`;
  never `make full`; the merge gate runs `make gate`; the allowed files, a clean
  merge". A `gear send --kind question` was sent about this reading (review.md
  has no literal `scripts/test.sh` instruction); default option (1), edit that
  clause, was taken.

Both rule files are embedded into the engine with `include_str!`
(`crates/gear-engine/src/rules.rs`), so the new text ships with the skill.

Nothing else changed. `Makefile` is the task's allowed new file.
