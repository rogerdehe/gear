# T-447 — report

A lane that onboarding starts on its chain's head is no longer restarted for a
"config change": onboarding now records the same configuration fingerprint that
`restart::reconcile_config` compares against, in the same write that records the
lane's model.

## What changed

- `crates/gear-engine/src/restart.rs` — the computation of `desired` moved out of
  `reconcile_config` into `pub(crate) fn desired_config(config, lane_name,
  lane_kind) -> serde_json::Value` (cli, model, args and chain from the lane's
  chain head). `reconcile_config` calls it with the lane's name and kind; its
  behaviour is unchanged.
- `crates/gear-engine/src/onboard.rs` — `fn finish_start`: in the same
  `store.write` that records `model_meta_key` for the entry, the seat's
  `engine.restart_config.<seat id>` is set to
  `crate::restart::desired_config(config, &seat.name, &lane.kind)` when the seat
  is a lane of the config.
- `crates/gear-engine/src/restart.rs`, `mod config_change_tests` — new test
  `onboarding_on_the_chain_head_is_not_a_config_change`: a lane whose stored
  `engine.restart_config` names an old model and no args is onboarded on a new
  head with args; `reconcile_config` in that tick and the next plans no restart
  (no `engine.restart.<seat>`, generation stays 1, no `pane run` with
  `export GEAR_CTX`). A re-init that changes the head afterwards still starts a
  restart. The test helper `config_with_args`/`change_to` was added; `config`
  and `change` keep their exact former output so the existing tests'
  string-replacements still match.

All existing tests in `config_change_tests` pass, including
`removing_the_model_chain_restarts_without_a_model_flag` and
`a_lane_on_a_later_chain_entry_is_left_to_the_quota_step`, and the onboarding
contract tests.

## Out of scope (noticed, not changed)

- A lane whose onboarding is resumed through a pending model switch
  (`resume_start` → `switch::switch_model`) does not go through `finish_start`;
  its `engine.restart_config` is not written there. That path is outside the
  packet's two files, so it is left as it is.
- The captain's seat is not a lane of the config, so `finish_start` writes no
  fingerprint for it; reconciliation only looks at lanes anyway.
