# T-445 — report

The first row of the board lists only the voyages a plan described: where
`voyage_list` is built from `entries`, the departure filter is followed by one
that keeps an entry only when its `done` is `Some` and not empty after trim.
Nothing else changed.

## What changed

- `crates/gear-board/src/lib.rs` — the `voyage_list` build (the
  `entry.departure.is_some()` filter) gains a second filter on
  `entry.done.as_deref().is_some_and(|done| !done.trim().is_empty())`, with a
  comment naming T-445. The shown voyage is still chosen as T-441 made it, a
  milestone named explicitly still shows, and `[`/`]` still move through the
  list (`position` on a missing shown voyage yields `None`, so they do nothing,
  as today).
- `crates/gear-board/tests/it/voyage_select_contract.rs` — the new test
  `the_voyage_list_shows_only_the_voyages_a_plan_described`: a store with M1
  (done sentence, departed) and M1.1-cancelled (departed later, one cancelled
  task, no done sentence) has `voyage_list` of M1 only, and with an M2 that has
  a done sentence too the list is M2 then M1.
- The T-441 test `a_plan_less_milestone_that_departed_later_does_not_hide_the_landed_voyage`
  asserted the old list (`M1.1-cancelled`, `M1`); its assertion and comment now
  read M1 only, which is the contract this task sets. Its other assertions
  (shown voyage M1, named milestone still shown) are unchanged and pass.

## Friction

- The shell carried a stale `GEAR_CTX` (generation 31 against seat generation
  32) after the restart: `gear` answered `STALE_GENERATION`. The captain said

  prefix. Cost: a few minutes at the start.

## Out of scope (noticed, not changed)

- `frame.rs` draws one label per `voyage_list` entry, so a plan-less milestone
  no longer gets a ⚓ label in the first row — the intended effect of the
  filter, no code change needed there.
- The golden contract tests append entries to `voyage_list` by hand after the
  build, so they are unaffected by the filter.
