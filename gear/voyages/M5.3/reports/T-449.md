# T-449 — report

A voyage that waits for its departure time says so: while the stored config's
`[schedule] depart_at` is ahead, the shared voyage line ends
`· departs at HH:MM`, so `gear` (the captain home page and
`gear report voyage`) and the board show why nothing moves. At and after that
moment, and without `[schedule]`, the line is unchanged.

## What changed

- `crates/gear-board/src/voyage.rs` — `VoyageReport` gains
  `departs_at: Option<Ts>`; `build_reports` fills it once per project with the
  same rule as `gear_app::config::departs_at` (`Some` while `now` is before the
  stored config's `schedule.depart_at`, `None` at and after it, without the
  section and when it does not parse). `VoyageReport::lines()` appends
  ` · departs at HH:MM` (via `gear_board::idle::clock`) to the voyage line only
  while that is `Some`. The line is the one `gear`'s captain home page and
  `gear report voyage` print and the one `crates/gear-board/src/lib.rs`
  `project_lines` draws as the board's voyage header, so both surfaces show it
  without a second copy.
- `crates/gear-board/src/idle.rs` — `rfc3339` is `pub(crate)` so the voyage
  report can parse the stored `depart_at` with the board's existing parser.

The captain's answer (M-6471) chose this shape: the shared voyage line in
gear-board, no gear-cli code change, tests in both crates. gear-board reads the
stored `config_toml` itself because gear-app already depends on gear-board, so
`gear_app::config::departs_at` cannot be called from there; the comment on
`departs_at` names it as the rule mirrored.

## Tests

- `crates/gear-cli/src/main.rs` — `run_home` of a captain with a voyage that
  has not departed and one open task: a future `depart_at` shows
  `departs at 14:00` for the test's local clock; without `[schedule]` the
  voyage line is unchanged.
- `crates/gear-board/tests/it/depart_contract.rs` — the board render: a future
  `depart_at` shows `departs at 14:00` for the test's local clock; at the
  moment and without `[schedule]` the line is unchanged. Registered in
  `crates/gear-board/tests/it/main.rs`.

## Friction

- Unclear contract: the packet names crates/gear-cli as where `gear` prints the
  voyage line, but gear-cli does not compose that line (gear_app::home does),
  and `gear_app::config::departs_at` is unreachable from gear-board (gear-app
  depends on gear-board). I asked the captain and worked on the confirmed
  gear-board rule.
- The first `make check` was aborted by the overrun question; I answered it and
  ran the checks again.

## Out of scope (noticed, not changed)

- The departure is a project-level moment, so every report `build_reports`
  returns carries it; with more than one open voyage, each voyage line would
  say `departs at`. Normal use has one open voyage.
- A project between voyages whose config names a future departure would show
  `departs at` on the latest finished voyage the board measures; that is the
  project's next departure, not a wrong moment.
- `hours` and `notice_min` are still unread here; T-450 uses them.
