# T-531 — report

An OpenCode seat changes its model only through its session API. The keys path
(`/model`, the picker filter, the variant dialog) is gone: it saved the variant
and the recent list in `~/.local/state/opencode/model.json`, the default of
every OpenCode session on the machine, which is not the seat's own change to
make.

## What changed

- `crates/gear-engine/src/switch.rs`:
  - `switch_model` no longer calls `switch_in_place` or `api_fallback`. A
    seat whose kind is not `opencode` is `Failed` with nothing sent. A binding
    with no `session_ref` clears the pending plan and is `Failed`. A catalogue
    `Lookup::NotLoaded`/`Lookup::Unavailable`, a failed `GET` of the session and
    a failed `session.switchModel` call wait like `wait_for_agent`, bounded by
    `WAIT_TICKS * 2`, then the plan is cleared and the seat is `Failed`. No
    pane text is sent on any path.
  - `pending` drops a plan an earlier binary stored with a typed step
    (`escape`, `command`, `filter`, `variant`, `confirm`): it clears the meta
    and returns `None`, so the API path runs from the beginning. `Step` keeps
    only `ApiConfirm` and the stored text `api-confirm`; `begin` records that
    step.
  - Deleted: `switch_in_place`, `api_fallback`, `SwitchSteps`, `failed_try`,
    `pane_of`, `keys`, `text`, `PICKER_MARKS` and the typed `Step` variants.
    `switches_in_place` is kept: `restart.rs` (the T-464 config apply) and
    `quota.rs` (the restart-vs-switch gate) still call it as the policy
    predicate, so it is not "called by nothing" — the packet's clause (4).
  - `crates/gear-engine/src/review.rs` (one plumbing change, asked in
    T-531:6): an OpenCode reviewer's start now makes its service session
    through `opencode::start_args`, as onboarding and the restart path already
    do. Without it the reviewer's binding has no `session_ref`, so the model
    gate could only fail and park a fresh reviewer.
- Tests: `switch.rs`, `onboard.rs`, `quota.rs`, `restart.rs`,
  `review.rs`, `tests/it/onboard_run_contract.rs` and
  `tests/it/reviewer_quota_contract.rs` were changed from the typed path to
  the API path or to `Failed`, and each asserts that no `/model` or `/models`
  text (and no key) reaches the pane. New switch tests: an API switch that
  succeeds sends no pane text; a seat with no session ref is `Failed` with
  nothing sent; an unavailable API is `Waiting` until the bound (exactly
  `WAIT_TICKS * 2` waits) and then `Failed`, with nothing sent; a pending plan
  stored with step `filter` is cleared and the next call makes the switch
  request; a non-OpenCode kind is `Failed` with nothing sent.

## Out of scope

- `crates/gear-engine/src/opencode.rs:161`: the doc of `start_args` still says
  "API failures leave the existing typed-switch fallback available"; there is
  no typed path any more. A comment only.
- `crates/gear-engine/src/quota.rs:757` and `restart.rs:1527` keep calling
  `switches_in_place`: the packet listed it for deletion but both callers
  remain, and the packet says to change those files only where they name a
  deleted item (asked as T-531:1).
- A reviewer seat has no `engine.worktree_path` meta (only onboarding and
  rebind set it), so the restart path's `opencode::start_args` is skipped for a
  reviewer restarted onto OpenCode: such a reviewer would be `Failed` at the
  model gate. The reviewer test seeds the key to exercise the production path;
  the missing key itself is the review path's, not switch.rs's.
