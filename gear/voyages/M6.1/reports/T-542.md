# T-542 — report (attempt 1)

A station item can wait for the user quietly (decision 06:35).

## `crates/gear-app/src/mail.rs` (only source file changed)

The reply check near line 1666 now refuses only `--resolve` on a station item:
`ReplyMode::Note` and `ReplyMode::Wait` are allowed (the refusal with
"station … needs a plan # Decisions line" still fires for `--resolve`). A wait
needs its `wait_until` as every wait does, and the item then goes through the
ordinary waiting path: state `Waiting`, `wait_on`, `wait_until`, out of
`actionable_for` until its time and back in it after — no doorbell in between,
which is what the existing waiting machinery does for every captain item.

## The plan's station path

`crates/gear-app/src/station.rs::apply_decisions` already accepts an item in
`Waiting`: it only skips a `Resolved` item (the retained historical decision),
so `station <id>: land` (or keep course, time-box, cut, move) settles one from
`Waiting`. No change was needed there.

## Tests (`crates/gear-app/tests/it/station_contract.rs`)

- `a_station_item_can_wait_for_the_user_quietly` — the ready-to-land item of a
  finished voyage answered with `--wait user --until +12h` is `Waiting` with
  `wait_on`/`wait_until` set; it is not in `actionable_for` nor in

  asserted that both `--resolve` and `--wait` are refused; now only `--resolve`
