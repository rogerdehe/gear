# T-536 — report (attempt 1)

A held task (`state: hold` → Draft) stays in its voyage's scope, counts as
remaining work, is listed as held, and still cannot be started.

## Counts and scope (1)

| site | change |
| --- | --- |
| `crates/gear-board/src/stations.rs` | the scope filter and both doc comments: Draft is in the scope, only Cancelled and Failed are out |
| `crates/gear-board/src/voyage.rs` | the voyage report's scope: same rule (header totals, `remaining_estimate_min`, `scope_min`, the per-lane left) |
| `crates/gear-app/src/station.rs` | the checkpoint scope: same rule |
| `crates/gear-app/src/time.rs` | the voyage's task set is now "not Cancelled, not Failed" (it excluded Draft only, so Cancelled and Failed were counted); held tasks and their rounds count |
| `crates/gear-board/src/lib.rs` | the board's project totals count a held task, as the stations do (captain's answer M-7531: a2) |

## Listings (2)

- `crates/gear-board/src/deps.rs` — `tree` lists a held task as open (doc comment too).
- `crates/gear-board/src/idle.rs` — `queue_of` lists it (doc comment too).
- `crates/gear-app/src/queue.rs` — the lane's queue lists it, and `LeftTask` carries `held` (captain's answer M-7531: b1); the line reads `T-x 60m held`.

## State name (3)

`crates/gear-board/src/graph.rs` and `crates/gear-board/src/lib.rs`
(`state_word`) say "held" for Draft. No text in `crates/gear-cli` prints "draft"
for a task; `TaskState::as_str` stays "draft" because the store and the plan
round-trip on that word (see Out of scope).

## Can start (4)

Every caller of `queue_of` is `idle_reason`; its `is_queued` matches Ready and
Waiting only, so a lane whose only task is held reports `NoWork`. The declared
wait check skips Draft (a held task is not waited for). `start_attempt` still
requires Ready; `crates/gear-engine/src/parallel.rs` still leaves Draft out of
the dispatch. The queue's `working` needs an open attempt. Nothing in
`crates/gear-engine` changed.

## Out of scope

- `crates/gear-board/src/graph.rs` `tasks_shown` still leaves Draft out of the
  flow view: a Draft task with no attempt would be staged `Queued`, which would
  read wrong without a "held" stage; the packet did not name it.
- `TaskState::as_str` keeps "draft" (the store and the plan round-trip on it), so
  plan refusals such as `task T-1 is draft, only a draft or ready task is held
  here` still say "draft" rather than "held".
- `crates/gear-app/src/plan.rs` still leaves a held task out of the shared-file
  warning (a task it cannot start); that matches (4) and its test stays green.
