# T-540 — report (attempt 1)

A merge never reports a branch as left on the remote when the branch is already
gone (decision 05:55, M-7576).

## `crates/gear-engine/src/merge.rs` (only file changed)

`fn close_branches` now asks the remote before it reports a failed delete. The
new helper `branch_on_remote` runs `git ls-remote --exit-code --heads <remote>
<branch>` in `dir`; when the branch is not there, the branch counts as closed
(pushed into `closed`) instead of left.

The two delete sites the packet names:

- the branch whose tip is the candidate (the `pushed.tips` loop): a delete that
  fails and a branch that is gone now pushes the name into `closed`; a branch
  that still exists is reported under `left` (once — the later task-branch block
  skips a name already in `left`, so no branch is named twice).
- the task branch whose tip moved past the candidate: a delete that fails and a
  branch that is gone pushes the task branch into `closed`; a branch that still
  exists stays in `left` with its commits, as today.
- the same check on the task branch whose tip is the candidate in the later
  block: gone → `closed`, still there → `left` (once).

Every other path, and the review branch's delete, is as today; steps 7–9 are
untouched.

## Tests (`mod tests`, the Scratch repos)

- `a_branch_deleted_on_the_remote_before_the_close_is_closed` — the gate runs
  between the fetch and the close and deletes `heat/t5` on the remote
  (`git --git-dir=../origin.git update-ref -d`): the merge lands, the result
  carries `closed on origin:` with `heat/t5`, no `left on` line is written, and
  the branch is not on origin.
- `a_branch_that_stays_after_a_failed_delete_is_left_on_the_remote` — a
  `KeepsBranchRemote` runner refuses only the delete of `heat/t5`: the result
  names `heat/t5` under `left on origin`, `review/t5` is still closed as usual,
  and `heat/t5` stays on origin.
