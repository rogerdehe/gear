# M6.1 lessons
- 2026-11-01: The user's order with the work and the staffing is the word to depart. The captain held M6.1 about 40 minutes for a departure sheet while answering other projects; it departs at once and reports instead.
- 2026-11-01: A release is finished only when the projects using GEAR run it. The binary, the engines and the installed skill copies (~/.codex, ~/.claude, ~/.pi … are copies, not links) were rebuilt, restarted and reinstalled at once; the other project's captain had read a skill from 10-25 through all of M6.
- 2026-11-01: An in-session `/model` saves the CLI's machine-wide default (Claude Code: "saved as your default for new sessions" into ~/.claude/settings.json; OpenCode's picker and variant dialog into ~/.local/state/opencode/model.json). Start flags do not. Change a model by restarting with flags; never type it into a seat.
- 2026-11-01: A Working flicker of an agent is no proof that it took a delivery: mast's packet sat in pi's input box with the Enter turned into a new line, and the engine confirmed it by the turn. Check the screen before trusting a turn (T-535).
- 2026-11-01: A conflict fix on the review branch never reaches a remerge, and a hand merge on dev loses the race against a 4-minute CI while other merges move dev (the other project, T-441). The fix goes in through the engine's own merge (T-532).
- 2026-11-01: A packet's acceptance command is run literally by a flash lane: `TESTS='skill'` was not a nextest filter, and the lane had to ask. Write the exact command, with `test(...)` around a name.
- 2026-11-01: The kickoff skipped the role charters, though M6 built them: the departure sheet has no line that makes the captain write them. Fixed in T-539; until it ships, check the charters before every departure.
- 2026-11-01: The other project's merge gate (its CI, about 6 min) was not its bottleneck: the merge step was busy 22 % of 34 h and a passed task merged in a median 9 min; 20 of 62 gate runs failed, 16 of them passed later on the same candidate, and those failures made the slow tails.
- 2026-11-01: A search the captain moved to the background kept running for an hour after its turn (grep over a 100 MB transcript at 90% of a core) and raised a machine health item. Stop every background command once its answer is no longer needed, and never grep a whole session transcript.
- 2026-11-01: A failure that passes later on the identical tree proves the result is not deterministic, not that a test is flaky: the other project's "flaky" Go test was another test's intentionally unlocked calibration on the shared database cluster. Name the cause only from the owner's evidence; ask the project's captain before recommending a quarantine.
- 2026-11-01: A packet that removes a code path named one file ("switch.rs only"), but the path's callers and tests sat in four more (review.rs, restart.rs, two integration files), and the reviewer start had no session for the remaining path; the lane spent most of 51 minutes finding that (F-309). Before writing "change X only" for a removal, `git grep` every caller and every test of what goes, and name those files in the packet.
- 2026-11-01: The machine's shared sccache server keeps the TMPDIR of whichever build started it; when that was a project's pruned scratch directory, every Rust build on the machine failed with os error 2 until the server was stopped (F-310). A shared server needs a fixed temp directory of its own.
- 2026-11-01: The captain pushed to dev while a merge was executing, because it read the op list before the merge started; check for an executing merge in the same command as the push, every time.
