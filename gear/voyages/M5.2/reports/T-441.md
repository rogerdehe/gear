# T-441 — report

With no voyage sailing, the board shows the latest voyage the plan described,
not a milestone the plan never described.

## What changed

`crates/gear-board/src/lib.rs`, `fn workload_voyage` only:

- The fallback after the active voyages still drops the active ones and keeps
  only reports whose departure is known (`elapsed_min` is `Some`), sorted by
  least elapsed time — the latest departure first, as before.
- It now prefers the first of those whose `done` is `Some` and not empty: a
  voyage the plan described, with a goal sentence to show.
- When no finished voyage is described, it falls back to today's choice (the
  first departure in that order), so a project with only plan-less milestones
  still shows one.

The active voyages still win unchanged, and the voyage list (`[`, `]`, the
header labels) and a voyage named with a milestone are untouched: they never go
through this function.

Tests in `crates/gear-board/tests/it/voyage_select_contract.rs` (where the crate
keeps the tests of the shown voyage), with a `planless` fixture — a voyage row
with an empty title and no done sentence, as `set_voyage_departure` creates it:

- `a_plan_less_milestone_that_departed_later_does_not_hide_the_landed_voyage`:
  M1 landed and described, M1.1-cancelled departed later with one cancelled
  task and no done sentence — the board shows M1 (its title, its done sentence,
  its task, its totals); the voyage list holds both departures, and naming
  M1.1-cancelled still shows it.
- `a_project_with_only_a_plan_less_milestone_still_shows_it`: M1.1-cancelled
  alone is shown as today's voyage, with no done sentence.
- `an_active_voyage_still_wins_over_a_later_departed_plan_less_one`: the
  sailing M2 is shown even when a plan-less milestone departed later.
