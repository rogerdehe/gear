# T-492 — report (attempt 1)

The scenario test is in `crates/gear-engine/tests/it/day_contract.rs`
(`a_day_of_two_fleets_in_different_zones_rings_once_and_settles_the_named_project`),
registered in `main.rs`. Test only: no product change.

## The day it drives

One engine on `FakeHerdr`, one captain pane (`w1:p1`) holding the captain
seats of two projects:

- p: `[schedule] hours = "08:00-20:00"`, `tz = "Asia/Shanghai"` (UTC+8) →
  00:00–12:00 UTC.
- q: `[schedule] hours = "06:00-18:00"`, `tz = "America/New_York"` (EST on
  2027-03-10, UTC-5) → 11:00–23:00 UTC.

The overlap is 11:00–12:00 UTC. The test ticks through the day:

- **04:00 UTC** (12:00 Shanghai, 23:00 New York): p's lane takes its `New
  task T-1`; q's lane takes nothing and is parked/released for its working
  hours (the hours report names it, and the pane is left a shell).
- **11:30 UTC** (19:30 Shanghai, 06:30 New York, the overlap): q's lane comes
  back on its own (restart on its chain's model) and takes its own `T-1`; p
  keeps working; neither lane is parked or released.
- **14:00 UTC** (22:00 Shanghai, 09:00 New York): no new task goes out to p's
  fleet and its lane is parked; q's lane keeps working.

The lane delivery ops the fake agent cannot confirm (it never runs `gear`) are
settled by hand between ticks, as a seat's check-in would.

## The doorbell and the reply

In the overlap, one open item is put in each project's captain inbox. One
tick produces exactly one new prompt on the shared pane, and that doorbell
names both projects' items (`- p: … <id>`, `- q: … <id>`) and says it holds
items across two projects — a resting project adds nothing, so the joined ring
is also the proof that both fleets work in the overlap.

`gear_app::mail::reply` is then called with the qualified id `q:<id>` from the
p captain's context on that pane: it resolves q's item and leaves p's item
open. The reply goes through the real `mail::reply`, so the qualified-id
resolution (T-485) is exercised, not a state write.

## Noted

- The fake never settles an op (its agent never checks in), so the test
  confirms deliveries and doorbells between ticks; without that, a failed
  delivery is re-typed and a doorbell op holds the captain's slot, which is
  what the first drafts hit.
- The two lane restarts and the restart notices put earlier items in the
  captains' inboxes; the test asserts on the *new* prompt of the overlap tick
  and on the item ids it made, so those notices do not make it brittle.
