# T-520 — report (attempt 1)

The gate has no wall-clock test: two engine tests that asserted an elapsed time
and failed under parallel load (F-293) now check the fact instead of the clock.

## The change

- `crates/gear-engine/tests/it/merge_scan_contract.rs`,
  `an_idle_merge_step_on_five_hundred_done_tasks_is_under_a_hundred_milliseconds`:
  the timing loop is gone. The test keeps what it already proved — after the
  first tick the stored `engine.lost_scan.p` is `T0`, and three idle ticks leave
  it at `T0`, so an idle tick re-runs no scan and reads none of the 500 done
  tasks. `Instant` is no longer imported; the "no clock" reason is in the doc
  comment.
- `crates/gear-engine/src/overrun.rs`,
  `a_long_history_does_not_cost_the_rounds_query` → `a_long_history_is_selected_by_index`:
  same history (one open round, 300 ended rounds, 10 000 messages), now on a
  store file, and the assertion is the **query plan** of `rounds_to_process`:
  `SEARCH rounds USING …` (the rounds key) and `SEARCH m USING …`
  (`messages_thread`), with no `SCAN rounds`, `SCAN m` or `SCAN messages`. The
  plan showed no scan, so no index was added (T-517's indexes already serve it:
  the answered-threads subquery searches `messages_thread` by project). The test
  still asserts that the one open round is selected.
- Nothing else changed; the tool's `grep -rn "from_millis" crates/gear-engine/tests crates/gear-engine/src`
  now finds only sleeps and injected delays, no assertion on an elapsed time.
