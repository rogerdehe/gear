# T-486 — report

`gear` with no arguments, run by a captain that holds several projects, shows
every held project: its voyage line and its inbox, each item line naming the
project by its qualified id, urgent items of all projects first.
`gear --show` and `gear friction close` take the qualified ids (`gear reply`
already did, T-485). With one project the page is exactly the page of
design/13.

## What changed

`crates/gear-app/src/home.rs`:

- `build_with_agents` asks `identity::captains_on_pane` for the pane's captain
  seats. More than one project → `multi_page`; one project → the old page
  unchanged (same lines, same bare ids, same snapshot).
- `multi_page` renders, in this order: a `URGENT (n threads)` block with every
  urgent item of every held project (each line `  <thread> [urgent]
  <project>:M-<n>` and its body), then one section per held project with its
  voyage report lines, its goal, `INBOX` of the remaining threads and
  `UNSHOWN` replies, every id qualified (`<project>:M-<n>`). Each project's
  view is recorded under that project's own captain seat, so a bare `M-<n>`
  shown in one project never marks the same id shown in another; `Home.views`
  carries one view per project and `Home.view` is the caller's own project's
  view.
- `next_command` (shared with the single-project page) takes the first shown
  message and prints `gear reply <qualified id>` / the station plan line /
  the verdict command.

`crates/gear-cli/src/main.rs`:

- `gear` records every view the page showed (`home.views`), not only the
  caller's.
- `gear --show <project>:T-<n>` resolves the project's captain seat on the
  caller's pane (`env_of_captain`) and prints that project's task packet; a
  bare id keeps the caller's own project.
- `gear friction close <project>:F-<n>` does the same for the report's
  project and closes it there.

## Tests

`crates/gear-app/tests/it/multi_home_contract.rs` (3): two held projects show
both voyage lines and project-qualified items, the second project's urgent
item above the first's normal item, one view per project with only its own
message; a second page does not show the first page's items again as
`UNSHOWN`; one project renders as before (voyage line first, bare ids, no
`URGENT` block).

`crates/gear-cli/tests/it/home_multi_contract.rs` (3, run the real binary as
the captain of the pane this test runs in): the rendered page above;
`gear --show b:T-1` prints the second project's packet while a bare `T-1`
prints the caller's; `gear friction close b:F-1` closes the second project's
report. Without a Herdr socket these tests return early; the rendered-page
tests above always run.

## Friction

Past the 40-minute budget. The packet's "its voyage line, then its inbox …
urgent items of all projects first" can be read two ways; I asked the captain
(M-6990) and went with the default: urgent items lifted into one block at the
top, then each project's voyage line and remaining inbox. Building the CLI
fixture also cost time: the caller must be a real Herdr pane (ancestry proof),
so the test discovers the pane's occupant kind and seeds the bindings on it.

## Out of scope (noticed, not changed)

- The multi-project page does not repeat the captain's plan snapshot (T-9)
  per project: the packet names the voyage line and the inbox, and the
  snapshot per project would double the page.
- `gear friction` without an id still lists only the caller's own project;
  the packet asked the commands to accept qualified ids, not to widen the
  listing.
- `gear reply` needed no change: T-485 already resolves qualified ids
  (`split_qualified`/`reply_project`).
