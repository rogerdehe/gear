# T-486 — report (attempt 4, rework)

The rework: the merge gate failed all three `home_multi_contract` tests
because they claimed the live Herdr pane while `make gate` runs under the
engine, outside that pane; run them without a live pane.

## What changed

`crates/gear-cli/src/main.rs`:

- `caller_door(store, env)`: a live Herdr when `HERDR_PANE_ID` is set (the
  path every pane takes, unchanged); otherwise — a caller that claims no
  pane — it fills the caller's pane from its seat's **active binding** and
  answers through a binding-backed `HerdrRead` (`FakeHerdr` seeded with the
  binding's pane, kind and session, and the process's own parent as the
  pane's shell), so the seat is still proven from the store without a Herdr
  connection. Without a context the door is an empty reader.
- `cmd_home` (`gear` and `gear --show`) and `cmd_friction` use it instead of
  `open_herdr()` unconditionally. With `HERDR_PANE_ID` set, nothing changes.
- `run_home`/`run_show` take an optional Herdr door; the unit tests keep
  passing a `FakeHerdr` and are unchanged in behaviour.

`crates/gear-cli/tests/it/home_multi_contract.rs`: the tests seed the
captains on a fixed pane and run the binary with `GEAR_CTX` and
`HERDR_PANE_ID`/`HERDR_SOCKET_PATH` removed (as the other gear-cli contract
tests do), so they no longer read or claim a live pane. The page still renders
the multi-project page, `--show b:T-1` still resolves b, and `friction close
b:F-1` still closes b's report — now from the binding-backed door.
