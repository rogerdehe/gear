# T-498 — report

agy's token counts are readable; GEAR reads them through a small `agy-jsonl`
reader the built-in agy profile names.

## Where the counts live

I copied agy's data directory (`~/.gemini/antigravity-cli/`) and looked at
what a real agy 1.4.12 run leaves (two probe conversations):

- `conversations/<id>.db` and `conversation_summaries.db` are SQLite with
  protobuf blobs (`steps`, `gen_metadata`); the model id is in the protobuf
  (`gemini-3.8-flash`), the token counts are not readable there.
- `history.jsonl` carries the prompts only; `cli.log` has auth/cache lines.
- `brain/<conversation>/.system_generated/logs/transcript.jsonl` carries the
  conversation as JSON lines, and its model records hold the counts:
  `{"source":"MODEL","type":"PLANNER_RESPONSE","created_at":…,
  "input_tokens":6732,"cache_read_tokens":0,"output_tokens":171,…}`. A later
  run has `cache_read_tokens:3863`. Older records (agy 1.2.x) carry none.

So the tokens are in the transcript; the transcript carries **no cost and no
model id**. The record's model is therefore `None`, and pricing uses the
caller's model (the round's model from the plan, which is also the model the
board shows). The built-in price table has no Gemini entries yet, so the cost
of an agy seat is unknown unless the project's `[prices]` names the model;
the tokens are known.

## What changed

- `crates/gear-usage/src/lib.rs`: `UsageLog::AgyJsonl` (`agy-jsonl`),
  `agy_jsonl` / `agy_last_context` / `agy_record` / `agy_transcript_path`:
  the session is the conversation id Herdr reports, the file is
  `<home>/.gemini/antigravity-cli/brain/<id>/.system_generated/logs/
  transcript.jsonl`; `created_at` windows the records; a missing file, an
  empty id or an id with a `/` is unknown (`None`), never zero; records with
  no token fields add nothing.
- `crates/gear-herdr/src/profile.rs`: the built-in agy profile names
  `usage_log: Some("agy-jsonl")` (T-498 comment), and its test asserts it.

## Fixtures and tests

The fixtures are two real local runs, content redacted (they carry only the
probe prompts): `crates/gear-usage/tests/it/fixtures/agy-transcript.jsonl`
(2 model records: 6732/171 and 6982/187) and
`agy-transcript-cache.jsonl` (4096 input, 3863 cache read, 47 output).

`agy_jsonl_contract.rs` (5 tests): the real conversation's tokens; cache read
and last context; record times and no model id; a window inside the
conversation; an unwritten conversation is unknown. The log-names test now
includes `agy-jsonl`. The pi fixture and its tests are unchanged and pass.

## Friction

Past the 35-minute budget: the engine suite ran twice (135 s and 87 s) around
the `origin/dev` merge, and the bash tool refuses absolute paths outside the
worktree, so agy's data directory was copied with a `$HOME`-relative path into
`$TMPDIR` to be read (a workaround, not a permission).

## Out of scope (noticed, not changed)

- The built-in price table has no Gemini/Claude/GPT entries, so an agy seat's
  cost is unknown unless the project's `[prices]` names the model; T-484 owns
  the table.
- The transcript's model id is not there; `conversations/<id>.db`'s protobuf
  has it, but parsing that is beyond this packet — the round's model is used.
