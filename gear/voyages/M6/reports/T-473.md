# T-473 — report

The four plan tools: a task can be held out of delivery with `state: hold`
until a later `state: ready`; a voyage departs only on its explicit
`depart: now` line; a milestone with no task and no history can be removed
with `- drop <milestone>`; and an apply warns when two Ready tasks on
different lanes name one file.

The captain answered the two open readings (M-6852, M-6854): 1 and 3(a) as
proposed; 2 is `depart: now` only, with a timed departure staying
`[schedule] depart_at` (T-448) and the kickoff step in `captain.md` writing
the line; 4 takes the file names from each Ready task's goal text (paths such
as `crates/x/src/y.rs`) and its evidence files, and only pairs on different
lanes warn.

## What changed

`crates/gear-app/src/draft.rs`:

- `state` accepts `hold` beside `ready` and `cancelled`.
- `milestone_depart(body)` reads the block's `depart:` line.
- `StaffItem::Drop { line, milestone }` and the `- drop <milestone>` staff
  line.

`crates/gear-app/src/plan.rs`:

- A NEW block with `state: hold` is created Draft (out of delivery); `state:
  cancelled` is allowed too. An existing Draft or Ready task becomes Draft on
  `hold`; a delivered task (Running/Waiting/Verifying) is refused with a line.
- `departs_now` and `planned_guard`: a milestone departs only when its block
  carries `depart: now` and it has tasks; the confirmation guard (T-461) now
  covers a milestone that already carried tasks without a departure too.
- `record_voyages`: `depart:` must be `now` (any other value is refused); a
  milestone with `depart: now` and tasks gets its departure, task count and
  scope estimate once, and a later block never moves it. The implicit
  departure from creating the first tasks is gone.
- `fix_departures`: only empties a milestone that lost every task; it recovers
  a departed voyage's missing scope estimate from the oldest plan that carried
  its tasks, but never moves the departure.
- `drop_milestone`: applied after the voyages; refuses a milestone the plan
  still describes, one with a task, a departure, a decision or a station, and
  otherwise deletes the voyage row. The staff line is recorded as a `staff`
  decision and in `ApplyResult.staffed`.
- `shared_file_warnings` and `files_of`: one warning per file named by two
  Ready tasks on different lanes (goal paths and evidence files); it never
  refuses the apply.

`crates/gear-app/src/goal.rs`: a departed voyage's block written back into the
plan carries its `depart: now` line.

`crates/gear-store/src/lib.rs`: `delete_voyage`.

`skills/gear/references/captain.md`: the kickoff step writes `depart: now`
after the user's word; the Voyage block and the Queue `state` fields name the
new rules; the Staff list names `- drop <milestone>`.

The merge with `origin/dev` kept T-467's `raise` staff line beside `drop`.

## Tests

`crates/gear-app/tests/it/plan_tools_contract.rs` (new module):

- `a_new_task_can_be_held_out_of_delivery_and_sent_ready_later` — a NEW block
  with `state: hold` is Draft; `state: ready` sends it.
- `a_ready_task_is_held_and_a_delivered_one_is_refused` — a Ready task becomes
  Draft; a Running task is refused with "only a draft or ready task is held
  here".
- `a_milestone_departs_only_on_its_explicit_depart_now_line` — a block with
  tasks and no `depart:` stays undeparted; `depart: now` departs it with its
  task count; a timed value is refused and writes nothing.
- `a_milestone_with_no_task_and_no_history_can_be_dropped` — a spare milestone
  is removed; one the plan describes, one with a task, and one whose move left
  a decision are refused.
- `a_plan_apply_warns_when_two_ready_tasks_on_different_lanes_name_one_file` —
  the warning names both tasks and the file; the same lane and a held task
  produce none.

The fixtures that expect a departure in the app and cli tests now write
`depart: now` (voyage, bar, station, staffing, time report, decision, and the
cli's `plan_draft_with_milestone`). `the_departure_is_the_first_task_creation_even_without_the_block`
was renamed in spirit: a block with tasks and no line no longer departs.

## Friction

- The task ran past its 50-minute budget: the four tools touched the apply's
  departure logic and 38 existing tests had to learn the explicit `depart:`
  line, and the merge with `origin/dev` conflicted with T-467's `raise` staff
  line, which cost a second conflict resolution and a full re-run of the
  three crates.

## Out of scope (noticed, not changed)

- A `depart: now` block with no task writes no departure (a voyage needs its
  tasks); this is silent, not a warning.
- The shared-file warning reads the contract's goal text with a path-shaped
  token heuristic (a slash and a file extension, no URL); a path written
  without a slash is not seen.
- Dropping a milestone with no history but with its stored `done`/`bar`/`eta`
  words deletes those words too: the plan no longer describes it.
