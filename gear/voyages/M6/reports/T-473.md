# T-473 — rework report (attempt 2)

The four review findings are fixed. The plan tools stay as in attempt 1:
`state: hold` keeps a task out of delivery, a milestone departs only on an
explicit line (or the project's schedule), a milestone with no task and no
history can be dropped, and an apply warns when two Ready tasks on different
lanes name one file.

## What changed

`crates/gear-app/src/plan.rs`:

- **F1** — `record_voyages` takes the project's `[schedule] depart_at` when a
  milestone block carries no `depart:` line and the stored config names a
  parseable instant: the voyage gets that departure, its task count and its
  scope estimate once (new `scheduled_departure`, about 10 lines). A timed
  voyage therefore keeps its eta and its scheduled end (`hours::voyage_eta`,
  `schedule_of`); a block with `depart: now` still departs at the apply, and a
  later block never moves either.
- **F2** — the `- drop <milestone>` staff decision is recorded against the
  empty voyage key, not the milestone it just deleted: the append-only log
  keeps the line, and a later milestone that reuses the id does not inherit it
  (a second drop of the reused id succeeds).
- **F3** — `counts_before` in `planned_guard` is removed.
- **F4** — the stale voyage test is now
  `a_block_with_tasks_and_no_depart_line_does_not_depart` and tests the real
  rule: a bare queue without the block is refused; a block with tasks and no
  `depart:` line creates them without a departure; a later `depart: now` block
  departs with the tasks it has then; a later block never moves it.

## Tests
