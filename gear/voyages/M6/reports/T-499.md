# T-499 — report

A re-review resumes the conversation of the review it continues, not whatever
conversation its seat had last. When that conversation cannot be resumed, the
packet names it and the earlier review file, as T-481 does for a lane.

## The bug and what changed

`crates/gear-engine/src/session.rs`:

- `review_facts` used the seat's **latest** review round of the task. Once the
  re-review's own round exists it *is* the latest one, and the session
  bookkeeping (`rounds`) records the session the seat still carries from its
  previous job on that round before the resume runs. So a seat that reviewed
  another task in between read that task's session as "the earlier review"
  (in the fleet's store, T-472 attempt 2's review round carried T-495's review
  session, and its recorded action was a `resume-fallback` of it). Now a
  re-review (attempt n ≥ 2) reads the round of attempt n-1 on the seat; only
  attempt 1 keeps the "latest review round of the task on this seat" lookup.
- `prepare_review_role`: for a re-review's open round, S1 resumes the session
  of attempt n-1, not the session the new round may already list from the
  seat's previous job.

`crates/gear-engine/src/review.rs`:

- The review packet carries one line when the re-review cannot resume the
  earlier review's conversation (the recorded action is not `keep` or
  `resume`: S3 held by another pane, a resume fallback, or a new
  conversation): `The earlier review of this task ran in <cli> session
  <session>; its review file is <reviews_dir>/<task>.md. Read it for reference
  if your CLI can.` The review file is the project's `[conventions].voyage_dir`
  reviews folder for the task's milestone; with no milestone it is
  `<task>.md`. When the round has no session recorded, the line names the
  review file only.

## Tests

`crates/gear-engine/src/review.rs`:

- `a_rereview_after_another_task_resumes_the_reviews_own_session`: the seat
  reviews T-1 attempt 1 in session A, then T-2 in session B; T-1 attempt 2's
  review records `resume` with A, not B — including after the seat's previous
  session B is recorded on the re-review's own round and the agent exits: the
  next preparation still starts with `resume` A.
- `a_review_whose_earlier_session_is_gone_starts_fresh_with_the_reference_line`:
  the seat's conversation moved on to B and another pane holds A (S3): the
  re-review starts fresh and its packet carries the line naming `codex session
  A` and `gear/voyages/M5/reviews/T-1.md`.

## Out of scope / noted

- A review round with no session recorded (the reviewer never reported one)
  cannot name a session; its re-review packet then names only the earlier
  review file. Logged as the edge case it is.
- The line is built from the project's review-folder convention; a project
  whose reviews live elsewhere than `<voyage_dir>/reviews` would name the
  convention path. The review packet's own instruction uses the same folder.
