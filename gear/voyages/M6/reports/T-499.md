# T-499 — report (attempt 2)

The re-review of a task resumes the conversation of the review it continues —
the seat's round of attempt n-1 — not whatever conversation its seat had last.
When that session cannot be resumed, the packet carries one line naming it and
the earlier review file.

## F1 — the fix is now active

The two edits the first review found switched off are on, with no
`if false` / `&& true` left in the diff:

- `crates/gear-engine/src/session.rs` `review_facts`: the earlier round is
  `round.role == "review" && round.seat == seat.id && (attempt < 2 ||
  round.attempt == attempt - 1)` — a re-review (attempt n ≥ 2) takes the
  seat's round of attempt n-1, never its latest review round; attempt 1 keeps
  the latest review round of the task on that seat (a retried first review).
- `prepare_review_role`: `if round.is_some() && role == Role::Review &&
  attempt >= 2` sets `facts.open_round_session = facts.earlier_session`, so
  S1 on the open round resumes attempt n-1's session; the guard on
  `round.is_some()` keeps the first preparation on V1's CLI/seat checks.

The recovery line from attempt 1 is unchanged (`review_recovery_line`): when
the action is not `keep`/`resume`, the packet names the CLI and session and
`<voyage_dir>/reviews/<task>.md`.

## F2 — the test now exercises the real shape

`a_rereview_after_another_task_resumes_the_reviews_own_session` was tightened:
after T-1 attempt 1's review in A and T-2's review in B, the re-review's round
opens; the T-2 agent exits and the first resume of A runs to its recorded
`done` state; then the seat's previous session B is put back on the agent, on
the binding and on the re-review's own round, the agent is killed, and the
next preparation must start `resume` with A, never B. The action recorded for
the round must be `resume` with A.

Verified against the unfixed code (the two edits temporarily set back to
`if false && …` / `&& true`, then restored): the test **fails** there at
`the start resumes A` with the start args `resume sess-b` — the seat's latest
job's session — and **passes** with the fix. The recovery-line test
(`a_review_whose_earlier_session_is_gone_starts_fresh_with_the_reference_line`)
still passes: a seat whose attempt-1 session is gone starts fresh and its
packet carries the line.
