# T-487 — report

A pane that holds several captain seats gets one doorbell, not one per
project: the engine joins the items of every seat bound to that pane into one
ring, each line naming its project, urgent first. A project outside its working
hours adds nothing to it; the other projects' rings go on. A single project
rings as it always did.

## What changed

`crates/gear-engine/src/doorbell.rs`:

- `Ring` and `RingSeat`: one ring per pane, its text, the ids it covers, and
  every seat it covers with that seat's own ids.
- `rings(inputs, resting, cooldown_s, now)`: groups the tick's inputs by pane,
  drops the inputs of a resting project, and applies the existing idle,
  at-once, slot and cooldown rules per seat (`may_ring`, the old `rings`).
  One ringing seat gets the old single text (with its goal), so a
  single-project ring is unchanged. Several seats get one text: the item lines
  of each project (urgent projects first), the command line, and each
  project's goal. `decide` stays for callers outside the tick.

`crates/gear-engine/src/ops.rs`:

- `intend_rings`: the ring's own op is recorded under the first ringing seat
  (Intended, typed once by the execute step). Every other seat gets an op of
  its own, already Submitted with the same text, its own ids, the pane and the
  primary op's id: its items are covered (never rung twice) and its slot is
  held without a second prompt. The captain's reminder clock is recorded for
  every seat, as `intend_doorbells` does.

`crates/gear-engine/src/lib.rs`:

- The project loop gathers each project's doorbell inputs at step 9 (after its
  deliveries) instead of deciding and executing per project. After every
  project has run, the rings are built (with `hours::resting` deciding which
  projects add nothing), intended in one transaction, and executed: deliveries
  and the rings' own ops per project, so one prompt goes to a shared pane and
  the other seats' ops are never typed.

## Tests

`crates/gear-engine/tests/it/ring_contract.rs` (new, registered in `main.rs`):

- `two_projects_sharing_a_pane_get_one_ring_naming_both`: two projects' captain
  seats in one pane, one open item each (the second urgent): one prompt, both
  ids, both project lines, the urgent project's line first, one op per seat
  (both Submitted, the ring's own op covering both ids).
- `a_project_off_hours_adds_nothing_while_the_other_rings`: a project whose
  departure passed and whose voyage eta is over adds nothing and gets no ring
  op; the working project still rings (one item).
- `a_single_project_rings_as_today`: one project's ring is the old text.

The existing doorbell, intend, execute and ready-state tests pass unchanged.

for a plain doorbell. An urgent joined ring is therefore typed at once into a
working (or unknown) shared captain agent, as a single project's urgent item

under; another project's ids stay in that seat's own op and in the ring array,

test asserts each op covers only its own project's id.
