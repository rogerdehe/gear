# T-466 — Captain handover

## What changed

- `gear captain handover --facts` (`gear-app::captain::handover_facts`, CLI
  `cmd_captain_handover_facts`) prints the handover template and its part 1
  facts from the store, following `gear/voyages/M6/handover.md` part B: project
  and voyage, goal and done clauses, bar, eta and elapsed, stations and
  releases, staffing (captain, lanes with duty and owned paths, reviewers,
  quota, models), board state (done, in progress, waiting, in review, waiting
  for the captain, reworks queued, lanes), every open inbox item with its text
  and the command that settles it, the plan's applied version and whether the
  file has unapplied or uncommitted edits, the other projects' captains and the
  engine. It also prints the skeleton of parts 2 and 3 (standing orders,
  decisions in flight, fragile things, promises, next three things, lessons,
  files to read first, free notes). It is read-only, starts no engine, and
  works for the previous captain after its generation is stale.
- `gear captain take` now captures the previous binding (pane, CLI, session
  ref), looks for the newest `captain-*.md` under the voyage's `handovers/`,
  and, when none is there, prompts the agent still in the previous captain's
  pane to write the document from `gear captain handover --facts` and commit
  it. It records the request with a 10-minute deadline and puts the pointer in
  the take item: the document's path when one exists, otherwise the previous
  session to read and part 2 to write after the deadline. A pane that lost its
  agent is reported the same way. `--facts` afterwards repeats the pointer
  (document, pending request, or "none after the request — read session …").
- `skills/gear/references/captain.md` says how: write the document from
  `--facts` at `gear/voyages/<M>/handovers/captain-<date>-<time>.md`, commit it
  and hand over; `gear captain take` asks for it and the 10-minute fallback;
  a model switch on the same CLI needs no handover.

## Evidence

- `crates/gear-cli/tests/it/captain_handover_contract.rs` (new):
  - the template prints part 1 (goal, clauses, bar, eta, stations, staffing,
    models, board, open items, plan, engine) and the part 2/3 skeleton;
  - `take` prompts the previous captain's pane, records the request with its
    deadline and session, and its item names the session and the fallback;
  - after the deadline with no document, `--facts` points at the previous
    session and says to write part 2;
  - an existing document is named instead of asking again;
  - a previous pane with no agent is reported and its session named;
  - the command prints the facts, and `--pane` is required without `--facts`;
  - a stale-generation caller still gets the facts.
- `make check CRATE=gear-cli` with `TESTS='test(/captain_handover/)'`: 7/7 pass.
- `make check CRATE=gear-cli`: 191/191 pass.

## Out of scope

  in the checkout and says GEAR records none itself.
- The engine's last restart is shown by the engine lock's mtime; the engine
  writes no start record.

  configured quota.
