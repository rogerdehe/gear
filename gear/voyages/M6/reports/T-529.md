# T-529 — report (attempt 1)

A tick reads the live work, not the whole history (schema v10).

## Store (`crates/gear-store`)

Four reads replace "read everything and filter in Rust":

| read | what it returns | served by |
| --- | --- | --- |
| `tasks_live_of_project` | the tasks that are **not terminal**, and the tasks of a voyage that still has one (`EXISTS` over the same project + milestone) | `tasks_state` (project, state), `tasks_milestone` (project, milestone, state) |
| `open_rounds_of_project` | the rounds with no `end_at` | `rounds_open` (project, end_at) |
| `closed_rounds_with_open_attempt` | the closed rounds whose attempt is still in progress — the ones a parked attempt reopens | `rounds_open` |
| `rounds_to_count` | the ended rounds whose usage was never found, up to the back-off's last mark (T-525) | `rounds_open` |
| `merged_done_tasks` | Done tasks holding an attempt whose merge landed (the dependency rule, T-236) | the attempts primary key, `tasks_state` |

v10: the three indexes in `schema.sql` for a fresh store and in `step_9_to_10`
(`SCHEMA_VERSION` 10, in `STEPS` after `from: 9`) for a store in use —
create-only, no row touched. The module doc lists v10.

## Callers routed

- `gear-engine/src/dispatch.rs` — `ready_tasks_of` reads the live tasks; on a
  store of six voyages (five landed) it no longer reads 528 task rows, and the
  per-Done-task `merged_at` loop (one `attempt_times_of_task` per done task)
  became one `merged_done_tasks` query.
- `gear-board/src/idle.rs` — `work_spans` reads the live tasks. It runs for
  every lane on every tick, through `helping` → `busy::check`.
- `gear-engine/src/rounds.rs` — the bookkeeping reads the open rounds (four
  reads per project per tick became open-only), step 1b reads the closed rounds
  whose attempt is still going, and the usage count reads `rounds_to_count`
  instead of every round the project ever ran. The back-off decision itself
  (T-525) is unchanged; it now only sees the rounds it can still act on.
- `gear-engine/src/rounds.rs` — `holds_job_for`'s direction check reads the open
  rounds.

Same decisions as today: every caller keeps the filter it had — the rounds
bookkeeping still closes what it closed (steps 1, 1a, 1b, 3, 3b), the dispatch
still dispatches what it dispatched, the idle view still counts the same spans.
A finished voyage's tasks are read only where a report asks for them
(`tasks_of_project` stays for the boards, the reports and the CLI).

## Noted

- Two existing tests caught behaviour the first cut of the live reads dropped,
  and both are kept: a landed voyage's Done task is still a **dependency**
  (now `merged_done_tasks`, which reads the whole project), and a **parked
  attempt reopens a closed round** (now `closed_rounds_with_open_attempt`). Both
  are in the report as the reason those two queries exist.
- No new project-wide *attempts* read was added: no per-tick caller reads all
  attempts of a project. The attempt reads are per task (`attempts_of_task`,
  served by the primary key) and per seat (`attempts_seat`, v8); what changed is
  that the tasks they hang off are the live ones.
- Friction: the gear-engine gate is slow here (98 s of tests, several minutes
  per run including the build) and this task needed three full runs — one to
  find what the routing broke, one to confirm the fix, one after the store
  change — which took the task past its 30 minutes.
