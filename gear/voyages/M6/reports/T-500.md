# T-500 — report

The captain picks a task's review model. `review-model: <model>` in a queue
block sends every review of that task — first review and re-review — to that
entry of `[models] review` and its CLI. A task without the field behaves as
today.

## What changed

- `crates/gear-app/src/draft.rs`: the queue block field `review-model:` is
  parsed into `QueueItem::review_model`; an empty value is refused.
- `crates/gear-app/src/plan.rs`: apply stores it as the meta key
  `task_review_model:<project>:<task>` — a block that names one sets it, a
  block without it keeps the model the task has (as `fresh:` is stored). The
  validation refuses a model that is not an entry of `[models] review`,
  naming the entry list, and one equal to the task's lane model, naming the
  lane. `gear plan show` prints `review-model: <model>` back.
- `crates/gear-store/src/lib.rs`: `task_review_model` / `set_task_review_model`
  meta accessors.
- `crates/gear-engine/src/model.rs`: `review_entry_for(config, writer_model,
  wanted)` returns the named entry when it is in the review chain, else the
  T-35 rule (the first entry that differs from the writer's current model).
- `crates/gear-engine/src/review.rs`: the three places that choose a review's
  entry — `start_reviews`, the direction-check start, and `seat_current_model`
  (the model a standby/fallback seat runs) — read the task's
  `task_review_model` and pass it. The seat switches to the entry and its CLI
  through the existing restart path (`restart::advance`), exactly as when the
  chain's choice changes.
- `skills/gear/references/captain.md`: the queue field list gains
  `review-model` with an example in the same sentence.

## Tests

- `crates/gear-app/tests/it/review_model_contract.rs` (new):
  - a NEW block's `review-model:` is stored, `gear plan show` prints it, a
    block without the field keeps it, a block naming another entry sets it;
  - a model outside `[models] review` is refused and the refusal names the
    entry list (`review-a, review-b, review-c`);
  - a model equal to the lane's model is refused, naming the lane;
  - an empty value is refused at parse.
- `crates/gear-engine/src/review.rs`:
  - `a_task_review_model_runs_its_first_review_and_its_re_review`: with
    `review-model: claude-sonnet-5-5` while the chain's first entry is
    `gpt-6.1-sol` (codex), the first review starts the claude CLI with that
    model and the seat records it; after a failed verdict and a rework hand-in
    the re-review's round is opened on the same CLI and model;
  - `a_task_without_a_review_model_takes_the_chains_first_entry`: the same
    project without the field starts codex with `gpt-6.1-sol`.

## Out of scope / noted

- If a task's `review-model` later stops being an entry of `[models] review`
  (the config changed under it), the review falls back to the T-35 rule
  rather than failing; apply is where the name is checked. Logged as the edge
  case it is.
- The field is not cleared when a task is done or cancelled (unlike `fresh:`):
  it describes every review of the task, so it is kept. Logged, no behaviour
  depends on clearing it.
