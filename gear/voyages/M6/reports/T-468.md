# T-468 — report

Dialogs never block a seat. A lane's or a reviewer's blocking screen is closed
in the same tick and the seat is told what to do instead; a captain's dialog
nobody answers is cancelled after ten minutes and the work goes on as it would
have without it. Every agent GEAR starts carries the three editor variables, so
no git command waits in an editor (2026-10-31: review-11's
`git rebase --continue` sat in vim for 59 minutes).

## What changed

`crates/gear-engine/src/dialog.rs` (new):

- `LANE_TEXT`: `Dialogs are not allowed for your role; ask the captain with
  gear send --kind question.` — the text the seat gets.
- `CAPTAIN_CANCEL_S = 600`: the ten minutes a captain's dialog may wait.
- `dialog_keys`: a dialog the seat's profile knows (a CLI startup screen,
  T-457) is answered with the profile's own keys, so the screen it asks about
  is the one it takes; any other blocking screen (a permission prompt, a
  question) is closed with `esc`. A seat whose screen shows a dialog or whose
  agent is `Blocked` is the seat with a dialog.
- `check`: for every lane and reviewer seat, closes the dialog in the same
  tick, types `LANE_TEXT` into the pane and submits it (an `agent.prompt` is
  refused while the agent is `Blocked`, so the text goes in as keystrokes
  after the close), once per spell; a dialog still open 30 s later is closed
  again, but the text is not repeated. For the captain seat it starts the
  ten-minute timer and cancels the dialog when it has passed, without telling
  the seat anything. The timer and the "told" mark live in the store's meta,
  so they survive an engine restart; a screen that no longer shows a dialog
  ends the spell.

`crates/gear-engine/src/lib.rs`:

- `dialog` module registered; `TickReport.dialogs` (the seats whose dialog was
  closed this tick) added.
- The dialog step runs in the per-project tick after the busy interrupt and
  before the blocked-seat watch, so a lane is told at once and the watch still
  reports a seat that stays blocked.

`crates/gear-engine/src/onboard.rs`, `restart.rs`, `review.rs`:

- `EDITOR_ENV` (`export GIT_EDITOR=true; export GIT_SEQUENCE_EDITOR=true;
  export EDITOR=true`) is appended to the environment line of every agent
  GEAR starts — a fresh lane (`plan_onboard`), a lane or reviewer restart
  (`restart::env_command`) and a reviewer start (`review.rs`). The captain's
  agent is started by the user in their own pane, so it keeps the user's
  environment; a seat GEAR starts never opens an editor.

`skills/gear/references/rules/lane.md`, `rules/review.md`: a dialog never
holds a lane or reviewer; the engine closes it, and a decision is asked with
`gear send --kind question`.

`skills/gear/references/captain.md` (step 6): the captain's dialog is the only
one GEAR allows; an unanswered one is cancelled after ten minutes, and a
lane's or reviewer's dialog is never the captain's to answer.

## Tests

`crates/gear-engine/tests/it/dialog_contract.rs` (new module, registered in
`tests/it/main.rs`), with `FakeHerdr` and the codex profile:

- `a_blocked_lane_is_closed_in_the_same_tick_and_told_to_ask_the_captain` —
  one tick: `report.dialogs` names the lane, `esc` goes to its pane, the
  `LANE_TEXT` is typed and its Enter is sent.
- `a_blocked_reviewer_is_closed_too` — the reviewer's dialog is closed and
  told; an idle lane is untouched.
- `a_dialog_that_stays_open_is_closed_again_but_the_text_is_not_repeated` —
  the same tick closes it, ten seconds later nothing, thirty seconds later
  it is closed again; the text was typed once.
- `the_screen_that_closed_starts_a_new_spell` — the seat works again, then a
  new dialog is closed at once and the text is typed again.
- `a_captain_dialog_is_cancelled_after_ten_unanswered_minutes` — the codex
  startup screen on the captain seat: no keys at 0 s and 599 s, the profile's
  keys at 600 s, and nothing typed to the captain.
- `a_captain_dialog_that_is_answered_never_starts_the_clock` — a dialog that
  goes away leaves no timer; a later dialog gets its own ten minutes.
- `the_dialog_step_closes_the_screen_of_a_blocked_seat` — the step alone,
  without the rest of the tick.

`onboard_contract.rs`, `onboard_run_contract.rs` and the onboard unit test
`without_a_model_chain_the_environment_line_stays_as_it_was` now expect
`EDITOR_ENV` in the environment line; the other env assertions use
`starts_with`/`contains` and still hold.

## Out of scope

- The captain's agent keeps the environment of the pane the user started it
  in: `gear captain take` binds an agent that is already running, so the
  three editor variables are not added there. A captain that opens an editor
  is still the user's own `EDITOR`.
- The ten-minute timer is wall-clock on the engine's `now`; a captain dialog
  that is open across a long engine outage is cancelled on the first tick
  after it, not ten minutes after the outage.
- A dialog a CLI shows in a pane whose profile names no dialog (pi, claude,
  opencode today) is closed with `esc`; whether `esc` is the right answer for
  a particular prompt is left to the CLI.
