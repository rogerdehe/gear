# T-484 — report

A pi record with tokens and `cost.total: 0` carries no cost now: it is priced
from the price table, and a model the table does not know is unknown, never
$0.00. GEAR ships a built-in table of official prices, the project's
`[prices]` entries override it, peak windows price a record by its own time,
and an ambiguous override stays unknown.

## What changed

`crates/gear-usage/src/prices.rs` (new) and `crates/gear-usage/src/prices.toml`
(compiled into the binary with `include_str!`):

- `Price`, `Peak`, `PeakWindow`, `Rates`; `parse_window` reads `Mon-Fri
  01:00-04:00` (days and UTC hours); `in_window` prices by the record's own
  UTC weekday and minute; `Price::cost` uses the peak rates inside a window
  and the base (off-peak) rates every other time.
- `model_id` strips the provider prefix and lowercases; `price_for` matches a
  project override on that id first, then the built-in table. A full key that
  names the model exactly (case-insensitively) wins; two different overrides
  for one id make the price ambiguous and unknown (the old bare-id rule).
- The built-in table: `deepseek-v4.1-flash-1017` off-peak/peak cache hit
  0.003/0.006, cache miss 0.15/0.30, output 0.60/1.20;
  `deepseek-v4-pro-0813` 0.022/0.044, 0.66/1.32, 1.98/3.96; peak Mon-Fri
  01:00-04:00 and 06:00-10:00 UTC. The file's comment says Chinese public
  holidays (off-peak all day) are not modelled.

`crates/gear-usage/src/lib.rs`:

- `UsageRecord` carries its own `at`; every reader (pi, Codex, Claude,
  OpenCode) fills it.
- `round_usage`: a CLI cost of 0 with tokens carries no cost; the record is
  priced from the table by its own time. A zero cost with no tokens stays a
  true zero; a record with no tokens and no cost says nothing about cost. A
  real nonzero CLI cost is kept. An unpriced record still makes the round's
  cost unknown.

`crates/gear-app/src/config.rs`: `Price` gains `peak: Option<PeakPrice>` (the
four peak rates and `windows`); validation refuses a non-finite or negative
peak rate, an empty window list, and a window that does not parse.

`crates/gear-engine/src/rounds.rs`: the project's `[prices]` are read through
`gear_app::config::Price` (so the shape and its checks are one place) and
converted to `gear_usage::Price`; the built-in entries are applied by
gear-usage itself, so an empty `[prices]` now prices the DeepSeek fleet.

The Cost tab's columns and labels are unchanged: the cost is simply the cost.

## Tests

`crates/gear-usage/tests/it/price_contract.rs` (new module, 8 tests):

- `a_zero_cost_with_tokens_and_no_price_is_unknown` — 6.1M tokens, cost 0,
  unknown model: cost None, source `none`.
- `a_deepseek_record_is_priced_at_the_off_peak_rate_on_a_saturday` — 0.753.
- `a_deepseek_record_is_priced_at_the_peak_rate_on_a_tuesday_0200_utc` —
  1.506.
- `a_provider_prefixed_differently_cased_model_matches_the_builtin_entry` —
  `hk-dgx-1/DeepSeek-V4.1-Flash-1017` and
  `tokenrhythm/deepseek-v4.1-flash-1017` both price.
- `a_prices_entry_overrides_the_builtin_one` — an override without a peak
  prices the Tuesday record at its base.
- `a_real_nonzero_cli_cost_is_kept`, `a_record_with_no_tokens_and_cost_zero_stays_zero`,
  and `the_builtin_table_carries_the_official_deepseek_prices`.

The engine's `codex_model_switch_prices_each_bare_id_and_rejects_ambiguity`
still holds: two overrides for one id stay unknown.

## Friction

- The task ran past its 45-minute budget: the four acceptance checks spent
  most of their wall time waiting for the build slot, so a run of the same
  code twice (before and after the ambiguity fix) cost about 15 minutes
  more than the code work.

  captain (M-6886) and used the default `cache_write` = the cache-miss rate.
