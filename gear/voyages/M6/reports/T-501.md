# T-501 — report

A seat that fell back on quota returns to the first model of its chain once the
model it left resets, at its next task boundary — never mid-task.

## What changed (`crates/gear-engine`)

`quota.rs`:

- **The record.** When the fallback moves a seat to the next entry, the engine
  records the model it left and that model's reset in the meta
  `engine.fallback.<seat>` = `"<model>|<until>"`. The reset is, in order: the
  quota source's spent window reset + 1 min (a source read of the left model),
  else the reset the screen states (`gear_usage::reset_from_text`) + 1 min,
  else `now + quota_reset_h` hours.
- **The boundary.** `return_from_fallback` runs in the quota step, before
  dispatch, after a switch on its way finishes. It fires only when the record's
  time has passed, the seat is Active/Standby/Retiring, and the seat is at a
  task boundary — every open attempt is handed in (Submitted) or there is none;
  an attempt still Delivered/Started/Stopped/Unknown keeps the seat where it is.
  The return uses the same switch the fallback uses (`change_model`: in place on
  the same CLI with a picker, else the restart with the handover) and emits one
  event line on the seat: `<seat>: back on <model>: quota reset`. The record is
  cleared when the return starts (and when the seat is already on the first
  model).
- **A spent first window.** Before returning, the engine reads the first model's
  own quota source. If it reads that window as still spent, the seat stays on
  the fallback and the record's time moves to the new reset (source reset +
  1 min, else `quota_reset_h`). A source that cannot be read does not hold the
  seat back.
- `source_of` is split so the same lookup works for a model the seat does not
  run on now (`source_for_model`).

`review.rs`:

- A reviewer that fell back keeps the model it fell back to while the model it
  left has not reset: `quota::fallback_review_entry` gives its next job that
  chain entry, so the warm seat is reused on the fallback and T-429 does not
  release it for a model move. After the reset the record is no longer pending,
  the job's entry is the chain's first review model that differs from the
  writer's current model (the rule that a reviewer never runs the writer's
  current model is unchanged), and T-429 releases the warm seat, which starts
  again on that first entry.

## Tests (new, all passing)

- `quota::tests::a_fallen_back_lane_returns_to_its_first_model_at_its_next_task_boundary`
  — a lane falls back at T with no source and no screen reset (record at
  T + `quota_reset_h`); it stays on the fallback before the reset; the reset
  passing while it is mid-task moves nothing; after it hands the task in, the
  next boundary returns it to the first model in place, with the line
  `p:heat: back on minimax-cn/MiniMax-M3.1-Flash: quota reset` and the record
  cleared.
- `quota::tests::a_source_that_still_reads_the_first_model_spent_keeps_the_lane_on_the_fallback`
  — at the boundary a source that reads the first model's window as spent keeps
  the lane on the fallback and moves the record to the new reset; once the
  window is free, the lane returns and the line names the first model.
- `review::tests::a_fallen_back_reviewer_takes_its_next_job_on_the_fallback_until_the_reset`
  — a warm reviewer on the fallback takes its next job on that model before the
  reset (no release); after the reset the next job releases the warm seat and
  starts on the first entry.

## Friction

Past the 55-minute budget: the fallback/reset/boundary design had to be read out
of quota.rs, review.rs and dispatch.rs first (the fallback branch, the source
parking branch, the reviewer release of T-429), and each engine run is about
1.5–4.5 minutes. The first push was also refused because the task branch's
upstream was `origin/dev`; it went as `git push origin HEAD:mast/t501`.

## Out of scope (noticed, not changed)

- A lane that has a quota source for its current provider parks on a spent
  window instead of falling back, so for such a lane the boundary source read
  only matters when the project's sources change; the read is implemented and
  tested (the test adds the source after the fallback).
