# T-465 — report

Switching a seat's agent now carries a handover. A switch to another CLI can
happen at the seat's next safe point, or at once: the outgoing agent is told to
wrap up and commit, the engine waits `[timing].switch_grace_min` (default 10
minutes) and then exits it whether or not it handed in. The incoming agent's
packet starts with the handover — whose work it takes over, the previous
conversation to read first, and the worktree's state (uncommitted changes,
untracked files, unpushed commits, branch, last commit, stash) — and then the
task packet. The handover document follows `gear/voyages/M6/handover.md` part A;
its template ships in the skill.

## What changed

- `crates/gear-app/src/config.rs` — `[timing].switch_grace_min` (default 10)
  and `[timing].switch_at_once` (default false = next safe point). The captain's
  answer (M-6804) confirms this shape: the mode is chosen where the switch is
  asked, and `switch_at_once` is the default.
- `crates/gear-engine/src/handover.rs` (new) — collects the part A facts from
  the store and git (`status --porcelain`, branch, last commit, upstream and
  unpushed commits, stash, session), writes the handover document at
  `<voyage_dir>/handovers/<seat>-<date>-<time>.md`, keeps the outgoing agent's
  parts 2 and 3 when it wrote them, commits only that path on the seat's
  branch, and stores the block for the incoming packet under
  `engine.handover.<seat>` for the new generation.
- `crates/gear-engine/src/restart.rs` — `When::AtOnce`: the wrap-up message goes
  out once, the grace starts, and the stop phase exits past it even while the
  agent is working. A safe-point switch keeps today's wait-for-idle behaviour.
  Every cross-CLI switch writes the handover before the exit keys, including
  the already-gone-agent path. `reconcile_config` passes the configured mode.
  The plan carries `at_once`, `grace_s`, `wrap_at`, `wrapped` and
  `handover_doc`, so an engine restart resumes the same grace.
- `crates/gear-app/src/plan.rs` — `render_task_packet` starts with the stored
  handover block when it is for this generation, task and attempt.
- `crates/gear-engine/src/quota.rs` — a restarted reviewer's packet is the
  handover block followed by its review packet.
- `skills/gear/templates/handover.md` (new) — part A's template, installed with
  the skill and registered in `gear-app/src/skill.rs` and the install contract;
  `skills/gear/SKILL.md` has one line telling a lane to read the handover first.

## Tests

- `crates/gear-engine/src/restart.rs` (module `handover_tests`):
  `an_at_once_switch_waits_the_grace_period_then_exits_even_while_working` — the
  wrap-up prompt and document exist, no exit before `wrap_at + grace`, the exit
  goes at the end of the grace while the agent is still working;
  `the_incoming_packet_starts_with_the_handover_of_a_dirty_tree` — the packet
  starts with the handover, names the dirty and untracked paths, the branch,
  the previous session and the document, and the task packet follows; the
  document has parts 1–3 and is committed on the seat's branch.
- `crates/gear-engine/tests/it/reviewer_quota_contract.rs` — the restarted
  reviewer's packet now starts with the handover, then the review packet.
- `crates/gear-app/tests/it/config_contract.rs` — the default timing carries the
  two new values.

`make check CRATE=gear-engine` passes with the latest `origin/dev` merged in
(880 tests, T-464's in-place same-CLI switch tests included). The whole
`gear-app` suite (596) and the `gear-cli` install-skill tests pass too.

## Out of scope

- Same-CLI model switches stay as T-464 leaves them (no handover); the merge
  keeps its in-place branch beside the restart path.
- There is no per-switch override command yet: the switch is asked through a
  config change, so `switch_at_once` is the only place the mode is chosen.
- A worktree the engine cannot write into (a fake path, an old seat) gets the
  block but no document; this is the edge case outside normal use.
- The check's last result is not recorded by the engine; the handover says so
  and the outgoing agent's summary carries it.
- For a CLI that reports a session file (pi) the session id and the transcript
  path are the same value.
