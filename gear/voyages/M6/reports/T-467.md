# T-467 — report

Reviewer seats now scale elastically. The configured counts still start and
release seats by themselves as work comes and goes, but a seat is released only
after its role's idle time (default 30 minutes), so a re-review finds its
reviewer warm. A count may be raised above the configured one only by a plan
line the user confirmed: it carries the reason and the end condition, the
engine starts up to the raised count while hand-ins wait, and when no hand-in
waits it releases idle extra seats only — never a running review — down to the
configured count, records both changes, and then scales within the configured
counts as before.

## What changed

- `crates/gear-app/src/config.rs` — `[quota].reviewer_release_idle_min` and
  `[quota].lane_release_idle_min` (default 30). The reviewer value is the idle
  time the release sweep uses; the lane value carries the role's own idle time
  (lanes keep their pane, worktree and build cache, as the user's seat model
  says).
- `crates/gear-app/src/draft.rs` — the `# Staff` line
  `- raise reviewers to=8 until=no-hand-ins-wait reason=<text>`; the role is
  `reviewers`, `to` must be positive, the end condition is
  `no-hand-ins-wait`, and the reason is required.
- `crates/gear-app/src/plan.rs` — apply stores the raise under
  `engine.review_raise.<project>` (`from`, `to`, `until`, `reason`, `at`,
  `plan_version`), records it as a `staff` decision, and drops the used line.
  Following the captain's addition (M-6823), a raise is the user's change: it
  is applied only with `--confirmed` and its own
  `- <time> confirmed: reviewers <from> -> <to> until ... | why: ...` line in
  the same apply; otherwise the whole apply is refused and nothing is written.
- `crates/gear-engine/src/release.rs` — the reviewer count in effect is the
  raised count while a raise is active; the release sweep waits for
  `reviewer_release_idle_min` before releasing a standby reviewer; while a
  raise is active the sweep is owned by the raise. When `no-hand-ins-wait`
  holds, the engine releases idle seats above the configured count (never a
  running review), records the return as a `staff` decision, and clears the
  raise once the count is back at the configured one. The ordinary sweep
  resumes on the following tick, as before.
- `crates/gear-engine/src/review.rs` — both the hand-in reviews and the
  direction checks start seats up to the effective count, not the configured
  one.
- Tests: engine `a_raise_starts_reviewers_up_to_the_raised_count`,
  `an_idle_reviewer_waits_its_release_idle_min`,
  `a_raise_returns_to_the_configured_count_without_interrupting_a_review`;
  app `a_raise_is_a_staff_line`, `a_confirmed_raise_is_applied_and_recorded`,
  `a_raise_without_confirmation_writes_nothing`,
  `a_raise_needs_its_own_confirmed_line`,
  `a_raise_is_not_confirmed_by_another_change`,
  `a_raise_below_the_configured_count_is_refused`,
  `the_release_idle_times_are_config`.

With the latest `origin/dev` merged in, `make check CRATE=gear-engine` (883),
the whole `gear-app` suite (610) and the whole `gear-cli` suite (192) pass on
the branch.

## Out of scope

- The raise line names `reviewers` only. Raising lanes needs lane definitions
  in the config; the lane count is already the configured one.
- `[quota].lane_release_idle_min` is carried but no automatic lane release path
  uses it: a lane is released by the plan's `retire`/`release` lines, and it
  keeps its pane, worktree and build cache by design.
- The raise is stored in the store, not written back into the config text.
- The board and home page do not show the raise; the plan's decision log and
  the store hold it.
- After a raise has returned, the ordinary sweep still uses the working lanes
  as its floor, delayed by the idle time, exactly as before.
