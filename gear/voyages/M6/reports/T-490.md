The captain skill covers several projects, and the departure sheet names the
project it departs. No code.

## What changed

`skills/gear/references/captain.md`:

- The opening line is the captain of a GEAR project, or of several from the
  same pane.
- One new paragraph, **Several projects in one pane**: `gear captain take
  <project> [<project>...]` binds each named project's seat and keeps the
  ones already held, `gear captain release <project>` lets one go; every
  project keeps its own kickoff, config, fleet, plan, voyage and departure
  sheet (take a second project only after its own kickoff and confirmed
  sheet, and share nothing but the pane); doorbells name their project
  (`gear reply <project>:M-<n>`), and a command acting on one project takes
  it from the qualified id, the plan header or the caller's own project, an
  unqualified id two projects hold being refused with both qualified ids
  named; when two projects run at once, urgent items first, then the project
  whose station is nearer its eta, with the board's project bar (`p`, `[`,
  `]`) showing each project's state, voyage, station and time against its
  eta.

`skills/gear/references/departure.md`:

- A rule that the sheet's title names the project
  (`Departure: <project> · <voyage id> <title>`), so the user knows which
  project is departing when several run from one pane.
- The form's title line carries the project.
