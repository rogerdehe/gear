# T-525 — report (attempt 1)

An ended round's usage is counted a bounded number of times: the 1/5/30-minute
back-off, the config parsed once per tick, and the Codex rollout lookup that
stops at the first match.

## `crates/gear-engine/src/rounds.rs`

**The back-off.** The old condition re-counted an ended round one minute after
its *last count*, forever, while its `input` stayed `None`:

```rust
if now < end + 60 || round.counted_at.is_some_and(|at| round.input.is_some() || now < at + 60)
```

Now the marks are measured from the round's **end**, not from the last count:

```rust
const UNKNOWN_COUNT_AFTER_END_S: [i64; 3] = [60, 300, 1800];

fn unknown_count_due(end: Ts, counted_at: Option<Ts>) -> Option<Ts> {
    let marks = UNKNOWN_COUNT_AFTER_END_S.map(|delay| end.saturating_add(delay));
    match counted_at {
        None => marks.first().copied(),
        Some(at) => marks.into_iter().find(|due| *due > at),
    }
}
```

The tick counts only when `now >= due`, and `None` means the back-off is spent:
the round is never counted again. It keeps `input = None` — unknown, never 0 —
so a session the reader cannot find stays visibly unknown instead of reading as
a round of no tokens. A round whose usage **was** found (`counted_at` set and
`input` some) is skipped as before: counted once and kept.

On a store of 542 such rounds this takes the `count_round` rate from about nine
a second to three per round for the life of the store.

**The config, once per tick.** `tick` reads the project row once, parses
`config_toml` once, and counts through `count_round_with(store, cfg, config,
round, now)`. `count_round` stays the one-round entry point (`gear-cli`, the
restart path, the tests) and parses the config itself, so its behaviour is
unchanged; `count_round_with` is the only body now, and it no longer re-reads
`get_project` per round.

## `crates/gear-usage/src/lib.rs` — `codex_rollout_path`

The day directories are sorted newest first and the first matching
`rollout-*-<thread>.jsonl` wins, instead of reading every day directory of the
last fortnight to keep the newest. It is the same file: a day directory's day is
its name, so a match in a newer day is a newer rollout than any in an older one.
The direct-path case and the 14-day window are unchanged.

## Tests

`crates/gear-engine/tests/it/rounds_contract.rs`:

- `an_unknown_round_is_counted_three_times_and_then_left_alone` — a round that
  ended at `end` with a session no reader can find: no count before `end+60`,
  one at `end+60` (`counted_at` moves, `input` stays `None`), none between the
  marks (`end+299`), one at `end+300`, none at `end+1799`, one at `end+1800`,
  and then none at `end+1801`, `+2h`, `+1d` and `+30d` — `counted_at` frozen at
  `end+1800`, `input` still `None`. The count is read from `counted_at`, which
  only a count moves (no clock, no fake session needed).
- `a_found_round_is_counted_once_and_kept` — a round whose log is on disk: one
  count at `end+60`, then the later marks (`+300`, `+1800`, `+1d`) change
  neither `input` nor `counted_at`.
- `closed_round_waits_for_late_logs_and_missing_logs_stay_unknown` — the one
  existing test that leaned on the old one-minute re-count: a log written after
  the first count is now picked up at the 5-minute mark (`end+400`) instead of
  `end+220`. Its accounting assertions are unchanged.

`crates/gear-usage/tests/it/codex_rollout_contract.rs`:

- `the_lookup_takes_the_newest_day_that_holds_the_thread` — the same thread in
  yesterday's and today's day directory: the newer file is the one read
  (`input`/`cache_read` of today's count), which is what the old walk kept.

No wall-clock assertion anywhere: every mark is an arithmetic tick time.

## Noted

- The one modified existing test (`closed_round_waits_for_late_logs_and_missing_logs_stay_unknown`)
  asserted a re-count two minutes after the end, which is exactly the unbounded
  behaviour this contract removes; it now waits for the 5-minute mark. Its
  "missing logs stay unknown" half is asserted unchanged in the same test.
- No new storage: the number of counts is derived from `end_at` and
  `counted_at`, both already on the round, so a store written by an older engine
  needs no migration and a round counted long ago (well past `end+1800`) is
  simply left alone.
