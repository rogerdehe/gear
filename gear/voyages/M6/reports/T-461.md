# T-461 — report

A captain can no longer lower the bar alone: every guarded change now needs the
user's word in the same apply — `--confirmed` **and** a `confirmed:` line in
`# Decisions` — and the voyage report shows every such line, every cut and every
done clause with its evidence (M6 S1).

## What changed

- `crates/gear-app/src/plan.rs` — one confirmed path for the goal/done/bar/eta
  (and title/stations) of a departed voyage, the departure of a new milestone
  and a move between milestones: without both `--confirmed` and a valid
  `- <time> confirmed: <what changes, before -> after> | why: <reason>` line in
  the same apply the apply is refused and nothing is written (the refusal is
  inside the apply transaction, so the rollback is the "nothing written"). The
  guard is computed before the queue writes, so a milestone that already
  carried tasks keeps its departure; a first voyage, a reused id or a new
  milestone departs with the confirmation. A cancel line changes the state
  only: milestone, lane, priority, required, deps, estimate, follow-up, issue,
  station, goal, accept, evidence-files, evidence-due and mechanical are
  compared with the stored task and any difference is refused. A cancellation
  is recorded as a cut in the voyage the task is in.
- `crates/gear-app/src/goal.rs` — the captain's goal check: `- done (<n>): met |
  evidence: …` / `- done (<n>): open | <why>` lines, one per done clause, stored
  in the existing `goal-check:<project>:<milestone>` meta (the board reads
  `met`/`text`; the extra `evidence`/`why` fields are for the report). A
  malformed line, a repeated clause or a missing clause is refused.
- `crates/gear-app/src/station.rs` — `station <id>: land` is refused while a
  done clause is open (an absent check means every clause is open, as the board
  reads it) or while cancelled/moved-out tasks exceed 20 % of the departure's
  tasks, unless the same apply is `--confirmed` with a `confirmed:` line that
  names the open clause numbers and/or the cut (the word `cut` or a cut task).
- `crates/gear-app/src/voyage.rs` — the report lists every `confirmed:` line,
  every cancelled or moved task with its decision line, and every done clause
  with its evidence or open reason.
- `crates/gear-app/src/decision.rs` — `confirmed` is a structured decision
  kind.
- `skills/gear/references/captain.md` — one paragraph: these changes are the
  user's, asked in the conversation; the decision line is the record; plus the
  `confirmed` kind and the goal-check lines in the reference.

## Out of scope

- Moving a task from a milestone to no milestone (`milestone=` absent) is not
  treated as "between milestones": it is still allowed without the confirmed
  line, as before. Only a change from one milestone to another is guarded.
- The confirmed line is required to exist, not to name the milestone or task
  for a departure/goal change; only the landing guard checks the naming (the
  packet asks it there explicitly).
- A goal-check line applies to the plan's voyage (its last milestone block or
  the current voyage); a plan that writes checks for another voyage in the same
  apply is not supported.
