# T-453 — report

A delivery now counts as landed only when the agent shows it took it: the
attempt's first check-in, or the agent's idle-to-busy turn after the text was
submitted. The text is typed into an empty composer (a command left in the box
is submitted before the packet follows it), a delivery typed into a working
agent has its window paused while the agent works and starts when it is idle
again, and a delivery that never lands gets one Enter, one resend, then the
captain's item.

## What changed

- `crates/gear-engine/src/composer.rs` (new): T-371's composer test, moved out
  of `ops.rs` so the session steps use the same one — the text's first line
  (40 characters) in the tail's last 6 non-empty lines. The captain's choice
  (M-6520): the last line alone is a status or border line on several CLIs.
- `crates/gear-engine/src/ops.rs`:
  - `note_agent_turns(tx, observed, now)`: every tick records each seat's
    agent status per generation, the first tick of its idle episode and the
    time of its idle-to-busy turn.
  - `shown_delivery` takes the turn as evidence: a turn at or after the
    delivery's submission time lands the op (evidence `turn <seat>/<gen> @
    <ts>`); the submission time is recorded when the op is typed
    (`engine.deliver_submitted.<op>`), so an old intent is not enough.
  - `confirm_pending_with`: a delivery whose seat is Working is not failed
    while the agent works (the text waits in its input queue); its window
    starts when the agent is idle again (the idle episode recorded by the tick),
    and only a delivery typed into a working agent (the `Delivery { working }`
    policy) uses that start — every other delivery keeps the window from its
    intent.
  - `aim`: a delivery whose text already sits in the composer (its Enter was
    lost) is submitted with one Enter instead of being typed again, so a resend
    does not join the text to itself.
  - `resubmit_unsent` (T-371/T-404) uses the shared composer test; unchanged
    otherwise (one Enter, one retype).
- `crates/gear-engine/src/session_runner.rs`: a step that types a session
  command (`/new`, `/compact`, `/quit`, and the fallback exit) confirms its
  Enter took — the command no longer shows in the composer — before the step
  moves on. If the composer still holds it, the step stays at `enter` and
  submits it on a later tick; a command already in the box is submitted, never
  typed twice. The packet therefore never follows `/new` into the same
  composer.
- `crates/gear-engine/src/lib.rs`: the tick records the turns before the
  confirm, and the resubmit (the one Enter) now runs before the confirm, so a
  text the window finds still in the box gets its Enter before the one resend.

## Friction

The task was broader than one module: the four shapes touch the delivery
confirm, the tick, the session steps and the composer test, and the FakeHerdr
needed five tick-level tests. No permission or tool was missing.

## Out of scope (noticed, not changed)

- The busy-agent window pause is bounded only by the agent's working episode:
  an agent that works for hours keeps its queued delivery waiting without a
  captain item. The packet asks for no stall while the text waits; a hard cap
  would be a new number, so none was added.
- The turn evidence is per seat and generation and is not tied to the op's
  text: any turn after a submission lands it. A delivery holds the seat's slot
  (no doorbell or nudge can type in between), so the turn is the delivery's.
- `note_agent_turns` writes two meta keys per seat per tick; the write is in
  one transaction and the cost is the same order as `record_sessions`.
- T-371's composer window is a heuristic: a transcript echo of the text within
  the last 6 non-empty lines counts as "still in the box", and the engine then
  presses one Enter (harmless) instead of retyping. The captain chose this
  window (M-6520).
