# T-497 — report

agy (Antigravity CLI) starts as a lane or a reviewer: a built-in profile, a
skill target, the model start args and kickoff's model list.

## What I checked

- `agy --version` → `1.4.12` (the packet says 1.2.13; this machine has
  1.4.12). `agy --help`: `--dangerously-skip-permissions`, `--model <model>`,
  `--effort low|medium|high|xhigh|max`, `--conversation` (resume by ID),
  `-c/--continue`, `--agent`, `--mode`, `--settings`; **no system-prompt
  flag**, no `--session`; the subcommands `models`, `plugin`, `agents`.
- `agy models` → `<id>\t<name>` lines after `Fetching available models...`
  (gemini-3.8-flash-high/medium/low, claude-sonnet-4-6, claude-opus-4-6-thinking,
  gpt-oss-120b-medium).
- `agy plugin list` → `[]`; `/help` lists `/skills`, `/usage`, `/model`,
  `/effort`, … but **no `/new` and no `/compact`**.
- `agy --print ' /skills'` lists the built-in skills; after
  `gear admin install-skill --agent agy` the list contains `gear`, so agy
  loads global skills from `~/.gemini/antigravity-cli/skills/gear/SKILL.md`
  (also agy's customizations guide: workspace skills under `_agents/skills/`).
- A live start through Herdr (see below): the project-trust dialog, the
  `Generating...` busy screen, `ctrl+c` twice to exit, and
  `herdr agent get` reporting `agent_session` (kind `id`, source
  `herdr:antigravity_cli`) after the first turn — so `session_ref` is true.

## What changed

- `crates/gear-herdr/src/profile.rs`: built-in `agy` — unattended
  `--dangerously-skip-permissions`; resume `--conversation {session}`;
  `session_ref: true`; exit `ctrl+c` twice; the startup trust dialog
  (`Do you trust the contents of this project?`) answered with Enter (the
  preselected "Yes, I trust this folder"); `Quota exhausted` and
  `, retrying in ` markers; `Generating...` busy; `instructions_args` empty;
  `new_session`/`compact` empty (agy has neither slash command). It is in
  `builtins()`.
- `crates/gear-app/src/skill.rs`: `SkillAgent::Agy`, skills root
  `~/.gemini/antigravity-cli/skills`.
- `crates/gear-app/src/kickoff.rs`: `models_of("agy")` runs `agy models` and
  `parse_agy_models` reads the ids; `agy` was already in the installed-kinds
  table.
- `skills/gear/SKILL.md`: the installer line names agy.
- `crates/gear-engine/src/model.rs`: one arm `"agy" => --model <model>`.
  **This is outside the packet's two crates and was asked about (M-7068,
  corrected M-7069):** the profile type has no model/effort field, the model
  flag comes from `model_start(kind, model)` and `start_args` drops the chain
  entry's args for an unknown kind, so without the arm agy would start with
  no model and no `--effort`. The default (add the arm) was taken; the effort
  itself stays the chain entry's `--effort` argument, like pi's `--thinking`.

The role rules reach agy the way GEAR reaches a CLI without a system-prompt
flag: the rules file is rendered as usual, `instructions_args` is empty, and
the rules travel in the seat's packet — the same path grok and opencode take.
