# T-485 — report

One captain pane holds several projects' captain seats. `gear captain take
<project> [<project>...]` binds every named project's captain seat to the
caller's pane and keeps the seats it already holds; `gear captain release
<project>` lets one go while the other seats stay. A command that acts on one
project takes it from a qualified id (`<project>:M-12`, `<project>:T-5>`), the
plan file's header, or the caller's own project; an unqualified id two
projects hold is refused with both qualified ids named.

## What changed

`crates/gear-app/src/captain.rs`:

- `take_all` resolves the caller's pane once, then binds each named project's
  captain seat; `take` keeps its signature and is the one-project wrapper.
- `take_one` keeps a seat the pane already holds (same generation, no new
  item) and rebinds the others as a handover does, with the per-project
  handover request and take item.
- `release` voids the project's binding on the caller's pane and sets the seat
  Released; the pane's other captain seats are untouched.

`crates/gear-app/src/identity.rs`:

- `seats_bound_to` and `captains_on_pane` list the seats one pane holds.
- `env_of_captain` resolves the caller as the captain of a named project: the
  caller's own context when it names that project, else the captain seat of
  that project bound to the caller's pane at that seat's own generation;
  `require_seat` still checks the claim.

`crates/gear-app/src/mail.rs`:

- `split_qualified` and `reply_project`: a qualified reply id names its
  project; an unqualified id is the caller's own project when it has the
  message, else the one project this pane captains that has it; two projects
  holding it are refused with both qualified ids named.
- `reply` resolves the env with `env_of_captain` and looks up the bare ids.
- `send_target`: a qualified `--task <project>:<T-n>` names its project and
  strips the prefix before the receipt and the gate.

`crates/gear-cli/src/main.rs`: `captain take` takes zero or more projects and
prints each; `captain release <project>`; the plan apply resolves the caller
as the captain of the plan header's project before applying.

## Tests
