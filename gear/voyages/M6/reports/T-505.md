# T-505 — report (attempt 1)

A voyage audit is now a queue field: `audit: true`. The task keeps its lane
(for the review-model choice and the writer seat) but its lane never works it;
reviewers check the voyage's promise against the integration branch, and the
captain rules every audit attempt.

## The field

- `crates/gear-app/src/draft.rs`: `QueueItem::audit` with the queue field
  `audit:` — `true` or `false`, anything else refused ("`audit` is `true` or
  `false`, got …").
- `crates/gear-store/src/lib.rs`: `task_audit` / `set_task_audit` on the meta
  key `task_audit:<project>:<task>` (as `task_fresh` is). `false` clears it.
- `crates/gear-app/src/plan.rs`: apply stores the mark for NEW blocks and for
  existing ones (a block without the field keeps it), refuses an audit whose
  block clears the lane ("an audit task keeps its `lane=`"), and
  `gear plan show` prints `audit: true`.

## The engine

- `crates/gear-engine/src/audit.rs` (new, step 6e in the tick, before the
  review step): for every Ready audit of a project whose `deps:` are all
  merged (the `tasks::merged_at` rule), it fetches `<remote>`, reads the tip of
  `<remote>/<integration>` from the tick's repo tips, and writes attempt
  `n = last + 1` as `Submitted` with that sha as the candidate, the lane's seat
  as the writer and the hand-in time now; the task goes `Verifying`, so
  `tasks_to_review` starts its review as for any hand-in. An attempt `n ≥ 2`
  reaches the previous attempt's reviewer through the existing T-480 rule.
- `crates/gear-engine/src/dispatch.rs`: `ready_tasks_of` skips an audit, so it
  is never delivered to its lane.
- `crates/gear-engine/src/review.rs`: `review_packet_for` reads the mark and
  passes it to `review_packet`, which replaces the `Diff to review:` line with
  the audit text ("Audit <task>: no diff. Check the promise in the goal against
  the dev branch at <candidate>, end to end in normal use. For each point of the
  promise say met or not, with the evidence (a command and its output). Every
  gap is a finding, also one outside this audit's slice."). The rest of the
  packet — binding, contract, verdict format, findings and `gear send` — is
  unchanged.

## The verdict

- `crates/gear-app/src/tasks.rs` `settle_review`: a review verdict on an audit
  is not auto-settled; the captain is told and the task stays `Verifying`.
- `settle` (the captain's `# Verdicts` line): a pass sets the attempt Accepted
  and the task Done, and records the attempt's merge time (the candidate it
  checked) with **no merge op**, so dependants start as after a merge; a fail
  sets the attempt Rejected and the task Ready, with no lane rework — the fix
  tasks added to the audit's `deps:` block the next attempt.

## Skills

`skills/gear/references/decompose.md` rule 7 gets the one sentence: an audit
slice is a queue task with `audit: true` whose `deps:` are the tasks it checks;
a gap is ruled by a fail verdict plus fix tasks added to its `deps:`, or a pass
with `why=` for a backlog item. The field is also named in the `# Queue` field
list of `skills/gear/references/captain.md` so the captain can find it.

## Tests

`crates/gear-app/tests/it/audit_contract.rs`: the field stored/shown/kept, the
lane requirement, `true|false` parsing, a captain pass (Done + merged, no merge
op), a captain fail (Ready, attempt Rejected), and a review verdict on an audit
waiting for the captain.

`crates/gear-engine/tests/it/audit_contract.rs` (real git fixture, one origin
on `dev`): the audit is handed in `Submitted` at the integration tip by the
lane's seat and its lane never gets a delivery for it; the packet carries the
audit text and no `Diff to review:`; a captain pass starts the dependant task;
a task without the field is dispatched to its lane as today; a captain fail puts
the audit back on Ready, it waits while the fix task named in its `deps:` in the
same plan apply is unmerged, and then attempt 2 is handed in and re-reviewed on
the same reviewer seat.

## Noted / out of scope

- An audit whose repository or `<remote>/<integration>` cannot be read is
  reported in the tick's `audit_failed` lines and retried next tick; nothing is
  handed in on a guess.
- `audit: false` was added so a captain can take the mark off a task again;
  the packet only names `true`.
- A failed audit keeps the captain's `rework` text in `rework_note`; the audit
  is never dispatched, so it does not reach a lane.
