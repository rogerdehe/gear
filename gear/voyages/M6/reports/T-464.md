# T-464 — report

A lane whose chain head changes model on its own CLI is switched **in place**
through the CLI's own model command at the next idle moment: the agent and its
conversation stay (same pane, same session, same generation), and no restart —
and so no handover — is written. The switch only happens when GEAR drives that
CLI's model picker (OpenCode, T-114); another CLI, a CLI without a picker (pi),
or a change of launch arguments keeps the existing restart path.

## What changed

- `crates/gear-engine/src/restart.rs` (`reconcile_config`): before starting a
  restart for a detected chain-head change, it checks whether the change can be
  made in place: a non-empty model that differs from the model the seat runs,
  the same CLI as the seat's binding, a CLI GEAR switches in place, and launch
  arguments unchanged. In that case it records the durable switch plan
  (`switch::begin`) and stores the applied fingerprint; nothing is restarted.
  A model with no labels anywhere flags the seat (`NeedsCheck`) and is never
  restarted, as the quota path already does.
- `crates/gear-engine/src/switch.rs`:
  - `labels_for` (new, private): the `[models.switch]` entry for a model, else
    OpenCode's catalogue in the seat's worktree (T-94), with the T-307 wording
    when the catalogue cannot be read. `ensure_model` now uses it instead of
    its inline copy.
  - `begin` (new): records the durable in-place switch plan and sends **no
    key**. The tick's switch step (the quota step, which resumes any pending
    plan) takes the first step in the same tick, so a config change never sends
    two submissions in one tick.

The switch itself is the existing state machine: it waits until Herdr reports
the agent idle, re-reads the whole screen before every submission, drives
`esc` → `/model` → the picker filter (or the OpenCode session API for a
session-bound agent), and confirms on the status bar. The existing finish
records the new model, resets the quota counter and sends the lane one
`Continue`.

## Tests

`crates/gear-engine/src/restart.rs` (`in_place_config_tests`):

- `a_chain_head_model_change_on_the_same_cli_switches_in_place` — an OpenCode
  lane on `provider/old` with conversation `ses_lane`, config changed to
  `provider/new` (version 2). While the agent is `Working` no key is sent and
  the plan waits; once idle, the tick drives `/model` and the picker filter
  (`New Provider`), each with its own Enter. Asserted: no `ctrl+c`, no `/quit`,
  no `AgentStart`; binding `session_ref` still `ses_lane`, pane unchanged, seat
  generation 1 and `Active`; `model` meta `provider/new`; no restart plan and
  no switch plan left; a later tick types nothing.
- `a_chain_head_model_change_on_a_cli_without_a_picker_restarts` — the same
  change on a pi lane still starts a restart plan and types no model command
  (T-114).

## Out of scope (noticed, not changed)

- The in-place switch is finished by the quota step, whose captain line still
  says "switched to <model> in place (provider limit)" — the wording is the
  same for a config-driven switch. It is an informational line, not urgent;
  changing the text would touch the quota path the packet did not name.
- A lane without a stored configuration fingerprint gets one restart for its
  first model change (the old behaviour); after that, same-CLI model changes go
  in place. The fingerprint is written by onboarding (T-447) and by the first
  reconciliation.
- A config change that changes both the model and its launch arguments keeps
  the restart path: the running process cannot take new arguments in place.
