# T-456 — report

Every review and direction packet opens with the seat's binding (task, attempt,
current candidate, branch, worktree) and says which kind of job it is; the
reviewer checks pwd, branch and HEAD against it before reading, and a review
packet for any other candidate is refused. A rework round's packet shows the
latest applied rework first, as the text that governs where it differs from the
goal (four cases in M5).

## What changed

`crates/gear-engine/src/review.rs` only.

- `job_packet` (direction) and `review_packet` (review) now open with the seat's
  binding and the job's kind:
  - direction: first line `Direction check of T-1 attempt 1. Binding: task T-1,
    attempt 1, candidate <sha>, branch direction/t-1, worktree <path>.` The
    branch is the reviewer's own `direction/t<n>`, not the lane's task branch
    (the old packet named the lane's branch, which the reviewer does not have
    checked out).
  - review: first line `Review T-1 attempt 1. Binding: task T-1, attempt 1,
    candidate <sha>, branch review/t1, worktree <path>.`
  - both then say how to check it: `pwd` must be the worktree,
    `git rev-parse --abbrev-ref HEAD` must be the branch and
    `git rev-parse HEAD` must be the candidate (M-3899, M-3900).
  - the direction packet keeps only the direction command
    (`gear send --kind result … --direction`): no review verdict and no lane
    result command, and no "You implement" line.
- The worktree path is the seat's real checkout: `start_reviewer` passes the
  path it opened/checked out; the restart paths (`job_for_seat`,
  `recover_missing_packets`) read `engine.review_path.<seat>`.
- `rework_section` (attempt n ≥ 2): the task's latest applied rework
  (`tasks.rework_note`) is rendered above the goal, headed
  `## Rework (attempt n, applied to the round before) — where it differs from
  the goal below, this text governs`. Both the review and the direction packet
  carry it, so a direction check of a rework round judges the applied rework
  rather than the goal it replaced (the four M5 cases T-254, T-271, T-293,
  T-304).
- `review_packet_for` refuses a packet whose candidate is not the attempt's
  stored candidate (`BadFormat`, naming both), so no reviewer reads and judges
  a stale commit after a seat was rebound mid-review (M-3715, T-283).

## Tests

`crates/gear-engine/src/review.rs`, `mod tests`:

- `a_direction_packet_opens_with_its_binding_and_only_the_direction_command`:
  the first line names the direction check and the binding (candidate, branch,
  worktree); the check instruction names pwd/branch/HEAD; the only hand-in
  command is the direction command; no `--candidate`, `--verdict` or
  "You implement".
- `a_rework_packet_shows_the_rework_above_the_goal`: a failed attempt 1 with a
  captain rework, attempt 2 handed in; both the review and the direction
  packet of attempt 2 put the rework text above `Goal:` and mark it as
  governing.
- `a_review_packet_for_a_stale_candidate_is_refused`: a packet rendered at a
  candidate other than the attempt's stored one is `BadFormat`, naming both;
  the stored candidate renders as before.
- `direction_checks_follow_pushes_and_report_results` (existing): its
  direction-packet assertions now expect the binding first line and `Run
  `gear` first` on the next line.

## Question sent to the captain (default taken)

M-6731 asked whether "a hand-in for a stale candidate is refused" means the
packet render (M-3715 wording, implemented and tested) or the reviewer's
verdict hand-in. The default is the packet render; the verdict path stays as it
is (a verdict already names task/attempt, and `settle` refuses a candidate that
differs from the attempt's).
