# T-518 — report

The engine parses a project's config once per config version, not once per
reader: `gear_app::config::parse` (toml_edit) is off the per-tick path.

## What changed

`crates/gear-app/src/config.rs`:

- `ConfigCache` holds, per project, the text it was parsed from and the parsed
  `ProjectConfig` (`Arc`), plus a parse counter. `parse(project, text)` returns
  the cached value when the same text was parsed before, else parses once and
  **replaces** the project's entry — one entry per project, and a changed text
  is parsed again and its value is what comes back. A text that does not parse
  is an error and is not cached.
- `parse_cached(project, text)` runs through a process-wide
  `OnceLock<Mutex<ConfigCache>>`, so every reader in the tick shares it.
- `latest(store, project)` now goes through `parse_cached`, so every `latest`
  caller (hours, rebind, restart, lib's per-project steps, captain quota) is
  served from the cache.
- `ConfigCache` also exposes `parses()`, `len()` and `is_empty()` for the tests.

Per-tick engine call sites routed through `parse_cached`:
`dispatch::ready_tasks_of`, `dispatch::conventions`,
`dispatch::integration_branch`, `attention::period`, `health` (two),
`busy`, `rebind`, `merge::merge_passed`, `parallel` (two), `review` (two:
`start_reviews_with_tips` and its helper), `onboard::onboard_queued`. Test-only
call sites and readers outside the tick keep plain `parse`.

## Tests

`crates/gear-app/src/config.rs`
`config::tests::a_config_text_is_parsed_once_per_project_version`:

- the same project text twice → one parse, and the very same cached value (the
  two `Arc`s are pointer-equal);
- a changed text → parsed again (counter 2), and the new value (a different
  `quota.lanes`) is returned and then served from the cache;
- another project → its own entry, `len() == 2` (one entry per project) and the
  first project still answers with its newest text at no extra parse;
- text that does not parse → an error both times, no entry kept, no cached
  value (the counter does not move).

## Friction

Past the 20-minute budget: the cache has to hand out a value the call sites can
use without a borrow (an `Arc` in the cache, a clone at the edge), and the test
config text needed `repo` and `[captain]` before it parsed; the engine suite on

## Direction check of attempt 1 (M-7394)

The direction check found `crates/gear-engine/src/parallel.rs`'s other-projects
loop calling `parse_cached(project, &row.config_toml)`: it filed another
project's config under the current project's name, overwriting the current
project's entry and forcing a re-parse on the next tick.

Fixed two ways:

- the loop now keys the row it reads (`parse_row`), and
- the row-based readers go through a new
  `config::parse_row(&ProjectRow)`, which takes the key from the row's own
  `id` and the text from its own `config_toml` — a reader that loops over
  projects can no longer name the wrong key. `busy`, `attention`, `health`
  (two), `dispatch` (three), `merge`, `parallel` (two), `review` (two) and
  `rebind` use it; `onboard` keeps `parse_cached(project, text)` because its
  text comes from one snapshot it read for that project.

New test `config::tests::a_row_is_cached_under_its_own_project`: two rows with
different texts are each cached under their own project, `len() == 2`, each
value is its own, and looking the first up again is served from the cache (no
re-parse).

Checks after the fix: `cargo nextest run -p gear-app` 656/656,
`-p gear-engine` 955/955, `cargo fmt --all --check` clean. Candidate a81b8baf +
this fix.

## Rework (attempt 2)

F1 is fixed (the direction check found it first, at 3c81ed1c):
`crates/gear-engine/src/parallel.rs`'s other-projects loop no longer keys a row
by the caller. It goes through `gear_app::config::parse_row(&row)`, which takes
the key from the row's own `id` — for that loop the key is the other project,
as the rework names it — and the text from the row's own `config_toml`, so a
loop over projects cannot name the wrong key at all. Every other row-based
per-tick reader (`busy`, `attention`, `health` ×2, `dispatch` ×3, `merge`,
`parallel`, `review` ×2, `rebind`) uses the same helper; `onboard` keeps
`parse_cached(project, text)` for its own snapshot.

The test the rework asks for: `parallel::tests::a_scan_of_two_projects_keeps_each_projects_config_in_the_cache`
— a store with two projects (`cache-a` with 1 lane, `cache-b` with 2) run
through the scan's `inputs`, then `config::cached("cache-a")` and
`config::cached("cache-b")` both exist and each holds its own value. With the
old keying restored the test fails at "cache-b holds its own entry"; with the
fix it passes. `gear_app::config::cached(project)` is the read accessor the test
needs.
