# T-491 — report

A project on v0.5.x upgrades to v0.6 with no hand step: a store as v0.5.6
wrote it opens on the current binary with no loss of tasks, attempts, seats,
messages or plan versions; its v0.5-shaped gear.toml loads unchanged; one
engine tick and the captain's home page run on it; a second open changes
nothing. No migration step was missing.

## What changed

- `crates/gear-store/tests/it/v056_store.sql` (new fixture): the v0.5.6 schema,
  copied from tag v0.5.6 (`git show v0.5.6:crates/gear-store/src/schema.sql`),
  and the rows of a project whose voyage is in progress: a v0.5-shaped
  `gear.toml` (no `[schedule]`, no `[health]`, no `direction_branch`, no
  switch fields), its captain and lane seats with their bindings, a running
  task with a delivered attempt and its contract, a plan version, a voyage
  with its departure, and an open question to its captain.
- `crates/gear-store/tests/it/upgrade_contract.rs` (new test): applies the
  fixture as a database file, opens it with the current binary, and asserts
  the version is current, the shape equals a fresh current store's, every row
  (voyage, task, attempt, both seats, the open item, the plan version) is
  there, and a second open leaves the version and the rows as they were.
- `crates/gear-engine/tests/it/upgrade_contract.rs` (new test): opens the same
  fixture, checks the v0.5 config loads unchanged (`validate` finds nothing),
  runs one `tick` with a fake Herdr (the fixture's two panes and their agents),
  builds the captain's home page and finds the voyage line and the open item
  on it, then asserts the voyage, the seats (Active), the open item, the task,
  its attempt and the plan version are intact, and that a second open is a
  no-op.
- `crates/gear-engine/Cargo.toml`: `rusqlite` as a dev-dependency (the fixture
  is SQL).

No change to `crates/gear-store/src/migrate.rs` or `schema.sql`: v0.5.6 and
v0.6.2 both stamp schema v7, and the schema files are identical, so the fixture
opens as it is today. The tests are written to keep holding when a later
schema bumps: the version is compared with `SCHEMA_VERSION`, the shape with a
fresh current store, and the rows with the fixture's own values.

The docs already carry the upgrade line: `docs/releases/v0.6.0.md`,
`v0.6.1.md` and `v0.6.2.md` say, under "Upgrading", `gear admin stop`,
`herdr plugin install … --ref vX`, then any `gear` call, "the engine changed,
so the restart matters. Nothing in an existing config has to change" — install
and restart the engine. No note needed changing for this task.
