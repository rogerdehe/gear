# T-483 — a review of a new attempt can push its review

The review of a second attempt now starts with `origin/review/t<n>` at **that**
attempt's candidate, so the reviewer's push of its review commit is a
fast-forward. Before this the remote branch still held the earlier attempt's
review, the new candidate did not descend from it, and the reviewer's push was
refused (T-457 attempt 2). A confirmed merge now deletes the review branch it
merged whatever its tip holds, so a stale review branch left by an earlier
attempt no longer stays on the remote after the task lands.

## What changed

- `crates/gear-engine/src/review.rs` — `prepare_review_tree`: after the
  reviewer's worktree is checked out at the attempt's candidate, the engine
  pushes that branch to the project's remote (`git push --force <remote>
  HEAD:refs/heads/<review branch>`) before the reviewer starts. The earlier
  review is not deleted: the branch is only a pointer, and the earlier attempt's
  review stays in that attempt's record. A direction check (`direction/t<n>`,
  T-456) is **not** pointed: it is the check's own branch, not the task's review
  branch, and the packet never asks its reviewer to push. `direction` is passed
  down through `prepare_seat_tree` for that.
- `crates/gear-engine/src/merge.rs` — `close_branches`: the review branch is
  closed by name after a confirmed merge, not only when its tip is listed by
  `for-each-ref --contains=<candidate>`. A review branch left by an earlier
  attempt does not contain the candidate and was therefore skipped before
  (T-457: `review/t457` stayed on origin after the merge). A branch that is
  already gone is still "closed" (`delete_remote` treats it so). The lane branch
  rules are unchanged.

No other design change: the branch templates, the merge order, the verdict
hand-in and the branch sweep are as they were.

## Tests

- `crates/gear-engine/src/review.rs`,
  `a_second_attempts_review_branch_is_pointed_at_its_candidate`: a real repo
  where attempt 1's review sits on `origin/review/t1` and attempt 2's candidate
  is a commit on `dev` that does not descend from it. After the review start,
  `origin/review/t1` is the new candidate; the reviewer's commit on top of it
  pushes to `refs/heads/review/t1` without a force (a fast-forward), and the
  earlier review commit is still in the repository.
- `crates/gear-engine/src/merge.rs`,
  `a_confirmed_merge_deletes_the_review_branch_of_an_earlier_attempt`: the
  review branch points at a commit cut from `dev` (an earlier attempt's review,
  not an ancestor of the candidate); the merge is confirmed, and neither
  `heat/t5` nor `review/t5` is on the remote afterwards. The result line names
  `review/t5` as closed.
- The existing real-git checkout tests (`direct_checkout_stashes_dirty_worktrees_and_reports_them`,
  `real_git_checkout_uses_the_submitted_commit`, the two mid-merge recovery
  tests) now run the push too; they pass unchanged.

## Acceptance

`make check CRATE=gear-engine TESTS='test(/review_branch|merge/)'` →
rustfmt check clean, 87 tests run, 87 passed.

The whole crate, because the review start now touches the remote in every
review (`cargo nextest run -p gear-engine`) → 869 tests run, 869 passed.

## Out of scope

- Review branches left on origin by merges that happened **before** this change
  stay there: nothing walks the remote to delete them (on the project's own
  remote today: `review/t454`, `review/t461`, `review/t469`). They are inert;
  the captain can delete them by hand.
- The direction branch is not pointed at its candidate (see above). A direction
  check does not push, so nothing needs it; if a later direction check is asked
  to push, the same rule would apply.
- The merge's own "already merged, review branch gone" early return is
  unchanged: there is no review branch left to close in that path.
