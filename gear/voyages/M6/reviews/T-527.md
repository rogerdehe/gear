## Findings
- F1 [P2, logged] The candidate map stores the input expression, not the resolved full commit id — `crates/gear-engine/src/parallel.rs:731` — `commits.insert(candidate.clone(), candidate.clone())` keeps a legacy candidate written as a branch name (pre-T-421) as a *name* in the `ancestor` cache key, so a later pass can reuse a stale ancestry answer after that branch moves. `git cat-file --batch-check` prints the resolved full object name as its first field, not the echoed input (the report's "Noted" says the opposite), so the resolved id is available and ignored. Normal candidates are full 40-hex ids, where input and resolved id are the same, so normal use is unaffected; this is an edge case and is logged, not blocking. Smallest fix: use the resolved name as the value — `commits.insert(candidate.clone(), fields[0].to_string());` (one line).

## Set aside
