## Findings
- F1 [P0, blocking] The direction-closed notice is inserted into the store but never delivered to the working reviewer. Reproduction (full `tick`, FakeHerdr): (a) a Temp reviewer whose check closed and whose seat was freed — `Standby`, `task_id = None` — gets no prompt; (b) the same reviewer reassigned to the review of the task, with a Submitted review `Deliver` op holding the seat's slot, also gets no prompt. Cause: `finish_direction_results` writes the notice with `task: Some(task.id)` and then, in the same transaction, sets the seat `Standby` and clears its task — `crates/gear-engine/src/review.rs:669-674`; `message_belongs` for a Temp seat returns `message.task == seat.task_id` — `crates/gear-app/src/seats.rs:176-177`, so the freed seat never matches the notice; and when the seat is reassigned in the handed-in case, the review delivery holds the seat's slot and `rings` returns false on `slot_busy` before it ever considers at-once items — `crates/gear-engine/src/doorbell.rs:190`, `crates/gear-engine/src/lib.rs:1435`. This breaks the contract's own v2 exception: the engine must interrupt the reviewer (its interrupt key) and deliver this notice so it ends its turn at once. The added tests do not catch it: `the_direction_closed_notice_cuts_a_working_reviewers_turn_first` calls `execute_intended` with a hand-made doorbell op, and `a_notice_waits_for_idle_except_the_direction_closed_one` tests only the pure `reaches_while_working`; neither runs the tick path that builds the op. Fix: deliver the notice through the at-once interrupt path before the seat's task is cleared (collect the closed-check notices in `finish_direction_results` and have its caller `start_reviews_with_tips`, which holds `herdr`, interrupt + prompt the pane the way `deliver_doorbell_now`/`check_op` do), or exempt this one notice from both the `message_belongs` Temp task-match and the `slot_busy` gate in `doorbell_inputs`/`rings`. Add a full-tick test that closes a check under a Working reviewer and asserts the escape precedes the notice text in its pane.
- F2 [P2, logged] `ends_direction_check` recognises the notice by the body prefix `"The direction check of "` — `crates/gear-engine/src/doorbell.rs:125` — while `crates/gear-engine/src/review.rs:668` builds the actual body with the same words independently; the two are not linked, so a reword of the notice silently disables the interrupt path. Suggest one shared constant for the body/prefix and a test that fails if they drift.
