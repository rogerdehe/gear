## Findings
- F1 [P2, logged] Extra scope beyond the packet's "no other design": the board was changed (`crates/gear-board/src/voyage.rs`, `crates/gear-board/tests/it/depart_contract.rs`, `crates/gear-board/Cargo.toml`) though the packet names only `crates/gear-app/src/config.rs`, the engine's use of them, and one time-zone crate. The change is correct, tests pass, and it prevents a real inconsistency (the board would keep showing the machine's clock for a tz project), so it is not an error in normal use and does not block; the captain should confirm keeping it or revert these three files.
- F2 [P2, logged] The engine's working-hours notice still renders the end/start on the machine's clock, not the project's zone — `crates/gear-engine/src/hours.rs:243` (`let end_clock = gear_board::idle::clock(end);`) and `:250`/`:312` (`gear_board::idle::clock(start)`). For a project whose `tz` differs from the machine's, the notice says "Working hours end at {machine-local HH:MM}", which is a different wall clock than the configured hours (e.g. hours end 18:00 Asia/Shanghai but the notice says 10:00 on a UTC machine). The actual rest/deliver behaviour is correct, so this is misleading, not broken; the board's "off hours until" line was updated to the project clock but this message was not. Smallest fix if the captain wants it: in `notice()`, format `end`/`start` with the schedule's zone (a zone-aware clock like the board's `clock_in`, fed from `config.schedule.tz`), about 5–10 lines.
