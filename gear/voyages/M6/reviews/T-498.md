## Findings
- F1 [P1, blocking] The model is never read, so the acceptance "its tokens and model are read" is unmet — `crates/gear-usage/src/lib.rs:1013` reads `value.get("model")` from a transcript that carries no model field, and `crates/gear-usage/tests/it/agy_jsonl_contract.rs:77` asserts the model is `None`. The cost then depends on the engine's `default_model` (the round's plan model), not the model agy actually used, and a cross-CLI round prices an agy session with no model at all. Fix: read the model id from where the writer already found it — open `~/.gemini/antigravity-cli/conversations/<session>.db` read-only (as `opencode_db` opens its db) and extract the model id from the protobuf blob (the writer reports it appears as the plain string `gemini-3.8-flash`), then set `UsageRecord.model` from it in the `UsageLog::AgyJsonl` arm and change the test to assert the model is read instead of `None`. ~20-30 lines.
- F2 [P3, logged] `crates/gear-usage/src/lib.rs:240` — `agy_record` requires `input_tokens` to be present, so a MODEL record that carries other token fields (`output_tokens`, `cache_*`, `thinking_tokens`) but no `input_tokens` is dropped entirely instead of contributing its tokens. Not seen in the fixtures (their MODEL records always have `input_tokens`); an edge case.
- F3 [P3, logged] `crates/gear-usage/src/lib.rs:198` — a readable transcript whose MODEL records carry no token fields (agy 1.2.x records, which the report says carry none) yields `Some(0)` records rather than `None` (unknown), contrary to the "never 0" clause. Outside normal use here: the machine runs agy 1.4.12, which writes the counts, and this matches every other reader's readable-but-empty behaviour.
