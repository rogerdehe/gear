## Findings
- F1 [P2, logged] reasoning tokens count as "tokens" for the zero-cost rule but are not priced — `crates/gear-usage/src/prices.rs:161` (`Price::cost` sums input/output/cache_read/cache_write only) while `crates/gear-usage/src/lib.rs:1092` includes `u.reasoning` in `tokens`. pi reports `usage.reasoning` separately from `usage.output`, and DeepSeek V4.x are reasoning models, so the Cost tab under-reports cost for this fleet. This is pre-existing (the old code priced only the four categories) and the contract names only cache hit / cache miss / output, so it does not block; if the captain wants reasoning billed at the output rate, the smallest fix is one line in `Price::cost` (add `usage.reasoning as f64 * rates.output`).
- F2 [P3, logged] a record with no tokens and no CLI cost leaves the round "unknown" rather than $0.00 — `crates/gear-usage/src/lib.rs:1095` (`None if tokens == 0 => continue` skips the record entirely, so a round of only empty records ends `cost_source: "none"`). The acceptance only requires "no tokens and cost 0 stays 0", which works; the empty-cost case is an edge case and the writer documents it ("says nothing about cost").
- F3 [P3, logged] the built-in table is parsed with `expect`/`panic!` — `crates/gear-usage/src/prices.rs:220-225`. A bad window in the compiled-in TOML would abort at runtime; the contract test `the_builtin_table_carries_the_official_deepseek_prices` exercises `builtin()`, so a hand-edited table is caught in CI. Acceptable for a constant resource.
