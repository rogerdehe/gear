## Findings
- F1 [P3, logged] Two parked rounds whose waits clear in the same tick can both reopen, leaving one seat with two live rounds — `crates/gear-engine/src/rounds.rs` step 1b (around lines 56–105). The reopen loop iterates a snapshot of `rounds`, so after it reopens the first parked round (end_at → NULL in the DB), the second iteration still reads the first round's snapshot `end_at` as `Some` and does not count it as `busy_elsewhere`; it then reopens the second round too. Both reopened rounds start at the same `now`, so the seat's single session of resumed work is accounted into two open rounds until one closes. Reachable only by a lane that chained two distinct blocked waits (e.g. two external waits or two dependency waits) and has both clear in the same tick while it is not busy on another task — a stacked coincidence, so it is logged, not blocking. Smallest fix if wanted: after `tx.reopen_round`, re-read the round's `end_at` (or re-read `open_round_of_seat`) and stop the loop for that seat, or guard the reopen with a per-seat "already reopened this tick" set (~2–4 lines).
