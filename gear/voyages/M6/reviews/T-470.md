## Findings
- F1 [P2, logged] the `enter` phase now short-circuits on `left_idle`, so a Working agent moves the step to `wait_action`/`wait_exit` without pressing Enter — `crates/gear-engine/src/session_runner.rs:495`. This drops the invariant the pre-existing test `a_refused_enter_stays_at_enter_and_goes_on_a_later_call_while_working` (`crates/gear-engine/src/session.rs:1160`) was written to pin: "a busy agent does not hold the Enter" — the Enter is still pressed when the agent is Working, because the text is already in the box. That test now passes only because its assertion (`calls` contains any Enter) is too weak to distinguish the refused Enter from a fresh one. The new test `an_enter_the_agent_left_idle_is_confirmed_in_the_same_call` asserts the opposite (no Enter when Working), and the state does not record *why* the step reached `enter`, so the two scenarios ("Working because the command was submitted" vs "Working because the earlier Enter was refused and the agent went busy") are indistinguishable. In the second scenario a command genuinely left in the composer is treated as submitted and the packet is later typed after it (the exact T-453 failure the composer check exists to prevent). I rate it P2, not P1, because the wrong path needs a refused Enter (`agent_blocked` maps to `Blocked`, not `Working`) followed by the agent independently going Working — an edge case — while the common stale-screen case (Enter succeeded, agent slow to show Working) is handled correctly. Suggested smallest fix (2 lines), if the captain wants it now: make `left_idle` relax the confirmation instead of skipping the Enter —
  `let took = enter(herdr, &binding.pane_id) && { herdr.type_settle(); !composer_holds(herdr, &binding.pane_id, command) || left_idle(herdr, &binding.pane_id) };`
  — and reconcile the two tests (update `an_enter_the_agent_left_idle_is_confirmed_in_the_same_call`, which currently asserts the regressed behaviour).
- F2 [P2, logged] the acceptance asks for a probe summary "before and after, from a real voyage's log"; the "after" is a replay/projection, not a real run of the new build — `gear/voyages/M6/reports/T-470.md` (the after table and the "Out of scope" note).
