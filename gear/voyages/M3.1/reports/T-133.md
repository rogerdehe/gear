# T-133 — a held lane can be released from the plan (attempt 2)

Scope: T-133 rework — F1 only: `- release <lane>` now asks the **session** which
agents are really running before it picks its target, instead of trusting a
store binding an exited agent leaves `Active`; a session that cannot be read
refuses the release rather than guessing.

Branch: mast/t133 (code @ the hand-in commit; origin/dev merged before
verification)

## Rework (F1)

`- release <lane>` is unchanged in what it means: a Held lane goes back to the
state the engine continues or onboards from — `Active` while its agent is there,
`Queued` when it is gone, so the engine onboards it again. What changed is where
"is the agent there" comes from.

- `crates/gear-cli/src/main.rs` (`run_plan`) — when the draft has a release line,
  the session's agents are read **once**, before the write transaction (Herdr is
  never touched inside one), and passed into the apply. A read that fails refuses
  the apply with `BAD_FORMAT`: "cannot read the session's agents, so `- release`
  cannot tell whether a lane's agent is still running: … — nothing was applied".
  A draft without a release line reads nothing (every other apply is unchanged).
- `crates/gear-app/src/plan.rs` — `apply` and `apply_queue` take
  `agents: Option<&[gear_herdr::AgentInfo]>`; `release_lane` picks `Active` only
  when the seat's current **active** binding sits on a pane that holds an agent
  of the binding's kind. No agent in that pane, or no active binding at all →
  `Queued`. `agents == None` (a caller that did not read the session) is refused
  per line: "cannot tell whether seat …'s agent is still running: the session's
  agents were not read, so the release is refused and the lane stays held". The
  store keeps its job (the pane, and whether the binding is still live); the
  session answers the one fact it owns.
- `crates/gear-herdr/src/fake.rs` — `FakeHerdr::agents_fail`: the session cannot
  list its agents while single-pane reads still answer, so the CLI's refusal is
  testable.
- Every other `plan::apply` caller now passes `None` (tests, the engine's
  remerge) — one line each, no behaviour change: none of them applies release
  lines.
