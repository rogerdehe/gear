# T-125 — a lane registered again reuses its home worktree

Scope: T-125 — onboarding a lane once more (a retired lane registered again, or
a restart) finds the worktree the lane already has and **opens** it; it creates
one only when there is none. The trial case: a lane's worktree exists at its
home path but its checkout is on the task branch it last worked, so Herdr's
home-branch lookup finds nothing and `worktree create` collided with the
existing path ("already exists"), leaving the seat in `needs_check`.

Branch: `hull/t125`; the candidate named in the hand-in carries this report.
Base: `origin/dev` merged into the branch before the hand-in (never rebased).

## The cause

A lane's home worktree is long-lived: retiring the lane closes its pane and
keeps the worktree, and the lane's checkout normally sits on the task branch it
last worked (`hull/t117`), not on `home/hull`. Onboarding looked it up with
`worktree open --branch home/<lane>` — Herdr's registry names a worktree by the
branch its checkout holds, so that lookup misses — and then called
`worktree create`, which refuses because the path
`<herdr worktrees>/<project>/home-<lane>` already exists. The refusal parked the
seat.

## The change

Onboarding tries, in order, and stops at the first hit (`onboard.rs`, the
worktree step):

1. **the lane's own recorded path** — the engine stores the path it made for
   the lane (`engine.worktree_path.<seat>`) when it first onboards it, and the
   record outlives retirement (same seat, same name). `worktree open --path`
   reopens exactly that worktree, whatever branch its checkout holds;
2. **its home branch** — for a lane whose checkout is still there, and for a
   stale record (the worktree was removed by hand: `worktree open --path`
   answers `worktree_not_found`);
3. **create** — only a lane that has neither.

So a lane that has a worktree is always opened, never created; the "already
exists" collision cannot happen for a lane GEAR onboarded itself.

Why not `herdr worktree list`: the list is a new call the engine's Herdr door
(`HerdrRead`/`HerdrAct`) does not have — it lives in `gear-herdr`, another
lane's crate — and it is not needed for the case the task is about: the path a
lane's worktree lives at is recorded by the engine at creation, and the record
survives the retirement that precedes a re-registration. The one case the list
would add — a worktree at the right path that GEAR never recorded (made by hand)
— is left as it is: the seat parks with the create's reason, which names the
collision, instead of guessing a path.
