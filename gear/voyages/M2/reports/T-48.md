# T-48 — released install and first plan apply

Contract v1, attempt 1. Tested 2026-10-23 on macOS arm64 with Herdr 0.9.1.

## Result

The actual GitHub tag `v0.1.0` (source commit `acdfc796002227514aeddc60b221b2f5182c1aa5`) installed through `herdr plugin install rogerdehe/gear --ref v0.1.0 --yes`, without cargo or rustc on PATH. Its downloaded binary registered a scratch project, installed its skills, and applied its embedded captain guide's first plan: version 1, T-1 and T-2. No locally built binary was substituted. Independent release checksum verification and byte comparison passed.

README changes pin the tested release, explain noninteractive approval and source fallback, show the kickoff inventory instead of redirecting it away, install the existing skill before starting its agent, remove stale local-link/pre-release assertions, and explain the live captain check. No plugin change was needed.

## Isolation and limits

All test state is under `/tmp/gear-t48-isolated` (`/private/tmp` is the same macOS directory). Subprocesses removed inherited HERDR_*, GEAR_*, XDG_*, CARGO_* and RUSTUP_* variables. HOME was set only for those subprocesses to `/tmp/gear-t48-isolated/home`; HERDR_CONFIG_PATH points at that home's `.config/herdr/config.toml`. Initial PATH was `/tmp/gear-t48-isolated/bin:/usr/bin:/bin:/usr/sbin:/sbin`. That bin contained links to the real Herdr binary and, for kickoff/startup, the real Claude binary. No Rust tools or fake agent executables were added. The successful plugin install preceded adding Claude. The installed plugin's bin was added using the README command.

A headless named test session was started with `herdr --session t48 server` under that environment. Its socket was `/tmp/gear-t48-isolated/home/.config/herdr/sessions/t48/herdr.sock`. A workspace was created explicitly in the scratch repo; the returned captain pane was `w1:p1`. Test calls then used that socket and pane, with the isolated default GEAR database. No live Herdr control calls were made, except read-only plugin inventory for preservation evidence.

The real Claude CLI started and Herdr recognized its kind. It remained at its first-run theme setup; no setup dialogs were answered, credentials copied, or model turns requested. The final plan command ran from a subprocess carrying `GEAR_CTX=acme:captain:1` and the returned pane ID while that real agent occupied the configured pane. This exercises the release's actual engine and seat validation; it does not claim an authenticated model independently wrote or applied the plan. The plan was copied from the released binary's `gear --skill captain`, changing only `lane=engine` to the configured `lane=lane-1`. A FASTEST-style bar was retained from that sample. Testing ends at the first apply; task execution, reviews, Linux/Intel, and board keypresses are outside this run.

The original unfilled kickoff skeleton was preserved in the transcript below. For registration its TODOs were filled with project `acme`, session `t48`, repo `/tmp/gear-t48-isolated/repo`, captain pane `w1:p1`, Claude profiles, lane `lane-1` owning `src/` with duty `Build the isolated onboarding fixture`, models `claude-haiku-4-5` / `claude-sonnet-5-5`, and quota policy `wait` for both roles. These are fixture choices, not a claim that the unconfigured CLI's provider models were queried.
