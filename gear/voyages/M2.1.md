# Goal
GEAR runs a project made of several git repositories — child repos cloned into a parent, side-by-side repos, a monorepo — the same way it runs a single repo: each lane works in one repo, and that repo's own integration branch and gate carry its reviews and merges. A single-repo project runs exactly as before.

# Milestone M2.1: Multi-repo projects
done: a project with a [[repos]] entry runs a lane bound to a child repo through development, review and merge on that repo's own integration branch and gate; a config without [[repos]] behaves exactly as before
bar: FASTEST (user's choice): block only what breaks the chain or loses data (a merge into the wrong repo, a gate run in the wrong repo); log the rest, at most one rework round
eta: 1h

## T-52 [now] lane=config milestone=M2.1 required
goal: The config describes the project's repos. In gear-app `config.rs`: a top-level `[[repos]]` array, each `{ name, path, integration, release, gate }` — `name` matches `[a-z][a-z0-9-]*`, `path` is relative to `project.repo` (not absolute, no `..`), and `integration`, `release`, `gate` are optional and default to `[conventions]`'s. `LaneSection` gets `repo: Option<String>` (a `[[repos]]` name; none = the project root). Add `pub struct Repo { pub name: String, pub path: String, pub integration: String, pub release: String, pub gate: String }` (`name` is "" for the root, `path` absolute = `project.repo` joined with the entry's path) and `impl ProjectConfig { pub fn root_repo(&self) -> Repo; pub fn repo_of_lane(&self, lane: &str) -> Repo }` (an unknown lane or a lane without `repo` → the root). `validate` adds: repo names unique; a lane's `repo` names a `[[repos]]` entry; each repo's gate not empty and without TODO, its integration and release non-empty and different; lane `owns` overlap is checked only between lanes of the same repo. This is the API the engine task (next) builds on; keep the names exactly.
accept: Unit tests: defaults from [conventions], path joining, repo_of_lane for a bound, an unbound and an unknown lane, and each new validation issue. A config without [[repos]] parses and validates exactly as before (existing tests pass unchanged). `cargo test --workspace` passes.
