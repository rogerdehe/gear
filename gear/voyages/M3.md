# Goal
GEAR goes into a project and a team that already run, fits how they work, and then runs the whole voyage by itself: nobody patches the store, branches or panes by hand, every agent in every role is watched over, GEAR writes only where the project allows, and a team on GitHub sees and joins the work there.

# Milestone M3: Fit in, and run without hands
done: (1) on our own fixture projects (a parent repo with cloned child repos; a project with its own CI and docs) a voyage runs from kickoff to landing with no hand fix — no store edit, no branch repointing, no pane closing, no engine restart by the captain; (2) a push to any destination the project did not register is refused and rings the captain, in a test and live; (3) a quota stop, a provider back-off and a start-up dialog are recognised and handled for Claude Code, Codex, OpenCode and Grok, each in the role it runs in; (4) on a GitHub sandbox repo, issues become tasks, a lane's task opens a draft claim PR with an ORCHESTRATE marker, hand-in and verdict appear on the PR, the merge closes the issue; (5) `gear --skill adopt` exists as a skeleton and the project standard it produces travels in every task and review packet
bar: (chosen by the user at kickoff)
eta: (chosen by the user at kickoff)

# Decisions
- 2026-10-25 Goal aligned with the user before any work: fit into running projects and teams, then run without hands.
- 2026-10-25 GitHub: neither graft BMAD-Team's skills (a manual, human-confirmed pipeline that fights GEAR's no-approval run) nor rebuild it locally (its value is state everyone sees on GitHub). GEAR gets its own forge layer: an engine interface with GitHub as the first implementation, plus `gear --skill github`. The mode is per project (and per repo) in the config; without it the project is local-only, as today. GEAR's plan and store stay the one source of truth; GitHub is the entry and the window. Markers follow BMAD-Team's `ORCHESTRATE:*` protocol so teams using it can read GEAR's PRs.
- 2026-10-25 The engine performs every GitHub write itself (deterministic, retried, bounded); agents never call `gh` to write. `gh` writes cannot be hooked like `git push`: the skill forbids them for agents, and says so plainly.
- 2026-10-25 Adopting an existing project starts as a skeleton (user): `gear --skill adopt` with the analysis steps and two templates (`gear/adopt.md`, `gear/standard.md`); the only code is that the engine puts the project standard into every packet. The user tries it on MarinaAI with its agents; it grows from that feedback. Mechanism: quarantine the auto-loaded instruction layer (CLAUDE.md, AGENTS.md, .claude/skills, .agents) behind a short new project file, name exemplars and no-go patterns, a trusted gate, keep/replace/drop of the existing process.
- 2026-10-25 Push allow-list (trial G12): `init` freezes each repo's resolved push destinations; every GEAR worktree runs a GEAR pre-push check (chained to the repo's own hook) that refuses anything else; the engine checks before its merge push; a refusal is one captain alert, never retried or routed around. Test git isolation already shipped in v0.2.4.
- 2026-10-25 Acceptance uses our own fixtures and a GitHub sandbox repo, never a trial user's project. Trial feedback is input: a chain-breaking report jumps the queue, the rest is ranked by value.
- 2026-10-25 Taken from the first trial's feedback: G01–G04, G08–G12 and parts of G05/G06 (the triage with reasons is in ops/plan/m3-backlog.md). Not taken: G05's agent-order cause, G06's home-branch slip (fixed by installing the skill), G07, G12's audit extras.
- 2026-10-25 Lanes (proposal for the sheet): steady = crates/gear-engine/; reach = crates/gear-herdr/ and the new crates/gear-forge/; course = gear-model, gear-store, gear-app, gear-board; base = gear-cli, skills/, docs/, README, scripts. Shared interfaces are written into both tasks' goals; nothing waits on a neighbour (decompose rule 3).
- 2026-10-25 The last task of the voyage is the skill review by subtraction against M3's lessons, then the release (ops/CONVENTIONS.md).
