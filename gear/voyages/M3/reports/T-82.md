# T-82 — A NeedsCheck seat can be retried, and the home page says why

Attempt 1, contract v1.

Branch: `course/t82`; the candidate named in the hand-in includes this
report. Base: `origin/dev` merged into the branch before the hand-in.

## What shipped

**The way back from a parked seat (trial G02, G04).** The plan's `# Staff`
gained one line:

```markdown
# Staff
- retry heat
```

A lane in **NeedsCheck** or **Unknown** goes back to **Queued** with the
reason `retried by the captain`, so the engine onboards it again — no store
edit. Any other state is refused with `BAD_TRANSITION` naming the seat and the
two states ("only a lane in NeedsCheck or Unknown is retried"); a lane that is
already Queued is a no-op (a target, not a command, like the other staff
lines); an unknown seat or a non-lane seat is a `BAD_FORMAT` line error.
`gear_model` gained exactly the two transitions this needs (`NeedsCheck →
Queued`, `Unknown → Queued`), with the reason written next to them.

**The home page says why a seat is down.** `gear_board::LaneBoard` carries a
`DownSeat` for a seat that is not running (Active, Standby, Starting and
Queued are running or about to be): its state in words, the reason the seat
recorded, and the plan line that acts on it. `lane_line` — the line both the
board and the captain's home snapshot print — reads, for example:

```
runtime · needs check: agent_start: refused (agent_pane_busy) · no current task · 1 queued
```

and for a NeedsCheck/Unknown seat it ends with `- retry runtime`; a parked or
held seat shows its state and reason without a `retry` (the retry would be a
transition it cannot make). A running lane keeps `agent <state>` exactly as
before: nothing changed for healthy seats.

## Acceptance evidence

- `plan_staff_contract::retry_puts_a_parked_lane_back_in_the_queue`:
  a lane set to NeedsCheck with a step reason → `- retry heat` applies
  (`staffed: ["retry heat"]`) and the seat is Queued with reason
  `retried by the captain`; `- retry` on an Active lane → **`BadTransition`**
  naming `p:wire`, nothing written; an Unknown lane → Queued; a queued lane →
  the no-op; an unknown seat and the captain → `BadFormat`.
- `board_contract::a_needs_check_lane_says_why_and_how_to_retry_it`: the
  NeedsCheck lane's line starts `runtime · needs check: `, contains the
  reason (`agent_pane_busy`) and `- retry runtime`, and never says
  `agent unknown`; a running lane keeps `agent <state>` and gains no action.
- The existing staff (park/hold/retire) and board tests are unchanged and
  pass.

## Out of scope

- Un-parking a `Parked`/`Held` lane from the plan: those seats were set by a
  staff line with an `until=`; the retry line deliberately covers only the
  states a failed onboarding or a lost pane leaves (NeedsCheck, Unknown). A
  parked lane is where the captain put it.
- The kickoff/plan validator's list of staff verbs: it names the verbs in its
  usage text; `retry` travels with `remerge` (T-92) as the second action line
  and is documented in the draft's parser.
- Showing the same detail for temp (reviewer) seats: the home snapshot lists
  lanes; a temp's state is on `gear board`'s temps line.
