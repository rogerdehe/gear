  were fetched and the planned ones filtered afterwards, so issue #1 could never
  be reached while #31..#2 were planned. One bounded call still returns them
  all; the comment says why the limit is not left to the default.

  review asked for: a fake `gh` that *behaves like the real one* — without
  `--limit` it answers the default first page, with it every issue — and 31
  open issues where #31..#2 are already in the voyage file and #1 is not. The
  test asserts #1 is printed and that the query asked for a limit. Red on the
  old code ("the older unplanned issue is missing"), green with the fix.
