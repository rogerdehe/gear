# T-67 — An empty OpenCode model list means "not loaded yet"

Attempt 1, contract v1.

Branch: `course/t67`; the candidate named in the hand-in includes this
report. Base: `origin/dev` merged into the branch before the hand-in.

## What shipped

Trial G01: a fresh worktree's `model.list` is empty while OpenCode's service
has not read that directory yet, and the start treated that as "invalid
OpenCode model — absent from model.list", parked the lane and never started
it. Now an empty catalogue is its own answer.

`crates/gear-engine/src/opencode.rs`: `target` returns a `Lookup`, not an
error string:

- `Target(value)` — the model (and the variant, when asked) is in the list;
- `NotLoaded` — the directory's list is **empty**: not loaded yet;
- `Invalid(reason)` — the list is there and does not hold the model/variant:
  a configuration fault (never a reason to pick another model);
- `Unavailable` — the service did not answer: the typed-key path's job, as
  before.

`start_args` waits for a `NotLoaded` list **for that same directory** —
`EngineCfg.model_list_wait_s` (default **60 s**), looking again every
`model_list_poll_ms` (default 500 ms), so the tests do not sleep — and starts
the lane once the list is there. Past the wait it fails with

```
the OpenCode model list is not loaded for <directory> after 60s: the model
<model> is neither valid nor invalid yet, start the lane again when OpenCode
has listed it
```

which parks the seat in NeedsCheck with the directory in the reason. Nothing
picks another model or provider on the way: `Invalid` returns an error, and
`Unavailable` keeps the existing typed-key fallback, which does not either.

The switch path (`switch.rs`) maps the same lookups: an `Invalid` list fails
the switch (a config fault), `NotLoaded`/`Unavailable` use the typed-key
fallback, so a switch never silently chose a different model either.

## Acceptance evidence

- `onboard::tests::an_empty_model_list_is_waited_for`: the first `model.list`
  for the directory answers `[]`, the second holds the model → the lane starts
  (`Active`, `--session ses_waited`), the two looks name the **same
  directory**, and no typed model key was sent.
- `onboard::tests::a_model_absent_from_a_loaded_list_parks_the_lane`: a
  loaded list without the model → NeedsCheck with
  `invalid OpenCode model … absent from model.list`, and no agent started.
- `onboard::tests::a_model_list_that_stays_empty_parks_the_lane`: still empty
  when the wait runs out → NeedsCheck with `model list is not loaded` and the
  worktree's directory in the reason, no agent started.
- The existing OpenCode start/switch tests keep passing (the API path, the
  session-before-TUI order, the typed fallback on a service error, the
  invalid-variant fault).

## Out of scope

- The journal/timing of OpenCode's own catalogue loading: the wait is a
  bounded look-and-retry, not a subscription; 60 s is the kickoff's number and
  the config can change it.
- The other kinds' start paths: only OpenCode has a service catalogue.
- Restarting a lane that parked for a model list that never loaded: the
  captain's `retry` (a plan `# Staff` line, T-82) is the way back; this task
  names the directory in the reason so the retry is informed.
