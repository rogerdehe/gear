# T-95 — A busy shell at an agent's start is retried on later ticks

Attempt 1, contract v1.

Branch: `course/t95`; the candidate named in the hand-in includes this report.
Base: `origin/dev` merged into the branch before the hand-in.

## The change

The in-tick wait is gone. Onboarding no longer sleeps 20 s for a slow shell
(T-89); a shell that refuses `agent_start` with `agent_pane_busy` now leaves the
seat **Starting** with its start pending, and the next tick tries once more.

- `crates/gear-engine/src/start.rs` (new): `PendingStart` — pane, generation,
  agent name, kind, the *rendered* start arguments and the number of busy
  refusals — kept in the store's meta (`engine.start.<seat>`), so it is durable
  and survives an engine restart.
- `onboard_seat` tries `agent_start` exactly once per tick. On a busy refusal
  `wait_for_shell` counts it: within the bound the record is stored and the tick
  returns (the seat stays Starting); at the bound the seat parks **NeedsCheck**
  with `agent_start: refused (agent_pane_busy): the shell was still busy after
  <n> ticks (the environment line has not finished)`.
- `resume_busy_start` is the later ticks: it re-reads the pending start, checks
  it still belongs to the seat's own binding (same pane, same generation), and
  calls `agent_start` with the stored arguments. It never opens or creates the
  worktree, never calls `begin_onboard` and never re-runs the environment line.
  A pending start whose binding moved is not retried elsewhere — the seat parks
  with the mismatch named, because a start on another pane is a human's call.
- After a successful start the model gate and `finish_onboard` run as before;
  the pending start and the seat's Active state are written in one transaction,
  so a crash never leaves a start pending on an Active seat. A `NeedsCheck`
  park clears the pending start too, and a fresh `begin_onboard` (a seat the
  captain queued again) clears a stale one: a pending start belongs to exactly
  one generation.
- `EngineCfg`: `pane_busy_limit_s` + `pane_busy_wait_ms` are replaced by
  **`pane_busy_ticks`** (default `start::MAX_TICKS` = 20). One tick is one
  attempt, so the bound is ticks, not seconds — a slow tick does not shorten the
  wait and a fast one does not lengthen it. No config-file key existed for the
  old fields, so no user-facing config changes.
- The tick is never held: the other queued lanes are onboarded in the same
  tick, behind the waiting one.

The reviewer (temp) path already worked this way (`Started::NotYet` + a pending
start record); the lane path now matches it.

## Acceptance

All three in `crates/gear-engine/src/onboard.rs`'s tests, with `FakeHerdr`:

- `a_shell_busy_for_three_ticks_then_free_starts_the_lane`: busy, busy, busy,
  free → `Starting, Starting, Starting, Active`; the pending record keeps the
  same pane and generation across the three ticks; one `PaneRun`, four
  `AgentStart` calls, one `WorktreeCreate`; `started_agents == ["toy-heat"]`.
- `a_shell_busy_past_the_bound_parks_the_seat` (bound 3): two `Starting` ticks,
  the third parks `NeedsCheck` with `still busy after 3 ticks`; nothing pending,
  no agent started.
- `a_second_queued_lane_onboards_while_the_first_waits`: in **one** tick the
  first lane (id order) is refused and stays Starting while the second lane
  becomes Active; the next tick starts the first. Proves the in-tick wait is
  gone.
- `a_busy_shell_at_start_is_retried`: one refusal → Starting with tries 1 and
  generation 1, then Active on the next tick; the two `AgentStart` calls name
  the same agent, pane and arguments; the environment line and the worktree are
  each done once.
- `start.rs` unit tests: the record round-trips, and a damaged record (no pane)
  or non-JSON is treated as no pending start rather than a start on a pane
  nobody checked.

## Notes / out of scope

- The live case (multi-api: three lanes on a slow shell, one went `NeedsCheck`
  after the 20 s wait) is covered by the per-tick tests; the acceptance here is
  a `FakeHerdr` one, as the task asks.
- A pending start whose seat has no binding any more, or whose binding moved to
  another pane/generation, parks with the mismatch named — never started on
  another pane.
- A config change during the wait keeps the start's own arguments (same
  binding); the model gate still checks the *current* chain, which is the model
  the lane must run on.
- Reviewer starts (`review.rs`) already retried per tick before this task and
  are unchanged.
