# T-93 — Cancelling a task from the plan finishes it

Attempt 1, contract v1.

Branch: `course/t93`; the candidate named in the hand-in includes this
report. Base: `origin/dev` merged into the branch before the hand-in.

## What shipped

`state: cancelled` on a task now **finishes** it. In `crates/gear-app/src/plan.rs`:

- every open attempt of the task becomes **Abandoned** — a delivered prompt,
  a started or stopped one, a handed-in result, and one whose outcome the
  engine could not read (that one is stopped first, then abandoned: the model
  keeps `Unknown → Abandoned` closed, and the engine never guesses an
  outcome; a cancelled task does not guess either, it just stops wanting it);
  so no attempt holds the lane and the engine can deliver its next task;
- the task's lane gets **one line**, as an Instruction to its seat:
  `T-n is cancelled; stop work on it, nothing to hand in` — once, in the same
  transaction as the cancel, and only when something was actually open (an
  idle task needs no line);
- a plan that keeps saying `state: cancelled` for a cancelled task is a
  **no-op, not an error** (M3: the same line failed three times). A task that
  is `done` or `failed` is still refused, naming it — a finished task is not
  cancelled after the fact.

The model gained the two transitions the cancel needs — `Delivered →
Abandoned` and `Submitted → Abandoned` — with the reason written next to
them: whatever the attempt did, the task is cancelled, so nothing of it will
be handed in or merged.

## Acceptance evidence

- `cancel_contract::cancelling_a_started_task_abandons_its_attempt_and_tells_the_lane`:
  a started attempt → Cancelled + Abandoned, `in_progress_attempts_of_seat`
  empty, and one Instruction to `p:heat` with exactly
  `T-1 is cancelled; stop work on it, nothing to hand in`.
- `cancel_contract::re_applying_the_same_cancel_is_a_no_op`: the same plan
  line applies again (`Ok`, the next plan version), the task stays Cancelled
  and there is still one line.
- `cancel_contract::a_handed_in_or_delivered_attempt_is_abandoned_as_well` and
  `an_unknown_attempt_is_closed_too` (the stop-then-abandon path).
- `cancel_contract::a_finished_task_cannot_be_cancelled_and_an_idle_one_gets_no_line`:
  a Done task is refused with its id; cancelling a task nobody was running
  writes the state and no message.
- `cancel_tick_contract::a_cancelled_task_frees_the_lane_and_the_next_task_is_delivered`
  (gear-engine, real tick with the fake Herdr): the lane is on T-1; the plan
  cancels T-1; the next tick delivers T-2 to that lane (its attempt is
  Delivered) — the M3 symptom, gone.

## Out of scope

- Killing the agent's current turn: the line tells the lane to stop, and the
  next delivery is a new task; a cancel does not type into the agent (the
  seat's own turn ends at its safe point, as design/06 says).
- Undoing what a cancelled task's branch may have pushed: the branch is left
  as it is; nothing merges it.
- A review already running on the cancelled attempt: the engine's existing
  obsolete-review path closes it (the task is terminal), unchanged.
