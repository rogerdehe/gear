## Rework

**F1 [P0, blocking] — a bracketed IPv6 host is one host.** `split` cut the
authority at its first colon, so `ssh://git@[2001:db8::1]/team/repo.git` and
`ssh://git@[2001:db8::2]/team/repo.git` both normalised to `[2001/team/repo`
and the second host passed the allow-list. The authority is now read through
its closing bracket — a port after it is not the host — in the scheme form and
in the scp form (`git@[2001:db8::1]:team/repo`), and a bracket that is never
closed names no destination at all (`normalise` → `None`, so the check
refuses). Hostnames and ports keep their behaviour:
`ssh://git@github.com:22/owner/repo` is still `github.com/owner/repo`.

**F2 [P2, logged; the captain reworked it with F1] — a Unicode path no
longer panics.** `clean_path` sliced the last four bytes for a `.git` suffix;
a path ending in a multi-byte character (any CJK path) starts that slice
inside a character and panicked. The suffix is now read through `str::get`,
which returns `None` on a non-boundary and leaves the path whole; a `/.git`
suffix also drops the slash before it, so the two spellings of one path
normalise alike.

Regression tests for both:

- `push::tests::an_ipv6_host_is_kept_whole`: the whole host, a port after the
  bracket, the scp form, case folding, two hosts of one path differing, an
  unclosed bracket.
- `push_contract::two_ipv6_hosts_of_one_path_are_two_destinations`: the
  reviewer's reproduction end to end — a real repo whose pushurl is
  `ssh://git@[2001:db8::1]/team/repo.git`; `init` freezes
  `[2001:db8::1]/team/repo`; the registered host passes (any port, either
  form) and `ssh://git@[2001:db8::2]/team/repo.git` is refused with its own
  destination named in the refusal.
- `push::tests::a_unicode_path_does_not_panic` and
  `push_contract::a_unicode_destination_is_frozen_and_checked`: a CJK path
  through `normalise`, `init` and `check`.

## What shipped (attempt 1, unchanged)

`gear admin init` reads, for the project root and every `[[repos]]` entry,
the destinations the repo's own `origin` remote resolves to —
`git remote get-url --push --all origin`, after git's own
`url.*.insteadOf` / `url.*.pushInsteadOf` rewrites — normalises them as
host + path and stores them, and reads them again on every init. Git runs
before the transaction, so the store is never held while a subprocess runs,
and the destinations are written with the registration.

`gear_app::push::check(store, project, repo, url) -> Result<(), Refusal>`
answers the one question a push asks. `repo` is the `[[repos]]` name, or `""`
for the project root (a repo's own path is accepted too); `url` is the
destination as git resolved it. A refusal names the repo and the normalised
destination and says why: an unknown repo, a repo with no destination, a
destination that is not registered, a project that is not registered, or a
store that cannot be read.

The destinations live in a `push_destinations` table (the store's schema
version moved to 3; the step from 2 creates it and keeps every row).
`InitResult` carries the frozen destinations, so `gear admin init --json`
shows where the project may push.

The API the other lanes call: steady's T-72 (`gear_app::push::check` before
the engine's merge push, with `git remote get-url --push origin`) and base's
T-74 (`gear push-check`, with the hook's `$2`).
