# T-74 — `gear push-check`, the pre-push hook's command

Scope: T-74 — the command a git pre-push hook runs (trial G12): resolve the
project from `GEAR_CTX` and the repo from the working directory, ask
`gear_app::push::check` whether the destination is registered, allow the push,
or refuse it with one urgent captain item and exit 1. Outside a GEAR seat it
allows the push and touches nothing.

Branch: base/t74 (code @ the hand-in commit; origin/dev d1f53e7 merged after
T-73 and T-61 landed, gate green on the merged result)

Files:
- `crates/gear-cli/src/main.rs` — the `push-check` subcommand and its helpers.
  The repo is found through git: the worktree's common git dir is the main
  repository's `.git`, and its parent is compared (canonicalised) with the
  project's root repo (`""`) and with every `[[repos]]` entry (its name) from
  the config the store holds. `run_push_check` is the tested body; the command
  starts no engine and, outside a seat, opens no store. A refusal prints
  `ERROR FORBIDDEN: <the refusal> (git push <remote> was not sent)` on stderr,
  stores one urgent item for the captain and exits 1 (exit code 1 is what
  `ErrorCode::Forbidden` gives). One refusal path covers both "the repo cannot
  be resolved" and "the destination is not registered": to the pusher they are
  the same event, and the captain hears about both.
- `crates/gear-cli/src/main.rs` (tests) — five unit tests: a registered
  destination is allowed and says nothing; an unregistered one is refused,
  names the destination and leaves exactly one urgent item; outside a seat the
  push is allowed; without Herdr the item is still stored; a worktree of a
  `[[repos]]` entry resolves to the child repo and checks the child's own
  destinations.
- `crates/gear-cli/tests/it/push_check_contract.rs` — the contract as a child
  process, the way the hook runs: allowed → exit 0 with empty stderr and an
  empty captain inbox; refused → exit 1 with the refusal on stderr and one
  urgent item; no `GEAR_CTX` → exit 0 and no store file created.
- `crates/gear-cli/tests/it/main.rs` — the new test module.
- `README.md` — the command table names the hook's command.
- `ops/reports/T-74.md` — this brief.

Decisions worth the captain's eye:
- The refusal is one **urgent question** through the `gear send` path, not a
  new message kind. `MsgKind` has no `alert` (gear-model is course's path), so
  the plan's "kind alert" became the one existing kind that reaches the
  captain as an open, ringing item. A real `alert` kind is a small follow-up
  in course's lane if you want the word in the store.
- The repo key is the `[[repos]]` name, `""` for the root — the identifier the
  config, the engine's worktree labels and `push::check` already use.
- When the seat's identity cannot be proven (no Herdr, or a stale binding) the
  item is stored directly in `push:<seat>` instead of the send path, so a
  refused push always rings the captain. The push is refused either way; this
  only decides whether the captain hears about it.
- Live, the production store has no `push_destinations` table yet (it is at
  schema v2; the running engine is the older binary), and a table alone is not
  enough: the destinations are frozen by `gear admin init`. Until the captain
  re-inits the project, every push from a GEAR worktree (once T-72's hook is
  installed) is refused — the safe side, but it stalls pushes until the
  re-init. That re-init is a user/captain action, not a lane's.
