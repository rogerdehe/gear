# T-110 (attempt 3) — an upgrade guide in the v0.3.0 release notes

Scope: T-110 — `docs/releases/v0.3.0.md` gets an upgrade guide in three cases
(user, 2026-10-26); the README links to it. Attempt 1 was failed on F1 and F2;
attempt 2 on F1 (one merge line does not prove quiet across repositories) and
F5 (tail hides older lines). This attempt fixes those; F2, F3 and F4 stand as
reviewed.

Branch: base/t110 (code @ the hand-in commit; origin/dev merged before
verification, gate green on the merged result)

What changed:
- `docs/releases/v0.3.0.md` — `## Upgrading`, three cases, one short line per
  step with copyable commands:
  - **New to GEAR** — the README's install section, then start a project.
  - **From 0.2.x, with no voyage running** — run the stop and the skill install
    in your own shell (F3: a seat is refused them); `gear admin stop`; replace
    the binary (`herdr plugin install rogerdehe/gear --ref v0.3.0` — its build
    step fetches the release binary or builds it — or, from a checkout,
    `git pull && cargo build --release && herdr plugin link .`); install the
    skill for every CLI in use; restart the agents; `gear` once migrates the
    store up and starts the engine again, and a newer store is refused with
    `SCHEMA_TOO_NEW`.
  - **During a running voyage** — wait until every task seen passing has ended
    (a `merged:` line in the engine log, or a merge-failed item; F1), then stop
    (own shell), replace, install skills, and start the engine again with any
    `gear` call; lanes and reviewers keep their tasks, and each agent picks up
    the new skill when restarted between tasks.
  - **What changes on upgrade** — the push allow-list and its pre-push hooks are
    gone (a hook left behind is removed when that seat comes online); a seat
    sees only its own messages; an agent's claim is checked against its real
    pane.
- `README.md` — after the install list, one line: "Upgrading from 0.2.x?" with
  the link to `docs/releases/v0.3.0.md#upgrading` and the three cases named.
- `ops/reports/T-110.md` — this brief, corrected where attempt 1's claims were
  wrong.

The review's findings:
- **F1 (blocking), fixed in round 3.** The page cannot show a merge: a passing
  task is marked `Done` by `settle_review` (`crates/gear-app/src/tasks.rs`), its
  merge then runs as a background worker (`crates/gear-engine/src/merge.rs`),
  and the board only shows `Running`, `Waiting` or `Verifying`
  (`crates/gear-board/src/lib.rs`). Round 2 still failed because one line does
  not prove global quiet: the engine runs a worker **per repository**
  (`worker_key(project, repo)`, `merge.rs`) and collects the workers one at a
  time in the order they finish, so a slow gate in one repo can still be
  running while a later pass merges in another. The guide now waits for **every
  task seen passing, in any repo** — and any that passes while waiting — to
  have ended (a `merged: ["…"]` line, or a merge-failed item) and says to look
  again immediately before stopping.
- **F1 evidence from this voyage's own store:** the page really is ahead of the
  merge. T-109 was settled (`Done`) at 01:31:05Z and merged at 01:37:42Z (its
  log line at 01:37:43Z); T-106 was settled at 01:07:45Z and merged at
  01:32:41Z. The log line format is the live one:
  `2026-10-26T01:37:43Z tick: … merged: ["T-109 @ base/t109"] …`.
- **F5 (logged), done.** `tail -f` shows only the last ten lines, so an older
  merge line would never appear; the guide uses
  `tail -n +1 -f ~/.local/state/gear/engine.log` and names the log's place next
  to the store.
- **F2 (blocking), fixed.** `<checkout>` was shell redirection; the line is now
  `git pull && cargo build --release && herdr plugin link .`, corrected the
  same way here. `herdr plugin link --help` shows `link [OPTIONS] <PATH>`, so
  `.` is the right argument, and `zsh -n -c 'git pull && cargo build --release
  && herdr plugin link .'` parses.
- **F3 (logged), done.** One line before the numbered steps: the stop and the
  skill install run in the user's own shell, because a seat is refused them
  (`cmd_admin_stop` and `cmd_admin_install_skill` reject a caller with seat
  context); the running-voyage step repeats "(your own shell)". Verified from a
  shell with no seat identity: `gear admin stop` on a scratch store prints
  `engine not running` (exit 0), and `gear admin install-skill --agent
  {claude,codex,opencode,grok}` writes into a scratch `HOME` for all four. From
  this seat both are `FORBIDDEN`, which is why the guide addresses the user.
- **F4 (logged), resolved on dev.** The 14 gear-engine failures the review met
  were the T-106-before-T-107 window: the T-72 pre-push hook (removed by T-107)
  still ran `gear push-check`, which T-106 had deleted, so every test merge
  push was refused. T-107 has since landed; this branch now passes the suite.
