# T-675 — a hand-in outside the lane's files is flagged, never refused

## What changed
- `crates/gear-app/src/base.rs`: added `changed_files(worktree, base, candidate)` — `git -C <worktree> diff
  --name-only <base>...<candidate>`, the non-empty lines; `None` on any git failure.
- `crates/gear-app/src/config.rs`: added `owns_path(owns, path)` — true for an entry equal to the path, a
  directory entry ending in `/` that the path is under, or a path starting with `<entry>/`.
- `crates/gear-app/src/mail.rs` `send_inner`: `outside` is declared before the hand-in gate. Right after
  `require_pushed`, when the project config has a lane with that name and non-empty `owns`, the candidate's
  changed files against `refs/remotes/<remote>/<integration>` are filtered by `owns_path`; any left give
  `outside = Some("outside lane <lane>'s files: <paths>")`. In the transaction, a `MsgKind::Result` body gets
  that line appended. Nothing is refused; no config, no `owns`, or a git that cannot tell → no line.

## Tests
- `crates/gear-app/tests/it/base_gate.rs`: `a_hand_in_outside_the_lanes_files_is_flagged` (body
  `Report: ops/reports/T-1.md\noutside lane heat's files: heat-t1.txt`),
  `a_hand_in_inside_the_lanes_files_is_not_flagged` (owns `heat-t1.txt` → plain body), and
  `a_current_candidate_is_accepted` now asserts the plain body.
- `crates/gear-app/src/config.rs` `mod tests`: `owns_path_matches_on_a_boundary`.
