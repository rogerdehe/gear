# T-683 — `gear issue file` / `gear issue show`: the captain files a bug through the engine

## What changed (`crates/gear-cli/src/main.rs`)
- `Cmd::Issue { op: IssueOp }` with the doc line `Captain: file an issue on the project's forge (the engine
  files it).`; `IssueOp::File { title, body, labels }` and `IssueOp::Show { id }`.
- Dispatch in `run` next to the `Cmd::Plan` arms; `Cmd::Issue` is in the no-engine list (`starts_engine`
  false), like `plan import-issues`.
- `run_issue_file`: the caller check and GitHub-mode check as `run_import_issues`, with `gear issue file`
  named in the messages; then one `store.write` reading `forge.issue_requests.<project>` (absent → `[]`,
  unparseable → BadFormat `the issue requests of <project> do not parse`), `id` = highest + 1, pushing
  `{"id","title","body","labels","number":null}` and writing it back. Returns `(id, repo)`.
- `cmd_issue_file` prints `issue request <id> recorded: the engine files it on <repo> and records its number;
  \`gear issue show <id>\` shows it.`, or `{"id":…,"repo":…}` with `--json`.
- `run_issue_show` / `cmd_issue_show`: captain or any registered seat of the project, read-only; prints
  `issue request <id>: filed as #<number>` or `issue request <id>: waiting for the engine`; an unknown id is
  NoTarget `no issue request <id> in project <project>`. The CLI never runs `gh`.

## Check
The packet's acceptance is empty. I smoke-tested the real binary against a scratch store: `issue file`
records the request (meta holds the array), `issue show` reports it waiting, an unknown id is NO_TARGET, a
lane's `issue file` is FORBIDDEN, and `--json` prints `{"id":2,"repo":"rogerdehe/gear"}`. Then the crate's
capped check: `make check CRATE=gear-cli` — 206/206 passed.

## Out of scope
- The engine's filing (T-664) is unchanged; it fills `number` in on its tick.
- `gear issue show --json` prints `{"id":…,"line":…}`; the packet names no JSON shape for `show`.
