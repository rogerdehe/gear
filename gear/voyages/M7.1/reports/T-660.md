# T-660 — a merge waiting on a carried task whose own merge failed names the way out

Candidate: 3d2bba66 (branch hull/t660)

## What changed (crates/gear-engine/src/merge.rs only)

- `tell_captain_waiting` now reads, in one `store.read`, each blocked task's
  latest merge op (greatest `(created, id number)` over
  `ops_of_kind_in_states(project, OpKind::Merge, &[])`) and keeps the blocked
  tasks whose last op is `OpState::Failed`.
- For each such task `X`, after the existing "has not passed" line, the body
  gains `\n{X}'s own merge failed; it cannot land by itself: cancel it (its work
  lands with {C}) or set \`carried-by: {C}\` on {X}.` with `C` the waiting task.
- The early return inside the write now requires both `unpassed` and the failed
  list to be empty. The once-per-attempt key, thread and open-item body update
  are unchanged.
