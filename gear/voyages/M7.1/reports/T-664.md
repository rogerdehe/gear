# T-664 — the engine files a captain's issue request once, retries a failure, and records the number

Candidate: 55702dc3 (branch hull/t664; T-663's `create_issue` merged in from
origin/hull/t663)

## What changed (crates/gear-forge/src/sync.rs only)

- `What::Issue { repo, title, body, labels }` added: `name()` is `"issue"`,
  `act` calls `forge.create_issue(...)` and returns the number as a string.
- Private `IssueRequest` (`Deserialize, Serialize`) with `id`, `title`, `body`,
  optional `labels`, optional `number`.
- `sync_with` reads `forge.issue_requests.<project>` and the project root's
  `[github]` repo; a missing/unparseable key or no GitHub mode means no
  requests. The early return now also requires `requests.is_empty()`.
- After the label call and before the intake, each request with no number is
  filed in id order through `run_call` with key/task `issue:<id>`:
  `Done` → parse the number, record it in one write (re-reading the key,
  setting that id's number, writing the array back) and push
  `<project>:issue:<id>`; `Already` → take the number from the confirmed op's
  result and record it, pushing nothing; `Pending` → nothing.
- New `record_issue_number` helper for the one-write update.

## Tests (mod tests)

- `an_issue_request_is_filed_once_and_its_number_recorded`: one request, tick
  returns `["p:issue:1"]`, the Recorder filed
  `issue owner/name A bug | steps | bug`, the key holds `number: 42`, a second
  tick returns nothing and files nothing.
- `a_failed_issue_request_is_retried`: a refused call leaves no number and
  returns nothing; the next tick files it and records 42.
- `a_project_without_github_files_no_request`: nothing filed, key unchanged.
- The existing sync tests pass unchanged.
