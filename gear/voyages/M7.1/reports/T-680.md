# T-680 — the idle view keeps the work span of a task finished within HELP_LIMIT_S

Candidate: 8a378279 (branch hull/t680)

## What changed

- `crates/gear-store/src/lib.rs`: new `tasks_finished_since(project, since)` next
  to `tasks_live_of_project`, selecting done/failed/cancelled tasks with
  `updated >= since` in rank, id order, with the packet's doc comment.
- `crates/gear-board/src/idle.rs`: `work_spans` takes `now`, reads the live
  tasks, then appends the tasks finished since `now - HELP_LIMIT_S` that are not
  already seen (a `BTreeSet<String>`); `helping` passes its `now`. The T-529
  comment carries the packet's added line.
- The span's end now takes the earliest of hand-in, merge and settle, and falls
  back to the attempt row's time only when no step wrote one — the doc comment
  already said "when no step wrote one", and the acceptance needs the span to
  end at the hand-in (see Deviations).

## Deviations (asked the captain, default taken)

The packet says the loop body stays as it is, but with the acceptance's Accepted
attempt (row `updated` = T0) the min-of-all end is T0, so the instruction at
T0+60 is not covered and the test fails. I made the row time a fallback used
only when no step wrote an end, which is what the existing comment describes.
