# T-665 — the engine carries out `- restart <lane>` through its at-once restart path

Candidate: 71ef01bd (branch hull/t665)

## What changed

- `crates/gear-engine/src/restart.rs`: new `pub fn restart_lanes(...)`. For each
  Lane seat in `Active` with a non-empty `engine.restart.<seat>` flag and no
  pending restart or switch plan: it takes the seat's current CLI, the latest
  config's role chain, the seat's recorded model (else the chain head, else
  skip), the matching chain entry's args, builds the `ModelEntry::Entry` target
  and calls `advance_when(..., When::AtOnce, ...)`, then pushes the seat id.
  A lane that is not Active keeps its flag.
- `crates/gear-engine/src/lib.rs`: step 8b now extends `report.restarted` with
  `restart::restart_lanes(...)` right after `release::restart_reviewers`, using
  the same `herdr`.

  `old-model` with `grace_s == GRACE`, the wrap-up prompt is sent, a second call
  returns nothing, and `advance_pending` at `wrap_at + GRACE` sends one `/quit`.
- The existing restart tests pass unchanged.

Check: `make check CRATE=gear-engine TESTS='test(restart::)'` — 33/33 pass. The

## Deviations (asked the captain, default taken)

The packet says to set `engine.restart.<seat>` to `""` after `advance_when`, but
that key is also the plan key (`plan_key` = `engine.restart.<seat>`, read by
`pending()`), so clearing it after the call erases the plan the acceptance
expects. I consume the flag before `advance_when` instead, so the plan occupies
the key; the second `restart_lanes` returns empty because `pending()` is Some,
and the test asserts the key holds the plan rather than `""`.
