# T-681 — installed skill copies carry their version; a captain's page names stale ones

## What changed
- `crates/gear-app/src/skill.rs`: `pub const VERSION_FILE: &str = ".gear-version"`; `install_into` writes it
  with `format!("{}\n", env!("CARGO_PKG_VERSION"))` before returning (not added to `written`, so the file
  lists and counts are unchanged; `SKILL.md` untouched). Added `stale_copies(home, codex_home, version)`:
  for each `SkillAgent::ALL`, the copy under `skills_dir_with(home, codex_home)/gear` is skipped when
  `SKILL.md` is not a file; the stored version is read (missing/empty → `None`); the copy is stale when it is
  `None`, when both versions parse as dot-separated `u64` lists and the copy's is less, or when one does not
  parse and they differ. A stale copy gives
  `skill copy for <agent> is from <old|an unknown version>, gear is <version>: run gear admin install-skill --agent <agent>`.
- `crates/gear-cli/src/main.rs` `cmd_home`: after `run_home` returns, when not `--json` and the context's seat
  is `captain`, `HOME` is read (unset → nothing) and `CODEX_HOME` (non-empty) is passed to `stale_copies`,
  whose lines are printed. `run_home` is unchanged.

## Tests
- `crates/gear-app/src/skill.rs` `mod tests`: `the_install_writes_the_version_beside_the_skill`,
  `a_copy_older_than_the_binary_is_named`, `a_current_or_newer_copy_is_not_named` (numeric order: 0.6.99 is
  older than 0.6.114), `a_copy_without_a_version_is_named_unknown`, `no_copy_no_line`.
- `crates/gear-cli/tests/it/home_multi_contract.rs`: the `gear` helper now removes `CODEX_HOME`; new
  `the_captains_page_names_a_stale_skill_copy` (0.0.1 named, current version silent).
- `crates/gear-cli/tests/it/install_skill_contract.rs` `the_skill_is_written_for_every_agent`: also asserts
  `.gear-version` reads the binary's version.
