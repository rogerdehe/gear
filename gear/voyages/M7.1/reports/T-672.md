# T-672 — `gear admin init` warns about a model whose context window nobody knows

## What changed
- `crates/gear-app/src/admin.rs`:
  - `InitResult` has `#[serde(default)] pub window_warnings: Vec<String>`; `register` and `re_register`
    set it to `Vec::new()`.
  - `pub fn window_warnings(config, home) -> GearResult<Vec<String>>`: builds the profile table, walks every
    lane's `lane_chain` with its profile, `models.review` with the reviewer profile (without `temps`, only
    entries that name a `cli()`), and `models.captain` with the captain profile. Entries with
    `context_window_k` are skipped. The CLI is the entry's `cli()` else the seat profile's `kind`; the log is
    the seat profile when its kind is that CLI, else the first table profile of that kind, then its
    `usage_log`. `CodexRollout` is skipped (it reports the window only from a session). A warning is emitted
    when the log is `None` or `context_window_in(log, None, model, home)` is `None`, one per distinct
    (model, CLI), in the order met.
  - `init_with_home` resolves the home (argument, else `HOME`; neither → no warnings) and fills
    `result.window_warnings` before returning. No refusal.
- `crates/gear-cli/src/main.rs`: the init text output prints `warning: <line>` for each warning after the
  seat lines; the JSON already carries the field.

## Tests (`crates/gear-app/tests/it/admin_init_contract.rs`)
- `a_model_without_a_known_window_is_warned`: a scratch home with `.pi/agent/models.json` (only `known` has
  a window) and a `[models]` chain of `prov/known`, `prov/unknown`, `prov/sized` (the last with
  `context_window_k`): exactly one warning, for `prov/unknown`, though two lanes run the chain.
- `no_model_chain_no_window_warning`: the plain `CONFIG` yields no warnings.

## Check
`make check CRATE=gear-app TESTS='test(admin_init_contract)'` — 21/21 passed. `cargo check -p gear-cli`
compiles the CLI change.

## Out of scope
- The warning is informational only; nothing refuses a config or changes how sessions are compacted.
