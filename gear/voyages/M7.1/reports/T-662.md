# T-662 — agy usage keeps partial records and says unknown, not zero, for a transcript without counts

Candidate: ee92f0cc (branch hull/t662)

## What changed (crates/gear-usage/src/lib.rs only)

- `agy_record`: a model record needs `source == "MODEL"`, a `created_at` time,
  and at least one of `input_tokens`, `output_tokens`, `cache_read_tokens`,
  `cache_write_tokens`, `thinking_tokens`; a record with none returns None. A
  missing field still counts 0 through `number`, so a record without
  `input_tokens` adds its output and cache tokens.
- `agy_jsonl`: tracks `counted` for every accepted record before the window
  check and returns None when no record carried a count; a transcript with
  counts but none in the window stays `Some` with zero totals. Doc comment
  updated to the packet's wording.
- `usage_records_in`: the same rule for agy via `agy_counted` (set in the
  `AgyJsonl` arm before the window check); before the final `Some(result)` it
  returns None when the log is `AgyJsonl` and nothing was counted.

## Tests (crates/gear-usage/tests/it/agy_jsonl_contract.rs)

- `a_model_record_without_input_tokens_still_counts`: two records, input 100,
  output 17, cache_read 5; `usage_records_in` gives two records.
- `a_transcript_without_counts_is_unknown`: `usage_in` and `usage_records_in`
  are None.
- `a_transcript_with_counts_outside_the_window_reads_zero`: `Some` with
  `records == 0`.
- The five existing tests pass unchanged.
