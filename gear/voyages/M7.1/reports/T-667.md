# T-667 — a landing order's next hint offers `land`, by its id

## What changed
- `crates/gear-app/src/station.rs`: added `pub fn actions_of(tx, project, message) -> GearResult<&'static str>`
  next to `relands`. It reads `station:{project}:{milestone}:land` (milestone from
  `message.thread.trim_start_matches("station:")`) and returns `"land"` when that meta names the
  message, else `"keep course|time-box|cut|move"`.
- `crates/gear-app/src/home.rs` `next_command`: the station hint now uses
  `crate::station::actions_of(tx, project, &message)?` instead of the literal.
- `crates/gear-app/src/captain.rs` `needs_of`: names the message id (the `milestone` local is gone) and
  uses `actions_of`.
- `crates/gear-app/src/mail.rs` `reply` station refusal: uses `actions_of` in the detail.

## Tests
- `crates/gear-app/tests/it/station_contract.rs`: `the_landing_order_offers_land` — landing order built as
  in `a_kept_course_landing_order_still_takes_the_landing`; `actions_of` is `"land"`; the captain's home
  page holds `station {land}: land)` and not `station {land}: keep course`; a `Resolve` reply is refused
  with `station {land}: land` in the detail.
- `crates/gear-cli/tests/it/captain_handover_contract.rs`: `a_landing_order_needs_land_by_its_id` — an open
  `station:M6` message with `station:p:M6:land` set; the facts text holds `station {id}: land)` and not
  `station M6:`.
- `three_done_uses_exactly_the_shared_pace_projection_and_slowest_lane` passes unchanged.

## Checks
`make check CRATE=gear-app TESTS='test(station_contract)'` — 21/21 passed.
`make check CRATE=gear-cli TESTS='test(captain_handover_contract)'` — 10/10 passed.

## Out of scope / note

  neighbouring `format!`/`match` arms in `mail.rs` needed rustfmt's own layout to keep `cargo fmt --all
  --check` clean (formatting only, no behaviour change). Applied by hand, no other file rewritten.
