# T-658 — orphaned processes in GEAR worktrees reach the captain as one item, never killed

Candidate: 66b56ccf (branch hull/t658; T-657's work merged in from origin/hull/t657)

## What changed (crates/gear-engine/src/health.rs)

- New thread/key helpers: `health:orphans:<project>` and
  `engine.health.orphans.<project>.alert`.
- New `live_worktrees(store, project)`: the worktree paths of the project's
  Active/Standby/Retiring seats — `engine.worktree_path.<seat>`, the
  `engine.worktree_path_repo.<seat>:*` values, `engine.review_path.<seat>` and
  the `engine.review_path.<seat>.*` values; empty values skipped.
- New `orphans_item(...)`, called in `check` right after the sample: an orphan
  whose cwd is not a live path and does not start with `live + "/"` is
  reported. None reported → the open item is resolved ("no orphaned process is
  left"), the key cleared, `orphans:resolved`. Some → one body sorted by pid
  with the packet's text and one line per orphan
  (`  pid {pid}, {cpu:.0}% of one core, running {h}h{mm}m, {command}, in {cwd}`):
  no open item → insert one (System, not urgent, engine → captain; no captain →
  nothing) and `orphans:opened`; another body → `update_message_body` and
  `orphans:updated`; same body → nothing. The watch sends no keys or signals.
