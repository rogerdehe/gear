# T-661 — a later `[timing] switch_at_once = true` speeds up a pending switch

Candidate: 1d89d6d0 (branch hull/t661)

## What changed (crates/gear-engine/src/restart.rs only)

- In `advance_when`, the `Some(plan)` arm of the pending-plan match now, when
  `plan.phase == Phase::Stop && !plan.at_once` and the project's latest config
  has `timing.switch_at_once`, sets `plan.at_once = true`,
  `plan.grace_s = grace_seconds(store, project, When::AtOnce)` and persists the
  plan with `set_pending`. It never sets `at_once` to false, and a plan past
  `Phase::Stop` is left alone. The existing `stop` then sends the wrap-up once
  and runs the grace as for any at-once plan.

## Tests (mod handover_tests)

- `a_pending_switch_becomes_at_once_when_the_config_asks_for_it`: a switch made
  with `switch_at_once = false` waits at `Phase::Stop` with no wrap-up; after
  the config asks for at-once, `advance_pending` upgrades it (`at_once`,
  `grace_s == GRACE`) and sends exactly one wrap-up prompt.
- `a_pending_at_once_switch_is_never_downgraded`: an at-once plan stays at-once
  after the config turns `switch_at_once = false`.
- The existing handover tests pass unchanged.
