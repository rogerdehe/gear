# T-674 — a rebind can name the project root

## What changed
- `crates/gear-app/src/draft.rs` `"rebind"`: after the `cancel` check the rest of the tokens are collected;
  a leading `repo=` token is taken out of the list — `.` → `""`, empty → `` `rebind` needs `repo=<name>`, or
  `repo=.` for the project root ``, else the name; without a leading `repo=` the repo is `""`. The rest is
  parsed for `owns=[...]` as before.
- `crates/gear-app/src/plan.rs`:
  - `rebind_config`: the `[[repos]]` check only for a non-empty repo; an empty repo removes the lane's
    `repo` key instead of inserting it.
  - `request_rebind`: both projected `target.repo` assignments are `None` for an empty repo name.
  - `rebind_preview`: an empty `new_repo` prints `root`, as the old side already did.
  - The applied line always carries the undo, writing `repo=.` when the old repo is empty.
  - `staff_text`: `repo=.` for an empty repo.
- `skills/gear/references/captain.md`: `- rebind <lane> repo=<name>|. owns=[<path>, ...]` (`.` is the project
  root).

## Tests (`crates/gear-app/tests/it/plan_fields_contract.rs`)
- `idle_rebind_applies_at_once_and_invalid_targets_are_atomic`: expected line updated to the undo with
  `repo=.`.
- `a_rebind_to_the_root_names_it_with_a_dot`: the apply line is `repo api → root … applied (to undo: - rebind
  heat repo=api owns=[src/heat/])`; `repo_of_lane("heat").name` is `""` and the stored lane has no `repo` key.
- `a_rebind_without_repo_means_the_root`: parsing gives `StaffItem::Rebind { repo: "", .. }`; `repo=` alone is
  an error.
- `idle_rebind_and_new_task_in_one_apply_use_the_destination_repo` also asserted the old undo-less line; it
  now expects the undo with `repo=.` (the "always add the undo" rule).

## Check
`make check CRATE=gear-app TESTS='test(plan_fields_contract)'` — 21/21 passed.

## Out of scope
- The engine's rebind step is unchanged: the root is already the empty repo name it reads.
