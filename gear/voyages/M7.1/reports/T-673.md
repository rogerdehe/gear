# T-673 — a blocked rebind waits alone; the other pending rebinds apply

## What changed
- `crates/gear-app/src/plan.rs` `reconcile_rebinds`: the lane seats are read once, then each lane's request
  runs in its own `store.write` (pending meta non-empty, no open attempts, parse the `RebindRequest`,
  `apply_rebind`). `Ok(true)` pushes the lane name and clears `lane-rebind-waiting:<seat id>`; `Ok(false)`
  does nothing; `Err(error)` — that seat's write rolled back alone — writes `error.detail` to
  `lane-rebind-waiting:<seat id>` only when it differs from the stored value, and the loop goes on. The
  function returns `Ok(changed)`; a waiting rebind no longer fails the project's tick.
- `cancel_rebind`: withdrawing a pending request also clears `lane-rebind-waiting:<seat id>`.

## Test (`crates/gear-app/tests/it/plan_fields_contract.rs`)
`a_blocked_rebind_does_not_hold_the_others`: two overlapping pending requests written straight into meta,
both attempts Accepted; `reconcile_rebinds` is `Ok` with exactly one lane; the other lane's pending meta is
still non-empty and its `lane-rebind-waiting` meta contains `overlaps`; a second call is `Ok` and empty and
leaves that meta unchanged. The existing rebind tests keep passing.

## Check
`make check CRATE=gear-app TESTS='test(plan_fields_contract)'` — 20/20 passed.

## Out of scope
- The engine's tick that calls `reconcile_rebinds` is unchanged; it now sees `Ok` where it used to see the
  overlap error.
