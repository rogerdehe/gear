# T-670 — a voyage is landed only when its land order is answered `land`

## What changed
- `crates/gear-board/src/stations.rs`: added `voyage_landed(tx, project, milestone)`. It is false while a
  task of the milestone is not terminal or `unmerged_done_tasks` names the milestone. With the work in, it
  reads `station:<project>:<milestone>:land`: no meta → true (a voyage from before land orders existed);
  a meta naming a message → true only when that message's `result` starts with `station <id>: land` and the
  rest is empty or starts with whitespace (a `superseded by …` result, or none, is not a landing).
- `voyage_open` is now `Ok(!voyage_landed(tx, project, milestone)?)`, its doc comment kept.
- `crates/gear-board/src/lib.rs` `voyage_entries`: `sailing` is `!crate::stations::voyage_landed(...)`; the
  `ended` time is still computed as today when not sailing.

## Tests (`crates/gear-board/tests/it/stations_contract.rs`)
Helpers `landed_world` (every M5 task terminal and merged) and `land_order`.
- `a_superseded_land_order_is_not_a_landing`: result `superseded by M-9` → `voyage_open` true,
  `voyage_landed` false.
- `a_land_order_answered_land_is_a_landing`: result `station <id>: land` → `voyage_landed` true.
- `a_voyage_without_a_land_order_is_landed`: no meta → `voyage_landed` true.
- `the_board_keeps_a_voyage_with_a_superseded_land_order_sailing`: `gear_board::build` for the superseded
  case, the M5 voyage entry's `sailing` is true.
- The existing land-order test (`a_voyage_with_a_done_task_not_yet_merged_is_open`) resolved its order with
  the result `"station: land"`, which the new rule does not read as a landing; it now resolves with
  `station <id>: land`.
