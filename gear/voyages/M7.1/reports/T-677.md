# T-677 — anchored screen markers; pi's markers no longer match inside tool output

## What changed (`crates/gear-herdr/src/profile.rs`)
- Added `marker_matches(marker, line)`: empty matches nothing; a marker without `^` matches as a literal
  substring; `^HEAD` matches when the line, after its leading whitespace/frame/spinner glyphs, starts with
  HEAD; `^HEAD*TAIL` matches when that stripped text starts with HEAD and the rest contains TAIL.
  `matches_any` uses it.
- `validate_template` checks each line with `marker_matches` instead of a substring of the whole template.
- `builtin("pi")` markers are now anchored: rate limit `^Error: *rate_limit_error`, `^429: *rate_limit_error`,
  `^Error: *Rate limit reached`, `^429: *Rate limit reached`, `^Error: 429:`, `^429:`; quota
  `^Error: *insufficient_quota`, `^429: *insufficient_quota`, `^Error: *exceeded your current quota`,
  `^429: *exceeded your current quota`; auth `^Error: No API key found for`; back-off `^Retrying (`;
  guardrails `^Command auto-denied:`, `^Access to *is blocked (outside working directory)`; error
  `^Error: *overloaded_error`, `^Error: Retry failed after`. No other profile changed.
- The rule is stated in the doc comments of `marker_matches`, `classify_screen` and `ratelimit_markers`; the
  pi paragraph of the profile doc comment quotes the new strings.
