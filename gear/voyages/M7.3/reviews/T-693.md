## Findings
- F1 [P1, blocking] The empty-goal fallback uses the unfilled merge template, so a merge op whose payload has no `"goal"` lands a squash subject with a literal `{source}` placeholder. `crates/gear-engine/src/merge.rs:4337` — `let goal = if goal.trim().is_empty() { commit } else { goal };` where `commit` is the template `fill(merge_message, [("project", p), ("task", t)])` = `merge(T-5): {source}` (the `{source}` is only filled per-merge inside the merge loop). The remerge op inserted by `crates/gear-app/src/plan.rs` (payload around plan.rs:3978-3990 has `"remerge": true` and no `"goal"`) reaches this fallback in normal use, so a `- remerge` under the default squash lands subject `T-5: merge(T-5): {source}` — breaking done clause (1) "subject `T-n: <goal>`". Smallest fix: compute `sources` before the goal, then fall back to the filled merge text, e.g. `let goal = if goal.trim().is_empty() { gear_model::commit::fill(commit, &[("source", sources.first().map(String::as_str).unwrap_or_default())]) } else { goal.to_string() };` (about 4 lines, plus moving the `sources` line above it).
- F2 [P2, logged] `sources` are the raw `merges` targets, not shas. In the legacy review-branch path (`has_review`), the review target is the ref name `origin/review/t5`, so the trailer becomes `Gear-Source: origin/review/t5` instead of a sha — `crates/gear-engine/src/merge.rs:4335` (and the `merges` entries built around 4226-4245). The contract says "sources the shas of the merges targets". The modern path resolves `task_tip` to a sha, so this only affects the shrinking legacy set; fix by resolving each target to a sha before use.
- F3 [P3, logged] The shared fixture `config_text` now sets `merge_method = "merge"` (`crates/gear-engine/src/merge.rs:11682`), so the whole existing merge suite runs under `merge` rather than the new default. The acceptance asks to set `merge` only in fixtures that read a merge commit's parents; this is broader and means only the two new tests exercise the default squash path. Tests pass and the two new tests cover squash, so this is a coverage note, not a bug.
