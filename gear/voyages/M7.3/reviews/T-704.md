## Set aside
- The acceptance says "a CLI test" but the test is a unit test that calls `run_report_speed`
  directly rather than spawning the `gear` binary. This matches the project's own convention —
  `report_time_prints_the_durations_and_the_ratio`, the coverage report tests, and every other report
  op are tested the same way — and the three required cases (two models, `--json`, empty store) are
  all exercised; only the one-line match arm `ReportOp::Speed => cmd_report_speed(cli.json)` is not
  covered, and it is identical to its neighbours and compile-checked. Not flagged.
- An empty store under `--json` yields `{"period_days":90,"models":[]}` rather than the
  `nothing is measured yet` line. The contract's "one line" is the human output; an empty `models`
  array is the idiomatic JSON equivalent, and the acceptance only asserts the line for the
  non-JSON empty store.
- The text assertion uses `contains` (not an exact row count), so an extra row would not fail the
  test; the JSON assertion does check `models.len() == 2`, so the row count is pinned there. Minor
  test-rigour only, not a behaviour gap.
