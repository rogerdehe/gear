# M7.3 lessons

- **A packet names only a function the captain found in that file.** T-696's packet named a `review.rs` `on_integration` that lives in `plan.rs`; a flash lane searched for it for 55 minutes. T-693's fallback named an unfilled template as the goal. Before a packet names a file, function or value, grep it in that file and read the line.
- **A packet that changes printed text names every test that asserts it, in every crate.** T-708 shortened the home page's voyage line; its packet named home and board tests, and gear-engine's upgrade_contract.rs, outside the lane's files, turned the merge gate red. Before the packet, grep `crates/` for the text being changed and give the lane those files.
- **A fix that freezes a state to stop a symptom is not a fix.** Twice (T-552, T-570) a pane holding two captain seats had its agent name frozen so prompts by name would not fail; the cost was that every captain that took over a fleet kept its old fleet's name. The root was that the choice of name had no rule; v0.7.33 gave it one (the fleet the pane took last) and deliveries already go to the live name. When a fix makes GEAR stop doing something the user can see, check that the user wanted it stopped.
- **GEAR deletes by ownership, never by name pattern.** After the shared `dev` was deleted (2026-11-12) the guard became "a name with a prefix"; MissHerAI's `selina/dev` passed it and was deleted with two open PRs (2026-11-17). A delete rule must prove GEAR made the branch (one of its templates, filled as GEAR fills it) and exclude every configured integration, release and staging branch; anything else is people's work.
- **A reminder repeats only when time can change its answer.** The engine already went quiet once a finished voyage's landing waited for the user, but a done task's leftover branch was retold every two hours, so the captain kept being woken. A done branch changes only by hand; v0.7.41 names it once. Before a reminder gets a retell interval, ask what could be different at the next tell.
- **Every store key about a task names its project.** Task ids repeat across projects (T-58 exists in four of them), and one engine serves them all from one store. The review-stall count was keyed by task and attempt only, so MissHerAI's T-58 attempt 2 read Lawrence's count from two weeks before and rang at 0 min (v0.7.43). A key built from a task id starts with the project; a key built from a seat id already carries it.
