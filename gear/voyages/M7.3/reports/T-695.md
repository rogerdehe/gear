# T-695 — Members are found by their `Gear-Task` trailer

## What changed (`crates/gear-engine/src/merge.rs`)
- `bisect_members` reads the first-parent log with
  `--format=%H%x09%P%x09%s%x09%(trailers:key=Gear-Task,valueonly,separator=%x2C)` and takes a
  non-merge commit as a member when its trailer names a task, the member's name being that task
  (the first value when the trailer holds several). Merge commits are members as before, named by
  their `merge(<task>): …` subject.
- `run_bisect`'s probe is unchanged: it merges the k-th member onto the base, which on a linear
  feature branch brings members 1..k.
- `prepare_merge`'s `members_in` (the feature integration task's members) reads the same log
  without `--merges`: a merge commit with a member subject still contributes `^2`; a first-parent
  non-merge commit with a `Gear-Task` trailer contributes its own commit, so it is left out of the
  foreign-commit check. A lane commit without the trailer is still refused.

## Tests (acceptance)
- `a_red_feature_gate_names_the_squashed_member_that_turned_it_red`: a feature branch of three
  squashed members (each a commit with `Gear-Task: T-n`, the second adding the file the gate fails
  on) bisects to `merge(T-2) <sha>`.
- `a_squashed_member_after_the_candidate_merges_with_the_integration_task`: a feature integration
  task whose branch holds two squashed members and the review after the candidate merges, with no
  foreign-commit refusal.
- `a_member_merged_after_the_candidate_merges_with_the_integration_task` and
  `a_red_feature_gate_names_the_member_that_turned_it_red` still pass: merge-commit members work as
  before.

## Out of scope
- The foreign-commit exclusion passes the squashed member's own commit to `--not`, which also
  excludes its ancestors: on a linear feature branch those are earlier members (already members),
  so a lane commit placed between two members would be excluded too. The packet names the commit,
  not the ancestors; logged here.
- The trailer key is the literal `Gear-Task` as the packet says; T-691's constant in `parallel` is
  not used here.
