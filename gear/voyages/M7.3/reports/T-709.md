# T-709 — A restart request has its own key

## What changed
- `crates/gear-app/src/plan.rs`: `- restart <lane|reviewer>` writes
  `engine.restart-request.<seat>` instead of `engine.restart.<seat>`.
- `crates/gear-engine/src/restart.rs`: `restart_lanes` reads and consumes the request under the new key
  (`restart_request`); the comment about the flag and the plan sharing the key is gone. `plan_key` stays
  `engine.restart.<seat>`. A value under the old key that has `at` and no plan field (`phase`) is read once
  as a request and the old key is cleared, so a pre-upgrade request is honored.
- `crates/gear-engine/src/release.rs`: the reviewer restart path reads the same request key (the plan writes
  it for reviewers too), so `restart_key` is `engine.restart-request.<seat>` and its tests use it. Without
  this, `- restart <reviewer>` would no longer be carried out.

## Tests
- `a_request_while_a_plan_is_pending_leaves_the_plan_and_runs_after_it`: the pending plan is unchanged, the
  request waits, and it is carried out once the plan is done.
- `an_old_key_request_is_honored_once`: a request under the old key restarts the lane once; the plan then
  lives under the old key and the second tick does nothing.
- `a_requested_lane_restart_wraps_up_then_resumes_the_same_model` and the reviewer restart tests use the new
  key; `restart_records_a_lanes_request` (gear-app) checks the new key.
