# T-692 — Shared git helpers in `crates/gear-app/src/base.rs`

## What changed
- `pub fn landed_in(dir, reference, commit) -> Result<bool, String>`: resolves `commit` with
  `git rev-parse --verify <commit>^{commit}` (a commit git cannot resolve → `Ok(false)`), then
  `git merge-base --is-ancestor <sha> <reference>` (0 → true, 1 → fall through, else `Err`), then
  `git log -1 --format=%H -F --grep="Gear-Candidate: <sha>" --grep="Gear-Source: <sha>" <reference>`
  (non-empty sha → true). Any other git failure is `Err`.
- `pub fn adds_nothing(dir, release, integration) -> Result<bool, String>`: true when `integration` is an
  ancestor of `release`, or when `git merge-tree --write-tree <release> <integration>` exits 0 and its tree
  equals `git rev-parse <release>^{tree}` (a squash landed the same content); a conflicting merge is false.
- `pub fn added_paths(dir, release, integration) -> Result<Vec<String>, String>`: the merged tree's paths
  against `<release>^{tree}` via `git diff --name-only`; a conflicting merge is `Err`.
- Private helpers `git` (run git in `dir`, spawn failure as an error string), `merged_tree` and
  `tree_of` (`pub`, used by `adds_nothing`/`added_paths`).

## Tests (`base.rs`, `landed_tests` on a temp repo)
- an ancestor is landed; a squashed commit whose message carries `Gear-Candidate:` or `Gear-Source:` makes
  that sha (and its short prefix) landed; an unrelated commit and an unresolvable sha are not.
- `adds_nothing` true for an ancestor and for a branch whose content was squashed onto release, false for a
  branch with a change of its own; `added_paths` lists only that change's file.
