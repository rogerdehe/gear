# T-707 — A new block can be named so another depends on it

## What changed
- `crates/gear-app/src/draft.rs`: `parse_block_header` accepts `## NEW:<label>` (lowercase letters,
  digits, `-`; empty or other characters refused); `QueueItem` carries `pub label: Option<String>`;
  `parse_queue` refuses two blocks with one label, naming the first block's line. `rewrite_applied` takes
  the label→id pairs, turns a `## NEW:<label>` header into `## T-n` like a plain `## NEW`, and rewrites
  every `NEW:<label>` in a `deps:` line to its id.
- `crates/gear-app/src/plan.rs`: builds label→id from `new_ids` before the dep check, replaces
  `deps: NEW:<label>` with the id, refuses an unknown label (`dep NEW:<label> names no block of this
  draft`), stores the resolved deps, and returns the label→id pairs in `ApplyResult.labels` (serde default)
  so the file rewrite can name them.
- `crates/gear-cli/src/main.rs`: passes `result.labels` to the rewrite.
- `skills/gear/references/captain.md`: one sentence on `## NEW:<label>` and `deps: NEW:<label>` in the
  `# Queue` header description.

## Tests
- `a_new_block_may_depend_on_another_by_label`: `## NEW:core` plus a block with `deps: NEW:core` applies in
  one go, the second task's stored deps name the first's id, and the rewritten file shows both ids and no
  `NEW`.
- `a_dep_on_an_unknown_label_is_refused`; `two_blocks_with_one_label_are_refused`;
  `a_label_is_lowercase_letters_digits_and_dashes`; `a_new_block_can_carry_a_label_and_the_rewrite_names_its_id`.
- A plain `## NEW` block is unchanged (existing rewrite and apply tests pass).

## Check
`make check CRATE=gear-app` — 816 passed; `make check CRATE=gear-cli` — 215 passed; `cargo fmt --all
--check` clean.

## Out of scope
- A label is only for NEW blocks of one draft; an existing `T-n` cannot carry one.
