# T-694 — rework attempt 2 (F1, F2)

## What changed

- F1: the replay now reads `git log --reverse --first-parent --no-merges
  --format=%H%x09%s <base_ref>..<task_tip>` and splits the commits by subject:
  the reviewer's commits (subject starting with the review prefix) are not
  cherry-picked as commits of their own. Each review commit is folded into the
  last replayed feature commit with `git cherry-pick --no-commit <sha>` then
  `git commit --amend --no-edit`, so its records land inside that commit; only
  then are `Gear-Source: <task_tip>` and `Gear-Candidate: <sha>` appended to
  its message. A replay that conflicts still aborts, resets to the base and
  falls back to the squash path with `- replay conflicted; squashed`.
- F2: the replay test now cuts the feature branch from dev, adds the two
  member commits and a review commit, and asserts dev gains exactly two
  commits (`rev-list --count` before + 2), the last one carrying the review's
  file (`r5.txt`) and the two trailers, with no review subject on dev.
- The conflict test's feature branch also carries a review commit, as normal
  use does.

## Out of scope

- A feature branch with review commits but no feature commit after the base:
  the review commits land as commits of their own (no last feature commit to
  fold into); edge case, logged.
- A cherry-pick that fails for a reason other than a conflict takes the same
  abort/reset/squash fallback; edge case, logged.
- `merge_method = "merge"` still lands a two-parent merge commit.
