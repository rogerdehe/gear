# T-704 — `gear report speed`

## What changed (`crates/gear-cli/src/main.rs`)
- `ReportOp::Speed` (`gear report speed`, `--json`), dispatched like the other report ops; it opens the
  caller's session store and resolves the caller the way `gear report time` does.
- `run_report_speed` reads `gear_app::speed::measured` and renders, under the header
  `Model speed · last 90 days`, one row per model: `<model> · <samples> samples · median <m>m of work ·
  ratio <r>x` (`0.14x`). `--json` gives `{"period_days": 90, "models": [{model, samples,
  median_work_min, median_ratio}]}`. An empty store prints `nothing is measured yet`.

## Tests
- `report_speed_prints_a_row_per_model_and_says_when_nothing_is_measured`: two models (3 samples at ratio
  0.15, 1 at 0.20) print both rows with their numbers; `--json` carries the same fields; an empty store
  prints the one line.

## Check
`make check CRATE=gear-cli` — 216 passed; `cargo fmt --all --check` clean.

## Out of scope
- The report is not restricted to the captain (the packet names no permission); a lane may run it.
