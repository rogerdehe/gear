# T-699 — The records merge follows the merge method and takes only voyage files

## What changed (`crates/gear-engine/src/finished.rs`)
- `records_step`: after the "nothing new" check and before opening the merge worktree, it lists
  `git diff --name-only <remote>/<integration>...<remote>/<seat branch>` and refuses with
  `Recorded::Failed("the captain's branch changes files outside <voyage folder>: <up to 10 paths>; move them
  to a task")` when any path is not under the voyage folder resolved for this project and milestone
  (`gear_model::layout::voyage_dir`). Nothing is merged or deleted on that path.
- In squash mode (`repo.merge_method == MergeMethod::Squash`) the records land as one commit: the merge is
  made, then `git reset --soft <remote>/<integration>` and `git commit -m "records: <project> <milestone>"`,
  so the integration tip gets one non-merge commit. Merge mode keeps today's `merge --no-ff` commit.

## Tests (`finished::tests`)
- `a_records_branch_changing_a_code_file_is_refused`: a branch adding `src/main.rs` opens the `records:M1`
  item naming the file and the voyage folder, nothing is merged, the branch stays on the remote and
  locally, no meta is written.
- `a_squashed_records_landing_is_one_commit`: with `merge_method = "squash"` the records land as
  `records: p M1` with one parent (no merge commit) and the branch is deleted.
- Fixtures adjusted: the test project names `voyage_dir = "voyages/{milestone}"` and
  `merge_method = "merge"` (today's behaviour for the existing records tests); the conflicting-records
  fixture now conflicts inside the voyage folder, and the "new records commit after the landing" fixture
  writes `voyages/M1/plan.md` from `origin/dev`.

## Check
`make check CRATE=gear-engine` — 1209 tests run, 1209 passed, 23 skipped; `cargo fmt --all --check` clean.

## Out of scope
- Paths with spaces are quoted by `git diff --name-only`; the prefix check would refuse them (an edge case
  outside normal use, logged here).
- The refusal names up to 10 paths; more are not counted in the item.
