# T-711 — A Claude seat's spent plan limit is a quota signal

## What changed (`crates/gear-engine/src/quota.rs`)
- Where a seat's quota signal is read, a seat whose profile's `usage_log` is `claude-jsonl` also signals
  quota when `gear_usage::claude_limit_stop(obs.session)` returns a stop whose `resets_at` is absent or later
  than now (the session is skipped when empty). The confirm rounds, source, fallback and park machine is
  otherwise unchanged.
- When the stop carries a `resets_at`, the park uses it as the reset instead of `[models] quota_reset_h`
  (after the screen's own reset, which is unchanged), and `fallback_reset` takes it in the same place, before
  `quota_reset_h`.

## Tests
- `a_claude_lane_whose_plan_limit_is_spent_is_parked_at_the_logs_reset`: a claude lane whose session log has a
  rejected `quotaLimits` record with a future reset is parked after its confirm rounds, with the wait's
  `until` equal to the log's reset (not `quota_reset_h`).
- `a_claude_stop_whose_reset_has_passed_is_not_out_of_quota`: the seat stays Active.
- `a_pi_lane_is_unaffected_by_a_claude_session_log`: a pi lane with the same log stays Active.

## Check
`make check CRATE=gear-engine` — 1221 passed, 23 skipped; `cargo fmt --all --check` clean.

## Out of scope
- A stop with no `resets_at` parks for `quota_reset_h` hours, as the packet says (the reset is left as it is).
- The log is read only for a seat whose profile names `claude-jsonl`; a Claude seat on another profile is
  unaffected.
