# T-693 — A task merge lands one squashed commit

## What changed (`crates/gear-engine/src/merge.rs`)
- `prepare_merge`, after the merge loop and the conflict-marker check, when
  `repo.merge_method == MergeMethod::Squash`: reads `lines` from
  `git log --no-merges --reverse --format=%s <base_ref>..HEAD` minus the subjects that start with
  the review prefix, runs `git reset --soft <base_ref>`, then
  `git commit -m gear_model::commit::squash_message(task, attempt, goal, sha, sources, lines)`.
  `goal` is `op.payload["goal"]`; empty falls back to the merge commit text `commit`. `sha` is the
  candidate and `sources` the shas of the `merges` targets. `MergeMethod::Merge` changes nothing.
  The tree is the merge's own: the reset only moves the commit boundary, so the gate and the push
  see the same tree as before.
- The merge op queued in `merge_passed` now carries `"goal"`, read from the task's contract row
  (`get_task` then `get_contract` at the task's contract version). The train and the batch carry
  the op's payload, so each of their tasks becomes one commit too.

## Tests (acceptance)
- `a_squash_merge_lands_one_commit_with_the_lane_subjects_and_trailers`: a task branch of three
  lane commits plus the review commit lands as exactly one non-merge commit; subject
  `T-5: the goal`, body with the three lane subjects, trailers `Gear-Task`, `Gear-Attempt`,
  `Gear-Candidate`, `Gear-Source`, and no review subject in the body. A twin fixture merged with
  `merge_method = "merge"` has the same `dev` tree and a two-parent merge commit.
- `a_squash_train_lands_one_commit_per_task_in_order`: a train of two tasks with squash lands two
  non-merge commits, T-2's on T-1's, in order.
- The shared merge fixture (`config_text`) now names `merge_method = "merge"`, so the existing
  merge tests that read merge commits and their subjects keep today's behaviour; the squash tests
  ask for `squash` through `config_text_method`/`repo_method`. The remote-contract fixture names
  `merge_method = "merge"` too, since it reads the landed subjects.

## Check
`make check CRATE=gear-engine TESTS='test(squash)'` — 2 tests run, 2 passed.
`make check CRATE=gear-engine TESTS='test(merge)'` — 163 tests run, 163 passed.
`make check CRATE=gear-engine` — 1209 tests run, 1209 passed, 23 skipped.

## Out of scope
- The shared fixture is set to `merge` rather than fixing only the fixtures that broke: 33 tests
  read the landed subjects or merge parents, and the packet allows setting the method in those
  fixtures. The default squash path is covered by the two new tests and the remote-contract run
  before the fixture change.
- A squash whose `git commit` fails (no identity in the worktree) ends the merge as `clear`, as a
  merge commit failure already does; the packet names no reason.
