# T-706 — The flaky reclaim test gets its own Herdr stub

## Cause
`finished::tests::a_clean_pushed_worktree_is_removed_and_not_named` failed in parallel runs because
`reclaim` calls `project_workspaces`, which spawns the real `herdr` from the process-wide `PATH`. Three
other tests in the same module set `PATH` to a stub `herdr` that lists a workspace (`p-captain-m2`,
`p-heat`, `p-merge`); when one of those was on `PATH` while the clean test ran, its reclaim saw that
workspace, could not close it (the fixture's `FakeHerdr` knows only `p/merge/M1`), and named it — the
item's body contains "worktree", so the assertion failed. Reproduced 3/3 before the fix.

## Fix (`crates/gear-engine/src/finished.rs`, tests only)
- `Landed` carries its own `workspaces` list (id, label, agent status) and `set_workspaces`; `reclaim`
  writes a per-fixture stub `herdr` that answers `workspace list` with exactly that list, holds a
  process-wide lock while `PATH` points at it, and restores `PATH` afterwards. Every reclaim test now
  gets its own stub and its own `PATH` window; no retry, no sleep.
- The three tests that set `PATH` by hand (`a_dirty_worktrees_workspace_is_not_removed`,
  `a_leaving_agents_workspace_is_named_only_after_its_grace`, `a_workspace_whose_worktree_is_gone_is_closed`)
  use `set_workspaces` instead; the `stub_workspace_list` helper is gone.
- The clean test is unchanged in what it asserts: the worktree is removed and not named.

## Check
- `cargo test -p gear-engine --lib finished::` — 26 passed, 5 runs in a row.
- `make check CRATE=gear-engine` — 1212 passed, 23 skipped; `cargo fmt --all --check` clean.

## Out of scope
- Production code is untouched; only the test module changed.
