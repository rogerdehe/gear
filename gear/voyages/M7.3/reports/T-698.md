# T-698 — The reclaim knows a squashed release and a records-only remainder

## What changed (`crates/gear-engine/src/finished.rs`)
- `branch_on_integration` uses `gear_app::base::landed_in`, so a leftover task branch whose work was
  squashed onto the integration branch (named by `Gear-Candidate`/`Gear-Source`) counts as on it and is
  deleted.
- `branch_on_release` and the integration-branch deletion guard use
  `gear_app::base::adds_nothing(<remote>/<release>, <remote>/<integration>)` instead of ancestry, so an
  integration branch squashed onto release by a pull request is deleted like one merged. The namespace and
  `may_delete_branch` rules are unchanged.
- When the integration branch adds something to release, `gear_app::base::added_paths` is computed. If every
  path is under the voyage folder (resolved for the landing's milestone), one non-urgent item on
  `records:<milestone>` says `only the voyage records on <integration> are not on <release>`, written once per
  landing under the meta key `records_unreleased:<project>:<milestone>`. Otherwise the branch is named in the
  reclaim item as `branch <integration> (not on <release>)`, urgently.

## Tests (`finished::tests`)
- a task branch squashed onto dev is deleted; an integration branch squashed onto main is deleted; one with a
  code change of its own is named urgently and kept; one whose only difference is `voyages/M1/report.md` gets
  the one non-urgent line, the meta key is set, and a second scan writes nothing.

## Check
`make check CRATE=gear-engine` — 1216 passed, 23 skipped; `cargo fmt --all --check` clean.

## Out of scope
- The packet says the reclaim "names the integration branch as not on the release branch"; since v0.7.11
  (T-622) it kept it unnamed. I asked the captain and, by default, restored T-622's naming for a
  project-namespaced integration branch with a code change (the existing test only covers a shared `dev`,
  whose guard is skipped, so it stays green). If the captain prefers silence there, drop the `left.push`.
- A path with a space is quoted by `git diff --name-only` and would not match the voyage prefix (edge case).
