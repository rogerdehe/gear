# T-698 — The reclaim knows a squashed release (attempt 2, rework)

## What changed (`crates/gear-engine/src/finished.rs`)
- `branch_on_integration` and `branch_on_release` take the repo's own integration branch (`repo.integration`)
  and never `config.conventions.integration`; the reclaim calls both with `&repo.integration`, so a
  `[[repos]]` entry whose integration differs from the project default is checked against itself (F1).
- `branch_on_integration` uses `gear_app::base::landed_in`, so a leftover task branch whose work was squashed
  onto the integration branch (named by `Gear-Candidate`/`Gear-Source`) counts as on it and is deleted.
- `branch_on_release` and the integration-branch deletion guard use
  `gear_app::base::adds_nothing(<remote>/<release>, <remote>/<integration>)`, so an integration branch
  squashed onto release by a pull request is deleted like one merged. The namespace and `may_delete_branch`
  rules are unchanged.
- The records-only line, its `records_unreleased:<project>:<milestone>` meta and its test are removed
  (M-8935: the reclaim names no unreleased integration branch since T-622). An integration branch with
  unreleased work is kept and not named.

## Tests (`finished::tests`)
- a task branch squashed onto dev is deleted; an integration branch squashed onto main is deleted; one with a
  code change of its own is kept and not named; a child repo's own integration branch (`p/feature` from a
  `[[repos]]` entry) with unreleased work is kept though the project's `dev` is on main.
