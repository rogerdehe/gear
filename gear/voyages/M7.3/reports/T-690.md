# T-690 — The parallel-change check reads the branch's own commits

## What changed (`crates/gear-engine/src/parallel.rs`)
- `changed(repo, from, to)` now runs `git log --no-merges --name-only --format= -z <from>..<to>`
  (with `--no-ext-diff --no-textconv --no-renames`, as before) instead of
  `git diff <from>...<to>`. It lists the files of the commits `to` has that `from` lacks, so a
  branch that merged the integration branch after it took another task's change no longer lists
  that file as its own (M7.1 M-8738).
- The cache is unchanged: keyed by `(repo, from, to)`, same `DIFFS` map and `DIFFS_MAX`, same
  `DIFF_MISSES` test counter, a failed read keeps nothing.
- The doc comment names the reason.

## Test (acceptance)
- `a_branch_that_merged_the_integration_branch_does_not_share_a_landed_file`: `dev` takes another
  task's `plan.rs` after T-1 is cut; T-2 is cut after it and changes `plan.rs`; T-1 merges `dev`.
  The scan reports no `tasks:T-1:T-2` pair and no `integration:T-1` overlap. Under the old
  `git diff <from>...<to>` T-1's diff held `plan.rs` and both rang.

## Check
`make check CRATE=gear-engine TESTS='test(parallel)'` — 35 tests run, 35 passed.
`make check CRATE=gear-engine` — 1208 tests run, 1208 passed, 23 skipped.

## Out of scope
- The stacked-task subtraction (`changed(base_tip, earlier tip)`) keeps the same directional read;
  its semantics are unchanged for a stacked branch, which has no merge of the earlier work.
- Renames: `--no-renames` is kept, so a rename still lists both paths as before.
