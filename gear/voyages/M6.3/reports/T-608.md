# T-608 — report

`make gate` keeps half its 80 s limit on a busy machine. The suite itself was
already under 40 s when run as the packet says (`cargo nextest run
--workspace`, the machine's cores); the gate was over half because its test
phase ran the suite with the build-slot's *build* job cap (4-5 threads under
load), which made the suite 54 s. Changed `scripts/gate.sh` only.

## What changed

`scripts/gate.sh`, the `test` phase: it now runs the suite with the machine's
cores, as the plain `cargo nextest run --workspace` does, by unsetting
`NEXTEST_TEST_THREADS` for that phase
(`tools/build-slot/build-slot.sh env -u NEXTEST_TEST_THREADS scripts/test.sh`).
The build phase keeps the build-slot cap. A comment in the file says why: a
build is sized to a fair share of the machine, but a test run is mostly waiting
on git subprocesses, and capping its threads at that share made the gate's
suite 54 s under load against 31-32 s with the cores it has. The 80 s limit,
the build-slot caps and the shard count are untouched.

No test of mast's crates (gear-app, gear-board, gear-cli, gear-forge,
gear-herdr, gear-store) was over 2 s in any run; the slowest mast test was
0.47 s (gear-app). Nothing in mast's crates needed making faster or
quarantining.

## Tests over 2 s (all in hull's crate gear-engine — for the captain)

Under the plain run (the machine's cores), five tests crossed 2 s. Each is a
whole merge/review pass over real git repositories in one process; there is no
sleep, fake clock or oversized fixture left to cut, and the time is the git
subprocesses themselves.

- `gear-engine merge::tests::the_train_merges_another_task_while_the_bisect_runs`
  2.60 s / 2.59 s — a merge train over real git while a bisect gate waits on a
  file (the test's own `sleep 0.02` poll loop is the gate's wait, not a fixture
  sleep).
- `gear-engine merge::tests::a_merge_that_loses_the_push_race_on_every_try_is_raced`
  2.19 s / 2.15 s — a merge retried against a remote that rejects every push
  (real `git push` races).
- `gear-engine merge::tests::a_refused_land_is_retried_by_a_remerge`
  2.06 s / 2.05 s — a refused land remerged over real git.
- `gear-engine::it audit_contract::a_captain_pass_merges_the_audit_and_starts_what_waits_for_it`
  2.04 s — a captain pass merging the audit over real git.
- `gear-engine review::tests::direction_checks_follow_pushes_and_report_results`
  2.02 s — review direction checks over real pushes.

Under the capped run (4 threads) none crossed 2 s (the slowest was 1.71 s), so
the per-test times move with the thread count; the suite wall time is what the
gate pays.
