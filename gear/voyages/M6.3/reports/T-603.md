# T-603 — report

[F-3 1/4] Herdr can split a pane for GEAR. No caller yet.

## What changed

- `crates/gear-herdr/src/lib.rs`: `HerdrAct::pane_split(&mut self, pane_id,
  direction, cwd) -> Outcome<String>` (the new pane's id), documented as Herdr
  `pane.split` that never focuses. `SocketHerdr` implements it over the socket
  call `pane.split` with `target_pane_id`, `cwd`, `direction` (`right`/`down`),
  `focus: false` and the workspace derived from the pane id (as the CLI
  `herdr pane split <pane> --direction <right|down> --cwd <cwd> --no-focus`
  does). An unknown direction is `Refused { invalid_params }` before anything
  runs; transport/protocol errors go through `outcome_from_error`.
- `fn pane_from_split_reply`: reads the new pane id from `.result.pane.pane_id`
  (the CLI envelope the packet names) or `.pane.pane_id` (the socket reply the
  door receives). A reply that names no pane is `Uncertain` — the split may
  have happened even though GEAR cannot name the new pane.
- `crates/gear-herdr/src/fake.rs`: `Call::PaneSplit { pane, direction, cwd }`
  and `FakeHerdr::pane_split`: splits a known pane into the next free pane id
  of its workspace, adds it as a shell (no agent), records the call, and
  honours `inject_next` (an injected failure creates no pane). An unknown pane
  is `Refused { pane_not_found }`.
- `crates/gear-engine/examples/opencode_live.rs`: the `NoKeys` driver forwards
  `pane_split` to the real door like its other calls.

## Tests

- `tests::pane_split_reply_names_the_new_pane` (lib.rs): the CLI envelope
  `.result.pane.pane_id` and the socket `.pane.pane_id` both return the new
  pane id; a null reply is `Uncertain`.
- `fake::tests::pane_split_creates_a_shell_pane_and_records_the_call`: the fake
  returns `w1:p2`, the new pane has no agent, the call is recorded with pane,
  direction and cwd, a second split takes `w1:p3`, an unknown pane is refused,
  and an injected failure creates no pane.
