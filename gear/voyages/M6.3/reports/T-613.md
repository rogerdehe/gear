# T-613 — report

A `gear send` for a task the lane has not been given says what to do (the
T-778 case: a lane looped inside one turn retrying `gear send --task T-778
--attempt 1` for a task not yet delivered, so it never went idle). Changed
`crates/gear-app/src/mail.rs` only.

## What changed

- `fn not_delivered` (new, `mail.rs`): whether a task is `Ready` and assigned
  to this lane with no attempt yet — the lane has not been given it.
- `send_inner`, the `Result` branch: when the attempt is missing and the task
  is ready for this lane, the NO_TARGET now carries
  `"<T-n> is not delivered yet: end your turn; GEAR delivers it when you are
  idle"` instead of `"no attempt <n> of task <T-n>"`. Any other missing attempt
  keeps its old text.
- `declare_wait` (the `blocked` kind): the same text for the same case; any
  other missing attempt keeps its old text.

The error code stays `NO_TARGET`, as the packet says; only the text changes.

## Tests

New `crates/gear-app/tests/it/mail_contract.rs` (added to `tests/it/main.rs`):

- `a_send_for_an_undelivered_ready_task_says_what_to_do`: a lane's
  `gear send --kind result --task T-1 --attempt 1` for a Ready task assigned
  to it with no attempt fails with `NO_TARGET` and exactly
  `T-1 is not delivered yet: end your turn; GEAR delivers it when you are idle`.
- `a_blocked_send_for_an_undelivered_ready_task_says_what_to_do`: the same
  text for `gear send --kind blocked`.

`make check CRATE=gear-app TESTS='test(mail)'` — 8 tests, 8 passed.
`make gate` — 2580 tests, 2580 passed (33 s, under half the 80 s limit).

## Out of scope

- A `progress` or `question` send for a task with no attempt still stores the
  message without checking the attempt (it never failed with NO_TARGET), so it
  is unchanged.
- The engine's own retry loop that caused T-778 is T-612's job (hull), not this
  task.
