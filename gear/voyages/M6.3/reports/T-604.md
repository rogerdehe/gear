# T-604 — report

[F-3 2/4] Another CLI starts in a new pane while the old agent keeps the seat.
Changed `crates/gear-engine/src/restart.rs`, `crates/gear-engine/src/quota.rs`
(the switch fallback and the tests that drove the old same-pane restart),
`crates/gear-herdr/src/fake.rs` (a fixture fix), and the two `tests/it`
contracts that drove the old same-pane restart.

## What changed

- `Phase::Split` and `Plan.new_pane` (durable, stored before the next step, so
  an engine restart never splits twice). `Plan.old_generation`/`old_profile`
  keep what the old agent has while a split start is under way.
- `stop`: for a CLI change it writes the handover as today (wrap-up, grace,
  `switch_at_once` stay) and moves to `Split` **without** exit keys and without
  `leave_reachable`: the old agent keeps its pane and the seat.
- `split`: `herdr.pane_split(<old pane>, "right", <the seat's worktree>)`, the
  new pane id stored in the plan before the next phase; an engine restart
  between Split and Start resumes at Start and never splits again.
- `start`: for a CLI change it runs today's start against `plan.new_pane`
  (reserve the new generation, environment line, the chain entry's args,
  `agent_start`). The new agent gets a temporary name (`<project>-<seat>-new<generation>`)
  because the old agent still carries the seat's name; the name move is T-605's.
- `finish`: the captain's decision — the reserved new binding is set Active at
  the new generation, the seat is Active, the model meta is set, the Continue
  packet with the handover block is delivered to the new pane, and the plan is
  cleared. The old agent and the old pane are not touched.
- A failed or timed-out start (`fail_start`, the `wait` timeout) closes the new
  pane, clears its environment line, undoes the reservation (old binding
  Active, old generation, old profile, the attempt carried back), clears the
  plan and flags the seat: the old agent stays bound and working.
- `quota::start_switch`: a pi or Claude model without `[models.switch]` labels
  now falls back to the restart instead of flagging (a restart carries the
  model; this is what the pi contract test expects).
- `fake::exit_agent` clears the agent's name, as a real agent that exits does.

## Tests

`make check CRATE=gear-engine TESTS='test(restart::)'` — 29 tests, 29 passed.
`make check CRATE=gear-engine` — 1097 tests, 1097 passed (23 skipped).
`make check CRATE=gear-herdr` — 59 tests, 59 passed.

New in `restart.rs`: a CLI change waits for the wrap-up, splits once in the
seat's worktree and starts the new CLI in the new pane while the old agent is
still there, the seat is rebound and the Continue delivered there; an engine
restart between Split and Start neither splits again nor starts a second agent;
a failed start closes the new pane and leaves the old binding Active and the
old agent in its pane. The existing restart tests that drove the old same-pane
restart were updated to the split behaviour (the old agent is not exited, the
new pane is not the seat's pane, the plan is cleared by the Finish).

## Out of scope

- The name move (clear the old agent's name, rename the new agent to the seat's
  name), the old agent's exit and the old pane's close are T-605's Finish. Until
  then the new agent carries its temporary name and the old agent its seat name.
- The quota and stray-pane exemption for the old pane is T-605's.
- The `onboard::resume_start` failure path still flags a seat instead of
  restarting it.

## Friction

The task took far longer than the 45-minute estimate (about 2 hours): the
packet's "today's start" and "Finish only records that the new agent is up"
pulled in opposite directions, and the captain's decision (Finish rebinds and
delivers the Continue) arrived after the first implementation. The split also
broke nine quota tests and two `tests/it` contracts that had encoded the old
same-pane restart, which had to be reworked to the new behaviour.
