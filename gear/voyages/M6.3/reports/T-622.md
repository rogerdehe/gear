# T-622 — report

A project's integration branch lives for one voyage: a landing's reclaim
deletes it once it is on the release branch, and the next departure cuts it
again.

## What changed

### Cutting the integration branch again (`crates/gear-engine/src/onboard.rs`)

`ensure_integration` is called before a worktree is created in the three
places the packet names:

- `onboard.rs`, the lane's home worktree (`worktree_create` on
  `repo.integration`);
- `review.rs`, both reviewer worktree creates;
- `merge.rs`, `bisect_worktree` and `stage_worktree`.

It fetches the remote; when `refs/remotes/<remote>/<integration>` is missing,
it pushes `<remote>/<release>` to `refs/heads/<integration>` once, fetches
again, and tells the captain in one `Info` item on thread
`integration:<project>`: `<integration> was missing; cut from <release> at
<sha>`. An integration branch equal to the release branch is never created.
A missing release branch (nothing to cut from) leaves the worktree step to
name the missing branch, as before.

### The reclaim (`crates/gear-engine/src/finished.rs`)

The integration branch is handled explicitly, whether or not it matches the
project's `<project>/*` prefix:

- its tip on the release branch → deleted on the remote (everything it holds
  is released);
- otherwise it holds unreleased work → kept and named
  `branch <integration> (not on <release>)`;
- an integration branch equal to the release branch is never deleted.

The landed-voyage fixture now carries a release branch at the integration
tip, so the existing reclaim tests keep their meaning.

## Checks

`make check CRATE=gear-engine TESTS='test(onboard::) | test(finished::)'`:
49/49 pass, including the three acceptance tests:

- `a_missing_integration_branch_is_cut_from_release_before_the_first_lane_worktree`
  (the branch is cut at the release sha and the Info item names it);
- `a_present_integration_branch_is_untouched` (no cut, no item);
- `the_reclaim_deletes_an_integration_branch_on_release_and_keeps_one_with_unreleased_work`
  (deleted on release; kept and named "not on main" with extra commits).

The whole `gear-engine` suite: 1131/1131 pass.

## Out of scope

- The helper fetches before every worktree create, not only the first of a
  voyage; the fetch is the one the create needs anyway, and the branch check
  is local.
- The reclaim still relies on the remote-tracking release ref for the
  ancestry check (the records step fetches with `--prune` first); a stale ref
  can only keep the integration branch longer, never delete it wrongly.
