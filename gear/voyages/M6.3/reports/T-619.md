# T-619 — report

Records written after a landing reach the integration branch with no gate
(Carthage M1: the plan file rewritten by an apply after the landing went
through a full 6-minute CI run, because the records step ran once per landing).

## What changed

- `crates/gear-engine/src/finished.rs` `merge_records`: the once-per-landing
  meta `records_merged:<project>:<milestone>` now stores the tip it merged
  instead of a timestamp. On a later scan, the captain's branch is fetched and
  its current tip compared with the meta: the same tip is left alone, a new tip
  (commits the integration branch lacks) is merged the same way — records
  merge, no gate, branch deleted — and the meta moves to the new tip. A branch
  that is gone leaves the meta and resolves the records item.
- `crates/gear-engine/src/finished.rs` `records_step`: when the opened merge
  worktree's path no longer exists (T-618's reclaim removed it), the worktree
  is dropped from Herdr (`worktree_remove`) and opened again the same way
  (`worktree_create` with the same repo, branch, base and label) before the
  merge.
- `crates/gear-engine/src/merge.rs`: `merge_label` and `step_failure` are
  `pub(crate)` so `finished.rs` can name the label and the failure the same way
  the open does.

## Tests

`make check CRATE=gear-engine TESTS='test(finished::)'` — 13 tests, 13 passed.

- `a_new_records_commit_after_the_landing_is_merged_on_a_later_scan`: the
  packet's case, with the real merge worktree left in place (the records step
  alone, not the reclaim). After the first merge, a new commit on the
  captain's branch is merged on a later scan and the branch deleted; no new
  commit, nothing happens.
- `a_removed_merge_worktree_is_reopened_before_the_records_merge`: the merge
  worktree's directory is deleted, the scan runs, and the fake records a
  `WorktreeRemove` for its workspace followed by a `WorktreeCreate` for the
  same branch. No merge is asserted on the fake path.

The existing T-585 tests now assert the meta holds the tip it merged.

`make gate` — 2616 tests, 2616 passed (49 s, under the 80 s limit).

## Out of scope

- The `Recorded::Missing` case no longer writes the meta, so a landing whose
  captain branch is gone fetches the remote on every scan within the reclaim
  window; the records item is resolved each time (a no-op once closed).
- The fake's `worktree_create` returns a `/fake-worktrees/...` path, so the
  reopen test asserts the Herdr calls only, not a merge on that path.
