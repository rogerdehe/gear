# T-630 — report

Reviewers stay at their quota, and a reviewer restarts without losing its
seat (Lawrence M2, 2026-11-06 09:37Z: to pick up a fixed DashScope account,
the captain released its three idle reviewers on GEAR's word; GEAR starts a
reviewer only when a review is due, so two stayed down and the user saw one
reviewer where three are resident by default).

## What changed

### 1. Reviewer seats stay up (`crates/gear-engine/src/review.rs`)

- `keep_reviewer_seats` (new): while the project's current voyage has open
  tasks and is not landed, and `[quota] temps` has room (`has_free_slot`, the
  same count the review start uses), and no hand-in waits for a seat
  (`release::hand_ins_waiting`), it starts **one** reviewer a tick in
  `Standby`. The model and CLI are the review chain's first entry, as a review
  of the project would run; an unverified profile starts nothing.
- `start_standby_reviewer` (new): the pane, environment and agent-start steps
  of `start_reviewer` without the job's branch and packet — the seat worktree
  is opened or created on its seat branch at the integration branch, the agent
  is started, and the seat goes `Starting → Active → Standby` with no task and
  no `engine.review_pending` reservation.
- `free_released_seat` / `create_standby_seat` (new): a released seat whose
  pane holds no agent is warmed first (its worktree and cache stay); else a
  new `review-<n>` seat is created.
- `crates/gear-engine/src/lib.rs`: the tick runs the step after the review
  step (`report.warm`), not while the fleet rests.

### 2. `- restart <reviewer>` (`crates/gear-app/src/draft.rs`, `plan.rs`, `crates/gear-engine/src/release.rs`)

- `StaffItem::Restart` parses `- restart review-n` under `# Staff`.
- `plan.rs` `restart_reviewer`: an idle reviewer (Standby, no job) or a
  working one (Active with a task) gets `engine.restart.<seat>`; any other
  state is refused with the reason. The line is logged as a staff decision.
- `release.rs` `restart_reviewers` (new, the engine step): a working reviewer
  waits — the flag stays until its verdict put the seat back in `Standby` with
  no job. Then, across ticks (`engine.restart_phase.<seat>`): the profile's
  goodbye (`exit_command`/`exit_keys`) goes to the seat's pane, the engine
  waits until the pane holds no agent, and starts the same CLI, model and
  chain arguments again in the **same pane and worktree**; the seat and its
  generation stay, and the flag is cleared. A failed start parks the seat
  `NeedsCheck` with the reason.
- `crates/gear-engine/src/lib.rs`: the tick runs the step after
  `release_finished_reviews` (`report.restarted`), so a verdict and its
  restart can happen in one tick.

## Out of scope

- A `Standby` seat whose agent died is still only noticed when a review takes
  it; the warm-seat step does not restart such a seat (it counts it as
  occupying the quota through its binding, `has_free_slot`'s live count).
- `- restart` does not resume the reviewer's conversation: the same CLI and
  model start a fresh session, as the packet asks ("exited and started again
  in the same pane and worktree").
