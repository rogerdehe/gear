# T-606 — report

[F-3 4/4] The same CLI with another model switches in place for pi and Claude.
Changed `crates/gear-engine/src/switch.rs`, `crates/gear-engine/src/quota.rs`
and `crates/gear-engine/src/restart.rs` (tests and comments only in the last
two, plus the restart fallback in quota).

## What changed

- `switches_in_place` now covers `opencode`, `pi` and `claude`; `codex` and
  `grok` keep the restart. The module comment and the kind test are updated.
- `switch_model` branches on the kind. OpenCode keeps its session-API path
  unchanged. pi and Claude take `switch_by_command`:
  - waits for an idle agent exactly as the OpenCode path does (observation,
    then `agent_get`; a busy/unknown agent is waited for, never typed into);
  - types `/model <model id>` in one `pane_type` call, `type_settle`, then the
    `enter` key (`type_command`); the id is the chain entry's model as passed
    in (for pi `<provider>/<model>`);
  - confirms when the last `profile.tail_lines` lines (the footer) contain the
    model's bar label (`footer_confirmed`); an already-correct footer is
    `Already` and sends nothing;
  - a footer that does not show within `WAIT_TICKS` gets one more typed
    command; after the second `WAIT_TICKS` without confirmation the plan is
    cleared and the outcome is `Failed`.
- `quota::settle_switch` falls back to today's restart on `Failed` for pi and
  Claude: `restart_target` builds the chain entry's model on the seat's own
  CLI (with its args), and `restart::advance` takes over. OpenCode still flags
  the seat (a restart cannot carry a model through its shared service).
- The durable plan still stores `api-confirm` for every kind; `Pending`'s
  `tries`/`waited` carry the typed command's two tries and its footer window.

## Tests

`make check CRATE=gear-engine TESTS='test(switch::) | test(restart::)'` —
52 tests, 52 passed.

New in `switch.rs`: a pi seat and a Claude seat get `/model provider/new`
typed once plus one Enter and are `Done` when the footer shows the label; a
footer that never shows it is `Failed` after two typed commands; an
already-correct footer is `Already` with nothing typed; a busy pi agent is
never typed into. The kind test now lists pi and Claude as in place and codex
and grok as not.

New in `restart.rs`: a pi and a Claude chain-head model change switch in place
by command and record the model with no restart; a pi footer that never shows
the model fails after two tries and a restart plan takes over.

Existing restart tests that drove a same-CLI pi model change as a restart now
use a change of launch arguments (which keeps the restart path by design), or
a codex CLI change where the test is about the restart state machine; their
assertions are unchanged except the codex `-m` model flag in
`a_lane_that_came_back_on_its_old_model_is_restarted_again`.

Also ran `make check CRATE=gear-engine TESTS='test(quota::) | test(onboard::)'`
— 87 tests, 87 passed — since `quota.rs` changed.
