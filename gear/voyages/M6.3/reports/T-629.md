# T-629 — report

A provider's content refusal is seen (Lawrence M2, 2026-11-06 09:26-09:31Z:
DashScope's content review cut the web lane's output four times, "Output data
may contain inappropriate content", because the zh-CN copy named a channel
stratum; the lane went idle after each and 12 tasks waited; GEAR noticed
nothing).

## What changed

- `crates/gear-herdr/src/profile.rs`: new `Profile.refusal_markers` and
  `ProfilePatch.refusal_markers`; the pi and opencode profiles carry
  `"inappropriate content"`, `"content_filter"`, `"data_inspection_failed"`.
  The other profiles carry an empty list.
- `crates/gear-usage/src/lib.rs`: new `last_assistant_errors` /
  `last_assistant_errors_in`, the error texts of the last two assistant
  records of a session (pi: `stopReason` `error` and `errorMessage`; opencode:
  the record's `error`).
- `crates/gear-engine/src/lane_nudge.rs`: `nudge_stopped_lanes` now takes the
  engine config and the profile table. For an idle lane with an open attempt,
  `refusal_step` reads the seat's round's last session, the profile's usage
  log and the last two assistant records. When both ended with a text matching
  a refusal marker, the lane moves to the next model of its chain through
  `restart::advance` (the restart path the quota path uses; the task
  continues) and one captain item on `refusal:<seat>` names the provider, the
  attempt and the marker. With no next model the item says so and the lane is
  set `Held`. One item per attempt (`engine.lanerefusal.<seat>.<task>.<attempt>`).
- `crates/gear-engine/src/lib.rs`: passes `cfg` and `profiles` to the step.
- `crates/gear-engine/tests/it/lane_nudge_contract.rs`: the two direct calls
  carry the new arguments.

## Tests

`make check CRATE=gear-engine TESTS='test(refusal)'` — 8 tests, 8 passed,
including the three acceptance tests in `lane_nudge.rs` `mod tests`:

- `refusal_two_in_a_row_switches_the_lane_and_opens_one_item`: a pi session
  fixture with two refusals in a row switches the lane to the chain's next
  model (the pending restart plan names `deepseek/deepseek-flash`) and opens
  one item naming `minimax-cn`, attempt 1 and the marker; a second tick adds
  no item.
- `refusal_one_then_a_normal_turn_does_nothing`: a refusal followed by a
  normal turn leaves no restart plan and no item.
- `refusal_with_no_next_model_opens_the_item_and_holds_the_lane`: a one-model
  chain opens the item saying there is no next model and the seat is `Held`.

`make gate` — 2648 tests, 2648 passed (50 s, under the 80 s limit).

## Out of scope

- The refusal detection reads the last two assistant records of the session;
  a refusal that scrolled out of the last two records is not seen.
- The opencode refusal text is read from the record's `error` field; the
  fixture for opencode is not exercised by these tests (the acceptance names a
  pi fixture).
- The lane's return to the first model after a refusal fallback is the quota
  path's `set_fallback` record, which this step does not write (it is private
  to quota.rs); the lane stays on the next model.
