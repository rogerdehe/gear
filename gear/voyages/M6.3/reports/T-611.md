# T-611 — report

A lane's page never names a command its role may not run (M-8226: hull was
shown `next: gear reply ... --resolve` for a captain reply and an engine
nudge; both FORBIDDEN for a lane). Changed `crates/gear-app/src/home.rs` only;
`crates/gear-app/src/mail.rs` was read for the role checks and needed no
change.

## What changed

`fn next_command` in `crates/gear-app/src/home.rs` now takes the seat's role
and, for a lane or reviewer, names only what that role may run:

- a captain reply or instruction it can answer → `next: gear send --kind
  progress --reply-to M-<n> "<text>"` (`gear send` is allowed for lane and
  temp; `gear reply` is captain-only, `mail::reply`'s `require_seat`).
- an item it cannot close (an engine nudge, a station item, a verdict item) →
  `the captain or GEAR closes this`, no command.
- no shown item → `next: gear`, as before.

The captain's page is unchanged: `next: gear reply M-<n> --resolve -m
"<what was done>"`, the station `gear plan apply` line and the verdict
`gear plan apply` line stay as they were.

The "Info item a lane has been shown is marked seen" part already held: the
lane's view records every shown id and `already_shown` filters it on the next
`gear`; a regression test now pins it.

## Tests

  and an engine nudge; the page has no `gear reply` and no `gear plan apply`,
