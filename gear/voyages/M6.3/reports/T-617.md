# T-617 — report

A GitHub issue closes only when its last task lands (an issue split into
tasks closed on the first merge, and the claim PR body said `Closes #n`, so
with `merge = "pr"` GitHub closed it too).

## What changed

- `crates/gear-forge/src/sync.rs`: the "another task is open" fact now reads
  the task state, not the merge time. A task bound to the same `issue:` is
  open unless it is Done or Cancelled. The `:close` call is added only when
  no other task bound to the issue is open (and the task itself has landed,
  so at least one is Done). The landing comment per task stays.
- The claim PR body says `Part of #n` when another task bound to the issue is
  open, and `Closes #n` only when this task is the last open one (all other
  tasks bound to the issue are Done or Cancelled). The claim marker is
  unchanged.

## Tests

`make check CRATE=gear-forge` — 45 tests, 45 passed. New test in
`crates/gear-forge/tests/it/sync_contract.rs`:
`an_issue_with_two_tasks_closes_only_when_the_last_lands` — an issue with
T-1 and T-2 stays open after T-1 lands, and T-1's claim says `Part of #12`;
after T-2 lands the issue closes and T-2's claim says `Closes #12`.

The existing `an_issue_with_another_unlanded_task_stays_open` still passes
(T-2 Ready keeps the issue open), and `a_first_delivery_opens_the_claim_and_nothing_else`
still sees `Closes #12` for a lone task.

`make gate` — 2590 tests, 2590 passed (34 s, under the 80 s limit).

## Out of scope

- A claim PR body is fixed at claim time. A task that becomes the last open
  task later keeps `Part of #n`; the issue is then closed by GEAR's own
  `close_issue` call, not by GitHub's auto-close.
- Two tasks that land in the same tick each add their own `:close` call; the
  second closes an already-closed issue (idempotent on GitHub).
