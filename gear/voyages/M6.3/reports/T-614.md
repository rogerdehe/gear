# T-614 — report

A `carried-by:` line never hides a merge (Prometheus T-779: v1394 set
`carried-by: T-752`, v1395 dropped the line, the mark stayed, and T-752 had
merged before T-779 started; T-779 sat accepted and unmerged 20 minutes).
Changed `crates/gear-app/src/plan.rs` only.

## What changed

- `apply_queue`, the `carried-by:` check: a mark naming a carrier that is
  `Done` and merged is now refused even when the task already has the mark
  (the old `!already` exception is gone). The refusal is
  `"<carrier> has merged: its merge cannot carry <task>'s work; drop the line"`.
- `apply_queue`, the existing-task branch: a block that no longer has a
  `carried-by:` line clears the mark, exactly as `carried-by: -` does (the
  parser gives `Some("")` for `-` and `None` for a missing line; both now
  clear). When a mark is cleared, the apply's `warnings` carries
  `"<task>: `carried-by` cleared (the block no longer names it)"`, which the
  CLI prints after the apply.

## Tests

- `crates/gear-app/tests/it/review_model_contract.rs`,
  `carried_by_is_stored_shown_cleared_and_checked`: updated — a block without
  the line now clears the mark, and a block that keeps a mark naming a merged
  carrier is refused with the new text.
- `crates/gear-app/tests/it/remerge_contract.rs`,
  `dropping_the_carried_by_line_clears_the_mark_and_queues_the_merge` (new):
  a task accepted while carried, its block drops the line; the mark is
  cleared, the apply warns, and `- remerge T-1` then queues the task's first
  merge.

`make check CRATE=gear-app TESTS='test(carried)'` — 3 tests, 3 passed.
`make gate` — 2584 tests, 2584 passed (44 s on this busy machine, under the
80 s limit).

## Out of scope

- The engine's own merge path is unchanged: a task whose mark is cleared still
  needs the captain's `- remerge T-n` (or the engine's retry) to queue its
  first merge, as before. The packet asked only for the plan apply to clear
  the mark.
