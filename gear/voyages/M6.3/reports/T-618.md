# T-618 — report

A landed voyage's worktrees are removed by GEAR (Prometheus had 16 worktrees
in its sidebar, 6 leftovers; Carthage M1's landing named 17 things to remove
by hand).

## What changed

- `crates/gear-engine/src/finished.rs` `reclaim`: after the records merge, for
  each worktree of the project it removes it itself with `git worktree remove`
  when `git status --porcelain` is empty and `git rev-list --count <branch>
  --not --remotes` is 0 (nothing the remote does not have). A dirty worktree is
  named with `uncommitted changes`; one with unpushed commits with `unpushed
  commits`; both are kept.
- For each remote branch of the project (release and staging kept), a branch
  whose tip is an ancestor of the remote integration branch is deleted on the
  remote; one with extra commits is named with `extra commits`.
- For each Herdr workspace of the project, one whose `agent_status` is
  `unknown` (no agent) is closed with `worktree_remove`; one holding an agent
  is named with `holding an agent`.
- The reclaim item now says GEAR removed what it could and names only the
  leftovers with the reason per entry. The main checkout and other projects'
  worktrees are never touched (`project_worktrees` skips the main checkout and
  matches only `<project>-…` paths or `<project>/…` branches).
- `merge_records` returns `Some("merged")` when it merged, even when there is
  no open records item to resolve, so a successful records step is reported.

## Out of scope
