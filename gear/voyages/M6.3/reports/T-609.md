# T-609 — report

T-572 again, on today's dev.

## What changed

The net T-572 change (`12d868ee..refs/backup/t572`, the dev the backup branch
merged) was applied to `crates/gear-engine/src/merge.rs` on today's dev. It
adds, in `run_batch` and the batch collection:

- `RedRound` on a finished batch round: the members, the gate's refusal as it
  printed it, and the same text normalized (shas, run ids and timings taken
  out).
- `note_red_round`: from the first red batch round on, one urgent `System` item
  per project on thread `merge-red:<project>`, opened at once and rewritten on
  every later round — the gate's refusal, the members, the red rounds and
  minutes on the line, and what the captain can do (send the cause back to a
  lane, take a member out with a fail verdict or a cancel, or let GEAR split).
  The halving goes on meanwhile.
- Two consecutive red rounds with different member sets and the same
  normalized refusal stop the splitting: every member is requeued, the batch
  line waits (`engine.merge_red.wait.<project>` remembers how many merge ops
  the project had), and the item says "the same refusal with different
  members: the cause is on <integration>, not in the batch". The line runs
  again only when a merge op is queued anew (a remerge or a new pass).
- A merge that lands closes the item and resets the line (`close_red_line`).

## Fixed for today's dev

- The T-572 tests registered the merge worktree under `p/merge/home`, but the
  code opens `p/merge/between-voyages` for a project with no voyage
  (`current_voyage`'s default), so the fake created a worktree path that does
  not exist and every merge retried on a missing lock. The three T-572 tests
  now register the branch the code opens.
- `the_same_refusal_with_different_members_stops_the_splitting` expected the
  requeued members to be `Unknown`; T-576 made a requeue `Intended` (queued
  again). The test now expects `Intended`, which is the packet's "requeue
  every member".
