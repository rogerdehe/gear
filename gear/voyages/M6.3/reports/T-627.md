# T-627 — report

A feature member's merge never waits behind a full gate.

## What changed (`crates/gear-engine/src/merge.rs`)

- `feature_target` reads a merge op's task: when its `base` is not the repo's
  own integration branch (a member of a feature, `base` naming the feature's
  branch), the merge's target is that feature branch.
- `feature_worktree` opens or creates the feature's own merge worktree,
  labelled `<project>-merge-<feature>` (the feature branch's last name; the
  repo's name is added for a child repo), holding the feature's branch. It has
  its own git directory and therefore its own `gear-merge.lock`, so it runs
  beside the integration train instead of waiting behind its gate.
- `merge_passed` sends a feature-target merge down the single-merge path with
  that worktree; the batch and train paths are skipped for it (a batch or a
  train would need several worktrees for one target). The worker key is the
  repo path plus the target branch, so two members of one feature share the
  key and still take turns in the one worktree, while the integration merge
  keeps its own key.
- `remove_landed_feature_worktrees` runs when a merge is collected: when the
  landed op is a feature's integration task (its `task_branch_override` is the
  feature's branch and its `base` is the repo's integration branch), the
  feature's merge worktree is opened by that branch and removed.

## Tests (`merge.rs` `mod tests`)

- `a_feature_members_merge_runs_beside_an_integration_merge_that_holds_its_lock`:
  the integration worktree's lock is held; the member's merge lands in the
  feature branch on the same tick, dev is untouched, the integration op stays
  `Unknown`, and the feature worktree was opened under `p-merge-f-1`.
- `two_members_of_one_feature_take_turns`: after one tick the first member is
  running and the second is still `Intended`; both land afterwards, in order,
  in the one feature worktree.
- `a_landed_feature_integration_task_removes_the_feature_worktree`: the
  integration task lands on dev and the feature's merge worktree is removed.

## Checks

## Out of scope

- A feature target does not batch or train: members of one feature run one at
  a time in their shared worktree (the packet's "take turns"). A feature's
  members could train among themselves later, with one worktree per stage.
- The feature worktree is removed on the tick that collects the integration
  task's landing; a worktree Herdr no longer has is simply skipped.
