# T-605 — report

[F-3 3/4] The new pane takes the seat, then the old pane closes.

## What changed

### `crates/gear-engine/src/restart.rs`

- `Phase::Close` (new) and `Plan.exit_sent`: a split CLI change no longer ends
  in `Finish`. The `Finish` phase now:
  - moves the seat's agent name to the new pane: the old pane's agent loses the
    seat's name first (`agent_clear_name`, Herdr names are unique), then the new
    agent takes it (`ensure_agent_name`);
  - rebinds the seat to the new pane at the new generation, voiding every older
    binding (as `captain take`'s `rebind` does), and records the model;
  - delivers the Continue (or the reviewer's packet) to the new generation and
    leaves the plan in `Close` — the phase change and the Continue are one
    transaction, so an engine restart never delivers twice.
- `close` (new): the old agent is told to quit once (`exit_command` by name, or
  `exit_keys`; an agent whose name moved gets a temporary `<project>-<seat>-old<n>`
  name so a command-taking CLI can be addressed), the engine waits until the
  pane holds no agent, then closes the old pane last and clears the plan. A
  pane that is already gone is fine; a refused close does not keep the seat.
- `FinishStep` (new): `Done`/`Close`/`Waiting`, so the state machine continues
  into `Close` in the same tick and the probe lines stay as they were.
- The same-CLI restart keeps its old path (same pane, no split, `Done` at
  `Finish`).

### `crates/gear-engine/src/names.rs`

- `switching_old_panes` (new): the old pane of a seat with a split restart plan
  in flight. `live_of_role` leaves it out of the lane/temp quota count — it
  belongs to the seat's own switch, not to a live agent the user sees.
- `name_moves_later` (new): `restore` leaves a seat alone while its plan is in
  `Split`/`Start`/`Finish`; until the name moves, the old pane holds it and the
  new one carries a temporary name, so the pass must not report a taken name.

### `crates/gear-engine/src/review.rs`

- `close_gone_seats` skips the old pane of a switch: the restart's `Close` phase
  closes it, never the stray sweep.

### Tests

- `crates/gear-engine/src/restart.rs` (`config_change_tests`, `tests`,
  `handover_tests`): the split tests now assert the T-605 order — the seat is
  bound to the new pane at generation 2, the name is on the new pane and the old
  agent lost it, the Continue is aimed at the new generation, the old agent is
  told to quit, no pane is closed before it is gone, the plan is in `Close`, and
  the pane is closed last with the plan cleared. New test
  `the_old_pane_is_not_counted_or_closed_during_the_switch`: the quota count
  leaves the old pane out and the stray sweep does not close it (even with the
  seat `Released`). `an_engine_restart_between_split_and_start_neither_splits_nor_starts_twice`
  also proves the Continue is not delivered twice after the restart.
- `crates/gear-engine/src/quota.rs` tests and
  `crates/gear-engine/tests/it/reviewer_quota_contract.rs` follow the new flow
  (the old agent is exited and its pane closed last; the captain's line comes
  when the switch is complete).

## Out of scope

- A model-gate failure in `Finish` (OpenCode without `[switch]` labels) still
  clears the plan and flags the seat; the old agent keeps its pane, so no
  `Close` runs and the old pane stays open until a human looks. That is the
  pre-existing failure path, unchanged by this task.
- The old pane's agent is exited with the profile's goodbye; a CLI with neither
  `exit_command` nor `exit_keys` is ended by the pane's close (no goodbye).
