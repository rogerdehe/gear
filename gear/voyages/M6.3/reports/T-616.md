# T-616 — report

A respawned seat's first GEAR call names its new pane (Prometheus M-11063:
review-1 was rebound to w26P:p1 at generation 976; 11 s later a call from
w26P claimed w26J:p1, two generations back and gone, and was refused once).

## Where the old pane came from

`crates/gear-app/src/identity.rs`: `resolve_env` returned an env that already
carried `GEAR_CTX` unchanged, so the pane in `HERDR_PANE_ID` (an inherited
variable in a process carried across the respawn, or a `--pane` from old text
in the resumed conversation) stayed the claim. `observe_via` then read the
occupant and processes of that old, gone pane and refused.

## What changed

- `crates/gear-app/src/identity.rs`: `resolve_env` now calls
  `resolve_void_pane` when the caller carries a context. If the claimed pane
  is a **void** binding of the same seat (an older generation's pane) and the
  caller really runs in the seat's **active** pane (found by process ancestry,
  `real_pane`), the env resolves to the active binding — the active pane and
  the seat's current generation. A caller in a truly foreign pane keeps its
  claim, and the refusal stays. A seat with no active binding, or a caller
  whose ancestry finds no pane (a daemon CLI), keeps the claim too.
- `crates/gear-store/src/lib.rs`: `void_binding_on_pane(seat, pane)`, one
  query (not one per generation) for "was this pane a void binding of this
  seat at any generation".

The CLI's `resolve_caller` (used by `gear`, `gear send`, `gear reply`, …)
calls `resolve_env`, so the resolved env reaches both `prove_seat` and
`require_seat`.

## Tests

In `crates/gear-app/tests/it/app_identity.rs`:

- `a_call_claiming_a_void_older_pane_from_the_active_pane_resolves`: a lane
  respawned to generation 2 on `w1:p2` (generation 1 void on `w1:p9`, gone);
  a call claiming `w1:p9` from inside `w1:p2` resolves to generation 2 and
  `w1:p2`, and `require_seat` accepts it.
- `a_call_claiming_a_void_older_pane_from_another_pane_is_refused`: the same
  claim from the captain's pane keeps the claim and is refused.

`make check CRATE=gear-app TESTS='test(identity)'` — 39 tests, 39 passed.
`make gate` — 2587 tests, 2587 passed (62 s on this busy machine, under the
80 s limit).

## Out of scope

- A daemon CLI (OpenCode, Codex) whose tools run outside its pane has no
  ancestry to find the active pane by; its `--pane` is the claim, so the fix
  does not apply to it. The packet's case is a pi reviewer, whose ancestry
  finds the pane.
- The refusal report (`report_claim`) is unchanged: a truly foreign pane still
  opens one urgent item naming the real pane.
