## Findings
- F1 [P2, logged] `ensure_integration` uses a plain `git fetch` without `--prune`, so a deleted remote integration branch leaves a stale `refs/remotes/<remote>/<integration>`. On the voyage after a landing, that ref is then read as "present" and the cut is skipped — the worktree is created from the stale (pre-landing) tip instead of the current release. Reproduction: a reclaim deletes `origin/dev`; the local remote-tracking ref survives the next plain fetch; `rev-parse --verify refs/remotes/origin/dev` succeeds, so no re-cut and no Info item. Fix (smallest): in `crates/gear-engine/src/onboard.rs` line ~510, fetch with `["fetch", "--prune", remote]` so the deleted ref is actually missing after the fetch. Not blocking: the acceptance the contract names passes, the stale tip is still on the release branch (an ancestor, since the reclaim deletes only when it is on release), and the literal spec says "missing after the fetch".
