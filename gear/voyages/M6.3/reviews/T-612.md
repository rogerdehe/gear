## Spec compliance
- Misunderstood: "no open attempt" is read as `lane_view(…).attempt.is_none()`. In the dispatch that precedes the nudge, an intended delivery is always accompanied by a `Delivered` attempt (`intend_dispatch` calls `start_attempt` — which writes `state: AttemptState::Delivered` — before it creates the Deliver op), and `LaneView::attempt` returns that `Delivered` attempt as the seat's open attempt (`Ready => attempt.state == AttemptState::Delivered`). So the exact state the task names — a working lane whose delivery "waited" — has `view.attempt.is_some()`, and the guard below clears the busy mark instead of freeing the lane.

## Findings
- F1 [P1, blocking] The Esc never fires in the scenario the task exists to fix. `free_busy_lanes` guards with `if view.attempt.is_some() { clear_busy(store, &seat.id)?; continue; }` (`crates/gear-engine/src/lane_nudge.rs:130`). But when a delivery is intended, a `Delivered` attempt already exists for that task: `intend_dispatch` runs `start_attempt` (state `Delivered`) before pushing the Deliver op (`crates/gear-engine/src/dispatch.rs:1126-1136`, `crates/gear-app/src/tasks.rs` `start_attempt` writes `state: AttemptState::Delivered`), and `lane_view` returns that `Delivered` attempt as the seat's open one (`dispatch.rs` `Ready => attempt.state == AttemptState::Delivered`). So `view.attempt` is `Some`, the lane is skipped, and no Esc is sent. The acceptance test `a_busy_lane_with_no_attempt_is_freed_with_one_esc` passes only because its fixture `intended()` inserts a Deliver op pointing at a nonexistent attempt (no `AttemptRow`), a state real dispatch never produces. Fix: treat only an attempt the lane is actually working as "an open attempt" for this guard — skip when `view.attempt`'s state is `Started` or `Stopped`, not when it is a `Delivered` (unconfirmed) attempt; and make the fixture create the matching `AttemptRow` (`Delivered`, `sent_at: None`) the way `intend_dispatch` does, so the test exercises the real state.
