## T-124 — the cause, found and reproduced: a rule, not a race

The rereview test failed once in a full `cargo test --workspace` run on deck's
T-118 worktree (156 passed, 1 failed) and passed when run alone. It was **not**
load-dependent. Reproduced on this tree (the candidate restored to `abc1234` on
attempt 2, three runs):

    thread 'review::tests::a_rereview_resumes_the_jobs_session' panicked at crates/gear-engine/src/review.rs:3211:14:
    called `Result::unwrap()` on an `Err` value: GearError { code: BadFormat,
    detail: "T-1: candidate abc1234 already failed on attempt 1: rework it and hand
    in a different candidate" }

Three runs out of three fail that way — deterministic, alone or under load. The
cause is **T-118's rule**: `gear_app::tasks::submit_result` refuses a candidate
that already failed on an earlier attempt of the task (`tasks.rs:201-217`), and
the test handed attempt 2 the same candidate `abc1234` as attempt 1. It was seen
once because that run was the first to carry T-118's rule; the re-run that
"passed alone" was made after the test was changed to a fresh candidate
(`def5678`) in T-118 itself (`b184570`), which is in dev.

What the test shares, checked on every channel the task named:

- **The clock** — none. Every timestamp is given (`T0`, `T0+10`, `T0+15`,
  `T0+25`, `T0+30`, `T0+35`) and the review path reads no wall clock.
- **A sleep** — none. The 300 ms typed-input settle is in `switch::text`, which
  is OpenCode-only; this test's reviewer is Codex.
- **A temp path** — none. The reviewer's worktree is the fake's
  (`/fake-worktrees/home-review-1`); `forget_gear_hooks` and `render_args` only
  read a path that does not exist, which gives the same answer every run.
- **A global** — none. No `static`, no `OnceLock`, no environment variable in
  the engine's unit tests; the store is `Store::open_in_memory()` and the Herdr
  is `FakeHerdr`, both private to the test.

So the test cannot be made "independent of load" — it already is. What it does
depend on is a **shared rule** (T-118's candidate refusal), and that is now
written down in the test at the spot where it matters, so a later reader does
not misdiagnose a real rule as a flake. No behaviour change: the test still
hands in a fresh candidate.

## T-127 F5 — no wall-clock sleep in the model-list test

`opencode::start_args` waited between two asks for the OpenCode catalogue with
`std::thread::sleep(model_list_poll_ms)`. The test
`onboard::tests::an_empty_model_list_is_waited_for` set `model_list_poll_ms = 10`
and so slept 10 ms on the wall clock — the last remaining engine test that did.

The fix is the review's smallest one:

- `crates/gear-engine/src/opencode.rs` — the sleep is guarded by
  `if model_list_poll_ms > 0`. A poll of 0 asks again at once; production keeps
  its positive interval (`EngineCfg::model_list_poll_ms` default 500 ms), so the
  behaviour in production is unchanged.
- `crates/gear-engine/src/onboard.rs` — the test's poll is 0. The wait between
  the two asks is then no wait at all: the fake's queued second answer (the
  loaded catalogue) is what moves the wait forward, so the test still exercises
  "the catalogue is empty at first, the lane waits for it and starts" — with no
  sleep. The test's assertions (the lane becomes `Active`, the binding carries
  the session, the same directory is asked again, no model key is typed into the
  TUI) are untouched.

Both `model_list_wait_s` (the bound) and the production poll stay as they are.
