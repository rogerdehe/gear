# T-186 — the fixtures contract is one test per fixture, each built once

Scope: T-186 — `crates/gear-cli/tests/it/fixtures_contract.rs`
`the_fixtures_build_replace_and_pass_their_gates` ran 10.7 s under load
(T-135 review F5). Split it into one test per fixture so nextest runs them side
by side, and build each fixture once per test. Every assertion is kept.

Branch: `deck/t186`; the candidate named in the hand-in carries this report.
Base: `origin/dev` cut for the branch; `origin/dev` merged into it before the
hand-in (never rebased).

## What the time was

The file's one test built **both** fixture projects and then **rebuilt both**
— four builds of a fixture in a single test — and every check of the file
waited for the slowest of them. The checks were never parallel; the file was
one long chain.

The fixture builder had its own cost: `scripts/fixtures/make.sh` runs one git
process per repository, per commit and per origin, and on this machine a git
process costs 40–150 ms before it does any work (measured in T-128). Two
changes to the builder cut that cost without touching what it builds:

- `git init --template=` — the sample hooks and templates git copies into a
  new repository are never used by a fixture, and copying them is a fifth of
  an init's cost.
- The bare origins are built **together** (`multi`'s three, `running`'s one)
  instead of one after another: they wait on nothing, so waiting for them in
  turn was waiting for nothing to wait for.

`make.sh` also learned a second argument — `multi`, `running` or `both` (the
default) — saying which project(s) to build. A run replaces exactly what it
builds; the rest of the target directory is untouched. The acceptance's call,
`sh scripts/fixtures/make.sh <dir>`, is unchanged: it still builds both
projects.

## The structure

Three tests, one per fixture plus the default run the acceptance uses. Each
builds its fixture **once** and reuses it for every check; nextest runs the
three side by side, so no test waits for the other project's build.

| test | what it builds | what it checks |
|---|---|---|
| `the_multi_fixture_builds_replaces_and_passes_their_gates` | `multi` | the parent on `dev` with a local origin and a clean tree; the children `web` and `api` as their own repositories on `feat`, each with its own local origin and a clean tree; the parent ignores the children; the three gates pass; `FIXTURE.md` carries the multi-repo config; the run replaces what an earlier run left |
| `the_running_fixture_builds_replaces_and_passes_its_gate` | `running` | the project on `main` with its own local origin `origins/running.git`, whose `main` was pushed; the CI file, both instruction files, the skill directory, the three stale docs, the exemplar and the bad pattern beside it, the Makefile and the gate; `CLAUDE.md` and `AGENTS.md` say what they must; the gate passes; the run replaces what an earlier run left |
| `the_default_run_builds_both_projects_and_replaces_what_was_there` | both (the acceptance's call) | both projects exist, on `dev` and `main`; both gates pass; both are replaced over what an earlier run left |

Every assertion of the former single test is in one of the three, and the
former test's own "a second run replaces both projects" assertion became the
"the run replaces what an earlier run left" assertion in each of them: the
stale file is planted **before** the run instead of between two runs, which
checks the same thing — the builder replaces the project, it does not build
over it — for one build instead of two.

## Times

Measured today, with the load the machine carried at the time (`uptime` before
each run). The load was **not** idle: this host ran four lanes at once, and
the load average was 30–45 during the runs below. The seconds are therefore
pessimistic; the structure is what the change is about.

`cargo nextest run -p gear-cli -E 'test(fixtures_contract)'`, load 33.68 /
30.96 / 36.47:

| test | s |
|---|---|
| `the_running_fixture_builds_replaces_and_passes_its_gate` | 4.4 |
| `the_default_run_builds_both_projects_and_replaces_what_was_there` | 4.9 |
| `the_multi_fixture_builds_replaces_and_passes_their_gates` | 7.1 |
| **the file, wall** | **7.1 s** (the three run side by side) |

The former single test, under the same load, was **10.7 s** (T-135 review F5)
and every check in the file waited for it.

The same three tests after `origin/dev` was merged into the branch: 2.0 s,
2.3 s, 2.7 s, the file **2.7 s wall** — every part under 3 s.

The builder alone, six runs each, the fastest of the six (load 30–50):
`multi` 951 ms, `running` 849 ms, `both` 995 ms — before this change the same
builder took 1582 ms / 805 ms / 1432 ms.

No test of this file is over 10 s in the whole-suite run below, so none of them
appears in `scripts/slow-tests.allow` (still empty; a lane never adds a line).
