# T-204 — A partial token or cost sum is never shown as complete (contract v1)

Scope: T-204 — in `crates/gear-board/src/lib.rs`, `tokens_of` returns `None`
when any round of the task has all four counted token fields absent, and
`cost_of` returns `None` when any round has `cost_usd = None`. The Time &
tokens view then shows `?` and labels its footer, as it already does for a
task with nothing measured.

Branch: keel/t204 (code @ the hand-in commit; origin/dev merged before the
final verification)

## The bug

The board's Time & tokens view aggregates the rounds of a task. `tokens_of`
counted a task as measured when *any* round had one of the four counted
token fields present, and `cost_of` counted it as priced when *any* round had
a price. A task with a measured dev round and a review round that had
counted nothing (its session log or its model price was not available yet)
therefore showed `812k  $  0.31` and a footer `so far: 0.8M tokens, $0.31` —
a partial sum presented as the task's complete usage and price (F5 of the
T-166 review, `ops/reviews/T-166.md`).

## The fix

- `crates/gear-board/src/lib.rs` — `tokens_of` walks the rounds of the task
  and returns `None` as soon as a round has none of the four counted fields
  (`input`, `output`, `cache_read`, `cache_write`) present: such a round
  counted nothing at all, so the sum hides it. The presence-based rule of the
  measured zero stays: a round with `Some(0)` fields is a measured zero and
  keeps its zero, and a measured round with absent optional cache fields
  stays measured.
- `crates/gear-board/src/lib.rs` — `cost_of` returns `None` as soon as a
  round has `cost_usd = None`: a round that was never priced is unknown, not
  a price of zero.
- Both keep returning `None` for a task without rounds (nothing was measured
  at all), so the behaviour of an unmeasured task does not change.
- `crates/gear-board/src/frame.rs` — unchanged: the view already renders a
  `None` as `?` and labels the footer `(known so far; N unknown)`.

## The tests

`crates/gear-board/tests/it/decisions_contract.rs`:

- `an_unmeasured_round_hides_no_part_of_the_sum` — the fixture's measured
  dev round (812k tokens, $0.31) plus a review round inserted without any
  counted field: the row of the task shows `?` for the tokens and `?` for the
  cost, it shows neither `812k` nor `0.31`, and the footer says
  `known so far`.
- `an_unpriced_round_hides_no_part_of_the_sum` — the same dev round plus a
  review round that counted its tokens (20k in, 2k out) but was never priced:
  the row shows the whole `834k` and `?` for the cost, no `0.31`, and the
  footer says `known so far`.

Both fail on the code before the fix (the row showed `812k  $  0.31` and
`834k  $  0.31`) and pass with it. The existing F5 test
(`the_unknown_usage_is_not_shown_as_zero`) — a measured zero and a task whose
price is unknown — still passes.

## Out of scope

- The voyage report and the landing (`gear report voyage`, v0.4.2) collect
  their own measures; this task changes only the board's aggregation.
- The round panel of the board shows the rounds as they are stored; it never
  summed them.
