# T-141 — a task keeps its repo, `followup-of` is live, the verdict line carries the rework minutes and the why

Scope: T-141 — design §1.1 (a NEW task copies the repo, the base and the gate

names a task that exists), and the verdict line's new fields: `estimate=<min>`

Branch: mast/t141 (code @ the hand-in commit; origin/dev merged before final
verification)

## Rework (attempt 2: F1, F2)

- **F1 (P1, blocking) — the quoted value is the last field.** A verdict line
  carries at most one quoted value (`rework="…"` on a fail, `why="…"` on a
  pass) and it is the **last** field: it runs from its first quote to its
  closing quote, so the prose may contain quotes of its own (a captain quotes
  exact error messages and expected values). The `key=value` fields
  (`estimate=`, `integrated-by=`, `evidence=`) come before it; one after it is
  refused with the order named. The attempt-1 tokenizer split the value at the
  first quote, so `fail rework="return the literal "unknown" on missing
  input"` was refused — a captain could not describe a fix that quotes a
  string.
- **F2 (P2, logged) — an unterminated value is refused.** The attempt-1
  parser invented the closing quote of `fail rework="fix the edge case`; the
  value is now refused (`a verdict line's quoted value has no closing quote`).
