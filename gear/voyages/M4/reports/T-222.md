# T-222 — A new task's packet says how to start its branch (contract v1)

Scope: `crates/gear-engine/src/dispatch.rs` only (plus this report and one
existing engine test that asserted the old wording).

Branch: `mast/t222` (cut from `origin/dev`, the integration branch)

## The bug

The assignment packet of a lane said only

```
Branch: heat/t222 (in your worktree).
```

The lane's worktree is the one the *previous* task used, and it sat on the
previous task's branch. Nothing in the packet said how to get onto the new
task's branch, so a lane could keep working on the old branch: the candidate
carried another task's commits, or work landed on a handed-in branch (M4:
four lanes started a task on the previous task's branch tonight — deck T-197,
keel T-188, mast T-184, keel T-221; friction F-75).

## The fix

`crates/gear-engine/src/dispatch.rs`:

- `first_attempt_text(task, version, branch, integration, packet)` — the
  packet of a **first attempt** (attempt 1). It replaces
  `Branch: {branch} (in your worktree).` with

  ```
  Branch: {branch}. Start it from the integration branch: git fetch origin && git switch -c {branch} origin/{integration} (if it exists already: git switch {branch}).
  ```

  The rest of the packet (design/09 "Delivery content") is unchanged.
- `assign_text(task, version, branch, packet)` — unchanged, and now the
  wording of a **rework** (attempt n ≥ 2): the branch and the worktree are
  already there, so a rework packet says nothing about starting them.
- `integration_branch(tx, project, lane)` — the integration branch the lane
  starts from: the lane's own repo and its integration branch (T-52), else
  the project's `[conventions].integration`. A project whose config does not
  parse falls back to the default convention (`dev`).
- `intend_dispatch` picks the wording by the attempt's number: attempt 1 gets
  `first_attempt_text`, attempt n ≥ 2 gets `assign_text`. The rest of the
  packet (the follow-up line, the project standard line) is untouched.

## The tests

In `crates/gear-engine/src/dispatch.rs` (the engine's own test module):

- `a_first_attempt_says_how_to_start_the_branch` — attempt 1's delivery
  carries the exact command with the lane's branch (`heat/t1`) and the
  integration branch of the project's config (`origin/trunk`).
- `a_rework_keeps_the_old_branch_line` — attempt 2's delivery keeps
  `Branch: heat/t1 (in your worktree).` and names no `git switch`.
- `the_lane_repo_names_the_integration_branch` — a lane bound to a `[[repos]]`
  entry starts from that repo's integration branch (`origin/web-dev`).
- `the_two_packet_writings` — the exact wording of both packets.

`crates/gear-engine/tests/it/dispatch_tick_contract.rs` asserted the old
wording for an attempt-1 delivery; it now asserts the new one (one line and
its import).

## Friction

- The contract's allowed-edit list named `crates/gear-engine/src/dispatch.rs`
  only. The existing engine test
  `crates/gear-engine/tests/it/dispatch_tick_contract.rs` asserts the packet
  text of an attempt-1 delivery, so it had to change with the wording; the
  change is one assertion and one import.
- The worktree carried uncommitted changes in five other gear-engine files
  (`blocked.rs`, `busy.rs`, `merge.rs`, `quota.rs`, `session_runner.rs`) from
  an earlier task. They are not mine and not part of T-222, so they stay out
  of the candidate.

## Out of scope

- A rework packet (attempt n ≥ 2) keeps the old wording: its branch and its
  worktree are the ones of the first attempt.
- The continue packet (a nudge for an attempt already delivered) and the
  reviewer's packet are unchanged.
- The lane's *worktree* is not moved by the engine: the packet tells the lane
  how to start its branch, the lane does it.
