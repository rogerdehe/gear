# T-207 — the reports count the open rounds and show an unknown usage as unknown

Scope: `gear report time` and `gear report voyage` showed the tokens of a
round that is still running as zero (the store counts a round when it ends,
design §4.3), and an unknown usage was printed as `0` (ops/reviews/T-171.md
F9).

## What changed

**`crates/gear-cli/src/main.rs`**

- `open_round_usage` — the counted usage of the **open** rounds of a project:
  every round with `end_at IS NULL` is counted read-only with
  `gear_engine::rounds::count_round(store, cfg, round, now)` at the injected
  `now`, and the count is put in a `gear_app::time::UsageOverrides` map keyed
  by `(task, attempt, role)`. A count that could not be read (the log is gone)
  is **not** put in the map: the round keeps what the store says, which for a
  round that was never counted is nothing — the round stays unknown.
  Nothing is written: the store's columns of an open round are still empty
  after the report.
- `caller_open_round_usage` — the same for the caller's project.
- `run_report_time` takes the `now` it counts at (it used the wall clock
  before) and passes the overrides to `gear_app::time::build_with`;
  `run_report_voyage` passes them to `gear_app::voyage::build_with`.
- `report_cfg` / `builtin_profiles` — the reports count their rounds with the
  built-in agent profiles (each kind's log); `engine_cfg` uses the same
  helper, so there is one list of profiles.

**`crates/gear-app/src/time.rs`**

- `UsageOverrides` — the counted usage of the open rounds: `(task, attempt,
  role) → Tokens`.
- `report_with` / `build_with` / `work_of_with` — the report construction with
  the overrides; the old `report`, `build` and `work_of` stay and call them
  with no override (the integration tests of the crate use them).
- The overrides stand in for the numbers of the round they belong to, in the
  round's own line, in the task's sum, in the lane's sum (`work_of_with`) and
  in the voyage's sum — all of them recomputed from the overridden rounds.
- `Tokens::line` — an unknown usage is printed as `tokens ? / cost ?`, never
  as `0`. A known usage keeps its shape (`tokens 1200 in / 300 out ·
  cost $0.4200`), and a known usage with an unknown cost says `cost ?`.
- `Tokens::add` — the sum of a known round and an unknown one is **unknown**,
  not the known part alone: a number that was not read is not a zero. The
  same for the cost. `Tokens::zero` is the known zero of a round that
  consumed nothing (an attempt with no round, a lane with no round).
- `impl From<&gear_store::RoundTokens> for Tokens` — the store's row becomes
  the report's tokens.

**`crates/gear-app/src/voyage.rs`**

- `build_with` / `report_with` — the voyage report with the overrides; the
  time of the voyage and the work of its lanes are built with them, so the
  voyage's own sum and the per-lane sums carry the open rounds' counts.

## Tests

`crates/gear-cli/src/main.rs` (the CLI fixture tests of the contract):

- `the_reports_count_the_open_round` — an open round with a readable pi
  session log (a temporary JSONL file with one assistant record) shows its
  nonzero counts in the time report (`T-7 attempt 1 dev · tokens 1200 in /
  300 out`, `cost $0.4200`), in the voyage report (`Time and tokens · tokens
  1200 in / 300 out`, `lane heat · tokens 1200 in / 300 out`) and in the
  task's and the voyage's sums; the store keeps the round's empty columns
  (`input` and `counted_at` are still `NULL`).
- `an_unreadable_open_round_is_unknown_not_zero` — an open round whose
  session file is gone shows `tokens ? / cost ?` in both reports, and never
  `tokens 0 in / 0 out`.
- `a_closed_round_keeps_its_counted_numbers` — a closed round shows the
  numbers the store counted (7 in / 8 out), not a fresh count of its log
  (which would say 1200 in / 300 out); the stored row is untouched.

## Out of scope

- The board's own "Time & tokens" tab (`crates/gear-board/src/frame.rs`)
  still shows the stored numbers of a round: it is not one of the two report
  runners of the contract, and it is not in the allowed edits of this task.
- A round whose log can be read but whose window holds no record counts as
  zero (`tokens 0 in / 0 out`): the log was read, and nothing was consumed
  in the window. Only a log that cannot be read is unknown.
