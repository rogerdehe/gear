# T-205 — integrated-by checks exactly what contract v3 of T-165 says

Scope: T-205 — the review of T-165 (F4, F5): the plan's check of the
candidate is an ancestry check, and the named task of an `integrated-by`
attribution must be Done with a confirmed merge op.

Branch: keel/t205 (code @ the hand-in commit; origin/dev merged before the
final verification)

## What was built

### F4 — the candidate must be an ancestor of the integration branch

`crates/gear-app/src/base.rs`: the tree scan (`tree_on_integration`) is
gone. It answered "is the candidate's **tree** somewhere on the integration
branch", so an unrelated commit with the same tree counted as the work that
landed — a rewritten or unrelated candidate was acknowledged as merged. The
fetch of the integration branch stays (the answer must be about the remote as
it is now) and is now `fetch_integration`, which names the ref that holds it.

`crates/gear-app/src/plan.rs`: the check uses the existing `base::contains`
helper with the **candidate as base** and the **fetched integration ref as
descendant** — `git merge-base --is-ancestor <candidate>
refs/remotes/origin/<integration>` — exactly what contract v3 of T-165 asks
for.

### F5 — the named task must be Done, with a confirmed merge op

`crates/gear-app/src/tasks.rs`: `require_merged_at` required only a merge
time, so a task that was not done (or a task whose merge op never
confirmed) could be named as the merge that landed the work. It now requires
the named task to be `Done` and a **Confirmed Merge op** for the attempt that
gives the merge time. Both settlement paths (the first pass and the
attribution that arrives after the attempt was accepted) call the same
function, so both are covered.

## The tests

`crates/gear-app/tests/it/integrated_by_contract.rs`:

- the fixture's accepted case now creates a genuinely Done task with a
  confirmed merge op;
- `a_commit_with_the_same_tree_but_no_ancestry_is_refused` — a commit with
  the same tree as the candidate, but no ancestry, is refused (the old tree
  scan accepted it);
- `a_candidate_that_is_an_ancestor_of_the_integration_branch_is_accepted` —
  the candidate is an ancestor of the integration branch even when the branch
  has moved on since;
- `a_pass_naming_a_task_that_is_not_done_is_refused`;
- `a_pass_naming_a_done_task_without_a_confirmed_merge_is_refused` — the
  merge op is not confirmed, so the merge time is a leftover, not a merge.
