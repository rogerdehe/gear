# T-191 — an ended tail stays ended when the Decisions history is replayed

Scope: T-191 — the captain's tail: a tail that has ended is not revived by
replaying the plan's retained `# Decisions` history (T-164 round 2, F2).
Branch: keel/t191 (code @ the hand-in commit; origin/dev merged before final
verification).

## The bug

`record_tail_decisions` (`crates/gear-app/src/plan.rs`) walked every tail line
in the plan's `# Decisions` and wrote the tail state for each one, in turn. The
`# Decisions` history is retained (the plan rewrite keeps the lines), so the
captain's file carries the tail line of every round:

```text
- tail: heat
- tail: heat until=T-1
```

The first line was written as a *new* declaration: it did not match the spent
marker of the tail that had ended, so it wrote `lane-tail:p:heat = 1` — and, not
being spent, it **cleared** the marker. The second line then had no marker to
compare with and wrote the tail again. Replaying the retained history brought a
tail that had ended back, without any new decision by the captain.

## The fix

Every tail line is still validated (a broken one refuses the whole apply), but
only the **final effective declaration** writes:

- the validated declarations are collected first; the last one is the effective
  declaration (a tail line replaces the set of lanes it silences —
  design/05-plan.md, "Tail declaration");
- the spent marker is read **before** this replay writes anything, and the
  effective declaration is compared with it: a declaration that has already
  ended stays ended (the lanes go back to "not tailed", the marker is kept);
- an earlier line in the retained history writes nothing at all, so it can
  neither clear the marker nor revive the tail.

Per lane the tail state is written from that final effective declaration: a
lane the declaration names is tailed, every other lane is not.

## The reading of "the final effective declaration per lane"

The plan's `# Decisions` section keeps the captain's decisions, and the store
holds **one** tail declaration for the project (`lane-tail-until` and
`lane-tail-spent` are one key each, not one per lane). design/05-plan.md
("Tail declaration") says a tail line *replaces the set* of lanes it silences.
So the effective declaration is the last tail line of the section, and it
writes every lane: the lanes it names are tailed, the others are not — the
behaviour the code had before this fix. "Per lane" is read as "the tail
metadata is written per lane, from that one effective declaration"; a reading
in which every lane keeps the last line that names it would contradict the
design and has nowhere to put a different end per lane.

Files:

- `crates/gear-app/src/plan.rs` — `record_tail_decisions` validates every tail
  line and writes only the final effective declaration, comparing it with the
  spent marker as it stood before the replay; the new `TailDecl` holds a
  declaration (its lanes and its end).
- `crates/gear-app/tests/it/tail_contract.rs` — the reopen test now uses the
  real settlement APIs: the lane starts an attempt on T-1 and hands it in, the
  captain passes it (`tasks::settle`), the tail ends (read through
  `lane_in_tail`), the captain's fail verdict reopens T-1 for a rework, and the
  same two decision lines are replayed — the lane stays untailed. A new
  declaration is still a new tail.
- `ops/reports/T-191.md` — this hand-in.
