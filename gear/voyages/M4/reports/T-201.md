# T-201: session retry after a generation change

Session preparation state now records the seat generation and is reused only for the same round and generation. A failed step remains sticky for its original generation; after retry and onboarding create a new generation, preparation starts afresh. Session recovery dispatch, doorbell gating, and the restored-session lookup also account for generation so stale state cannot control the replacement seat.

The fake-Herdr regression drives an ineffective exit through the recovery deadline to NeedsCheck, verifies the failure remains sticky, performs the retry/onboarding transitions, and verifies that the replacement generation reaches Ready without editing stored state.

`scripts/test.sh` passed all 1,169 tests (76 s build, 74 s suite). Concurrent load produced slow-test warnings in existing fixtures.
