# T-167: round token and cost accounting

Closed rounds are counted after their 60-second log-settling interval using their sessions and half-open ownership windows. Missing logs leave tokens unknown and are retried at a bounded interval. The round clock remains under the existing overrun calculation. The read-only `gear_usage::round_usage` API supports live counts without writing the round and is available to the board and report work.

The usage reader retains each record's model for price lookup, uses agent-reported cost where present, leaves the full cost unknown if any record cannot be priced, and refuses to combine inconsistent snapshots when a log changes between reads. The fixture tests exercise resumed sessions, back-to-back rounds, compact work, review sessions, model changes, agent and configured prices, unpriced and missing logs, and late writes.

Project configuration acceptance of `[prices]` is being implemented separately in T-147. Board and CLI report integration are assigned to T-166 and T-171, respectively; the read-only usage API is available to them.

After merging integration through T-161 and T-148, `scripts/test.sh` passed all 1,185 tests (177 s build, 52 s suite). The first two full runs before the integration merge also passed; shared load produced slow-test warnings in existing fixtures.
