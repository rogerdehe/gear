# T-195 — the role rules at agent start, profile side

Scope: the profile side of the role rules (user, 2026-10-26: inject the
working rules as a system prompt where the CLI allows it): the
`instructions_args` of a profile, its built-in values, and the rendering of
the placeholders.

## What changed

**`crates/gear-herdr/src/profile.rs`**

- `Profile.instructions_args: Vec<String>` — the CLI flags that carry the role
  rules into the agent as a system prompt. The same shape as
  `unattended_args`, and the config patch may set it.
- The built-in values:

  | kind | instructions_args |
  | --- | --- |
  | pi | `["--append-system-prompt", "{rules_file}"]` |
  | claude | `["--append-system-prompt-file", "{rules_file}"]` |
  | codex | `["-c", "developer_instructions={rules_toml}"]` |
  | opencode | `[]` (the packets carry the rules, T-194) |
  | grok | `[]` (the packets carry the rules, T-194) |

- `render_rules(args, rules_file, rules_text) -> Vec<String>`: `{rules_file}`
  is the rules file's absolute path, `{rules_toml}` the rules text as one
  TOML value (`toml::Value::String(text).to_string()`), so a text with a
  quote or a newline survives the round trip.

**`crates/gear-herdr/Cargo.toml`** — the `toml` crate (the rules text as one
TOML value).

**The test files** — the `Profile` literals name the new field (a struct
literal must).

## Tests

`crates/gear-herdr/src/profile.rs` (unit tests):

- `the_built_in_profiles_carry_the_rules_where_the_cli_allows_it` — the five
  built-in values;
- `the_rules_file_is_rendered_into_the_args` — pi's args carry the file's
  path;
- `the_rules_text_is_rendered_as_one_toml_value` — codex's argument is one
  TOML `key = value` pair, and it parses back to the same text (a text with a
  quote and a newline);
- `a_config_patch_overrides_the_rules_args` — a patch sets the list, and a
  patch without the field keeps the profile's own.

## Open questions

The codex value is rendered by `toml::Value::String(text).to_string()`: a
text with a newline comes out as a TOML *multi-line* basic string, which
parses back to the same text. The contract names that call, so it is the
contract's wording; a codex that wants a one-line basic string would need a
different rendering.
