## Findings
F1 [P1, blocking] Confirmation can reuse a pre-signal reading after the signal read fails — `crates/gear-engine/src/quota.rs:765` (also count_error_tick at :1440 and the cache check at :1192). Quota ticks and error ticks both call signal_start with the same `engine.quota_signal.<seat>` key; the absent flag writes zero. For an error-only stop, the first tick writes the new start and attempts the read, but the next tick's absent quota flag clears the start before error confirmation. With a previous successful quota-left reading and a failed new read, `since=0` then admits the old reading, incorrectly taking the five-minute provider-error wait instead of the unreadable quota_reset_h park. A previous spent reading can likewise supply an obsolete reset. This leaves attempt 1 F1 unresolved for normal source failures and breaks §9.2 and the STABLE normal-use bar. Smallest fix: give quota and error episodes separate start keys in signal_start/count_quota_tick/count_error_tick (or update a single combined signal episode once per tick); preserve the active episode start across confirmation and use it for freshness. About 10–20 lines in quota.rs plus fake-reader regressions for quota-only and error-only signals with a cached reading followed by a failed signal read; assert the old reading never decides the park and confirmation still respects the episode start.
F4 [P1, blocking] Codex polling can read a released reviewer's obsolete session indefinitely — `crates/gear-engine/src/quota.rs:1088`. codex_session returns the first seat sorted by id whose profile is codex and binding has a session_ref, without checking role, seat state or binding status. release_one deliberately retains the session_ref while marking the binding Void and the seat Released. Thus a released codex-1 is chosen ahead of an active codex-2 in ordinary reviewer turnover; the immutable old rollout is repeatedly presented as a new reading (`read_at=now`), hiding current usage/reset values. The independent fake-reader probe reproduces this with exactly those two seats. This leaves the current-session part of attempt 1 F4 unresolved and breaks §9.1 plus the STABLE normal-use/usability bar. Smallest fix: in codex_session, select a current Temp reviewer with an Active binding of kind codex, prioritizing Active reviewers over eligible Standby reviewers and excluding Released/Void bindings (use binding kind rather than requiring the literal profile name). About 15–25 lines in quota.rs plus a fake-reader test with a released earlier-id reviewer and an active current reviewer, asserting the latter's session is passed; when no eligible reviewer exists return None rather than reuse a released session.
