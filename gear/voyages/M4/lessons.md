# M4 lessons

What M4 taught, recorded as it happened. A lesson holds for this voyage; only what the release review distils into the shipped skill (`skills/gear/`) carries over. Numbers are the ones lessons had in the old shared file, so earlier references still find them.

28. **Watch each task's clock, not only the fleet's pace.** At every station the captain compares each open task's work time with its estimate and looks at its commits; a task past 1.5× gets the overrun question at once. (M4: hull spent ~4 h of work on a 45 min task with no commit before the captain looked; the station only showed fleet pace.)

29. **Ask before you reset.** A lane past its time is first asked what it has done, what it weighs and what it needs; its context is reset only on its answer and the facts (diff, commits), never on one screen of its thinking. (M4: the captain gave keel a fresh session from one screen of reasoning, and restored it when the user objected.)

30. **A lane that thinks is a contract that failed.** Lanes implement and never design; a doubt goes to the captain at once as a question with a default. When a lane starts weighing, the captain looks first at its own packet and design text for the gap. (M4: hull spent 251 min and keel 2 h thinking on four contradictions and one unspecified sender in the captain's T-143 and T-160 texts; neither asked.)

31. **A decision that changes a contract goes into the contract.** A captain message to the lane is not enough: the reviewer judges the packet. Bump the task's contract in the plan with the decision (and tell the lane). (M4: T-143's reviewer had to ask whether M-2603's four decisions overrode contract v1.)

32. **Watch the machine, not only the fleet.** A long voyage shares one machine with builds, reviewers and the user's other work; the captain checks load and orphan processes when anything feels slow, and GEAR is to watch them itself (M5). (M4: load 159 and two orphaned `find /` scans; the user noticed first.)

33. **Match the task to the model.** MiniMax Flash finishes small, crisp tasks; on engine work that spans several modules it reads and thinks for hours without writing code (M4: T-143 on hull's pi, T-160 and T-152 on keel, each 2-4 h with no commit; Codex Terra did T-143's rework and T-145/T-146 within the hour). Put cross-module engine tasks on the stronger lane from the start; measure, then move after 30 min without a commit, not after hours.

34. **A stopgap watch must keep running by itself.** A check the captain re-arms by hand lapses the first time the captain is busy (M4: the 15-minute lane scan ran 19:30-20:16, then only by chance, and keel's T-152 went 2 h without code unseen). Run it as one loop that wakes the captain and is re-armed on each wake, until the engine does it.

35. **A pi lane that fails every turn has lost its session writes; restart the process.** Pi saves a message only after every extension's message_end handler returns; when one hangs or fails (here most likely pi-lens, which runs clippy, cargo check and LSPs at turn end and fights the lane's own build for the target lock), nothing is saved and each later turn ends with `Extension "<boundary>" error: turn_end could not resolve the persisted assistant entry ID`. Neither /new nor /resume recovers it; restarting pi with `--session <id> --model <lane model>` does (M4 19:24 and 01:25). Always pass the lane's `--model` on a hand start: without it a new session falls back to settings.json's defaultModel (opencode-go deepseek here).

36. **A change to how agents start is proven by a real start.** T-195 put the role rules into the Codex command line and passed every unit test, then broke every Codex start on the live fleet twice: Herdr refuses an argument with a newline, and the command Herdr types into the shell is cut near 1024 bytes (M4 05:30-06:00: all four reviewers and hull down, no reviews or merges for half an hour). A task that changes the start command, its arguments or its injected text accepts only after one real `herdr agent start` of that profile in a scratch pane; keep injected text in a file and pass a short pointer.

37. **A refused hand-in stops the lane; watch every in-flight state.** hull's T-175 hand-in was refused twice because dev moved during its 12-minute suite; it ended its turn and sat idle for two hours (M4 06:46-08:40). The engine's nudge was not live yet, and the captain's watch looked only at Started attempts, while this one was Delivered. A stopgap watch covers every state a lane can hold a task in, and a gate that a lane can fail by no fault of its own (a moving base) needs a window, not a retry loop (T-221).

38. **A Flash lane keeps polishing after its bar is met; the bar must be a checkable end.** Three times on M4 a MiniMax lane went on well past its estimate refining work that already met its contract: deck re-timing builds for an "idle machine" number it could not measure (T-186, 136 min against 25), keel polishing a report after its hand-in, mast counting existing clippy warnings (T-220, 59 min against 10). Write accept lines as an end the lane can check today (a test, a structure, a command that passes), never a number the machine state decides; when a lane runs long with its accept met, interrupt it and say "hand in now".

39. **A scope decision that reverses a cut puts the cut back, and the landing names what moved out.** The user kept M4's full scope at 20:03, but six tasks cut at the earlier stations M-2503 and M-2572 (T-176, T-180-T-183, T-185) stayed cancelled, and the landing said "all 85 tasks done" without naming them (M4 landing, 11:40). When the user overrides a cut, restore every task cut under the old rule the same hour; a landing summary lists each cancelled or moved task with its reason before anything else.

40. **"Build it to the prototype" is accepted against the prototype, side by side.** The M4 board contracts said "copy its layout"; every lane, reviewer and the captain checked layout and data, and nobody ran the prototype next to the real board, so all of its colour was dropped and a lane name longer than the column runs into the goal ("rewriteGive"). The user saw it on the first real voyage (2026-10-28). A contract to match a prototype lists what must match (layout, colour per state, column widths) and its acceptance is one screenshot of each next to the other. Deeper (2026-10-28, at M5's board design): a screenshot is still a person's eye, and the details lived only in the prototype's code. The prototype must be the test: golden frames with colours exported from it, compared cell by cell by the board's tests; each prototype change maps to a task; each view is shown to the user next to the prototype before the next starts. And a mismatch found after landing is a task in a voyage, not a captain's own fix (the M4 colours were patched by a captain's subagent).
