# T-437 — report

A mechanical task's packet no longer tells the lane to run the merge gate
itself: the Review line now says the engine runs the gate at the merge and that
the lane runs only the acceptance commands above the line.

## What changed

Two files, no other change:

- `crates/gear-app/src/plan.rs`, `fn render_task_packet`: the mechanical line
  becomes exactly

  ```
  Review: none — mechanical ({reason}): the engine runs the merge gate at the
  merge, and it is the only check; run only the acceptance commands above,
  never the gate yourself.
  ```

  (one line in the packet; the wrap here is the report's). The comment above it
  now says why the lane does not run the gate (T-437), alongside T-272's note.
  The surrounding packet and every other line are untouched.
- `crates/gear-app/tests/it/packet_contract.rs`,
  `a_mechanical_task_says_the_gate_is_the_only_check`: asserts the new line
  verbatim and, per the acceptance, that the mechanical packet no longer
  contains `run its command before you hand in`. That negative assert is the
  deliverable bar: the old sentence is gone from the packet, not merely joined
  by a new one. The doc comment gained T-437's sentence.

No other packet rendering changed: a reviewed task still says nothing about the
gate, and the plain-path asserts of the same test are unchanged.

## Acceptance

```
$ git fetch origin   # hull/t437 cut from origin/dev
$ make check CRATE=gear-app TESTS='test(packet_contract)'
     Summary [   0.069s] 9 tests run: 9 passed, 558 skipped
exit=0
```

The filter is the packet's `packet_contract` as a nextest filter; the bare
string is not a filterset and nextest refuses it, so `test(packet_contract)`
is what ran. `make gate` is the engine's, at the merge: not run here.

## Friction

The packet writes the TESTS value as `'<a nextest filter: packet_contract>'`.
The literal `packet_contract` is not a nextest filterset expression and
`make check` fails with `failed to parse filterset`, which cost one round trip.
The filter that works is `test(packet_contract)`. Not a permission or a slow
build, so no `--friction` on the hand-in; logged here.

- `docs/releases/v0.5.1.md` (release note) and `gear/voyages/M5/plan.md`,

  They are history — the packet allows these two code files only — but a reader

- Nothing tells the lane, elsewhere in the packet, not to run the gate: the
