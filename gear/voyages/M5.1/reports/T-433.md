## The change (the captain's commit, cherry-picked)

`de48e4fb` — `bcdc8d0a` cherry-picked onto `hull/t433` with no edits
(`git cherry-pick bcdc8d0a`, 20 insertions, 16 deletions in the same two
files):

- `crates/gear-engine/src/restart.rs`, `finish`: the seat's transition to
  `Active` is skipped when onboarding already made it `Active` **on the plan's
  generation** (`row.state == Active && row.generation == plan.generation`);
  the model meta, the quota meta, the cleared plan and the Continue are booked
  as before. Before this, `require_transition(Active -> Active)` was false and
  the finish returned `BAD_TRANSITION`, so the restart never completed.
- `crates/gear-engine/src/quota.rs`, `apply_quota_policy_with`: a pending
  restart's `advance` result is matched — `Ok(Some(line))` is the event,
  `Ok(None)` is a step that waits, and `Err(e)` becomes the event
  `"<seat>: restart step failed: {e}"`. One seat's failed restart step no
  longer aborts the project's quota tick.

## The tests

`crates/gear-engine/src/restart.rs`, new `#[cfg(test)] mod tests` (a fixture of
its own: a project with one opencode lane `heat`, its task `T-1` started, and
`PANE`; the module sits beside the existing `config_change_tests`):

- `finish_accepts_a_seat_onboarding_made_active_on_the_plans_generation` — a
  real restart onto **another CLI** (opencode → claude, model `gpt-6.1-sol`):
  the plan begins (exit keys), the old agent goes, one refused start leaves the
  generation reserved and the plan in `Phase::Start`; the test then sets the
  seat `Active` on that generation, as onboarding does. The next `advance`
  finishes: `Ok(Some(line))` (no error), `pending` is `None`, the model meta is
  the plan's model, the seat is `Active` on the plan's generation, and the open
  attempt gets exactly one `Deliver` op (task `T-1`, attempt 1, the plan's
  generation, `Intended`) — the same op it gets on the `Starting` path.

`crates/gear-engine/src/quota.rs`, `mod tests`:

- `one_seats_failed_restart_step_does_not_stop_the_other_seats_quota_step` — a
  project with two lanes. `heat` (chain ends on codex) has a pending restart:
  the limit is confirmed, the agent exits, one refused start reserves the
  generation, and the seat is then **retired mid-restart** — `Active` can no
  longer be reached, so its finish fails. `glow` (a one-model chain of its own,
  its quota tick counted once before) is the seat the quota step acts on. In
  one `apply_quota_policy` call: it returns `Ok`, `events[0]` is
  `"p:heat: restart step failed: …retired -> active"`, `heat`'s plan is still
  pending, `events[1]` is `glow`'s own park line and `glow` is `Parked` — the
  other lane was handled in the same call.
