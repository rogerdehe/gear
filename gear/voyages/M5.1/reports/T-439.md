version strings and one new release file, as the packet says.

## What changed

- `Cargo.toml` — `[workspace.package] version`.
- `Cargo.lock` — the nine workspace crate entries (`gear-app`, `gear-board`,
  `gear-cli`, `gear-engine`, `gear-forge`, `gear-herdr`, `gear-model`,
  `gear-store`, `gear-usage`), as `cargo build --release -p gear-cli` rewrote
  them; no other entry changed (the unrelated `sqlite-wasm-rs 0.5.5` was
  already 0.5.5 and is untouched).
- `herdr-plugin.toml` — `version`.
- `README.md` — all three version strings it names: the Status line (which now
  points at `docs/releases/v0.5.5.md`), the `herdr plugin install … --ref`, and
  the `gear --version` check line.

New `docs/releases/v0.5.5.md`, in the form of `docs/releases/v0.5.4.md`: a
one-line intro, then one bullet per task merged on `origin/dev` since `v0.5.4`
with its T-number and what it changed for a user (from the task's goal), the
`## Skill` section ("Nothing outside the tasks above."), and the `## Upgrading`
section (0.5.4 → 0.5.5, `gear admin stop`, plugin install, any `gear` call).

The tasks merged on `origin/dev` since `v0.5.4` at the hand-in
(`git log v0.5.4..origin/dev --grep='^merge(T-'`) are T-438 alone — it is in the
notes:

- T-438 — the review packet names the exact `git push <remote>
  HEAD:refs/heads/<branch>` command, and a full review's verdict checks that
  `<remote>/<branch>` holds the reviewer's commit before anything is stored, so

Nothing else was touched; the captain merges `dev` into `main`, tags `v0.5.5`
and publishes.
