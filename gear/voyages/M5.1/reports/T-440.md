# T-440 — report

A lane can now wait on something outside GEAR (a CI run, evidence the captain
must fix): `gear send --kind blocked --on external "<what you wait for>"`. The
wait is written on the task like a wait on another task, so `quiet.rs`
(`crates/gear-engine/src/quiet.rs`, `eligible`/`loop_attempt` →
`waits::waiting_seat`) asks the lane no no-push question while it lasts, and
`crates/gear-engine/src/waits.rs::reconcile` ends it — on the lane's next word
on the task, or after 120 minutes with an instruction to push what it has.
Nothing else changed.

## What changed

- `crates/gear-app/src/mail.rs`
  - New `pub const EXTERNAL_WAIT_MIN: i64 = 120` and
    `pub fn external_wait_key(project, task)` →
    `engine.wait_until.<project>.<task>`: one place for the cap and the key,
    read by both crates.
  - `fn declare_wait` takes the message body and branches on `on == "external"`:
    the trimmed body is required (empty → `BadFormat`, nothing stored); it
    writes `wait_on = "external"`, `wait_cond = "external"`, opens the `wait`
    pause with the reason `waiting for: <body>`, sets the meta key to
    `now + 120 min`, and inserts one Info item for the captain:
    `"<lane> waits on <task> for: <body> (at most 120 min)"` (kind `system`,
    thread `wait-external:<task>:<attempt>`, not urgent, so nothing is typed
    into a pane). `--on T-<n>` is untouched: `wait_on = <T-n>`,
    `wait_cond = "merged"`, the pause reason `waiting for <T-n>`, no meta key,
    no extra item.
  - The `blocked` field check now says `--on T-<n>|external`, and the doc of
    `send`/`declare_wait` names the external wait.
- `crates/gear-engine/src/waits.rs`, `fn reconcile`: a task whose `wait_cond`
  is `"external"` ends its wait — `clear_task_wait`, `close_pause`, the meta
  key emptied — when the lane sent any later message on that task other than
  `blocked`, or when `now` reached the time in the meta key. On the time-out
  alone the lane gets the packet's instruction
  (`GEAR: your external wait on <task> ended after 120 min. Push what you have,
  or declare the wait again with its reason.`, urgent, thread
  `wait-external-end:<task>:<attempt>`). A `"merged"` wait keeps its merge
  ending exactly as before, and every wait still opens its pause, resolves
  stall notices and voids a delivery intended before it.
- `crates/gear-cli/src/main.rs`: the `--on` help is now
  “Blocked only (design §5.3): the task the lane waits for (T-N), or
  `external` with the reason as the message”.
- `skills/gear/references/rules/lane.md`: one line after the no-push line, as
  the packet words it. `gear_engine::rules::LANE` includes that file, so the
  rule reaches every lane's `rules/lane.md` with no second copy.

## Tests

- `crates/gear-app/tests/it/app_send.rs` (the wait tests of the send path):
  - `an_external_wait_is_stored_with_its_reason_and_capped_at_two_hours` — the
    task carries `("external", "external")`, the pause is open with the reason,
    the meta key is `now + 7200`, and the captain has exactly one Info item
    with the packet's wording.
  - `an_external_wait_needs_its_reason` — `""` and `"   "` are refused with
    `BadFormat`, and nothing is kept (no task wait, no meta key).
  - `a_wait_on_a_task_is_unchanged` — `--on T-8` still stores
    `("T-8", "merged")`, writes no external clock and no external item.
- `crates/gear-engine/tests/it/waits_contract.rs`:
  - `a_later_message_ends_an_external_wait` — a second `blocked` message does
    not end it; a `progress` one does (pause closed at the tick's time, meta
    key emptied, no time-out instruction).
  - `an_external_wait_times_out_with_an_instruction` — still waiting one second
    before 120 min, and at 120 min the wait is gone, the instruction is the
    packet's text, it reaches the lane's pane and it is sent once.
  - `a_merged_wait_keeps_its_own_ending` — 200 minutes on a wait for T-2 still
    waits, with no external instruction.
- `crates/gear-engine/src/quiet.rs` (`mod tests`):
  `an_external_wait_keeps_the_no_push_question_off_the_lane` — three hours of
  external wait raise neither the lane's question nor the captain's alarm; once
  the wait is cleared the clock runs from the end of the wait (nothing at
  1199 s, the question at 1201 s).

## Out of scope (noticed, not changed)

- `crates/gear-board/src/idle.rs:143` picks the queue task with a `wait_on` and
  formats `waiting for {on} (...)`; on an external wait `on` is `"external"`,
  so the board reads "waiting for external (…)" and `lane_and_stage` looks up a
  task named `external`. It does not panic, but the board's wording for the new
  wait is now misleading. The packet allows the files it names only.
- `crates/gear-app/src/plan.rs::clear_wait` (a contract bump or a re-lane of
  the task) clears `wait_on`/`wait_cond` and closes the pause but leaves the
  `engine.wait_until.<project>.<task>` key behind. It is inert — the engine
  skips a task without `wait_on`, and the next external wait overwrites it —
  but it is a stale time left in the store.
- `docs/` and the design text still describe `--on` as another task only; the
  packet's four files did not include them.
