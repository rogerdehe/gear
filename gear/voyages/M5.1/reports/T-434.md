# T-434 — report

A session step now types its command and presses Enter in the same call, so a
long tick or an agent that looks busy right after the text can no longer leave
`/new` or `/quit` typed and unsent. The two terminal steps that type a session
command submit it themselves: the `initial` step of a session action and the
resume fallback, `fallback_exit`.

## What changed

`crates/gear-engine/src/session_runner.rs` only:

- `fn enter(herdr, pane) -> bool` — `type_settle()` and then `send_keys(enter)`,
  `true` when Herdr took it. Both terminal steps and the two `enter` steps'
  retries share it, so the settle is still what it was (T-127).
- `fn submitted(seat, state, action_name, now)` — the step a submitted command
  waits in (`wait_exit` for a resume, else `wait_action`) with the `t0` and the
  compact `offset` that phase `enter` used to set. The same bookkeeping, now
  reachable from either place.
- phase `initial`: after `pane_type` succeeds, `enter` runs at once. Taken →
  `submitted` (today's `enter` step body). Refused → step `enter`, as today.
- phase `enter`: the text is already in the box, so it no longer waits for the
  agent to be idle or done; it presses Enter on a later call and then does the
  same `submitted` bookkeeping. Its `resume`-with-no-occupant branch is
  unchanged.
- phase `fallback_exit`: after a successful `pane_type` of the exit command,
  `enter` runs at once; taken → `fallback_wait_exit`, refused →
  `fallback_enter`, which stays as the retry step (now via `enter`, which is
  the same two calls it always made).

Nothing else moved: step names, the probe lines `step()` emits and their order,
the exit-key path (profile without `exit_command`), the resume-without-command
path and every wait/bound are as before. `crates/gear-engine/src/session.rs`
and the integration test `tests/it/session_dispatch_contract.rs` changed only in
the tests noted below.

## Tests

`crates/gear-engine/src/session.rs`, `mod tests` (where the crate keeps the
session step tests):

- `new_session_is_typed_and_entered_in_one_step` (replaces
  `new_session_is_typed_then_waits_five_seconds_for_codex`) — one call on an
  idle codex types `/new` and sends Enter; the step is `wait_action` at once
  (never `enter`). The agent turns `Working` right after the text: the next
  call sends nothing and `/new` stays typed exactly once. The five-second
  codex confirmation still ends at `new-unconfirmed`.
- `a_refused_enter_stays_at_enter_and_goes_on_a_later_call_while_working`
  (new) — an `enter` step with a refused Enter (injected) stays at `enter`; the
  next call, with the agent `Working`, sends Enter and moves to `wait_action`
  with `t0` at that call. This is the retry path the initial step falls back to.
- `resume_fallback_types_the_exit_command_and_enter_in_one_step` (new) — an
  idle pi lane's initial step types `/quit` and submits it (`wait_exit`); the
  agent does not exit, so the fallback runs at the 30 s bound and its
  `fallback_exit` call types `/quit` and presses Enter in the same call (the
  last two recorded calls are that `PaneType` and `SendKeys ["enter"]`), landing
  at `fallback_wait_exit`.
- Calls that counted the extra step moved one tick:
  `pi_new_waits_for_changed_session_or_thirty_second_fallback` (the changed
  session confirms at +5, not +6),
  `pi_compact_without_work_finishes_as_keep_after_fifteen_seconds` (+15, not
  +16) and `the_round_row_is_created_once_over_two_calls` (its second
  `prepare_lane` call at +12, inside the five-second wait). The resume,
  fallback-bound and probe tests needed no change in `session.rs`.

`crates/gear-engine/tests/it/session_dispatch_contract.rs`:

- `a_session_switch_to_done_logs_one_probe_line_per_step_and_one_total` — the
  probe lines now read `initial`, `wait_action`, `done`: the Enter leaves with
  the typed `/new`, so the `enter` step is not visited. The old `enter` line
  and its 1 s are gone (`wait_action` now carries the whole 7 s wait).

The acceptance bar: a `new` action types and submits in one call even when the
agent is `Working` afterwards; a refused Enter leaves the step at `enter` and
the next call sends it while the agent is still `Working`; a resume fallback
types its exit command and Enter in one call.

## Out of scope (noticed, not changed)

- `phase == "enter"` has no bound of its own (`fallback_enter` fails at 30 s),
  and the observation-error path still does not list `enter`. That was true
  before this task; with the Enter now sent on the first retry the stuck-switch
  case the packet describes is shorter, but a step that never gets its Enter
  taken is still only bounded by the seat being checked elsewhere. Left as it
  was, the packet names no bound.
- The FakeHerdr cannot refuse only `send_keys` (its `inject_next` is consumed by
  the next side-effecting call, which is `pane_type`), so the refused-Enter test
  seeds the `enter` step rather than refusing inside phase `initial`. The
  initial step's refusal path is the same two calls (`enter` helper) and the
  seeded test covers the retry while `Working`.
