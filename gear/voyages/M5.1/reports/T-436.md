# T-436 — report

GEAR v0.5.4 is versioned and its release notes are written. No code changed: the
version strings and one new release file, as the packet says.

## What changed

Version 0.5.3 → 0.5.4 in:

- `Cargo.toml` — `[workspace.package] version`.
- `Cargo.lock` — the nine workspace crate entries (`gear-app`, `gear-board`,
  `gear-cli`, `gear-engine`, `gear-forge`, `gear-herdr`, `gear-model`,
  `gear-store`, `gear-usage`), as `cargo` rewrote them.
- `herdr-plugin.toml` — `version`.
- `README.md` — all three version strings it names: the Status line (which now
  points at `docs/releases/v0.5.4.md`), the `herdr plugin install … --ref`, and
  the `gear --version` check line.

New `docs/releases/v0.5.4.md`, in the form of `docs/releases/v0.5.3.md`: a
one-line intro, then one bullet per task merged on `origin/dev` since `v0.5.3`
with its T-number and what it changed for a user (from the task's goal), the
`## Skill` section ("Nothing outside the tasks above."), and the `## Upgrading`
section (0.5.3 → 0.5.4, `gear admin stop`, plugin install, any `gear` call).

The tasks merged on `origin/dev` since `v0.5.3` at the hand-in
(`git log origin/dev --grep='^merge(T-' v0.5.3..origin/dev`) are T-433, T-434,
T-435 and T-437 — all four are in the notes:

- T-433 — a restart finishes even when onboarding already made the seat Active,
  and one seat's failed restart step no longer aborts the project tick.
- T-434 — a session step types its command and presses Enter in the same step,
  so `/new` and a resume's `/quit` no longer sit unsent after a long tick.
- T-435 — the overlap check caches each commit pair's diff instead of
  re-diffing it every ten minutes and at every hand-in.
- T-437 — a mechanical task's packet no longer tells the lane to run the merge
  gate itself.

Nothing else was touched; the captain merges `dev` into `main`, tags `v0.5.4`
and publishes.
