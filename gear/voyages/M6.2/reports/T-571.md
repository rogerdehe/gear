# T-571 — a finished voyage sends nothing

The user, 2026-11-05: Lawrence's voyage M1 finished on 2026-11-04 — every task
done or cancelled, every lane retired — yet its new captain was rung again and
again for two branch warnings from 2026-11-03 (M-768, M-777), each doorbell
carrying M1's goal.

**A voyage is finished when none of its tasks is open** — the rule
`tasks_live_of_project` already uses (T-529): a voyage with a task that is not
terminal is open, a finished voyage's tasks are history.

## (1) A finished voyage's items resolve: `crates/gear-engine/src/finished.rs` (new)

A new tick step, right after the station step and before the doorbell is built,
reads each project's finished voyages once (`Sweep`) and resolves every open item
that belongs to one with the result **`voyage <M> is finished`**:

- **items of its tasks** (by `task`): a task's threads, its `merge-failed:<task>`
  and `merge-lost:<task>` items, its `merge-wait:<task>`, its overrun ask;
- **`station:<M>`** — the voyage's own station items;
- **the project-level threads** — `branches:`, `merge-failed:`, `merge-lost:`,
  `merge-wait:`, `overrun`, `stalled` — closed once **no voyage of the project is
  open any more**, because such a thread may be about another voyage while one
  is open.

A finished voyage whose items are already resolved writes nothing, so the step
is quiet on later ticks. Two reads back it, in `crates/gear-store/src/lib.rs`:
`open_messages_of_project` (the project's open and waiting items) and
`tasks_of_voyage` (one voyage's tasks, not every voyage's history). No new
table.

## (2) The doorbell: `crates/gear-engine/src/doorbell.rs` and the tick

- `goal_line` returns None when the current voyage is finished (new
  `doorbell::voyage_finished`), so `with_goal` adds no "Your goal, voyage M1"
  line to a doorbell — the line that carried M1's goal into Lawrence's ring.
  This also covers the single-message `gear send` path in `ops.rs`, which builds
  its text from the same `goal_line`.
- `doorbell_inputs`, in the captain's branch, drops every item `Sweep::why`
  classifies as belonging to a finished voyage: **a project with no open voyage
  is rung only for items a person or another seat addressed to it.** (1) already
  resolves those items before this doorbell is built; the filter keeps a stale
  one the store still holds — an item written by an older engine — from ringing
  again.

## Tests — `make check CRATE=gear-engine TESTS='test(doorbell) | test(merge::)'` → 184/184

In `crates/gear-engine/tests/it/doorbell_contract.rs`:

- **`a_finished_voyage_resolves_its_items_and_rings_nobody`** (the acceptance):
  a project whose only voyage has every task done, with an open `branches:100`
  item and an open `station:M1` item, driven through `gear_engine::tick`. Both
  resolve with `voyage M1 is finished`, `goal_line` is None, and **three following
  ticks create no doorbell op for the captain**.
- **`an_open_voyage_keeps_its_items_and_its_goal`**: the same `branches:` item in
  a voyage with a task still open stays open, the goal line stays, and the tick
  does ring the captain — so the first test's "no doorbell" is not vacuous.

Both halves run through the real tick (FakeHerdr, `EngineCfg::default()`), not
the pure `decide` alone.

Also run, to be sure nothing else moved: whole `gear-engine` crate **1044/1044**,
`gear-store` **97/97**.

## Decisions

- **Project-level threads close only when no voyage is open.** The packet says
  "when a project's voyage finishes"; a project can have an older finished
  voyage and an open one, and a `branches:` or `merge-wait:` item then still
  speaks about live work.
- **The reason names the voyage.** Every item closed by the sweep carries
  `voyage <M> is finished` in its `result`, so a captain reading an old item
  learns why it closed.
- **`goal_line` is fixed, not just the doorbell.** Its other caller (`ops.rs`,
  the single-message text) would otherwise keep naming a landed voyage's goal.

## Out of scope, logged

- Older stores keep whatever items a previous engine left until the tick after
  the release runs (the sweep is idempotent and closes them then); no migration.
- The station step already opens no new stations for a finished voyage
  (T-336/F5), so the sweep and the station step do not fight each other.
- `docs/design/` is untouched.
