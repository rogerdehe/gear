# T-568 — a newer report replaces the older one instead of piling up

## What changed

**(1) `crates/gear-app/src/station.rs`** — `supersede_earlier(tx, project,
thread, newest, keep, now)`: every earlier **open** (or waiting) item of the
station thread resolves with `superseded by <new id>`. Called at both write
sites: the "ready to land" item and the station report. Their bodies are never
rewritten — Superseded says the newest is true now; the snapshot stays readable.

The **landing order is kept open** (`keep` = the id in `{key}:land`): it is a
one-time order ("run `gear report voyage`, review it with the user, then ask
about the lanes") and not a snapshot, so a later report says nothing in its
place — without the guard, the tick that lands a voyage whose done count is a
multiple of three would open the order and the station in the same write and
the order would be resolved in that same tick. The order still supersedes the
reports before it.

**(2) `crates/gear-engine/src/merge.rs`** — the branch sweep writes on
`branches:<now>`, so a project gathered one item per sweep (123 open ones). After
inserting its item, the sweep resolves the project's earlier open items whose
thread starts with `branches:` with the same `superseded by <new id>`.

**(3) `crates/gear-store/src/lib.rs`** — `messages_in_threads_starting(project,
prefix)`: one query by thread prefix (`substr(thread, 1, length(?2))=?2`), since
the sweep's threads differ only by the tick. **No new table.**

Both close the pile that came before them at the next write, so an existing
store heals itself without a migration.

## Decisions and deviations

- **The landing order is not superseded** by a later station report (see above).
  The station report *is* superseded by the landing order written in the same
  tick, since the order is the newest item then — that keeps one open station
  item and one open order at most.
- **A superseded item cannot be closed by its own plan decision any more.** The
  captain answers the newest station; the older ones say why they closed. That
  is the behaviour the packet asks for, and one existing test now says so.
- **Only open items are touched**: an item the captain already resolved keeps
  its own reason (`station <id>: …`), which a later sweep does not overwrite.
