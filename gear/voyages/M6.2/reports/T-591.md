# T-591 — report

A light check is reminded at 5 minutes that it is a stage check, and is never
stopped.

## What changed

`crates/gear-engine/src/overrun.rs` only.

- `stage_check(tx, round)` (new): a round is a stage check when its role is
  `direction` and its task carries a feature mark (`tx.task_feature`, M6.2). The
  feature's integration task is never marked (the plan writes only its branch
  override and `feature_carrier`), so the carrier's review stays a review round.
- `STAGE_CHECK_BUDGET_MIN = 5` — the budget of a stage check is its own five
  minutes, not the task's estimate (`round_budget_min`).
- `stage_check_text(task, feature)` (new): the one prompt, word for word from
  the packet:
  `GEAR: <T> is a stage check of feature <F>, and 5 minutes have passed. Report
  what you found now. If you have a lead that needs more time, reply with one
  line saying why and keep going; the full review comes on the feature's
  integration task.`
- In `process`:
  - the clock runs from the round's own start (`round.start_at`), not from the
    attempt's start, and its stop is never the hand-in: a stage check reads a
    candidate that is already handed in, so `times.handed_in` would close its
    clock before it began.
  - `live` for a stage check is "the round is still open" (`round.end_at` is
    None). This step never ends the round, never sets a result for it and never
    judges it on course: `rounds` (T-515) still closes it when the check's job
    ends.
  - at the budget the seat gets **one** urgent `Instruction` — the same shape
    and thread (`overrun-question:<T>:<attempt>:<role>`) the overrun question is
    delivered in today — and `stage_reminded` is stored, so no second reminder
    is ever written, at any later time.
  - the stage check takes no part in the overrun question's answer path: no
    captain item in `overrun:<T>:<role>`, no clock moved by an answer, no
    no-answer escalation (the 10-minute item and the 15-minute repeat).
  - `stage_check_reply` (new): a `progress` line from the check's seat after the
    reminder (no `--left`/`--blocker` needed) resolves that prompt
    (`progress received`) and so silences the reminder for that round.
- Nothing else moved: `paused_now`/`askable` were hoisted out of the tail (same
  conditions), and `next` is still read *after* the no-answer item moves
  `next_active` — reading it earlier briefly asked a second normal question in
  the same tick, which two existing tests caught.

## Tests (`overrun.rs` `mod tests`)

Fixtures: `stage_check_world()` (T-1 marked `feature: F-1` plus a `direction`
round in a temp review seat beside the world's dev round), `reviewer_line()`
(the reviewer's one-line reply, `meta` None), `round_of(role)`.

- `a_stage_check_is_reminded_once_at_five_minutes` — nothing at 299 s; at 300 s
  exactly one urgent `Instruction` to the check's seat with the text above; then
  ticks at 301/600/1200/3600 s leave it at one, still `Open`, with no item in
  `overrun:T-1:direction`; the round has `end_at` None, `active_s` 3600 and no
  direction result.
- `a_stage_check_reply_silences_the_reminder` — the reply at 320 s resolves the
  prompt (`progress received`); ticks at 600/660/1800/5400/7200 s write no
  second prompt and no captain item; the round stays open.
- `a_normal_round_keeps_its_estimate_budget` — the same member's dev round asks
  at 600 s with the normal words and its estimate (10 min), and a `review` round
  on a marked member keeps the review budget (30 min at 1800 s): the five
  minutes reach nothing but the direction round of a member.

## Noted

- `cargo test -p gear-engine --lib overrun::` (one process, tests in parallel)
  fails `a_tick_looks_only_at_the_rounds_that_can_still_change` and
  `an_ended_round_is_looked_at_while_its_overrun_item_is_open` because `PROCESSED`
  is a process-wide counter every ticking test bumps. That predates this task —
  it fails the same way on the base commit with these tests stashed — and the
  gate's nextest gives each test its own process, where it does not happen.
- A stage check whose five minutes pass while its seat is parked, held, paused
  or waiting on `wait_on` is reminded as soon as it is askable again: the guard
  is the overrun question's own, and the reminder is still one.
