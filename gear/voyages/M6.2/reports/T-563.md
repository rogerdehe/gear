# T-563 — report

A task placed on a lane nobody works is named at apply and in the queue, and a
failed gate leads with its own refusal (prometheus, 2026-11-04: four `now`
tasks went to retired lanes and sat "ready but not delivered" while the server
lane idled).

## What changed

1. **The apply names it** (`crates/gear-app/src/plan.rs`): `retired_lane_warnings`
   walks the project's tasks in plan order and, for every task that is not done
   or cancelled whose lane has no seat in `Active` or `Standby`, pushes
   `warning: T-<n> is on lane <lane>, which is retired: move it to a working
   lane or bring the lane back` into `ApplyResult.warnings` — the list the CLI
   prints next to the run-dry warnings. Read-only: the apply writes what it
   wrote, and the warning never refuses it. A lane this same apply revived
   (T-247: a Ready task names a retired lane again, quota permitting) is left
   out — the apply already printed `start <lane>` for it.

2. **The queue and the board say it** (`crates/gear-board/src/idle.rs`): a new
   `IdleReason::Retired { tasks }` for a retired seat whose lane holds Ready
   tasks, described as `retired: T-a, T-b are on it and will not start` — in
   place of `next T-x is ready but not delivered`. A retired lane with nothing
   ready keeps its normal reason (`nothing left planned`).
   `crates/gear-board/src/frame.rs` (`reason_word`) says `retired` for it.

3. **The failed gate keeps its refusal** (`crates/gear-engine/src/merge.rs`):
   `without_push_noise` drops the lines a push leaves in the gate output —
   `remote: …`, `To …`, ` * [new branch] …`, ` - [deleted] …` — before the
   reason (`gate failed (<gate>):`) is built from the failure lines and the
   tail, so the captain's item and the board lead with the gate's own words.

## Acceptance

- `make check CRATE=gear-app TESTS='test(plan::)'` — 8 tests, 8 passed. New:
  `a_task_on_a_retired_lane_is_named_and_the_apply_stands` (two tasks on the
  retired lane, one on an active lane: two warnings, the tasks are in the
  store).
- `make check CRATE=gear-board TESTS='test(idle::)'` — the filter names the
  module, but the contract tests live in `tests/it/idle_contract.rs`, so the run
  was `test(idle::) | test(idle_contract::)`: 27 tests, 27 passed. New:
  `a_retired_lane_with_ready_tasks_says_they_will_not_start` (text exactly
  `retired: T-1, T-2 are on it and will not start`; with nothing ready the
  reason is `NoWork`).
- `make check CRATE=gear-engine TESTS='test(merge::)'` — 109 tests, 109 passed.
  New: `a_failed_gate_keeps_its_refusal_and_drops_the_push_noise` (an output with
  `remote:`, `To github.com:…`, ` * [new branch]`, ` - [deleted]` and the
  refusal: no noise kept, the refusal last, the FAIL line first).
- Also run because the new `IdleReason` arm is shared with them:
  `test(queue_contract::)` in gear-app (6/6) and `test(feed_contract::) |
  test(imbalance::)` in gear-engine (23/23).

## Out of scope

- `gear queue` and the board still list a retired lane's seat only when it has
  a seat; a lane that exists in the plan but has no seat row keeps the generic
  reason.
- The board's `LaneBoard` skips a retired lane's tasks (`retired.contains(..) =>
  continue`), so the new text shows in `gear queue` and via `idle_reason`, not
  in the board's lane column.
- A task whose lane name has no seat at all (never staffed) gets the same
  "retired" wording: the packet's condition is "no seat in Active or Standby".
