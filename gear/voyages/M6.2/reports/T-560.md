# T-560 — a stalled voyage rings the captain instead of going quiet

## What changed

`crates/gear-engine/src/feed.rs` only.

When `startable_tasks` is 0, the lane items still close with
`no lane has work left to start` (T-232). One thing is added beside them: if the
project's open voyage still has tasks that are not done and not cancelled, one
urgent item for the captain lives on the thread `stalled`.

- **Opened once, updated while the state lasts, closed with the state.** The item
  is the project's one item of that kind (`open_stalled` finds the open | waiting
  System item of the thread); the body is rewritten only when it changed, and
  the tick reports `FeedChange { lane: "stalled", action: "opened" | "updated" |
  "closed" }` like the lane items do. It closes with `a task can start again`
  (the next tick with work in it) or `no task is left in the voyage`.
- **The body.** `voyage <M> is stopped: no lane can start anything, <n> tasks
  left. <up to 5 tasks, each with what it waits for>[ and <k> more]. Plan work
  that moves the goal, unblock or move these, or ask the user to stop the voyage.`
- **What a task waits for** comes from `gear_board::idle` (`idle_reason` and
  `describe`, the same words as the queue), after the task's own facts, which
  are the ones that decide whether it can start:
  1. no lane → `is on no lane`; a lane with no seat → `is on lane <l>, which has
     no seat`; a retired seat → `is on retired lane <l>`;
  2. in progress or in review → `is in progress` / `is in review` (a task
     already underway is not waiting for its lane's queue);
  3. a declared wait → `waits for <task> (<lane>, <state>)`;
  4. a dependency not merged → `waits for <dep> (<lane>, <state>)`;
  5. otherwise the lane's own idle reason: `waits for <task> (...)`,
     `is ready but not delivered`, `waits for lane <l> (held: …)`,
     `waits behind <head> in lane <l>`.
- Tasks whose lane is retired or has no seat count as left and are named, as the
  packet asks. **No new table**; no message schema change.

## Decisions the packet left open

- **The open voyage is `gear_app::plan::current_voyage`** (the latest departure).
  A project with no departed voyage stays quiet: the packet scopes the item to
  "the project's open voyage", and T-232's own test (a running task, no voyage)
  stays green untouched.
- **Which tasks count as left**: the live tasks (`tasks_live_of_project`, so a
  landed voyage's history is out) that are not terminal, of the current
  voyage or of no voyage at all. A leftover task of an older, still-open voyage
  is not named under the newest milestone; it is still counted as left by that
  voyage's own tick.
- **More than five**: the five are named and the rest are counted (`and 2
  more`), so the captain knows the size of what is left.

## Tests

quiet-project ones unchanged:

- `a_voyage_stopped_by_a_task_in_review_names_the_tasks_that_wait_for_it` —
  acceptance (a): every lane idle, two tasks left waiting on a task in review,
  one urgent item naming both with their waits and the review task with its own
  step, and no item on any lane's thread;
- `a_stalled_voyage_rings_the_captain_once_on_its_own_thread` — retired lane, a
  dependency, a held lane; the exact body; a second tick updates, never opens a
  second item;

  removed and the item resolves with `a task can start again`;
- `a_voyage_with_no_task_left_keeps_the_project_quiet` — .(e) no item, no
  changes at all;
- `the_stalled_item_names_at_most_five_tasks` — seven left, five named, `and 2
  more`.

## Out of scope, logged

- The board's own views do not show the `stalled` item: it is a captain item,
  and the packet puts it in the feed.
- `startable_tasks` counts lane seats in `Active | Standby` only, so a project
  whose every lane is parked or held reads as stopped — which is what the item
  says, and the words name the parked/held lane.
- The design documents are untouched: `docs/design/` does not describe the
  `stalled` item yet.
