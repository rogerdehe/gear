# T-548 — report

A red batch names its culprit when the gate says which paths failed (scope 9).
Changed `crates/gear-engine/src/merge.rs` only.

## Part (1), already pushed as d4d0b6fc on hull/t548 (unchanged)

- `pub const GATE_FAILED_ENV: &str = "GEAR_GATE_FAILED"`, documented like
  `GATE_TEMPFAIL_ENV`, and `fn gate_failed_path(dir)` =
  `dir.join(".git-gear-gate-failed")`.
- `fn gate_command` sets the variable beside `GEAR_GATE_TEMPFAIL`.
- `fn run_gate` removes that file before the gate runs, as it does the tempfail
  file, and does not remove it after a failure, so the red batch can read it.
  The gate may write the repo-relative paths of the files or directories whose
  tests failed, one per line.

## Part (2), this attempt

- `fn run_batch`'s red branch, when the reason cannot clear and more than one
  op built: `fn gate_failed_paths(dir)` reads the file once — lines trimmed,
  empty lines skipped, a trailing `/` dropped — and removes it, so a line an
  earlier gate left is never read. `fn matching_paths(listed, changed)` gives
  the listed paths that equal one of an op's `changed` paths or are the
  directory one of them is in.
- Exactly one suspect: that op gets `Report::Failed` with the gate's reason
  plus the line `the batch's failed paths match only <task>'s changes: <the
  matching listed paths>`; every other built op gets
  `Requeue("its batch failed on <task>'s changes: it merges again without it")`;
  the cap is not halved.
- No suspect, several suspects, or no file: the halving of T-547 stands
  (every built op requeued, cap `ceil(built / 2)`).
- A `Clear` reason keeps T-547's rule first: nothing is read and every built op
  is requeued with `single` set.
