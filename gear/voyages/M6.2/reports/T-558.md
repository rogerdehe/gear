# T-558 — report

A review leaves no branch of its own on the remote: the reviewer pushes its
review commits onto the task's own branch, and the merge takes the task branch.

## (1) review.rs and the review packet

- The review packet's push instruction now names the TASK branch:
  `git push {remote} HEAD:refs/heads/{task branch}`, and says the review commit
  goes onto the task branch, GEAR refuses the verdict until
  `{remote}/{task branch}` holds it, and `git pull --no-rebase {remote}
  {task branch}` (a merge, never a rebase) then pushing again is the way when
  the lane pushed meanwhile. The reviewer still works on the review branch in
  its own worktree.
- `prepare_review_tree` no longer force-pushes a review branch onto the remote
  (T-483's push). It still cuts the local review branch at the attempt's
  candidate, so the reviewer's worktree holds the code that was handed in.

## The verdict gate (outside the packet's file list — asked, default A)

The gate that refuses an unpushed review lives in `crates/gear-app/src/mail.rs`
(T-438): it required the reviewer's HEAD on the REVIEW branch of the remote.
With the reviewer pushing the task branch, that gate refused every verdict, so
it now requires the reviewer's HEAD on the TASK branch
(`crate::base::task_branch`). Question M-7736 named this; the default (A) was
taken.

## (2) merge.rs

- `prepare_merge`'s merge source: the task branch (`remote/<payload.branch>`,
  the `task_branch` expansion of the attempt's lane) — with the candidate
  ancestry check kept: the task branch must hold the approved candidate, or the
  merge fails saying so.
- Transition: when the remote still has the old review branch for the task, the
  merge is exactly as before (candidate, then the review branch); that branch is
  still deleted by `close_branches` and named by the sweep.
- A missing task branch (and no old review branch) fails the op with the branch
  named, as the missing-review-branch case did. A restart after the push (the
  candidate already on the integration branch, branches gone) still answers
  "already merged" rather than failing.

## (3) dispatch.rs

The Rework and Resume texts continue the switch sentence with
`, then git pull --no-rebase {remote} {branch}: the review is committed on it`.
`assign_text` gained the `remote` argument for it (the project's
`[conventions].remote`), as `resume_text` already had one.
