# T-567 — report

The board's time line never shows an impossible forecast, and names what can
never merge; the goal box shows every clause (user, 2026-11-04, prometheus M4:
"expected 16716h25m of 50h00m, 16666h25m behind").

## What changed

1. **The forecast says which jobs can never start**
   (`crates/gear-board/src/forecast.rs`): `NO_DEP` (1,000,000 min — the
   prototype's `10 ** 6`) is public now, and `LaneEnd` carries
   `blocked: Vec<(String, String)>`: for every queued job whose dependency no
   job of the queue speaks for (a done-but-unmerged task whose merge keeps
   failing, say), the job and that dependency, in queue order. The forecast of
   the lanes themselves is unchanged: a blocked lane still ends past `NO_DEP`,
   which is what marks it.

2. **The header leaves impossible ends out and names the blocker**
   (`crates/gear-board/src/frame.rs`): `expected_of` takes the max of the lane
   ends **below** `NO_DEP` (the other lanes' forecast, as today) and builds the
   clause `blocked: T-570 waits for T-665, which nothing will merge`, with
   ` (+N more)` when several jobs are blocked — the first such job and
   dependency. The clause is appended (` · …`) to the time line of the folded
   header and of the unfolded one (`with_blocked`). The unfolded header's
   "slowest lane" also ignores lanes the forecast cannot reach, so the lane it
   names is a lane of the `expected` end.

## Rework (attempt 2, review F1 and F3)

- **F1** (`forecast.rs`): `blocked` no longer records every job that can never
  start. A job is recorded only when one of its **own** dependencies is unknown
  to `merged` — a dependency no job of the queue speaks for. A job that waits
  behind another queued job which is itself blocked is not named, so the line
  names the task whose own dependency nothing will merge: X waits for Y, Y
  waits for Z gives `blocked: Y waits for Z, which nothing will merge`, never
  `X waits for Y` (a real queued job called "nothing will merge").
  New test `a_job_blocked_through_another_queued_job_is_not_named` (hull's X
  on a Deps stage, mast's Y queued on Z which no job is: hull has no blocked
  job, mast has `Y waits for Z`). The writer's own cases (T-570 → T-665,
  T-571 → T-665) still pass: T-571's other dependency is a real job.
- **F3** (`frame.rs`): the unfolded header's slowest-lane clause is
  `slowest_lane_clause`, empty when no lane has a forecast — an all-blocked
  board prints no `(slowest lane: )`. New test
  `a_header_with_no_lane_to_name_prints_no_slowest_lane`; the clause's text for
  a real lane is unchanged.
- **F2**: the wording stays as written (` (+N more)`); the review logged it as
  non-blocking and asked for no change.
