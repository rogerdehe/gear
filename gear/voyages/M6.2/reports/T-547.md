# T-547 — report (attempt 2, the rework)

The batch merge (scope 9): with `[conventions] merge_batch` above 1 the engine
merges several passed merges of one project onto the integration branch in one
worktree and gates them once. Changed `crates/gear-engine/src/merge.rs` only.

## The rework, from the review of attempt 1

- **F1** [P1, blocking] `run_batch` now classifies a rejected push exactly as
  step 9b of `land_merge` does before using it: a reason holding
  `non-fast-forward`, `fetch first` or `cannot lock ref` becomes
  `format!("{RACE}{reason}")`, any other becomes `format!("push failed:
  {reason}")`. `single` is set only when `!lost_the_race(&reason)`, and every
  built op is requeued with that reason. Before, `lost_the_race` was called on
  the raw push text, which never carries the `RACE` prefix, so an ordinary race
  always threw the project out of batching.
- **F2** [P3, logged] Each op's `merged <task> into <integration>: ...` line now
  names the commit built for that op (`git log -1 --oneline <HEAD right after
  that op was built>`), not the last op's commit. `fn closed_and_line` takes the
  commit to name: `Some(commit)` from a batch, `None` (its own HEAD) from
  `land_merge`, so the single merge reads as before.
- **F3** stays as it is, as the review said: a batch that collects to one op
  falls through to the normal single path (with `merge_parallel > 1` it reaches
  the train branch, harmless and only reachable with both settings above 1).

## Tests

- `dev_moving_during_a_batch_gate_is_a_race` (new, F1): the gate itself commits
  to `origin/dev` while the batch runs, so its push cannot be a fast-forward —
  one batch is launched and collected, both `O-1` and `O-2` are `Unknown` again
  with a result starting `RACE`, `cfg.merges.single` is empty, and nothing
  landed on dev.
- `two_merges_are_merged_together_and_gated_once` (extended for F2): the two
  ops' merged lines name different commits and each of those is a commit of
  `origin/dev`.
- The rest of the batch tests (one gate run; the red batch halved; a
  conflicting member steps aside) and the existing train and single-merge tests
  pass unchanged.
