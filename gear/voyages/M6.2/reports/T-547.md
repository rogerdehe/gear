# T-547 — report

The batch merge (scope 9): with `[conventions] merge_batch` above 1 the engine
merges several passed merges of one project onto the integration branch in one
worktree and runs the gate once. Changed `crates/gear-engine/src/merge.rs`
only.

## What changed

- `MergeWorkers` gains `batch_cap: Arc<Mutex<BTreeMap<String, usize>>>` next to
  `single`: the batch size a repo's next batch starts with.
- `fn merge_passed`, where `merge_parallel` builds the train: when
  `merge_batch > 1`, PR mode is off and the worker is not `single`, the batch is
  collected the same way (this op, then later ready ops through
  `train_member`, at most `cap` = the `batch_cap` entry for the worker key or
  `merge_batch`) and `fn launch_batch` is called; `merge_parallel` is not
  consulted. A batch of one op falls through to the normal single path (a red
  batch halves the cap, and a cap of 1 runs each merge alone).
- `fn launch_batch`: as `launch_train` (ops set `Executing`, one `TrainOp`
  each) but with the integration worktree (stage 0) and a thread running
  `fn run_batch`; it reports `Report::Train(results)` and stores the cap
  `run_batch` returns for the key. A `single` demand and a panic are handled as
  `launch_train` handles them.
- `fn run_batch`: takes the merge lock, then for each op in order takes
  `before` = HEAD (the remote integration branch for the first), runs
  `prepare_merge` (`base` `None` for the first built op, `Some(HEAD)` after),
  and keeps `changed[i]` = `git diff --name-only <before> HEAD` per built op,
  for T-548 to name a culprit from. A merge whose prepare fails steps aside as
  in `run_train` (Clear: single + Requeue; Merged: as `run_train`; other:
  `step_report`), and the worktree goes back to the last good HEAD before the
  next op. Nothing built: return. Then one `run_gate`.
  - Green: one push as step 9b of `land_merge` (a rejected push requeues every
    built op with the reason, `single` set unless `lost_the_race`), then each
    built op closes its branches and writes its `merged <task> into
    <integration>: ...` line; the cap returned is `min(merge_batch, cap * 2)`.
  - Red with `Blocker::Clear`: every built op Requeue, `single` set.
  - Red otherwise: one op built, that op `Report::Failed` as alone; more, every
    built op Requeue("its batch failed the gate: it is gated again in a smaller
    batch") and the cap is `ceil(built / 2)`.
- The close-and-line tail of `land_merge` (step 10) is extracted into
  `fn closed_and_line`, used by both the single merge and the batch.

  T-2 Confirmed, dev has b and not a.
