# T-595 — report

A voyage with accepted work not yet merged is not finished (M6.2, voyage
handover, bug found while landing M6.2 itself).

## What happened

GEAR M6.2 had every task Done. T-584's merge failed its gate, so its accepted
candidate was not on the integration branch, yet the sweep saw a voyage with no
task that is not terminal and closed both the `merge-failed` and the
`merge-lost` items as "voyage M6.2 is finished". The captain was told the work
was done and nothing would ever merge T-584.

## What changed

- `crates/gear-store/src/lib.rs`: `Tx::unmerged_done_tasks(project)` — the Done
  tasks whose **latest accepted attempt has no merge time**, with the voyage
  each belongs to. One SQL query (the latest accepted attempt per task,
  `merged_at IS NULL`); a voyage audit is left out, it is judged against the
  integration branch and has nothing to merge. Every tick reads it, so the rule
  lives in one place and the three readers cannot drift apart.
- `crates/gear-app/src/station.rs`: `unmerged_tasks` is `pub fn unmerged_tasks`
  (the landing's refusal of a voyage with unmerged work, T-511, read the same
  rule) and now delegates to the store, so the refusal and the sweep agree.
- `crates/gear-engine/src/finished.rs`: `open_voyages` — a voyage is open while
  a task of it is not terminal (T-529, unchanged) **or** its Done tasks hold
  accepted work that is not on the integration branch. `finished_voyages` skips
  every such voyage, so its merge-failed, merge-lost and other items stay open
  and the captain is still rung about them; `Sweep::read`'s `any_open` uses the
  same reading, so the project-level threads (a merge wait, the branch sweep)
  stay open too. Once the attempt carries a merge time the voyage finishes and
  the sweep closes its items exactly as before.
- `crates/gear-board/src/stations.rs`: `voyage_open` answers the same question
  for the home page and the reclaim — open when a task of the voyage is not
  terminal **or** a Done task of it is unmerged (`unmerged_done_tasks`).
- `skills/gear/references/course.md` (§7 table, §9): "Ready to land (every task
  done **and its work merged**)" — a done task whose merge failed is not a
  finished voyage, and the captain lands over merged work, not over verdicts.
