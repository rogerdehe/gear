# T-545 — report

The project setting for the batch merge (`[conventions] merge_batch`).

## What changed

- `crates/gear-app/src/config.rs`:
  - `Conventions` gains `pub merge_batch: u32` right after `merge_parallel`,
    with the packet's doc comment (how many passed merges are merged together
    and gated once; a failing batch is split by the paths the gate names, else
    halved; default 1, each merge gated alone).
  - `impl Default for Conventions` sets `merge_batch: 1` next to
    `merge_parallel: 1`.
  - `validate()`: next to the `merge_parallel == 0` check, `merge_batch == 0`
    is refused the same way (field `conventions.merge_batch`, "must be at
    least one (the default is 1: each merge is gated alone)"), and
    `merge_batch > 1` together with `merge_parallel > 1` is refused as one
    issue naming both fields and both values, with a comment saying why: a
    batch is gated once and so cannot also be a train.
- `crates/gear-app/tests/it/config_contract.rs`:
  - the `Conventions { … }` literal in the first test carries `merge_batch: 1`;
  - `merge_batch_defaults_to_one_and_a_project_may_raise_it` — the default is
    1 and `merge_batch = 4` alone is accepted;
  - `a_merge_batch_of_zero_is_refused` — field `conventions.merge_batch`;
  - `a_merge_batch_above_one_refuses_a_merge_train` — `merge_batch = 3` with
    `merge_parallel = 2` is one issue whose message names both fields and both
    values.
- `skills/gear/references/conventions.md`: the sample block gains
  `merge_batch = 1         # how many passed merges are merged together and gated once (a batch merge); default 1`
  under `merge_parallel`, and the merge paragraph gains the two sentences the
  packet asks for (a batch above 1 merges the passed merges together, gates
  them once and lands them together; a gate may write the repo-relative paths
  of its failing tests, one per line, to the file `$GEAR_GATE_FAILED` names,
  and the task whose changes match them fails while the others merge again).

The engine reads `config.conventions.merge_batch` in the next task (hull); this
task only adds the setting, its validation and its documentation.

## Acceptance

- The default is 1: asserted in the existing defaults test and in
  `merge_batch_defaults_to_one_and_a_project_may_raise_it`.
- `merge_batch = 0` is refused: `a_merge_batch_of_zero_is_refused`.
- `merge_batch = 3` with `merge_parallel = 2` is refused naming both fields:
  `a_merge_batch_above_one_refuses_a_merge_train`.
- `merge_batch = 4` alone is accepted: same test as the default.
- `make check CRATE=gear-app TESTS='test(config)'` — 95 tests run, 95 passed,
  584 skipped (the three new tests pass).

## Out of scope

- The engine half (selection, `launch_batch`, `run_batch`, `batch_cap`) is the
  next task in the plan and was not touched.
- The batch merge has no release note yet; the voyage's release note is not
  this task's.
