# T-577 — report

The `feature:` field and its settings (feature integration, stage 1, part 1/7).

## What changed

- `crates/gear-app/src/draft.rs`:
  - `QueueItem` gains `pub feature: Option<String>` after `carried_by`, with
    the doc comment naming `feature: F-<n>` (`-` clears it).
  - `parse_queue`: the literal `None` for the new field.
  - `parse_queue_field`: `feature` is a known field; its value must be `-`
    (stored as `Some("")`, as `carried-by` does) or `F-` followed by digits,
    and anything else is `BadFormat` naming the line, `\`feature\` is
    \`F-<n>\` …; got "x"`.
- `crates/gear-app/src/plan.rs`:
  - `apply` stores the value with `set_task_feature` on a NEW block and on an
    existing block that names it (a block without the field keeps the feature
    the task has, `-` clears it) — the same shape as `carried-by:`.
  - `show` (`gear plan show`) prints `feature: F-<n>` next to `carried-by`.
- `crates/gear-store/src/lib.rs`, next to `task_carried_by`:
  `task_feature` / `set_task_feature` (`task_feature:{project}:{task}`,
  empty = none), `feature_carrier` / `set_feature_carrier`
  (`feature_carrier:{project}:{feature}`), `task_branch_override` /
  `set_task_branch_override` (`task_branch_override:{project}:{task}`); each
  setter clears on an empty value.
- `crates/gear-app/src/config.rs`:
  - `Conventions` gains `feature_branch: String` (default
    `{project}/feature/{feature}`, constant `FEATURE_BRANCH`),
    `feature_check: Option<String>` (default `None`), `feature_max_tasks: u32`
    (default `FEATURE_MAX_TASKS = 10`), next to `merge_batch`.
  - `validate()` refuses a `feature_branch` without `{feature}`
    (`conventions.feature_branch`) and a `feature_max_tasks` of 0
    (`conventions.feature_max_tasks`).
- `crates/gear-app/tests/it/config_contract.rs`: the `Conventions { … }`
  literal carries the three defaults;
  `the_feature_conventions_default_to_their_own_branch_check_and_cap`
  (defaults + a project naming its own), and
  `a_feature_branch_without_the_feature_and_a_cap_of_zero_are_refused` (the
  two refusals, by field name).
- `crates/gear-app/tests/it/draft_contract.rs`:
  `a_feature_line_is_parsed_and_a_bad_one_is_refused` — `feature: F-3`,
  `feature: -` → `Some("")`, and `x`, `F-`, `F-3x`, `f-3`, `3` refused with
  the line named.
- `crates/gear-app/tests/it/plan_fields_contract.rs`:
  `a_feature_mark_is_parsed_stored_shown_and_cleared` — applied on a NEW
  block, printed by `plan show`, kept by a block without the field, cleared
  by `-`.
- `skills/gear/references/conventions.md`: the `[conventions]` example gains
  `feature_branch`, `feature_check` and `feature_max_tasks`, one-line comments.
