# T-585 — report

A landing merges the captain's records (M6.2, voyage handover, part 2/5).
Engine code, tests and one skill line.

## What changed

- `crates/gear-engine/src/finished.rs`:
  - `landed_voyage` (extracted from `reclaim`'s read closure) returns the
    milestone of the newest finished voyage whose `station <id>: land` order was
    answered in the last day, not just whether there is one — the records step
    is keyed by the landed milestone.
  - `merge_records` / `records_step`: on each reclaim scan of a landed voyage,
    once per landing (`records_merged:<project>:<milestone>`), the captain's
    seat branch (`expand_seat(seat_branch, project, "captain")`) is fetched from
    the project remote. Nothing new on it (already an ancestor of the
    integration branch, or no such branch) → the branch is only deleted, on the
    remote and locally. Commits the integration branch does not have → they are
    merged in the integration worktree with a merge commit
    `records: <project> <milestone>`, `--no-ff`, no gate, no conflict resolved;
    the integration branch is pushed, then the branch is deleted on the remote
    and locally.
  - A conflict, a push the remote refuses, or an integration worktree that
    cannot be opened opens one captain item on thread `records:<milestone>`
    (urgent, naming the branch and the git error), leaves the branch in place
    and leaves the meta unset, so the next scan (every `RECLAIM_EVERY_S`, and
    only within a day of the landing) tries again; the item closes when the
    records land. Another merge holding the worktree lock is not a failure: the
    scan skips and tries later.
  - The reclaim item's body no longer tells the captain to merge the voyage
    records itself.
- `crates/gear-engine/src/merge.rs`: `open_integration_worktree` (the merge
  seat's worktree, opened exactly as every merge opens it), and `merge_lock`,
  `git`, `git_with_lock` made `pub(crate)` for that step.
- `crates/gear-engine/src/lib.rs`: the tick hands `herdr` to `finished::reclaim`.
- `skills/gear/references/course.md` §9, one sentence: the landing merges the
  captain's own branch, so the captain commits and pushes its records before
  landing; only a conflict comes back to it.

## Noted

- The contract's `expand_seat(seat_branch, project, "captain", <milestone>)`
  names four arguments; `gear_model::branch::expand_seat` takes three, and a
  seat branch is per seat, not per voyage — the milestone is the meta key and
  the merge commit, as the rest of the contract says.
- `git branch -D` cannot delete a branch still checked out in the captain's own
  worktree; the remote branch is always deleted, the local one when git allows
  it, and the reclaim item names the worktree that still holds it.
