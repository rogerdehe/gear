# T-570 — report

A pane that holds two seats keeps one agent name (2026-11-05: pane w2:p10 held
prometheus:captain and lawrence:captain; the user renamed its agent
`prometheus-captain` and the engine's name restore set it back to
`lawrence-captain`, so prompts to `prometheus-captain` failed with
`agent_not_found`).

## What changed

1. **`crates/gear-herdr/src/lib.rs`**: `ensure_agent_name_keeping(herdr, names,
   pane, name, keep)` — like `ensure_agent_name_with`, but the agent may keep
   **any** of `keep`; only an agent with no name, or with a name no seat of the
   pane has, is renamed to `name`. `ensure_agent_name_with` delegates with an
   empty `keep`, so every existing caller behaves as before.

2. **`crates/gear-engine/src/names.rs`**:
   - `seats_on_pane(tx, pane)` — every seat, across every project, whose
     `Active`/`Pending` binding is that pane (with the binding's time).
   - `has_open_voyage(tx, project)` — a departed voyage whose work is not all
     settled (the board's "sailing" voyage).
   - `primary_name(store, on_pane)` — the name an **unnamed** agent gets: the
     seat whose project has an open voyage first, then the seat bound first
     (the older T-485 rule), ties by seat id.
   - `kept_on_pane(store, pane)` / `ensure_for(store, herdr, pane, name)` — the
     naming a delivery does before it types: the agent keeps a name of any seat
     of the pane.
   - `restore` uses all of that: it builds the pane's keep-set and the primary
     name, calls `ensure_agent_name_keeping`, and renames nothing whose name
     belongs to a seat bound to that pane. `older_captain_on_pane` (the
     captain-only skip of T-485) is gone: the keep-set covers every seat, not
     just captains.

3. **`crates/gear-engine/src/ops.rs`**: `aim` takes the pane's keep-set and the
   delivery refusal repair names the agent with it (`ensure_keeping`), so a
   delivery to a seat whose pane carries the other project's name does not
   rename it. `execute_intended` and `deliver_doorbell_now` compute the set with
   `names::kept_on_pane`.

4. **`crates/gear-engine/src/onboard.rs`**: the leftover-agent naming uses
   `names::ensure_for`.

## Acceptance

- `make check CRATE=gear-engine TESTS='test(names::)'` — 2 tests, 2 passed
  (new `mod tests` in names.rs):
  - `a_pane_with_two_seats_keeps_one_agent_name`: two captain seats of two
    projects bound to `w2:p10`, the agent named `prometheus-captain` keeps the
    name over three restore passes of each project, and a delivery to either
    seat finds it (`resolve_target` → `Prompt { name: "prometheus-captain" }`,
    and `ensure_for` says `Named`).
  - `an_unnamed_agent_gets_the_open_voyages_seat_name`: lawrence has the open
    (departed, unfinished) voyage, so the unnamed agent is renamed to
    `lawrence-captain`, and the next pass renames nothing.
- Also run, because the change touches them: `test(agent_names_contract::) |
  test(ops::)` in gear-engine — 44/44; `make check CRATE=gear-herdr` — 57/57.

## Out of scope

- `gear-app/src/captain.rs`'s `captain take` still calls
  `gear_herdr::ensure_agent_name` directly: it keeps a name through
  `Ensured::Kept` (T-552) and is the captain's own command, not the engine's
  restore or a delivery.
- A pane whose seats belong to projects the store cannot read falls back to the
  plain rule (rename to the seat's own name) — an observation failure is never
  taken as "the name is fine".
- Only `restore`, the delivery/doorbell naming (`aim`) and the leftover-agent
  naming use the keep-set; restart/health/quota test helpers keep calling
  `ensure`.
- No release note: the packet does not name one.
