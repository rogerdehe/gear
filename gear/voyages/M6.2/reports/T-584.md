# T-584 — report

Seat branches name their voyage (M6.2, seat branch naming, part 1/4).
Model, app, engine code, their tests and two skill lines.

## What changed

- `crates/gear-model/src/branch.rs`:
  - `expand_seat(template, project, seat, voyage)` also fills `{voyage}`; an
    empty voyage fills `BETWEEN_VOYAGES` (`between-voyages`, the text
    `gear_app::captain::BETWEEN_VOYAGES` uses — that constant is now the same
    one, one line), so the name is never `p/hull/`.
  - `SEAT_BRANCH` is `{project}/{seat}/{voyage}`; tests: `{voyage}` filled, an
    empty voyage gives `p/captain/between-voyages`, a template without
    `{voyage}` is unchanged.
- `crates/gear-app/src/seat_branch.rs`: `PREVIOUS_DEFAULT` is
  `{project}/{seat}/home` (v0.6.55's default), settled the way T-565 settles one.
  `settle` now renames a seat's own old branch whether it *stands in the way*
  (`p/hull/home` under `p/hull/home/x`) or merely *beside* the new name
  (`p/hull/home` beside `p/hull/M2`), which is what this change needs; a ref of
  another name that is a folder of the new one is still refused, naming it, and
  nothing is touched. Tests: the previous default is `p/hull/home`;
  `p/hull/home` → `p/hull/M2` (old name gone); a foreign ref in the way named
  and left alone; a checked-out old branch renamed from its worktree; a free
  name settles nothing.
- Every caller passes the project's voyage:
  - `config.rs`: `SAMPLE_VOYAGE` (`"M1"`) next to `SAMPLE_PROJECT`/`SAMPLE_SEAT`
    — `validate` stays pure and expands the seat-vs-lane-branch overlap and the
    placeholder check with it (captain's M-8050); `{voyage}` is an allowed
    placeholder; the clash hint names `{project}/{seat}/{voyage}`; the config
    test is `the_default_seat_branch_is_project_seat_voyage`
    (`p/captain/M2`, `p/heat/M2` in voyage M2).
  - `admin.rs`: `move_seat_branches` takes the voyage and expands both the old
    and the new template with it; `init_with_home` reads
    `gear_app::plan::current_voyage`.
  - `onboard.rs` both sites, `review.rs` (the reviewer's seat branch) and
    `merge.rs` (`stage_worktree`, the merge seat) read `current_voyage`.
- `crates/gear-engine/src/onboard.rs`:
  - `settle_project_seat_branches` keeps the template **with `{voyage}` filled**
    in `engine.seat_branch_settled.<project>` (`{project}/{seat}/M2`), so a new
    voyage's departure settles the lanes' branches again.
  - `plan_onboard` takes the voyage, so a lane's `WorktreeStep.branch` is
    `p/hull/M2`; its unit tests pin `toy/heat/between-voyages` (no voyage in
    their fixtures).
  - New test `a_lane_on_the_previous_default_seat_branch_is_moved_to_the_voyage_branch`:
    a real repository with a departed voyage M2, the lane's checkout on
    `p/hull/home` → it is `p/hull/M2` afterwards, `p/hull/home` is gone and the
    checkout moved with it.
- `crates/gear-engine/src/finished.rs` (T-585, which landed meanwhile):
  `merge_records` expands the captain's seat branch with the **landed
  milestone**, as T-585's own contract says (`expand_seat(seat_branch, project,
  "captain", <milestone>)`); its fixture's records branch (`p/captain/M1`) and
  merge worktree (`p/merge/M1`) take the voyage's names.
- `skills/gear/references/conventions.md`: the `seat_branch` default in the
  table and in the prose (`{project}/{seat}/{voyage}`, one per voyage,
  `between-voyages` when none is under way). `skills/gear/references/captain.md`
  §4: one line — a seat branch names the voyage, a new voyage's departure moves
  the lanes' branches by itself, and `p/hull/home` is renamed rather than left
  beside `p/hull/M2`.
- The test fixtures that pinned the old default across gear-engine (onboard,
  merge, review, rebind, finished, and the `tests/it` contracts that create a
  lane's, reviewer's or merge worktree) carry the new names
  (`.../between-voyages`, or the voyage their fixture departed).

## Noted

- Pre-0.6.55's default (`{project}/{seat}`, e.g. `p/hull`) is no longer the
  previous default — T-565's chain carries one, and this task's contract names
  `{project}/{seat}/home`. A project whose engine has not run since v0.6.55
  (never settled `p/hull` → `p/hull/home`) gets `settle`'s refusal naming the
  ref (`p/hull` stands in the way of `p/hull/M2`) as a captain item, with the
  git command to fix it; every project that ran an engine on v0.6.55 or later
  moved on already. Logged, not blocking normal use.
- `validate` cannot read the store, so its sample voyage is `"M1"` (captain's
  answer M-8050); only the callers that name a real branch read
  `current_voyage`.
- `git fetch origin` failed twice with `Permission denied (publickey)` while
  merging the integration branch in; the third attempt a minute later worked.
  No key, agent, config or remote URL was touched.
