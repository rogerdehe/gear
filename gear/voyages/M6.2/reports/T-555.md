# T-555 — report

Every gate run is told which project and which merges it judges, so a project's
gate can name its CI branch and run after them (user, 2026-11-04: SelyraAI's
gate branches were `ci/candidate/<sha>`, owned by no project and unreadable).
Changed `crates/gear-engine/src/merge.rs` only.

## What changed

- `fn gate_command` gained `project: &str, round: &str, tasks: &[String]` and
  sets, next to `GEAR_GATE_TEMPFAIL` and `GEAR_GATE_FAILED`:
  - `GEAR_GATE_PROJECT` — the project id;
  - `GEAR_GATE_ROUND` — the id of the first merge op of this gate run,
    lowercase without the dash (`O-6543` → `o6543`);
  - `GEAR_GATE_TASKS` — the task ids of the merges this run judges,
    space-separated in merge order (`T-637 T-646 T-662`).
  Each is a new `pub const` documented like `GATE_TEMPFAIL_ENV`:
  `GATE_PROJECT_ENV`, `GATE_ROUND_ENV`, `GATE_TASKS_ENV`, and
  `fn gate_round(op)` builds the round from an op.
- `fn run_gate` takes the three and passes them to `gate_command`. Its three
  callers give them:
  - the single merge (`merge_one_locked`): its op — project, `gate_round(op)`,
    and the op's one task;
  - a train stage (`run_train`): that stage's op (`ops[index]`), so each
    side-by-side stage is its own round with its own task;
  - a batch (`run_batch`): the batch's first op as the round, and every built
    op's task in merge order as the task list.
- Nothing else changed: no gate outcome, retry or report reads these.

## Tests (`mod tests`)

- `a_single_merges_gate_names_its_project_round_and_task`: gate
  `echo $GEAR_GATE_PROJECT $GEAR_GATE_ROUND $GEAR_GATE_TASKS > <file outside the
  worktree>; true`, one passed task `T-1` — the file holds `p o1 T-1`.
- `a_batchs_gate_names_the_round_and_every_task_it_judges`: the same gate with
  `batch_of_two` and both tasks passed — the one gate run of the batch writes
  `p o1 T-1 T-2`.
- `the_gate_runs_without_the_store_of_this_machine` now calls `gate_command`
  with the three new arguments; it still asserts `GEAR_DB` and `GEAR_CTX` are
  removed.

`make check CRATE=gear-engine TESTS='test(merge::)'` — 108 tests, 108 passed.

## Out of scope

The variables reach the gate only; nothing in GEAR reads them back. A gate that
wants `$GEAR_GATE_TASKS` word-split for a loop gets that from an unquoted
expansion, as the tests do.
