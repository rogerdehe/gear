# T-559 — report

A seat's own branch is named project / seat / home, and an apply moves each seat
worktree's branch to it by itself.

## What changed

- `crates/gear-model/src/branch.rs`: `SEAT_BRANCH` is `{project}/{seat}/home`
  (doc says why: it reads like a task's project / lane / task, and the seat
  branch sits beside the lane's task branches); its unit test expects
  `p/hull/home`.
- `crates/gear-app/src/config.rs`: the ref-and-directory clash hint now suggests
  `seat_branch = "{project}/{seat}/home"`. With the new default the sample
  `p/heat/home` and the task branch `p/heat/t1` are siblings, so no issue is
  raised.
- `crates/gear-app/src/admin.rs`: `init_with_home` reads the stored
  `seat_branch` before the write, and after the config is stored (git never runs
  inside the store transaction) calls the new `move_seat_branches` when the
  template changed. Per seat with a worktree path in meta:
  - the worktree stands on the old branch → `git branch -m <old> <new>` in that
    worktree; when the old name is on the remote, the new one is pushed and the
    old one deleted there;
  - the worktree is on another branch → left alone and named;
  - the path is gone, or git cannot tell → named as such.
  Nothing is removed; a git step that fails is reported in the seat's line, never
  a reason for the apply to fail. `InitResult.stale_worktrees` carries these
  lines (its doc updated).
- `skills/gear/references/conventions.md`: the table's default and the merge/branch
  paragraph (default `{project}/{seat}/home`, the example `prometheus/web/home`
  beside `prometheus/web/t675`, and the sentence on the re-apply switch).
  `skills/gear/references/captain.md`: one sentence in the init paragraph — a
  changed `seat_branch` renames each seat worktree's branch by itself.
- `docs/releases/v0.6.55.md` (new, form of v0.6.54): Changed — the new default
  and the switch; Fixed — a review leaves no branch of its own on the remote
  (the hull task, written from T-558's goal since its code was not on `dev` at
  hand-in; tasks already in review still merge their old review branch);
  Why; Upgrading from 0.6.54 with the seat_branch/review_branch lines to change
  or delete.
- Tests (gear-app):
  - `config.rs` mod tests: `the_default_seat_branch_is_project_seat_home` (the
    default expands to `p/captain/home`, and it is valid beside
    `{project}/{lane}/t{n}`) and
    `an_apply_moves_a_seat_worktree_to_the_new_seat_branch`: a temporary git
    repository with two linked worktrees — the one on `harbor/seat/heat` is
    renamed to `harbor/heat/home` by the apply, the one on `keel/t1` is left
    alone and named.
  - `tests/it/config_contract.rs`: the defaults literal and the clash test now
    use the new default, and the clash cases name the old shape explicitly.
  - `tests/it/admin_init_contract.rs`: the T-373 test now covers the "path is
    gone" line (the real rename is the config.rs test).
- Tests (other crates, following the default): the engine's fixtures that pin a
  seat branch now use the new names — `p/merge/home` for the merge seats
  (`p/merge-2/home` for a train's stage), `p/review-1/home` for reviewers,
  `p/heat/home`, `toy/heat/home`, and the fake worktree paths and pane/workspace
  ids the fake Herdr derives from a branch name (`p-review-1-home`,
  `wt-p-review-1-home`). `crates/gear-cli/tests/it/admin_init_contract.rs`'s
  T-373 print test follows the new "path gone" line.

## Acceptance

- The default expands to `p/captain/home`:
  `config::tests::the_default_seat_branch_is_project_seat_home`.
- The clash check accepts it beside `{project}/{lane}/t{n}`: same test
  (`p/heat/home` and `p/heat/t1` are siblings).
- An apply that changes the template renames a seat worktree's branch in a
  temporary repo and reports a seat on another branch:
  `config::tests::an_apply_moves_a_seat_worktree_to_the_new_seat_branch`.
- `make check CRATE=gear-app` — 684 tests run, 684 passed.
- Because the default changed, the whole engine suite was run:
  `make check CRATE=gear-engine` — 1016 tests run, 1015 passed, the one failure
  (`onboard_contract::lane_gets_worktree_env_and_unattended_args`, an expected
  `harbor/heat`) fixed, and its module re-run 3/3 green.
- `make check CRATE=gear-cli` (the T-373 test) green for the touched test.

## Out of scope

- The hull task (T-558: reviews push to the task branch) was **not on `dev`** at
  hand-in; the release note describes it from its goal, as T-556 did for T-555.
- The apply renames the *branch* in place; the seat's worktree path and Herdr's
  `<project>-<seat>` label are unchanged, so no worktree is removed or recreated.
- The engine test fixtures were updated to the new names rather than pinning the
  old template; the engine's own behaviour is otherwise untouched (one comment
  in `merge.rs` now names the new default).
- Worktrees of seats that are not running (released seats with a kept checkout)
  are moved the same way, since the rule is the branch their checkout stands on.
