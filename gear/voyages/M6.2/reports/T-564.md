# T-564 — report

The merge never publishes a lane commit nobody reviewed (found 2026-11-04
after v0.6.55: the merge takes the task branch tip, so a lane commit pushed
after the hand-in — hull's fix on T-562 — would land unreviewed).

## What changed

`crates/gear-engine/src/merge.rs`, `prepare_merge`, on the task-branch path (no
old review branch, not a mechanical settle):

- **The ref is resolved once.** `task_tip` is read with one `rev-parse` before
  the ancestor check, and that sha is what the merge takes (`merges.push((tip,
  task_ref))`): the merge commit still names the branch, but a push that lands
  after the read cannot slip in. The ancestor check now asks the same pinned
  sha.
- **Every commit after the candidate must be the review.** One
  `git log --no-merges --format=%H%x09%s <candidate>..<tip>` lists them; each
  subject must start with `review_prefix`, the project's
  `[conventions].review_message` filled with the task and the attempt and cut at
  `{what}` (the default gives `review(T-7): `). A merge commit is no way out:
  its parents are in the range, so a lane commit pulled in under one is named
  too.
- **Otherwise the op fails `stuck`**, naming each foreign commit:
  `T-x: the task branch holds commits after the approved candidate that are not
  the review: <sha> <subject>; a change after hand-in needs a new attempt`.
- A `git log` that cannot be read is `clear` (the branch may be moving), not
  `stuck`.

The prefix is computed where the project's config already is and threaded the
way the merge message is: `merge_passed` → `merge_with_retries` →
`merge_one_locked` → `prepare_merge`, and `TrainOp.review_prefix` for merge
trains and batches.

## Acceptance

- `make check CRATE=gear-engine TESTS='test(merge::)'` — 112 tests run, 112
  passed.
- Candidate + one review commit merges: the existing
  `a_review_on_the_task_branch_merges_candidate_and_review` (its fixture now
  commits a real review subject, `review(T-5): pass, r5`, instead of `r5`).
- Candidate + review + one lane commit fails `stuck` naming the lane commit:
  `a_lane_commit_after_the_candidate_on_the_task_branch_is_refused` (the sha,
  the subject and the "needs a new attempt" sentence; nothing landed).
- A lane commit pulled in under a merge commit is caught too:
  `a_pulled_in_lane_commit_under_a_merge_commit_is_refused`.

## Out of scope

- Only the task-branch path is checked. An old review branch (a task reviewed
  before T-558) merges exactly as before: it is a ref of its own, and the packet
  scoped the check to the task-branch path.
- A mechanical settle has no reviewer and no review commit; its pinned candidate
  merges alone, unchanged.
- The check runs before the merge and before the gate, so a refusal costs one
  git log and never touches the integration branch.
- No release note was written: the packet does not name one (T-563's did not
  either).

## Rework (attempt 2, review F1)

The review's F1 is right: the range `<candidate>..<task_tip>` also holds the
commits of the integration branch when the task branch merged it — the
documented conflict fix (`course.md`: merge dev into the task branch, resolve,
push, `remerge`). Those subjects are dev's own and are reviewed work already on
the branch; the check called them foreign and failed the remerge `stuck`.

- The `git log --no-merges --format=%H%x09%s <candidate>..<tip>` now carries
  `--not <base_ref>` (`base_ref` is the remote integration branch, or the
  train's stage ahead): only the commits the merge newly brings in are judged.
  A lane commit is never on the integration branch, so all three acceptance
  cases still refuse.
- New test `a_task_branch_that_merged_the_integration_branch_still_merges`:
  `dev` moves after the hand-in, the task branch commits the review and then
  `git merge dev`, and the merge lands (the review and dev's commit both in the
  integration log). Without the `--not` the test fails with the reviewed
  message verbatim (`…not the review: <dev sha> dev moved; a change after
  hand-in needs a new attempt`) — checked by reverting the flag locally.

`make check CRATE=gear-engine TESTS='test(merge::)'` — 113 tests run, 113
passed (the three attempt-1 acceptance tests still green).
