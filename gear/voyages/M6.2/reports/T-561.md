# T-561 — report

A retired seat takes its agent with it, a remote outage never retires one, and
the quota counts the live agents Herdr shows.

## What changed

1. **Retirement closes the pane** (`crates/gear-engine/src/review.rs`,
   `retire_checkout_seat`): the seat leaves through
   `crate::release::release_one` — the release every other exit uses, which
   closes the seat's pane (its `Starting` branch closes it and frees the slot,
   `Active`/`Standby` close it and put the seat in `Releasing`). Only then is the
   seat marked `Retired`, and its reason names the worktree and the git error. A
   release that cannot close the pane does not keep the seat: the reason says
   the pane could not be closed, and the tick's sweep (3) closes it.
   `crates/gear-model/src/state.rs`: a temp seat may go `Releasing → Retired`
   (a reviewer sent on its way out whose worktree is broken is retired, not
   released back into the pool); nothing else about the model changed.

2. **A remote outage is not the worktree's failure** (`review.rs`,
   `prepare_seat_tree`): a checkout whose git error carries one of the transport
   words (`fetch remote failed: `, `Permission denied (publickey)`, `Could not
   read from remote repository`, `Could not resolve host`, `Connection refused`,
   `Connection timed out`, `Connection closed by`, `Operation timed out`,
   `Network is unreachable`, `ssh: connect to host`, `kex_exchange_identification`)
   is not counted: no failure count, no stuck attempt, no retirement. The tick
   retries it. The seat's first failure is recorded
   (`engine.review_remote_outage.<seat>`); a checkout that lands clears it, and
   the captain is told once (`review-remote:<seat>`) when the outage has lasted
   30 minutes, naming the worktree, the error and the fact that the seat stays in
   the pool.

3. **The quota is Herdr's count, not the store's**:
   - `review::close_gone_seats`, run every tick for every project
     (`crates/gear-engine/src/lib.rs`, step 0e, report field
     `TickReport.gone_seats`): every pane whose agent carries a seat's name
     (`<project>-<seat>`) while that seat is `Retired` or `Released` is closed,
     and the captain hears of it once per seat (`seat-pane:<seat>`). An
     unreadable agent list closes nothing.
   - `names::live_of_role(store, herdr, project, role, except)`: the panes whose
     agent carries the name of a seat of that role, from Herdr's agent list.
   - `review::seats_free_for_new` and `review::has_free_slot` refuse a start
     while the live reviewer panes reach `[quota] temps`; a seat that is being
     reused or resumed is left out of its own count (`except`).
   - `onboard::onboard_queued` refuses a lane start while the live lane panes
     reach `[quota] lanes`, the lane being started left out of its own count.

4. **Tests** (`review.rs` `mod tests`): `a_retired_seat_closes_its_pane` (the
   fake Herdr records `Call::PaneClose` for the seat's pane, and the existing
   T-425 test still sees `Retired` and one captain item),
   `a_remote_outage_keeps_the_seat_and_is_told_after_half_an_hour` (three
   `Permission denied (publickey)` failures: not retired, failure count empty,
   pane open, no message; one message after 30 minutes, still one after 60),
   `a_live_agent_of_a_gone_seat_is_closed_and_named_once` (the sweep),
   `live_reviewer_panes_at_the_quota_start_no_new_reviewer` (three retired seats
   whose agents are live, quota 3: nothing starts, no fourth seat). The
   review-only fake git can now return the remote's own words
   (`REVIEW_GIT_FAIL_TEXT`).

## Acceptance

- `make check CRATE=gear-engine TESTS='test(review::) | test(release::)'` — 167
  tests run, 167 passed.
- Because the same change touches the tick, the lane start and the model, the
  whole crate was run: `make check CRATE=gear-engine` — 1020 tests run, 1020
  passed. `make check CRATE=gear-model` — 24 run, 24 passed.
- Retire with a local error closes the pane and still tells the captain once;
  three publickey failures leave the seat in the pool with its pane open; a
  retired seat's live pane is closed by one tick and the captain told once; live
  reviewer panes at the quota start no new reviewer.

## Out of scope

- The lane gate is a start gate only: `admin::lane_quota_problem` still checks
  the config's lane count against `[quota] lanes`.
- A lane or reviewer whose own agent is live but whose start was never recorded
  keeps its own pane out of the count (it is the seat being started).
- The sweep closes panes by the name Herdr reports; an agent that lost its name
  is not counted and not closed (it also cannot receive a prompt).
