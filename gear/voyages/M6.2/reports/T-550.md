# T-550 — report

An item addressed to a retired seat closes with it.

## What changed

- `crates/gear-store/src/lib.rs`, `Tx::set_seat_state`:
  - its doc now says a retired seat takes its items with it and why: only the
    recipient may resolve an item, and nothing rings for a seat that is gone,
    so left open it stays open for ever; a released seat's items stay as they
    are, since it may come back.
  - after the seat's own row is written (and only when the new state is
    `SeatState::Retired`), the messages addressed to that seat id are read and
    every one whose state `MsgState::can_transition` says may move to
    `Resolved` (`open`, `waiting`, `info`) is set to `Resolved` through
    `update_message_state`, with result `"closed: its seat retired"` and
    `resolved` = `now`. It is the same transaction, so the seat and its items
    move together; a row that is already `Resolved` is skipped.
  - the rows are read into a list before they are updated, so the reading
    statement does not run while the same table is written.

Nothing else changed: released (not retired) seats keep their items, and the
state machine itself is untouched.

## Acceptance

- A seat with an open and a waiting item retires and both become resolved with
  `"closed: its seat retired"` and `resolved` = the retirement time:
  `contract::a_retired_seat_closes_its_items`.
- An item to another seat and an already resolved item are untouched (the
  second keeps its own result and its own earlier `resolved` time): same test.
- A seat set to `Released` keeps its open item:
  `contract::a_released_seat_keeps_its_items`.
- `make check CRATE=gear-store TESTS='test(seat)'` — 9 tests run, 9 passed,
  88 skipped.
