# T-586 — report

A captain's quiet page follows open work, not the last departure.

## What changed

- `crates/gear-app/src/home.rs`:
  - New private `open_voyages(tx, project)`: the milestones of the project's
    tasks (`tasks_of_project`, milestones deduplicated in `BTreeSet` order)
    whose voyage still has a task that is not terminal, tested with
    `gear_board::stations::voyage_open` — exactly the packet's rule, in
    milestone order so it matches the order `gear_board::voyage::reports`
    carries.
  - `sailing` is now: a captain is sailing when the project has no voyage
    (`plan::current_voyage` empty, as before, so a project with no departed
    voyage keeps the page it had) **or** any of its milestones has a task that
    is not terminal — no longer only `plan::current_voyage`.
  - The goal line loop follows the same list: one `goal_text` per voyage with
    open work, right under the voyage report lines (the reports already list
    every voyage with open work), instead of the goal of the last departed
    voyage only. A finished voyage keeps no goal line and no report line.
  - `multi_page` (a captain whose pane holds several projects) had the same
    `current_voyage` goal line; it now uses the same `open_voyages` helper, so
    the two captain pages agree.
- `crates/gear-app/tests/it/app_home.rs`:
  `a_finished_voyage_does_not_hide_another_that_still_runs` — M1 departed and
  finished (its only task done), M2 never got a depart line and has a running
  task with an open `station:M2` item. The page shows `Station M2`, the M2
  goal and the snapshot, and carries no `Your goal, voyage M1`.

The engine items the page shows when sailing are unchanged, and the doorbell
already rang for those items (`doorbell::goal_line` / `finished::Sweep` were
not touched): page and doorbell now agree, which is the GEAR M6.2 case (the
page took the finished M6.1 and hid M-8020 while the doorbell rang it).
