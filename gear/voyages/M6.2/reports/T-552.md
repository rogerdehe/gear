# T-552 — report

A pane that already holds one project's captain seat keeps its agent's Herdr
name when it takes another project's captain seat.

## What changed

- `crates/gear-app/src/captain.rs`:
  - new `fn other_captain_in_pane(store, pane, seat) -> GearResult<Option<String>>`:
    the id of another project's captain seat (`Tx::captain_of` for every project
    of the store) whose **current** binding is `Active` on `pane`, ignoring
    `seat` itself. Doc: a captain pane may hold several projects' captain seats
    (T-485), the agent carries one name, and renaming it after the second
    project takes the first captain's name away, so every prompt to that name
    fails with `agent_not_found`.
  - `fn finish_rebind` (step 7, the naming): when another project's captain
    seat is bound Active to the pane, the naming is skipped and the name is
    reported as kept; otherwise `ensure_agent_name` runs as before. The clearing
    of the name on the old pane (when the seat moved from another pane) is
    unchanged.
  - the early return of `fn take_one` for a seat this pane already holds: the
    same check, so a pane holding A's captain and B's seat does not rename B's
    agent either.
- `crates/gear-herdr/src/lib.rs`: `Ensured` gains `Kept` ("The pane already
  carries another project's captain name, and it was kept (T-552)").
- `crates/gear-engine/src/names.rs`, `onboard.rs`, `ops.rs`: one arm each for
  the new variant (the engine's ensure never returns it; nothing to do).
  The captain allowed this in the answer to M-7682.
- `crates/gear-cli/src/main.rs`: `named_line` prints `Kept` as "kept: the pane
  already holds another project's captain name".

The question and the captain's answer: there was no "kept" outcome to report;
option (a) — a new `Ensured::Kept` with a truthful line — was chosen over
reusing `Named`, whose line ("already the captain's name") would be false.

## Acceptance

Tests in `crates/gear-app/tests/it/captain_take_contract.rs` with the fake Herdr
(`world` now also builds project `q` on the same checkout and pane through
`add_project`, and `config_of(id, root)` names either project):

- `take_keeps_the_captain_name_a_pane_already_holds`: the pane carries
  `p-captain` and holds p's captain seat; taking `q` reports `Ensured::Kept`,
  the agent is still `p-captain`, no rename to `q-captain` was attempted, and
  both seats stay Active on the pane.
- `take_names_the_captain_of_a_pane_that_holds_no_other`: a pane with no other
  captain seat is renamed to the new captain's name as today.
- `a_handover_to_a_fresh_pane_names_the_captain_as_before`: a handover to a
  fresh pane still reports `Renamed` and names the agent.
- `make check CRATE=gear-app TESTS='test(captain)'` — 44 tests run, 44 passed.
- The files outside gear-app that the new variant touches (the engine's three
  arms, gear-cli's line): `make check CRATE=gear-cli TESTS='test(captain) |
  test(handover)'` — 21 tests run, 21 passed, including the handover that moves
  the name and the multi-captain take.

## Out of scope

- The engine's own naming pass (`names.rs`) still renames a seat's agent to
  `<project>-<seat>`; if it ever runs for a second captain seat of the same pane
  it can undo this. The packet names only `captain.rs`, so it was left alone.
- No skill or design text was changed; the captain skill already says a pane may
  hold several projects' captain seats.
- The release note for v0.6.52 (T-549) does not name this item.
