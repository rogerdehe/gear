## What changed

- `skills/gear/references/captain.md`, `# Queue` § field list: `feature`
  (`F-<n>`) is documented between `deps` and `state`, in the packet's words —
  the task is part of a feature; members merge into the feature branch with no
  CI, deps between members release on that merge, and GEAR creates one
  integration task per feature that reaches the integration branch with one
  review and the full gate; at most `feature_max_tasks` members; a dep from
  outside names the integration task; members share the feature's issue. It is
  inside the existing field-list line, so it adds no line.
- `skills/gear/references/decompose.md`, §1 rule 8 (new, one line): a capability
  that takes several small tasks is cut as `feature: F-<n>` at decomposition —
  in issue mode, one issue — so its members merge into the feature's branch and
  reach the integration branch once, reviewed once and gated once with the full
  gate (`gear --skill captain` `# Queue`); small unrelated tasks stay without
  one.
