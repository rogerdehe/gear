# T-562 — the board and the queue say what a task really waits for

## What changed

**(1) `crates/gear-board/src/graph.rs` — the words of a waiting task.**
`Stage::words_of` takes the dependencies that are **not merged yet** plus how
many the task has (`deps_open` / `dep_count`):

- one to three open → `waits for T-563, T-665 to merge`;
- more → `waits for 5 of 47 to merge`;
- none (a stage the store did not give) → `waits for - to merge`, as before.

`GraphTask` and `TaskBoard` carry `deps_open`, computed once per build from
`tx.merged_done_tasks` (T-529's single query — the rule `dispatch::ready_tasks_of`
uses, so a dependence counts only when its work is merged, T-236/F-76). All
three `words_of` call sites pass it (`Stage::words`, `lib.rs`'s board build,
`frame.rs`'s lane panel).

**(2) `crates/gear-board/src/idle.rs` and `frame.rs` — a lane's next task.**
Both now pick the first task **in the plan's rank order whose dependencies are
all merged**; only when none can start do they name the first blocked task and
its first unmerged dependency. Before, the first queued task won even when a
later one was ready (the user's Prometheus case: platform's next read T-667
waiting on T-570 while T-682 was ready behind it). `idle.rs` reads the merged
set with one `merged_done_tasks` call; `frame.rs` reads it from the board's own
`deps_open`.

## Decisions and deviations

- **"The same rule dispatch uses" is `merged_done_tasks`**, i.e. done **and**
  merged, not `Done`. That is why two existing idle tests changed: a done but
  unmerged dependency now still holds the lane, as the engine holds it.
- **The packet's "Tests in graph.rs and idle.rs `mod tests`"**: neither file had a
  `mod tests`. The pure `words_of` cases went into a new `graph.rs mod tests`;
  the idle cases need a store, so they went into `tests/it/idle_contract.rs`,
  where every other idle test lives.

## Out of scope, logged

- `graph::stage_of` still calls a dependency merged when its state is `Done`,
  while `deps_open` and the queue use `merged_done_tasks`. A Done-but-unmerged
  dependency therefore shows the task as `queued` on the board while the queue
  says it waits for that dependency. One line to change if the captain wants
  them one rule; the packet named only the words and the next lookup.
- The deps column (`deps_rows`/`edges_of`) still draws to every direct
  dependency that is not merged by `finished`/`Merged`; it does not read
  `deps_open`.
- The board's next lookup mirrors dispatch's *deps* rule only, not its other
  filters (a task of another repo, a voyage audit, `priority = wont`).
- `docs/design/` is untouched.
