# T-587 — report

A plan written before features moves to them in one apply.

## What changed

`crates/gear-app/src/plan.rs`:

- **(1) A task that has started joins no feature.** In the draft's validation,
  an existing task whose block names a different, non-empty `feature:` and that
  has any attempt is refused:
  `T-<n> has started: it finishes on the integration branch; only a task with no
  attempt joins a feature`. Validation runs before any write, so the task keeps
  its base and gate (and no carrier is minted). A block that re-states the mark
  the task already has is not a join and stays allowed, as does `feature: -`.
- **(2) An outside dep on a member is rewritten, not refused.** T-578's
  `BadFormat` is gone. After the queue blocks are validated, every task's deps
  are rewritten: a dep on a member of another feature becomes that feature's
  integration task (`features.work(dep_feature).carrier`), once — a task that
  already names the carrier keeps a single entry, and a second member of the
  same feature rewrites to the same carrier once. The rewrite lands in the
  store in the apply's transaction, for tasks the draft does not name too (their
  plan line would otherwise keep a wait that can never be satisfied on the
  integration branch), and the apply prints one line per rewrite:
  `T-<x>: dep T-<m> -> T-<carrier> (feature F-<n>)`.
- **(3) A member waits for the feature's outside work.** For each feature, the
  deps of its members outside the feature that are **not merged**
  (`Tx::merged_done_tasks`, the same notion dispatch uses) become deps of every
  member that is not cancelled, so the feature branch is cut from an integration
  branch that holds them and no member is delivered before. A merged outside dep
  is ignored: its work is already there. The waits are written for every member,
  the ones the draft does not name included. (A dep on another feature's member
  is rewritten to that feature's carrier first, so what a member waits for is
  the carrier — which is unmerged until that feature lands.)
- The dependency cycle check now also holds the carriers as nodes (their deps
  are the members, or the stored deps of a carrier on record). Without them, a
  member that waits on an outside task which in turn waits on the carrier is a
  cycle delivery never breaks; with them the apply is refused as it is for any
  other cycle.
- `ApplyResult` gains `rewritten: Vec<String>` (serde default), holding those
  lines; `render_apply` in `crates/gear-cli/src/main.rs` prints them after
  `created`/`resolved` lines, so the text output and the JSON both name them.

`crates/gear-app/tests/it/feature_plan_contract.rs` — three new tests, replacing
T-578's refusal test:

- `a_running_task_joining_a_feature_is_refused_and_keeps_its_base` — T-1 has a
  started attempt; the apply is refused with the packet's sentence and T-1 keeps
  `base = dev`, `gate = make test`, no feature mark, no carrier.
- `an_outside_dep_on_a_member_names_the_integration_task` — T-2 (outside F-1)
  depends on T-1 (member): T-2's deps name the carrier, `result.rewritten` is
  exactly `T-2: dep T-1 -> T-3 (feature F-1)`; a later block that also names the
  carrier keeps one entry and prints one line.
- `a_member_waits_for_an_unmerged_outside_dep_and_not_for_a_merged_one` — T-1
  outside, unmerged: both members (T-2 names it, T-3 does not) end with deps
  `[T-1]`; once T-1 is Done with a merged attempt, a re-apply leaves T-3 with no
  deps and T-2 with its own `T-1`.

The file's module doc names the new rules.

## Noted (edge cases outside the contract's normal use)

- Only *joining* is refused: `feature: -` on a started task still clears the
  mark and moves it back to the lane's integration branch and full gate. The
  packet names `feature: F-<n>` on a started task, so that stayed as T-578 left
  it; if a started task must never move, clearing needs the same refusal.
- The waits (3) writes are not in the plan text: the store's deps for a member
  can be a superset of the block's `deps:` line while the outside work is
  unmerged. A later apply that cancels such an outside dep is refused by the
  existing "depends on cancelled" check, asking the captain to drop a dependency
  he never wrote — rare (a feature member held on outside work that is then cut).
- A dep on a member of a feature whose carrier is gone from record (all members
  cancelled, nothing stored) is left as written: there is no carrier to name.
- The first pushes to the remote were refused twice ("Permission denied
  (publickey)", then GitHub's `fatal error in commit_refs_rules`); the branch
  went up on the third attempt, retried in a loop.
