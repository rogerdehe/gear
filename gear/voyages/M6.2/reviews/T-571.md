## Findings
- F1 [P2, logged] the two halves use different notions of "finished": `finished_voyages` requires `departure.is_some()` and at least one task — `crates/gear-engine/src/finished.rs:56,64` — while `doorbell::voyage_finished` only checks that no live task remains — `crates/gear-engine/src/doorbell.rs:372`. A voyage whose tasks are all terminal but which never departed is "finished" to `goal_line` (its goal is dropped) yet not swept: `Sweep::empty()` is true, so both `finished::close` (`finished.rs:111`) and the doorbell filter (`lib.rs:1585`) do nothing and a stale `branches:`/`station:` item would still ring. Reached only by a never-departed all-terminal voyage or a departed voyage with zero tasks, which normal voyages do not produce — outside normal use. Smallest fix if wanted: drop the `departure.is_none()` gate (and the `tasks.is_empty()` skip), or gate the doorbell filter on `!any_open` instead of `!rows.is_empty()`.
- F2 [P3, logged] the reason for project-level threads names `finished.last()` as "the newest finished voyage", but `voyages_of_project` orders by the milestone string, so `last()` is the lexicographically largest, not the newest — `crates/gear-engine/src/finished.rs:163`. With ten or more milestones and several finished voyages the `result` text can name the wrong voyage. Cosmetic (the item still resolves with a finished voyage's name).
