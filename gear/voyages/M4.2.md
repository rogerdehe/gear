## T-228 [must] lane=mast milestone=M4.2 required
goal: [v0.4.8] `gear admin init --check <config>` validates a config and changes nothing. Today init is the only validator and it registers the project, so the engine starts every lane (another project's captain started its fleet nine times only to check its toml). In crates/gear-app/src/admin.rs move the checks of `init_with_home` that run before its first `store.write` — step 2 (`config::parse`, `config::validate` and the issue list), the profile checks (`config::profile_table`, unattended args) and the GEAR-skill checks with the `home` resolution — into a new `pub fn check(config_text: &str, home: Option<&std::path::Path>) -> GearResult<config::ProjectConfig>`, with the same errors and texts. `init_with_home` calls `check` where step 2 starts and keeps step 2b (the caller-context checks, which read the store) after it, so init behaves exactly as before. In crates/gear-cli/src/main.rs: add `#[arg(long)] check: bool` to `AdminOp::Init`; when it is set, `cmd_admin_init` reads the file, calls `gear_app::admin::check(&text, None)` and prints `config ok: project <id>, <n> lanes, <m> reviewers` (with `--json`: `{"ok":true,"project":…,"lanes":…}`); errors go out as every other GearError (exit 1). It needs no GEAR_ADMIN, opens no store and reaches no Herdr, and `starts_engine` returns false for `Init { check: true, .. }`. Add one line to the captain guide (skills/gear/references/captain.md, step 4 "Write the config"): "Check it with `gear admin init --check gear/gear.toml` until it passes; that starts nothing."
accept: CLI contract tests (crates/gear-cli/tests/it/admin_init_contract.rs, same helpers): a valid config with --check prints "config ok" and exit 0, and the store file named by GEAR_DB does not exist afterwards; a config with two lanes owning the same path exits 1 with the same issue text init gives; --check without GEAR_ADMIN works. Existing init tests unchanged and passing. `cargo test -p gear-app -p gear-cli` passes; `scripts/test.sh` once at hand-in.
