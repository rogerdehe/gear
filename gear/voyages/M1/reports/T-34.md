# T-34 — one canonical plan file per voyage

Scope: T-34 — the voyage's plan is one file in the project repo (`gear/voyages/<milestone>.md`, edited in place) and `gear plan apply <file>` rewrites it after a successful apply: `base=` becomes the applied version, each `## NEW` block gets `## T-<id>`, and the `# Verdicts` section is dropped (verdicts live in the store). A landed voyage's file stays as its record. `gear plan apply` with no path names the voyage file. The README and the captain guide show the `gear/gear.toml` + `gear/voyages/M1.md` layout.

Branch: board/t34 (code @ pending, see the hand-in commit)

Files:
- `crates/gear-app/src/draft.rs` — `rewrite_applied(text, version, created)`: a pure rewrite of the plan text (header `base=`, `## NEW` → `## T-<id>` in draft order, the `# Verdicts` section dropped whole, everything else kept as written; a dropped last section leaves no blank tail), with two unit tests.

Open questions:
- **A replayed apply still rewrites.** A repeated `--request-id` replays the stored result and the file is rewritten again with the same version and ids; that is idempotent. A newer plan applied in between would be overwritten by the replay's rewrite of the older file — the store is the authority, and the next apply fixes the file.
- **The Verdicts section is dropped, not emptied.** A captain who keeps verdict lines in the file for readability must keep them elsewhere (the store and the task packet show them).
- **The README's kickoff line is still a plain redirect** (`gear admin kickoff > gear/gear.toml`), which writes the inventory before the TOML; the extraction fix is T-26's rework (in review), not this task's "nothing else".
