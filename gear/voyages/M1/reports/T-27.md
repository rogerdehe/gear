# T-27 — A release users install without Rust

Scope: T-27 — a `v*` tag builds `gear` for the three supported targets, publishes `gear-<version>-<target>.tar.gz` with a `.sha256`, and the plugin's `[[build]]` step downloads + verifies that archive, falling back to `cargo build --release` on any miss.
Branch: data/t27 (code @ pending, see the hand-in commit)
Files:
- `.github/workflows/release.yml` — `v*` tags: verifies the tag against `herdr-plugin.toml` and the workspace version, builds `gear` for `aarch64-apple-darwin`, `x86_64-apple-darwin`, `x86_64-unknown-linux-gnu`, packages `gear-<version>-<triple>.tar.gz` (binary `gear` at the archive root) with `<archive>.sha256`, uploads the artifacts, and creates/updates the GitHub release with `gh release`.
- `scripts/fetch-or-build.sh` — the build step: detects the triple, reads the version from `herdr-plugin.toml`, downloads `gear-<version>-<triple>.tar.gz` + its `.sha256` from the release, verifies the SHA-256, unpacks the binary to `target/release/gear` (where `bin/gear` looks). On any miss (no release, no curl/wget, no sha tool, checksum mismatch, unknown platform) it says why and runs `cargo build --release` (sourcing `~/.cargo/env`). Paths, base URL and build command are overridable (`GEAR_REPO_ROOT`, `GEAR_CARGO_TOML`, `GEAR_OUT`, `GEAR_BASE_URL`, `GEAR_CARGO`) so the logic is tested hermetically.
- `scripts/test-fetch-or-build.sh` — the hermetic test: a fake `file://` release for this machine's triple, a cargo stub, and three runs.
- `herdr-plugin.toml` — the `[[build]]` step now runs the script (unix/macos only, like the file viewer).

Open questions:
- GitHub-hosted `macos-latest` builders are arm64; the `x86_64-apple-darwin` leg is a cross-build (`rustc` installs the target, no extra tooling). If a native runner is preferred later, the matrix entry changes without touching the assets.
- The script's checksum check reads `<archive>.sha256` (one line, `<hex>  <name>`), the format the workflow writes; the file viewer instead publishes a combined `SHA256SUMS`. Say so if a combined file is wanted too.
- `GEAR_CARGO` exists for the hermetic test (a stub build command); production never sets it.

Out of scope:
- Windows: the plugin's `platforms` are linux/macos, and the packet names three targets.
- Signing/notarisation of the macOS binaries.
- The plugin's install from GitHub and `herdr plugin link` are unchanged.
