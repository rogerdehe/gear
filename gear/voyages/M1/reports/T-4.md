# T-4 — GEAR as a Herdr plugin

Scope: T-4 — the plugin manifest, the `bin/gear` wrapper and the README section: the plan board opens from a Herdr hotkey, in a split or in a tab.

Branch: board/t4, based on origin/dev 81ab49e. The hand-in commit carries the code and this brief; the candidate sha in the result names it (a brief inside a commit cannot name its own sha).

Files:
- `herdr-plugin.toml` — the manifest: `id = "herdr-gear"`, a `[[build]]` that runs `cargo build --release`, the `[[panes]]` entry `board` (`./bin/gear board`), and the two `[[actions]]`: `open-board` (a split) and `open-board-tab` (a tab).
- `bin/gear` — the wrapper the agents find on PATH: it runs `target/release/gear` from any working directory and finds the store (`GEAR_DB` when it is set, otherwise `~/.local/state/gear/gear.db`).
- `README.md` — the install section: build, link, bind a key, open the board without a key, put `gear` on PATH for the agents.

Verification:
- The manifest parses as TOML. Its **top-level field names are identical** to the file viewer's and its **item field names a subset** of them (`command`, `description`, `id`, `placement`, `title`) — checked against `~/.config/herdr/plugins/github/herdr-file-viewer-c993314e2614/herdr-plugin.toml`. No field Herdr does not know.
- The wrapper runs the board: `env -u GEAR_DB ./bin/gear board` → the gear project (6 tasks, the three lanes with their queues, the captain's inbox, the temp slots). Without a built binary it says so and exits 1.
- `cargo test --workspace` → 261 tests, all ok; `cargo build --workspace --all-targets` → no warnings.
- `sh -n bin/gear` → the wrapper is valid shell; `bin/gear` is executable (mode 755).

## The commands for the captain

```bash
# 1. build (a linked plugin is NOT built by Herdr: `plugin link` runs no build step)
cd /Volumes/Data/myai/gear && cargo build --release

# 2. link the plugin
herdr plugin link /Volumes/Data/myai/gear

# 3. see what it offers
herdr plugin list
herdr plugin action list --plugin herdr-gear

# 4. open the board (split beside the current work / its own tab)
herdr plugin action invoke herdr-gear.open-board
herdr plugin action invoke herdr-gear.open-board-tab
```

The keybindings go into `~/.config/herdr/config.toml` (the keys the file viewer does not use; `prefix+b` is free in the default config), then `herdr server reload-config`:

```toml
[[keys.command]]
key = "prefix+b"
type = "plugin_action"
command = "herdr-gear.open-board"
description = "open the GEAR board in a split"

[[keys.command]]
key = "prefix+shift+b"
type = "plugin_action"
command = "herdr-gear.open-board-tab"
description = "open the GEAR board in a tab"
```

Open questions:
- **The board pane runs `gear board`, which is T-3.** The plugin is only useful once the board command is in the linked checkout; T-3 is in rework and its fix is on `board/t3`. Linking this worktree (or the main checkout after T-3 is merged) makes the pane work; linking a checkout without the board command opens a pane that says `unrecognized subcommand 'board'`.
- **The wrapper defaults `GEAR_DB` to `~/.local/state/gear/gear.db`.** A pane opened by Herdr inherits the *server's* environment, which has no `GEAR_DB`; without a default the board pane would only say `GEAR_DB is not set`. `GEAR_DB` still wins when it is set (the agents get it from the engine).
- **`contexts = ["workspace"]` is not in the manifest.** design/14 lists it and the Herdr docs have it, but the packet asks for the file-viewer's field names and the file viewer has no `contexts`. Adding it back is one line per action.
- **The pane's default placement is `tab`** (design/14); the two actions choose the split or the tab explicitly, like the file viewer.

Out of scope:
- Linking and invoking the plugin — the captain does that (the packet says so).
- The Windows entries the file viewer has: GEAR's board uses `termios`, so it is unix-only (`platforms = ["linux", "macos"]`).
- The skill install step of design/14 (`npx skills add …`): that belongs to the skill, not to the plugin.
- A test for the manifest: the crate that could host it (`crates/gear-board`) is not in `dev` yet, and Herdr validates the manifest itself when it links the plugin.
