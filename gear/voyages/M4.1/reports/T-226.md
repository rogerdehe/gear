# T-226 — A restarted agent takes the project's current config

Scope: T-226 (contract v1) — the restart of an agent that exited from its pane (`restart_missing_jobs` in `crates/gear-engine/src/lib.rs`) takes the model, the CLI and the arguments from the **current** config, not from the snapshot the round began with.

Branch: hull/t226 · contract v1.

Files:
- `crates/gear-engine/src/lib.rs` — `restart_missing_jobs` only. The `(model, cli, args)` of the restart is now chosen from the config as it is now (`gear_app::config::parse(&project_row.config_toml)`, as before):
  - a **reviewer** (`SeatRole::Temp`) takes the current review chain `config.models.review` (`crate::model::review_chain`), the entry whose model is the seat's saved model (`crate::model::model_meta_key(&seat.id)`), else the first entry;
  - a **lane** takes `crate::model::role_chain(&config, &l.name)`, the entry whose model is the saved model, else the first entry — the kind of the old binding no longer takes part in the choice;
  - the CLI is `entry.cli()` when the entry names one, else the role's current kind (`l.kind` for a lane, `config.temps.as_ref().map(|t| t.kind.clone())` for a reviewer) — never `binding.kind`;
  - the arguments are the entry's own; the `ModelEntry` is built as before;
  - for a reviewer the meta `engine.review_model_entry.<seat>` is updated to the chosen entry (`cli`, `model`, `args`).
  - `restart::advance` and the restart state machine are untouched.
- `crates/gear-engine/src/lib.rs` — the new test module `t226_restart_tests` (same fakes as the T-209 tests).
- `ops/reports/T-226.md` — this brief.

## What was wrong

The restart built its `ModelEntry` out of snapshots:

- a reviewer took the model and the arguments from the meta `engine.review_model_entry.<seat>`, written when its round began;
- a lane looked for the chain entry whose CLI equals the old binding's kind (`binding.kind`), and the entry was built with `cli: Some(binding.kind.clone())`.

So after a re-init that fixed a model id (`anthropic/claude-sonnet-5-5` → `claude-sonnet-5-5`) or changed a lane's kind (opencode → pi), every restart brought the old agent back: the reviewer with the old model id, the lane on the old CLI. The CLI was pinned to the old binding in both cases.

## The tests (next to the T-209 ones, same fakes)

- `a_restarted_reviewer_takes_the_current_review_chain` — the round began on `gpt-6.1-sol` (`engine.review_model_entry` and the model meta say so); the config is applied again with the review chain `[gpt-6.2-codex]` (`cli = codex`, `model_reasoning_effort=low`); the agent of the round exits and the restart starts **Y** with Y's arguments (`-m gpt-6.2-codex`, `-c model_reasoning_effort=low`, never `high`), and the meta `engine.review_model_entry.p:review-1` now holds Y.
- `a_restarted_lane_takes_the_current_kind_and_model` — the lane is bound with the CLI `opencode`; the config now says the kind `pi` with the model `pi-model` (the chain entry names no CLI, so the lane's current kind is the CLI); after the exit the restart starts the **pi** CLI with `--model pi-model`, and the seat's model meta follows.
- `an_unchanged_config_restarts_as_before` — an unchanged config: the same model, the same CLI and the same arguments as before (lane and reviewer).

## Verification

- `cargo test -p gear-engine t226` → **red before** the change on (a) and (b) — the reviewer came back with `-m gpt-6.1-sol -c model_reasoning_effort=high`, the lane restart found no entry at all (the old code looked for the entry whose CLI equals `binding.kind` = `opencode`, and the new chain entry names none) — green after: `3 passed`.
- `cargo test -p gear-engine` → `288 passed` (unit) and `303 passed` (integration), 0 failed.
- `scripts/test.sh` → `1428 tests run: 1428 passed, 0 skipped`; suite 49 s (the red line is 300 s).
- `cargo build --workspace --all-targets` → no warnings.

## Out of scope

- `restart::advance` and the restart state machine are untouched, as the task says: a CLI that differs from the old one is already handled there.
- The re-init path itself (`restart::reconcile_config`, the in-place switch of a lane whose config changed) is untouched. The tests change the config of the project row without a config version bump, so the restart under test is the only one that acts.
- A reviewer's chain entry may name a CLI that differs from `[temps].kind`; the restart then runs the entry's CLI, while the review start path (`review.rs`) still starts a reviewer on `[temps].kind`. Both are as the task prescribes; the meta of the reviewer records the CLI it actually runs on.
- A lane whose current config names no chain at all keeps the saved model and the role's kind, with no arguments.
