# T-227 — a seat that produces nothing reaches the captain

## What landed

`crates/gear-engine/src/silent.rs` (new): `pub fn tick(store, project, observed, profiles, now) -> GearResult<Vec<String>>`.

- For every seat of the project with role `Lane` or `Temp`: take its open round
  (`tx.open_round_of_seat`). Skip when there is none, when
  `now - round.start_at < 600`, when the seat's observation says its agent is
  not idle (it works, it is gone, it waits on a dialog — those paths have their
  own alarm), when the attempt of the round is over (cancelled or settled: the
  seat holds no live work), or when the meta
  `engine.silent.<seat>.<task>.<attempt>.<role>` is already set.
- The seat is silent when none of the round's `sessions` has a usage record in
  `[round.start_at, now]`; the usage log is the seat profile's, read exactly as
  `session_runner.rs` reads it (`profile.usage_log` → `gear_usage::UsageLog`,
  `gear_usage::usage(log, session, round.start_at, now)`; `usage()` returning
  `None` counts as no record).
- A round with no session, or a profile with no usage log, counts as silent
  only when the seat has said nothing since the round began (any message of the
  seat counts: progress, question, blocked).
- For a silent seat: one urgent `System` message to the project's captain
  (`tx.captain_of(project)`), thread `silent:<seat id>`, task and attempt of the
  round, body
  `"<seat name> has produced nothing for <m> min on <task> (<role> round, model <round.model or unknown>): its pane may show an error such as a refused model id; look at the pane, fix the config, then stop the agent so it restarts on the current config"`,
  the meta key set to `now`, and the seat id returned.

`crates/gear-engine/src/lib.rs`: the module is declared and `silent::tick` is
called once per project per tick right after `restart_missing_jobs`. Its seats
stay **out** of `report.flagged`: that path sends a second, generic stall alert
for the same incident (review round 1, F1 — contract v4). The only edit in that
file.

`crates/gear-store/src/lib.rs`: `pub fn messages_from_since(&self, project,
sender, since) -> GearResult<Vec<MessageRow>>` — a copy of `messages_to_since`
with the recipient replaced by the sender and no kind filter (any message of the
seat counts). The only edit in that file.

## Tests (in `crates/gear-engine/src/silent.rs`, the store fakes the other engine
tick tests use)

- (a) a reviewer round started 11 min ago, agent idle, no usage records: exactly
  one urgent captain message on thread `silent:<seat>`; a second tick adds none.
- (b) the same round with one usage record: no message.
- (c) a round started 9 min ago: no message.
- (d) an agent observed working: no message.
- (e) a new round on the same seat after an alert: alerts again.
- (f) a round with no session: one message from the seat after its start means
  no alert, none means one alert.
- (g) **full-tick regression** (contract v4): the whole `gear_engine::tick` with
  the fakes — the first tick raises exactly one urgent captain message, on
  thread `silent:<seat>` only, and none on `stall:<seat>`; the second tick adds
  none. This test fails against the attempt-1 code (the seats were in
  `report.flagged`, so the generic stall alert fired as well) and passes now.

## Notes on the contract

- Contract v2 (captain, M-3939/M-3941) dropped the push check: the fallback
  (no session / no usage log) reads only the seat's own messages. No git call
  is made from `silent.rs`, and nothing from `quiet.rs` is reused.
- Contract v4 (captain, review round 1 F1): the seats of `silent::tick` do not
  enter `report.flagged`. The call stays where the contract puts it; only the
  `extend` is gone. The review's proposed alternative (keep the ids, skip the
  generic stall insertion for them) is the captain's call, and the captain
  chose the simpler one.
- The guard "the attempt of the round is over (cancelled/settled) → skip" is
  mine, not in the packet. Without it the seat of a cancelled task was flagged
  as silent and rang the captain as a stall, which broke
  `undelivered_delivery_contract::cancellation_closes_the_failed_delivery_stall_and_prevents_a_reminder`.
  It matches the voyage's own wording ("a lane or reviewer that holds work").
- `messages_from_since` counts a message created exactly at `round.start_at`
  (`created>=since`), so "since the round began" includes the start itself.
